## オントロジーと個別の関係

オントロジーは、ノードの種類、関係の名前、関係の主語と目的語が取れる種類、証拠を必須とするかを定義する。
個別の関係は、wiki ページの frontmatter の `graph.relationships` に、述語、目的語、ソース、引用、確信度、状態とともに記述する。
主語はその関係を書いたページのノードである。

## 開発用 wiki の語彙の例

以下は架空の不具合・修正実装・試験を説明するための追加例である。
現在の ontology.yaml の置き換えや、実際の不具合修正の記録ではない。
既存の node_types と predicates に、それぞれ項目を追加する想定である。

```yaml
node_types:
  bug:
    explicit_only: true
    description: "期待した動作と実際の動作の違い"
  implementation:
    explicit_only: true
    description: "設計や不具合修正を具体化した実装"
  test:
    explicit_only: true
    description: "動作を確かめる試験"

predicates:
  fixes:
    description: "実装が不具合を修正する"
    subject_types: ["implementation"]
    object_types: ["bug"]
    requires_evidence: true
  verified_by:
    description: "実装の動作が試験によって検証される"
    subject_types: ["implementation"]
    object_types: ["test"]
    requires_evidence: true
```

explicit_only の種類は、ページの graph.node_type に書く。
たとえば type が concept のページで、graph.node_type を implementation、graph.node_id を implementation:pdf-header-fix-example とする。
fixes の目的語には bug:invalid-pdf-accepted、verified_by の目的語には test:reject-invalid-pdf を指定する。
source は「検証記録の例」という type: source のページのスラッグを指す。
それぞれの evidence の架空の引用は「ヘッダー判定を修正し、不正な PDF の受け入れを防いだ。」「不正な PDF を拒否する試験が成功した。」である。
どちらにも confidence: high と status: current を指定する。

## 使う際の条件

参照先の不具合と試験のノード、引用を持つソースの要約ページも必要である。
YAML の description は人とエージェントに向けた説明であり、書いた日本語から検証器が意味的な真偽を判断するわけではない。
型への適合や引用の存在と、引用が関係を支持するかの判断は区別する。
実際に登録する場合は、明示的な出典と引用を持つ関係だけを採用し、graph lint と extract を実行する。
記事のコードフェンスに例を置くだけでは、実際の型付きエッジは登録されない。
