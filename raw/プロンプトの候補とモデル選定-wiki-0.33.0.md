# プロンプトの候補とモデル選定と wiki 0.33.0

2026-11-18。prompt-context-hook の実装、測定、レビュー、公開と導入確認の一次記録。作者: to884。作業の実行: Codex。

## 機能とモデルの決定

Claude Code の UserPromptSubmit で、指示に関係の強い wiki ページの候補を返す。本文を注入せず、題、パス、見出し、索引の要約を渡す。直接参照、題・スラッグ・別名、識別子、索引の要約との一致を使い、本文の語の一致は使わない。候補の表示後にだけ既出を保存し、同じセッションの40ターン以内の再表示を抑える。

候補を読む段はR0〜R3。自動メモリを無効にした158回の比較、OpusとSolの意味の採点、本文を用いた裁定から、R0はメインが現在の設定で直接読む、R1/R2はsonnet/low、比較や判断のR3はsonnet/mediumと決めた。費用が必ず減るという主張はしない。モデルとエフォートの指定はフックからエージェントへの指示であり、導入試験が推論の実行を証明するものではない。

計画と決定はADR-0034。先行mainとの番号の重複を解消した。過去の測定はADR-0032表記のまま凍結し、reader descriptionの番号1箇所だけを測定時に戻してハッシュを検証する。測定対象の本文とモデル表の意味は変えていない。

## 並列作業での起動とレビュー

uvのscript専用環境を使わず、プロジェクトの設定を読まないPythonの起動へ変更した。入口と解析の子は-I -Sを使う。走査だけではMarkdown解析器を初期化せず、解析するときに同梱版を共通の口から検証して取得する。Windowsではフックの親子にAboveNormalを試みる。APIが拒否した場合は継承した優先度を保つ。

内部2.5秒、外側5秒の期限を維持した。絶対時刻の期限で子を停止し、候補を出力してflushした後にだけ状態を保存する。既存のURL取り込みが遅延初期化により失敗する回帰はOpusの指摘で修正し、外部のMarkdownモジュールが先にロードされた場合も検証する。

wiki 0.32.0の先行mainを取り込み、概要、翻訳確認、Codex、物理リンクの拒否を保持した。統合後の関連試験は739件、15件skip。フックの参照文書のパス検査など17件も成功した。

統合後の合成150ページの試験は、フック4本と通常優先度のPython起動・ファイル読込を並行させた。ウォームアップ後の各20回では、負荷8本の明示参照がp95 957.2ms・最大970.1ms、負荷16本の明示参照がp95 1265.9ms・最大1363.7ms、負荷16本の題の一致がp95 1189.7ms・最大1194.4msだった。60/60回で候補2件、終了コード0、標準エラーなし、5秒以内を確認した。旧版の120回とは別の測定であり、任意の負荷への上限や版間の改善率は示さない。

Opus 5.5/highの統合レビューは採用可、確信度中、致命的・重大0件。レビュー記録はdocs/agent-runs/2026-11-18-wiki-prompt-hook-release/opus-integration.md。親の参照を子の実際のマージコミットへ更新する指摘も公開手順へ反映した。最終の変更は参照文書のパス表記のみで、製品の実行コードは変えていない。
