# Claude Code の Edit と Write の書き込みの競合

取り込みの手順 6〜7 は、要約ページ、関連ページ、`index.md`、`log.md` を、モデルが Claude Code の Write と Edit で書く。wiki のスクリプトでロックを持つのは、グラフの抽出（`.extract.lock`）と閲覧だけで、共有のテキストファイルには排他がない。2 つのセッションが同じ wiki を同時に書くとどうなるかを、2026-11-14 に、デスクトップアプリの Claude Code 2.1.321（Windows）で試した（[[セッションの取り込みの設計-2026-11-14]]）。

## 分かったこと

| 試したこと | 結果 |
| --- | --- |
| 読んだあと、ほかのプロセスが行を足し、そのあとで Edit で行を足す | 両方の行が残った。ハーネスは次のツールの結果に「ディスクで変わった」と知らせた |
| ほかのプロセスが行を足すのと同じ応答の中で、古い内容のまま Write で全体を書き直す | Write は `File has been modified since read` で拒んだ |
| 同じ並びで、Edit で行を足す | 当たり、ほかの行も残った。「ほかの変更がある」との注意が付いた |
| ほかのプロセスが 10 ミリ秒ごとに「読む、足す、書く」で書き換える間に、Edit で 5 行を足す | 両方向に消えた。Edit が成功と報告した 1 行と、相手の 1,500 行のうち 7 行が消え、どちらにも誤りは出なかった |
| 読み取り専用のファイルを、ジャンクションを経由して Edit と Write で書く | どちらも `EPERM`（一時ファイルから名前を変えるところ）で失敗し、中身も一時ファイルも残らなかった |

> Claude Opus 5.5 補足: 表は、上の 4 つが共有のテキストファイルの競合、最後の 1 つが読み取り専用のファイルの守りを試したものである。ふだんの競合は Write の検査と Edit の当て方で防げるが、数ミリ秒の中で重なる書き込みは黙って失われる。

## 使い方

- ふだんの使い方（古い内容を覚えたまま書き直すこと）は、Claude Code のツールが防ぐ。ただし、Edit も中では原子的でなく、同時の書き込みは黙って失われる。lint は、索引に足りない項目とログの抜けを見つけない。これは、今のどの取り込みにもある性質である。
- Claude Code の Write と Edit は、一時ファイルに書いてから名前を変える。Windows では、読み取り専用のファイルは名前の変更で置き換えられないので、取り込んだ raw を読み取り専用にすれば、パスの別名を経由した書き込みからも守れる。POSIX では、ディレクトリに書ければ読み取り専用のファイルも置き換わる見込みで（確かめていない）、守りにはならない。
- wiki 単位のロックを持つ書く段は、`docs/plans/wiki-apply-2026-11-14.md` で設計する。
