# エッジの ID の決め方

wiki 0.9.2 のグラフの抽出（`wiki_graph_extract.py` の `edge_id()`）は、エッジの ID を次の値のハッシュ（SHA-256 の先頭 24 桁）にする。この形は、Sol の敵対的レビューで 3 回却下されたあとに落ち着いたものである（[[グラフの抽出の修正-0.9.2]]）。

| 入れる値 | 理由 |
| --- | --- |
| 主語、述語、目的語、出典、証拠 | 0.9.1 までと同じ |
| ページ（ディスク上の相対パス） | 別のページの同じ関係を 1 本にしない（[[グラフの抽出の契約]] の 2）。出力の `page` は NFC のパスだが、NFC と NFD の名前の違いだけの 2 つのファイルでも消えないよう、ディスク上のパスを入れる |
| 関係の項目の `confidence`、`status`、`valid_from`、`valid_to`、`notes`、`raw_ref` | 項目 1 つから 1 本のエッジにする（契約の 7） |
| `contradicts`、`supersedes` のうち、エッジの ID の形（16 進 24 桁）でない値 | ノード ID などの参照だけが違う項目を、並べ替えても取り違えない |
| 上がすべて同じ項目の中での、ページで出てきた順の番号 | まったく同じ 2 件も別のエッジにする |

> エッジの ID の表 補足: 上から順に、0.9.1 までの値、ページ、関係の項目の欄、参照の欄、番号を足したことを示す。番号は、番号を入れる前のハッシュが同じ項目の中で数える。

## 入れないもの

- **エッジの ID を書いた `contradicts` と `supersedes` の値。** 入れると、2 つの関係が互いのエッジの ID を書いたとき、書き直すたびに自分の ID が変わり、参照が成り立たない。
- **未知の拡張の欄。** 入れ子の辞書のキーに数値と文字列が混ざると、並べられずに抽出が止まったので、決まった欄だけを使う。

## 残した制約

- エッジの ID の参照か未知の欄だけが違う 2 件は、番号で分かれるので、並べ替えると ID が入れ替わる。黙らずに、グラフの lint が `order_dependent_edge_ids` に挙げる。
- 0.9.2 で、すべてのエッジの ID が変わった。グラフ層を使う wiki は作り直しが要る。

## 確かめるときの注意

- 番号の数え方とハッシュで、空の値の扱いをそろえる。1 回目の案では、番号は `None` と `""` を区別し、ハッシュは区別しなかったので、`source` を省いた項目と `source: ""` の項目が同じ ID になって 1 本に消えた。
- 並べ替えの試験は、ID の集合ではなく、項目と ID の対応で比べる。ID が別の項目に移っても、集合は変わらない。
