# info-hive のオントロジーの記述例

オントロジーは種類と関係の定義、ページの `graph.relationships` はその定義に従う個別の関係である。
ここでは不具合・修正実装・試験を使って書き分ける。
すべて架空の例であり、現在の `ontology.yaml` や実際の型付き関係には追加していない（[[オントロジーの記述例-2026-11-18]]）。

## 種類と関係を定義する

`wiki/graph/ontology.yaml` の既存の `node_types` と `predicates` に、次の項目をそれぞれ加える想定である。
既存のファイル全体を、この抜粋で置き換えるものではない。

```yaml
node_types:
  bug:
    explicit_only: true
    description: "期待した動作と実際の動作の違い"
  implementation:
    explicit_only: true
    description: "設計や不具合修正を具体化した実装"
  test:
    explicit_only: true
    description: "動作を確かめる試験"

predicates:
  fixes:
    description: "実装が不具合を修正する"
    subject_types: ["implementation"]
    object_types: ["bug"]
    requires_evidence: true
  verified_by:
    description: "実装の動作が試験によって検証される"
    subject_types: ["implementation"]
    object_types: ["test"]
    requires_evidence: true
```

| 欄 | この例での役割 |
| --- | --- |
| `node_types` | 不具合、実装、試験というノードの種類 |
| `explicit_only` | ページの `graph.node_type` で明示して使う種類 |
| `subject_types`・`object_types` | 関係の主語と目的語に許す種類 |
| `requires_evidence` | 出典と証拠の引用を必須にする指定 |
| `description` | 人とエージェントが読む意味の説明 |

この定義では `fixes` は実装から不具合へ、`verified_by` は実装から試験へ向く。
たとえば試験ノードを `fixes` の主語にすると、主語の型が合わず、グラフの lint が検出する。
`description` の日本語から、検証器が関係の意味的な真偽を判断するわけではない。

## 個別の関係をページに記述する

実装のページの frontmatter は、次のようになる。
`type` は wiki のページの種類、`graph.node_type` はグラフ内の役割である。
主語は、この関係を書いたページのノードになる。

```yaml
---
type: "concept"
title: "PDF ヘッダー判定の修正例"
tags: ["グラフ"]
sources: ["検証記録の例"]
created: 2026-11-18
updated: 2026-11-18
graph:
  node_type: "implementation"
  node_id: "implementation:pdf-header-fix-example"
  relationships:
    - predicate: "fixes"
      object: "bug:invalid-pdf-accepted"
      source: "検証記録の例"
      evidence: "ヘッダー判定を修正し、不正な PDF の受け入れを防いだ。"
      confidence: "high"
      status: "current"
    - predicate: "verified_by"
      object: "test:reject-invalid-pdf"
      source: "検証記録の例"
      evidence: "不正な PDF を拒否する試験が成功した。"
      confidence: "high"
      status: "current"
---
```

使う場合は、目的語のIDと種類を持つ不具合・試験のページと、`type: "source"` の「検証記録の例」ページも必要になる。
実際の引用を確認し、型付き関係に必須の `predicate`、`object`、`source`、`evidence`、`confidence`、`status` を記述する。
語彙や関係を編集した後はグラフの lint を確認し、extract で索引を作り直す。
コードフェンス内の例は、実際の型付きエッジとして登録されない。
