# rag が受け付ける PDF のヘッダーの条件

rag は、PDF を 2 つの段階で確かめる。登録で拒むものと、登録のあとの処理でジョブが `failed` になるものがある。wiki の取り込み手順（`info-hive-wiki` の `skills/info-hive/references/ingest-workflow.md`）は、この 2 つを分けて案内する。

| 段階 | 呼ばれる所 | 確かめること | 外れたとき |
| --- | --- | --- | --- |
| 登録 | `register_pdf` → `Config.pdf_path`（`rag_config.py`） | 拡張子が `.pdf`（大文字と小文字は区別しない）、通常のファイル、UNC パスでない、派生データやキャッシュの中でない | 登録を拒む |
| 処理 | ワーカーの `Engine.ingest_pdf` → `read_pdf`（`rag_index.py`） | `%PDF-` が先頭から 1024 バイトの範囲で始まる | ジョブが `failed` になる |

> 段階の表 補足: `register_pdf` はジョブを台帳に書くだけで、PDF の中身を読まない。ヘッダーを読むのは、接続中だけ動くワーカーが PDF を読み込むときである。

## 境界

- `has_pdf_header` は `data.find(b"%PDF-", 0, 1024 + 5)` で探す。`%PDF-` の開始位置（0 始まり）が 0〜1024 なら受け付ける。言い換えると、`%PDF-` の前にあるバイトが 1024 バイト以下なら受け付ける。
- 上限は PDFium にそろえた。PDFium は `%PDF` を位置 0〜1024 で探す。pypdfium2 5.14.0（PDFium 156）で、改行、CRLF、空白、NUL などの前置きが 1024 バイトなら開け、1025 バイトでは開けないことを確かめた（[[pdfのヘッダーの判定の修正-rag-0.5.1]]）。
- 判定を通っても、PDFium で開けるとは限らない。開けないものは抽出で失敗する。

## 書き方

「先頭から 1024 バイト目まで」は、1 始まりで読むと、受け付ける範囲が実装より 1 バイト狭くなる。開始位置が 1024 の `%PDF-` は 1025 バイト目から始まるからである。wiki 0.11.1 からは「`%PDF-` の前にあるバイトが 1024 バイト以下」と書く（[[取り込み手順の追従とリリース-wiki-0.11.1]]）。

rag の README、CHANGELOG、v0.5.1 の GitHub リリースの本文は、まだ前の書き方のままである。

## 版による違い

| rag の版 | ヘッダーの条件 |
| --- | --- |
| 0.5.0 以前 | 先頭がちょうど `%PDF-` |
| 0.5.1 以降 | `%PDF-` の前のバイトが 1024 バイト以下 |

- wiki 0.11.1 と rag 0.5.0 を組み合わせると、先頭に改行や空白がある PDF のジョブは `failed` になる。wiki の手順は版による違いを書き、`failed` の理由をそのまま伝えるよう案内する。
- rag 0.5.0 でこの理由で失敗したジョブは、0.5.1 に更新しても自動では再開しない。`retry_job` で再試行するか、取り込み直す。
- 取り込み直しは要らない。SHA-256 と抽出は前置きを含む読んだままのバイト列に対して行い、今まで受け付けていた PDF の判定は変わらないので、抽出の版（ADR-0014）を上げていない。
