# 2 つの wiki の分離の確かめ方

2 つの wiki（ユーザースコープとプロジェクト）を 1 つの問い合わせで引くとき、2 つが何も分け合っていないことを確かめる方法である。分け合っていると、一方の検索が他方のページを返して出典の区別を誤り、許した書き込み（`.wiki-cache/` のキャッシュ）が他方のファイルを書き換える。[[2つのwikiを引く問い合わせの設計-2026-11-16]] の 7 回の敵対的レビューで確かめた。実装はまだなので、どれも設計の段階の判断である。

## 崩れた比べ方

| 比べ方 | 崩れた配置 | 回 |
| --- | --- | --- |
| 根のパスの文字列が同じか、一方が他方の前方にあるか | 大文字と小文字、NFC、ジャンクションで、同じ場所が別のパスに見える | 1、2 |
| 根を `casefold()` してそろえる（`wiki_key()` と同じ） | `straße` と `strasse` のような別々のディレクトリを同じものにする | 2 |
| 根の入れ子だけを見る | 根の下のジャンクションが他方の wiki を指す | 2 |
| 検索が走査するページだけを比べる | 索引（`index.md`）や `.wiki-cache/` の `.tmp` が、他方のページとハードリンクで同じファイル | 3 |
| ディレクトリだけを比べる | ファイルのシンボリックリンクが他方のページを指す | 4 |
| リンクを禁じたうえで、入れ子だけを見る | bind mount は、リンクを作らずに同じ部分木を別の場所に見せる | 5 |
| 入力と、そろえた根が同じ実体か | MCP は受け取った根を NFC にそろえ直すので、そろえた根をもう一度そろえると、NFC の名前の別のディレクトリに移る | 6、7 |

> Claude Opus 5.5 補足: どの比べ方も、守りたい性質（2 つの wiki が実体を分け合わない）を、名前や構造の一部で代わりに確かめていた。代わりのものと性質がずれる別名の仕組みが、回ごとに 1 つずつ見つかった。

## 残った確かめ方

- **根の下の実体の識別子を全部比べる。** 2 つの根の下に現れるすべてのディレクトリとファイル（根そのもの、`.wiki-cache/`、`raw/`、`graph/` も含む）の識別子の集まりが、1 つも重ならないことを確かめる。識別子は、Windows では `wiki_pages.win_file_id()`（ボリュームとファイルの ID）、ほかでは `(st_dev, st_ino)` である。入れ子、bind mount、`subst` を、仕組みを区別せずに見つける。
- **raw と wiki にリンクを置かない。** リンクがあれば、識別子を比べる前に止める。取り込みはリンクの先の中身を写し、lint が見つける（ADR-0029、提案）。
- **確かめた根を、そのまま全部の道具に渡す。** MCP のツールは根を `normalize_wiki_root()`（NFC にそろえてから解決する）でそろえ直し、CLI の `wiki_search.py` はそろえずに使う。補助はそろえた根を出し、その根が「もう一度そろえても同じ実体を指す」ことを識別子で確かめる。そうでなければ確かめられないとする。
- **確かめられないものは、引かない側に倒す。** 一覧できないディレクトリ、識別子が取れない項目（すべて 0 を含む）があれば、2 つを引かない。

## 確かめられないこと

- 識別子を安定して返さないファイルシステムと、同じネットワークの共有を 2 か所に別々にマウントした配置（デバイスの部分が違って見える）。
- 確かめたあと、問い合わせの途中で配置が変わること。
- MCP の索引が前に読んだ古い本文（パス、大きさ、更新時刻が変わらなければ読み直さない）。
