# 2 つの wiki の分離の確かめ方

2 つの wiki（ユーザースコープとプロジェクト）を 1 つの問い合わせで引くとき、2 つが何も分け合っていないことを確かめる方法である。分け合っていると、一方の検索が他方のページを返して出典の区別を誤り、許した書き込み（`.wiki-cache/` のキャッシュ）が他方のファイルを書き換える。[[2つのwikiを引く問い合わせの設計-2026-11-16]] の 11 回の敵対的レビューと、4 体のエージェントの見直しで確かめた。実装はまだなので、どれも設計の段階の判断である。

## 崩れた比べ方

| 比べ方 | 崩れた配置 | 回 |
| --- | --- | --- |
| 根のパスの文字列が同じか、一方が他方の前方にあるか | 大文字と小文字、NFC、ジャンクションで、同じ場所が別のパスに見える | 1、2 |
| 根を `casefold()` してそろえる（`wiki_key()` と同じ） | `straße` と `strasse` のような別々のディレクトリを同じものにする | 2 |
| 根の入れ子だけを見る | 根の下のジャンクションが他方の wiki を指す | 2 |
| 検索が走査するページだけを比べる | 索引（`index.md`）や `.wiki-cache/` の `.tmp` が、他方のページとハードリンクで同じファイル | 3 |
| ディレクトリだけを比べる | ファイルのシンボリックリンクが他方のページを指す | 4 |
| リンクを禁じたうえで、入れ子だけを見る | bind mount は、リンクを作らずに同じ部分木を別の場所に見せる | 5 |
| 入力と、そろえた根が同じ実体か | MCP は受け取った根を NFC にそろえ直すので、そろえた根をもう一度そろえると、NFC の名前の別のディレクトリに移る | 6、7 |
| 根の下のすべてを比べる | 問い合わせが開かない `.git/` や uv のキャッシュのハードリンクでも止まり、ADR-0029 の「記事でないリンクだけでは止めない」に反する | 13 版目 |
| エージェントが呼ぶ補助が、開くものを数え上げて比べる | 接続したままの古い MCP は補助のプロセスと版が違う。MCP の索引の中のファイルや `ontology.yaml` が数え上げから漏れる | 8 |
| 記事でない場所のディレクトリのリンクは、先の識別子だけを取る | 一方の `graph/` が外の `X/` を指し、他方の `graph.sqlite` が `X/graph.sqlite` を指すと、識別子は重ならないのに同じファイルを開く | 9 |
| 登録の文字列をそのまま根にする | 作業領域の `dirs.wiki` は相対パスで、`~/` の定型文は基準につなぐと展開されず、Windows の `C:wiki` や `\wiki` は解くプロセスの今のドライブに依存する | 9〜11 |

> Claude Opus 5.5 補足: どの比べ方も、守りたい性質（2 つの wiki が実体を分け合わない）を、名前や構造の一部で代わりに確かめていた。代わりのものと性質がずれる別名の仕組みが、回ごとに 1 つずつ見つかった。

## 残った確かめ方

- **確かめる者と読む者を同じにする。** 2 つの根を受け取る読み手が、どの索引も開く前に確かめ、`disjoint` のときだけ読む。エージェントが呼ぶ別の補助で確かめると、補助が比べたものと読み手が開くものが、版、データの場所（環境変数）、開くものの数え上げでずれた。開く処理と、比べる規則を同じモジュールに置く。
- **読み手が開くものの実体の識別子を比べる。** 根そのもの、記事、走査が降りたディレクトリと、記事でない開く場所（`graph/`、`.wiki-cache/`、MCP の索引）の下のすべてを、2 つの wiki で対称に比べる。記事でない開く場所では、リンクの先の識別子を取り、ディレクトリのリンクにも降りる。読み手が開かない場所（`.git/`、`raw/`、`assets/`）は比べない。識別子は、Windows では `wiki_pages.win_file_id()`（ボリュームとファイルの ID）、ほかでは `(st_dev, st_ino)` である。入れ子、bind mount、`subst` を、仕組みを区別せずに見つける。
- **記事のリンクは、走査が拒んで知らせる。** ADR-0029（承認済み）の走査はリンクの記事を読まないので、記事のリンクでは止めず、警告として添える。
- **登録の綴りを、絶対パスかホームからのパスにして渡し、読み手の中でそろえ直さない。** 読み手は、根ごとに、綴り、そろえた根、識別子を持ち、入力の実体とそろえた実体が違えば確かめられないとする。内部ではそろえた根を `Path` のまま渡すので、不動点の確かめは要らなくなった。
- **確かめられないものは、引かない側に倒す。** 一覧できないディレクトリ、識別子が取れない項目（すべて 0 を含む）があれば、2 つを引かない。

## 確かめられないこと

- 識別子を安定して返さないファイルシステムと、同じネットワークの共有を 2 か所に別々にマウントした配置（デバイスの部分が違って見える）。
- 確かめたあと、問い合わせの途中で配置が変わること。
- MCP の索引が前に読んだ古い本文（パス、大きさ、更新時刻が変わらなければ読み直さない）。
