# frontmatter のリストの値の読み方と、そろえる関数の違い

`tags`、`sources`、`raw` のようにリストを入れる欄でも、frontmatter のパーサー（`wiki_text.parse_frontmatter_text`）は、書かれた形のまま、文字か文字の配列を返す。値を 1 つだけ書くと文字になる。使う側でリストにそろえる関数が 3 つあり、空の値、空白、文字でない値の扱いがそれぞれ違う。wiki 0.12.1 で、検索の結果の欄がそろっていなかったのを直した（[[検索の結果のtagsとsourcesの修正-wiki-0.12.1]]）。

## パーサーが返す値

2026-11-13 に、wiki 0.12.0 のパーサーと `canonical_meta()` で確かめた。

| frontmatter の書き方 | 読んだ値 |
| --- | --- |
| `tags: 検索`（`タグ: 検索` も同じ） | `"検索"`（文字） |
| `tags:`（値なし） | `[]` |
| `tags: ""` | `""` |
| `tags: []` | `[]` |
| `tags: [a, b]` | `["a", "b"]` |
| `tags: 2024`、`tags: null` | `"2024"`、`"null"`（文字） |
| `tags: ["", " x "]` | `["", " x "]` |
| `tags: [a, b`（`]` がない） | `"[a, b"`（文字） |

> パーサーが返す値の表 補足: 数、真偽値、`null` も、書かれた文字のままの文字列になる。数や辞書が入るのは、パースキャッシュ（`.wiki-cache/search-index.json` など）を手で書き換えたときだけである。キャッシュを読むときは、`meta` が辞書であることしか確かめない。

## そろえる関数

| 関数 | 使う所 | 文字 1 つ | `None`、`""`、`[]` | 要素の空白と空の要素 | 文字でない値 | 値を変えるか |
| --- | --- | --- | --- | --- | --- | --- |
| `wiki_pages.ref_values()` | lint の `sources` と `raw`、browse 0.12 の `sources`、検索の結果の `tags` と `sources`（0.12.1 から） | 1 要素の配列 | `[]` | 前後の空白を除き、空になったものと `None` を除く | `str()` で文字にする（`5` は `["5"]`） | 空白を除くだけ |
| `wiki_text.normalize_tags()` | lint の `unknown_tags`、検索の `--tag` の絞り込み | 1 要素の配列 | `""` は `[""]`、`None` と `[]` は `[]` | 前後の空白を除くが、空の要素は残す | 配列でない数は `TypeError` | NFKC をかける（`ＡＩ` が `AI` になる） |
| `wiki_graph_extract._tag_list()` | グラフのノードの `tags` | 空でなければ 1 要素の配列 | `[]` | そのまま残す | 配列でなければ `[]`。配列の要素は文字にしない | 変えない |

> そろえる関数の表 補足: 比べるためにそろえるなら `normalize_tags()`、出力や参照の解決に使うなら `ref_values()` が合う。`normalize_tags()` は NFKC で値そのものを変えるので、結果の欄に使うと、書いた文字と違う文字を返す。2026-11-13 時点で作業中の browse の改修では、埋め込みの検索のデータが `nfc(str(v))` にし、`None` と `""` だけを除く別の書き方をしている。型は同じだが、空白だけの要素を残す。

## 結果の欄に使うとき

- `wiki_search.py --json` と MCP の `query` の結果の `tags` と `sources` は、0.12.1 から `ref_values()` で作る。いつも文字の配列になる。CLI と MCP の結果は、どちらも `wiki_search.json_result()` で作る。
- 新しく出力にリストの欄を足すときは、規則を書き足さずに `ref_values()` を使う。値を 1 つだけ書いたページを、試験の入力に入れる。
- 規則が 3 つあるのは、移植と修正の積み重ねによる。まとめる作業はまだしていない。

## 残っている欠陥

2026-11-13 の修正では直さず、範囲の外として残したもの。

| 書き方 | 起きること |
| --- | --- |
| `title: [x, y]` | 検索の `collect_pages()` の `body + " " + meta.get("title", "")` が `TypeError` で止まる。CLI の検索も、MCP の索引も動かない |
| `type: [concept]`、`updated: [2026-01-01]` | `--json` の `type` と `updated` が配列のまま出る。契約（文字か `null`）から外れる。lint は `updated` を `non_iso_dates` として指摘する |
| パースキャッシュの `tags` が `5` のような数 | `--tag` で絞り込むと、`normalize_tags()` が `TypeError` を出す |
| `tags: 検索` のページを MCP の `get_page` で読む | `meta.tags` は文字のまま返る。`get_page` の説明は、日本語の別名のキーを英語にそろえることしか約束していない |

> 残っている欠陥の表 補足: `title` と `type` と `updated` は、配列で書かれたときにどの値を使うか（先頭か、つなげるか、誤りとするか）を決めないと直せない。
