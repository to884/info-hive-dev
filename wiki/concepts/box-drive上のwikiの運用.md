# Box Drive 上の info-hive wiki の運用

Windows 版 Box Drive の Cloud Files 方式では、1 台の PC で info-hive wiki の基本操作が動いた。複数端末で編集すると、Box の同期はファイル単位のため、wiki 全体で同じ更新時点を保てないことがある。複数端末への共有は、書き込み元を 1 台に固定し、確定版を配布する。[[box-driveでのwiki互換性-2026-11-19]]

## 動作を確認した操作

2026-11-19 に、Windows 11 の 1 台で Box Drive 2.56.271.0、Python 3.14.6、wiki v0.38.1 を使い、架空の日本語記事 1 ページと原本を試験した。[[box-drive-wiki-compatibility-2026-11-19]]

| 操作 | 結果 |
| --- | --- |
| 初期化とファイル保存 | 標準初期化から検索の準備完了まで成功。日本語 Markdown 原本の保存、既存記事とログの置き換えも成功。 |
| 検索と構造の点検 | CLI の BM25 とハイブリッド検索、MCP のハイブリッド検索、ページ取得、lint が成功。 |
| グラフの生成と照会 | 生成後の SQLite の整合性検査と MCP のノード照会に成功。 |
| 閲覧 | browse の静的 HTML 生成とローカル HTTP 閲覧が成功。 |
| オンライン専用ファイル | 再取得後の本文に更新した語句が含まれ、原本の SHA-256 は保存前と一致した。 |

> Codex 補足: 同じ PC の Box Drive 上で、wiki の作成から再編集、検索、閲覧までを確認した。オンライン専用に戻した記事と原本も、ネットワーク接続中に読み出せた。

## オフライン中の操作と再接続後の同期

Windows 11 の 1 台と Box Drive 2.56.271.0 の Cloud Files 方式、wiki v0.38.1 で実測した。接続中に初期化と検索モデルの準備を済ませ、`wiki/` と `raw/` を「このデバイス上で常に保持」にした。Box への通信だけを遮断し、オンライン専用の対照ファイルを取得できないことを確認した。[[box-driveのオフライン編集と再同期-2026-11-19]]

| 操作 | 結果 |
| --- | --- |
| 閲覧 | 固定済みの記事と原本を読めた。browse の静的 HTML に編集後の 2 記事が反映された。 |
| 検索 | CLI の BM25 とハイブリッド検索で、更新した記事と新規記事の両方が見つかった。 |
| 編集 | 記事・`index.md`・`log.md` の更新と、新規記事・原本の追加ができた。 |
| 再接続後の同期 | 変更した 5 ファイルの SHA-1 が Box API の応答と一致し、オンライン専用の状態から再取得した後の SHA-256 もすべて一致した。 |

> Codex 補足: ダウンロード済みのファイルだけで、切断中に閲覧・検索・編集ができた。接続を戻すと、編集したファイルと新規ファイルの内容が Box に反映された。

出先で編集する前に、親フォルダーを「このデバイス上で常に保持」にしてダウンロード完了を確認する。再接続したら Box Drive のアップロードが完了するまで待ち、別端末に切り替える前に必要な変更が反映されたことを確認する。 [Box のオフライン利用](https://support.box.com/hc/en-us/articles/360043697574-Making-Content-Available-Offline)

## 複数の書き手が編集したときの競合

Windows 1 台で Box Drive と Box Web を書き手にした。共通版から記事・`index.md`・`log.md` を Box Drive 側でオフライン編集し、先に Box Web から別の版を保存した。Box Drive を再接続すると、3 ファイルすべてで正規名に Web 版が残り、Box Drive 版が別名コピーになった。Box API の SHA-1 で両方を照合した。[[box-driveのwikiの競合と復旧-2026-11-19]]

| ファイル | 復旧で照合する内容 |
| --- | --- |
| 記事 | 両方が変更した節と frontmatter。同じ行で異なる事実を足した場合は出典や編集意図を確認する。 |
| `index.md` | 掲載項目、要約、リンク先。分割済みの場合は該当する `indexes/` と上位索引の件数も確認する。 |
| `log.md` | 両方の操作と追記を確認する。同じ日付や同じ見出しの操作も、その記述だけで同一と判定しない。 |

> Codex 補足: Box は記事・索引・ログを個別に扱う。別の版が残っていても、本文、索引の項目、ログの追記は wiki 側で統合する必要がある。

別々の記事が両方残っていても、片方の索引項目ともう片方のログが欠け得る。その状態をローカルで再現すると、lint のリンク切れと孤立ページは両方とも 0 件だった。元の版と照合して欠けた索引項目やログを確かめる。[[box-driveのwikiの競合と復旧-2026-11-19]]

## 競合後の復旧手順

1. **編集を止め、版を保全する。** 両方で新しい編集や取り込みを止め、開いたままの下書きは Box の外に保存する。未同期のローカル版、正規名のファイル、別名コピーも Box の外にコピーする。Box の版履歴から共通版を取得できる場合は一緒に保存する。 [Box の版履歴](https://support.box.com/hc/en-us/articles/360043697054-Accessing-Version-History)
2. **同期外で統合する。** 共通版と両方の編集を比べ、まず記事を確定する。変更が重なる箇所は人が確認する。確定した記事から索引の項目を直し、ログへ両方の操作を 1 回ずつ反映する。検索と lint を実行し、両方の編集内容、索引の掲載漏れ、ログの欠落や重複を手元の版と照合する。グラフを使う wiki では抽出をやり直す。
3. **1 台から書き戻して確認する。** 統合したファイルを正規名で保存し、アップロード完了後に Box 側の版と内容を確認する。保全を確認した別名コピーは wiki の外へ退避する。他の端末は復旧版を取得してから編集を再開する。[[box-driveのwikiの競合と復旧-2026-11-19]]

実機試験では、統合した記事・索引・ログの 3 ファイルと、退避した競合コピーの 3 ファイルについて、Box 側とローカルの SHA-1 がすべて一致した。[[box-driveのwikiの競合と復旧-2026-11-19]]

## 制約と対処

- **複数端末の書き込み。** 取り込みでは記事、索引、ログ、原本を順に更新する。Box のファイル単位の同期では、読み手に更新途中の組み合わせが見えるおそれがある。別々の記事を編集する場合でも、書き手が共通の `index.md` や `log.md` を更新すると競合し得る。Box の競合コピーから wiki が更新内容を自動統合する機能はない。 [Box のファイル競合](https://support.box.com/hc/en-us/articles/360044193873-File-Version-Conflicts)
- **全ファイルの複製と排他。** Box は先頭にドットが付く隠しファイルや一時ファイルを同期対象外としている。同期フォルダーだけから `wiki/.page-template.md` なども含めた完全な復元を期待できない。グラフ抽出の OS ロックは同じ端末内の処理を調整する。 [Box の同期対象外ファイル](https://support.box.com/hc/en-us/articles/360044195433-File-Types-Ignored-or-Blocked-by-Box-Sync-and-Box-Drive)
- **グラフ DB の置き換え。** 読み取り接続を開いたまま再生成すると、Box と非同期のフォルダーの両方で Windows が置き換えを拒否した。接続を閉じてから再実行すると成功した。[[box-drive-wiki-compatibility-2026-11-19]] [[windowsのファイルの共有と削除待ち]]
- **検索の索引。** MCP のデータは既定の端末ローカル領域に置き、`INFO_HIVE_DATA_DIR` を Box 配下に変更しない。CLI のハイブリッド検索は wiki 内の `.wiki-cache/embeddings.sqlite` に書く。CLI で検索の書き込みを避けるときは `--no-embed` を指定し、`--cache` を付けない。[[box-driveでのwiki互換性-2026-11-19]]

## 運用の選び方

1. **1 台で編集する。** 同じ親フォルダーの下に `wiki/` と `raw/` を置き、原本の相対参照を保つ。親フォルダーを「このデバイス上で常に保持」にすると、検索や全件走査のときにダウンロード待ちが減る。 [Box のオフライン利用](https://support.box.com/hc/en-us/articles/360043697574-Making-Content-Available-Offline)
2. **他の端末で閲覧する。** 編集が終わった時点で静的 HTML 一式、または必要な原本と Markdown を含めたアーカイブを Box で配布する。元の wiki と同じ検索・グラフが必要なときは、受け取った版を端末ローカルに展開し、索引・グラフを作り直す。[[box-driveでのwiki互換性-2026-11-19]]

## 適用範囲

競合の実機試験は同一アカウントの Box Drive と Box Web の組み合わせで行った。Box Drive 2 台、別アカウント、同時再接続、端末全体の通信切断、切断中の初回セットアップと MCP 検索、Web・会話の取り込み全体、rag ジョブ、大規模 wiki は未検証。旧 Windows 方式にはローカル AI エージェントからのアクセスに既知の制限がある。 [Box Drive の Windows 固有の制限](https://support.box.com/hc/en-us/articles/360043695854-Windows-Specific-Limitations-for-Box-Drive)
