# myKG

文書のディレクトリから、導出したスキーマに沿うナレッジグラフを構築し、MCP を通じて AI アプリケーションへ公開するオープンソースのツール。作者 Senol Isci の [[mykgとclaude-desktopの接続]] が、Claude Desktop と接続するデモを説明している。

## 構築と利用の分担

| 段階 | 記事で説明された役割 |
| --- | --- |
| スキーマの提案 | Pass 1 で文書群から型を提案する |
| 対象と関係の抽出 | Pass 2 でスキーマに従ってグラフを構築する |
| ノートの出力 | Obsidian に準拠するリンク付き Markdown のノートを書き出す |
| 問い合わせ | stdio の MCP サーバーから探索・参照のツールを提供する |
| 回答の生成 | クライアントの Claude が複数のツールを呼び、ノートを読んで回答する |

> 処理の分担 補足: 2026 年 7 月 7 日公開の記事の説明を整理した。ツール数や更新オプションを含め、現行版の仕様と動作はこの wiki では検証していない。

## グラフと原文の関係

記事の組織図の例には、グラフで別々のチームが統合されていたと Claude が説明し、元の文書を参照して区別し直す場面がある。グラフが型を持つことを、個々の抽出結果の正しさの保証とはしない。探索後の本文の確認という点で [[既存リンクからのグラフ検索]] とつながるが、myKG の構築は既存のリンクを解析する方式とは異なる。

## リポジトリで確認したアーキテクチャ

[[mykgのアーキテクチャ]] は 2026-11-18 にコミット `afb0a9c9bafdc49751563b9aa7f59bcf4bb787fb` の README・設計文書・主要実装を照合した記録である。[[スキーマの導出と事実の抽出の分離]] を中心に、構築の 12 段階、セッションによる再開、差分更新、統合、LLM 接続の交換を整理している。

永続化は JSONL、問い合わせ時の探索はメモリ上の NetworkX と BM25 が担う。MCP はグラフの構築を行わず、完成したセッションの検索・探索・原文の参照を提供する。確認した版の MCP は 16 ツールで、上の利用記事の 14 ツールと区別する。抽出精度・性能の実測や、実際の導入は行っていない。

スキーマの検証は警告で継続できること、混合バッチでは出所が過剰に付くこと、探索用の DiGraph は同じ両端の複数関係を独立した多重エッジとして持たないことも、同記事の留保として残した。

外部の製品についての記録であり、info-hive の実装や導入済みの依存関係を表すものではない。
