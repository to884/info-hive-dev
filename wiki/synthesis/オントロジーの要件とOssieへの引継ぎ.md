# オントロジーの要件とOssieへの引継ぎ

Apache Ossieの採用を検討する別セッションへ渡す、要件と未解決事項の入口である。名称はユーザーの指定どおりで、製品機能・正式名称・リポジトリURL・対象版は本セッションで未検証である。採用は決定していない（[[オントロジーの要件と引継ぎ-2026-11-19]]）。

その後、2026年11月19日に公式仕様の調査、設計、書き出しと移行の PoC、独自の DuckDB アダプターでの実行まで行った。11月20日の再確認では、一方向の交換形式として使えること、公式検証器と変換器の対応範囲が異なることを確認した。型・関係を記述する形式としては採用候補で、根拠・履歴、承認付き移行、既存照会は info-hive 側で扱う。本プロジェクトの wiki の公開版は未有効化。[[apache-ossie-ontology-management-2026-11-20]]

## 採用候補と照合する事項

| 検討事項 | 必要な判断 |
| --- | --- |
| 意味モデル | 型・役割・関係・相手・対象・期間をどう表し、顧客の一覧や件数をどう定めるか |
| 識別と根拠 | 実体・主張・根拠をどう分け、IDと旧IDへの対応をどう保つか |
| 継続する移行 | 定義の版、旧定義、保留、複数回の部分移行と解消をどう扱うか |
| 正本 | entityページか別の記録か。既存ページとIDをどう再利用するか |
| 責任範囲 | 候補に任せる定義管理・検証・推論と、info-hiveが担う抽出・名寄せ・移行・承認・公開制御の境界 |
| 導入範囲 | ingest・lint・extract・query・browse・MCPと既存wikiへの変更 |

外部の見方として、[[knowledge-catalog-ossie-genai]] は Ossie を「指標などの定義を共有するオープンな標準（Apache Incubator の段階）」、Google Knowledge Catalog を「定義を発見して関連づけ、エージェントに文脈として渡す層」と分け、補完し合う可能性を挙げる。ただし著者の推測で、Google の発表に Ossie との直接の対応はない。同じ記事は、標準を採用しても定義の選択と承認は組織のガバナンスに残るとみる。Ossie の資料は未確認で、記事の記述は採用判断の根拠にしない。

顧客を型に固定することや、固定ID方式への変更を、ユーザーが決定済みとは解釈しない。
共通の書く段との接続は[[wikiの書く段の設計-2026-11-15]]も参照する。現行ADRの保証をそのまま移行全体の保証とみなさない。
