# Claude Code のセッションを wiki に取り込む設計の記録（ADR-0020）

2026-11-14 の、Claude Code のセッションの会話を `/wiki:ingest` で wiki に取り込む機能の設計の記録である。原本は、GPT-6.1 Sol の 7 回の敵対的レビューと、崩れた前提の一覧、並行の書き込みの試験を残した `docs/agent-runs/2026-11-14-wiki-session-ingest/` である。4 体のエージェントの再設計は `docs/agent-runs/2026-11-14-wiki-session-ingest-redesign/`、設計は `docs/plans/wiki-session-ingest-2026-11-14.md`、決定は ADR-0020（承認）、分けた書く段の方針は `docs/plans/wiki-apply-2026-11-14.md` にある。実装はまだである。

## 経緯

1. 作者が「セッションの会話を記事の形で wiki に取り込む方法」を尋ね、続けて「コマンドで作りたい」と頼んだ。記録（JSONL）の構造を、会話の文を読まずに集計した（[[セッションの記録の構造]]）。
2. 1〜3 版目は、人が自由に直した写しを元と照らして許された編集かを推す作りと、ファイルの有無から状態を推す作りで、Sol に 3 回続けて却下された。直すたびに、その回に足した仕組みに新しい反例が出た。
3. 作者の判断で、4 体（Opus 5.5、Fable 5.1、Sol、Astra）に独立に設計し直させ、相互レビューと総括を受けた。総括は「安全に関わる事実を、書き手が作った結果として持たず、あとから推していた」を共通の原因とし、エージェント A（Opus 5.5）の構造を推した。A は、3 版目までの規則が、キューに入った入力への返答 545 件を前のターンに混ぜることも実物で示した。
4. 4 版目に wiki の書く段（ロック、パッチ、追記）を足すと、4 回目のレビューの重大 7 件のうち 6 件がそこに出た。作者の判断で、書く段を別の設計に分けた。
5. 5〜7 回目は、raw と wiki の書く先の重なりと、パスの別名（浅いリンク、bind mount、UNC）を突いた。パスで重なりを証明するのをやめ、raw を読み取り専用にし、最後にハッシュを照らす形にした（[[editとwriteの書き込みの競合]]）。7 回目の重大は raw の置き場所の全体の問題に移ったので、限界として書き、作者が承認した。

## 決めたこと

- 新しいコマンドは足さず、`/wiki:ingest session` などの引数で受け付ける（ADR-0015）。`.jsonl` は、セッションの記録と認めなければ止まり、明示の依頼なしにふつうの取り込みへ回さない。
- 編集される写しを作らない。人の決定は、伏せる位置と消すターンの番号のデータとして持ち、スクリプトが raw を 1 回で作る。確認の前の会話の文はディスクに置かない。
- 同一性は、作った raw のバイト列とする。キーを並べない。実行の時刻は書かない。
- raw は、承認したハッシュに一致したときだけ、重ねて書かない形で置き、読み取り専用にする。上書きの手段は持たない。
- 取り込みが済んだかは、スクリプトが判定せず、Web ページの W2 と同じく人に聞く。
- wiki の書き込みは既存の取り込みと同じ水準にとどめ、書く前に、伏せた文字列の検査（`scan`）と、中身をユーザーに見せる手順を足す。

## 崩れた前提と直し方

| 崩れた前提 | 直し方 |
| --- | --- |
| 人が編集した写しを元と照らせば、許された編集かが分かる | 写しを作らず、決定を位置のデータで持つ |
| ファイルの有無やキーの列挙で、状態と同一性が決まる | 同一性を raw のバイト列にし、状態を判定しない |
| 話者とターンの境界を、本文の形や位置から推せる | 記録ごとの属性と `parentUuid` のつながりで決める |
| 今の中身を探せば、変更が当たったかが分かる（書く段） | 書く段を分けた。方針は、前と後のハッシュの日誌で判定する |
| パスの検査で、wiki の書く先が raw と重ならないことを示せる | 読み取り専用と、最後のハッシュの照合にした |

## 主張と行き先

| 候補 | 主張と成り立つ条件 | 根拠の位置 | 行き先 | 理由 |
| --- | --- | --- | --- | --- |
| 記録の構造 | `uuid` を持つ記録は 4 種類で、返答の宛先は `parentUuid` でたどれる。キューに入った人の発言は `attachment` にしか残らない（2026-11-14、Claude Code 2.1.309〜2.1.321 の検証環境の記録） | 設計書の「背景」、再設計の `results/A.md` と `reviews/B.md` | create | [[セッションの記録の構造]] |
| Edit と Write の競合 | Write は読んだあとに変わったファイルを拒み、Edit は今の中身に当たるが原子的でない。読み取り専用のファイルは、Windows では Write と Edit が `EPERM` で失敗する（Claude Code 2.1.321） | `concurrency-check.md`、設計書の 9 節の手順 8 | create | [[editとwriteの書き込みの競合]] |
| 推して得る作りの失敗 | 安全に関わる事実を、書き手の結果として持たずにあとから推すと、レビューのたびに新しい反例が出る | `root-causes.md`、再設計の `summary.md`、`design-review-4.md` | source_only | 1 つの設計の経緯で、まだほかの設計で確かめていない |
| 書く段の方針 | wiki の書き込みを、ロックを持つ 1 つのプロセスに移す | `docs/plans/wiki-apply-2026-11-14.md` | source_only | 方針だけで、設計とレビューはこれから |
