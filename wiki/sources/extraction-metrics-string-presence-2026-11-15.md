# 経験: 抽出の指標が文字列の有無だけを見て反例を見逃した（2026-11-15）

`/wiki:learn` で記録した経験である。raw は `raw/experiences/extraction-metrics-string-presence-2026-11-15.json`（ファイルの SHA-256 は `def2d0757e195430a2565a405a3d9728510d31f46fb49f0ec3c6b9d1eab176f1`）。結果は failure。ベンチマークは [[抽出の方式の比較-markitdown-2026-11-15]] にある。

## 観測したこと

- 最初の指標は、空白と Markdown の記号を消してから、正解の文字列が出力にあるかを見ていた。
- Sol の 1 回目のレビューが、混線した出力で読み順が 1.0 になること、列のずれた表を正しい表と同じに数えること、表を 1 行につないだ出力が満点になることを示した。
- 直したあと、2 回目のレビューが、右へ 1 列ずれた表を満点にすること、10 倍にした数値の網羅率が 1.0 のままであること、区切りの行のない「|」の行を表とみなすことを示した。
- 照合の単位を変えたあと、自己試験の 15 個の assert が通り、expenses.pdf の MarkItDown の列のそろった表の行は 3/7 に、slides.pdf の MarkItDown の順に読めた割合は 0.909 に下がった。

## 原因についての仮説

比べる前に空白を消し、文字列があるかだけを見たので、数値の境目、表の列、文の混線が指標から消えた（仮説）。

## 適用範囲と反例

抽出や変換の出力を、正解の文字列と照らして数えるとき。直した指標は 3 回目のレビューを受けていない。文の意味は機械の指標では見ていない。短い数値の正解は、境目を見ても別の場所の同じ数値に当たりうる。

モデルは Claude Opus 5.5（計測）と GPT-6.1 Sol（レビュー）。道具は Codex CLI 0.166.0、Python 3.12.13、uv 0.12.2、markitdown 0.1.9。
