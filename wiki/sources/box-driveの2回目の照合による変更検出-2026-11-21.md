# Box Drive で1回目と2回目の照合の間に変更されたログを検出した試験

前回と同じ Box Drive 上の検証用 wiki、Windows 11 ホスト、Hyper-V 上の Windows 11 VM を使った。対象は `concepts/guide.md`、`index.md`、`log.md`。前回の確定版と同じ照合用 JSON を使い、元のログは VM の Box 外に保全した。[[box-driveの同じ更新日時とサイズでの引き継ぎ待機-2026-11-21]]

VM の計測用ラッパーが通常の `check` と同じ処理を呼び出し、2 回目の読み取りを始める直前に別プロセスで `log.md` を書き換えた。スクリプト本体と照合・判定の処理はそのまま使った。1 回目の照合終了、ログの書き換え、2 回目の照合開始の順序は VM の計測時刻で照合した。

## 実測結果

| 段階 | 記事と `index.md` | `log.md` | 判定（終了コード） |
| --- | --- | --- | --- |
| 同じ実行の 1 回目 | SHA-256 一致 | SHA-256 一致 | 2 回目の照合へ進む |
| ログ変更後の 2 回目 | SHA-256 一致 | 不一致（`mismatch`） | 待機（1） |
| 元の内容へ戻して通常のコマンドを再実行 | SHA-256 一致 | SHA-256 一致 | 引き継ぎ可（0） |

競合コピーは全段階で 0 本だった。元の内容に戻した後、ホストと VM の再照合でも 3 ファイルの SHA-256 が一致した。試験では 1 回目の照合終了後、2 回目の照合開始前に書き換えを完了させた。
