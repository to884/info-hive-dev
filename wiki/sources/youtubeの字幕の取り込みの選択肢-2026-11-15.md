# YouTube の動画の字幕を wiki に取り込む方法の選択肢（2026-11-15）

YouTube の動画の字幕（トランスクリプト）を取り、要約を wiki に取り込む方法を調べ、選択肢を並べた調査である。原本は `docs/research/wiki-youtube-transcript-2026-11-15.md`（PR #131 でマージ）。字幕の本文の取り方（A1〜A8）と、プラグインへの組み込み方（B1〜B4）を分けて整理した。

まだ何も決めていない。決めるときは ADR にする。[[抽出の方式の比較-markitdown-2026-11-15]] で挙がった、対応する形式を広げる構想の 1 つ（YouTube）にあたる。

## 進め方

- 字幕を取る道具、公式の API、モデルの API、手元での文字起こしの道具を Web で調べた。弾かれる問題を書いた記事の多くはプロキシやホスト型 API の販売元によるもので、主張の根拠には PyPI、yt-dlp の wiki、Google の文書を使った。
- この PC（Windows 11、自宅の回線）で、公開動画 1 本を使い、今の `wiki_fetch.py` と yt-dlp 2026.08.19 を 1 回ずつ試した。検証の環境での観測で、利用者の環境での動きは保証しない。

## 分かったこと

- 今の `/wiki:ingest` に YouTube の URL を渡すと、`text/html` なので Web ページの経路（`wiki_fetch.py`）に進む。raw に残ったのはページの下のリンク（概要、プレスルーム、著作権…）だけで、字幕は入らなかった。
- 今すぐ使える方法は、字幕の本文を `.md` か `.txt` にして `raw/` に置き、文字起こしとして取り込むことだけである。
- yt-dlp の `--skip-download --write-subs --write-auto-subs --sub-format json3` で、投稿者の字幕（`ja`、`en`）、自動字幕（`en-orig`）、自動翻訳（`ja`）を区別して取れた。PO Token は求められなかった。ただし、JS の実行環境（deno）がないという警告が毎回出た。
- 英語の自動字幕には、句読点の位置のずれと聞き違いがあった。
- 公式の YouTube Data API の `captions.download` は、動画を編集する権限を求めるので、他人の動画には使えない。
- youtube-transcript-api（1.2.5）は軽いが、クラウドの IP は弾かれやすい。Gemini API は YouTube の URL を受け付けるが、字幕そのものを返す API ではなく、raw の原本にならない。

候補として、yt-dlp で字幕を取るスクリプト（A2）を作り、取り込みに動画の分岐を足す（B2）案を挙げた。字幕のない動画は、利用者が求めたときだけ、手元での文字起こし（A7）で補う。

決めておくこととして、整えた字幕や訳文を raw とみなすか（Web ページの訳文を raw に置く ADR-0004 が前例）、frontmatter の項目（URL、`video_id`、字幕の種類、言語、元の字幕の SHA-256）、時刻付きのリンクでの引用、利用者に求める依存、公式でない取り方の壊れやすさと規約を挙げた。
