# 次の版に追い越されたあとの wiki 0.15.0 のリリースの記録

2026-11-14 の、wiki 0.15.0（raw の段をエージェント `wiki:web-raw` に任せる変更）のタグと GitHub リリースの記録である。変更の設計は `docs/plans/wiki-web-raw-agent-2026-11-14.md`、実地の確かめは [[rawの段を任せるエージェントの確かめ-2026-11-14]]、モデルの決定は [[ingestに使うモデル]] にある。このページは、リリースの作業の記録から書いた。

## 経緯

1. 子の PR（to884/info-hive-wiki#58）と親の PR（to884/info-hive-dev#103）が 2026-11-14 にマージされ、wiki の main の `plugin.json` は 0.15.0 になった（マージコミット `5adb069`）。タグと GitHub リリースは作られなかった。
2. 同じ日に、セッションの取り込みの PR（to884/info-hive-wiki#59、to884/info-hive-dev#107）がマージされ、main は 0.16.0（`8c400d7`）になった。0.16.0 もタグとリリースがないままだった。
3. 作者が「0.15.0 のリリースは可能か」と聞いた。`git fetch` で、最新のタグが v0.14.1 で、v0.15.0 と v0.16.0 がないことを確かめた。リリースを進めているセッションはなかった。作者は 0.15.0 だけを出すと決めた。
4. 注釈付きのタグ `v0.15.0`（`v0.15.0: URL の取り込みの raw の段を Sonnet のエージェントに任せるようにした`）を `5adb069` に付けて push した。タグの時点の `plugin.json` が 0.15.0 であることを確かめた。
5. GitHub リリース `v0.15.0` を作った。本文は、`5adb069` の CHANGELOG の 0.15.0 の節である。`--latest` を付けたので、v0.16.0 を出すまでは v0.15.0 が Latest になる。
6. 使い捨ての設定でマーケットプレイスから入れると、0.16.0 が入った（[[リリースの確かめ方]]）。0.15.0 そのものは、マーケットプレイスからは入れられない。
7. かわりに、v0.14.1 から v0.15.0 までに変わった 11 のファイルを、入った 0.16.0 と比べた。0.16.0 で変わっていない 4 つ（`agents/web-raw.md`、`skills/info-hive/references/web-raw.md`、`skills/info-hive/scripts/wiki_fetch.py`、`skills/info-hive/scripts/wiki_rawcheck.py`）は、SHA-256 がタグの中身と一致した。違った 7 つは、どれも v0.15.0 から main までに変わったファイルだった。

## 決めたこと

- 次の版が main に入ったあとでも、前の版のタグは、その版のマージコミットに付ける。main の先頭には付けない。
- 0.16.0 は、このとき出さなかった。作者が 0.15.0 だけを選んだ。
