# /wiki:query の検索の説明への外の語の漏れの直しと wiki 0.21.2 のリリース

`/wiki:query` の回答で、どう探したかを説明する文に wiki の外の知識が入る漏れを直し、wiki 0.21.2 として出した記録である。0.21.1 の測り直しで残った問題を扱った（[[queryの確からしさの決め方の分離とリリース-wiki-0.21.1]]）。測定の原本は `docs/research/wiki-query-confidence-sonnet-2026-11-16.md` の「検索の説明への外の語の漏れの直し」の節にある。レビューの原本は `docs/agent-runs/2026-11-16-wiki-query-search-terms/` にある。

## 原因

- 0.21.1 の決まりは「自分の知識で思い付いた答えを、検索に使った語として回答に書かない」だった。
- 漏れた回は、この決まりの書かれた手順（コマンドの手順 7、`query-confidence.md`）を読んだうえで破っていた。原因は決まりの置き場所ではなく、文面にあると見た。
- この文面では、どの語が答えに当たるかを、エージェント自身が判断することになる。Claude Sonnet 5.5 が書いた語は、略語を展開した語（Command Query Responsibility Segregation）、訳した語、ライブラリの別名（`fitz`、`MuPDF`）、答えの語（Rust）だった。

## 直したこと

- 回答のうち wiki の内容を述べない部分を、1 つの決まりにまとめた。どう探したかの説明と、取り込むとよいソースの提案の 2 つである。どちらにも、自分で選んだ語を書かない。
  - 探した語として示すのは、質問文にそのままある語だけにする。ほかの語は「言い換えた語でも探した」とだけ書く。
  - ソースは、資料の種類と、質問文か wiki にある語で示す。自分の知識で、題名、著者、URL を挙げない。
- 判断に頼らず、字句で決まる決まりにした。置き場所は、コマンドの手順 4c とクエリのワークフローの手順 5 である。手順 7 と `query-confidence.md` からは、そこを指す。
- 答えの語を含む否定の例（「『Rust』で検索したが…」）は、答えを含まない書き方の例に替えた。否定の例は、避けたい型そのものを見せてしまう。

## レビューで直したこと

Sol の敵対的レビューを 2 回受けた。決まりの文は 2 回とも崩されなかった。指摘は、測定の照合の作りに集まった。

- 1 回目の照合は、回答から「検索を述べた文」を推し量り、その中の引用を数えていた。これでは、引用符のない語、「調べた」「照合した」の言い回し、箇条書きを見逃した。そこで、問いごとに「出てはならない外の語」を決め、回答のどこかに出たかで判定するようにした。
- 2 回目の指摘は 2 つだった。
  - 答えが「C」の 1 文字の問いは、字句で見分けられない。そこで、問いを答えに特徴のあるもの（sqlite-vec の作者）に替えた。
  - 最終の回答がない回を「漏れなし」と数えていた。そこで、こうした回は判定できない回として分けた。
- 取り込む候補から題名、著者、URL を外したのは、Sol の指摘を受けて足した部分である（候補の名前に答えが入る経路。再現はしていない）。この部分だけの効き目は、測定では切り分けられていない。

| 外の語が回答に出た（Q09〜Q11） | 5/9 | 0/9 |

> 測り直しの表 補足：0.21.1 の 5/9 は、新しい照合で数え直した値である。目視で数えた 3/6 では、Q10 の `fitz` と `MuPDF` を見落としていた。費用は合わせて 4.04 USD だった。

- 合否は、照合のスクリプトだけでなく、回答をすべて読んで決めた。照合が見つけられるのは、登録した表記だけだからである。
- 最初の 15 回は、最新の wiki で流した。この wiki には、0.21.1 の測定の記録のページが入っている。Q11 の 2 回は、Grep の結果で、その記録の「答え（Rust）を検索語として回答に書いた」という行を見ていた。そこで、記録のページを含まない wiki（`4b3f578`）で Q11 を流し直し、3 回とも漏れがないことを確かめた。
- Q09 の 1 回目は、自分の知識で訳した語で検索したが、回答には書かなかった。検索に使うのはよく、回答に書かない、という決まりのとおりの形である。
- 決まりの文のとおりではない書き方が 2 つあった。どちらも答えは含まない。
  - 質問を言い換えた語を、探した語として書いた回（Q13 の 3 回目）。
  - 取り込む候補に「PKCE を定めた仕様（RFC）」を挙げた回（Q12 の 3 回）。
- 答えのある問い（Q01〜Q08）は流していない。

## リリース

1. 子の PR（to884/info-hive-wiki#73）と、親の PR（to884/info-hive-dev#146）を作った。子の CI 4 件と、子の先頭を指した親の CI 17 件が通ってから、子の PR をマージした（`9fa01b6`）。Codex の PR レビューは、どちらも指摘なしだった。
2. 注釈付きのタグ `v0.21.2` と GitHub リリースを作った。本文は CHANGELOG の 0.21.2 の節である。
3. 使い捨ての設定でマーケットプレイスから入れ、0.21.2 が入ることを確かめた。v0.21.1 から変わった 5 つのファイルの SHA-256 は、タグの中身と一致した。
4. 親の参照をマージコミットに付け替えて、親の PR をマージした。

並行して、同じ `query-confidence.md` と `query.md` に触れる確からしさの規則の直し（案 1〜4）が、別のセッションで進んでいた。そちらは、この版のあとに合わせることになる。
