# Box Drive 上で競合コピーが残ると編集の引き継ぎを待機する試験

前の引き継ぎ試験と同じ検証用 wiki、Windows 11 ホスト、Hyper-V 上の Windows 11 VM を使った。対象は `concepts/guide.md`、`index.md`、`log.md`。ホストで採取した照合用 JSON が前回の確定版から採取したものとバイト単位で一致することを確認した。[[box-driveの編集引き継ぎをsha256で判定した試験-2026-11-21]]

前回の競合で Box Drive が生成した別名コピー 3 本を、退避先から wiki 内の元の場所とファイル名に複製した。まず 3 本が届いた状態を照合し、次に記事と索引の別名コピーを退避してログの 1 本だけを残した。最後にログの別名コピーも退避し、両端末で再照合した。[[box-driveの旧版からの編集引き継ぎと復旧-2026-11-20]]

## 実測結果

すべての段階で、正規の 3 ファイルの SHA-256 はホストと VM で照合用 JSON と一致した。

| 段階 | wiki 内の競合コピー | ホストと VM の判定（終了コード） |
| --- | --- | --- |
| 複製前 | 0 本 | 引き継ぎ可（0） |
| 3 本とも残っている | 記事・索引・ログの各 1 本 | 待機（1） |
| 1 本だけ残っている | ログの 1 本 | 待機（1） |
| すべて退避した後 | 0 本 | 引き継ぎ可（0） |

試験用の複製は `wiki/` の外にある `recovery-archive/handoff-check-conflicts-2026-11-21/` に退避し、3 本の SHA-256 が両端末で元の競合コピーと一致することを確かめた。複製元の 3 本も元の SHA-256 で残っている。
