# title が値なしや配列のページで検索などが止まる件の修正と、wiki 0.12.2 のリリースの記録

2026-11-13 の、frontmatter の `title` が文字でないページで検索などが止まっていた件の修正と、そのリリースの記録である。原本は、Sol の敵対的レビューと対応を残した `docs/agent-runs/2026-11-13-wiki-title-list-values/` である。リリースと導入の確かめは、作業の記録から書いた。

## 経緯

1. wiki 0.12.1 の記録で、`title: [x, y]` と書くと検索が止まることを、残っている欠陥として挙げていた（[[frontmatterのリストの値]]）。作者が「title が配列のとき検索が止まる件を直して」と依頼した。
2. 調べると、値のない `title:` でも止まった。パーサーは `title:` を空の配列に、`title: [WIP]` を 1 要素の配列に読む。こうしたページが 1 つあると、次のものが止まった。
   - 検索: `collect_pages()` の `body + " " + meta.get("title", "")` が `TypeError` になる。CLI の検索のすべての機能（`--backlinks`、`--top-linked` を含む）と、MCP の `query` の索引が止まる。
   - lint の `--suggest-pages`: `nfkc()` に配列が渡って止まる。
   - グラフの抽出: 配列の `title` を sqlite に渡して止まる。
   - 閲覧（browse）は止まらないが、題名を `['x', 'y']` と表示する。
3. 配列の `title` の扱いを、作者に聞いた。「要素をつなぐ」と「題名なしとみなす」の 2 つを示し、作者は「要素をつなぐ」を選んだ。
4. 新しい `wiki_pages.text_value()` に `title` を通すようにした。検索、lint、グラフの抽出とグラフの lint、判定レイヤー、MCP の `list_index` の、`title` を読む箇所をすべて差し替えた。browse は差し替えていない。
5. 試験を先に書き、修正前の実装で失敗することを確かめてから直した。CLI、lint、グラフ、判定の経路はプラグインの `eval/scripts/test_title_values.py` に、MCP の `query` と `list_index` の経路は親の `tests/wiki/test_wiki_index.py` に置いた。
6. 評価ゲートの出力と、評価のコーパスの全クエリの `--json` の出力（170 通り）は、修正の前後でバイト単位で同じだった。文字の `title` だけのページの結果は変わらない。
7. GPT-6.1 Sol の敵対的レビューは、条件付きで採用可（確信度は中）だった。軽微な指摘 3 件に対応した（下の「途中で起きたこと」）。直しはレビューにかけ直していない。
8. 子の PR（to884/info-hive-wiki#51）と親の PR（to884/info-hive-dev#89）を出した。親の PR は、はじめ子の PR の head（`da6ba5c`）を指した。親の CI の 9 つと子の CI の 4 つが通ってから、子をマージした（`6db310e`）。
9. 親の参照を子のマージコミットに付け替えた（`3da9caa`、木の差はない）。付け替えたあとの CI の 9 つが通り、参照先が子の main の先頭と同じことを確かめてから、親をマージした（`92e669c`）。
10. タグとリリースを作る直前に取り直すと、注釈付きのタグ `v0.12.2`（`6db310e`）と GitHub リリース（2026-11-13 10:25、日本時間。GitHub の記録では 2026-11-13T01:25Z）が、すでに作者のアカウントで作られていた。作り直さず、タグの指す先と、リリースの本文が CHANGELOG の 0.12.2 の節と同じことを確かめた。
11. 使い捨ての設定でマーケットプレイスから入れ、0.12.2 が入ることを確かめた（[[リリースの確かめ方]]）。v0.12.1 から変わった 12 のファイルの SHA-256 がタグの中身と一致した。入った `wiki_search.py` で、`title: [甲板, 乙板]` と `title:` のページがあっても検索が止まらないことも確かめた。

## 決めたこと

- `text_value()` の規則: 文字はそのまま返し、前後の空白も変えない。文字でなければ `ref_values()` でそろえ、要素を「, 」でつなぐ。値がないか空の配列なら `""` を返し、呼ぶ側がスラッグや見出しを使う。
- 文字の `title` の結果を 1 バイトも変えない。検索の語（トークン）には、今までどおり `title` だけを足し、`title` がなければ何も足さない。スラッグで補うのは表示の側だけである。トークンまでスラッグで補うと、`title` のないページの順位が変わる。
- 依頼は検索の件だったが、同じ原因（`title` を文字と決めつけていた）で止まっていた lint とグラフも、同じ関数で直した。止まる箇所だけを 1 つずつ直すのでなく、`title` を読む箇所をすべて 1 つの関数に通した。
- browse は直さなかった。別のセッションが browse の中核を大きく変えている途中で、変更が重なる。`text_value()` を使うよう、セッションの共有メモで伝えた。
- `list_index` は、題名も見出しもない索引のファイルで、今までどおり `null` を返す。修正の前から `title: ""` のファイルでも `null` だった。
- 版はパッチ（0.12.2）にした。止まっていたのを直す修正で、新しい機能はない。

## 途中で起きたこと

- lint は、`title:`、`title: []`、`title: ""` を「`title` がない」と指摘するが、`title: [WIP]` は引用符がないことしか指摘しない。引用符付きの `title: ["WIP"]` は何も指摘しない。題名なしとみなす案では、利用者が気づけないまま題名が消える。これを作者への問いに添えた。
- Sol の指摘 3 件。
  - `list_index` が `null` を返す入力が残る。振る舞いは変えず、CHANGELOG の言い過ぎを直した。
  - グラフの lint の試験が `--decide` の経路を通らない。`--decide` の有無の 2 通りで、終了コードまで確かめるようにした。
  - 検索の `--decide` の試験が、判定できない（fail open）経路しか通らない。同梱の偽のバックエンド（`eval/decisions/fake_backend.py`、127.0.0.1）で判定が成功する経路を通し、判定モデルに渡る題名を確かめる試験を足した。
- リリースの本文と CHANGELOG の節を比べたとき、はじめは「違う」と出た。CHANGELOG の節を Python の標準出力で取り出したときに、改行が CRLF に変わっていたためである（[[pythonの書き戻しの改行]]）。
- 偽のバックエンドを止めるとき、`server.shutdown()` だけでは待ち受けのソケットが残り、`ResourceWarning` が出た。`server.server_close()` も呼ぶようにした。
