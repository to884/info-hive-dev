# YouTube の字幕の取り込みの設計の記録（ADR-0027）

2026-11-15 の、YouTube の動画の字幕を `/wiki:ingest` で取り込む設計の記録である。原本は ADR-0027（提案、PR #134 でマージし、2026-11-16 に字幕の訂正と confidence を足した）で、GPT-6.1 Sol の 8 回の敵対的レビューと、固定した yt-dlp で確かめたスクリプトと結果は `docs/agent-runs/2026-11-15-adr-0027-review/` にある。[[youtubeの字幕の取り込みの選択肢-2026-11-15]] の A2（yt-dlp で字幕だけを取る）と B2（取り込みに動画の分岐とスクリプトを足す）を組み合わせた。作者は 2026-11-16 に ADR を承認し、wiki 0.23.0 で実装して出荷した（[[youtubeの字幕の取り込みの実装とリリース-wiki-0.23.0]]）。実装のレビューで、印の読み方と照合の決まりを改めた。

## 経緯

1. 1 版目は、トラックの名前の `-orig` で元の自動字幕と自動翻訳を見分け、字幕を Markdown の行にし、raw のバイト列で同じ取り込みを決めていた。1 回目のレビューは却下（重大 4）だった。名前の推し方、字幕の中の記法、道具の版を上げるだけで別版になること、予告編の動画に移った結果に気づけないことを突かれた。
2. 2 版目は、トラックの種類を字幕の URL の引数（`tlang` の有無）で決め、外から来た文字をフェンスと引用符の中にだけ置き、json3 の SHA-256 で同じ資料を決め、返った動画の ID を照らす形にした。2 回目のレビューは却下（重大 1）だった。同一性の判定にトラックの名前が残っていて、同じ字幕に `-orig` が付くかどうかで別版になった。
3. 3 版目は、同一性を `video_id` と json3 の SHA-256 の 2 つだけにし、スラッグによらず同じ動画の raw を探す形にした。3 回目のレビューは採用可（軽微 3）だった。軽微な指摘は仕様の書き漏れを埋めて直し、4 回目は行わなかった。その直しはレビューを受けていないと ADR に書いた（[[敵対的レビューで設計を直す進め方]]）。
4. Sol が挙げた yt-dlp の振る舞い（元の字幕を `-orig` の付いた名前と付かない名前の両方で登録する、訳したトラックに `tlang` を付ける、予告編の結果を返す）は、固定した 2026.08.19 のソースを読んで確かめ、ADR に行の番号を書いた。
5. 2026-11-16 に作者が、自動字幕の聞き違いを取り込むときに訂正し、何を訂正したかを利用者に伝え、訂正の多いソースは confidence を下げるよう求めた。4〜7 回目のレビューはどれも却下（重大 4、3、3、1）で、重大の多くは直しで足した記録の形から出た。表を要約ページごとに持つとページを分けるだけで値が下がり、raw ごとに 1 つにするとページの大きさの上限を超え、時刻と語で出現を指すと同じ秒の 2 つの行を区別できなかった。raw の行に番号を振り、文の中の印と、ページの下の定義で残す形にして、8 回目で採用可（軽微 2）になった。軽微な 2 件への直しはレビューを受けていない（[[敵対的レビューで設計を直す進め方]]）。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| 取り方と依存 | `wiki_youtube.py` を `uv run --script` で動かし、PEP 723 で yt-dlp の版を 1 つに固定して、字幕だけを取る。Python の範囲は ADR-0026 に合わせる。JS の実行環境は求めず、yt-dlp の警告を利用者に伝える |
| 経路 | `/wiki:ingest` は、Web ページの経路より先に動画の分岐に進む。`wiki_fetch.py` は、リダイレクトの先も含めて YouTube の URL を拒む。再生リストとチャンネルは止まる。返った動画の ID が URL の ID と違えば止まる |
| トラック | 投稿者の字幕（`subtitles`）と、`kind=asr` で `tlang` のない元の自動字幕だけを使う。自動翻訳は使わない。決まらなければ推して選ばずに止まり、利用者が `--track` で選ぶ |
| raw | スクリプトだけが `inspect`（何も書かない）と `write`（1 回で、重ねて書かない形で書き、読み取り専用にする）の 2 段で作る。字幕、題名、チャプターの題名は、フェンスか frontmatter の引用符の中にだけ置く。字幕の各行に、スクリプトが番号（`L123`）を振る。説明文、取得の時刻、字幕の URL は入れない |
| 同じ資料 | `video_id` と json3 の SHA-256 で決め、`<RAW_ROOT>` の直下をスラッグによらず探す。違う字幕なら別版のスラッグで書くかを利用者に聞く |
| 自動字幕 | 要約ページの冒頭に自動字幕から書いたと書く。聞き違いと考えた語は、raw でなく要約ページと関係するページの文で訂正し、語の直後に `〔訂正 L123-1〕` の印、ページの下に字幕の語と訂正した語と根拠の定義を置く。正しい語を決められない語と、利用者が退けた訂正には `〔留保 L123-1〕` を付ける。取り込みの計画の承認を求めるときに、定義の一覧を利用者に示す。`asr` のソースからは型付きのエッジを書かない |
| confidence | 親の要約ページの frontmatter に `high`、`medium`、`low` で書く。出発点は字幕の種類（投稿者の字幕は `high`、自動字幕は `medium`）で、下げる方向だけに動かす。raw に根拠のある訂正は重み 1、モデルの知識だけの訂正と留保は重み 3 で、合計が字幕の行数の 3% 以上なら `low` にする（仮の値）。`wiki_youtube.py verify` と lint が照らす。ADR-0028（回答の確信度、承認）の上限の行は、実装の PR（wiki 0.23.0）で `query-confidence.md` の表に足した（0.21.1 で手順 5b から移った） |
