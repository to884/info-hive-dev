# YouTube の字幕の取り込みの設計の記録（ADR-0027）

2026-11-15 の、YouTube の動画の字幕を `/wiki:ingest` で取り込む設計の記録である。原本は ADR-0027（提案、PR #134 でマージ）で、GPT-6.1 Sol の 3 回の敵対的レビューと、固定した yt-dlp で確かめたスクリプトと結果は `docs/agent-runs/2026-11-15-adr-0027-review/` にある。[[youtubeの字幕の取り込みの選択肢-2026-11-15]] の A2（yt-dlp で字幕だけを取る）と B2（取り込みに動画の分岐とスクリプトを足す）を組み合わせた。実装はまだである。

## 経緯

1. 1 版目は、トラックの名前の `-orig` で元の自動字幕と自動翻訳を見分け、字幕を Markdown の行にし、raw のバイト列で同じ取り込みを決めていた。1 回目のレビューは却下（重大 4）だった。名前の推し方、字幕の中の記法、道具の版を上げるだけで別版になること、予告編の動画に移った結果に気づけないことを突かれた。
2. 2 版目は、トラックの種類を字幕の URL の引数（`tlang` の有無）で決め、外から来た文字をフェンスと引用符の中にだけ置き、json3 の SHA-256 で同じ資料を決め、返った動画の ID を照らす形にした。2 回目のレビューは却下（重大 1）だった。同一性の判定にトラックの名前が残っていて、同じ字幕に `-orig` が付くかどうかで別版になった。
3. 3 版目は、同一性を `video_id` と json3 の SHA-256 の 2 つだけにし、スラッグによらず同じ動画の raw を探す形にした。3 回目のレビューは採用可（軽微 3）だった。軽微な指摘は仕様の書き漏れを埋めて直し、4 回目は行わなかった。その直しはレビューを受けていないと ADR に書いた（[[敵対的レビューで設計を直す進め方]]）。
4. Sol が挙げた yt-dlp の振る舞い（元の字幕を `-orig` の付いた名前と付かない名前の両方で登録する、訳したトラックに `tlang` を付ける、予告編の結果を返す）は、固定した 2026.08.19 のソースを読んで確かめ、ADR に行の番号を書いた。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| 取り方と依存 | `wiki_youtube.py` を `uv run --script` で動かし、PEP 723 で yt-dlp の版を 1 つに固定して、字幕だけを取る。Python の範囲は ADR-0026 に合わせる。JS の実行環境は求めず、yt-dlp の警告を利用者に伝える |
| 経路 | `/wiki:ingest` は、Web ページの経路より先に動画の分岐に進む。`wiki_fetch.py` は、リダイレクトの先も含めて YouTube の URL を拒む。再生リストとチャンネルは止まる。返った動画の ID が URL の ID と違えば止まる |
| トラック | 投稿者の字幕（`subtitles`）と、`kind=asr` で `tlang` のない元の自動字幕だけを使う。自動翻訳は使わない。決まらなければ推して選ばずに止まり、利用者が `--track` で選ぶ |
| raw | スクリプトだけが `inspect`（何も書かない）と `write`（1 回で、重ねて書かない形で書き、読み取り専用にする）の 2 段で作る。字幕、題名、チャプターの題名は、フェンスか frontmatter の引用符の中にだけ置く。説明文、取得の時刻、字幕の URL は入れない |
| 同じ資料 | `video_id` と json3 の SHA-256 で決め、`<RAW_ROOT>` の直下をスラッグによらず探す。違う字幕なら別版のスラッグで書くかを利用者に聞く |
| 自動字幕 | 要約ページの冒頭に自動字幕から書いたと書き、確かめられない固有名詞と数値に留保を付ける。同じソースから書いたほかのページの文にも付ける。型付きのエッジは書かない |

## 主張と行き先

| 候補 | 主張と成り立つ条件 | 根拠の位置 | 行き先 | 理由 |
| --- | --- | --- | --- | --- |
| 名前で推す作りが崩れた | トラックの種類を名前で推す作りと、同一性に別名（トラックの名前）を使う作りが、続けて崩れた。字幕の URL の引数と、原本のバイト列に替えると崩れなかった | `review-1.md`、`review-2.md`、ADR の「理由」 | update | [[敵対的レビューで設計を直す進め方]] の「状態を推す作り」の項に、3 つ目の設計として足した |
| 選択肢の調査の行き先 | A2 と B2 を組み合わせた ADR を提案した | ADR の「背景」 | update | [[youtubeの字幕の取り込みの選択肢-2026-11-15]] の「まだ何も決めていない」を、ADR への案内に改めた |
| トラックの見分け方 | 字幕の URL に `tlang` がなければ元の言語の字幕である。yt-dlp と YouTube の公開の仕様ではない | ADR の「背景」、固定した yt-dlp の `_video.py` の L4305〜L4327 | source_only | yt-dlp の 1 つの版のソースと 2 本の動画で確かめただけで、実装もまだである |
| json3 のバイト列の安定 | 同じ動画の json3 は、別々に取った 2 回で SHA-256 が一致した。日をまたいだときは試していない | ADR の「背景」、`probe/` の結果 | source_only | 観測が少なく、同じ資料の決め方の前提として見直す条件に挙げてある |
| 外から来た文字の置き場所 | フェンスか引用符の中にだけ置けば、字幕の中の記法が Markdown として読まれない | ADR の「理由」、`review-3.md` の「検証した事実」 | source_only | ADR-0020 のセッションの raw と同じ決まりで、実装の試験で確かめる前である |
