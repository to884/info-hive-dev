# 翻訳を省略した取り込みの完了を防ぐ wiki 0.31.1 の修正

翻訳が必要な Web raw に `--language-override keep` を指定し、英語のまま保存した状態を完了としていた。日本語の要約があっても raw の翻訳の代わりにはならない。プラグインの修正は to884/info-hive-wiki#87、回帰試験と記録は to884/info-hive-dev#171 で扱う。

## 完了を決める記録

W8 の JSON に `translation` と `completed` を追加した。`ok: true` は検査に誤りがないことを表し、`completed: true` は必要な警告の確認を終え、`--finish` が成功した場合だけ返す。フォルダーの消失や翻訳者名から完了を推定しない。翻訳必須の `keep` はエラーとなり、`--accept-warnings` でも完了できず、比較元が残る。

警告を受理する場合は、wiki の更新より前に `prepare` の記録に理由を書き、実際の完了の JSON を確認する。raw の確認を終える前に取り込みの完了を記録しない。この区別を Claude Code、Codex、raw のエージェント、セッションの監査でそろえた。

## レビューで変えた判定

初回の Opus のレビューでは、日本語の文字数の割合による判定が崩れた。製品名を英語で残した正しい見出しは拒み、段落の後半の英語や中国語の近似コピーは通していた。名前を推定して文章から除く方法も、各語を大文字で始めた文章を取り逃がした。

最終的には、残る外国語の候補を検出し、対象ごとの ID・全文・種類・具体的な保持の理由を、現在の原文と raw のハッシュに結び付けて確認する方式にした。未解決の候補はエラーで、`--accept-warnings` だけでは完了できない。有効な確認の記録も警告として親が読み、理由をログに残してから受理する。名前と文章の意味を機械で分類して、受理する方式は採らない。

検査器は記録の形式と対象への結び付きを調べる。保持の分類・理由の意味、訳の正しさや完全性は確認者が読む。漢字の多い日本語の見出しも対象になるため、委譲時の警告の返却と親による全件確認を通常の経路にした。同一文に混ざる外国語の語など、検出できない形もある。自己確認は独立したレビューではなく、理由の意味や `prepare` のログの順序も機械では保証しない。確認の記録を翻訳の代用にしない。これは、実行したことを記録で決める範囲と、内容を読んで判断する範囲を分ける実例になった（[[エージェントに守らせる決まりの書き方]]）。

## 検証

関連テスト 373 件は失敗なし（環境による 7 件をスキップ）、encoding の静的検査は 62 ファイルで成功した。保存済みの記事を一時 wiki の fixture に置く検査では、英語のままの 2 ケースは未完了で比較元が残り、日本語版は固有名の保持 3 件と日本語 11 件の確認記録、既知の警告 4 件を確認して完了した。この検査は実際の取り込みの受領記録ではない。実際の raw の内容は変えず、ハッシュも記録した。
