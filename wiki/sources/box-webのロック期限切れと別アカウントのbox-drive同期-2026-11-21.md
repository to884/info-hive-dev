# Box Web のロック期限切れ後に別アカウントの Box Drive が自動同期した試験

前回と同じ Box Drive の検証用 wiki を使った。ホストはフォルダーの所有者、Windows VM は別の Box アカウントで参加する編集者とした。Box Web のコラボレータ欄で編集者の権限を確認した。試験前は記事・`index.md`・`log.md` の SHA-256 が照合用 JSON と一致し、両端末で「引き継ぎ可」（0）だった。

所有者の Box Web で `log.md` を 5 分間ロックした。ダウンロードは禁止しなかった。ロック表示を確認してから VM でログを 1 回だけ保存し、書き込んだ内容を SHA-256 で読み戻した。

## ロック中の保存とアップロード拒否

VM ではローカル保存に成功した。約 6 秒後に、同じファイル ID へのアップロード失敗が VM の Box Drive ログに `403 ITEM_LOCKED` と記録された。保存から約 43 秒後までに試験版の SHA-1 を返す Box の応答はなく、ホストは元のログを読んだ。

## 期限切れ後の自動同期

VM で再保存や手動リトライをせず、5 分間のロックが失効するまで待った。ロック設定操作から約 5 分 32 秒後に VM が受け取った Box の応答と、約 5 分 47 秒後にホストが受け取った応答の両方で、同じファイル ID の SHA-1 が試験版と一致した。ホストの実ファイルでも試験版の SHA-256 を確認した。

Box Web は再読み込み前に以前のロック表示を出していた。再読み込みするとロック表示が消え、`log.md` は 874 バイトから 947 バイトに変わり、更新者は VM の編集者アカウントになっていた。試験版は同期済みの状態で残した。

## 引き継ぎ判定

| 照合の時点と基準 | ホスト | VM |
| --- | --- | --- |
| 試験前の内容を試験前の JSON と照合 | 引き継ぎ可（0） | 引き継ぎ可（0） |
| ロック中に試験前の JSON と照合 | 引き継ぎ可（0） | 待機（1、ログのみ不一致） |
| 期限切れ後に試験前の JSON と照合 | 待機（1、ログのみ不一致） | 待機（1、ログのみ不一致） |
| 期限切れ後に同期済みの試験版の JSON と照合 | 引き継ぎ可（0） | 引き継ぎ可（0） |

いずれの照合でも記事と索引は一致し、競合コピー候補は検出しなかった。ロック中にホストが「引き継ぎ可」を返しても、VM にクラウド未反映のログが残っていた。期限切れによる再同期を 1 回実測した。繰り返し試験による所要時間のばらつきは未検証。期限前に手動解除した試験は、[[box-webの手動ロック解除とbox-driveの自動同期-2026-11-21]] を参照。
