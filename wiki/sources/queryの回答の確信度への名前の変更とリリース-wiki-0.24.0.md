# /wiki:query の回答の「確からしさ」を「確信度」に変えた wiki 0.24.0 のリリース

作者の決定で、`/wiki:query` の回答に付ける「確からしさ（confidence）」の名前を「確信度」に変え、wiki 0.24.0 として出した記録である。決め方、上限、上げる方法は変えていない（[[queryの確からしさの規則の直しとリリース-wiki-0.23.1]]）。レビューの原本は `docs/agent-runs/2026-11-16-wiki-confidence-rename/` にある。

## 変えたこと

- 回答の終わりの決まった 1 行は `**確信度（confidence）: 中**` になった。複数の結論の文の終わりは「（確信度: 高）」になった。
- プラグインでは、コマンド、決め方のファイル、ワークフロー、スキル、利用者向けの文書の 86 か所を変えた。browse のグラフのエッジの表の列名も「確信度」にした。
- 決まった 1 行の字句が変わり、前の字句を機械で数えている利用者には互換性のない変更になる。そこで minor を上げて 0.24.0 にした。0.24.0 を予定していた to884/info-hive-wiki#71 は、0.25.0 に振り直すことになる。
- ADR-0028 は承認済みなので、本文を書き換えず、「名前の追記」の節を足した。

## 「確信度」が別の意味で使われていたこと

「確信度」は、グラフのエッジの `confidence`（`low` など）と、判定モデルの答えの値（0〜1）で、すでに使われていた。回答の確信度とエッジの `confidence` が同じ文に出る箇所は、取り違えないよう「回答の確信度」「エッジの `confidence`」と書き分けた。

この重なりは、測定の要約のスクリプトでも問題になった。Sol のレビューでは、広い抽出式が「エッジの確信度: 低」も回答の印として拾う反例が、言い回しを変えて 3 回出た。字句の工夫では見分けきれないと判断し、作りを替えた。

- 新しい名前は、決まった形（決まった 1 行と結論の文末の印）だけを機械で読む。
- 広い抽出は、回答の意味でしか使っていない前の名前だけを読む。
- 新しい名前の崩れた書き方は、回答を読んで判断する。

3 回目の判定は採用可だった。残った反例は、エッジの値を決まった形（「（確信度: 低）」）で書いた回答だけである。これは回答の書き方の誤りなので、読めば見分けられる。

## wiki のページの直し方

確からしさを扱う 11 ページ（index を含む）の地の文と title を「確信度」にした。変えていないものは次の 4 つである。

| 変えないもの | 理由 |
| --- | --- |
| ページ名（スラッグ）と `[[リンク]]` | 変えるとリンクが切れる |
| frontmatter の `sources` のページ名 | ページ名と同じ |
| 当時の版の字句（バッククォートの中、「（確からしさ: 高）」） | その版で実際に使っていた字句という事実である |
| `log.md` の過去の行 | 時系列の記録である。名前を変えたことは 1 行足した |

> 変えないもの 補足：親の main を取り込んだとき、main 側で同じ行が書き換わっていたページが 1 つあった。main の行を取り、同じ規則で置き換え直した。

## リリース

1. 子の PR（to884/info-hive-wiki#77）と、親の PR（to884/info-hive-dev#156）を作った。子の CI 4 件と、子の先頭を指した親の CI 17 件が通ってから、子の PR をマージした（`2eb8ac4`）。Codex の PR レビューは、どちらも指摘なしだった。
2. 注釈付きのタグ `v0.24.0` と GitHub リリースを作った。本文は CHANGELOG の 0.24.0 の節である。
3. 使い捨ての設定でマーケットプレイスから入れ、0.24.0 が入ることを確かめた。v0.23.2 から変わった 10 個のファイルの SHA-256 は、タグの中身と一致した。
4. 親の参照をマージコミットに付け替えて、親の PR をマージした。
