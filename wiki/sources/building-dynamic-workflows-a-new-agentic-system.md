# Building Dynamic Workflows: A New Agentic System

Fareed Khan による Medium（Level Up Coding）の記事で、2026年10月19日の公開、会員限定である。リードモデルが計画の全体を短い Python のプログラムとして一度だけ書き、素の Python が多数のワーカーを並列に動かして実行する「動的ワークフロー」を、部品ごとに組み立てて評価する。原本は `raw/building-dynamic-workflows-a-new-agentic-system.md`（Claude Sonnet 5.5 の訳）である。会員として開いた普段のブラウザのタブから本文を取った。画像 19 枚は取得できておらず、図そのものは読んでいない。評価の数字は、本文の文章と出力のコードブロックから取った。

## 組み立てる題材

849 個の Python ファイル（約 135 万トークン）のライブラリに、著者が 72 個のバグを 1 つずつ埋め込み、エージェントに見つけさせる監査である。バグは、ファイルの doctest を少なくとも 1 つ失敗させる 1 行の編集で、エージェントが読むコピーからは doctest を取り除いてある。採点器は、正しいファイルと関数を挙げ、バグから 5 行以内を指した指摘だけを数える。再現率は 72 個に対する割合、適合率は報告した場所に対する割合である。キーの外の場所は誤検知に数えるので、適合率は下限である。

## 設計の段

1. **偵察する。** 素のコードが、約 500 トークンのファクトシート（ファイル数、トークン数、価格、上限、予算）を書く。
2. **計画を立てる。** リードがシートだけを読み、短い Python のプログラムを書く。
3. **検査する。** 構文と名前のホワイトリスト、80 行と 6,000 文字の長さの上限、`result` の代入を求める規則で、費用の前に拒む。
4. **リハーサルする。** 無料の代役モデルで計画を 1 回実行し、ワーカーの数と費用を見積もる。
5. **承認する。** 自動の上限（40 クレジット以下、予算の 3 分の 1 以下）を超える計画は、人が決めるまで保留する。
6. **実行する。** 1 つの予算のもとで、バックグラウンドの実行として動かす。

部品は、回答を質問の指紋で保存する台帳（同じ質問に二度払わない、クラッシュ後の再開）、予算の上限で待つメーター、ワーカーごとの会話の記録、スキャン・懐疑者の検証・投票・報告の監査キットである。

## 測定

| 設計 | ラン数 | 再現率の平均 | 適合率の平均 | 費用の平均（クレジット） |
| --- | --- | --- | --- | --- |
| A: エージェント 1 つだけ | 3 | 0.02 | 1.00 | 23.7 |
| A2: 動的ランの予算を与えた 1 つ | 2 | 0.04 | 0.78 | 46.4 |
| B: ヘルパーを使うリード | 1 | 0.17 | 0.67 | 10.3 |
| C: 人が書いた固定計画 | 3 | 0.30 | 0.82 | 13.8 |
| D: 動的ワークフロー | 3 | 0.45 | 0.71 | 48.4 |

- D の再現率は、A より +0.30〜+0.56、C より +0.06〜+0.25 高い（ブートストラップの 95% 区間）。費用は C の約 3.5 倍である。
- 著者は、14 回スキャンさせた固定計画を実行していない。D の向上を「多く読んだこと」と「良く計画したこと」に分けられない。
- 事前に書いた 11 個の予測のうち、成り立ったのは 3 個（H1、H1b、H5）である。懐疑者の効果（H4）は適合率が +0.25 高まったが、区間の下端が +0.15 に届かず、再現率も最大 0.069 下がりうる。失敗する呼び出しを実行する効果（H6）は成り立たなかった（0.84 対 0.85）。
- リードの 1 回の計画の呼び出しが読んだのは 1,780 トークンで、エージェント 1 つだけは 1 つのプロンプトに最大 91,171 トークンを抱えた。
- 予算を 20 と 60 クレジットに絞ると、リードの計画は 8.3 と 18.1 クレジットで、バグの 28% と 39% を捕らえた。

## 著者が挙げる限界

各設計のランは 3 回以下、ライブラリは 1 つ、モデルは 1 系統で、区間は広い。動的ランが 1 つのランごとに違う計画だったので、エージェント 1 つより一貫していたとは言えない。ライブラリは公開されており、72 個の関数をモデルに書き戻させると元との類似度の中央値は 0.17 だった。ランが使ったのは 3 日間で、2,616 回の呼び出し、557.4 クレジットである。
