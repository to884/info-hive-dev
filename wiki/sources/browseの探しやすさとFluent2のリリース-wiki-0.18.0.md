# browse の探しやすさと Fluent 2 と wiki 0.18.0 のリリースの記録

閲覧（`/wiki:browse`）に、索引の木の整理、全ページの一覧と絞り込み、静的の検索を足し、画面を Fluent 2 のデザインにして、wiki 0.18.0 として出した記録である。設計は `docs/plans/wiki-browse-findability-2026-11-13.md`（8 版目）と `docs/plans/wiki-browse-fluent2-2026-11-14.md`（4 版目）、決定は ADR-0021 にある。試作、レビュー、対応の原本は `docs/agent-runs/2026-11-14-wiki-browse-fluent2/` にあり、実装のレビューへの対応は同じディレクトリの `impl-responses.md` にある。このページは、作業の記録から書いた。見た目の決まりは [[browseのデザインシステム]] にまとめてある。

## 経緯

1. 作者が、Fluent 2 化を探しやすさの設計に組み込むこと、配色の切り替えを足すこと、スキル fluent2-html-replica のパスに依存せずプラグインが写しを持つことを決めた。
2. `fluent2.css`（625,811 バイト）を書き換えずに `browse_assets/` に写し、試作で見た目の承認を得た。設計は Sol の敵対的レビューを 3 回受けた（A は 3、1、0 件）。
3. 構造の直し（0.17.0）が main に入ってから、探しやすさの設計の 10 節の順に実装した。木の 2 つ目の段は、書き換える前の中核の写し（`tests/wiki/browse_nav/core_before.py`）の上で動く参照の実装（`nav_model.py`）と、19 の例で同じ木になることを試験で確かめる。
4. 試験が、設計の誤りを 2 つ見つけた。索引のファイルのグループの番号に読めないファイルも数えると、読めない入力の約束（構造の直しの 4.1）とぶつかる（`test_browse_fs` の読む側の探索が見つけた）。ネイティブの選択は、いちばん長い選択肢の幅になり、200 文字のタグで横にはみ出す。どちらも設計書を直した。
5. Sol の実装のレビューを 4 回受けた。A は 2、1、1、0 件で、2 回目からは致命と重大が 0 件だった。4 回目で止める条件に届いた。
6. 版は 0.18.0 にした。0.17.1 は、開いている to884/info-hive-wiki#61 が使っていた。
7. 手元で、Python の試験 174 件（`test_browse_fs`、`test_browse`、`test_browse_server`）、ブラウザの `browse.test.mjs`、新しい `findability.test.mjs`、`startup.test.mjs` が通った。1,000 ページの合成の Wiki で、記事のページは 1.9 秒、索引のページは 2.2 秒だった（目安は 5 秒）。データの大きさは、`index.html` が 662 KB、`data/search.js` が 231 KB、`nav.js` が 110 KB だった。
8. 子の PR（to884/info-hive-wiki#62）の CI（Linux と Windows の 4 つ）と、子の head を指した親の PR（to884/info-hive-dev#116）の CI が通ってから、子をマージした（マージコミット `2e48a73`）。親の参照をそのコミットに付け替え、付け替えたあとの親の CI を待たずに親をマージした。子の main に、PR の head から新しいコミットがなく、参照先の中身が CI を通した head と同じ（差分が空）だったためである。[[リリースの確かめ方]] の 0.12.0 の進め方（付け替えたあとの CI を待つ）とは違う。
9. 注釈付きのタグ `v0.18.0`（本文は「v0.18.0: 閲覧の探しやすさ（木、全ページの一覧、静的の検索）と Fluent 2 の画面」）を `2e48a73` に付けて push し、GitHub リリース `v0.18.0` を作った。本文は CHANGELOG の 0.18.0 の節である。
10. 使い捨ての設定でマーケットプレイスから入れ、0.18.0 が入ることを確かめた。v0.17.0 から v0.18.0 までに変わった 14 のファイルの SHA-256 が、すべてタグの中身と一致した。入った `wiki_browse.py` で使い捨ての Wiki を書き出し、`assets/fluent2.css`、`assets/theme.js`、`data/search.js` があり、`data-theme="auto"` と一覧の行が出ることを確かめた。

## 実装のレビューで崩れた前提

| 回 | 崩れた前提 | 作りで決めた形 |
| --- | --- | --- |
| 1 | 行の順は、読み込んだときの配列で分かる | 行の順は DOM だけが持つ。Enter は DOM の今の並びで見えている先頭を読む |
| 1 | 知らない種類は `t-other` になる | 種類の札は既定で中立の色にし、色を持つのは知っている 4 つだけにする |
| 2 | `#group=` の断片は、いつも解ける | ID は URL で符号化されない文字だけなので、断片を解かずに形と木で確かめる |
| 3 | 欄が空でなければ、語で絞っている | 「語で絞っているか」は、照合と同じ `terms()` の 1 か所で決める |

4 回目の C は、試験の確かめ方の問題だった。配色の試験は、測る要素がない部品を測らずに通していた（`source` と `synthesis` の札、スコープの札、被リンク、未解決のリンク）。測れなかった部品があれば落とすようにし、状態を変えたあとは色の切り替わりが終わってから測るようにした。

## 残したこと

- 記事のページの部品（メタ欄、関係表、被リンク、診断を Fluent の Table や List にする。Fluent 2 の設計の 5 節、F2）は、まだ実装していない。0.18.0 では、記事のページの色をトークンに替えただけである。
- 5 つのブラウザ（Chromium のほか、Firefox、WebKit、Edge、Chrome）での手の確かめは、まだしていない。
