# wiki 0.11.1 の取り込み手順の追従と、wiki 0.11.1・rag 0.5.1 のリリースの記録

2026-11-12 の、rag 0.5.1 の修正（[[pdfのヘッダーの判定の修正-rag-0.5.1]]）に wiki の文書を合わせ、両プラグインをリリースするまでの記録である。原本は、Sol の敵対的レビューの依頼と結果、レビューした差分を残した `docs/agent-runs/2026-11-12-wiki-rag-pdf-header-docs/` である。

## 経緯

1. wiki の `skills/info-hive/references/ingest-workflow.md` の 18 行目が「拡張子が `.pdf` で先頭が `%PDF-` の通常のファイルだけを受け付け」と書いていた。`info-hive-wiki` の中で古い条件を書いていたのは、この 1 箇所だけだった。
2. rag の README の書き方に合わせて直し、版を 0.11.1 にした（014593f）。main はすでに 0.11.0 で、タグと GitHub リリースもあったので、次のパッチにした。
3. Sol のレビューは「条件付きで採用可」。版の条件がないことと、境界の書き方が 1 バイト狭く読めることを直した（6f8b688）。ヘッダーを確かめる段階が登録ではなく処理であることも、rag の main で確かめて書いた（[[pdfのヘッダーの条件]]）。
4. レビューの途中で to884/info-hive-rag#7 がマージされたので、wiki の文書が rag より先走ることはなくなった。
5. to884/info-hive-wiki#47 をマージし（59af357）、v0.11.1 をリリースした。親の to884/info-hive-dev#78 は、wiki の参照を PR の head からマージコミットに付け替えてからマージした（c457312）。
6. rag の v0.5.1 をリリースした（タグは 0dea049）。両方とも、使い捨ての設定でマーケットプレイスから入れて確かめた（[[リリースの確かめ方]]）。

## 途中で起きたこと

- 別のセッション（wiki の走査の修正）が、同じ wiki の 0.11.0 を準備していると知らせてきた。main ではすでに 0.11.0 が公開済みで、こちらが 0.11.1 を使ったので、相手は 0.11.2 以降になると伝えた。
- 親の #78 の CI で、`browse (windows-latest)` の静的版の試験が、`file://` のページの `page.goto` で 30 秒のタイムアウトになった。同じジョブで Playwright の導入に 6 分かかっていた（いつもはジョブ全体で 5 分ほど）。再実行で通った。ランナーの遅さによる一時的な失敗と見ているが、観測は 1 回だけである。
- Git Bash で `git show origin/main:.claude-plugin/plugin.json` を実行すると、引数が `origin\main;.claude-plugin\plugin.json` に書き換えられて失敗した。`MSYS_NO_PATHCONV=1` を付けて確かめ直した（[[git-bashのパス変換]]）。
- to884/info-hive-dev#77（rag の参照の付け替え）を「まだマージされていない」と報告したが、実際には 12:54 にマージされていた。状態を確かめた後に、取り直さないまま報告していた。

## 残したこと

- rag の README、CHANGELOG、v0.5.1 の GitHub リリースの本文は、まだ「先頭から 1024 バイト目までに」の書き方である。wiki だけを「前置きが 1024 バイト以下」に直した。2026-11-13 に rag 0.5.2 でそろえた（[[pdfのヘッダーの条件]]）。
- wiki の CHANGELOG の末尾の比較リンクは v0.7.0 で止まったままで、`[0.11.1]` の行も足していない。CONTRIBUTING.md のリリースの手順のうち、スモークテストもしていない。
- `tests/wiki` を全部流したときの 2 件の失敗と 16 件の例外は、変更前の main で同じになるかを確かめていない。
