# Box Drive 2 台で同じ行を編集したときの競合と手動復旧

Windows 11 ホストと Hyper-V の Windows 11 VM で、同じ Box アカウントと Box Drive 2.56.271.0 の Cloud Files 方式を使った。検証用 wiki は info-hive v0.39.0 で初期化した。記事・`index.md`・`log.md` の共通初版を Box と両端末で照合し、両端末で固定した。

## オフライン編集と再接続

ホストでは Box への通信をプロキシで拒否し、VM では仮想 NIC を切断した。記事では両端末が同じ 16 行目だけを書き換えた。索引では同じ要約行を置き換え、ログでは同じ末尾に自分の操作を 1 件ずつ追記した。既存ファイルを直接上書きし、切断中に編集内容のハッシュを照合した。

ホストのプロキシ解除と VM の NIC 接続を同じ時刻に予定した。再接続操作の開始差は 3.8 ミリ秒だった。

| ファイル | 正規名に残った VM 版 | 別名の競合コピーに残ったホスト版 |
| --- | --- | --- |
| `concepts/guide.md` | 水鳥の観察には双眼鏡を使う。 | 水鳥は木道から観察する。 |
| `index.md` | 双眼鏡を使うという要約 | 木道から観察するという要約 |
| `log.md` | VM の操作 1 件を追記 | ホストの操作 1 件を追記 |

再接続の基準時刻から約 1.5～1.7 秒後の Box API 応答で正規名の 3 ファイル、約 11.5～11.6 秒後の応答で別名コピー 3 本の SHA-1 を照合した。約 28 秒後の観測で、計 6 ファイルが両端末にそろった。

## 三方向マージの衝突と手動復旧

1. 共通版、正規名の VM 版、競合コピーのホスト版を Box の外に保全した。`git merge-file -p --diff3` を 3 ファイルそれぞれに実行すると、記事と索引の同じ行、ログの同じ追記位置に、各 1 か所の衝突が出た。
2. 記事の共通版「水鳥は指定の場所から観察する。」と両端末の文を照らし合わせ、観察場所と道具の指定が両立することを確認した。「水鳥は木道から、双眼鏡を使って観察する。」と手で書き直した。索引はその内容を 1 行で要約し、ログには初期化の記録と両端末の操作を 1 件ずつ残した。
3. ホストから復旧版 3 ファイルを正規名に書き戻した。保存開始から約 23 秒後の観測で、両端末と Box API の SHA-1 が一致した。両端末の SHA-256 も書き戻し前の復旧版と一致した。
4. 照合後に競合コピー 3 本を `wiki/` と同じ階層の `recovery-archive/` に移した。退避開始から約 19 秒後の観測で、退避先の SHA-1 が両端末と Box API で一致し、両端末の wiki 内の競合コピーは 0 本になった。

ホストでは書き戻し前と退避後の BM25 検索で、「木道」と「双眼鏡」の両方から記事を見つけられた。lint のリンク切れと重複スラッグは 0 件だった。時刻と正規名に残った版は、同じアカウントでの 1 回の観測結果である。
