# ページの概要の生成と表示と wiki 0.32.0

求めたページだけから図を中心にした概要を作り、元記事を編集せず保存して browse に出す変更である。保存設計第6版と表示設計第3版に従い、Astra による設計レビュー、Opus による実装レビューを経た。決定は ADR-0033。main の Codex の ADR と番号が重なったため0031から移し、過去のレビュー記録は旧番号を残している。

## 元記事と派生物を分ける

`/wiki:overview` が指定した1ページだけを読み、format 2 のサイドカーに概要の Markdown と SVG をまとめる。書くのは CLI だけで、browse からは生成・修復しない。記事と概要を同じ Snapshot から判定し、検索、見出し ID、被リンク、ページ数、グラフに概要を加えない。

browse は最初のトップレベル h1 の直後、h1 がなければ本文先頭に概要を出す。新しい概要は開き、古い概要は警告付きで閉じる。壊れた概要の本文と図は出さず、元記事を閲覧できる状態を保つ。

SVG は内容で名付けて img として配信し、Mermaid は既存の sandbox で描く。静的版は Mermaid のコードを示す。CSP と配色は [[browseの図の描画とリリース-wiki-0.26.0-0.27.0]] の仕組みを共用する。

## 読まなかったことを不在にしない

Opus の初回レビューで、記事のディレクトリをジャンクションに替えると概要を孤立と誤判定し、`remove --orphan` で消せる反例が見つかった。拒否した道とサイドカーの識別子を照合し、`page_unreadable` として削除を拒むようにした。これは [[wikiの記事リンクの拒否とリリース-wiki-0.31.0]] の「読まない」を「ない」に変えない規則を、概要にも適用したものである。

規定名のハードリンクの概要は `broken/unreadable` とし、恒久的な拒否を transient にしない。署名へ拒否の印を入れるため、サイズと更新時刻が同じままリンク数だけが戻っても、回復を検出する。

概要が壊れて識別子を読めず、読まなかった道がある場合は、不在を確かめられないので削除を拒む。人が対応と不要であることを確認した場合の手動削除を、help に復旧手順として残した。本文や図を手で編集して修復する手順ではない。

## 検証と公開

関連 Python 410件、入出力層33件、プラグイン内116件は失敗なし。最終の概要・help・ひな形・Codexの140件も失敗なし（1件skip）。5ブラウザ×静的/サーバー×明暗の20ケースで、キーボード、320px、閉じた図、配色の再描画、CSPとwiki不変を確認した。1,000ページの起動は本文中央値2.873秒、索引3.467秒で5秒基準を通過した。

Opus の実装レビューは3回。最終は採用可、確信度は中〜高で、致命的・重大は0件。親子の全 CI 成功後にプラグイン PR #90 をマージし、main の `d761c62` に注釈付きタグ `v0.32.0` を付け、GitHub リリースを2026年11月18日08:08:11（Asia/Tokyo）に公開した。

公開カタログから使い捨ての設定で Claude Code と Codex に導入し、両ホストで版0.32.0と全25変更ファイルのタグとの一致を確認した。導入先のスクリプトによる概要の保存、新旧の表示とSVGの配信、元記事の不変も成功した。モデルに生成を推論させる試験ではない。結果を [[リリースごとの導入の確かめの記録]] に追加し、[[リリースの確かめ方]] の完了条件を満たした。

Codex の公開カタログからの別の隔離導入では、2スキル・7 MCPツールを認識し、統計と日本語検索が成功した。読み取りの前後で試験用wikiはバイト単位で一致した。
