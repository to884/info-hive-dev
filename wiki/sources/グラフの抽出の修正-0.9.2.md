# wiki 0.9.2 のグラフの抽出の修正の記録

2026-11-09 から 11-11 にかけての、`info-hive-wiki` のグラフの抽出（`wiki_graph_extract.py`）の修正の記録である。原本は、Sol の敵対的レビュー 6 回の依頼と結果、指摘への対応を残した `docs/agent-runs/2026-11-09-wiki-graph-duplicate-slugs-review/` である。変更の一覧は `info-hive-wiki/CHANGELOG.md` の 0.9.2 の節にある。

## 経緯

- browse の第 1 段階の設計のレビュー（`docs/agent-runs/2026-11-09-wiki-browse-stage1-review/design-review-1.md` の重大 1）で、別のディレクトリに同じスラッグのページがあると、型付きの関係の主語が別のページのノードになることが再現した。
- 最初の修正は、主語をスラッグではなくページから引くことだけだった。そのあと、browse の設計のレビューが進むにつれて、関係表がグラフの抽出に頼る性質が決まり、2 回足された（[[グラフの抽出の契約]]）。
- 2026-11-11 に `to884/info-hive-wiki#34` と `to884/info-hive-dev#63` をマージし、0.9.2 をリリースした。`info-hive-wiki` の main は be117ad（タグ `v0.9.2`）、`info-hive-dev` の main は 7feb3c5 である。マーケットプレイスから 0.9.2 が入ることを、空の設定ディレクトリで確かめた。

## 直した不具合

1. 同じスラッグのページで主語を取り違える。パスを付けた `[[a/Foo]]` も別のページを指し、同じスラッグの 2 つのノードがあると `nodes.slug UNIQUE` に反して抽出が止まった。
2. ページの違う同じ内容の関係を、1 本のエッジにまとめる。
3. 同じページの関係の項目で、`status` などだけが違う 2 件を 1 本にまとめる。
4. 別のスラッグのページに同じ `graph.node_id` を付けると、後のページの関係が消える。
5. パスで書いた `sources:`（`sources/paper`、`[[sources/paper]]`）から `sourced_from` を作らない。

## レビューで分かったこと

- 却下は 3 回あった。NFC と NFD の名前の違いだけのファイルでエッジが消えること、`contradicts` の相互参照で ID が変わり続けること、並べ替えで ID が別の項目に移ることである。どれもエッジの ID の決め方に関わり、[[エッジの識別子]] の形に落ち着いた。
- マージの前に `info-hive-wiki` の CI が落ちた。開発リポジトリの試験しか流しておらず、`info-hive-wiki` 自身の試験（`eval/`）を流していなかったためである（[[グラフのlintの期待値]]）。
