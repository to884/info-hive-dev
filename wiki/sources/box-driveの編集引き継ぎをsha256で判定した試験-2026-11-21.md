# Box Drive 上の wiki の編集引き継ぎを SHA-256 で判定した試験

前回と同じ Windows 11 ホスト、Hyper-V の Windows 11 VM、Box Drive 上の検証用 wiki を使った。対象は `concepts/guide.md`、`index.md`、`log.md`。前回は VM に旧版が残ったまま保存すると、3 ファイルとも競合した。[[box-driveの旧版からの編集引き継ぎと復旧-2026-11-20]]

## 手順と判定

ホストで書き込む予定の 3 ファイルを Box 外に準備し、照合用 JSON を発行して VM に渡した。混在状態を作るため、ホストでは Box Drive 上の記事を先に保存し、VM で記事だけが新版になったことを確認してから索引とログを保存する手順にした。各判定では VM の Box Drive 上のファイルを開き、得られた SHA-256 をホストで保全した旧版と新版の両方に照らした。

| VM の状態 | 記事 | `index.md` | `log.md` | 判定（終了コード） |
| --- | --- | --- | --- | --- |
| すべて旧版 | 不一致 | 不一致 | 不一致 | 待機（1） |
| 記事だけ新版 | 一致 | 不一致 | 不一致 | 待機（1） |
| すべて新版 | 一致 | 一致 | 一致 | 引き継ぎ可（0） |

ホストで先に記事を保存し、Box API 応答で新版の SHA-1 を確認した。VM のサインイン後に記事だけが新版になった状態で「待機」を観測し、その後にホストで索引とログを保存した。約 23 秒後の照合で 3 ファイルとも一致し、直後の再照合でも「引き継ぎ可」だった。最後にホストの実ファイルから再生成した照合用 JSON は、VM に先に渡したものとバイト単位で一致した。約 23 秒はこの試験で照合した時点までの観測値である。

別のローカル試験で、改行だけの違い、ファイル欠落、Unicode の正規化形式が異なる競合コピー候補を検出した。スクリプトと対象ファイルの SHA-256 は raw の記録にある。
