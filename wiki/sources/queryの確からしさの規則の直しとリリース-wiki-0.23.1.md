# /wiki:query の確信度の規則の直し（エッジ、Grep、何が結論か）と wiki 0.23.1 のリリース

[[queryの確からしさの未測定の規則の測定-2026-11-16]] で作者が決めた直しの向き（案 1-A、2-B、3、4）を `/wiki:query` の確信度の規則に入れ、Claude Sonnet 5.5 で測り直して、wiki 0.23.1 として出した記録である。測定の原本は `docs/research/wiki-query-confidence-0-21-3-2026-11-16.md`、決定は ADR-0028 の「0.23.1 の追記」、レビューの原本は `docs/agent-runs/2026-11-16-wiki-query-confidence-0-21-2/` にある。

## 直したこと

| 項目 | 決めたこと | 決めた人 |
| --- | --- | --- |
| エッジの上限（案 1-A） | エッジの `confidence` と `status` は、結論をエッジから導いたときだけ上限に数える。エッジの `source` のソースの要約ページか raw の本文が関係を直接述べていれば数えない | 作者 |
| エッジだけの前提 | 本文で確かめられないときは、エッジを書いたページの frontmatter で確かめて引用し、出発点を「中」にする。グラフの行だけを前提にしない | 提案を作者が承認 |
| 推測を答えにする | 根拠に推測や記憶として書かれたこと（「〜だったと思う」）を答えとして述べたら、留保を添えても上限は「低」 | 作者（提案は「中」） |
| グラフを必ず呼ぶ | 関係を問う質問では、ページを読む前に必ず `graph` の `neighbors` を呼ぶ。手順を 5b から 2b に移し、ノードの ID の作り方（`graph.node_id` の上書き、結果の `path` の確かめ）を書いた | 作者 |
| `Grep` で見つけたら縮退（案 2-B） | 縮退の理由に「0. 語彙だけの道具で見つけた」を足した。見つけ方は道具を呼んだ順だけで決める | 作者が「開く前に呼んだか」を選んだ |
| その場の検索し直し | 縮退に当たったページは、答える前に MCP の `query` で検索し直してよく、正常な hybrid の結果にそのページが出れば上限は外れる | 作者 |
| 縮退の目的（案 3）と複数の結論（案 4） | 縮退は見落としを表すのでページを読んでも外れない。結論の文の終わりに「（確からしさ: 高）」、決まった 1 行は 1 つの値 | 作者 |
| 何が結論か | 質問が問う事柄について、前提に使えるもの（出発点が決まるもの）が wiki にあるかで決める。前提に使えるものがない問いには付けず、どの問いにもなければ決まった 1 行も書かない | 作者が「直してから出す」と決めた |

> 直したこと 補足: 「見つけ方」の文は、Sol の敵対的レビューで 2〜7 回目まで毎回崩れた。インデックスの行の読みで決める形と、リンクのたどり元から引き継ぐ形は、どちらも同じ記録から高と中を導けた。道具を呼んだ順だけで決める形にして、5 回目で条件付きで採用可になった（[[エージェントに守らせる決まりの書き方]] の「読み手の判断に任せず、記録で決める」）。

## 測り直し

試験用の wiki（架空の製品 Tsuyukusa）で、前回の 15 問に `Grep` の経路の問い R16 を足し、16 問 × 3 回を流した。測ったのは出す版の 1 つ前のコミット `ea0a5b5` である。

- 一致は 48 回中 41 回だった。事前に書いた別の読み（R16 の 3 回と R04 r2）が 4 回、規則の外れが 3 回である。前回と同じ 15 問に限ると 45 回中 41 回（前回は 40 回）だった。
- 関係を問う R07 と R08 の 6 回とも、グラフの `neighbors` を呼んだ（前回は 0 回）。R07 は 3 回とも「推測を答えにした」で「低」、R08 は 3 回中 2 回が「高」だった。
- 複数の結論の書き方は 6 回とも規則どおりだった（前回は 6 回中 1 回）。
- `Grep` を答えのページを開く前に呼んだ回は 2 回だけで、R16 でも Sonnet は先に hybrid の MCP の検索を呼んだ。理由 0 の「中」と、その場の検索し直しの経路は、ほとんど測れていない。
- R02（主張がシンセシスにしかない）が 3 回中 2 回、「答えられない」に「低」を付けた。直しの前の v0.23.0 でも、3 回中 1 回が補足に「中」を付けた。作者は直してから出すと決め、「何が結論か」を足した。直した版（`f5b99d3`）で R02、R03、R04 を 3 回ずつ流すと、9 回とも期待どおりだった。

費用は合計 15.1 USD だった（本番の 48 回が 11.52、取り込む前の版の試しが 0.84、v0.23.0 の R02 が 0.65、直した版の確かめが 2.10）。

## 版と順番

作者は「この直しを先に出す」と決めていた。作業中に、検索語の漏れの直し（0.21.2、to884/info-hive-wiki#73、[[queryの検索の説明への外の語の漏れの直しとリリース-wiki-0.21.2]]）と YouTube の字幕（0.23.0、to884/info-hive-wiki#74、[[youtubeの字幕の取り込みの実装とリリース-wiki-0.23.0]]）が先に出たので、2 回取り込んで 0.23.1 にした。順番は作者の決定と逆になった。0.23.0 が上限の表に足した動画のソースの 3 行は、そのまま残した。

## リリース

1. 子の PR（to884/info-hive-wiki#75）の CI 4 件が通ってから、マージした（`955c15a`）。
2. 注釈付きのタグ `v0.23.1` と GitHub リリースを作った。本文は CHANGELOG の 0.23.1 の節である。
3. 使い捨ての設定でマーケットプレイスから入れ、0.23.1 が入ることを確かめた。変えた 5 つのファイル（`commands/query.md`、`query-confidence.md`、`query-workflow.md`、`graph-workflow.md`、`plugin.json`）の SHA-256 は、タグの中身と一致した。
4. 親の参照をマージコミットに付け替えた。

## 残った直しの候補

- 時期や版の不明の行で、`/wiki:lint` の提案が抜けやすい。
