# Box Drive 上でログの排他ロック中は編集の引き継ぎを待機する試験

Windows 11 ホストと Hyper-V 上の Windows 11 VM で、欠落試験と同じ Box Drive 上の検証用 wiki を使った。対象は `concepts/guide.md`、`index.md`、`log.md`。3 ファイルの SHA-256 が前回の確定版と一致することを確認し、同じ照合用 JSON を全段階で使った。[[box-driveのファイル欠落による引き継ぎ待機-2026-11-21]]

VM の `log.md` を読み取り専用かつ共有なし（`FileShare.None`）で開き、ハンドルを保持した。追加の読み取りは Win32 エラー 32（共有違反）で失敗した。この状態で別プロセスから `check_handoff.py check --json` を実行した。ハンドルを閉じてから同じコマンドを再実行した。

## 実測結果

| VM の状態 | 記事と `index.md` | `log.md` | 判定（終了コード） |
| --- | --- | --- | --- |
| ロック前 | SHA-256 一致 | SHA-256 一致 | 引き継ぎ可（0） |
| 排他ロック中 | SHA-256 一致 | 読み取れない（`unreadable`） | 待機（1） |
| 解除直後 | SHA-256 一致 | ロック前と SHA-256 一致 | 引き継ぎ可（0） |

`log.md` の SHA-256 はロック前と解除後で同じだった。ホストも試験の前後に照合し、どちらも 3 ファイルが一致して「引き継ぎ可」だった。試験は VM の `log.md` で 1 回行った。
