# Codex のプラグインと会話の取り込みに対応した wiki 0.29.0 のリリース

Claude Code 向けだった wiki を Codex のプラグインとしても導入できるようにし、Codex の会話履歴の自動取り込みを加えた。プラグインの PR は to884/info-hive-wiki#86、カタログは to884/info-hive-marketplace#6 と #7。プラグインの main の `10afe5d` に注釈付きタグ `v0.29.0` を付け、GitHub リリースを公開した。別の未マージ PR が 0.28.0 を予定していたため、作業中の版を 0.29.0 に変えた。

## 共用した部分と分けた部分

Codex の定義は `.codex-plugin/plugin.json`、呼び出しは `$wiki:info-hive <操作> <引数>` である。11 種類の操作の手順の正本は既存の `commands/*.md` とし、`wiki_codex.py` が Codex 用の呼び出し名とパスで表示する。MCP の入口と検索、lint、グラフ、閲覧、Markdown の保存形式は共用した。

Codex CLI 0.166.0 の互換形式は MCP の `${CLAUDE_PLUGIN_ROOT}` を展開しなかった。Codex 用の定義を `cwd: "."` とプラグイン内の相対パスにした。Web の raw は Codex 自身が作り、Claude のエージェントを起動しない。rag の Codex 対応は今回の範囲に含めなかった。

## 会話履歴の取り込み

`$wiki:info-hive ingest session` は実行中のチャット、`session:<ID>` は指定したチャットを対象にする。現在の ID は `CODEX_THREAD_ID` を優先し、なければ `CODEX_SESSION_ID` を使う。ID がないときに、最新のチャットを勝手に選ばない。

従来の legacy 履歴は完全なターン、paginated 履歴は項目のページを、Codex の読み取り API で得る。実行中は依頼を含むターン全体の手前に範囲を固定する。最新のユーザー発言で区切る案は、追加入力が間に入ると取り込み依頼と作業が混ざるため退けた。

許可した会話の本文だけを抜き出し、思考、ツール結果、システム指示、通知、圧縮の本文を原本に通さない。未加工の会話の写しは保存せず、既存の伏せ字、手動の決定、承認済みハッシュ、raw の排他作成・読み取り専用、scan / verify を共用する。Claude Code の既存の fixture は raw と base のハッシュが変更前と一致した。raw を 1 回で作る方針は [[セッションの取り込みの設計-2026-11-14]] と同じである。

## 公開と導入の確かめ

- 関連回帰 230 件で失敗なし。Windows では POSIX 専用の 1 件をスキップした。
- プラグイン自身の CI 手順を手元で完走し、GitHub の Linux / Windows × Python 3.12 / 3.14 の 4 ジョブも成功してからマージした。英語と日本語の検索の品質ゲート、baseline、キャッシュ一致も通った。
- 公開カタログの初回確認では、Codex が `source: "github"` を認識せず、wiki が一覧から消えた。`source: "url"` と Git の HTTPS URL に直す PR #7 をマージし、使い捨ての設定でカタログの取得からやり直した。
- Codex は 0.29.0、スキルと 7 個の MCP ツールを認識し、統計と日本語検索が動いた。配布物の重要な 7 ファイルがタグと一致し、使い捨ての wiki は前後でバイト単位に一致した。
- Claude Code は 0.29.0 が有効になり、v0.27.0 からの全 16 変更ファイルがタグと一致した。ヘルプ 2 本も正常終了した。
- legacy と paginated の合成した会話で、実 CLI からの抽出、保存、ハッシュ照合、読み取り専用を確認した。通常の設定は変えず、一時設定とキャッシュは削除した。推論と `ask-claude` は呼んでいない。

Codex 用の配布カタログの形式は、ローカルの素材だけの導入試験では崩れなかった。公開後に GitHub から取得する経路まで確かめたことで、未対応の source の形式を見つけた。完了の条件は [[リリースの確かめ方]]、版ごとの結果は [[リリースごとの導入の確かめの記録]] にある。
