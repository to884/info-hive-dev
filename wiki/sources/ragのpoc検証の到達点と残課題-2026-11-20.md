# RAG PoC 検証の到達点と残課題

[[info-hive-rag]] の PoC サマリを、全量 OCR・ANN・キャッシュ管理まで統合した。
正本は `docs/research/rag-poc-summary-2026-11-04.md` にある。

## 確認した到達点

全量の入力は 905 文書・245,346 ページで、22,335 OCR ページを含む。
製品 0.5.0 で終えた 903 文書に、ヘッダー判定で失敗したテキストのみの 2 文書を回復して加えた。
OCR の空文字 753 ページも集計しており、全文字の認識成功とは区別する。

[[rag全量ocr後のann保守と中断再開-2026-11-19]] では、783,117 チャンクを一括準備した後、実 MCP の ANN 自動保守 45 項目を確認した。
3 箇所で強制終了し、同じジョブを再開した。最終の 783,645 行に未索引・重複・旧世代は残らなかった。
905 文書を個別に最初から取り込む E2E ではない。

[[ragのocrキャッシュの再利用と回収-2026-11-20]] では、Windows 回帰 84 件、Linux 82 件成功・2 件スキップ、実 MCP 21 項目を確認した。
13 ジョブで新規 OCR は 2 回、再利用経路では 0 回だった。
修正は [[rag-0.5.4の公開と導入確認-2026-11-20]] として公開済みである。

## 未検証と残課題

全量 ANN のコードは `791998a3…`、最終キャッシュ修正・公開版は `021ea077…` である。
最終版で全量 ANN を繰り返していない。
最終キャッシュ修正版の実 MCP は全 1 チャンク保存後・公開前の失敗と再試行で、複数バッチの途中からの再開は回帰試験の範囲である。

全量 OCR 後の人手質問による検索品質、905 文書の個別取り込み E2E、CPU の全量構築時間、Linux の全量実行は未検証である。
従来の全量テキスト層のページ再現率 0.7250 は 4 文書由来の 60 問によるもので、OCR 後の品質を表さない。
空文字ページの原因分類と OCR 分類の人手精度も未確認である。

失敗・キャンセル後の内部ジョブは OCR を保護する。放棄判定・明示的破棄は未実装で、保持が長期化する。
多数の共有キャッシュの走査コストと回収待ちの表示、段組み・表の読み順、正解なし質問の棄却、継続索引化中の検索待ちにも課題が残る。

OS の電源断・再起動、WSL の停止は実施せず、macOS も今回の対象外とした。
最終版の複数バッチ再開、OCR 後の質問評価、継続運用の容量・待ち時間の測定を次の候補として整理した。追加実行の完了記録ではない。
