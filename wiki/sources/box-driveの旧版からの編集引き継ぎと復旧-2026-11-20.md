# Box Drive で VM に旧版が残ったまま編集を引き継いだ試験と復旧

Windows 11 ホストと Hyper-V 上の Windows 11 VM で、同じ Box アカウントに接続した Box Drive 2.56.271 の Cloud Files 方式を使った。両端末をオンラインに保ち、前の引き継ぎ試験と同じ検証用 wiki の `concepts/guide.md`、`index.md`、`log.md` を編集した。[[box-driveのホストからvmへの編集引き継ぎ-2026-11-20]]

## 切り替え時点の判定

1. 両端末の対象 3 ファイルが同じ内容で、競合コピーがないことを確認した。共通版と、そこからホスト・VM がそれぞれ加える変更を Box の外に保全した。
2. ホストで記事に満潮前の戻り時刻を決める文を追加し、索引とログにも反映した。3 ファイルを閉じて、ホストでの編集を止めた。書き込み開始から約 8 秒後に、Box Drive が受け取った Box API 応答の SHA-1 が 3 ファイルともホスト版と一致した。
3. その応答を確認してから VM に編集を指示した。VM で保存に使う 3 ファイルを開き、読み取った内容の SHA-256 がすべて共通版と一致した時点で保存した。記事には帰路に水が入り始めた場合の対応を追加し、索引とログにも反映した。VM に保存した直後に 3 ファイルのハッシュを VM 版と照合した。

## 競合と変更の欠落

| ファイル | 正規名で両端末に残った変更 | 別名の競合コピーで両端末に残った変更 |
| --- | --- | --- |
| 記事 | 満潮前に戻れる時刻を決めるホストの追記 | 帰路に水が入り始めたら引き返す VM の追記 |
| `index.md` | ホスト版の要約 | VM 版の要約 |
| `log.md` | ホストの操作 1 件 | VM の操作 1 件 |

対象ファイルと各別名コピーの SHA-1・SHA-256 を保全済みの版と照らし、表の内訳を確かめた。VM の保存から約 23 秒後の照合で 6 ファイルが両端末にそろい、約 65 秒後にも同じ状態を確認した。正規名からは VM の変更が 3 件とも欠けていた。別名コピーから 3 件とも回収できた。

## 復旧と再同期

実際の正規版と別名コピーを Box の外に保全し、共通版を含めて三方向マージを試すと、3 ファイルに各 1 か所の衝突が出た。記事では両方の文を残し、索引は確定した記事の要約 1 件にまとめ、ログでは両方の操作を各 1 件残した。

ホストだけから書き戻し、約 25 秒後の照合で 3 ファイルとも両端末の SHA-1・SHA-256 および Box API 応答の SHA-1 が統合版と一致した。その後、別名コピー 3 本を `wiki/` と同階層の `recovery-archive/` に退避し、退避先のハッシュの一致と両端末の wiki 内の競合コピー 0 件を確認した。試験用 wiki のリンク切れは 0 件だった。秒数は同じ構成で 1 回試したときの観測値である。
