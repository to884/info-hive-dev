# rag 0.5.2・0.5.3 の PDF のヘッダーの書き方とメッセージの修正、リリースの記録

2026-11-13 の、rag の PDF のヘッダーの書き方をそろえた 2 つのパッチと、そのリリースの記録である。原本は、0.5.3 の Sol の敵対的レビューを残した `docs/agent-runs/2026-11-13-rag-pdf-header-message/` である。0.5.2 のレビューは `docs/agent-runs/2026-11-13-rag-pdf-header-wording/` にある。リリースと親の参照の付け替えは、作業の記録から書いた。

## 経緯

1. wiki 0.11.1 では、wiki の文書だけを「`%PDF-` の前にあるバイトが 1024 バイト以下」と書き直していた。rag の文書は「1024 バイト目まで」のままだった（[[取り込み手順の追従とリリース-wiki-0.11.1]]）。
2. rag 0.5.2（to884/info-hive-rag#9、親は to884/info-hive-dev#81）で、rag の README、CHANGELOG、`rag_index.py` のコメント、v0.5.1 の GitHub リリースの本文、親の ADR-0013 を同じ書き方にした。文書だけの修正である。試験が固定していたエラーメッセージは残した。
3. rag 0.5.3（to884/info-hive-rag#10）で、エラーメッセージを「%PDF- がないか、最初の %PDF- の前に 1024 バイトを超えるバイトがある」に直した。Sol の判定は「採用可」（確信度：高）。条件の詳細は [[pdfのヘッダーの条件]] にある。
4. v0.5.2 は 2026-11-13 01:04（日本時間。GitHub の記録では 2026-11-12T16:04Z）にリリースされた。v0.5.3 は、rag の main のマージコミット c59d05e に注釈なしのタグを付け、01:21（同じく 16:21Z）にリリースした。どちらも本文は、CHANGELOG の項目と「更新のしかた」である。
5. 親の to884/info-hive-dev#84 は、rag の参照が ebe2658 を指していた。ebe2658 は main に含まれるが、CHANGELOG に日付を入れたコミット 76f00e6 とマージコミットの手前である。ブランチを持つセッションが c59d05e に付け替えてから（6022c0c）、マージした（a118042）。
6. 使い捨ての設定でマーケットプレイスから入れ、rag 0.5.3 と依存の wiki 0.12.0 が入ることを確かめた（[[リリースの確かめ方]]）。

## 途中で起きたこと

- v0.5.3 のリリースを、2 つのセッションが作ろうとした。片方がタグを push してリリースを作ったあと、もう片方は手元で同じ c59d05e にタグを付けた。リリースが作成済みだと気づいて、作成を取りやめた（そのセッションの報告による）。リモートのタグは c59d05e のままで、GitHub リリースは 1 つだけである。
- 導入の確かめで、新しいエラーメッセージを丸ごと `grep` で探すと 0 件だった。コードでは f 文字列が 2 行に分かれていたためで、1 行に収まる部分（「最初の %PDF- の前に」）で探し直すと、入ったファイルの 78 行目にあった。
