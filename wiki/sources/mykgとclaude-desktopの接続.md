# myKG でナレッジグラフを作り、Claude Desktop に接続する

[[mykg]] の作者が、文書からスキーマとグラフを抽出し、MCP を介して Claude Desktop から問い合わせる手順を示した記事。架空の会社 Acme Corp の小規模なデモを使っている。注目するのは、グラフで回答の構造を見つけた後、元の文書で主張を確かめる分担である。

## 構築と問い合わせの流れ

```mermaid
flowchart LR
  D["文書群"] --> S["Pass 1: スキーマの提案"]
  D --> E["Pass 2: エンティティと関係の抽出"]
  S --> E
  E --> G["型のあるグラフとリンク付きノート"]
  G --> M["読み取り専用の MCP ツール"]
  M --> C["Claude が探索とノートの参照を行う"]
  C --> A["原文を確かめて回答・組織図を作る"]
```

> GPT-6 補足: 記事の構築段階と問い合わせ段階を整理した。グラフの型が決まることと、その中の個々の対象や関係が正しいことは分けて扱う。

`mykg init` で LLM の提供者とモデルなどを設定し、`mykg extract-graph notes/ --obsidian-vault` で抽出する。リンク付きノートは Obsidian に準拠するが、利用に Obsidian 本体のインストールは要らない。記事は、Ollama のローカルモデルと、OpenAI、Google Gemini、OpenRouter、Anthropic の API に言及する。

MCP サーバーは stdio と FastMCP を使い、検索、ノードの参照、隣接ノードと経路の探索、スキーマ・統計、ハブ・孤立ノードの検出、ノートの参照、再読み込みなど、14 個の読み取り専用ツールを公開すると説明する。MacOS の接続例は `uv --directory <プロジェクトのパス> run mykg mcp-serve` を起動し、設定後に Claude Desktop を完全に終了して起動し直すものだ。

## デモで観察されたこと

統計の画面は、4 ファイルから 42 ノード、52 エッジ、弱連結成分 2 個ができたと示す。組織図の依頼では、検索 9 回とファイルの参照 2 回が表示される。これらは記事の画面の記録であり、この取り込みでは再実行していない。

最後の画像内の Claude の説明は、グラフの `Platform team` ノードが、Bob の管理するインフラのチームと James の監督するプラットフォームのチームを混同しており、元の文書を読んで分け直した、と述べている。Product team の責任者は原文に指定がないため、担当者なしで示したとも説明する。型のあるグラフでも誤統合を含みうること、欠けた情報を補わずに残すことの事例として扱う（[[既存リンクからのグラフ検索]]）。

## 適用の範囲と未確認の点

デモの抽出が 1 分未満だったという報告には、文書の大きさ・種類、モデル、バッチのトークン数、同時実行数で時間と費用が変わるという留保が付く。実際の API 費用、抽出の精度、数百文書での比較評価は示されていない。「グラフなら文書をまたぐつながりの見落としがない」という結びの主張は、一般的な保証としては採用しない。

ツール数、コマンド、モデルの選択肢は記事の記載であり、現行版の仕様は未検証である。差分更新の `--append` とスキーマ拡張の `--append --grow-schema` も原文どおり保存した。組織図の誤統合の訂正は画面内の説明まで確認できるが、元のデモファイルと突き合わせた再現確認はしていない。info-hive への機能追加や myKG の導入も行っていない。
