# Box Web で log.md をロックした状態での Box Drive 保存と同期

前回と同じ検証用 wiki を、Windows ホストと Hyper-V 上の Windows VM の Box Drive で開いた。Box Web と両端末は同じ Box アカウントを使用した。開始時に記事・`index.md`・`log.md` の SHA-256 が試験前の照合用 JSON と一致し、両端末で「引き継ぎ可」（0）だった。

Box Web のフォルダー一覧で `log.md` のメニューから「ロック」を選び、期間を 5 分に設定した。「ダウンロードを無効にする」はオフのままにした。行に「ロック済み」が表示されてから、ホストで試験用のログを保存した。その内容を VM が受信してから、VM で別の試験用のログを保存した。

## ロック中の保存と反映

| 保存した端末 | ローカル保存と読み戻し | Box で反映を確認 | もう一方の端末で読み戻し |
| --- | --- | --- | --- |
| ホスト | 成功。保存した版と SHA-256 が一致 | 保存開始から約 7 秒 | VM で約 21 秒 |
| VM | 成功。保存した版と SHA-256 が一致 | 保存開始から約 6 秒 | ホストで約 25 秒 |

Box への反映は、各 Box Drive が受け取ったネットワーク応答にある同じファイル ID の `log.md` の SHA-1 を、保存したバイト列の SHA-1 と照合して確かめた。両方の反映後に Box Web を再読み込みし、更新されたサイズ（902 B）と「ロック済み」の表示が同時に出ることを確認した。解除ダイアログで、このアカウントがロックを設定したことも確認した。

## ロック解除後の同期と判定

1. Box Web で手動解除し、一覧からロック表示が消えたことを確認した。両端末に VM 側の試験版が残っていた。試験前の照合用 JSON では、`log.md` だけが不一致で、両端末とも「待機」（1）になった。
2. VM 側の試験版が同期済みであることを確認してから、その版で照合用 JSON を作ると、両端末とも「引き継ぎ可」（0）になった。
3. ホストで試験前の `log.md` を書き戻した。保存開始から約 11 秒で Box の応答と SHA-1 が一致し、約 29 秒で VM でも試験前の内容を読めた。試験前の照合用 JSON で 3 ファイルの SHA-256 が一致し、競合コピー候補がなく、両端末とも「引き継ぎ可」（0）に戻った。

Box の公式仕様では、ロックを設定したアカウントは引き続きファイルを編集できる。今回の手順では、同じアカウントの両端末から保存と Box への反映ができた。両端末で同時に保存した場合は未検証。別アカウントでの保存は、後続の [[box-webのロック期限切れと別アカウントのbox-drive同期-2026-11-21]] を参照。 [Box のファイルのロックと解除](https://support.box.com/hc/en-us/articles/360043697174-Locking-Unlocking-Files)
