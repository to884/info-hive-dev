# /wiki:query の確信度の規則を Sonnet 5.5 で測った記録（2026-11-16）

wiki 0.20.0 の `/wiki:query` が付ける確信度（ADR-0028、[[queryの確からしさとリリース-wiki-0.20.0]]）が、Claude Sonnet 5.5 で規則どおりに決まるかを測った記録である。原本は `docs/research/wiki-query-confidence-sonnet-2026-11-16.md` で、質問の組と期待（実行の前にコミットした）、全回の道具の呼び出しと回答、スクリプトは同じ名前のディレクトリにある。

## 測り方

- この wiki に 11 問を作り、規則から期待の判定、正解、要因、上げる方法を決めた。種類は、ソースの要約ページ、計算、コンセプトのページだけ、仮説、判断（「十分か」）、`log.md`、扱っていない問い、問いの一部だけ答えがある問いである。
- info-hive-wiki の `v0.20.0` を `--plugin-dir` で読み込み、`claude -p "/wiki:query <質問>" --model claude-sonnet-5-5 --output-format stream-json --verbose` で各問を 3 回ずつ流した。Write と Edit は禁じ、各回のあとに wiki が変わっていないことを確かめた。
- MCP の索引の埋め込みが終わるのを待ってから流した。全回で検索の縮退は起きていない。
- 試しの 1 回を含めて 34 回で 5.27 USD、1 回は 15〜34 秒だった。

## 結果

| 確かめたこと | 結果 |
| --- | --- |
| 判定のラベルの一致 | 24/33（73%）。理由も規則どおりだったのは 18/33 |
| 3 回とも同じ判定 | 8/11 問。Q02（計算）、Q05（仮説）、Q08（`log.md`）でぶれた |
| 外れた向き | 9 回すべてが期待より低い |
| 手順 5b（`references/query-workflow.md`）を開いた | 0/33。`SKILL.md` も 0/33 |
| 決まった書き方（`**確からしさ（confidence）: X**`） | 0/33 |
| 上げる方法が要因に合った（期待が中の 15 回） | 10/15。判断の問い（Q06）は 0/3 |
| 扱っていない問いと、問いの答えのない部分 | 3 回とも答えず、確信度も付けなかった |

外れた理由は、どれも手順 5b の表にない上限か、5b にあって `commands/query.md` の手順 6b の要約にない規則だった。

- 「観測や実行が 1 回だけ」「raw を確かめていない」「git の履歴で確かめていない」を上限にした。6b の要約の「ソースの要約ページか raw で確かめたか」を「raw まで確かめたか」と読み、上限の列挙の「など」に足したと見られる。
- wiki 自身の事柄を `log.md` で答えたら高、という規則は 6b にない。`log.md` の日付を問う Q08 は、3 回中 2 回が中だった。

ラベルが合っても、理由が違う回があった。Q06（Haiku 5.5 で十分か）は 3 回とも中だったが、評価の言葉への当てはめを理由に挙げた回はない。Q10（pdfminer の揺れの原因）は 3 回とも中だったが、原因がソースの要約ページにないことを挙げた回はない。

## 外の知識の漏れ方

答えそのものを添えた回はなかった。それでも、規則の文面に当たらない経路で、wiki にない情報が回答に入った。

- 会話に読み込まれたプロジェクトの指示（AGENTS.md）の CSP の記述を、補足や理由に入れた（Q03 の 3 回とも）。
- 答え（Rust）を検索語として回答に書いた（Q11 の 3 回とも）。

## 規則の直しの案

ADR-0028 は、判定のぶれが報告されたら見直すとしている。原本は、次の 4 つを作者に示した。直しは作っていない。5b を読ませれば外れが減るというのは仮説で、測り直して確かめる。

1. `commands/query.md` の 6b に、`${CLAUDE_PLUGIN_ROOT}/skills/info-hive/references/query-workflow.md` を Read で開くことを書く。5b を小さな参照に分ける案もある。
2. 6b の要約から、読み違いを生んだ言い回し（「raw で確かめたか」「など」）を除き、wiki 自身の事柄の規則を足す。
3. プロジェクトの指示と、答えを含む検索語を、外の知識の経路として規則に書く。
4. 書き方を検査できるように、決まった見出しを 6b に例として載せる。

## 0.21.1 での測り直し

作者は案 1〜4 を入れると決め、wiki 0.21.1 にした。前回と同じ wiki（親のコミット `4b3f578`）と同じ 11 問で、3 回ずつ測り直した（33 回、6.11 USD）。

| 確かめたこと | 0.20.0 | 0.21.1 |
| --- | --- | --- |
| ラベルの一致 | 24/33 | 33/33 |
| 3 回とも同じ判定の問い | 8/11 | 11/11 |
| 決め方の正本を開いた | 0/30 | 30/30 |
| 決まった書き方の 1 行目 | 0/30 | 29/30 |
| AGENTS.md の記述が入った（Q03） | 3/3 | 1/3 |
| 答えを検索語として書いた（Q09、Q11） | 3/6 | 3/6 |

> 測り直しの表 補足：0.21.1 では、決め方を `references/query-confidence.md` に分け、コマンドの手順 6b でパスを書いて Read させた。外れていた 9 回は、すべて期待どおりになり、理由も規則の表に沿っていた。答えを検索語として書く漏れは、Q11 では減ったが、確信度を付けない Q09 で新しく起きた。その回は、決め方のファイルを開いていない。

規則がエージェントに届けば、判定はそろう。前回の原本が仮説として書いた「手順 5b を読ませれば外れが減る」は、この測り直しで確かめられた。答えを検索語として書く漏れをどこで止めるかは、まだ決まっていない。
