# Box Drive 2 台による wiki の同時再接続試験

Windows 11 Enterprise ホスト（ビルド 26300）と Hyper-V の Windows 11 Enterprise LTSC Evaluation ゲスト（ビルド 26100）で試験した。両方で Box Drive 2.56.271.0 の Cloud Files 方式を使い、同じ Box アカウントで検証用の wiki を同期した。wiki は info-hive v0.39.0 で初期化した。

## 条件と手順

1. 記事 2 本と `index.md`、`log.md` の初版が Box と両端末で一致することを SHA-1 で照合し、4 ファイルを両端末で固定した。
2. ホストの Box への通信を拒否するプロキシを使い、実際に拒否されたことを確認した。VM は Hyper-V の仮想 NIC を切断し、ゲスト側で切断を確認した。
3. ホストで北の記事、VM で南の記事を更新した。それぞれ共通の索引では自分の記事の要約 1 行を変更し、共通のログには自分の操作を 1 件追記した。既存の Markdown を直接上書きし、切断中にそれぞれの版のハッシュを確認した。
4. ホスト時刻の同じ基準時刻にプロキシの解除と VM の仮想 NIC の再接続を始めた。操作の開始差は 8.5 ミリ秒だった。

## 結果

| ファイル | 正規名 | 別名の競合コピー |
| --- | --- | --- |
| 北の記事 | ホストの編集を反映 | なし |
| 南の記事 | VM の編集を反映 | なし |
| `index.md` | VM 版。南の記事の要約だけ更新済み | ホスト版。北の記事の要約だけ更新済み |
| `log.md` | VM 版。VM の操作だけ追記済み | ホスト版。ホストの操作だけ追記済み |

再接続の基準時刻から約 1.8 秒後に、VM の Box API 応答で `index.md` と `log.md` の正規名と VM 版の SHA-1 を確認した。約 12.5～12.6 秒後に、ホストの Box API 応答で別名コピー 2 本とホスト版の SHA-1 を確認した。約 27 秒後の観測では、記事 2 本と索引・ログの両版、計 6 ファイルの SHA-1 が両端末で一致した。時刻は今回の 1 回の観測値である。

競合の復旧では、正規名に残った記事 2 本を採用し、索引へ記事 2 本の更新後の要約を、ログへ両端末の操作を反映する。書き戻しと退避の手順は、別の Box Drive と Box Web の試験で検証した。今回の試験では競合が収束した状態を保存した。[[box-driveのwikiの競合と復旧-2026-11-19]]
