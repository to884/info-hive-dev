# wiki の書く段の設計の記録（ADR-0023）

2026-11-14〜15 の、wiki のページ、索引、ログへの書き込みを、モデルの Edit と Write から、ロックを持つ Python のプロセス（`wiki_apply.py`）に移す設計の記録である。原本は、GPT-6.1 Sol の 15 回の敵対的レビューと各版を残した `docs/agent-runs/2026-11-14-wiki-apply/` で、経緯の要約は同じ場所の `summary.md` にある。設計は `docs/plans/wiki-apply-2026-11-14.md`（17 版目、承認）、決定は ADR-0023（承認）にある。実装はまだである。

## 経緯

1. セッションの取り込みの設計の 4 版目に足した書く段が、レビューの重大の指摘を集めたので、作者の判断で別の設計に分けた（[[セッションの取り込みの設計-2026-11-14]]）。並行して書くと行が黙って消える問題（[[editとwriteの書き込みの競合]]）を防ぐのが目的である。
2. 1〜5 回目は、済んだかを今の中身から推す作り、検査を書く場所ごとに分ける作り、パスの字面で場所を決める作りが崩れた。日誌だけで判定し、書き込みの入口を 1 つにし、正規のパスだけを受ける形に直した。
3. 3〜10 回目は、ロックと日誌を利用者の PC に 1 か所に置き、wiki の印で管理領域を決める形を足しては崩された（環境変数で管理領域が分かれる、印を移す操作が並ぶ、など）。
4. 作者が「作者が決めること」に答えた（2026-11-15）。ロックはプロジェクト（wiki）ごとに持ち、落ちても残るファイルにして、利用者が `unlock` で外す。待ちは 3 分で、待ちきれなければ差分を `.wiki-cache/apply-pending/` に置いて誤りにし、5 件以上で知らせる。日誌は 14 日残す。これで印の仕組みが要らなくなり、外した。
5. 11〜15 回目は、作り直しの継ぎ目と、raw の守りの境目（bind mount、`raw:` の向け方）を突いた。raw の守りは、書く道に別名がないことと、wiki の木と raw の木がディレクトリを分け合わないことの組にした。
6. 重大の指摘の発生の度合いを回ごとに分けると、実装すれば確実に踏む欠陥は作り直した直後にだけ出て、13 回目からは出ていなかった。作者はレビューを 15 回で止め、17 版目を承認した（[[敵対的レビューで設計を直す進め方]]）。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| 書き手 | wiki のページ、索引、ログを書くのは `wiki_apply.py` だけにする。モデルは作業用のフォルダーに変更を用意し、wiki のファイルを直接書かない |
| 変更の種類 | `new`（新しいページ）、`edit`（ファイルの全体が用意したときと同じときだけ置き換える）、`ops`（索引とログの決まった操作を、ロックの中で今の中身に順に当てる）。3 方向の当て方はしない |
| 済んだかの判定 | 書く前に「前」と「後」の中身を日誌に書き、日誌だけで決める。次にロックを取った書き手が前に進め、置けなければ戻す |
| 承認 | `plan_id` を含む計画の全体からハッシュを作り、計画が指すファイルを 1 回だけ読んで使う |
| ロック | wiki ごとの残るロックのファイル。3 分待って差分を置く。`unlock` で外す |
| raw の守り | 書く道に別名（リンク、再解析点、mount point）がないことと、wiki の木と守る raw のルートの木が交わらないことの組。走査は完全でなければ書かない |
| 移す範囲 | 文書とスクリプトの書き込みの指示と書き手を洗い出した表にし、機械の検査で閉じる |

## オントロジーの移行との接続

[[オントロジーの見直しのレビュー-2026-11-19]]では、このADRがグラフDBの更新を範囲外とし、読み手が途中の内容を見ることも防がない点を確認した。[[オントロジーの見直しと移行]]で必要となる、書かない依存先の変化の検査と、候補検索から出典確認まで同じ公開版を読む条件には追加設計が必要である。これはADRを改訂済みとする記録ではない。
採用候補との責任範囲は[[オントロジーの要件とOssieへの引継ぎ]]に整理した。
