# Box Web で期限前に手動解除した後の Box Drive 同期

前回と同じ Box Drive の検証用 wiki を使った。ホストは Box の所有者アカウント、Windows VM は別アカウントの編集者とした。前回の期限切れ試験で同期した版を今回の基準とし、開始時は両端末とも「引き継ぎ可」（0）だった。[[box-webのロック期限切れと別アカウントのbox-drive同期-2026-11-21]]

## ロック中の保存

Box Web で `log.md` を 5 分間ロックした。ダウンロードを無効にする設定はオフにした。最初の試行では VM のファイルが読み取り専用になり、書き込み用に開く段階でアクセス拒否（`0x80070005`）になった。ファイルの内容は基準どおりで、両端末とも「引き継ぎ可」だった。ホストでロックを解除し、VM の読み取り専用属性が解けたことを確認した。

同じ設定で再びロックし、Box Web に「ロック済み」が表示された約 7 秒後に VM で 1 回だけ書き込んだ。保存した内容を SHA-256 で読み戻した。保存から約 10 秒後、同じファイル ID へのアップロード失敗が VM の Box Drive ログに `403 ITEM_LOCKED` と記録された。解除前は、ホストの `log.md` は試験前の版、VM の `log.md` は保存した試験版だった。

## 手動解除後の同期

ロック設定操作から約 43 秒後、5 分の期限が切れる前にホストの Box Web から手動解除した。解除のボタンを押した時刻を起点とし、VM で再保存や手動リトライをせずに観測した。

| 観測点 | 解除操作からの経過 | 確認した内容 |
| --- | --- | --- |
| VM が受け取った Box の応答 | 約 15 秒 | 同じファイル ID の SHA-1 が試験版と一致 |
| ホストが受け取った Box の応答 | 約 28 秒 | 同じ SHA-1 を確認 |
| ホストの Box Drive 上の実ファイル | 約 32 秒 | 試験版の SHA-256 と最初に一致。直前の約 27 秒時点では試験前の版 |

再読み込みした Box Web でロック表示がなく、更新者が VM の編集者アカウントであることを確認した。検証用 wiki には同期した試験版を残した。

## 引き継ぎ判定

| 照合時点と基準 | ホスト | VM |
| --- | --- | --- |
| 保存できた試行のロック中、試験前の JSON | 引き継ぎ可（0） | 待機（1、ログのみ不一致） |
| 手動解除後の同期完了時、試験前の JSON | 待機（1、ログのみ不一致） | 待機（1、ログのみ不一致） |
| 手動解除後の同期完了時、同期した試験版の JSON | 引き継ぎ可（0） | 引き継ぎ可（0） |

記事と `index.md` はすべての照合で基準と一致し、競合コピー候補はなかった。ホスト側のロック表示が消えてからも版が届くまで時間がかかった。引き継ぎ前に Box への反映と、受け手の確定版との照合を確認する。ローカル保存に成功したケースでの手動解除は 1 回の実測である。
