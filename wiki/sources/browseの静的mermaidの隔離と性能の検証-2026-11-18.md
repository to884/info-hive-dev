# browse の静的 Mermaid の隔離と性能の検証

Claude の `static-mermaid` worktree を Codex が引き継ぎ、方式比較、PoC の修正、サーバー版の修正、性能の診断まで進めた会話である。
対象は 2026年11月17日21:38〜18日08:40（日本時間）。件数・測定値・レビュー判定は会話での実行者の報告として記す。今回の取り込みで試験を再実行したものではない。
原文に思考・ツール結果・圧縮の本文・他のエージェントの会話は含まない。Codex 自身の当時のモデルは履歴 API では不明である。

## 方式比較と利用者の選択

利用者は worktree の引き継ぎと GPT の 2 モデルでの比較を依頼した（T14、T29）。
Sol と Astra の初回評価はファイルを読めず、コードと結果を添えてやり直した。両モデルは、`pageDir` を送り同じ枠で複数図を扱う既存 PoC の採用を見送った。
図ごとの `relay-srcdoc` と書き出し時のヘッドレス生成の優先順位は未確定だったが、利用者は前者を選んで修正と検証を依頼した（T53、T60、T65、T71、T72）。

## 隔離の反例と修正

自分の図と配色だけを渡す形に直し、親・検索・別図・パスの取得を検査した。当初は 55 項目合格と報告されたが、Opus の利用上限により利用者が指定した Astra のレビューで穴が見つかった（T118〜T129）。
同時の描画側同士による直接の `postMessage` での入力交換と、描き直し失敗を試験が合格にする問題を再現した。
1 図ずつの実行へ直し、成功・入力・実行回、生成物のハッシュ、遷移後の観察を照合した。最終報告は 5 ブラウザ × 12 項目成功、Astra は開発用 PoC として採用可だった（T139、T144、T151、T156）。

サーバー版でも交換を再現し、逐次実行へ直した。埋め込み・`opener` で結ばれたページ同士でも反例が成立し、これらの入口では描画せずコードを表示する修正を追加した（T178、T230、T239）。
最終報告は 5 ブラウザ・30 ケース成功、Astra の再レビューで重大指摘なしだった。静的 PoC 自体は単独ページが前提であり、入口制限を適用済みとは扱わない（T292）。条件は [[図ごとの描画の隔離]] を参照する。

## 性能の診断と未解明の差

最初の同時測定では 50 図に約 20〜121 秒かかった。その後、時間とメモリを分け、図数ごとにブラウザを起動し直した（T292、T303）。
Opus の指摘で、監視の有無 × 前処理の有無の対照、弱参照の校正、時間切れの途中記録を追加した。
WebKit の条件順が同じになる欠陥を修正し、因子比較を採り直した。通常測定の処理は変わらないことを照合して 27 ケースを保持し、正式測定は計 52 ケースが成功した（T325、T342、T366、T387、T414、T421）。

中央値になった 50 図の初回の約 70〜86% は、枠の追加から `ready` までの待ち時間だった。非同期の後始末や GC も混ざるため、コンパイルだけの費用とは断定しなかった（T363、T414）。
WebKit は画像と結果の解放・GC 要求後も約 4.1 GiB の private bytes が残り、context 終了後に約 0.38 GiB へ減った。Firefox は GC 要求後に大きく減った。弱参照の校正は内側の実行領域や native cache の回収を証明しない（T406）。
通常測定の初回中央値は、起動後に 10 秒待つ因子比較の「新規・監視なし」に対して Firefox 1.54 倍、WebKit 1.91 倍だった。未統制の差の原因は未解明である（T425、T436）。読み方は [[描画の性能測定の条件]] にまとめる。

## 終了時点

Opus の最終判定は開発用診断として採用可、重大指摘なしと報告された。100 秒超の未再現を解決済みとはせず、静的版の製品組み込みは保留した。
次の課題は絶対時間のばらつき、準備処理の内訳、context が生きている間の保持である（T436、T440）。
コミット・公開は未実施と報告され、その後この会話内に公開完了の報告はない（T292〜T440）。
