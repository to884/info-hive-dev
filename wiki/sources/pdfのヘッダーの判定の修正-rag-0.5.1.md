# rag 0.5.1 の PDF のヘッダーの判定の修正の記録

2026-11-12 の、`info-hive-rag` の `read_pdf`（`scripts/rag_index.py`）の修正の記録である。原本は、Sol の敵対的レビューの依頼と結果、境界を確かめたスクリプト（`probe_header_offset.py` など）を残した `docs/agent-runs/2026-11-12-rag-pdf-header-offset/` である。

## 経緯

- rag 0.5.0 の `read_pdf` は、ファイルの先頭がちょうど `%PDF-` でないと「PDF の形式ではありません」として拒んでいた。
- 全量の OCR（`docs/research/rag-full-ocr-v050-2026-11-09.md`）で、先頭に改行が 1 バイトあるだけの 2 文書（`L4/` の下の seL4 の論文）が、この理由で失敗した。
- `%PDF-` が先頭から 1024 バイトの範囲で始まれば受け付けるように直した。上限は PDFium にそろえた（[[pdfのヘッダーの条件]]）。
- Sol のレビューの判定は「採用可」（確信度：中）。軽微な指摘の 1 つが、wiki の取り込み手順が古い条件のままだということで、wiki 0.11.1 で別に直した（[[取り込み手順の追従とリリース-wiki-0.11.1]]）。
- to884/info-hive-rag#7 を 2026-11-12 にマージし（b3f45e3）、CHANGELOG に日付を入れた #8（0dea049）のあと、v0.5.1 をリリースした。

## 判断

- 版は 0.5.1（パッチ）。今まで受け付けていた入力の扱いを変えず、受け付ける範囲を広げるだけである。
- 抽出の版（`EXTRACT_REVISION`、ADR-0014）は上げない。SHA-256 と抽出は、前置きを含む読んだままのバイト列に対して行う。今まで受け付けていた PDF は判定の結果が変わらず、新たに受け付ける PDF は前の版では抽出まで進まないので、既存の抽出の結果と食い違わない。
- ヘッダーの判定を通っても、PDFium で開けるとは限らない（ヘッダーだけで本体がないなど）。開けないものは抽出で失敗する。前の判定も同じだったので変えない。

## 確かめたこと

- 実データの 2 件を、直した `read_pdf` と `extract_pages`（`ocr_mode` は `off`）に通した。70 ページと 18 ページで、すべてテキストのページだった。前置きの改行を取り除いても、先頭の 3 ページのテキストは同じだった。
- Windows の `.rag-venv` で、`tests/rag/` の `test_jobs.py`、`test_indexes.py`、`test_extraction.py` の 67 件が通った。
- 実データの 2 件を、MCP の `register_pdf` から索引化までの経路で取り込むことは確かめていない。
