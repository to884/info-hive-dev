# browse の構造の直しと wiki 0.17.0 のリリースの記録

閲覧（`/wiki:browse`）の書き込みと読み取りの作りを、設計 `docs/plans/wiki-browse-structure-2026-11-11.md`（8 版目）に合わせて作り直し、wiki 0.17.0 として出した記録である。実装、探索、レビューの原本は `docs/agent-runs/2026-11-14-wiki-browse-structure-impl/` にあり、指摘と対応は同じディレクトリの `responses.md` にある。このページは、作業の記録から書いた。

## 経緯

1. 試験の道具を先に作った。初期の状態と世界の差分（`tests/wiki/browse_sandbox.py`）、コマンドを外から流す黒箱の道具（`browse_blackbox.py`）、書く側の探索（`browse_sweep.py`。設計の試作の探索を移したもの）、読む側の探索（`browse_read_sweep.py`）である。黒箱の道具を直す前の main に当てると、失敗のない実行で 124 件の違反があった。直したあとは 0 件である。
2. `wiki_browse_fs.py` を入出力の層にし、試作 `write_model.py` を製品に移した。入口と中核はファイルの入出力を呼ばず、`Path` を持たない。
3. 移す途中で、0.10.0 が通していた振る舞いの後退を 4 つ見つけて直した。同時の初回の書き出しと起動で `mkdir` と目印の作成がぶつかる、POSIX の 0700 と 0600、同時の 2 つの `stop` で記録が残る、である。
4. Sol の敵対的な実装のレビューを 6 回受けた。6 回とも却下で、指摘は原因の構造から直した。作者の判断で 6 回で終えた。最後の 2 回の重大は、どちらも Windows の 8.3 の短い名前に由来した。
5. 版は 0.17.0 にした。0.16.0 は、作業中に別のセッションがマージしたセッションの取り込み（to884/info-hive-wiki#59）が使った。作者が 0.15.0 に含める案を退けた。0.15.0 は main に入った時点で利用者に届いていて、同じ番号で中身を変えると更新が届かないためである。
6. 直したあとのコードに当てた探索の全量（`sweep-8`）は、書き出しの 137 の状態で 277,128 回、サーバーの記録などで 27,662 回、読む側で 3,525 回で、破れた決まりは 0 件だった。わざと破った対照は、どれも見つかった。
7. 子の PR（to884/info-hive-wiki#60）をマージした（マージコミット `8068cbe`）。親の PR（to884/info-hive-dev#108）の参照をそのコミットに付け替えた。注釈付きのタグ `v0.17.0` を `8068cbe` に付けて push し、GitHub リリース `v0.17.0` を Latest として作った。本文は CHANGELOG の 0.17.0 の節である。タグの本文は `v0.17.0` だけで、CONTRIBUTING.md の「`vX.Y.Z: <要約>`」の形になっていない。
8. 使い捨ての設定でマーケットプレイスから入れ、0.17.0 が入ることを確かめた（[[リリースの確かめ方]]）。v0.16.0 から v0.17.0 までに変わった 5 つのファイルの SHA-256 が、すべてタグの中身と一致した。入った `wiki_browse.py` で、8.3 の形の名前のディレクトリ（`data~a~1`）を含む Wiki を 2 回書き出し、2 回とも 0 で終わった。

## レビューで崩れた前提

どの回も、直したあとの前提が次の回に崩れた。崩れたのは、数え上げで決めた前提だった。最後は、数え上げをやめて、作りで決まる形にした。

| 回 | 崩れた前提 | 作りで決めた形 |
| --- | --- | --- |
| 1 | 拒む判定の前に作ってよい | 拒む判定は、何も作る前に済ませる |
| 2 | まだない場所どうしの重なりは、今ある祖先で決まる | 作られる予定の場所（今ある祖先の識別子と、まだない名前の並び）で比べる |
| 2 | 確定のあとの失敗は `Unknown` と `Absent` だけ | 確定のあとは、1 つの境界がどの例外も警告にする |
| 3、4 | 入れ子は、書き出し先の祖先を見れば見つかる | browse が作るどの場所にも、置いてよい自分の目印を決めて当てる |
| 3、4 | 最後のフラッシュは標準出力だけでよい | 標準出力と標準エラーの両方を最後にフラッシュし、出せなければ捨てる |
| 5 | まだない名前の比較で、重なりを言い当てられる | 拒むときは、その実行で作った空のディレクトリを取り除いて戻す（作者の決定） |
| 6 | 大文字と小文字を同一視して違う出力のディレクトリは、ディスクでも違う | 出力のディレクトリの名前を、`~` を含む 8.3 の形にしない |
