# browse の木をタグでまとめ、左のペインを Tree にした wiki 0.25.0 のリリース

`/wiki:browse` の木を、索引の見出しの下でページの最初のタグごとにまとめ、左のペインを Fluent 2 の Nav の入れ子から Tree に描き直して、wiki 0.25.0 として出した記録である。原本は `docs/agent-runs/2026-11-16-wiki-browse-tag-groups/`、設計は `docs/plans/wiki-browse-tag-groups-2026-11-16.md` と `docs/plans/wiki-browse-tree-2026-11-16.md` にある。見た目の決まりは [[browseのデザインシステム]]、確かめの手順は [[browseの画面の確かめ方]] にある。

## 経緯

1. 作者が、索引の見出し（「コンセプト」「ソース」）の直下にページが並ぶ木を、ページの最初のタグでまとめることを求めた。中核の木に 3 つ目の段 N9 を足した。ページの項目を持つグループのすべてに、タグのグループ（ID は `_gt<番号>`）を挟み、タグのないページは「タグなし」に入れる。参照の実装 `nav_model.py` に N9 を別に書き、例の表をその出力から写した（手で書いた 1 版目の表は、N3 と N4 を当てた結果と 4 例で食い違った）。
2. タグの段を見た作者が、左のペインが Fluent 2 の Nav の規則（入れ子は 1 段まで、深い階層は Tree）から外れていると指摘した。Nav の 3 段に収める案と、部品ごとのずれだけを直す案も示し、作者は Tree を選んだ。
3. 作者が Fluent 2 のサイトの左のペインの画面を示した。サイトの左のペインは、Nav でも Tree でもないサイト独自の作りだった。部品は Tree のままにし、見た目の値（ペインの地、字下げ、ホバーと今の項目の色）をサイトに合わせ、サイトのピンクのアクセントは Fluent の既定の brand のトークンに置き換えた。
4. 実装の画面を見た作者が、件数のバッジを名前のすぐ隣に、字下げをサイトの形に、暗い配色のバッジを黒く沈まない地に、配色の選択をサイトの形の「テーマ」のトグルに、「索引」を「Index」に、記事のページの左の木もグループだけにする、と順に決めた。
5. Sol の敵対的レビューを、タグの設計に 1 回と実装に 1 回、Tree の設計に 2 回と実装に 1 回、リリース前の最終に 1 回受けた。Tree はどの回も分類 A が軽微な 1 件ずつ出た（リンクの下線、ホバーで隠れるバッジのツールチップ、深い段で増える字下げ）。最終は「採用可」で分類 A は 0 件だった。
6. Chromium、Firefox、WebKit で試験を流した。WebKit で、葉を押したあとの Tab の入口がずれる不具合が見つかった。WebKit はリンクを押してもフォーカスを移さないので、フォーカスの移動で行うローヴィングの同期が働かなかった。押したときに自分でフォーカスを移すようにした。
7. 版は 0.25.0 にした。作業の間に main が 0.21.1 から 0.24.0 まで進み、0.22.0 と 0.24.0 は別の PR が名乗っていた。
8. 子の PR（to884/info-hive-wiki#78）の CI 4 つと、親の PR（to884/info-hive-dev#157）の CI 17 が通ってから、子をマージした（`d0e2aa0`）。親の PR は、その前に main と競合し、main を取り込んで解いた。
9. 注釈付きのタグ `v0.25.0` を `d0e2aa0` に付け、GitHub リリース `v0.25.0` を作った。本文は CHANGELOG の 0.25.0 の節である。
10. 使い捨ての設定でマーケットプレイスから入れ、0.25.0 が入ることを確かめた。v0.24.0 から v0.25.0 までに変わった 9 つのファイルの SHA-256 が、すべてタグの中身と一致した。

## 改めた決定

| Fluent 2 の設計 3.2: 配色は 3 つから選ぶ | 「テーマ」のトグル。OS と同じ見た目に戻すと auto を保存する |

## 分かったこと

- **公式のサイトの見た目は、部品の規則と同じではない。** Fluent 2 のサイトの左のペインとテーマのトグルは、Fluent の部品ではなくサイト独自の作りだった。見た目を合わせるときは、部品の規則（Tree の字下げ 24px など）と食い違う所を、作者の決定として設計に書く。
- **手で書いた例の表は、規則を最後まで当てた結果と食い違う。** 参照の実装の出力から写す形にすると、食い違いがなくなる。
- **同梱のスキルの不具合は、利用側の上書きでよけ、スキルの側でも直す。** Tree の actions が祖先のホバーで出る不具合と、葉の Enter を止める不具合は、browse では `style.css` と `app.js` でよけた。スキルの側は、別のセッションが fluent2-html-replica 0.1.4 で直したと報告した（このページでは確かめていない）。
