# Box Drive 上でログが欠けると編集の引き継ぎを待機する試験

前回と同じ Box Drive 上の検証用 wiki、Windows 11 ホスト、Hyper-V 上の Windows 11 VM を使った。対象は `concepts/guide.md`、`index.md`、`log.md`。以前の引き継ぎ試験で使った確定版と、3 ファイルの SHA-256 が同じことを確認した。[[box-driveの編集引き継ぎをsha256で判定した試験-2026-11-21]]

VM の Box Drive 上で `wiki/log.md` を同じ親フォルダー内の `recovery-archive/` へ一時的に移して、VM で照合した。元のログと一時退避先のログは SHA-256 が一致した。照合用 JSON は試験の前後で同じものを使った。

## 実測結果

| 段階 | VM の記事と索引 | VM の `log.md` | VM の判定 | ホスト側の照合 |
| --- | --- | --- | --- | --- |
| 移動前 | SHA-256 一致 | SHA-256 一致 | 引き継ぎ可（0） | 3 ファイル一致、引き継ぎ可（0） |
| 一時退避後 | SHA-256 一致 | 欠落（`missing`） | 待機（1） | この時点では 3 ファイル一致、引き継ぎ可（0） |
| 元のパスへ戻した後 | SHA-256 一致 | 移動前の SHA-256 と一致 | 引き継ぎ可（0） | 3 ファイル一致、引き継ぎ可（0） |

VM の欠落を確認した直後にホストでも照合した。この時点ではホストにログが残っていた。同じファイルを VM で元のパスへ戻すと、直後の照合で「引き継ぎ可」になった。両端末で成功した後に再照合し、3 ファイルの SHA-256 と一時退避パスが消えたことを確認した。試験は `log.md` を対象に 1 回行った。
