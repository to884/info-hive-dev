## 結論

最初に 0.2.1 のリリースの後始末をする。次にグラフ層の後始末で lint とグラフの動きをそろえ、回帰テストを置いてから、本命の MCP サーバーと検索の基盤の移行に入る。Web ページの取り込みは、ほかの作業に依存しないので並行して進める。

| 順位 | 項目 | 種類 | 規模 | 理由 |

| 2 | グラフ層の後始末（ADR-0009）と作業領域の残り（ADR-0008） | 実装 | 小〜中 | 3 で `graph` と `lint` を MCP のツールとして公開する前に、動きをそろえて回帰テストを置く |

2 と 4 は 3 と並行して進められる。5 の第 1 段階（静的に描く閲覧）も 3 を待たない。

## 判断の基準

次の順に重みを置いた。最初の版と同じである。

1. すでに規則に反している、または利用者に影響が出ているもの
2. ほかの作業を止めているもの
3. 承認済みで、すぐ着手できるもの
4. 作業の無駄が出るおそれ（あとで作り直しになる作業は後ろに回す）
5. 規模（同じ順位なら小さいものを先にする）

最初の版から変えた点は 2 つある。統一の判断が済んだので、MCP サーバーの実装が「ほかの作業を止めているもの」に上がった。グラフ層の後始末は、MCP のツールの土台になるので、MCP の前に置いた。

### 3. MCP サーバーと検索の基盤の移行

【記述】ADR-0011 と ADR-0012（どちらも 2026-11-06 に承認）で、次のことが決まった。

- 埋め込みは ruri-v3-130m の ONNX、ベクトル索引は usearch、語彙検索は Tantivy にする。wiki の語彙検索には bigram のトークンを入れる。
- wiki のプラグインが、127.0.0.1 で待ち受ける streamable HTTP の MCP サーバーを持つ。モデルの読み込み、埋め込み、索引の書き込みは、このサーバーだけが行う。
- `.mcp.json` に stdio の中継を登録する。中継はロックを取り、生きているサーバーを使うか、なければ起動する。要求がない時間が続くと、サーバーは自分で止まる。
- ツールは `query`、`get_page`、`list_index`、`lint`、`stats`、`graph`、`index_chunks` の 7 つ。Wiki の Markdown を書き換えるツールは持たない。
- 索引は wiki の外（`%LOCALAPPDATA%/info-hive/index/<wiki のハッシュ>/`）に置く。
- `/wiki:query` などのコマンドは MCP のツールを呼ぶ形に移し、MCP が使えないときは今の CLI に戻る。

【確認済み】`info-hive-wiki` には `.mcp.json` もサーバーのコードもない。試作は `poc/rag/decision/mcp_probe/` にあるが、配布の対象ではない。

【記述】今の CLI の検索は 1 回に約 3.1 秒かかる（統一の測定、13 ファイルの標本）。

進め方の案:

1. サーバーと中継の骨組み。ADR-0001 の 3 つの条件（待ち受けのアドレスの固定、起動ごとのトークン、Host ヘッダーの確認）と、ロックによる二重起動の防止を先に作る。
2. 検索を新しい基盤に移し、`query`、`get_page`、`list_index` を出す。
3. `lint`、`stats`、`graph` を今のスクリプトの薄い包みとして出す（2 の回帰テストを使う）。
4. `index_chunks` を出す。ここで rag の移行が始められる。
5. コマンドを MCP のツールに移し、CLI への戻り道を残す。

【要確認】Claude Code のデスクトップアプリが stdio の MCP サーバーをどう起動するかは確かめていない（ADR-0012 の影響）。1 の段階で確かめる。

### 5. browse（閲覧）

【記述】ADR-0002（承認）は、必要なときだけ起動するローカルサーバーを決めている。ADR-0010（提案、決定日は未定）は、Wiki を解釈する中核を Python の 1 か所に置き、サーバー、アプリ、静的 HTML を薄いアダプタにする案である。【確認済み】`commands/browse.md` はまだない。

ADR-0010 の未決は 6 件ある。

1. ページ集合（lint と search で違う。ADR は lint の集合を正とする案を推している）
2. 書き出し先
3. 静的出力のファイル名
4. RAG への経路。ADR-0012 で 4 つ目の案（閲覧の画面を wiki の MCP サーバーのクライアントにし、rag の索引も含めて検索する）が加わった
5. 静的版の検索の範囲
6. アプリの技術

実装前の PoC で確かめる項目は 5 件あり、どれもまだ確かめていない。

進め方:

- 未決 1 を決めて ADR-0010 を承認する。未決 4 は、3 の MCP サーバーを使う案を軸に決め直す。
- PoC を済ませる。
- 作る順序は ADR-0010 のとおりにする。`resolve_link()` の切り出し、中核とテンプレート、静的に描ける第 1 段階、サーバーのアダプタ、検索とグラフと RAG の順である。

第 1 段階は 3 に依存しない。browse を急ぐなら、4 と並べて前に出せる。検索と RAG との連携は 3 が済んでからにする。

### 6. 知識を使うための機能

【記述】[LLM Wiki で蓄積した情報の活用方法の検討](wiki-knowledge-utilization-2026-11-06/brainstorm-diverge-converge.md) は、次の 3 つを着手の条件つきの候補にしている。

| 候補 | 着手の条件 |
| --- | --- |
| コンテキストの切り出し（焦点から k ホップ、行数の予算） | 実際の wiki で 2 ホップの被覆率を測ってから |
| 出典のチェーン（主張 → ページ → source → raw） | ページ単位なら今も動く。主張単位は `raw_ref` を書く規約を先に置いてから |

【確認済み】習慣の前提だった synthesis の保存例の不備は、0.2.1 で直った。
