# プロンプトのフックの段階 0 の測定（2026-11-17）

[ADR-0032](../adr/0032-wiki-prompt-hook-suggests-candidate-pages.md) の段階 0 の記録である。環境は Windows 11、uv 0.12.2、Python 3.14.6、Claude Code 2.1.325、info-hive-wiki 0.27.0 に段階 1 の変更を足したもの。結果の JSON は同じ名前のディレクトリにある。

## (a) 起動行

`tests/wiki/bench_prompt_hook.py launch`（30 回、依存のない入口の代わりのスクリプト）。結果は `launch.json`。

| 形 | p50 | p95 | 終了コード |
| --- | --- | --- | --- |
| exec（`uv` を直接起動） | 79 ms | 87 ms | 0 |
| Git Bash のシェル形式 + `; exit 0` | 140 ms | 226 ms | 0 |
| PowerShell + `; exit 0` | 509 ms | 530 ms | 0 |

| 失敗の場面 | exec | Git Bash | PowerShell |
| --- | --- | --- | --- |
| スクリプトがない | **2** | 0 | 0 |
| Python がない（`UV_PYTHON=3.99`） | **2** | 0 | 0 |
| uv がない | 測れず（注） | 0 | 0 |

- 注: Windows の CreateProcess は、子に渡した PATH ではなく親の PATH で実行ファイルを探すので、exec の「uv がない」は再現できなかった。
- exec は 2 を返すので採らない。UserPromptSubmit で 2 を返すと、利用者の指示が止まる。
- PowerShell の 0.5 秒は pwsh の起動そのものの時間である。Git Bash のない Windows ではこの遅れが足される。

## (c) ページ数への伸び

`bench_prompt_hook.py scale`（合成の wiki、5 回の p95）。結果は `scale.json`。

| ページ数 | `collect_pages` | セクションと BM25 | 合計 |
| --- | --- | --- | --- |
| 80 | 613 ms | 83 ms | 701 ms |
| 150 | 809 ms | 153 ms | 965 ms |
| 300 | 2,028 ms | 483 ms | 2,477 ms |
| 1,000 | 9,499 ms | 1,482 ms | 11,058 ms |

`import wiki_search` に 0.3〜0.5 秒かかり（`wiki_pages` が同梱の markdown-it を読み込む）、150 ページで基準（1.0 秒）を超えた。markdown-it を使わずに frontmatter と見出しだけを正規表現で読むと、80 ページで 14 ms、150 ページで 27 ms、1,000 ページで 149 ms だった。本文のトークン化を足すと、150 ページで 162 ms、1,000 ページで 1,052 ms だった。

そこで、フックは `wiki_search` を読み込まず、題、見出し、索引の要約だけを照らす形にした（本文は識別子の文字の照合にだけ使う）。トークン化は `wiki_tokens.py` に移した。実際のフックの時間（80 ページのプロジェクトの wiki、`uv run` を含む）は、飛ばす指示で約 140 ms、検索する指示で 400〜480 ms だった。

## (d) 発火の形

記録するだけの試験用のプラグインを `--plugin-dir` で読み込み、`claude -p`（Haiku）で確かめた。

- `additionalContext` はモデルに届く（足した合言葉にモデルが答えた）。起動行の `uv run …; exit 0` は Claude Code の中でも動く。
- スラッシュコマンドでは、`prompt` に打ったままの 1 行が入る（`/wiki-probe:ping hello`）。
- サブエージェントの中では発火しない。サブエージェントの報告が戻るときに、`<agent-message from=…>` で始まる `prompt` で発火する。
- `userConfig` の既定の値は、設定していなければ環境変数（`CLAUDE_PLUGIN_OPTION_*`）で届かない。既定はスクリプトの側で持つ。
- `--plugin-dir` のプラグインのデータの場所は `<名前>-inline` になる。
- マーケットプレイスの `wiki@info-hive` と `--plugin-dir` の `wiki` を同時に読むと、`--plugin-dir` の側のフックが登録される（`Plugin "wiki" from --plugin-dir overrides installed version`）。
- `--output-format stream-json` の記録には、UserPromptSubmit のフックの出来事は出ない。届いたかは `--debug-file` の `Hook UserPromptSubmit ... provided additionalContext (N chars)` で確かめる。
- `/loop` と他のセッションからの知らせは `-p` では再現できなかった。どちらもタグで始まる形で届くとみて、タグで始まる指示を飛ばす。
- デスクトップアプリで窓が出るかは、作者が目で確かめる。

## ゲートの評価

`tests/wiki/eval_prompt_context.py`。評価のデータ `tests/wiki/fixtures/prompt_context/prompts.json` は、関係あり（P）63 問、無関係（N1）60 問、短文（N2）40 問、利用者が打たないターン（N3）20 問である。並びの位置を 5 で割った余りが 3 か 4 の問いを確かめ用にし、しきい値は開発用だけで決めた。題材の wiki は親のコミット `faf9a6e` の `wiki/`（89 ページ）である。

| 版 | データ | 再現率 | 精度 | N1 | N2 | N3 |
| --- | --- | --- | --- | --- | --- | --- |
| 最初の試作（本文の一致あり） | 開発用 | 0.641 | 0.674 | 0 | 0 | 0 |
| 欄ごとの DF、強い一致で弱い一致を隠す | 開発用 | 0.872 | 0.672 | 0.167 | 0 | 0 |
| 1 語の一致に裏付け、版は 3 つの部分 | 開発用 | 0.872 | 0.776 | 0 | 0 | 0 |
| 要約の一致を 3 単位以上、本文の一致をやめる、題の差 0.2 | 開発用 | 0.872 | 0.894 | 0 | 0 | 0 |
| 同じ（調整はここまで） | 確かめ用 | 0.833 | 0.857 | 0 | 0 | 0 |
| 識別子を語の境目で照らし、数字のない大文字の語を除く | 確かめ用 | 0.917 | 0.893 | 0 | 0 | 0 |
| 同じ | 全体 | 0.889 | 0.893 | 0 | 0 | 0 |

- しきい値の格子（`INDEX_MIN` 2/3、`INDEX_RATIO` 0〜1、`BODY_COVERAGE` 0.5〜0.9、`NAME_MARGIN` 0.2〜0.5、`NAME_SHARE` 0.4〜0.6、`DOMINANCE` 0/1）は開発用のデータだけで比べた。本文の一致は、どの値でも採られるたびに精度を下げ（当たり 1 件、外れ 2〜4 件）、無関係な指示で発火した。
- 確かめ用で見つけて直したのは、仕組みの誤り（識別子の部分一致、`HTTP` を識別子とみなしたこと）と、評価のデータの誤り（`/` で始まる問い 2 つ）だけで、しきい値は動かしていない。
- 一致の種類ごとの当たりと外れ（全体）は、S2 が 41 と 6、S3 が 15 と 2、S4 が 11 と 0 だった。結果は `gate-eval.json`。
- 外れは、2 つの話題をまたぐ問いで、片方の話題のページだけが出るものが多い。

## 実際の発言での発火

このプロジェクトのセッションの記録（88 ファイル）から、利用者の発言 1,557 件を手元だけで取り出してフックに通した。発言はリポジトリに入れていない。

| 項目 | 値 |
| --- | --- |
| 検索の前に飛ばした | 920 件（コマンド、タグで始まるターン、圧縮の要約、短文） |
| 候補が出た | 111 件（7.1%） |
| 段 | R0 47、R1 58、R2 6 |
| 時間の p95（読み込み済みのプロセスの中） | 37 ms |

最初の版では 9.6% で、圧縮の要約が直接の参照で当たる、本文にある他の製品の版の番号（`0.4.0`）が当たる、の 2 つの型が目立ったので直した。

## 読む段の呼び出し

`claude -p --plugin-dir <worktree の info-hive-wiki>` で確かめた。

- R0（候補 1 件）の指示では、メインが自分でページを開いた。
- R1 の指示で、最初の書き方（「関係があるなら、Agent ツールで … を呼び」）では、メイン（Sonnet）が呼ばずに 1 ページを自分で読んだ。理由を添えて「自分で開かずに、Agent ツールを subagent_type=wiki:wiki-reader、model=haiku、effort=low で呼んで読ませる」と書くと、書いたとおりの値で呼び、サブエージェントが候補の 3 ページを読んだ。
