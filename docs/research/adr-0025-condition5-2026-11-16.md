## 製品の決まり（測るときもこれを使う）

確信度とページの判定は、製品のコードを通して測り、同じ決まりを測る側で作り直さない。

- **行の確信度:** `rag_ocr_confidence.line_records` の `confidence`。文字の確率と、終わりの記号の確率の最小値である。本文が空の行（読めなかった行）は 0 になる。
- **低い:** `rag_review.is_low` のとおり、`confidence_min < threshold`（等号は低くない）。
- **ページの確信度:** `rag_pdf.confidence_min` のとおり、そのページのすべての行の確信度の最小値。行のないページは 1.0。確信度が不明（`None`）のページは、低いとも高いとも扱わない。
- **確信度の低いページ:** 確信度が閾値より低い行が 1 つ以上あるページ（ADR-0025 の「ページ」）。
- **OCR の経路:** 選んだページごとに、`extract_pages` が OCR に使う関数（`rag_pdf.ocr_page`、`confidence_record`、`confidence_min`）を、`ocr_dpi` を既定の 150 にして呼ぶ。OCR は、rag の OCR の環境の `rag_ocr.py --worker` を `OcrClient` で動かす（1 回目のレビューの前は `extract_pages` を呼ぶと書いていた。546 ページの防衛白書の全ページを OCR しないために変えた。描画と OCR と確信度の関数は同じである）。
- **OCR するページ:** 製品は、`ocr_mode` が `auto`（既定）なら判定が `garbled`、`scan`、`vertical` のページを、`always` ならすべてのページを OCR する。(c) は、この 2 つの場合に分けて数える（下の「数えるもの」）。
- **製品の版:** rag 0.6.0 の候補（`feat/pdfminer-body-ocr-store`）、`OCR_CONFIDENCE_REVISION` は `confidence-v1`。

### 合成の PDF

- **原稿:** リポジトリの `docs/adr/` の ADR から作る。ファイル名の順に並べ、最初の 25 個を使う。1 つ目は試しの原稿（下の「試しの原稿」）とし、2〜25 個目の 24 個を測る原稿とする（1 回目のレビューの前は 12 個だった。原稿の数が少ないと、原稿に固有の誤りで偶然に合格しうるため、増やした）。各 ADR の本文から、Markdown の記号（見出しの `#`、表の `|`、強調、リンクの URL、コードの囲み）を除き、空白を詰めて、先頭の 1,520 文字を取る。フォントにない文字は、描く前に除く。

- **正解:** 描いた各行の文字と、描いた位置から求めた行の箱。
- **画像:** 描いた PDF を pypdfium2 で画像にし、次の 5 つを作る。どれも 1 つの強さだけで、条件を満たすように調整しない。強さは、事務のスキャンでよくある程度として決めた。

  | 名前 | 作り方 |
  | --- | --- |
  | `clean` | 150 dpi で描く |
  | `lowres` | 100 dpi で描く（製品が 150 dpi で描き直すときに引き伸ばされる） |
  | `blur` | 150 dpi で描き、ガウスぼかし（半径 1.0 ピクセル） |

  各画像を、同じ大きさ（A4）のページ全面に貼った、画像だけの PDF にする。製品は、この PDF を 150 dpi で描き直して OCR する。`skew` の正解の箱は、行の箱の 4 隅を同じ角度で回し、それを囲む箱にする。

### 正解から除く行

- 私用領域の文字（U+E000〜U+F8FF）、`(cid:<数>)`、U+FFFD のどれかを含む行（文字の層が、見た目の文字を表していない）。
- 下の「比べ方」の正規化をして、空になる行。
- 目での確かめで、画像と違った行。

除いた正解の行と直接つながる OCR の行と、除いた正解の行は、(a) と (b) に入れない。除いた正解の行と同じまとまり（下の「対応」）にあって、除いた行と直接つながらない OCR の行は、正解が分からないので、不利な側に数える。ページの判定（c）には、製品のとおり、そのページのすべての OCR の行を使う。

目で確かめて行を除いたあと、ページの決まり（正解の行が 10 行以上）を当て直す。外れたページは測らない（防衛白書は、上のとおり足す）。

## 行の対応と、行の誤り

(a) と (b) は、製品が確信度を持たせる単位である OCR の行ごとに数える。正解と 1 対 1 に対応しない行は、誤りかどうかが決まらないので、条件を満たしにくい側（不利な側）に数える。

- **つながり:** OCR の行 O と正解の行 G は、重なりの面積が、O と G の小さい方の面積の半分以上のとき、つながる。
- **対応:** つながりでできるまとまり（連結成分）を 1 つの対応とする。対応の本文は、正解の行も OCR の行も、読む順に並べてつなぐ。横書きは上から下、同じ高さは左から右。縦書き（OCR の `vertical`、pdfminer の `LTTextLineVertical`）は右から左、同じ列は上から下。
- **誤り:** 正規化した正解と OCR の本文の編集距離（Levenshtein、文字の単位）が 1 以上。

OCR の行ごとの誤りは、対応の形で次のように決める。閾値 t より低い行を「低い行」と呼ぶ。

| 対応の形 | OCR の行の誤り |
| --- | --- |
| 1 対 1 | 対応の誤り |
| 1 対 1 でない（OCR が 2 行を 1 行に読んだ、1 行を 2 つに分けたなど） | 対応に誤りがなければ、どの行も誤りでない。誤りがあれば、低い行は誤りでないとし、低くない行は誤りとする |
| 正解とつながらない（合成） | 正解は空なので、正規化した本文が空でなければ誤り |
| 正解とつながらない（公開） | 文字の層にない文字（画像の図の中の文字など）を読んだ行かもしれず、正解が分からない。低い行は誤りでないとし、低くない行は誤りとする |
| 除いた正解の行と直接つながる | 数えない |
| 除いた正解の行と同じまとまりにあるが、直接つながらない | 正解が分からないので、低い行は誤りでないとし、低くない行は誤りとする |

不利な側に数えるので、1 対 1 でない対応と正解とつながらない行は、(a) を下げ、(b) を下げる。その行の数を報告に書く。

- **読み落とした行:** OCR の行とつながらない正解の行。確信度がないので低い行にはならず、(b) の分母に「捕えていない誤り」として入れる。

## 比べ方（正規化）

正解と OCR の本文の両方に、次の順で当てる。

1. Unicode の NFKC。
2. 空白（Python の `str.isspace` が真の文字）を除く。
3. 見た目の同じ記号をそろえる。

   | そろえる先 | 元の文字 |
   | --- | --- |
   | `-` | U+2010、U+2011、U+2012、U+2013、U+2014、U+2015、U+2212、U+FF0D |
   | `~` | U+301C、U+FF5E |
   | `'` | U+2018、U+2019、U+201A、U+201B |
   | `"` | U+201C、U+201D、U+201E、U+201F |
   | `・` | U+FF65、U+00B7 |

## 数えるもの

閾値 t ごとに、資料の側（選ぶ、確かめる）と種類（合成、公開）ごとに数える。

- **(a) 低い行の誤りの割合:** 低い OCR の行のうち、誤りの行の割合。
- **(b) 誤りのうち低い行の割合:** 誤りの OCR の行と読み落とした行のうち、低い OCR の行の割合。
- **(c) 低いページの割合:** OCR したページのうち、確信度の低いページの割合。`always`（選んだすべてのページ）と `auto`（判定が `garbled`、`scan`、`vertical` のページ）に分けて数える。確信度が不明なページは、分母にも分子にも入れず、数を書く。

参考として、文字の誤りの割合（1 対 1 の対応の、編集距離の合計 ÷ 正解の文字数）、画像の種類ごと（合成）と PDF ごと（公開）の (a)〜(c)、1 対 1 でない対応と正解とつながらない行の数を書く。

## 閾値の選び方（選ぶ資料だけを使う）

候補は 0.01 から 0.99 まで 0.01 おきの 99 個とする。

1. 余裕 m を 0.05 として、合成と公開のそれぞれで、(a) ≥ 0.5 + m、(b) ≥ 0.8 + m、(c) ≤ 0.2 − m をすべて満たす候補を集める。(c) は `always` と `auto` の両方で満たす（`auto` で OCR するページがない種類は、`always` だけ）。両方で満たす候補（共通部分）があれば、その中央値を選ぶ（数が偶数なら、小さい方）。
2. 1 で候補がなければ、m を 0 にして同じことをする。選んだら、余裕のない閾値であることを報告に書く。
3. 2 でも候補がなければ、ここで止める。確かめる資料は測らない。ADR の「満たさないとき」のとおり、確信度の数え方か、確認の単位を見直す。

中央値にするのは、(b) の境目ちょうどの閾値を選ぶと、確かめる資料での小さなぶれで (b) を外すためである。

選んだ閾値、候補の集まり、選ぶ資料での (a)〜(c) を記録してコミットしてから、確かめる資料を測る。

## 合否（確かめる資料で、1 回だけ）

選んだ閾値で、合成と公開のそれぞれについて、次をすべて満たせば合格とする。

1. **点の値:** (a) ≥ 0.5、(b) ≥ 0.8、(c) ≤ 0.2（ADR-0025 の基準のまま）。(c) は `always` と `auto` の両方。
2. **偶然の合格を除く:** 片側 95% の限界で、(a) の下限 ≥ 0.5、(b) の下限 ≥ 0.8、(c) の上限 ≤ 0.2（`always` と `auto` の両方）。同じ原稿の行とページは一緒に変わりうるので、行やページを独立とみなさず、単位（合成は原稿、公開はページ）ごとに数える。比 R = Σy / Σx（y と x は単位ごとの分子と分母）の分散を、単位ごとの残差 y − R·x で線形化して見積もり（n/(n − 1) を掛ける。n は単位の数）、自由度 n − 1 の t 分布の 95% 点を使う。分母が 0 の単位も n に数える。
3. **数が足りている:** 低い行が 20 以上、誤りの行が 20 以上、`always` と `auto` のそれぞれで OCR したページが 20 以上。足りなければ「判断できない」とし、合格にしない。

合格しなければ、ADR の「満たさないとき」のとおり見直す。見直したあとに確かめ直すときは、今回の確かめる資料を使わず、新しい原稿と新しい PDF で確かめる資料を作り直す。

## 試しの原稿で見たこと（選ぶ資料を測る前）

試しの原稿（`dev`、5 ページ、190 行）を、1 回目のレビューの前の数え方で数えた。

- 190 行すべてが 1 対 1 に対応した。座標の変換と行の対応は、この原稿では働いた。
- 190 行のうち 80 行（42%）に誤りがあり、文字の誤りの割合は 2.7% だった。多くは英字と数字の読み違い（`G` を `6`、`Q4` を `04`、`l` を `I`、`TypeScript` を `Typescript`）で、確信度が 0.9 を超える誤りも多かった。
- 閾値 0.5 で、低い行は 4 行、誤りのうち低い行は 4%、低いページは 5 ページ中 3 ページだった。

この結果は、選ぶ資料でも閾値が決まらない見込みが高いことを示す。測り方は、この結果を見たあとでも、条件を満たしやすい方には変えない（1 回目のレビューで直したところは、どれも条件を満たしにくくする）。

## 1 回目のレビューで直したこと

Sol の 1 回目のレビュー（`docs/agent-runs/2026-11-16-adr-0025-condition5-review/review-1.md`、却下）の 4 つの重大な指摘を、次のように直した。

1. 正解とつながらない OCR の行を (a) と (b) から除いていた。合成では誤りとして数え、公開では不利な側に数える。
2. 対応の確信度（最小値）と対応の誤りを組み合わせ、正しい低い行が、別の行の誤りを捕えたことになっていた。OCR の行ごとに数え、1 対 1 でない対応は不利な側に数える。読み落とした行も、捕えていない誤りとして (b) に入れる。
3. 点の値と 20 件以上だけでは、偶然の合格を抑えられなかった。片側 95% の限界を合否に加え、合成の原稿を 24 個に増やした（限界の数え方は、2 回目のレビューで直した）。
4. `always` で OCR したページだけで (c) を数えると、`auto` の確認の量が分からなかった。(c) を `auto` でも数え、`auto` で OCR するページが少ない公開の確かめる資料には、縦書きのページを足す。

## 2 回目のレビューで直したこと

Sol の 2 回目のレビュー（`review-2.md`、却下）の 2 つの重大な指摘と 2 つの軽微な指摘を、次のように直した。

1. スクリプトが、除いた正解の行を含むまとまりの OCR の行を、すべて除いていた（文書は、直接つながる行だけを除くと書いていた）。除くのは直接つながる行だけにし、同じまとまりの残りの行は、正解が分からないので不利な側に数える。
2. 行とページを独立とみなした Wilson の区間と、原稿を 1 つ除く検査では、少数の原稿に誤りが固まったときに偶然に合格しえた。単位（合成は原稿、公開はページ）ごとの線形化の分散と t 分布の限界に替え、原稿を 1 つ除く検査は外した。
3. 目で確かめて行を除いたあとに、ページの決まりを当て直していなかった。当て直し、外れた防衛白書のページは、決めた順で足す。
4. 文字の誤りの割合の対象を、スクリプトに合わせて、1 対 1 の対応と書いた。

## 測る前に分かっている難しさ

ページは、閾値より低い行が 1 つでもあれば低くなる。1 ページが 38〜40 行で、正しく読めた行が低くなるかどうかがページの中で独立なら、誤りのないページが (c) の 2 割に収まるには、正しく読めた行が低くなる割合が、1 行あたり約 0.56%（1 − 0.8^(1/40)）以下でなければならない（低い行が少数のページに固まれば、この限りでない）。また、誤りのある行を含むページが 2 割を超えると、(b) と (c) を同時に満たすのは難しくなる。

合成の資料は 5 つの画像のうち 4 つを劣化させているので、劣化した画像で誤りが多ければ、合成の (c) は満たせない。その結果は、ページごとの確認がスキャンの PDF では重すぎることを示すものとして扱い、画像の配分を測ったあとに変えて合わせない。
