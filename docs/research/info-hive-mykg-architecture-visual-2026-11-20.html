公開版で保存（任意）

記事を変える候補でグラフを再生成し、記事・定義・グラフ・必須の Ossie 成果物を1つの release_id で切り替える。

図は保存の分担。目次は index.md などで、検索用キャッシュとは別。「公開版」はローカル wiki の確定版を指し、インターネットへの公開ではない。手で保守する ontology.yaml と原本の raw は、生成キャッシュと分けて残す。

MCP は共有のローカル索引を使う。公開版の release_id による版固定とは別。この切替は構成の説明で、実際の wiki を変更する操作ではない。

MCP は記事を書かない。
stdio の中継が 127.0.0.1 の共有サーバーへ接続する。ライブの検索は Tantivy と usearch。CLI の代替検索は別の索引系。

公開版では同じ ID を引き継ぐ。
query → get_page / graph / browse を同じ release_id にそろえる。公開成果物の版固定であり、外部 raw や PDF は別途指紋を照合する。

GENERATED GRAPH

グラフは、明記した関係の索引。

記事の graph メタデータと wikilink を ontology.yaml に沿ってコンパイルする。記事を変える公開保存では候補の中で検査・再生成する。自由文から新しい意味関係を作る LLM の段とは別。

BROWSE / OVERVIEW

読む画面も、記事から派生する。

概要はサイドカーに保存し、元記事を変えない。browse の静的 build は Mermaid を Pele の SVG に書き出す。serve は隔離した枠で描画する。PNG との比較は調査で、出力を PNG に変えた実装ではない。

lint：形式と内容を分けて点検

リンク・引用欄・型の不整合は機械で検査する。主張の妥当性はホストが本文で確認する。型付き辺のないノードと、被リンクのないページは別の検査。

対象を混同しない
myKG は全エッジがゼロの点。ここでは orphan_typed_nodes を使い、被リンクゼロのページを使う通常 lint とは分ける。

結べない点は残す
孤立は誤りとは限らない。回数と費用を制限し、原文に根拠がなければ新しい関係を採用しない。

破線は追加する工程・接続。実線は既存機能。意味の候補を生む処理と、採用済みの Markdown をコンパイルする処理を分ける。

進める順序の提案既存の版・原本の指紋を使う→少数の候補で採否を評価→抽出の再開と孤立点検を足す

真偽を型検査だけで決めない

引用や語彙の形式が正しくても、意味上の支持は別。任意の D2 は既定無効で、失敗時は継続する。

myKG の制約は引き継がない

スキーマ検証は警告で続く場合があり、混合バッチは出所を過剰付与しうる。DiGraph の多重関係の制約もそのまま採らない。

公開版の実装と本番可否は別

適用と版固定は v0.39.0 にある。初回データの準備と、保存先・停止・復元の実証は別。開発中の wiki_restore は数えない。
