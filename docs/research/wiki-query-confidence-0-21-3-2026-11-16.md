### 測った版と出す版の違い

測ったあと、次の 3 つを直してから出す。

1. **その場で検索し直したときに上限が外れる条件。** 測った版は「正常な hybrid の結果にそのページが出ていて、ほかに関係するページが出ていなければ」としていた。Sol の 7 回目のレビューで、「関係する」の範囲しだいで高と中に分かれると分かった。出す版は、正常な hybrid の結果にそのページが出ているかだけで決め、ほかの結果のページは手順として読んで矛盾を確かめる。48 回のうち、縮退に当たったあとで検索し直した回は 0 回だった。ただし R16 r2 は、回答に「`Grep` で見つけたので縮退に当たるところを、検索し直して外した」「ほかに関係するページは出なかった」と書いた。記録では、ページを開く前に hybrid の検索を呼んでいるので、決め方の 2 で「高」になり、判定は同じである。0.21.2 を取り込む前の版で流した試しの R16 r1 は、`Grep`、ページを開く、MCP の `query` の順で、この経路を実際に通った（「高」、理由に検索し直したことを書いた）。
2. **探す道具を数えるときの「wiki のページ」の範囲。** 測った版は `graph/` の下のファイルを含むかを書いていなかった。R08 r1 は、開く前の `Glob("wiki/graph/*")` が `graph/README.md` を返し、数えるかが 2 通りに読めた（回答は数えなかった）。出す版は、インデックスに載るページだけを数える。
3. **0.23.0（YouTube の字幕、ADR-0027）の取り込み。** 上限の表に動画のソースの 3 行が入る。試験用の wiki に動画のソースはないので、測った問いには当たらない。

### 理由が規則どおりか

ラベルが合った 41 回と alt の 3 回のうち、理由に規則と合わないところがあったのは 3 回である。

- R04 r1: 料金表を MCP の検索の前に `Bash` の `cat` で開いたのに、理由に「`query` の hybrid 検索の結果から開いた」と書いた。
- R12 r2: 開く前に `Grep` も呼んでいたので、理由 0 が先に当たる。回答は理由 4 と書いた。上げる方法は結果として同じだった。
- R16 r3: 理由に見つけ方を書いていない。

規則どおりだった主な点は、次のとおりである。

- **エッジ（R07、R08）:** 6 回とも `neighbors` を呼んだ。ノードの ID は、R07 が `concept:差分同期`、R08 が `product:tsuyukusa-cli` で、6 回とも 1 回目の呼び出しで見つかった。「高」にした R08 の 2 回（r1、r3）は、どちらも `confidence: medium` に触れた。そのうえで、「エッジから導かず、要約ページの本文で直接確かめたので上限に数えない」と書いた。
- **縮退（R09〜R12）:** 12 回とも、答えのページを初めて開く前に縮退した検索を呼んでいた（決め方の 3）。理由ごとの上げる方法も合っていた。R12 r1 は「ページ本体を読んでも、この上限は外れない」と書いた（案 3）。前回の試しの回 R12 r0 のように、ページを読んだことを理由に上限を外した回はなかった。
- **縮退の対照（R13）:** 3 回とも、探す道具を呼ぶ前にインデックスから管理者ガイドを開いた。あとの `Grep` か MCP の検索は「すでに開いたページの矛盾の確認」と書き、縮退を数えなかった。

## 測っていない規則と、測り方の限り

- **理由 0（`Grep` で見つけたページの「中」）は、R12 r2 の 1 回（縮退した検索と重なった回）でしか起きていない。その場の検索し直しで上限を外す経路は、この 48 回では起きず、試しの回（取り込む前の版の R16 r1）の 1 回だけである。** R16 で `Grep` を指示しても、Sonnet は多くの回で先に MCP の検索を呼んだ。この 2 つを測るには、MCP の `query` を使えない条件で `Grep` を指示する問いが要る。
- **エッジだけの前提（本文で確かめられないエッジ。出発点を「中」にする）は、試験用の wiki に当たるエッジがないので測っていない。**
- **測ったのは出す版の 1 つ前のコミットである。** 違いは上の「測った版と出す版の違い」の 3 つで、このうち 1 と 2 は、この 48 回では判定に関わる経路を通っていない（2 は R08 r1 の 1 回が、出す版の読みと同じ判定だった）。
- **wiki が小さく、モデルは Sonnet 5.5 だけで、1 問 3 回である。**

## 再現の手順

`wiki-query-confidence-0-21-3-2026-11-16/scripts/` にスクリプトがある。前回のスクリプトを写し、次を変えた。

- `paths.py` は、試験用の wiki を前回の `fixture/wiki` から作る。

```bash

python run_all.py
python aggregate.py
python export_summary.py
```

ready の索引は、同じサーバーで 3 回呼ぶと埋め込みが終わる（`probe_mcp.py ready ... 5`）。判定（`J`）は回答を読んで付けたもので、ログの SHA-256 を `judged-logs.json` に記録している。判定を付けた全回の要約は [runs-summary.json](wiki-query-confidence-0-21-3-2026-11-16/runs-summary.json) にある。
