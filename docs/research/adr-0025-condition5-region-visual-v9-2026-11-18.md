# 条件5：region-v9で必要になる画像の正解

合否、正規化、評価行、OCR本文と整数箱、元の字の所属の0.5と直交中心は変えない。旧正解・旧監査を保存し、別の版で画像の正解を補う。ここで使う問題行の確認は無作為の領域監査とは区別する。

## 対象

region-v9の全120頁8822行を列挙する。新たな書き起こしの対象は、(1) v9が未決定の全行、(2) v9の自動確定と既知の目視正解が正規化後に違う全行、(3) 旧監査で問題になった全51行の和集合とする。以前の目視がある未決定行も、旧指示と所属の規則の整合を未確認のまま再利用せず、すべて新しく読む。既存目視を再利用するのは、v9自動確定と正規化後に一致し、箱とOCR本文のSHAが一致する行だけとする。印や正誤で一部を除かない。新旧の件数と重なりを記録する。

旧監査v6と450 DPI診断の「箱内の画素だけで読む」という指示の回答を、新しい所属指示による書き起こしとして再利用しない。既存目視と領域の違いも、新しい回答ができるまでどちらが誤りかを確定しない。

旧目視が既知だった再確認行でも、新しい読みが未決定なら旧目視で補わず、不明のまま全配置の評価へ残す。これは、所属規則がそろったと確認できていない答えを確定にしないためである。不明の割合や組み合わせが増えて測れなくなる場合も、その結果を受け入れる。以前の目視自体は保存する。

## 画像と指示

各担当は新しい文脈で、自分専用の一段下のフォルダーの画像と匿名一覧だけを読む。資料名、OCR本文、文字層の本文、旧正解、候補文、印、点数、対象となった理由を示さない。対応表はcorpus内に残す。OSの権限による隔離ではなく、範囲外を読まない指示による運用上の遮蔽である。

固定150 DPIの枠なし周辺と枠あり周辺を3倍の最近傍で示す。同じ原本の450 DPIにも、固定150 DPIの連続アフィンからPDF user spaceを経由して同じ物理箱と周辺を写す。単純な3倍による丸めの違いを持ち込まない。長い画像は重なる分割を作り、両解像度・枠あり/枠なしの全分割の閲覧を求める。150 DPIと450 DPIの読みが違う場合、字の識別には450 DPIを使えるが、所属は固定150 DPIのインクの範囲で判定する。

所属軸xは、字のインクの左右の長さの0.5以上が枠内で、上下のインク中心が枠内にあること。所属軸yは、上下の長さの0.5以上が枠内で、左右のインク中心が枠内にあること。文字自体が縦書きか横書きかとは別に、一覧で指定された軸を使う。部分的に枠外でもこの規則を満たす字は全体を含める。同じ字を識別するために枠外の部分を見てよい。枠に属さない別の字を足さず、見えない文を文脈で補わない。転記順は画像の自然な読む順とする。

文字の識別または所属が決められなければ行全体をunreadable、本文を`?`とする。字がないと決めた場合はempty、本文は空にする。それ以外はreadableとして本文を書く。区別する必要のある句読点や同形に見える字を、都合よくそろえない。

## 受領と照合

全対象を二つの独立した新しい文脈で画像だけから読む。段を進める際に担当番号への配分を回し、担当は束ごとに新規のagentとして起動する。全受領でagent_idの使い回しを拒否し、rootが実際に起動したIDへ結ぶ。担当を匿名化した別のフォルダーへ分け、最初の回答は次の担当へ示さない。二人の既知の回答が既存のnormalizeで一致した場合だけ確定候補とし、違うか未決定なら三人目の新しい文脈で画像だけから読む。既知の二人が一致しなければ未決定のままとする。同じモデルの共通の読み違いを排除する保証とは呼ばない。

各束は画像を開く前に、corpus内の全対応のSHAをresultsにも記録する。公開した束のSHAと受領のSHAが一致しなければ次へ進めない。両辺が長い周辺画像は二次元に分け、各詳細は両辺とも1450画素以下とする。担当の一覧に頁の絶対座標を渡さない。

rootは、各束のSHAと公開記録のSHAが道具の実行結果へ出たことを確認してから担当を起動する。コミット前の作業ツリーだけに固定の証拠を依存させない。これはOSの隔離や第三者の時刻証明を与えるものではない。

回答は`truth.json`、実際に開いた画像名の重複しない配列は`viewed.json`へUTF-8で書く。受領時に全ID・形式・必要な閲覧・元の全ファイルのSHA・余分なファイルのないことを検査する。実際に開く道具の記録と自己申告の閲覧記録は区別する。回答、閲覧記録、一覧、全画像をcorpusへ退避し、現物・退避・受領に記録したSHAを各段の集計へ結ぶ。後から回答を修正して受け取らない。

準備前に方法・コード・テスト・依存・旧固定入力・v9の全生成物を固定し、各段の前後で確認する。新しい画像の正解は、公開の結果へ本文を出さず、数とSHAだけを出す。対象をすべて処理した後、旧正解優先との差、決定/未決定の変化、残る不明行を報告する。読めない行を評価対象から除かず、元の全配置による限界の計算へ渡す。

この作業自体を新しい無作為の監査や合否と呼ばない。新しい正解で固定した判定を検証し、別に種20261118で全層から領域の監査を行う。独立検証と製品の切り替えはその後に残る。
