## 統合レビューとCIの移植性

Opus 5.5/highの統合レビューは採用可、致命的・重大0件だった。走査・概要・翻訳確認と遅延初期化の統合、トークン化の同一性、モデル決定とハッシュ、739件のログと60回の測定の数値を確認している。子のマージ後に、親の参照を実際のmainのマージコミットへ更新する点も指摘され、公開手順に組み込んだ。

親PR #179の最初のWiki walkのCIでは、次の試験環境の差が見つかった。製品のコードは変更せず、試験と証拠ファイルの属性を直した。

- Windowsのcheckoutで、ハッシュで結んだJSONがCRLFへ変換された。測定とレビューの保存領域を `.gitattributes` の `-text` で保護し、記録時のLF/CRLFのバイト列を保つ。期待するハッシュの値は変えない。
- Windowsの短いパス名と長いパス名がvenvの比較で一致しなかった。interpreterの親ディレクトリを正規化して比較する。POSIXのpython本体はvenvの外へ向くsymlinkなので、本体のresolveでvenvを消さない。
- GitHub ActionsのPythonはBelowNormalを継承していた。APIを拒否する試験ではNormal固定でなく、変更前に観測した継承クラスを親子が維持することを検査する。
- Linux/macOSの走査のI/O監視が、遅延初期化による同梱パーサーの所在の検査まで「wikiの外」として拒否した。統計は本文を解析するので、wikiの走査の監視を始める前にパーサーを初期化する。走査だけでは解析器を読まない試験と、除外ディレクトリへ触らない監視は両方維持する。

初回の失敗は https://github.com/to884/info-hive-dev/actions/runs/44202117200 。修正対象のローカル8件は成功した（`ci-fixes-local.log`）。
