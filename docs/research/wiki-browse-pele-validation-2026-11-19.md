# 静的版 browse の Pele を実際の図と 50 図の再表示で確かめた

2026年11月19日。静的版の採用方式は [ADR-0035](../adr/0035-wiki-browse-prerenders-diagrams-with-pele.md) に記した。

## 実際の wiki の図

開発用 wiki の 108 ページを `wiki_browse.py build` で書き出した。Mermaid 原稿はフロー図 6 件とシーケンス図 1 件で、すべて明暗の SVG ができた。計 14 枚で 66,774 バイトだった。

静的ファイルを Playwright の Chromium と Windows 版 WebKit で開いた。ビュー幅 390 px で明暗を切り替え、7 図それぞれで画像と元のコードを開けた。図の表示幅は 327〜334 px だった。SVG の文字の境界とスクリーンショットを確認し、図の外へ切れたラベルは見つからなかった。

| 図 | 元の SVG 幅 | 390 px ビューでの最小文字サイズの目安 | 観察 |
| --- | ---: | ---: | --- |
| 初期化された wiki の判定 | 432 px | 10.8 px | 上から判定へ進み、左右に分岐する。`/wiki:init を案内` は別行に出る |
| コマンドの引数の渡し方 | 602 px | 7.8 px | 長いラベルのある分岐で図全体が縮み、枝の文字が小さくなる |
| 敵対的レビューで設計を直す進め方 | 486 px | 9.6 px | 右の戻り線と本文の流れを区別できる |
| Claude の thinking とツールの流れ | 334 px | 14.0 px | シーケンス図の 3 列を保つ。参加者名とメッセージは複数行になる |

文字サイズの目安は SVG の最小フォントサイズに、表示幅を元の幅で割った値を掛けた。Chromium で幅の広い図の SVG を開き、2 倍に拡大すると細い文字と矢印も輪郭を保った。狭いページに収めたときの文字の小ささは残る。

## 50 図を同じタブで 10 周表示した測定

同じ合成フロー図 50 件を使った。原稿の JSON の SHA-256 は `f882a73df7f2836ca48331909d35c7d2941b874c0709015fb59a202fbfcf1741`。対照には前回の Mermaid SVG と、その SVG を resvg 0.50.0 で変換した PNG をそのまま使った。Pele 1.13.0 の明暗 SVG は、実装と同じ書き出し処理で作った。

Windows 版 Playwright WebKit 26.0 の新しいブラウザで各方式を 2 回測り、2 回目は順番を逆にした。1 周ごとに明暗各 50 枚を `<img>` で表示し、全画像をデコードしてから暗色のまま 5 秒待った。1 ケース内では同じ文書とタブを使い、手動 GC は要求しなかった。私有コミットはブラウザのルートと子孫プロセスを合計し、10 周中の観測ピークから描画前の値を引いた。デコード時間は 50 枚をページに入れ始めてから先頭図の `decode()` が完了するまでの値である。

Mermaid SVG と PNG の図は 572 × 61 px、Pele SVG は幅 319 または 334 px、高さ 68 px だった。同じ原稿を各方式で書き出したときの比較であり、SVG と PNG の形式だけを変えた比較は Mermaid SVG とその PNG の間に限られる。

### 結果

| 方式 | 観測ピーク私有コミット増分の中央値 | 10 周目の待機後の私有コミットの中央値 | 明暗 100 枚の合計 |
| --- | ---: | ---: | ---: |
| Mermaid SVG | 63.72 MiB | 857.14 MiB | 1,282,530 バイト |
| Mermaid SVG を変換した PNG | 33.78 MiB | 811.12 MiB | 287,735 バイト |
| Pele SVG | 1.48 MiB | 794.31 MiB | 226,460 バイト |

Pele の増分は 1 回目が 1.49 MiB、2 回目が 1.46 MiB だった。Pele の画像合計は Mermaid SVG より 82.3%、PNG より 21.3% 小さかった。

| 方式 | 初回の明色、2 回分 | 初回の暗色、2 回分 | 2〜10 周目の中央値、明色／暗色 |
| --- | ---: | ---: | ---: |
| Mermaid SVG | 180、191 ms | 156、181 ms | 7.5／8.0 ms |
| Mermaid SVG を変換した PNG | 134、121 ms | 138、152 ms | 10.0／9.0 ms |
| Pele SVG | 126、109 ms | 151、159 ms | 8.0／8.0 ms |

初回の値は 2 回分で、PNG と Pele では明色と暗色で順序が入れ替わった。この測定から初回表示の速度差を一般化しない。6 ケースとも 10 周を完了し、各ケースの Web プロセスの PID は維持された。メモリと画像サイズは、この 50 図と Windows 版 WebKit での結果である。

採用判断では、実際の図を 7 件とも書き出せたことと、50 図の再表示で小さい増分だったことを確認した。小画面で長いラベルがある図は、拡大して読む必要がある。
