# PDF の本文の取り出しの品質の判定

あなたは、PDF から取り出したテキストの品質を判定する審査員である。LLM が管理する wiki（info-hive）では、PDF の本文をテキストとして取り出し、LLM がそれを読んで要約ページを書く。取り出し方を選ぶために、同じページを 5 つの方式で取り出した結果を比べたい。

## 読むもの

- `docs/research/adr-0024-verification-2026-11-15/judge3/<ページ>/page.png`: ページの画像（100 dpi）。これが正解である。画像を見て、ページに何がどの順で書かれているかを確かめる。
- `docs/research/adr-0024-verification-2026-11-15/judge3/<ページ>/<記号>.txt`: 取り出したテキスト。記号（A〜E）はページごとに無作為に付けてあり、方式の名前は伏せてある。
- `docs/research/adr-0024-verification-2026-11-15/judge3/manifest.json`: 判定する写しの一覧。`digest` の値を、出力の JSON の `judge_digest` にそのまま書く。

`judge3/` のほかは読まない。とくに、方式の名前が分かるファイル（`outputs/`、計測のスクリプト、結果の表）を探さない。判定は、画像とテキストの中身だけで行う。

出力には、Markdown の見出しや表の記法を付けるもの、ページの画像を OCR したものもある。どれも、書き方ではなく中身で判定する。

ある方式は、ページを「OCR が要る」と判定したとき、本文の代わりに「（このページは OCR が要る: <種類>）」という 1 行だけを出す。これも、そのまま判定する（本文がないので、網羅と読み順は低くなる）。

## ページ

| フォルダ | 中身 |
| --- | --- |
| `bert-p1`、`bert-p6`、`bert-p7` | LaTeX で作った英語の論文。2 段組み。p6 と p7 には表がある |
| `whitepaper-point-p1` | 日本の官公庁の資料（組版のソフト）。日本語 |
| `whitepaper-summary-p2`、`-p4`、`-p7`、`-p11` | 日本の官公庁の資料の概要。スライドのような版面で、図と表が多い。図の中の文字は画像のことがあり、どの方式でも取れない。それは減点しない |
| `kanpo-p1-p1`、`kanpo-p2-p1` | 官報。縦書きで段組み。縦書きは、右の行から左の行へ、各行は上から下へ読む |

## 判定の軸

それぞれのテキストに、次の 5 つの軸で 1〜5 の点を付ける（5 が最良）。当てはまらない軸は `null` にする。

1. `coverage`（網羅）: ページの本文（画像になっている図の中の文字を除く）が、どれだけ欠けずに出ているか。
2. `order`（読み順）: 原本の読む順に読めるか。段の混線、行や文の入れ替わりは減点する。
3. `table`（表）: 表のセルの対応（どの値がどの行と列に属するか）を、テキストから復元できるか。表のないページは `null`。
4. `legibility`（文字の正しさ）: 文字化け、別の文字への置き換わり、1 文字ずつの改行のような、読みにくくする崩れがないか。
5. `usability`（総合）: LLM がこのテキストだけを読んで要約を書くとき、誤解せずに使えるか。

点のほかに、意味を変える誤り（段の混線、値の取り違え、文字化け）があれば、テキストの行を挙げて具体的に書く。推測は推測と書く。

## 出力の形

最終メッセージに、次の 2 つをこの順に書く。

1. 次の形の JSON を、```json のコードブロックに 1 つだけ書く。

```
{
  "judge_digest": "<manifest.json の digest>",
  "bert-p1": {
    "A": {"coverage": 5, "order": 4, "table": null, "legibility": 5, "usability": 4, "fatal": ["…"], "comment": "…"},
    …
  },
  …
}
```

`fatal` と `comment` は日本語で書く。`comment` は 2 文以内にする。

2. `## 総評` の見出しのあとに、日本語で、ページの種類ごとに分かった傾向を箇条書きで 8 項目以内にまとめる。方式の名前は推測しない。
