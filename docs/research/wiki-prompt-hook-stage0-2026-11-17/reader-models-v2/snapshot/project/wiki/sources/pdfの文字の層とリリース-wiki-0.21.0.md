# PDF の文字の層の取り出し（ADR-0025 の段階 1）と wiki 0.21.0 のリリース

ADR-0025（PDF の文字の層を pdfminer の縦書きの検出ありで取り出す）の実装の段階 1 と、それを出した wiki 0.21.0 の記録である。レビューの依頼と結果は `docs/agent-runs/2026-11-16-adr-0025-stage1-review/` にある。

## したこと

- wiki に `wiki_pdf.py` を足し、取り込みの手順 2 で PDF をこれで読むようにした（to884/info-hive-wiki#70）。判定と取り出しの本体は `wiki_pdf_layer.py` で、rag の `rag_pdf_layer.py` と同じバイト列である（to884/info-hive-rag#11。rag の取り込みの動きは変えていない）。
- 契約の試験（ADR の試験 1、2、6、7）を `tests/contract/test_pdf_layer.py` に置き、Windows と Linux、Python 3.12〜3.14 で CI に流す（to884/info-hive-dev#138）。
- 本文の並びを決まった順にする製品の関数を、モジュールの変数を書きかえない形で作った（[[pdfminerの本文の並びの揺れ]]）。

## レビューで分かったこと

Sol の敵対的レビューを 2 回受けた。進め方は [[敵対的レビューで設計を直す進め方]] と同じである。

- 1 回目は条件付きで採用可で、重大な指摘が 2 つあった。
  - ページの数を全部読んだあとにしか比べていなかったので、途中のページだけを読むと、PDFium と pdfminer のページの対応のずれに気づかなかった。最初のページを返す前に比べる形に変えた。
  - 古い rag の手順に要る「文字の層の本文が空のページ」が `--json` になかった。一覧を足し、PDF の SHA-256 も照らすようにした。
- 軽微な指摘で、上限を守ること（最小 500 文字）、続きの位置に抽出の識別を入れること、続きがあるときの終了コード 3、試験 7 の対照を元の `id()` で確かめることも直した。
- 2 回目は採用可だった。ページの数を比べるためにページツリーを毎回たどる費用（500 ページで 1 回 0.16 秒）は、対応の検査を優先した割り切りとして説明に書いた。

## CI で分かったこと

- **改行:** Windows の CI は `core.autocrlf=true` で取り出す。wiki は `.gitattributes` で LF に固定しているが、rag にはなかったので、`rag_pdf_layer.py` が CRLF になり、「同じバイト列」の試験が落ちた。rag の `.gitattributes` で、このファイルだけを LF に固定した。2 つのリポジトリに同じ中身のファイルを持つときは、両方で改行を固定する。
- **入口の分類:** wiki のスクリプトに `__main__` を持つ入口を足すと、`tests/wiki/test_uninitialized_wiki.py` の分類表（`TAKES_WIKI`、`RUNNERS`、`NO_WIKI`）に入れないと落ちる。`wiki_pdf.py` は wiki のパスを受け取らないので `NO_WIKI` に入れた。
- **版の番号:** 版を決めたあとで、別のセッションが同じ 0.20.0 を出した。main を取り込み、0.21.0 に振り直した（[[リリースの確かめ方]]）。
- 親の PR は、ほかのセッションが `wiki/log.md` に記録を足すたびに 4 回競合した。どれも末尾の行だけで、main の行を先に置いて解いた。

## リリース

- `v0.21.0` は、注釈付きのタグで、#70 のマージコミット（`e21cfd8`）を指す。GitHub リリースの本文は、CHANGELOG の 0.21.0 の節と同じである。
- 使い捨ての設定フォルダーで、マーケットプレイスから `rag@info-hive` を入れると、依存の wiki 0.21.0 が入った。v0.20.0 から v0.21.0 までに変わった 6 つのファイルが、すべてタグの中身と一致した。入った rag（0.5.3、main）の `rag_pdf_layer.py` も、入った wiki の `wiki_pdf_layer.py` と同じだった。
- 入った `wiki_pdf.py` を、公開の BERT の PDF で動かした。`--json` は 16 ページを判定し、確かめるべきページ（4、6）を返した。本文の読み出しは終了コード 3 で終わり、続きの位置を返した。
