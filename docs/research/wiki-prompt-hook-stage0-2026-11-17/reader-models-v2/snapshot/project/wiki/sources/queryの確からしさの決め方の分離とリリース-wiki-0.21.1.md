# /wiki:query の確信度の決め方の分離と wiki 0.21.1 のリリース

`/wiki:query` の確信度の決め方を別のファイルに分けて確実に読ませ、読み違いと外の知識の経路を直して、wiki 0.21.1 として出した記録である。きっかけは、Sonnet 5.5 で測ったときに、決め方の正本（手順 5b）が 1 回も読まれていなかったことである（[[queryの確からしさのsonnetでの測定-2026-11-16]]）。レビューの原本は `docs/agent-runs/2026-11-16-wiki-query-confidence-reach/` にある。

## 直したこと

作者は、測定のレポートが示した案 1〜4 をすべて入れると決めた。

1. 決め方の本文を `skills/info-hive/references/query-confidence.md` に分けた。コマンドの手順 6b では、確信度を書く前に、このファイルを `${CLAUDE_PLUGIN_ROOT}` のパスで Read するよう求めた。手順 5b は、このファイルへの案内として残した。
2. 6b の要約を、読み違いを生まない 3 点にした。
   - ソースの要約ページに書かれていれば高で、raw まで読まなくてよい。
   - wiki 自身の事柄を記録で答えたら高。
   - 上限は表の行だけで、回数、再現、raw や git で確かめていないことでは下げない。
3. wiki の外の知識に、会話に読み込まれたプロジェクトの指示と、wiki の外のファイルを含めた。思い付いた答えを、検索語として書くことも禁じた。
4. 1 行目は `**確からしさ（confidence）: 中**` の字句のまま書くことにした。

判定の表の中身は変えていない。ADR-0028 は承認済みなので書き換えず、置き場所の行に日付つきで追記した。

## レビューで直したこと

Sol の敵対的レビューを 3 回受けた。指摘はどれも、外の知識の例外の決め方に集まった。

- 1 回目は、例外を frontmatter の `raw` の欄に限っていた。これでは、文字コードを変換した写しと、rag の抽出済みの Markdown が外れた。
- 2 回目は、「本文から参照している」という条件にしていた。これでは、`rag_job_id` で指す rag のページが外れた。

最後は、要約ページがそのソースの raw として指しているもの、とした。指し方は 3 つ（`raw` の原本、`rag_job_id` のジョブ、本文の参照とその画像）である。欄や書き方の 1 つで例外を決めると、取り込みの手順が作る別の形を取りこぼした。

## 測り直し

リリースの前に、前回と同じ wiki（`4b3f578`）と 11 問で測り直した。

- ラベルの一致：24/33 から 33/33 に上がった。
- 決め方のファイルを開いた回：0/30 から 30/30 になった。
- 判定のぶれ：なくなった。

答えを検索語として書く漏れは残った。Q11 では減ったが、確信度を付けない Q09 で新しく起きた。この漏れは、0.21.2 で字句で決まる決まりにして直した（[[queryの検索の説明への外の語の漏れの直しとリリース-wiki-0.21.2]]）。

## リリース

1. 子の PR の先頭を指した親の CI 17 件が通ってから、子の PR（to884/info-hive-wiki#72）をマージした（`4ffecc5`）。
2. 注釈付きのタグ `v0.21.1` と GitHub リリースを作った。
3. 使い捨ての設定でマーケットプレイスから入れ、0.21.1 が入ることを確かめた。v0.21.0 から変わった 7 つのファイルの SHA-256 は、タグの中身と一致した。
4. 親の参照をマージコミットに付け替えて、親の PR（to884/info-hive-dev#144）をマージした。

並行して、to884/info-hive-wiki#71（rag の page_report）と ADR-0027 の実装が、どちらも 0.22.0 を予定している。
