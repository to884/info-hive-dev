# /wiki:query の確信度の未測定の規則を Sonnet 5.5 で測った記録（2026-11-16）

wiki 0.21.1 の `/wiki:query` が付ける確信度のうち、[[queryの確からしさのsonnetでの測定-2026-11-16]] ではこの wiki に素材がなく問いを作れなかった規則を、試験用の wiki で測った記録である。原本は `docs/research/wiki-query-confidence-rules-2026-11-16.md` で、試験用の wiki のページ、問いと期待（実行の前にコミットした）、全回の要約、スクリプトは同じ名前のディレクトリにある。

## 測り方

- 架空の製品「Tsuyukusa」の 14 ページの wiki を作った。シンセシス、矛盾する 2 つのソースのページ、`status: superseded` の料金表、発行日も版もない FAQ、`confidence: low` と `medium` の型付きのエッジ、`sources` のないコンセプトを置いた。中身を架空にしたのは、モデルが外の知識で答えられないようにするためである。
- wiki はリポジトリの外に作り、そこを作業ディレクトリにした。リポジトリの `AGENTS.md` とこの wiki を読ませないためである。
- 検索の縮退は、MCP のデータの置き場所（`INFO_HIVE_DATA_DIR`）を条件ごとに分けて起こした。モデルを写した置き場所は `hybrid`、空のモデルのファイルを置いた置き場所は「埋め込みモデルを使えない」、モデルがなく取得もできない置き場所は「埋め込みモデルを用意している」になる。流す前に MCP を直接呼んで、費用なしで確かめた。
- `--no-embed` とページ単位の検索は、モデルが自分からは選ばないので、問いの文で指示した。
- info-hive-wiki `v0.21.1`（`4b87e9d`）を `--plugin-dir` で読み込み、15 問を 3 回ずつと試しの 3 回、合わせて 48 回を流した。8.61 USD だった。48 回とも wiki は変わらなかった。

## 結果

| 確かめたこと | 結果 |
| --- | --- |
| 判定のラベルの一致 | 40/45。外れた 5 回は、事前に書いた別の読み（エッジ）が 2 回、事前に書いていない経路（`Grep`）が 2 回、規則の外れ（決まった 1 行を崩した）が 1 回 |
| 3 回とも同じ判定 | 11/15 問。エッジの medium、MCP の縮退の 2 問、複数の結論の 1 問でぶれた |
| 規則の正本 `query-confidence.md` を開いた | 48/48 |
| グラフ（`graph` の MCP か CLI）に問い合わせた | 0/48。関係の問いの 6 回も、エッジは人物のページの frontmatter で読んだ |
| 期待どおりだった規則 | シンセシス、前提のないシンセシス、矛盾、superseded と過去を問う対照、時期や版の不明、`--no-embed`、ページ単位、インデックスから見つかる縮退の対照 |
| 上げる方法 | 検索の縮退は、4 つの理由のどれでも理由に合っていた。superseded、時期や版の不明、エッジの行では、`/wiki:lint` か `/wiki:graph lint` の提案が抜けやすかった |
| 複数の結論の書き方 | 6 回とも結論ごとの違いを書いたが、結論のそばに「（確からしさ: 高）」を置いたのは 1 回だけだった |

外れの分かれ目は、規則に書かれていないことだった。

- **どのエッジを根拠に数えるか。** 同じ主張がソースの要約ページにもあると、3 回中 2 回が「根拠はエッジではなくソース」として `confidence: medium` を上限に数えず、「高」にした。ソースの記述そのものが弱い問いでは、3 回とも「低」だった。
- **`Grep` で見つけたページ。** 検索の縮退の上限は wiki の検索（MCP か CLI）だけを数える。`Grep` でページを見つけた 2 回は、「インデックスから直接見つけた」と道具の記録と違うことを書いて「高」にした。`Grep` は 48 回中 38 回で使われた。「grep や glob で探してはならない」という規則は `SKILL.md` にあるが、`SKILL.md` を読んだ回は 0/48 で、`commands/query.md` にはこの規則がない。

試しの回の 1 回は、縮退した検索で見つけたページを「本体を読んで確かめたので下げない」として「高」にした。抜粋だけの行と、検索の縮退の行を取り違えている。

## 規則の直しの案

原本は、次の案を作者に示した。案 1〜4 は作者が決めた。直しは作っていない。ADR-0027 の実装（0.22.0）も同じ `query-confidence.md` を変えるので、入れるときは順番を決める。

1. ソースの要約ページにもある関係のエッジを、上限に数えるか。作者は 2026-11-16 に「数えない」（A）を選んだ。エッジの上限は、結論をエッジから導いたときだけ当てる。理由は、`graph-workflow.md` が `confidence` の選び方を決めておらず、正本は Markdown で、弱いソースの記述は「判断を加えた導き方」でも下がるためである。あわせて、手順 5b では、関係を問う質問に `graph.sqlite` があれば、ページを読む前に必ず `graph` の `neighbors` を呼ばせると決めた（frontmatter を読むことで代えない）。
2. `Grep` で答えのページを見つけたときの扱い。作者は 2026-11-16 に、禁じずに検索の縮退（中）に数えると決めた（B）。矛盾や答えがないことの確かめに使うのは、上限に数えない。上げる方法は MCP の `query` で検索し直すこと。候補をどう見つけたかは、道具の記録どおりに書かせる。
3. 「ページ本体を読んでも、検索の縮退の上限は外れない」と、上限の目的とともに書く。作者は 2026-11-16 に入れると決めた。
4. 複数の結論の書き方に例を足し、決まった 1 行は 1 つの値で書くと書く。作者は 2026-11-16 に入れると決めた。

規則の外では、`wiki_graph_query.py neighbors` の文字の出力が入ってくるエッジの `confidence` を出さないことと、MCP の「埋め込みモデルを使えない」の warning にモデルのファイルの絶対パスが入ることも見つかった。
