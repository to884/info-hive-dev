# ADR-0024 の承認の条件の検証（公開の PDF、2026-11-15）

[ADR-0024](../adr/0024-wiki-extracts-pdf-text-with-pdfium.md)（wiki の PDF の本文を PDFium の文字の層から取り出す。状態は提案）の承認の条件 1 を、公開の PDF で確かめた。スクリプト、試料の URL と SHA-256、判定の記録は [adr-0024-verification-2026-11-15/](adr-0024-verification-2026-11-15/) にある。PDF の本文、ページの画像、取り出した本文は、リポジトリに入れていない。

## 結論

**承認の条件 1 は満たさなかった。** ADR の手順では、満たさない種類の PDF があれば、その種類と程度を記録し、決定を変えるか、その種類だけ別の扱いにするかを決める。どちらにするかは作者が決める。

条件 1 の判断の基準は 2 つある。結果は次のとおりだった。

- **読み順と表で、pdftotext と pdfminer を下回らないこと: 満たさなかった。**
  - 表は、PDFium（ADR の仕様どおりの試作）がもっとも良かった（Sol の表の点の平均 4.0、ほかは 3.0〜3.2）。
  - 読み順は、日本の官公庁の資料で下回った。組版のソフトや、作成したソフトの記録がない PDF である（白書のポイントで 2 点、Xpdf と pdfminer は 5 点。白書の概要の 4 ページで 2〜4 点、ほかは 2〜5 点）。PDFium は、版面の順ではなく、ファイルの中の文字の順に返していると考えられる。白書のポイントでは「第Ⅱ部」を「第Ⅰ部」より先に出した。
  - LaTeX の 2 段組みの論文では、読み順はほかと並んだ。ただし、行末のハイフンで分けた語の切れ目に U+FFFE が入り、文字の正しさの点がほかより 1 点低かった（3 点、ほかは 4〜5 点）。
- **読めないページの見逃しがないこと: 見逃しは 0 だった。** 判定と確かめるべきページの印のどちらでも拾えなかった読めないページは、なかった。ただし、判定が誤って、読めるページを読めないページとして扱った例があった（官報の 4 ページ目。下の「読めないページ」）。

縦書きの官報は、どの方式でも要約に使える本文にならなかった（Sol の総合の点は 1〜2）。ADR の仕様では、縦書きと判定したページは本文を出さず、rag の OCR に回す。

## Sol の判定

10 ページを選び、方式の名前を伏せて、Sol（GPT-6.1 Sol、effort high）に、ページの画像を正解として 5 つの軸で採点させた（[依頼](adr-0024-verification-2026-11-15/judge/task.md)、[判定の全文](adr-0024-verification-2026-11-15/judge/sol-result.md)）。

- 選んだのは、2 段組み、表、日本語の組版、図の多い版面、縦書きのページである。
- 最初の判定では、Sol がページの画像を開いていなかった（記録に読んだ跡がない）。2 回目は `codex exec` の `-i` で画像を添え、Sol は総評に「添付の 10 画像をすべて確認した」と書いた。
- 判定に書かれたダイジェストと、写し、出力、対応表が一致することを、集計のスクリプトで確かめた。

## 読めないページ

試料の 39 ページをすべて画像で見た。結果は次のとおりである。

| ページ | 状態 | 判定 | 確かめるべきページ | 結果 |
| --- | --- | --- | --- | --- |
| synth-scan p1 | 文字の層がない | `scan` | 入る | 拾えた（OCR に回る） |
| synth-scan-header p1 | ヘッダーの 33 文字だけが文字の層にある | `text` | 入る | 印で拾えた |
| synth-outline p1 | 文字がアウトライン | `blank` | 入らない | 判定で拾えた（`blank` のページは Read で見る手順） |
| kanpo-p1 p1 | 縦書き。文字の層はあるが、列の順が逆になり、ページ番号の漢数字が別の漢字に化けている | `text`（縦書きを見逃した） | 入る | 印で拾えた |
| kanpo-p2 p1、kanpo-p3 p1 | 縦書き。文字の層はある | `vertical` | 入る | 判定で拾えた（OCR に回る） |
| kanpo-p4 p1 | 横書きの表を 90 度回したページ。文字の層は読める | `vertical`（誤り） | 入る | 読めるページを、読めないページとして扱った |
| ほかの公開の PDF の 32 ページ | 本文はすべて文字の層にある（図の中の文字には、画像のものがある） | `text` | 白書の概要の 1、9 ページだけ入る | 読めないページはない |

- 判定と印のどちらでも拾えなかった読めないページは、0 だった。
- 確かめるべきページの印は、公開の PDF の 6 ページに付いた。官報の 4 ページと、白書の概要の表紙と 9 ページである。そのうち実際に崩れていたのは、官報の 1〜3 ページだった。官報の 4 ページはどれも `image_coverage` が 1.0 だったので、官報の 1 ページ目を印で拾えたのは、ページ全体にかかる画像があったためで、文字が崩れていたためではない。
- 判定の誤りが 2 つあった。官報の 1 ページ目の縦書きを `text` とし、4 ページ目の回した横書きの表を `vertical` とした。後者は、ADR の仕様では本文を出さないページになる。
- 官報の 1 ページ目の文字の化け（漢数字が別の漢字になる）は、`bad_ratio` が 0.012 で、閾値 0.02 を下回り、判定では拾えなかった。

## そのほかに分かったこと

- **U+FFFE:** PDFium は、行末のハイフンで分けた語の切れ目に U+FFFE を入れる（`representa\ufffetion`）。BERT の論文では 332 か所あった。rag の `inspect_page` は U+FFFD と私用領域しか数えず、`chunks_for` にも U+FFFE を取り除く処理がないので、rag のチャンクの本文と埋め込みに使う文にもそのまま入ると読める（コードを読んで分かったことで、rag に取り込んで確かめてはいない）。
- **縦書きの文字の層:** 官報の 2 ページ目の PDFium の文字の層は、条文が列ごとにつながっていて、ある程度は読めた（これは目で見た印象で、Sol は判定していない）。それでも Sol の判定では、どの方式も、改正前と改正後の区別が失われ、法令の変更点を正確に要約できないとされた。

## 決めること

ADR-0024 は「提案」のままにした。条件 1 を満たさなかったので、次のどれにするかを作者が決める。

1. **ADR を書き直す。** たとえば、本文は版面を解析する方式（Xpdf か Poppler）で取り出し、ページの区切り、判定、確かめるべきページの印だけを PDFium で行う。その場合、rag と本文がそろわなくなるので、「何をそろえるか」を決め直す。
2. **種類で分ける。** LaTeX の論文のように PDFium が下回らない種類は PDFium にし、組版のソフトで作った日本語の資料は別の方式にする。種類を見分ける方法（作成したソフト、版面）を決める必要がある。
3. **ADR を取り下げる。** wiki の手順は今のまま（`pdf-reading` スキル、pdftotext、pdfminer）にする。

どれを選んでも、次の 2 つは別に直す必要がある。

- 縦書きの判定の誤り（縦書きを見逃したことと、回した横書きを縦書きとしたこと）
- U+FFFE の扱い。rag の本文と索引にも関わる

## 制約

- Sol の判定は 10 ページ、1 回だけで、点のぶれは測っていない。
- 試作は ADR の仕様どおりに書いたが、本当の `wiki_pdf.py` ではない。
- 公開の PDF の種類は 4 つ（LaTeX、InDesign、記録なし、Acrobat Distiller）で、スキャンの PDF は合成だけである。
- 文字の対応表の誤りは、官報の 1 例しかない。
- 縦書きの読み順は、どの方式も低く、方式の差を測れていない。

## 再現の手順

```powershell
cd docs/research/adr-0024-verification-2026-11-15
python -I scripts/fetch_corpus.py               # 公開の PDF を取得し、sources.json に URL と SHA-256 を書く（前の値と git diff で比べる）
uv run --script scripts/prepare.py              # 合成の試料、ページの画像、info.json
uv run --script scripts/extract.py              # 4 方式で取り出し、outputs/ と pages.json
python -I scripts/prepare_judge.py <worktree の外の対応表のパス> --discard-judgement
# 判定のあいだ、outputs/ と pages.json を worktree の外に移す
python -I scripts/run_judge.py                  # 画像を添えて Sol に判定させる
# outputs/ などを戻し、対応表を judge/mapping.json に写す
python -I scripts/aggregate.py                  # ダイジェストを照らして集計し、summary.md を書く
```

`extract.py` は、Poppler の `share\poppler` に日本語の対応表がないか、Xpdf の設定のファイル（環境変数 `XPDFRC`、既定は `%USERPROFILE%\pdf-cjk-data\xpdfrc`）がないと止まる。取り出しのときに Poppler か Xpdf が日本語の対応表がないと警告したときも止まる。
