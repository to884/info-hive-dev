# 全量 ANN 検証の敵対的レビュー

目的は、固定した実 PDF 905 文書と製品形式の 22,335 OCR ページの結果を使い、rag 0.5.3 の ANN の自動作成・追加・差し替えと中断・再開を検証することである。
原本、元の OCR、以前の全量ベクトルのファイルは読み取りだけに使う。
OS の電源断、再起動、WSL の停止は行わない。

`docs/plans/rag-full-ann-validation-2026-11-19.md` と `poc/rag/full_ann/` の設計と実装をレビューする。
製品コードは `info-hive-rag/scripts/` であり、今回変更していない。
製品の索引保守は `rag_indexes.py`、取り込みは `rag_index.py`、永続ジョブと親の終了監視は `rag_jobs.py`、`rag_worker.py` にある。

特に、次の欠陥を探す。

- 既存のベクトルを異なる入力・モデル・版として再利用する経路。
- 準備用の台帳や追記ベクトルが、途中終了や同時実行で食い違う経路。
- 全量テーブルの索引作成を手動で代替して、MCP による自動処理の成功として数える経路。
- 意図した索引処理中に停止できていないのに、中断・再開を成功と報告する経路。
- 検証コードが保存済みの OCR を書き換える、原本を複製・変更する、別のセッションのプロセスを止める経路。
- 件数・未索引行・世代・重複・出典の照合が不足して偽陽性になる経路。

大量投入と全量の公開台帳の作成は検証用の準備であり、905 回の MCP 取り込みを検証したとは扱わない。
実 MCP で行うのは、その全量テーブルに対する検証用 PDF の追加と差し替えである。
検索試料は保存済み本文を使う既知ページのスモーク試験であり、人手質問による精度評価とは扱わない。

現時点では `prepare.py` と `embed.py` が動いており、MCP の全量試験は開始前である。
読み取りと静的検査を行い、稼働中の処理の終了、DB や製品の書き換え、試験の起動をしないこと。
指摘は実際の行と反例を示し、確認済みの欠陥と仮説を分けること。
