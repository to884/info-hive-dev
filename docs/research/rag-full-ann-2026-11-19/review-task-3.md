# 再開位置と後始末の修正の確認

レビュー 2 の Major を実 LanceDB で再現した。
`retirement-cursor-before-fix.log` に、取り込み直した文書の 4 行中 3 行しか残らない失敗と、索引のリセット後に後始末の意図が残る失敗を記録した。

現在の修正では、旧文書を削除する前に、その文書の既知の全世代の jobs 行を消してコミットする。
旧文書を取り込み直すときは、ジョブの保存位置を作る前、抽出のロックを取る前に、その文書に関する後始末を完了させる。
索引をリセットするときは後始末の台帳も空にする。
公開直後の停止、後始末の通常の失敗、元の内容の再公開、再公開の途中での失敗と別文書の取り込み、索引リセットの 5 試験は、`retirement-cursor-after-fix.log` ですべて通過している。

この不変条件と、新しい反例がないかを現在のコードで確認してほしい。
`rag_index.py` の `_finish_retirements`、`ingest_pdf` の冒頭、`_reset_index` と、その 5 試験を中心に読むこと。

その他の Minor も次のように対処した。

- 変更履歴は、通常は次の取り込みで回収するという表現に直した。
- 再開時の MCP 子プロセスには、文書の encode が呼ばれたら失敗させるテスト用フックを設定する。決定的なベクトルのハッシュだけに再利用の証明を頼らない。
- 抽出のスタンプが空なら失敗させる。
- 最終集計が、確定済み 79,900 ベクトルの入力の対応表とバイナリの先頭部分を照合するコードを加えた。途中で実行した同じ照合の証跡も `embedding-interruption.json` にある。
- 中断時のコミット境界を summary に出す。
- `adopt_index_fix.py` は、許すメソッド以外のモジュール AST の変更を拒む。取り込みの入力の AST から取り除けるのは、指定した後始末の if 文だけである。修正全体のパッチとハッシュを保存する。

現在、783,117 チャンクの索引なしテーブルの投入が完了している。
全量の実 MCP 試験も開始する。稼働中の処理を止めたり、試験や全量走査を起動したり、元データを編集したりしないこと。
現在のファイルを読み、確認済みの欠陥と仮説を分けて報告してほしい。
