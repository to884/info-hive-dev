## 今の形が Nav の規則から外れている所

Nav の章（スキル `fluent2-html-replica` の `references/14-components-navigation.md`）と照らした。

| # | Nav の規則 | 今の左のペイン |
| --- | --- | --- |
| 1 | 入れ子は 1 段まで（NavCategory › NavSubItem）。2 段より深い階層は Nav で表さず、Tree を使う | 記事のページは、NavCategory の中に NavCategory を入れる（Fluent 2 の設計の 4 節の「独自の拡張」）。タグの段で、どの wiki でも 2 段より深くなる |
| 2 | NavItem は入れ子にしない。子を持つものは NavCategory（開閉する見出しで、リンクではない）にする | 索引のページは、NavItem のリンクの下に NavItem を `ul` で入れ子にする。開閉がない |
| 3 | NavCategoryItem（`summary`）は開閉の見出しである | `summary` の中に、件数と「一覧」のリンクを置く。押せる部品の中に押せる部品がある |
| 4 | 選んだ項目は、背景を変えず、太字とインジケーターで示す | 今のページの項目に、独自の背景を付ける |

Fluent 2 の設計は、Tree を使わない理由を「`role=tree` の `div` で、開閉に JS が要り、項目のリンクと競合する」とした。この設計は、その 2 つに答える。開閉とキーボードの操作は `app.js` が受け持つ（木はもともと `app.js` が描き、スクリプトなしでは描かない）。リンクとの競合は、葉の項目そのものをリンクにし、枝の項目にはリンクを入れないことで避ける（2.2）。例外は、記事のページの枝の「一覧」で、Tree のクイックアクションとして置く（6.4）。

## 1. 守ること

Fluent 2 の設計の 1 節と、探しやすさの設計の 1 節は、そのまま守る。この設計で特に関わるものを挙げる。

| | 内容 |
| --- | --- |
| CSP と画面の契約 | インラインの `style`、インラインのスクリプト、イベントの属性を出さない。`app.js` は要素の `style` に触らない。変えるのは、要素を作ることのほかは class、`hidden`、`open`、`aria-*`、`tabindex` だけである。`tabindex` は、Tree のローヴィングのために、この設計で足す |
| 同梱 | `fluent2.css` は書き換えない。スキルの `fluent2.js` は積まない（要素の `style` に書く部品がある）。Tree の動きは `app.js` に書く。`fluent2.js` の `enhanceTree` を下敷きにするが、葉の Enter とローヴィングの同期は 2.4 のとおりに直す（`enhanceTree` は葉の Enter でもリンクの移動を止める。1 回目のレビューの 1） |
| 独自の CSS | `style.css` は、トークンの CSS 変数で書く。hex と px を直に書かない |
| スクリプトなし | 今と同じく、左のペインには `<noscript>` の「索引へ」のリンクだけが出る |
| コントラスト | 木の文字は、light と dark の両方で、止まっている状態、ポインターを置いた状態、押している状態、押したままポインターを外した状態、選んだ状態のすべてで 4.5:1 以上にする。6.2 の組は、同梱の `fluent2.css` の値で計算した |
| Fluent 2 の設計の 4.2 を改める | 4.2 の 2 つ目の規則は、地が状態で変わる要素（ナビの項目、グループ、「一覧」）の文字に brand の色を使わないとした。暗い配色で、brand のリンクの色（`colorBrandForegroundLink`）と中立のホバーの地（`colorSubtleBackgroundHover`）の組が 4.18:1 になったからである。この設計は、左のペインの木と索引へのリンクで、地と文字を組で brand のトークン（`colorBrandBackground2` 系と `colorBrandForeground2` 系）に替える。組の比は 6.2 のとおりどれも 4.5:1 以上で、試験（4）が状態ごとに測る。規則が守ろうとしたこと（状態で地が変わっても 4.5:1 を割らない）は変えず、使うトークンの組を変える。左のペインの外（本文、索引のページの一覧、検索の結果）は、4.2 のまま中立の文字にする |

## 2. 部品

### 2.1 入れ物

```html
<div class="tree">                                  <!-- 今と同じ。drawer の中 -->
  <div class="fui-Tree" role="tree" aria-label="索引の木">
    …項目…
  </div>
</div>
```

- `data-size` と `data-appearance` は付けない（medium、subtle。v9 の既定）。行の高さは 32px で、文字は `body1` である。
- 木の入れ物は、今と同じく `nav.fui-NavDrawer` の `div.fui-NavDrawerBody` の中に置く。NavDrawer は、幅（260px）を持つ入れ物として使い、地は 6.1 のとおりページと同じにする。中の部品は Nav でなく Tree にする。

### 2.2 項目

どの項目も、Tree の `TreeItem` の中に `TreeItemLayout` と `TreeItemLayout__main` を置く。`fluent2.css` のフォーカスの輪、最小の高さ、字下げは、どれも子の `TreeItemLayout` に当たるので、これを持たない項目を作らない（1 回目のレビューの「崩れる前提」と 3）。`TreeItem` を `a` にするとき、`TreeItemLayout` と `__main` は `span` にする（`a` の中に `div` を置かない）。

| 項目 | マークアップ | 補足 |
| --- | --- | --- |
| 枝（子のグループか項目を持つグループ） | `div.fui-TreeItem.tree-group[role=treeitem][aria-level][aria-expanded][data-group][aria-label]` の中に `div.fui-TreeItemLayout`（`__expandIcon`、`__main.tree-name`、`__aside`、記事のページでは `__actions`）と、子の `div.fui-Tree[role=group]` | 枝はリンクにしない。`aria-label` は「名前（N ページ）」にする。バッジの数と「一覧」の文字が項目の名前に混ざらないようにし、バッジの情報を項目の名前で伝えるためである（Badge の使い方。6.3） |
| 葉: ページ | `a.fui-TreeItem.tree-page[role=treeitem][aria-level][href][aria-current]` の中に `span.fui-TreeItemLayout` と `span.fui-TreeItemLayout__main` | 項目そのものがリンクである。押すと移り、Enter でも移る（リンクの既定の動き） |
| 葉: グループへの項目 | `a.fui-TreeItem[role=treeitem][aria-level][href="…index.html#group=<ID>"]` と、同じ `TreeItemLayout` と `__main` | 今と同じ行き先 |
| 葉: 未解決と曖昧 | `span.fui-TreeItem.wl.wl-<状態>[role=treeitem][aria-level][aria-disabled=true][title]` と、同じ `TreeItemLayout` と `__main` | 今と同じく `wl` で始まる class と `title` を付ける。押しても何も起きない |
| 葉: 索引のページのグループ | `a.fui-TreeItem.tree-index[role=treeitem][aria-level][href="#group=<ID>"][data-group][aria-label]` と、同じ `TreeItemLayout`、`__main`、`__aside` | 子を持たないグループ（タグのグループなど）。押すと右の一覧を絞る。`aria-label` は「名前（N ページ）」 |
| 枝: 索引のページのグループ | 記事のページの枝と同じ `div` に `data-group` を付ける。`__actions` は置かない | 押す（`__expandIcon` の外）と Enter で、右の一覧をそのグループに絞り、閉じていれば開く。`__expandIcon` を押すと開閉だけをする（Tree の使い方の「ナビゲーション」の操作。6.4） |
| 葉: すべてのページ | `a.fui-TreeItem.tree-all[role=treeitem][aria-level=1][href="#"][data-group=""]` と、同じ `TreeItemLayout` と `__main` | 索引のページの木の先頭 |

- `aria-level` は、木のいちばん上を 1 とする深さである。記事のページは、グループの深さ（いちばん上のグループが 1）と、その中の葉（親の深さ + 1）である。
- 件数は、枝と索引のページのグループの葉の `__aside` に、CounterBadge（6.3）で置く。
- 記事のページの枝の「一覧」のリンク（`index.html#group=<ID>`）は、`__actions` の中の `a.fui-Link.tree-filter` に置く（6.4）。
- `a` の `TreeItem` には、リンクの既定の下線と色を打ち消す規則（`text-decoration: none`、`color: inherit`）を `style.css` で当てる。Tree の CSS はリンクの既定の表示を消さない（1 回目のレビューの 2）。対象は要素の名前で選ばず、木の中の `a.fui-TreeItem` のすべてにする。

### 2.3 開閉、今の項目、深さ

| | 規則 |
| --- | --- |
| 記事のページの開閉 | 今のページを含む枝と、その祖先の枝だけを開く（`aria-expanded="true"`）。ほかは閉じる（探しやすさの 3.1 と同じ）。ページが 2 つのグループに載っていれば、どちらも開く |
| 索引のページの開閉 | 深さ 1 の枝と、絞っているグループの祖先の枝を開く。タグのグループは子を持たないので、深さ 1 の枝を開けば「ソース」の下のタグまで見える |
| 今のページ | 葉に `aria-current="page"` と `is-current` を付ける。読み込んだときに、その項目が見える所まで木だけを送る（今と同じ） |
| 絞っているグループ | 索引のページで、そのグループの項目に `aria-current="true"` と `is-current` を付ける（今と同じ） |
| 今の項目の見た目 | 6.2 の「選んだ項目」の見た目にする |
| 深さの字下げ | 作者の決定で、Fluent 2 のサイトの字下げに合わせる（Fluent の Tree の字下げ、葉は段 × 24px、枝は (段 − 1) × 24px は使わない）。名前の位置を「シェブロンの幅（24px）+ 段の数 × 1 段」とし、段の数は 1 段目と 2 段目が 0、3 段目が 1、4 段目より深い段が 2 である。1 段目と 2 段目の名前がそろうのは、サイトの区画の見出しと、その子の名前がそろう形である。1 段は、トークンの和 18px（`spacingHorizontalL` + `spacingHorizontalXXS`）にする。最初はサイトの 35px に近い 34px にしたが、作者の決定で 3 段目（ページの題名の行）を 16px ほど左に寄せた。枝は、名前の位置からシェブロンの分だけ前から描く。`style.css` は、`TreeItemLayout` の先頭の余白を、この規則で上書きする。作者の決定（Fluent 2 の設計の「作者が決めたこと」）に従い、字下げは 4 段目で止める。`app.js` は、`aria-level` が 5 以上の項目に `tree-deep` を付け、`style.css` がその項目の段の数を 4 段目と同じにする。5 段目より深い枝の子の木には、`colorNeutralStroke2` の縦の線を、4 段目の枝のシェブロンの中ほどの位置に引く。線は背景の画像で描き、`margin` や `border` を使わない。箱の大きさが変わると、深い段ごとに字下げが増える（実装の 1 回目のレビューの 1） |
| 深さの上限 | 木の深さは、索引の作りで上限がある。`indexes/` のファイルのグループ（1）、見出しのグループ（h1〜h6 の 6）、タグのグループ（1）、ページ（1）で 9 段である。N3 で 1 段畳まれることもある。`fluent2.css` は 10 段目までの変数を持つので、11 段目より深い項目は作られない。`tree-deep` は、それでも 5 段目より深いすべての項目に付ける |
| 長い名前 | `__main` を `white-space: normal`、`overflow-wrap: anywhere`、`min-width: 0` にし、`TreeItemLayout` の高さを内容に合わせる（Fluent 2 の設計の 4.3。Tree の使い方も、既定では長いラベルを折り返す） |

### 2.4 キーボードと押す操作

| キー | 動き |
| --- | --- |
| Tab | 木の中で `tabindex="0"` の項目は 1 つだけである（ローヴィング）。最初は、今の項目（今のページ、絞っているグループ）が見えていればそれ、なければ先頭の項目にする |
| ↓ と ↑ | 見えている項目の次と前に移る。端では止まる |
| Home と End | 見えている最初と最後の項目に移る |
| → | 閉じた枝なら開く。開いた枝なら最初の子に移る |
| ← | 開いた枝なら閉じる。そうでなければ親の項目に移る |
| Enter | 葉では何もしない（`preventDefault` を呼ばない）。リンクの葉は、リンクの既定の動きで移る。記事のページの枝は開閉する。索引のページの枝は、そのグループに絞る |
| 文字 | 見えている項目のうち、今の項目の次から、名前（`__main`）がその文字で始まる項目に移る。変換中のキーは扱わない（探しやすさの 5.3 と同じ） |
| Tab（枝の中） | 記事のページの枝が `tabindex="0"` のとき、Tab でその枝の「一覧」に移れる。「一覧」の `tabindex` は、その枝が `tabindex="0"` の間だけ 0 にし、ほかは -1 にする |

- **ローヴィングの同期は、フォーカスが移ったことで行う。** 木の中で `focusin` が起きたら、フォーカスを受けた `TreeItem`（「一覧」が受けたときは、その枝）を `tabindex="0"` にし、ほかを -1 にし、「一覧」の `tabindex` を合わせる。矢印キー、押す操作、プログラムからの `focus()` のどれでも同じ処理を通る。1 版目は押す操作と矢印キーのそれぞれで同期を書いたので、索引のページの葉を押したとき（ページは読み直されない）に同期が漏れた（1 回目のレビューの 4）。
- **押したとき（`click`）:** 枝の `TreeItemLayout`（`__actions` の外）を押すと、記事のページでは開閉する。索引のページでは、`__expandIcon` なら開閉だけ、ほかなら絞り込み（2.2）。葉はリンクの既定の動きに任せる。どれも、フォーカスが移れば上の同期が働く。
- 開いた枝を閉じたとき、その中にフォーカスがあれば、枝にフォーカスを移す。

## 3. 振る舞いが変わる点

| 変わる点 | 今 | 直したあと |
| --- | --- | --- |
| 左のペインの部品 | Nav の NavCategory、NavSubItem、NavItem の入れ子 | Tree の TreeItem |
| ペインの地 | ページと違う地（`colorNeutralBackground4`） | ページと同じ地（6.1） |
| 行の高さと文字 | Nav の 40px と `body1` | Tree の 32px と `body1`。枝は semibold |
| 開閉の印 | 下向きのシェブロン（開くと上向き）が行の右端 | 右向きのシェブロン（開くと下向き）が名前の前 |

## 5. 限界

- **ホバーと今の項目の見た目は、Fluent の Tree の部品の既定と違う。** Tree の部品は、ホバーで中立の地にし、選んだ項目を色で示さない。この設計は、作者の決定で、Fluent 2 のサイトの左のペインの見た目（brand の薄い地と brand の文字）にする（6.2）。
- **件数のツールチップは `title` 属性で近似する。** Tree の使い方は、バッジの意味をホバーのツールチップで示すことを求める。Fluent の Tooltip は `fluent2.js` の部品で、同梱しないので、ブラウザーの `title` の表示で代える。読み上げには、項目の `aria-label` で伝える。
- **字下げと件数の位置は、Fluent の Tree の部品の規則と違う。** Tree の使い方は、子の字下げを 24px とし、例の図はバッジを行の右端に置く。この設計は、作者の決定で、字下げを Fluent 2 のサイトの形（1 段 18px。サイトは 35px）にし、バッジを名前のすぐ隣に置く（Badge の使い方の「隣に置く」形）。
- **Tree の開閉に動きはない。** スキルの CSS も v9 の Collapse を再現していない（`14-components-navigation.md` の Tree の「v9 との差」）。
- **索引のページの枝はリンクでない。** 押すと絞れるが、新しいタブで開くことはできない。葉（タグのグループなど）はリンクなので、新しいタブで開ける。
- **開閉の状態は保存しない。** ページを移ると、2.3 の規則で開き直す（探しやすさの 11 と同じ）。

### 6.4 「一覧」のクイックアクション

（2026年11月16日に、9 節の決定でなくした。以下は、なくす前の規則とその理由の記録である）

Tree の使い方は、クイックアクションがあるとき、ホバーの間はバッジの代わりにアクションを出すことを既定とし、アクションをもっと見える別の手段でも使えるようにすることを求める。

- 記事のページの枝の「一覧」は、`__actions` に置く。`fluent2.css` は、項目にポインターかフォーカスがある間だけ actions を出し、aside を隠す（使い方の既定の形）。
- 「一覧」を出すのは、その行（`TreeItemLayout`）自身にポインターがあるときと、その項目か「一覧」にフォーカスがあるときだけにする。同梱の CSS は項目（`TreeItem`）のホバーで出すので、子の行にポインターを置くと、祖先の枝の「一覧」まで出る（実装のあとに撮った画面で見つけた）。
- この設計は、aside を隠さない。`style.css` で aside をいつも出し（名前のすぐ隣。6.3）、actions を行の右端に置く。使い方は「ホバーの間もバッジを見せる必要があるときは、バッジを横に寄せてアクションの場所を空けてよい」とする。隠すと、バッジにポインターを置いた時点で行全体がホバーになってバッジが消え、6.3 の条件（バッジの意味をホバーのツールチップで示す）を満たせない（2 回目のレビューの 1）。
- 別の手段は、索引のページの左の木である。同じグループを押すと、同じ絞り込みになる。
- クイックアクションは、この 1 つだけにする（使い方は 1〜2 個までとする）。

## 7. 配色の切り替え（トグル）

| 葉の行き先 | Index のページでは `#group=<ID>`（右の一覧を絞る）。記事のページでは `index.html#group=<ID>`（Index のページをそのグループに絞って開く） |
| 枝を押す | 名前を押すか Enter で、そのグループの一覧に移る（Index のページでは右の一覧を絞り、枝を開く。記事のページでは Index のページをそのグループに絞って開く）。シェブロンを押すか ← と → で、開閉だけをする |
| 開く枝 | どちらのページでも、深さ 1 の枝を開く。記事のページでは、今のページを持つグループの祖先の枝も開く。Index のページでは、絞っているグループの祖先の枝も開く |

| 「一覧」 | なくす。グループの名前を押せば、そのグループの一覧に移れるからである |
| 索引の行の未解決と曖昧の項目、グループへの項目 | 左の木には出さない。未解決と曖昧の行は、今と同じく Index のページの「ページに決まらない Index の行」に出る。グループへの項目の行き先のグループは、木にグループとして出ている |

試験（`findability.test.mjs`）は、記事のページの木に記事の題名が 0 件であること、今のページを持つグループに印が付き、その祖先が開くこと、枝の名前と Enter と葉の Enter で Index のページがそのグループに絞られて開くこと、シェブロンで開閉だけをすることを確かめる。
