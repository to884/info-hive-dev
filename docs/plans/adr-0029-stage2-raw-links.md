# ADR-0029 段階2：raw のリンク検証

2026-11-18。段階1の wiki の記事と道の拒否に続き、source ページの raw の検査を実装する。規範は [ADR-0029](../adr/0029-wiki-and-raw-hold-no-links.md) と [実装の設計](wiki-links-2026-11-16.md)。

## 範囲

- `wiki_pages.resolve_raw()` が、`wiki_raw` の共通の境界を呼ぶ。source ページの値ごとに `resolved`、`missing`、`ambiguous`、`unknown`、`link`、`outside` を返す。
- wiki の与えられた綴りと解決した綴りの両方から候補を作る。セッションは wiki の親だけを基準にする。途中の `..` を畳まない。
- raw の根は呼ぶ側から渡す。リンク検査の起点は候補を含む最も内側の raw の根、次に wiki の根。それ以外は候補そのものだけを検査し、途中の道を調べていないことを返す。根と祖先のリンクを許す。
- 全候補の道と、ディレクトリの raw の隠し項目を除く木を検査してから、ハッシュや身元を照らす。リンクや検査不能の候補を「版が違うから missing」にしない。
- `raw_sha256` のある既存ページは版を照らす。なければ session_id / url / final_url を照らす。身元は一致・不一致・欄がなく未確認の3つに分け、明示的に違う候補だけを捨てる。欄のないテキスト、バイナリ、ディレクトリを「原本がない」にしない。SHA-256 のない参照と、複数値のハッシュの数や形が違う参照は版未検証とする。
- ディレクトリのハッシュは、NFC と実際の綴りで並べた `[相対パス, ファイルのSHA-256]` の JSON 行を LF で結んだ UTF-8（末尾 LF なし）の SHA-256。
- rag_job_id のある source の、守る木の外の絶対パスは外の原本としてリンク検査と版の読み取りをしない。allowed_roots による読む場所の制限は外の原本にも当てる。
- lint の missing_raw と字幕の原本・訂正の根拠の読み取りを、この境界に接続する。CLI の `--raw-root` と MCP の `raw_root` を追加する。リンク、検査不能、曖昧さ、版未検証、途中の検査の不足を区別し、書き換えない。
- 字幕検査は全参照の不確かさを `raw_warnings` に保つ。字幕の `findings` にするのは動画の欄・定義があるページか、verify の対象の raw を指すページに限る。訂正の根拠の source は使う時点で検査する。無関係な raw の曖昧さだけで動画の取り込みを止めない。
- YouTube verify は、最初に読む raw と、字幕検査の両方へ既知の raw の根を渡す。既存のセッションの書いた直後の検査は、missing_raw の部分集合だけでは判定せず、共通の結果が resolved のときだけ読み取り専用の属性を付ける。書き手全体の移行ではなく、変更した API の呼び出し元の整合性の修正である。

## 後続段階

raw の書き手が raw_sha256 と根の記録を残す移行、記録の読み込みと upgrade、書き込みの部品 wiki_fsguard と依存の完全性、取り込みの全経路の接続は、段階3以降に残す。段階2は raw の書き手の安全を保証しない。共通の関数は `raw_roots` を複数受け取れるが、CLI/MCP が渡すのは指定された現在の根であり、過去の根を自動で発見しない。

検査後の置き換えを防ぐ完全な TOCTOU 対策、bind mount の検出は範囲外である。
