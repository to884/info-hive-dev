# ADR-0029 段階3の MCP 索引保護

[実装計画](wiki-links-2026-11-16.md) の I6 に従い、設定されたデータの根から MCP の索引を検査する。データの根と祖先の別名は許す。通常の wiki 索引と `index_chunks` のチャンク索引は、同じ SQLite・Tantivy の実装を使う。

- 索引のディレクトリ、SQLite 本体、`-wal`、`-shm`、`-journal`、Tantivy の `lexical/` とその中の項目を、ライブラリを開く前に検査する。索引の再利用では、保持中の索引ディレクトリ、台帳、Tantivy のディレクトリ、ロックファイルが開いたときと同じ実体であることも確かめる。実体が変わったときはサーバーの再起動を案内する。台帳の更新、Tantivy の writer 取得の各再試行、バックグラウンドの埋め込みの読み書きも検査を通す。ライブラリに渡したあとの外部からの置き換えは ADR の境界に従う。
- ロック、索引のメタデータ、usearch の保存にも書き込み検査を適用する。usearch は一意の一時ディレクトリに保存してから置き換える。fingerprint の更新や明示的な reset で作り直す場合は、プロセス間の書き込みロックを保持し、削除対象の木を検査してから消す。チャンク検索と reset が同時に呼ばれた場合、検索中の索引の世代を閉じない。新しい索引が開けたあとにメタデータを確定して公開し、途中で失敗したときは取得した接続とロックを閉じる。
- チャンクの tokenizer はプロセス間のロックを取ってから読む。既存の台帳のメタデータが欠損・破損している場合は、理由を返す。作り直すには `reset: true` を持つ呼び出しが必要になる。reset の前に新しいチャンクを検査する。
- パースキャッシュは従来どおり、検査で拒んだときは記事を読み直して続けられる。索引を開けない場合や書き込みを拒まれた場合は場所と理由を持つエラーにする。wiki を指定した `query`、`get_page`、`stats` は MCP のツールエラーとして、理由と `wiki_search.py --no-embed` の案内を返す。記事のリンク、未初期化の wiki、チャンクのエラーはそれぞれの理由を返す。

回帰試験では索引の道、SQLite の付随ファイル、Tantivy の中の項目を独立に検査し、拒否時に既存ファイルが変更されないことを確かめる。MCP の stdio から3つのツールを呼んでエラーを確認し、経路を戻したあとの成功、既存索引の更新、通常のチャンク検索も試す。
