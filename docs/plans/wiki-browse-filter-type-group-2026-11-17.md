## 作者が決めたこと

| 日付 | 決定 |
| --- | --- |
| 2026年11月17日 | 左の木で「ソース」のグループ（またはその下のタグのグループ）を選んだまま、右の「コンセプト」のボタンを押すと、0 件になる。これを直す。種類のボタンを押したら、グループの絞り込みを外す（0 件になるボタンを押せなくする案も示したうえで、こちらを選んだ） |

## 1. 今の作りと、0 件になる理由

- グループは URL の断片 `#group=<ID>` に持ち、`hashchange` で読み直す（探しやすさの 4.3）。種類は、ページの中の値（`filt.type`）に持ち、URL には入れない。
- 一覧は、検索語、種類、タグ、グループのすべてを満たす行だけを残す。索引の見出しのグループ（「ソース」「コンセプト」）は、たいていページの種類と重なるので、別の種類を選ぶと、満たす行がなくなる。
- 逆の順（先に種類のボタンを押し、あとで左の木でグループを選ぶ）でも、同じく 0 件になる。

## 2. 規則

種類とグループは、どちらも記事を分類で選ぶ操作なので、あとから選んだほうだけを効かせる。タグと検索語は、今と同じく重ねて絞る。

| 操作 | 種類 | グループ |
| --- | --- | --- |
| 種類のボタンのうち、「すべて」でないものを押す | 押した種類にする | 絞っていれば外す。URL の断片を `history.replaceState` で消す（`hashchange` は起きない）。左の木の印は「すべてのページ」に戻る |
| 種類のボタンの「すべて」を押す | 外す | 変えない（「すべて」はグループと食い違わないため） |
| 左の木でグループを選ぶ（断片が別のグループの ID に変わる） | 「すべて」に戻す。ボタンの `aria-pressed` も合わせる | そのグループにする |
| 「すべてのページ」を選ぶ、グループの印の × を押す、断片が空か不正になる | 変えない | 外す |
| 最初に開いたとき（断片にグループがある） | 「すべて」のまま | そのグループにする |

- 種類を「すべて」に戻すのは、グループが**別の値に変わった**ときだけにする。同じグループの断片を読み直したとき（`fromHash` は、`hashchange` のほかに、「すべてのページ」を押したときにも呼ばれる）に、選んだ種類を消さないためである。
- 種類のボタンを押してグループを外したとき、右の件数、グループの印（「グループ: 名前 ×」）、左の木の `aria-current` と `is-current` は、今と同じ `apply()` で描き直す。

## 3. 試験

`findability.test.mjs` の索引のページの確かめに足す。

| 確かめること |
| --- |
| 左の木で「第一」のグループを選び（断片を変える）、種類の「エンティティ」を押すと、断片が空になり、グループの印が消え、一覧の件数がエンティティの行の数になる。左の木の印は「すべてのページ」に戻る |
| 種類の「エンティティ」を押してから、左の木で「第一」のグループの行を押すと、種類の「すべて」が `aria-pressed="true"` になり、一覧の件数が「第一」の行の数になる |
| 検索語とタグを入れたまま、グループを選んでから種類を押しても、検索語とタグは残る |
| 左の木でグループの行を 2 つ続けて押し、種類を押してから履歴を戻ると、1 つ目のグループに戻り、種類は「すべて」になる（5 節の限界のとおり） |
| 種類の「エンティティ」を押してから「すべてのページ」を押しても、種類は「エンティティ」のまま |
| どの操作のあとも、`[style]`、ID の重複、CSP の違反、画面のエラーが 0 件 |

## 4. 振る舞いが変わる点

| 変わる点 | 今 | 直したあと |
| --- | --- | --- |
| グループを選んだまま種類を押す | 両方を満たす行だけ（多くは 0 件） | 種類だけで絞る。グループは外れる |
| 種類を選んだまま左の木でグループを選ぶ | 両方を満たす行だけ（多くは 0 件） | グループだけで絞る。種類は「すべて」に戻る |

## 5. 限界

- **種類とグループを重ねて絞ることはできなくなる。** 分割した索引のグループ（種類の混ざるグループ）の中で、さらに種類で絞ることもできない。種類の混ざるグループでは、タグか検索語で絞る。
- **種類は URL に残らない。** 今と同じく、ページを読み直すと種類は「すべて」に戻る。ブラウザの履歴を戻るか進んでも、選んだ種類は戻らない。たとえば、グループ A、グループ B、種類「エンティティ」の順に選ぶと、B の履歴の項目は断片のない項目に置き換わる（`replaceState`）。戻ると A のグループで種類は「すべて」になり、進んでも「エンティティ」は戻らない（1 回目のレビューの「崩れる前提」）。
