# URL の取り込みの決定論的な処理をスクリプトに移す（設計案、5 版、2026-11-13）

## 目的

`/wiki:ingest` に URL を渡したとき、今は `wiki_fetch.py` が取得と Markdown への変換をし、残りの工程をモデルが raw のファイルを直接書き換えて行う。対象は、雑音の削除、言語の判定、訳、画像の補足、`translated_by` の記入である（[ADR-0004](../adr/0004-raw-holds-translated-web-pages.md)）。

2026-11-13 の比較（[docs/research/wiki-ingest-model-comparison-2026-11-13.md](../research/wiki-ingest-model-comparison-2026-11-13.md)）では、raw の誤りの多くが、モデルの判断の誤りではなく、**規則で決まっている形をモデルが守れなかった**ことから生じた。この設計は、規則で決まる工程をスクリプトに移す。

設計の原則は 4 つある。

1. **モデルに Markdown を書かせない。** モデルが返すのは、訳文の平文と、対になったタグ（`⟦L1⟧…⟦/L1⟧`）と、決まった形の判断だけである。Markdown の記法、エスケープ、字下げ、引用の記号は、すべてスクリプトが書く。
2. **構造で決まる規則は構造で守り、推測でしか決まらないものは止めずに記録する。** コード、リンク、画像、守る語は、モデルが変えられない形で渡す。原文の文字列の形から推し量るしかないもの（原文にない内容の追加など）は、誤りにすると正しい訳を止めるので、取り込みの記録に残すだけにする。
3. **推測による除外は、すべて同じ木の上の印にする。** 本文の選択と雑音の判定は、要素を捨てずに印を付ける。モデルは印を見て、戻せる。
4. **raw に書くのは `apply` だけにし、同じスラッグを扱う操作は OS のファイルの錠で排他する。** 確定、清掃、作り直しは、錠を取ってから状態を確かめる。錠はプロセスが止まれば OS が外すので、錠を回収する操作を持たない。

## 比較で見つかった失敗

| 失敗 | 起きた実行 | 原因の構造 |
| --- | --- | --- |
| SQL のコメントを訳し、コードブロックを変えた | Haiku（SQLite） | モデルがコードブロックを含むファイル全体を書き直す |
| 本文のリンクを落とした | Haiku 8 か所、Sonnet 2 か所、Opus 1 か所（SQLite）。Haiku 1 か所（Medium） | モデルが訳文と一緒にリンクの記法を書き直す |
| 図の下の説明文 34 個を消し、訳して alt に移した | Haiku（Medium） | 画像の行もモデルが書き換えられる |
| 原文にない `<>` を補った | Sonnet（SQLite） | 訳文の検査がない |
| `Event Sourcing`、`BoundedContext`、`Greenwich`、`Unix` などを訳した | Haiku、Sonnet、Opus | 守る語が決まっておらず、守ったかの検査もない |
| です・ます調とである調が混ざった | Haiku（SQLite） | 文体の検査がない |
| 雑音の残り（タグのリンク、重複した題名、曖昧さ回避の表、Wikipedia のロゴ） | Haiku、Sonnet | サイトに共通の雑音を、毎回モデルが見つけている |
| 雑音の削除の範囲がモデルごとに違う | 12 実行すべて | 削除の判断が、削った結果の差分でしか残らない |
| 実行のたびに、作業用のスクリプトや原文の写しを自分で作った | Sonnet と Opus（Medium など）。Opus は 85 回ツールを呼んだ | 長いページを節ごとに訳し、書き戻す手段がない |

モデルの判断の質に関わる失敗（図の数値の読み違い、訳の言い方の強め）は、この設計では防げない。

## 選択肢

この文書の「設計」の節は、いちばん大きな案（大）である。次の 3 段を比べる。

- **小（検査）**: `wiki_fetch.py` が取得した直後の raw を作業用の写しとして残す。モデルは今どおり raw を書き換え、書き換えたあとにスクリプトが写しと突き合わせる。コードブロックの一致、URL の出現回数、画像の行、見出しの階層、表の形が違えば止め、モデルに直させる。土台は、比較で使った `compare_raw.py` である。
- **中（検査と規則）**: 小に、サイトに共通の雑音を消す規則（取得の段階で消し、消した行を出力に示す）と、ブラウザで取った HTML を変換する `--html-file` を足す。
- **大（受け渡しの作り直し）**: 下の「設計」の 5 版。中間表現、タグ、守る語、`apply`、錠と確定。

| 失敗 | Sonnet で起きたか | 小 | 中 | 大 |
| --- | --- | --- | --- | --- |
| コードブロックの変更 | 起きない（Haiku だけ） | 止めて直させる | 止めて直させる | 起きない |
| リンクの欠落 | 起きた（SQLite で 2 か所） | 止めて直させる | 止めて直させる | 起きない |
| 図の説明文の alt への移動 | 起きない（Haiku だけ） | 止めて直させる | 止めて直させる | 起きない |
| 表の形の崩れ | 起きない | 止めて直させる | 止めて直させる | 起きない |
| 原文にない `<>` の追加 | 起きた | 増えた並びを示す | 増えた並びを示す | 増えた並びを記録する |
| 固有の名前の訳 | 起きた（`Greenwich`、`EventPosters` の単数形） | 消えた語を示す | 消えた語を示す | 守ると決めた語は起きない |
| 文体の混在 | 起きない | 示す | 示す | 記録する |
| 雑音の残り | 起きた（タグのリンク、重複した題名） | 防げない | 規則で減る | 規則で減り、振り分けが必須 |
| 削除の範囲のばらつき | 起きた | 消した行が差分で見える | 規則の分は名前で残る | 記録に残る |
| 作業用のスクリプトを毎回作る | 起きた（Medium） | 減らない | 減らない | なくなる |
| 図の数値の読み違い | 起きた | 対象外 | 対象外 | 対象外 |
| 有料のページの本文 | — | 手順がない | `--html-file` | `--html-file` |
| 同じスラッグの同時の取り込み | 観測していない | 対象外（今と同じ） | 対象外（今と同じ） | 錠で防ぐ |

大は、raw の規則を「守れない形」にできるが、変更が大きい。`wiki_fetch.py` の変換の作り直し、新しいスクリプト、手順の書き直し、試験に加えて、次の制約を受け入れることになる。

- `os.link` が使えないフォルダーでは取り込めない。
- 同じ機械での利用に限る（今と同じ）。
- セルにブロックを持つ表は、raw の中で HTML の表になる。
- raw の隣に、消した雑音の文字列（原文の断片）を含む記録を置く。
- 守る語の候補を振り分ける手間が増える。比較の 4 ページでは、候補は重複を除いて CQRS 53、SQLite 173、Medium 160 だった（文の先頭の機能語を含む）。

錠、確定、パスの仕組み（5 回のレビューの重大な指摘の約 3 分の 1）は、観測した失敗から来たものではない。小と中は、今と同じく同時の取り込みを対象にしない。

## 工程の仕分け

| 工程 | 今 | この設計 |
| --- | --- | --- |
| HTML の取得、ハッシュ、画像の保存 | スクリプト | 変えない |
| 本文の選択 | スクリプト（選ばなかった要素は捨てる） | スクリプトが選び、木の上の印にする。モデルが確かめる |
| 本文の変換 | スクリプト（Markdown の文字列を返す） | スクリプト（中間表現を返し、そこから Markdown を描く） |
| ブラウザで取った HTML の変換 | 手順がない | スクリプト（`--html-file`） |
| 雑音の候補の検出 | モデル | スクリプト（規則）。モデルが振り分ける |
| ページに固有の雑音の判断 | モデル（行を消す） | モデルがノードの ID を選ぶ |
| 言語の判定 | モデル（規則に従う） | スクリプト（同じ規則を、文章のノードだけで計算する） |
| コード、リンク、強調、改行、画像、数式 | モデル（守るよう頼む） | スクリプトが持ち、モデルにはタグとして渡す |
| 守る語の決定 | なし（モデルが訳しながら判断する） | スクリプトが原文から候補を挙げ、モデルが決める。決めた語はタグにする |
| 訳文 | モデル | モデル（ノードごとの平文とタグ） |
| 画像の補足の文 | モデル | モデル |
| 補足の位置と接頭辞、飾りの画像の削除 | モデル | スクリプト |
| `translated_by` の記入 | モデル | スクリプト（モデルが表示名を渡す） |
| raw の確定 | モデル（ファイルを書き換える） | スクリプト（錠を取り、状態を確かめて確定する） |
| raw を書き換えていないことの確認 | 規則だけ | スクリプト（取り込みの記録と `raw_sha256`） |

## 設計

### 流れ

```text
wiki_fetch.py <URL> --stage             取得、中間表現への変換、本文の選択と雑音の候補の印
        │                                → <WIKI_ROOT>/.wiki-cache/ingest/<スラッグ>/
        ▼
wiki_webraw.py review <作業場所>         本文の選択、雑音の候補、守る語の候補、画像の一覧を渡す
        │
モデルが decisions.json を書く           本文の選択の確認、雑音の振り分け、守る語、画像の判断
        ▼
wiki_webraw.py next <作業場所>           訳すノードを、決まった量ずつ、前後の文脈と一緒に渡す
        │                                （訳さないページでは使わない）
モデルが fill-NNN.json を書く            訳文
        ▼
wiki_webraw.py apply <作業場所>          検査し、通れば raw と assets と取り込みの記録を確定する
        │                                通らなければ何も書かず、直す箇所を返す
        ▼
取り込みの手順 3 以降（要約ページなど）。要約ページに raw_sha256 を書く
```

判断（`decisions.json`）を訳（`fill`）より先に分けるのは、守る語を決めてから訳すためである。`next` は、決まった守る語をタグにして渡す。

`wiki_fetch.py` の今の使い方（`--stage` なしで raw に直接書く）はやめ、`--stage` と同じ動きにする。raw に書く口は `apply` の 1 つになる。今の使い方を呼んでいるのは、`commands/ingest.md` と `ingest-workflow.md` の手順、`SKILL.md`、`docs/` の説明、試験（`tests/wiki/test_wiki_fetch.py`、`info-hive-wiki/eval/scripts/test_fetch.py`）である。手順と説明は `--stage` を使うように書き直し、試験は変換の部分（中間表現と描画）を直接呼ぶように直す。

### 中間表現

`Converter` を、Markdown の文字列ではなく、ブロックのノードの木を返すように変える。描画（`render`）は、木から Markdown を作る別の関数にする。

- **木の範囲**: ページの `body` 全体を木にする。木に入れないのは、文字を描かない要素の種類（`script`、`style`、`template`、`head`）だけである。それ以外の、今は推測で捨てている要素（`nav`、`aside`、`noscript`、`hidden` と `aria-hidden="true"` の要素、`role` や class・id の語に当たる要素、本文に選ばれなかった要素）は、木に残して印を付ける。`aria-hidden` は支援技術への見せ方の指定で、画面に見えないとは限らないので、雑音の候補にとどめる。
- **ブロックのノード**: `title`、`heading`（段の数を持つ）、`paragraph`、`list`（`ordered` を持つ）、`list_item`、`quote`、`code`（言語と中身）、`table`、`table_row`、`table_cell`、`image`、`figcaption`、`math_block`、`rule`、`container`（本文の選択の対象になる要素）。`list_item`、`quote`、`table_cell` は子のブロックを持てる。HTML でブロックを入れられる要素は、すべて子のブロックを持てる形にする。
- **文章のノード**（`title`、`heading`、`paragraph`、`figcaption`、子のブロックを持たない `list_item` と `table_cell`）: インラインの並びを持つ。子のブロックを持つ `list_item` と `table_cell` は、文章を子の `paragraph` に持つ。インラインは、`text`、`link`（URL と子のインライン）、`strong`、`em`、`code_span`、`math`、`hard_break`、`inline_image` からなる。`text` は常に文字であり、描画は Markdown の記法になる文字をエスケープする。
- **表**: `rowspan` と `colspan` のセルは、HTML のセルとして 1 つのノードにする。今の出力のように複数の行に同じ内容を描くのは描画の仕事で、訳すのは 1 回である。セルが子のブロック（段落、リスト、コードブロック）を持つときは、Markdown の表の 1 つのセルには描けない。描画は、その表を HTML の `<table>` として raw に描く。セルの中のコードブロックも、訳すノードにはならない。
- **ID**: ノードごとに、作業の世代の中で一意の ID（`n0001` から）を振る。
- **画像**: 画像の出現（`image` と `inline_image` のノード）と、保存したファイル（`asset`）を分ける。出現は `asset` の ID を指す。同じ URL の画像が 2 回出れば、出現は 2 つ、`asset` は 1 つになる。取得できなかった画像の出現は、`asset` を持たず、`unavailable` の印を持つ。

言語の判定（`ja_ratio`）は、選ばれた本文の範囲の、`code`、`code_span`、`math` を除いた文章のノードの文字だけで計算する。

### 本文の選択

今の `choose_root()` と同じ規則で本文の要素を選び、選んだ `container` に `content_root` の印を付ける。選ばなかった要素は捨てない。

`review` は、選んだ本文に加えて、次のものをモデルに見せる。

- 選ばれなかった `article` と `main` の要素（文字数と冒頭の文）。class・id の語で候補から外れたものも含む。
- 選んだ本文の外にある、文字数の多い上位の `container`（数は試験で決める）。

モデルは `decisions.json` の `content_root` に、選んだ本文をそのまま使うか、別の `container` の ID に替えるかを書く。選ばれなかった `article` か `main` があるのに `content_root` がなければ誤りにする。ないときは書かなくてよい。

雑音の候補、守る語の候補、画像、言語の判定は、`decisions.json` の `content_root` で決まる最終の本文の範囲で数える。`review` は何度でも呼べ、そのときの `decisions.json` を読んで、最終の本文の範囲で足りない判断を示す。本文を替えたら、もう一度 `review` を呼んで足りない判断を埋める。`apply` も同じ範囲で判断の不足を調べる。

### 雑音

規則は、削除を決めない。**候補を挙げる**だけにする。

- `--stage` は、本文の範囲の中で規則に当たったノードに `noise_candidate`（規則の名前）を付ける。描画は、モデルが消すと決めたノードだけを外す。
- 規則の例: 今の `NOISE_WORDS` に当たる class・id・role、`nav` と `aside`、題名と同じ文字列だけの段落、リンクだけからなりリンク先がタグの一覧のパスの段落、ボタンの文言の一覧に一致する段落、MediaWiki の部品（スキップのリンク、`siteSub`、曖昧さ回避の注記）。具体的な class 名は、保存した HTML の試料で確かめてから足す。
- モデルは `decisions.json` の `noise` で、候補を `confirm`（消す）か `restore`（残す）のどちらかに必ず振り分ける。振り分けのない候補があれば誤りにする。ノードは木に残っているので、戻すときに位置も種類も失わない。
- 候補でないノードを消すときは `drop` に理由と書く。見出しと題名は消せない。
- ノードの一部だけが雑音のとき、訳すページでは、訳文からその部分を外し、外したタグを `fill` の `drop_inline` に書く。訳さないページでは、`decisions.json` の `noise.drop_text` に、ノードの ID と、消す文字列と、その文字列が何回目の出現かと、理由を書く（`{"id": "n0120", "text": "共有", "occurrence": 2, "reason": "共有のボタンの文言"}`）。出現は、そのノードの 1 つの `text` の中で、重ならないように前から数える。`occurrence` を省けるのは、文字列がちょうど 1 回だけ現れるときである。指定した出現がなければ誤りにする。タグ（リンク、強調、コード）を含む範囲は `drop_text` では消せず、ノードごと消すか、`drop_inline` と同じ形で、タグの番号で消す。

試験で今の出力と比べるときは、候補をすべて `confirm` したものとして描く。今の変換と同じ要素が外れる。

### 守る語

ADR-0004 の「識別子、固有名詞の英語表記は変えない」を、訳の前に決める。

- `review` は、選んだ本文の文章のノードから、守る語の候補を挙げる。候補は、CamelCase の語、すべて大文字の語、英字と数字が混ざる語、大文字で始まる語（文の先頭でも挙げる）、それらが続く句、英数字だけからなるリンクの文言である。候補はページ全体で重複を除いて 1 回ずつ挙げる。
- モデルは `decisions.json` の `terms` で、候補ごとに `keep`（英語のまま守る）か `translate`（訳してよい）を決める。候補にない語を `keep` に足してもよい。振り分けのない候補があれば誤りにする。
- `next` は、`keep` の語の出現を、`⟦T3⟧` のような単独のタグにして渡す。中身はノードの横の表で渡し、訳文にはタグだけを書かせる。コードと同じく、モデルは守る語の文字を書き換えられない。
- 候補の句が重なるとき（`Event` と `Event Sourcing`）は、`keep` の中でいちばん長い句を先に当てる。
- 守る句は、インラインの境目（強調、リンク、コードの境目）をまたがない、1 つの `text` の中だけで当てる。`**Greg** Young` の `Greg Young` は当たらない。`review` は、`keep` の句が境目をまたいでいて当たらなかった出現を示す。その出現は構造では守られない。
- `keep` は綴りごとの既定である。同じ綴りの出現のうち、守らない出現（言語名の `Rust` と、さびの意味の `rust` が同じ綴りで出る場合など）は、`fill` の `release_terms` に、ノードの ID とタグの番号と理由を書いて外す。外したタグの中身は、訳文に書いてよい。宣言のないタグの欠けは誤りになる。
- 訳さないページでは、守る語を決めない（`terms` を書かない）。
- 大文字で始まる語を文の先頭でも候補に挙げるので、`Many` や `The` も候補に出る。モデルはそれを `translate` に振り分ける。手間は増えるが、語の位置で判定を変えないので、語順が変わっても結果が変わらない。

### 訳の受け渡し

`next` は、文章のノードを決まった量（既定は 8,000 文字分。試験で決める）ずつ、前後の数ノードを読むだけの文脈として添えて渡す。各ノードのインラインは、次の形の文字列にして渡す。

```text
CQRS stands for ⟦S1⟧Command Query Responsibility Segregation⟦/S1⟧. It's a pattern that I first heard described by ⟦L2⟧⟦T3⟧⟦/L2⟧.
```

- 対になるタグ: `⟦L2⟧…⟦/L2⟧`（リンク）、`⟦S1⟧…⟦/S1⟧`（強い強調）、`⟦E4⟧…⟦/E4⟧`（強調）。
- 単独のタグ: `⟦T3⟧`（守る語）、`⟦K5⟧`（インラインのコード）、`⟦M6⟧`（数式）、`⟦BR⟧`（改行）、`⟦I7⟧`（段落の中の画像）。守る語、コード、数式の中身は、ノードの横に `{"T3": "Greg Young", "K5": "set_cookie()"}` の表として渡す。
- 原文の `⟦` と `⟧` は、別の文字に逃がして渡し、描画のときに戻す。
- モデルが訳文に書いた `*`、`|`、`` ` `` などは、描画がエスケープするので、文字として描かれる。

モデルは、訳文を同じ形で返す。

### モデルが書くもの

`decisions.json`（1 つ）:

```json
{
  "stage_id": "9f3c2a7e5b1d4c80",
  "translated_by": "Claude Sonnet 5.5",
  "annotated_by": "Claude Sonnet 5.5",
  "content_root": "n0042",
  "noise": {"confirm": ["n0002"], "restore": ["n0040"], "drop": [{"id": "n0011", "reason": "著者の紹介"}]},
  "terms": {"keep": ["Greg Young", "CQRS", "Event Sourcing"], "translate": ["Many", "The", "Greenwich"]},
  "images": {
    "o0002": {"caption": "単一のモデルで読み書きする従来の構成の図。……"},
    "o0001": {"decorative": true, "reason": "著者の顔写真"}
  },
  "language_override": null,
  "notes": []
}
```

`fill-NNN.json`（訳すページだけ。いくつでもよい）:

```json
{
  "stage_id": "9f3c2a7e5b1d4c80",
  "nodes": {"n0007": "CQRS は ⟦S1⟧Command Query Responsibility Segregation⟦/S1⟧（コマンドとクエリの責務分離）の略である。……"},
  "drop_inline": [{"id": "n0210", "tag": "L7", "reason": "図の説明文の末尾の著者の表記"}],
  "release_terms": [{"id": "n0301", "tag": "T9", "reason": "さびの意味の rust"}]
}
```

- `stage_id` は、`--stage` が作業場所ごとに作る 16 進の値（`secrets.token_hex(8)`）である。ファイル名に使える文字だけからなる。作った日時は `source.json` の別の項目に持つ。
- `decisions.json` と `fill` の `stage_id` が `source.json` と一致しなければ誤りにする。
- 同じノードが 2 つの `fill` にあれば誤りにする。
- `annotated_by` は、補足を書いたときに必要になる。訳すページでは `translated_by` と同じ値でよい。

### `apply` の検査

誤りがあれば何も書かない。誤りの一覧を、ノードの ID つきの JSON で返す。

**タグの照合（誤り）**

- 訳文がタグの木として読めない（閉じていない、交差している）。
- 対になるタグと単独のタグが、元のノードと**多重集合として**一致しない（欠けた、増えた、2 回使った、知らない番号）。`drop_inline` と `release_terms` で宣言したタグは除く。
- 入れ子の関係が元と違う。対になるタグどうしの入れ子は、元と同じでなければならない。単独のタグ（守る語、コード、数式）は、元で対になるタグの中にあったなら、訳文でも同じタグの中になければならない。元で外にあった単独のタグは、訳文で対になるタグの中に入ってもよい（日本語の語順で、リンクの文言の範囲が広がるため。下の「試した結果」）。並びの順は変わってよい。
- 対になるタグの中身が空。

守る語はタグなので、リンクの中の `Event Sourcing` を別のリンクの中に移すと、入れ子の関係が変わって誤りになる。

**判断の照合（誤り）**

- `content_root` が必要なのにない。知らない ID を指す。
- 振り分けのない雑音の候補、振り分けのない守る語の候補がある。
- 取得した画像のすべての出現に、`caption` か `decorative` がない。`unavailable` の出現に `caption` がある。補足があるのに `annotated_by` がない。
- 訳すページで、訳文のない文章のノードがある（消したノードを除く）。知らないノードの ID がある。
- 訳すページで `translated_by` が空。訳さないページで `translated_by` がある。
- 見出しと題名を消そうとした。

**記録（書くが、取り込みの記録に残し、`apply` の出力にも出す）**

構造から決まらないので、誤りにしないもの。

- 訳文に増えた英字か `<`、`>`、`=`、`!`、`&`、`|` を含む並び（原文の同じノードにないもの）。数字と句読点だけの並びは対象にしない。`<>` の追加はここに出る。
- です・ます調の文とである調の文が、どちらも全体の 1 割を超える。
- 訳文が元のノードに比べて極端に短い（値は試験で決める）。
- 消すノードの文字数が、本文の文章全体の 1 割を超える。

モデルは、出力を見て `fill` を直すか、`decisions.json` の `notes` に理由を書いて残す。

### 作業場所と錠

管理用のパスは、スラッグをそのまま 1 つのフォルダーの名前にし、その下に決まった名前の子を置く。スラッグに接尾辞を付けた名前や、ワイルドカードで探す名前は使わない。

スラッグが文字列として違っても、ファイルシステムが同じ名前とみなすことがある（Windows では大文字と小文字を区別せず、名前の末尾のピリオドと空白を無視する）。そこで、スラッグの検査に次を足す。

- 末尾がピリオドか空白のスラッグ、Windows の予約された名前（`CON`、`NUL`、`COM1` など）のスラッグは拒む。
- スラッグの照合の鍵を、NFC に正規化して `casefold()` した文字列とする。`--stage` は、`raw/` の Markdown、`raw/assets/` のフォルダー、`.wiki-cache/ingest/` のフォルダーの名前を一覧して、鍵が同じで文字列が違う名前があれば止まる（「`X` と `x` は同じ名前として扱われる」）。`apply` と `clean` も、錠を取ったあとに同じ確認をする。

これで、受け付けたスラッグが違えば、管理用のパスも raw のパスも、ファイルシステムの上で別の場所になる。

```text
<WIKI_ROOT>/.wiki-cache/ingest/<スラッグ>/lock        錠のファイル（残ってよい）
<WIKI_ROOT>/.wiki-cache/ingest/<スラッグ>/work/       作業場所
<RAW_ROOT>/.ingest-tmp/<スラッグ>/                     確定の途中の一時フォルダー
```

作業場所（`work/`）には、次を置く。

- `source.json`: `stage_id`、作った日時、`source_sha256`、frontmatter に入れる値、言語の判定、中間表現の木
- `images/`: 保存した画像
- `decisions.json`、`fill-NNN.json`: モデルが書く

**錠**: `<WIKI_ROOT>/.wiki-cache/ingest/<スラッグ>/lock` のファイルを開き、OS のファイルの錠を取る（Windows は `msvcrt.locking`、POSIX は `fcntl.flock`。どちらも標準ライブラリにある）。待たずに取れなければ、操作の名前と日時（錠のファイルの中身。参考の情報で、錠の判定には使わない）を示して止まる。錠は、操作が終わるか、プロセスが止まれば OS が外す。錠のファイルそのものは残ってよく、消さない。

`--stage`、`--restage`、`apply`、`clean` は、どれも操作の初めに錠を取り、終わりまで持つ。

- `--stage`: 錠を取り、作業場所がなければ作る。あれば止まる。
- `--restage`: 錠を取り、作業場所を消して作り直す。`stage_id` が変わる。
- `apply`: 錠を取り、作業場所の `stage_id` が `fill` と一致することを確かめてから確定する。成功したら、錠を持ったまま作業場所を消す。
- `clean`: 錠を取り、作業場所と、確定前の生成物（下の「確定」）を消す。

錠を回収する操作はない。錠が取れないのは、別のプロセスがその操作を実行している間だけである。lint は、7 日より古い作業場所と、確定前の生成物を報告する。

OS のファイルの錠は、ネットワークのフォルダーでは効かないことがある。同じ wiki を同じ機械で使う前提であり、複数の機械から同じフォルダーで同時に取り込むことは対象にしない。

作業場所は、取り込みの途中の原文を含む。ADR-0004 の「原文を保存しない」は、raw に原文を残さないこととして新しい ADR で改める。

### 確定

`apply` は、錠を取り、検査を通ったあと、次の順に書く。

**確定前の生成物**は、次の 2 つである。

- 一時フォルダー `raw/.ingest-tmp/<スラッグ>/`。`raw/<スラッグ>.md` があってもなくても、常に確定前の生成物である。
- `raw/<スラッグ>.md` がないときの、`raw/assets/<スラッグ>/` と `raw/<スラッグ>.ingest.json`。

どれもスラッグから決まる名前で、別のスラッグのパスに当たることはない。

1. `raw/<スラッグ>.md` があれば止まる（`source_sha256` が同じなら「同じ内容がすでにある」、違えば別版のスラッグを提案する）。確定前の生成物があれば、前の取り込みが途中で止まった残りなので、`clean` を案内して止まる。
2. 一時フォルダー `raw/.ingest-tmp/<スラッグ>/` を作り、その中に `assets/`、`record.json`、`page.md` を書き終える。
3. `assets/` を `raw/assets/<スラッグ>/` に名前を変える。
4. `record.json` を `raw/<スラッグ>.ingest.json` に名前を変える。
5. `page.md` を `os.link` で `raw/<スラッグ>.md` に結ぶ。行き先があれば失敗し、書きかけのファイルは正式な名前で見えない。これが確定の時点である。
6. 一時フォルダーを消す。錠を持ったまま作業場所を消し、錠を外す。

Markdown があるとき、記録と assets はすでにある。どの段で止まっても、残るのは確定前の生成物だけで、錠は OS が外しているので、`clean` がそれを消して作業場所からやり直せる。5 のあと 6 の前に止まった場合は、raw は確定しており、一時フォルダーだけが残る。`clean` と lint はそれを確定前の生成物として扱う。`os.link` が使えないファイルシステムでは、`apply` は確定せずに止まる。

### 取り込みの記録

`raw/<スラッグ>.ingest.json` に、確定した取り込みの記録を残す。

- `stage_id`、`source_sha256`、`translated_by`、`annotated_by`、使ったスクリプトの版
- 本文の選択（選んだ要素と、モデルが替えたか）
- 雑音の判断（規則の候補と、`confirm`・`restore`・`drop`・`drop_text`・`drop_inline` の別と理由。消したノードと文字列も残す）
- 守る語の判断（`keep` と `translate`、`release_terms` で外した出現と理由）
- 記録の項目（増えた並び、文体、短い訳、消した量）と `notes`
- raw の Markdown と、各 asset の SHA-256

消した雑音の文字列は原文の断片である。量は小さく、何を消したかを後から比べるために残す。新しい ADR に書く。

### raw の不変性

`apply` は、raw の Markdown の SHA-256 を出力する。要約ページの frontmatter に `raw_sha256` として書く（PDF の取り込みと同じキー）。lint は、要約ページの `raw_sha256` と raw の Markdown を照らし、取り込みの記録の SHA-256 と assets を照らす。偶然の書き換えを見つけるためのもので、改ざんを防ぐものではない。

### 画像

- 画像の出現はスクリプトが描き、alt と title は変えない。
- `apply` は、`caption` のある出現の直後に、同じ入れ物（引用の中、リストの項目の中）の兄弟のブロックとして `> <annotated_by> 補足: <caption>` を置く。
- `decorative` の出現は描かない。`asset` は、残る出現から参照されていなければ書き出さない。番号は振り直さない。

### ブラウザで取った HTML

`wiki_fetch.py` に `--html-file <パス>` を足す。ページの取得の代わりにファイルを読み、同じ変換と画像の取得をする。`source_sha256_of` は `dom` とし、`source_sha256` は手順のとおり本文のテキストに対して取る。今回の Medium の記事で使った `docs/agent-runs/2026-11-13-wiki-ingest-model-comparison/scripts/fetch_from_dom.py` を、正式な引数にしたものである。

## モデルに残す判断

- 訳文そのもの。言い方を強めた、弱めたといった質は、検査では分からない。
- 本文の選択を替えるか。雑音の候補を消すか戻すか。候補でない雑音を見つけること。
- 守る語を決めること。候補に挙がらない語は、モデルが足さない限り守られない。
- 図の説明の内容。数値の読み違いは検査できない。
- 記録に出た項目（増えた並び、文体）を直すか残すか。

## 失敗と対策の対応

| 失敗 | 対策 | 種類 |
| --- | --- | --- |
| コードブロックの変更 | コードブロックは訳すノードにならない。インラインのコードはタグ | 構造で防ぐ |
| リンクの欠落、記法の崩れ | リンクは対のタグで、URL はスクリプトが持つ。タグの多重集合と入れ子を照らす。記法は描画が書く | 構造で防ぐ |
| リンク先の入れ替え | タグの番号が URL を持つ | 構造で防ぐ |
| 説明文の alt への移動 | 画像の出現をスクリプトが描く。説明文は別のノード | 構造で防ぐ |
| 表の記法の崩れ | セルの訳文は平文で、エスケープは描画がする | 構造で防ぐ |
| 固有の名前の訳 | 守る語を訳の前に決め、タグにする | 決めた語は構造で防ぐ。決めなかった語は防げない |
| `<>` の追加 | 増えた並びの記録 | 見つけて記録する |
| 文体の混在 | 記録 | 見つけて記録する |
| 雑音の残り | 規則で候補を挙げ、モデルに必ず振り分けさせる | 見落としを減らす |
| 本文の誤った削除、誤った本文の選択 | 規則と本文の選択は印を付けるだけ。ノードは木に残り、戻せる | 戻せる |
| 削除の範囲のばらつき | 取り込みの記録に、判断と理由を残す | 記録で比べられる |
| 別の取り込みとの衝突、確定中の清掃 | raw に書くのは `apply` だけ。スラッグごとの OS のファイルの錠 | 構造で防ぐ |
| 同じ綴りの固有の名前と普通の語 | 守る語は綴りごとの既定で、出現ごとに `release_terms` で外せる | 宣言で外す |
| 古い `fill` の混入 | `stage_id` の照合 | 構造で防ぐ |
| 作業用のスクリプトを毎回作る | `review`、`next`、`fill` | 手順を固定する |

## ADR と文書への影響

- ADR を 1 つ足す（ADR-0018 の候補）。決めること: 中間表現、モデルに Markdown を書かせないこと、推測による除外を印にすること、守る語、タグの照合、作業場所と錠、確定の手順、取り込みの記録と雑音の断片を残すこと、Web ページの raw にも `raw_sha256` を書くこと。ADR-0004 の「スクリプトとモデルの分担」と「原文を保存しない」を、この ADR で改める。
- `commands/ingest.md` の「Web ページの取り込み」の手順 2〜7 と、`ingest-workflow.md` の「Web ページ」を書き直す。
- `wiki_lint.py` に、`raw_sha256` と取り込みの記録の照合、古い作業場所、確定前の生成物の報告を足す。

## 試験

- **HTML の内容との一致**: 中間表現から描いた Markdown を Markdown として読んだ結果が、HTML の本文の文字、リンク、強調、改行、コード、画像、表の形と一致する。試料は今回の 4 ページの HTML と、レビューで挙がった形（入れ子のリスト、引用の中のコード、複数の段落を持つ項目、段落の中の改行、連続した改行、改行を含む強調、リンクの付いた画像、セルの中の `|`、`rowspan`、同じ画像の 2 回の出現、取得できなかった画像、本文中の `*literal*` と `[manual](…)` の文字列）。
- **今の出力との差**: 今の `wiki_fetch.py` の出力との差を一覧にする。差は、エスケープと、今の変換が HTML の内容を落としていた箇所（上の試料）だけであることを確かめる。今の出力との一致は合格の条件にしない。
- **訳さずに戻ること**: 訳文として原文のタグ付きの文字列をそのまま返すと、描いた raw が、中間表現を訳さずに描いたものと一致する。
- **タグの照合**: タグを消す、増やす、2 回使う、番号を入れ替える、閉じない、交差させる、入れ子を変える、空にする、守る語を別のリンクに移す、の各場合に誤りになる。並びの順だけを変えた訳文は通る（対照）。`Unix` を文の先頭に移した訳文も通る（対照）。
- **記録**: `<>` を足すと記録に出る。`1, 2, 3.` を `1、2、3。` と訳しても記録に出ない（対照）。
- **本文の選択**: id に `cookie` を含む `article` が選ばれず別の `div` が選ばれたとき、`review` がその `article` を見せ、`content_root` がなければ誤りになり、替えれば本文とコードが raw に入る。
- **雑音**: 候補を `restore` すると元の位置に戻る。振り分けのない候補があれば誤りになる。
- **錠と確定**: `apply` を確定の各段（assets の名前の変更のあと、記録の名前の変更のあと、Markdown を結ぶ直前）でプロセスごと止めると、錠は外れ、確定前の生成物だけが残り、`clean` のあとにやり直せる。`apply` の実行中に別のプロセスの `clean` と `--restage` は錠で止まる。`--stage` のあとに同じスラッグの raw を別に作ると、`apply` が止まり、raw を上書きしない。`stage_id` を含むパスが Windows で作れる。
- **守る語**: `Rust` を `keep` にし、さびの意味の出現を `release_terms` で外すと通る。外さずにタグを落とすと誤りになる。`**Greg** Young` は当たらず、`review` に示される。
- **管理用のパス**: スラッグ `x` と `x.lock`、`x` と `x.v2`、`x` と `x.tmp-y` を続けて、また同時に取り込み、`clean x` を走らせても、互いのファイルに触れない。`x.` と `x ` は拒まれる。`x` を確定したあとの `X` は、同じ名前として止まる。
- **木の範囲**: `aria-hidden="true"` の中の目に見える式が雑音の候補として残り、`restore` で raw に入る。セルの中に段落とコードブロックを持つ表が、HTML の表として描かれ、コードブロックは訳すノードにならない。
- **部分の削除**: 訳さないページで `drop_text` が段落の末尾の文言だけを消す。「「共有」は操作名である。共有」の 2 回目の「共有」だけを `occurrence: 2` で消せる。文字列が 2 回現れるのに `occurrence` がないとき、指定した出現がないときは誤りになる。
- **HTML の表の読み方**: HTML の内容との一致の試験では、Markdown の中の HTML を読む設定（`html=True`）のパーサーで読む。HTML の表として描いた表の段落とコードが、その設定で読めることを確かめる。
- **画像**: 同じ画像の 2 回の出現の片方を飾りにしても、残る出現のファイルが残る。取得できなかった画像は判断なしで通る。引用の中の画像の補足が、引用の中に置かれる。
- **言語の判定**: 日本語の説明と英語のコードからなる引用だけのページが、日本語と判定される。
- 今回の比較を再実行し、Haiku でもコード、リンク、画像の行、表、守る語が崩れないことを確かめる。

## 段階

1. 中間表現と描画への置き換え。推測で捨てていた要素を印に変える。今の変換が落としていた内容（リンクの付いた画像、改行、項目の中の段落など）を直す。`--html-file`。この段階では raw の書き方は変えない。
2. `--stage`、`review`、`next`、`apply`、錠、タグと判断の照合、確定の手順、取り込みの記録。`--stage` なしで raw に直接書く使い方をやめる。手順の書き直しも同じ PR に入れる。
3. `raw_sha256` の書き込みと、lint の照合。

## 試した結果（2026-11-13）

大の案の成否を分ける前提を、実装の前に 2 つ試した。

- **タグの往復**: CQRS と SQLite の基準の raw から 32 の段落を、リンク、強調、インラインのコード、守る語（`CQRS`、`SQLite`、`INTEGER` など）をタグにした形に変え、Sonnet 5.5 に訳させた（タグ 92 個、33 秒）。31 段落はタグの多重集合と入れ子が元と一致した。残る 1 段落は、「Flexible typing is a feature of SQLite, not a bug」のリンクの範囲を、日本語の語順に合わせて「柔軟な型付けは SQLite の欠陥ではなく機能である」まで広げ、外にあった守る語がリンクの中に入ったものだった。訳として正しいので、入れ子の照合を上のとおり非対称にした。訳の質は、比較のときの Sonnet の raw と同じ水準だった。Haiku と Opus では試していない。
- **守る語の候補の数**: 比較の 4 ページのうち英語の 3 ページで、候補の規則を当てた。重複を除いて CQRS 53、SQLite 173、Medium 160（コードを除く）。文の先頭の機能語（`An`、`As`、`But` など）が多く混ざるので、機能語の一覧で除けば減る。
