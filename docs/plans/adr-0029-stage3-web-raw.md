# ADR-0029 段階3の Web ページ取り込み

[段階3のセッション](adr-0029-stage3-session-raw.md) と [字幕](adr-0029-stage3-youtube-raw.md) に続き、Web ページの取得と確定を共通の書き込み検査に移す。

- `wiki_fetch.py` は、raw の本文、画像、一時ファイルと退避、wiki の作業用の写しを、それぞれ設定された根から検査する。根の記録に成功してから原本と画像を保存する。既存の `--force` と画像の退避・復旧を保ち、リンクの項目を置き換えない。名前の変更の再試行では経路も再検査する。
- 取得後の公開と作業用の写しの確定は、wiki と raw のそれぞれで、スラッグごとの OS のファイルロックを保持して行う。原本が取得中に変わった場合は保存を止める。ロックファイルは隠し領域に残し、プロセスが終了するとロックが解ける。フォルダーの移動など、プラグイン外の操作全般に対する完全な同時置換防止は範囲外とする。
- `wiki_rawcheck.py` は原本と作業用の写しをリンクを通さず検査する。freeze は共通部品の一時名で `removed.json` と `cleaned.md` を置く。W8 で完了するときは根を記録し、検査に使った最終 Markdown のバイト列の `raw_sha256` と絶対パスの `raw_ref` を返す。確定の境界は、作業用の写しの名前を外す操作とし、その後の削除に失敗した場合は片付けの残りを報告する。W9 は `read` のハッシュ検査を通った本文を使い、この出力から source ページの欄を埋める。
- 警告を受理する通常の手順では、直前に確認した `check_sha256` を渡す。比較元・原本のハッシュ、検査と警告の結果が変わっていれば確定を止める。既存の直接呼び出しでは期待値を省略できる。
- Python が処理できる保存エラーでは従来どおり画像を戻す。強制終了などで画像の退避が残った場合は、退避を保護して自動再開、取り直し、確定を止める。画像と本文を照合して戻す操作は手動で行う。
- 検査中に作る訳文や補足、利用者が許可した画像の削除は、今までどおり W4〜W8 の作業とする。取得元の HTML の `source_sha256` は取得や再開の照合に残す。

取得を模した試料で、根の記録の失敗、リンクの保存先の拒否、退避からの復旧、確定した本文の版、記録済みの過去の根を使う lint を検査する。
