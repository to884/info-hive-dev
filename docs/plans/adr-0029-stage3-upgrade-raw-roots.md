# ADR-0029 段階3のアップグレード時の raw の根の登録

[/wiki:upgrade の実装計画](wiki-links-2026-11-16.md) に従い、初期化済みの wiki に現在の raw の根を登録する。以前の取り込みで別の根を使っていた場合は、繰り返し指定できる `--previous-raw-root <パス>` を使う。`--wiki-dir`、`--raw-dir`、`--previous-raw-root` は絶対パスも指定できる。相対パスは `init_wiki.py` に渡したベースディレクトリを基準にする。

- 既存の `SCHEMA.md` で wiki を確認し、指定された過去の根がすべて通常のディレクトリとして使えることを確かめる。過去の根は作らない。現在の根がなければ、従来のアップグレードと同じく作る。
- 利用者が指定した綴りと解決したパスを、既存と同じ `given`・`resolved` の形式で記録する。ベースディレクトリの別名を経由した綴りも残す。所属が変わりうる `..` を含むパスは根に使わない。
- 記録は `wiki_fsguard.py` 経由で排他公開する。並行する根の登録は同じロックで直列にする。同じ組には同じファイル名を使い、再実行時は `given`、`resolved`、`writer` が一致すれば、元の日時を保って再利用する。記録の途中で失敗した場合は、登録済みの項目を残して理由を返し、実行環境のセットアップに進まない。
- 既存の `raw:` や `raw_sha256:` は書き換えず、原本を検査のために移動したり作り直したりもしない。lint は従来の経路で記録を読む。過去の根の別名がすでに別の場所を指す場合、当時の実体のパスが分かればそれも登録する。ハッシュを持たない旧ページは版未検証とする。

回帰試験では、現在の根と過去の根を登録し、現在の根を切り替えたあとも lint が元のファイルの版を検査できることを確かめる。途中にディレクトリのリンクがある場合は、原本を開かず警告する。並行する登録で同じ組が重複せず、異なる組は両方残ることも確かめる。
