## 2. 守る範囲

### 2.1 守るもの

守るのは、次の 4 つの性質である。試験（9.1 の世界の差分）は、この 4 つを、実行の前と後で比べる。

| 性質 | 内容 |
| --- | --- |
| 名前 | 項目のパス（ディスク上の綴り） |
| 種類 | ファイル、ディレクトリ、リンク（シンボリックリンクと、ジャンクションなどの再解析点） |
| 中身 | ファイルの通常の中身の SHA-256。リンクは、たどらない |
| 属性 | 読み取り専用か、と更新時刻。ファイルにもディレクトリにも当てはめる |

守る場所は、領分の外のすべてである。Wiki のルートの下、`--out` に指した場所に前からあるもの、リンクやジャンクションの先、ハードリンクのもう片方の名前を含む。

ただし、ディレクトリの中に項目を作る、名前を付け替える、消すと、そのディレクトリの更新時刻は変わる。そこで、**browse が新しく作るディレクトリと、名前を付け替えるディレクトリの、親の更新時刻**は、守る対象から外す。ディレクトリの名前で数え上げずに、操作で決める。領分の外で、これに当たるのは次の場合である。

- `--out` の書き出し先の親（書き出し先と作業用のディレクトリを、作る、付け替える場所）。
- `<data_dir>/browse/` を作るとき、ない祖先を上から作るので、いちばん上に作ったディレクトリの親。`<data_dir>` があれば `<data_dir>`、なければ `<data_dir>` の親（さらにないときは、その上）である。

更新時刻を元に戻すことはしない（属性を変える操作になるからである）。browse が領分の外に作ってよいディレクトリは、領分と書き出し先そのものと、その祖先（`<data_dir>` がないとき）だけである。

### 2.2 対象にしないもの

上の 4 つで量れないものは、守る対象にしない。browse の操作（名前の付け替え、名前を指した削除、空のディレクトリの削除、排他での作成）は、これらを変えることがある。

- 代替データストリーム（NTFS）、拡張属性、アクセス制御の一覧
- マウント（ジャンクションやリンクでない形で、ディレクトリの場所に別のファイルシステムを重ねたもの）
- 調べてから操作するまでのあいだに、ほかのプロセスが割り込む競合
- 利用者が一覧（`.browse-generation`）を書き換えた場合

`--out` の書き出し先や、その中のファイルに代替データストリームを付けると、次の書き出しで失われる。10 に挙げる。

### 2.3 browse の領分

browse の領分は、browse が自分のために作るディレクトリである。領分の中に利用者が手で置いたものは、守らない。browse は、領分の中のものを、自分のものとして置き換え、消す。

| 領分 | 場所 | 目印 |
| --- | --- | --- |
| browse のデータの場所 | `<data_dir>/browse/` の全体（共通のロック `build.lock` を含む） | 場所で決まる |
| 既定の書き出し先 | `<data_dir>/browse/<wiki_key>/` | 場所で決まる |
| 状態のディレクトリ | `<data_dir>/browse/<wiki_key>.server/` | `.browse-server`。中身は Wiki のルートの識別子 |
| 作業用のディレクトリ | 書き出し先の隣の `<名前>.browse-work/`（既定の書き出し先と `--out` の両方） | `.browse-work`。既定の書き出し先の作業用は、中身が Wiki のルートの識別子 |

`wiki_key` は、Wiki のルートのパスを NFC にそろえて作るので、綴りだけが違う 2 つの Wiki に同じ値を返す。そこで、`wiki_key` で場所を決める領分は、目印に Wiki のルートの識別子を書き、触れるたびに照らす（7.1）。

目印は、所有の証明ではなく、「この場所を browse が使っている」ことを利用者とほかの browse に知らせる印である。目印のあるディレクトリと、`<data_dir>/browse/` の下の決まった名前は、browse が使う。目印がなく、空でもないディレクトリが、作業用や状態のディレクトリの場所にあれば、使わずに止まる。

領分の中で消すときの決まり（6.2）は、領分の外にあるものを守るためにある。リンクやジャンクションの先は、領分の外である。

## 3. 入出力の層（P1、P2）

browse のファイルの入出力は、すべて `wiki_browse_fs.py` を通す。`wiki_browse.py` と `wiki_browse_core.py` は、入出力を呼ばない。

### 3.1 口

層が OS を呼ぶ口を、一覧で決める。呼ぶたびに `os` から引いて呼ぶ。

| 口 | 使う場面 |
| --- | --- |
| `os.scandir`（開く、項目を 1 つ取り出す、閉じる）と、項目の `is_symlink`、`is_dir`、`stat` | 走査（走査の計画の関数が呼ぶ）、領分の一覧、書き出し先の照らし合わせ |
| `os.lstat`、`os.stat` | 種類、大きさ、更新時刻 |
| 識別子を取る関数（走査の計画の `win_file_id()`。Windows では `CreateFileW`、`GetFileInformationByHandleEx(FileIdInfo)`、`CloseHandle` を直接呼ぶ。POSIX では `os.stat` の `st_dev` と `st_ino`） | 同じディレクトリかどうか（6.1） |
| `os.open`、`os.read`、`os.write`、`os.close` | 読む、排他で作る |
| `os.mkdir`、`os.rename`、`os.replace`、`os.unlink`、`os.rmdir` | 作る、付け替える、消す |
| `os.path.realpath(…, strict=True)` | 書き込みの口が、対象の場所が Wiki のルートと重ならないかを確かめる（6.1）。結果は、識別子の比較にだけ使う |
| ロックの取得と解放 | 共通のロック、作業用のロック、サーバーのロック |

使わないもの:

- `pathlib` の入出力（`Path.is_file()` など）と、組み込みの `open`。
- 属性を変える操作（`chmod`）と、ディレクトリを中身ごと消す操作（`shutil.rmtree`）。

標準ライブラリには、失敗を黙って読み替える関数があり、どれがそうかは版によって違う。2026年11月11日に、開発用の PC のソースと実物で確かめた例は次のとおりである。

| 関数 | 読み替え |
| --- | --- |
| `Path.is_file()`（3.14） | 中で呼ぶ `nt._path_isfile` が、どの失敗も偽にする |
| `os.path.realpath()`（3.10、3.14） | `strict` を付けないと、アクセスの拒否（Windows のエラー 5）や共有違反（32）で解けなかった部分を、解かないまま返す |
| `os.path.realpath(…, strict=True)`（3.14） | 結果から `\\?\` を外せるかを確かめる 2 度目の呼び出しの失敗を握りつぶし、`\\?\` の付いたパスを成功として返す（走査の計画のセッションが確かめた） |
| `os.stat()`、`os.lstat()`（Windows の 3.10、3.14） | ファイルやディレクトリを開けないとき（アクセスの拒否、共有違反など）、ディレクトリの一覧の情報で「成功」を返し、`st_ino` を 0 にする（`win32_xstat_impl`。同。3.10 では `st_dev` も 0 になる） |
| `os.stat()`（Windows の 3.12 以降） | `FileIdInfo` の取得の失敗を捨てて続け、`st_dev` を 64 ビットではなく 32 ビットの値にする。`st_ino` は 0 にならない（`win32_xstat_slow_impl`。走査の計画のセッションが確かめた）。3.10 は、いつも 32 ビットの値を返す |
| `os.stat()`、`os.lstat()`（Windows の 3.10、3.14） | 属性の取得（`GetFileInformationByHandle`、3.12 以降は `FileBasicInfo` も）がエラー 1、50、87 で失敗すると、`st_mode` をブロックデバイス（`S_IFBLK`）にして成功として返す（`win32_xstat_impl`、`win32_xstat_slow_impl`。走査の計画のセッションが確かめた） |
| `os.scandir()` を閉じる操作（3.10、3.14） | `FindClose` と `closedir` の戻り値を見ず、失敗を捨てる（`ScandirIterator_closedir`。同）。項目を取り出すときの失敗は、送出される |
| `wiki_graph_common._try_lock()` | どの `OSError` も「取れなかった」にする。`_unlock()` は、失敗を黙って捨てる |

それぞれの扱いは、次のとおりにする。

- `realpath` の結果は、文字で比べない。解いたパスの実体が、解く前のパスの実体と同じ識別子であることを確かめてから、親をたどる比較にだけ使う（6.1）。`\\?\` の有無は、識別子の比較に響かない。
- 同じものかどうかは、走査の計画と同じ識別子の関数で決める。`os.stat()` の識別子は、版によって幅が変わり、失敗しても黙って続くので、比べる用には使わない。識別子の関数が失敗したとき（識別子を返さないファイルシステムを含む）は、「分からない」とする。
- browse の層が自分で呼ぶ `os.stat()` と `os.lstat()` で、識別子（`st_dev`、`st_ino`）が 0 なら、「分からない」とする。種類（ファイル、ディレクトリ、再解析点）は、一覧の情報から返る値でも正しいので、そのまま使う。大きさと更新時刻は古いことがある（4.2）。
- Windows で、種類がブロックデバイス（`S_IFBLK`）なら、属性を取れなかったものとして、「分からない」とする。
- 走査の計画の関数の結果は、そのまま使う。走査の計画は、Windows で `.md` の `os.stat()` が識別子 0 の成功を返したとき、ファイルとして返す（作者の決定。今と同じ集合）。`MdFile` は識別子を持たないので、browse はこの場合を見分けない。そのファイルは開けないことが多く、読むときに「読めない」になる（4.1）。
- `os.scandir()` は、閉じる前に項目を最後まで取り出す。閉じるときの失敗は見えないが、結果は変わらない。探索は、閉じる操作には手を入れない。
- ロックの口は、層が自分で持つ。「ほかが持っている」（Windows の `EACCES` と `EDEADLOCK`、POSIX の `BlockingIOError`）だけを「取れなかった」とし、ほかの失敗は「分からない」にする。解放の失敗は、記述子を閉じれば OS が外すので、閉じたうえで捨てる。`_try_lock()` と `_unlock()` は使わない。

### 3.2 失敗の読み替え

- 読み替えは、層の 1 つの関数だけが行う。分け方は、走査の計画（6 版目の「決めること」の 2）と同じにする。

| 分け方 | 失敗 |
| --- | --- |
| ない | `FileNotFoundError`、`NotADirectoryError`、解けないリンク（`ELOOP`、Windows のエラー 1921）、正しくない名前（Windows のエラー 123） |
| 分からない（例外 `Unknown`） | `PermissionError`（準備のできていないドライブの Windows のエラー 21 を含む）、`NoFileId`、識別子が 0、`EBADF`、そのほかの `OSError` |

- 解けないリンクを「ない」にするのは、木の状態として必ず起きる失敗だからである。「分からない」にすると、自分を指すシンボリックリンクが 1 つある Wiki で、browse だけが新しい中核を採れなくなる（lint は、そのリンクを飛ばす）。
- 走査の計画は、「そのほか」を送出する。browse の層では、送出された例外も「分からない」として受ける（4.1）。
- browse のほかの場所は、ファイルの入出力の `OSError` を受けない。受けてよい箇所は、この関数と、7 の境界（要求、コマンドの出口、仕事の単位）だけで、一覧にして試験で固定する。
- 呼ぶ側は、「分からない」を空、偽、既定の値に直さない。
- 「ない」という答えから、あとの書き込みが安全だと決めない。安全の結論は、あると見て識別したものにだけ付ける（6.1）。
- 1 つの操作には、口を 1 つだけ使う。どの口を使うかは、先に調べた種類で決める。口が失敗したら、別の口で同じ操作を試し直さず、その失敗の分け方で決める。失敗を受けた側は、口の選び違いと、権限の失敗や、書き込みの口の中の確かめ（6.1）の失敗を見分けられないからである。0.10.0 の `_remove_link()` は、リンクを外す `unlink` のどの失敗も `rmdir` で試し直し、6 版目の初めの規則（6.2）も同じ形だった。探索は、その試し直しが「分からない」の失敗を警告なしに飲み込むことを見つけた（9.6）。
- 書いたあとの `close` の失敗は、書けなかったこととして扱う。書き込みが要求より短く終わったら、書き終わるまで続ける。
- 通信（サーバーへの問い合わせ、ブラウザとの接続、中核の子プロセスの標準入出力、コマンドの標準出力）は、ファイルの入出力ではない。受ける箇所を別の一覧にする。標準出力に書けないときの終了コードは、7 の規則で決める（単位の真実で決め、知らせの失敗では変えない）。

### 3.3 層の外の入出力

- `wiki_pages` は、読み込みのときに、同梱のファイルを読む（`_vendor_digest()`）。browse は、`wiki_pages` と、それを読み込むモジュールを、コマンドの出口の境界の中で読み込む。読めなければ、種類だけの短い知らせと、0 でない終了コードで終わる。
- `_vendor_digest()` は、列挙を拒まれると、例外ではなく空の集合のハッシュを返す（4 回目のレビューが確かめた）。その値（`PARSER_ID`）を使うのは、検索の解析の保存だけで、browse は使わない。走査の計画も、範囲の外としている。この計画でも直さない（11）。
- 同梱の画面の部品（`app.js`、`style.css`）は、`serve` と `build` の始めに 1 度だけ読む。読めなければ、起動しない。

### 3.4 試験

- browse の 3 つのモジュールの構文木をたどり、口の一覧にない入出力の呼び出しと、一覧にない `OSError` の受け口がないことを確かめる。違反を 1 つ埋めた写しで、この試験が失敗することも確かめる。
- 層から呼ぶ依存先の関数（走査の計画の関数、lint とグラフの抽出の、文字を解釈する関数）は、口を通して呼ぶので、探索（9.3）が中の呼び出しにも手を入れられる。

## 4. 入力の集合（P3）

browse は、Wiki をたどるコードを持たない。ページと索引の名前の集合は、走査の計画の関数（`wiki_pages.walk_pages()` と `walk_index_files()`）から受け取る。別名のジャンクション、リンクの `indexes`、輪の扱いは、その関数が決める。

走査の計画の 7 版目（作者が 2026年11月12日に承認した）が約束することは、次のとおりである。

- 結果は `Walk(files, unlistable, unknown)` である。`files` は `MdFile(rel, size, mtime_ns)` の並びで、大きさと更新時刻は、ファイルかどうかを調べた `os.stat()` の値である。
- 一覧を作れなかった場所は `unlistable` に、種類か、同じ場所を回っていないかを調べられなかった項目は `unknown` に入る。権限の失敗は、口のどの呼び出しで起きても、どちらかに入る。そのほかの `OSError` は、送出する。
- 同じディレクトリかどうかは、識別子だけで決める。識別子を取れないときは、`unknown` に入れて降りない。
- たどる間になくなったものは、知らせなしに欠ける。受けるのは呼び出し元である。

**入力の一覧は 1 つにする。** browse の入力は、ページ、索引のファイル、オントロジー（`graph/ontology.yaml`）である。走査の関数が返すのは、前の 2 つだけである。そこで、2 つの走査の結果に、オントロジーの項目（層の `os.lstat` と `os.stat` で得た種類、大きさ、更新時刻。ないなら「ない」）を足したものを、**入力の一覧**とする。写しが読むものも、変化を知るための印も、比べる 2 回の走査（4.2）も、この 1 つの一覧から作る。印を作る箇所が、別に入力を数え上げることはしない。

### 4.1 browse の扱い

守ること 2（lint と同じ判定）は、すべてが分かるときに成り立つ。分からないことがあるときは、守ること 9（状態を区別して示す）を先にする。

| 分からないこと | lint | browse |
| --- | --- | --- |
| 走査が送出した。`unlistable` か `unknown` が空でない | 知らせを見ずに、残りの集合を使う | 新しい中核を採らない。サーバーは前の中核を「古い」と示して使い、なければ 503。書き出しは失敗し、前の世代が残る |
| ページの中身を読めない | そのページを集合から外し、`read_errors` に挙げる。そのページへのリンクは、`broken_links` に入る | そのページがない Wiki と同じに描く。加えて、そのページを「読めない」と示し、診断に挙げ、中身に依る一覧（未解決リンク、被リンク、関係）に「読めないページがあるので不完全」と出す |
| 索引のファイルの中身を読めない | その索引を飛ばす | その索引のファイルがない Wiki と同じに描く。加えて、診断に挙げ、ナビゲーションに「不完全」と出す |
| オントロジーがあるかどうかを調べられない、中身を読めない | グラフの抽出は、読めなければ終了コード 2 で止まる | オントロジーがない Wiki と同じに描く。加えて、関係表の場所に「オントロジーを読めない」と示す（今と同じ） |

中身を読めない入力は、**その入力がない Wiki と同じに描き、読み取りの印を足す**。この 1 つの規則で、3 つの行が決まる。

名前の集合が分からないときは、全体を採らない。名前は分かっていて中身だけが分からないときは、その部分を「読めない」と示して続ける。前者を続けると、ページの減った Wiki が、印のないまま正常な Wiki に見えるからである。

今の中核（0.10.0）は、すでにこの規則のとおりに動く。中核と lint を実物で呼んで確かめた（[unreadable_probe.py](../agent-runs/2026-11-11-wiki-browse-structure/unreadable_probe.py)、[出力](../agent-runs/2026-11-11-wiki-browse-structure/unreadable_probe-output.md)）。

- `a.md` が `[[b]]`、`[[missing]]`、`[[c#見出し]]` を持ち、`b.md` が `[[a]]` を持つ Wiki で、`a.md` だけを読めなくした。lint の `broken_links` も、browse の未解決リンクも、`[("concepts/a.md", "missing")]` から `[("concepts/b.md", "a")]` に変わった。
- `one/x.md` と `two/x.md` があり、`b.md` が `[[x]]` を持つ Wiki で、`two/x.md` だけを読めなくした。`[[x]]` は、曖昧から、`one/x` への解決に変わった（4 回目のレビューの重大 5 の例）。
- どちらの例でも、読めなくしたときのリンクの解決、被リンク、未解決リンクは、そのページを木から取り除いたときと同じだった。出力のファイルで違ったのは、`data/diagnostics.js` と `index.html`（診断の件数）だけだった。
- 中身を空にして代わりに使う実装（対照）は、どちらの例でも、取り除いた木と違った。2 つ目の例では、未解決リンクは同じ `[]` で、lint との一致だけでは見つからない。

### 4.2 走査は、読む前と読んだあとの 2 回

たどる間になくなったものは、知らせなしに欠ける（走査の計画の約束）。読んでいるあいだの編集や名前の変更も、1 回の走査では見えない。そこで、仕事の単位（7）ごとに、走査を 2 回行う。

1. 1 回目の走査で、入力の名前、大きさ、更新時刻を得る。
2. 入力を読む。
3. 2 回目の走査を行う。

2 回の結果が同じときだけ、写しを採る。違えば、読んでいるあいだに Wiki が変わったとして、採らない。

- 静的の書き出しは、最大 3 回までやり直す。3 回とも違えば、失敗で終わり、前の世代が残る。
- サーバーは、その要求では新しい中核を採らず、前の中核を「古い」と示して使う（なければ 503）。次の要求で、またやり直す。

2 回目の走査の結果は、サーバーが次の要求で変化を知るための印にも使う。

開けないファイルの大きさと更新時刻は、Windows ではディレクトリの一覧の情報から返り、古いことがある（3.1）。そのファイルは読めないので、写しの中では「読めない」になり、2 回の比較で変化が見えなくても、古い中身を採ることはない。

### 4.3 「lint と同じ集合」の範囲

lint の今の集合は、Python の版で違う。Windows の Python 3.10 の `rglob` は、返したパスを `Path` の比較で重複を除くので、大文字と小文字を区別するフォルダーにある `a.md` と `A.md` の片方を、黙って落とす（走査の計画のセッションが実物で確かめた。3.12 以降は両方を返す）。

索引の集合も違う。今の `index_files()` は、`rglob("*.md")` が返す名前を種類を確かめずに返すので、先のないリンク、ディレクトリへのリンク、`.md` で終わる名前のディレクトリ、FIFO も返す。走査の計画は、ふつうのファイルだけを返す（作者が承認した）。

そこで、試験の基準は、第一に「走査の結果が、木の作りから計算した答えと等しい」とする。lint との一致は、走査の計画が確かめた OS と版で、走査の計画の「違いの表」にあるものを除いて求める。browse と lint が同じ関数に乗ったあとは、両者は作りで一致する。

## 5. 読む側（P4）

入力の実体の中身は、実体がどこにあっても、Wiki の内容として読んで描く。Wiki の外のファイル、browse の状態のファイル、browse が書き出したファイルを指すページも、同じである。読まない入力を作らないので、未解決リンクの一覧は、どの配置でも lint と一致する。

- **起きること**: Wiki のページが `server.json` を指していると、操作のトークンがページに描かれる。
  - サーバーでは、そのページを見られるのは、表示のトークンを持つ手元のブラウザだけである。
  - **静的の書き出しでは、トークンが書き出したファイルに残り、ファイルを持ち出すと渡る。** トークンは起動ごとに変わり、サーバーが終われば使えない。サーバーは 127.0.0.1 でしか待ち受けない。
- **検査の目印に、トークンを足す。** 公開の前の検査（8）は、`<data_dir>/browse/` の下にあるすべての状態のディレクトリの記録から、トークンを集めて探す。見つかれば、ファイルの名前を挙げて警告を出す。書き出しは止めない。記録があるのに読めないときは、「トークンが含まれていないかを確かめられなかった」と警告を出す（P1）。記録を写したファイルや、ほかの `data_dir` の記録のトークンは、探さない（11）。
- **生成の記録（`build-report.json`）を、ファイルに書かない。** Wiki のルートの絶対パスを持つファイルで、読む箇所がどこにもない。記録は、今までどおり標準出力に出す。
- 状態のディレクトリと入力の重なりを見て、サーバーを終わらせる仕組み（`shutdown_requested`、`_refresh_guard`）をなくす。

## 6. 書く側（P5）

browse は、Wiki と入力の実体を調べて守るのをやめる。確かめるのは、書き込む場所が Wiki のルートと重ならないことと、領分の外で置き換えたり消したりするものが自分の作ったものかどうか、の 2 つである。どちらも、Wiki の入力を調べない。

### 6.1 Wiki のルートと重ならないこと

**書き込みの口が、どれも確かめる。** 確かめる場所を、領分や書き出し先として数え上げない。層の書き込みの口（作る、排他で開く、ロックのファイルを開く、付け替える、置き換える、消す、空のディレクトリを取り除く）は、呼ばれるたびに、次の 2 つを確かめる。どちらかに当たれば、何もせずに止まる（Stop）。

| 確かめること | 当てはめる口 |
| --- | --- |
| 名前を足す、変える、消すディレクトリ（対象の親）が、Wiki のルートでも、その下でもない | すべての書き込みの口 |
| 動かす、取り除くディレクトリそのものが、Wiki のルートでも、その祖先でもない | 付け替える（元がディレクトリのとき）、空のディレクトリを取り除く |

ディレクトリ D が Wiki のルートかその下かは、次の手順で決める。

1. D そのものを `os.lstat` で見る。ディレクトリか、ディレクトリへのリンクでなければ、口を呼ばずに失敗する（「ない」なら「ない」、ほかは「分からない」）。祖先にはさかのぼらない。書き込みの口は、どれも親がなければ成り立たないからである。「ない」という答えから、あとの書き込みが安全だと決めない。
2. D を `os.path.realpath(…, strict=True)` で解く。解いたパスと解く前のパスの識別子（識別子の関数。3.1）が同じことを確かめる。
3. 解いたパスから根までさかのぼり、どの親の識別子も、Wiki のルート（同じく解いたもの）の識別子と同じでないことを確かめる。
4. どこかで分からなければ（識別子の関数が失敗した場合を含む）、止まる。

「Wiki のルートの祖先」は、Wiki のルートを解いたパスとその親の識別子の集まりで決める。

- 同じ仕事の単位の中では、確かめたディレクトリと、取った識別子を覚えておき、取り直さない。覚えるのは、あると見て、識別子を取ったディレクトリだけである。仕事の単位のあいだに場所が入れ替わることは、競合として範囲の外である（2.2）。
- 書き出しの始めには、どこにも作る前に、書き出し先そのもの（`--out` と既定）と、その親を、同じ手順で確かめる。口も確かめるので、これは守りではなく、作業用のディレクトリを作る前に止めるためである。書き出し先が「ない」なら、書き出し先そのものの確かめは飛ばす。そのあとの書き込みの安全は、口のそれぞれの確かめが受け持ち、この「ない」の答えには頼らない。
- 6 版目の初めの手順は、1 で「ない」なら親へさかのぼり、祖先で確かめた結論を、「ない」と答えた D の名前に覚えていた。D がある（`lstat` だけが誤って「ない」と答えた）と、あとの口がその覚えに乗り、Wiki のルートの下に作業用のディレクトリを作った（探索が、Wiki のルートの下の `--out` で見つけた。9.6）。
- 空の Wiki のルートそのものを `--out` に指したとき（4 回目のレビューの重大 1）は、始めの確かめが「Wiki のルートは動かさない」として止まる。始めの確かめがなくても、ルートを取り除く口が止まる。`data_dir` が Wiki のルートの下にあるときは、`<data_dir>/browse/` に作る口が止まる。

**入れ子の書き出し**: 書き出し先と作業用のディレクトリを、ほかの browse のディレクトリ（目印 `.browse-work`、`.browse-server`、`.browse-generation` を持つディレクトリ）の中には作らない。上の手順でさかのぼる解いたパスの親のそれぞれに、目印があるかを `os.lstat` で確かめる。分からなければ止まる。これは守りではない。入れ子にすると、外側の世代が「一覧にない項目がある」として、次の書き出しで止まるので、先に知らせるためである（今の 0.10.0 と同じ振る舞い）。

### 6.2 領分の扱い

**それぞれの領分**:

| 領分 | browse が作る名前 | browse が消す名前 | 知らない項目 | 目印がないとき |
| --- | --- | --- | --- | --- |
| 作業用のディレクトリ | 目印（とその置き換えの `.new`）、`build.lock`、`tmp-N`、`old-N`、`del-N` | `tmp-N`、`del-N`、`old-N`（`del-N` に付け替えてから）、0.10.0 の `seq` と `build-report.json` | そのまま残す。拒む理由にしない | ないか空なら、作って目印を置く。空でなければ、使わずに止まる |
| 状態のディレクトリ | 目印（とその置き換えの `.new`）、`server.lock`、`server.json`、`server.json.new` | `server.json`、`server.json.new`、目印の `.new` | そのまま残す。拒む理由にしない | 同上 |
| 既定の書き出し先 | 世代の中身と一覧 | 前の世代（作業用に退避してから） | 前の世代と一緒に退避し、消す | 目印は使わない。場所で決まる |

**消すときの決まり**:

- 名前を 1 つずつ消す。ディレクトリは、中を 1 つずつ消してから `rmdir` する。
- リンクとジャンクションは、たどらずに、`unlink` でリンクそのものを外す。外せなければ、`rmdir` などで試し直さず、その失敗の分け方で決める（3.2）。`os.unlink` は、Windows でも、ジャンクションとディレクトリのシンボリックリンクを外し、先を残す（2026年11月12日に、開発用の PC の Python 3.11.15、3.13.7、3.14.6 で確かめた）。
- 属性を変えない。読み取り専用のファイルは消せないので、警告を出して残す（ハードリンクのもう片方の属性も変わるからである）。
- 分からなければ、そこで止め、警告を出して残す。残りは、次の実行が続きを消す。
- 警告には、残した項目の今の名前（`del-N` に付け替えたあとなら `del-N`）と、失敗した口と、その対象（作業用のディレクトリからの相対の名前）を書く。どのファイルの失敗で何が残ったかが、警告から分かるようにするためである。

### 6.3 `--out` の書き出し先

`--out` の書き出し先は、利用者が指した場所で、領分ではない。browse は、そこにあるものが自分の作った世代と確かめられるときだけ、置き換える。

- 世代のディレクトリを作ったら、最初に一覧（`.browse-generation`）を書く。一覧は、その世代のファイルとディレクトリの名前、ファイルの大きさと SHA-256 を持つ。通し番号も記録のために書くが、復旧の順にも、次の番号にも使わない（6.4）。
- 書き出し先は、次のどれかのときだけ置き換える（門）。
  - ない。
  - 空のディレクトリである（取り除いてから、新しい世代を置く。守ること 1 の例外）。
  - 一覧と照らして、世代の全体が合う。一覧にない項目、種類の違う項目、中身の違う項目、一覧にあってないものが 1 つもない。
- どれでもなければ、書き出しを止める。「書き出し先に、browse が作っていないものがある」と、理由を挙げて知らせる。終了コードは 0 でなく、書き出し先は前のままである。
- 一覧は、門で 1 度だけ読む。判定にも通し番号にも、その 1 度の結果を使う。
- 既定の書き出し先は領分なので、門を通さず、前の世代を読まない。種類と、空かどうかだけを見る。

**0.10.0 が残したもの**: 0.10.0 の世代は、一覧に名前と中身がないので、門を通らない。`--out` の書き出し先なら、書き出しを止め、場所を挙げて、消してからやり直すよう知らせる。既定の書き出し先は領分なので、そのまま置き換える。0.10.0 の一覧の番号は、読まない。

### 6.4 静的の書き出しの手順

1. 既定の書き出し先なら、ない祖先（`<data_dir>` と `<data_dir>/browse/`）を上から作る。書き出し先とその親を確かめる（6.1）。作業用のディレクトリを使う（6.2。既定の書き出し先の作業用は、目印の Wiki のルートの識別子を照らす。7.1）。作業用のロックを取る。取れなければ、「同じ書き出し先に、ほかの書き出しが動いている」と止まる。
2. 作業用の残り（`tmp-N`、`del-N`、0.10.0 の `seq` と `build-report.json`）を消す。
3. 書き出し先が「ない」か「空」で、`old-N` があれば、途中で止まった入れ替えから、最後に退避した世代を戻す。`old-N` のうち、**名前の番号 N** がいちばん大きいものを、書き出し先の名前にする。一覧は読まない。`del-N` と `tmp-N` は、戻さない。
4. 門（6.3）。既定の書き出し先は、通さない。
5. 通し番号を、作業用にある名前（`tmp-N`、`old-N`、`del-N`）の番号のうち、いちばん大きいものに 1 を足して決める。作業用に番号の付いた名前がなければ、1 にする。

番号は、作業用にあるどの名前よりも大きく取る。そのため、作業用に同時にある `old-N` のあいだでは、番号の大きいほうが、あとで退避した世代である。番号が 1 に戻るのは、作業用に番号の付いた名前が 1 つもないときだけで、そのときは比べる相手がない。一覧の番号は、0.10.0 の世代や、既定の書き出し先のように読まない世代があるので、順を表さない（5 回目のレビューの重大 2）。
6. `tmp-N` を作り、一覧を書き、世代のファイルを排他で作る。
7. 入れ替える。書き出し先が空なら取り除く。世代なら `old-N` に退避する。`tmp-N` を書き出し先の名前にする（**確定の点**）。付け替えに失敗したら、`old-N` を書き出し先に戻す。戻せなければ、次の実行の 3 が戻す。
8. 確定のあと、`old-N` を `del-N` に付け替えてから消す。失敗しても、警告を出し、終了コードは 0 にする。
9. 生成の記録を標準出力に出す。出せなくても、警告を標準エラーに出そうとし、終了コードは 0 にする（7）。

文章にはなかったが、探索（9.3）が見つけた規則が 3 つある。どれも、上の手順と 7.1 に入れた。

- 門で読んだ一覧を、通し番号を決めるときに読み直していた。2 度目の読み取りが失敗すると、前の世代が「一覧がない」に見えた。判定に使った値は、読み直さない（6.3）。
- 書いたあとの `close` の失敗を、握りつぶしていた。書けなかったこととして扱う（3.2）。
- 動いているかを確かめる操作が、目印のない空の状態のディレクトリに、ロックのファイルだけを作っていた。次の起動は「目印がなく、空でもない」として止まった。状態のディレクトリと作業用のディレクトリに触れる操作は、どれも 6.2 の領分の確かめを先に通す（7.1）。

## 7. 仕事の単位（P6）

単位ごとに、何が真実か、終わってよい状態はどれかを決める。「すべて済むか、前のまま」と言えるのは、取り消せる単位（静的の書き出し、中核の組み立て）だけである。

**終了コードは、単位の真実だけで決める。** 確定の点のあとに起きた失敗（片付け、標準出力への知らせ、標準エラーへの警告）は、どれも終了コードを変えない。確定の点の前に、知らせは出さない（4 回目のレビューの重大 3）。

| 単位 | 真実 | 終わってよい状態 | 確定の点 |
| --- | --- | --- | --- |
| 静的の書き出し | 書き出し先にある世代 | 新しい世代が書き出し先にある（終了コード 0。作業用に残りがあってもよい）。または、前のまま（0 でない）。入れ替えの途中で止まったときは、書き出し先がなく、前の世代が作業用の `old-N` にあり、次の実行が戻す | 新しい世代を書き出し先の名前にする、名前の付け替え |
| サーバーの中核の組み立て | サーバーが持つ今の中核 | 新しい中核。または、前の中核を「古い」と示して使う。前の中核がなければ 503 | 中核の入れ替え（生成日時は中核が持つ） |
| サーバーの一生 | 状態のディレクトリのロック。持つプロセスが止まれば、OS が外す | 動いている（ロックがある）。または、動いていない（ロックがない。記録の有無は問わない） | なし |

### 7.1 サーバーの記録

記録（`server.json`）は、真実ではなく、手がかりである。

- **領分の確かめ**: 起動、終了、`stop`、動いているかの確かめは、どれも、状態のディレクトリに触れる前に 6.2 の確かめを通す（ないか空なら目印を置き、目印がなく空でなければ止まる）。目印を置く前に、ロックのファイルを作らない。
- **持ち主の確かめ**: `wiki_key` で場所を決める領分（状態のディレクトリと、既定の書き出し先の作業用のディレクトリ）の目印には、Wiki のルートの識別子を書く。触れるたびに、今の Wiki のルートの識別子と照らす。
  - 同じなら、そのまま使う。
  - 違い、領分のロック（`server.lock`、`build.lock`）が空いていれば、別の Wiki が前に使っていた場所である。目印を置き換え、「別の Wiki が使っていた場所を引き継いだ」と警告して使う。
  - 違い、ロックが取られていれば、別の Wiki が今使っている。何もせずに止まる。
- **起動**: ロックを取る、待ち受けを始める、記録を置き換える、の順にする。置き換えは、前の起動が残した `server.json.new` を消し、`server.json.new` を排他で作り、`os.replace` で `server.json` にする。記録を書けなければ、待ち受けを閉じ、ロックを離して、失敗で終わる。
- **終了と `stop`**: 待ち受けを閉じる、記録を消す、ロックを離す、の順にする。記録を消せなければ、警告を出して続ける。どこで失敗しても、ロックは外れ、「動いていない」になる。残った記録は、次の `serve` が置き換える。
- **使い回しと `stop`**: 記録には、Wiki のルートの識別子を入れる。記録を読む側（`serve` の使い回し、`stop`）は、記録の Wiki のルートの識別子が今の Wiki のものと同じか、と、記録の `instance` がその口で答えているサーバーと同じか、の両方を、いつも確かめる。どちらかが違えば、使い回さず、止める要求を送らず、知らせて止まる（4 回目のレビューの重大 4）。
- **記録を読めない（分からない）とき**: ロックがあれば「動いているが、届かない」として待ち、時間が切れたら知らせて失敗で終わる。ロックがなければ、古い記録として扱う。
- 守りが Wiki の入力を見ないので、Wiki の内容が、`serve` と `stop` を拒む理由になることはない。

### 7.2 部分の失敗と境界

- **部分の失敗**: ページの中身を読めない、1 ページを描けない、関係表を作れない、の 3 つは、その部分を「使えない」と示し、単位は失敗にしない。描けないページは、その場所に「このページを描けない」と出す。描画は中核を変えないので、失敗のあとも、同じ中核からもう一度描ける。
- **要求の境界**: サーバーの 1 つの要求の全体を囲み、ヘッダーのそろった 500 を返す。ここに来るのは、不具合だけである。
- **コマンドの出口**: 思わない例外でも、種類だけの短い知らせと、0 でない終了コードで終わる。スタックトレースは、`--debug` を付けたときだけ出す。

## 8. 描く側（P7）

- 写しを 2 つに分ける。
  - **内容**: 入力ごとの種類、相対パス、文字（読めなければその理由）、世代。`Path` と、機械の絶対パス（Wiki のルート、ホーム、`data_dir`）を持たない。`Core` は、内容だけを受け取る。
  - **読み取りの情報**: 入力の印と、読めなかった入力。
- 今、中核が絶対パスに触れる 4 か所のうち、前の 3 つ（スラッグと索引の題名をファイル名から取る 2 か所、グラフのページの `path` の欄）は、相対パスから作る。残る `raw:` の `~` の展開はやめ、`link` の描き方でも、`~` で始まる値はリンクにせず、文字で出す。
- `Recorder` と、利用者が書いたかの推定をなくす。
- **言えること**: 生成器は、機械の情報（絶対パス、トークン）を出力に足さない。出力に機械の情報が入るのは、入力の実体の中身にあるときだけである。だれがその中身を書いたか（利用者か、browse か）は問わない（5）。
- **公開の前の検査**: 作った世代から、Wiki のルート、ホーム、`data_dir`、Wiki の外にある入力の実体の絶対パスと、記録のトークン（5）を探す。見つかれば、ファイルの名前を挙げて警告を出す。書き出しは止めない。
- **作りの確かめ**: 機械の情報を書いておらず、browse の作ったファイルも指していない Wiki を、目印の文字を含むディレクトリに置く。内容と、組み立てたあとの `Core` の値をすべてたどり、目印の文字と `Path` がないことを確かめる。

## 9. 試験（P8）

### 9.1 実装に依らない基準

基準は、browse の実装の出力からではなく、試験の側の表（木の作り、入れた失敗の場所）から決める。手を入れない実行の結果と比べるだけでは、正常な経路にある誤りが見えないからである。

| 基準 | 決め方 |
| --- | --- |
| 手を入れない実行 | 失敗も競合も入れない実行が、7 の「終わってよい状態」のうち、成功の側に着く。書き出しは 0 で終わり、新しい世代がある。browse の書き出しと確かめられない書き出し先と、Wiki のルートに重なる書き出し先では、止まり、何も変えない。これが「失敗のないときの約束」である（作者が決めたこと） |
| 世界の差分 | 砂場のディレクトリの全体（砂場の根そのもの、Wiki、Wiki の外の入力、書き出し先、ほかの書き出し、`data_dir`、関係のないファイル）について、2.1 の 4 つの性質を、ファイルにもディレクトリにも、実行の前と後で、試験の側が自分で読む。差は、領分と、その実行に指した書き出し先の中だけにある。2.1 で外した、新しく作るディレクトリと付け替えるディレクトリの親の更新時刻だけは、変わってよい。新しくできてよいのは、領分と書き出し先と、その祖先（`<data_dir>` がないとき）だけである。browse の書き出しと確かめられない書き出し先は、変わらない。Wiki のルートと重なる書き出し先では、手を入れない実行は、砂場の全体が変わらない。失敗を入れた実行（とそのあとの実行）では、Wiki のルートの下が、ルートそのものの属性を含めて変わらず、ほかはこの行の規則に従う（Wiki のルートの外にある領分は、できてよい） |
| 新しい世代 | 0 で終わったとき、書き出し先の木が、描くべきファイルの表から計算した木と同じである |
| 木の作りとの一致 | ページと索引の集合が、木の作りから計算した答えと同じである |
| lint との一致 | ページの集合、未解決リンク（`broken_links`）、`sources:` の解決が、同じ Wiki に、同じ失敗を入れた lint の結果と同じである。範囲は 4.3 のとおり |
| 2 方式の一致 | サーバーと静的版で、リンクの移動、被リンク、関係表、診断が同じである（今ある試験） |
| 決まった期待 | 9.4 の入力のそれぞれに、手で書いた期待を付ける。手を入れない実行が成功すること、出力にある文字、ない文字 |
| 機械の情報 | 8 の「作りの確かめ」の Wiki では、どの応答と出力にも、目印の文字とトークンがない |
| 触れない場所 | 入力でない場所（`raw/`、`assets/`、Wiki の外の関係のない場所）を対象にした口の呼び出しが、1 つもない。口の呼び出しの集合と、それぞれの役割（一覧、種類、読む、作る、消す）を、木の作りから計算し、失敗のない実行で、実際の呼び出しの集合と等しいことを確かめる。失敗を入れたときの答えも、役割から計算する（走査の計画の試作 `walk_v4.py` と同じ形） |

### 9.2 劣化の基準

口の呼び出しに手を入れたときに許す結果を、手を入れた対象の種類ごとに決める。P は、入力を変える前に得た結果である。

| 手を入れた呼び出しの対象 | 許す結果 |
| --- | --- |
| 入力の名前の集合（走査の口） | サーバー: 応答の全体が P と同じで「古い」の表示がある。前の中核がなければ 503。書き出し: 終了コードが 0 でなく、書き出し先の木が P と同じ。権限の失敗を入れたときは、必ずこのどちらかになる（新しい中核を採らない） |
| 入力の中身の読み取り（ページ、索引のファイル、オントロジー） | 結果が、その入力を木から取り除いて、手を入れずに得た結果（R）と、読み取りの印を除いて同じである。比べるのは、リンクの解決（解決、曖昧、未解決と、行き先）、被リンク、未解決リンク、関係表、ナビゲーション、各ページの HTML である。読み取りの印（ページの「読めない」、診断の `read_error`、中身に依る一覧の「不完全」、関係表の「オントロジーを読めない」）は、決まった場所に置き、比べる前に取り除く。印は、なければならない。加えて、未解決リンクが、同じ失敗を入れた lint の `broken_links` と同じである（4.3 の範囲で） |
| browse が作る場所（確定の前） | 書き出し: 終了コードが 0 でなく、書き出し先の木が P と同じか、入れ替えの途中の形（7）である。ただし、作業用の残りの片付けの失敗は、警告を出して続けてよい（6.2）。そのときは 0 で、新しい世代がある。サーバーの起動: 失敗で終わり、「動いていない」 |
| browse が作る場所（確定の後）と、知らせの出力 | 書き出し: 終了コードが 0 で、書き出し先の木が新しい世代である |
| どの場所でも | 「分からない」の失敗（権限、識別子 0、ブロックデバイス）を入れて 0 で終わったなら、同じ状態で手を入れない実行が出した警告にない、新しい警告がある（警告の多重集合で比べる。別の理由の警告で代えさせない）。手を入れなくても同じ呼び出しが同じ種類で失敗する場所に入れたときは、新しい失敗ではないので、この行を当てない。その代わり、手を入れない実行で「分からない」の失敗が起きて 0 で終わったなら、警告がある。確定の前か後かを、試作の申告に頼って分けない。例外は、読み終えたファイルとロックのファイルの `close` と、ロックの解放である（どれも、閉じれば OS が外し、結果を変えない） |
| 強制停止 | 7 の「終わってよい状態」のどれかで、手を入れない次の実行が成功し、新しい世代に着く。サーバーは「動いていない」で、次の `serve` が成功する |
| サーバーの終了と `stop` | 「動いていない」。同じ Wiki の次の `serve` が、手を入れなければ成功する |

どの場合も、9.1 の世界の差分を合わせて確かめる。500 と、入力の欠けた新しい結果は、どの行にもない。

「入力の中身の読み取り」の比較では、世代の識別子もそろえる。世代の識別子は、読み取りの情報（読めなかった入力を含む）から作るので、U と R では違い、各ページの HTML とデータのファイルに出る。そろえずに比べると、出力の 6 つのファイルが違い、そろえると 2 つ（診断と、索引の件数の表示）だけになる（[unreadable_probe-output.md](../agent-runs/2026-11-11-wiki-browse-structure/unreadable_probe-output.md)。U と R は、実際の `take_snapshot()` で作った）。

### 9.3 探索

口の呼び出しを数え、N 回目に手を入れる実行を、N を 1 から数え終わるまで繰り返す。走査の計画の関数の呼び出しも、同じ口を通る。

| 探索 | N 回目にすること | 見つける種類 |
| --- | --- | --- |
| 手を入れない | 何もしない（各状態で 1 回） | 失敗のないときの約束の破れ |
| 失敗 | 失敗の種類を、3.2 の表の行から取る（走査の計画と同じく、Windows と Linux で、その OS で起きる種類）。書いたファイルの `close` の失敗は、遅れて出た書き込みの失敗として、ファイルの中身を失わせてから返す | 失敗を空として扱う。境界の外の失敗。確定の点の前後の取り違え。解けないリンクで止まる。`close` の失敗の握りつぶし |
| 2 つ目の失敗 | 1 つ目の失敗のあとの 30 回までの呼び出し（片付けと戻し）にも、失敗を入れる | 片付けの失敗が、元の失敗を隠す。戻しの失敗で、前の世代を失う |
| 短い書き込み | 書き込みなら、要求の半分だけ書いて、正常に戻る | 短い書き込みを成功と取り違える |
| 正常に戻る異常 | 識別子を取る呼び出しが、識別子 0 で成功を返す。Windows で、種類を調べる呼び出しが、ブロックデバイスで成功を返す（3.1） | 例外だけを見て、成功の形の異常を「分かった」と読む |
| 強制停止 | そこで止める。それ以降の口の呼び出しは実行せず、開いていた記述子を閉じる（OS がロックを外したのと同じ）。書き込みなら、半分書いてから止める場合も試す | 途中の一時ファイルや残りで、次の実行が止まり続ける。途中の世代を、公開した世代として戻す |
| 変化 | その呼び出しの直前に、Wiki か書き出し先を変える（ページを編集する、消す、名前を変える、状態のファイルや書き出したファイルへのリンクやハードリンクにする、書き出し先に利用者のファイルを置く） | 変更に気づかない。browse のものでないものを消す。読んでいるあいだの変化を採る |
| 割り込み | その呼び出しの直前に、browse の別の操作を走らせる（`stop`、別の書き出し、別の `serve`、サーバーへの要求） | 組み立ての途中の終了。2 つの書き出しの取り合い。2 つのサーバー |
| 解釈 | 解釈の入口（Markdown の解析、YAML の読み取り、URL の解析、1 ページの描画）の N 回目を例外にする | 部分の失敗が全体を止める。描画の失敗のあとで描けない |

- ディレクトリの一覧は、開く、項目を 1 つ取り出す、の 2 つの口に分けて数え、取り出す途中にも手を入れる。閉じる操作には手を入れない（3.1）。
- 変化と割り込みは、1 つのスレッドの中で順序を作る。2 つのスレッドが本当に同時に動く競合は、探さない（11）。
- 変化の探索のあとは、手を入れない次の実行が、変えたあとの Wiki の新しい結果を返すことも確かめる。

### 9.5 対照

基準のそれぞれに、対照を付ける。守ることをわざと破った実装で同じ探索を走らせ、基準が失敗することを確かめる。対照は、呼ぶ側だけでなく、層の中にも置く。

| 基準 | 対照 |
| --- | --- |
| 劣化の基準（名前の集合） | 層の中で、一覧の失敗を空にする。層の中で、種類を調べられない項目を「リンクでない」にする。権限の失敗で知らせを出さない。知らせを 1 つ出して、全ページを捨てる |
| 劣化の基準（中身の読み取り） | 読めないページの中身を空にして使う。読めないページを外したあとも、外す前の候補で解決する（曖昧のまま残す） |
| 触れない場所 | 入力でない最上位の項目の属性を取らせる |
| 世界の差分 | 門を通さずに置き換える。リンクをたどって消す。消すときに属性を変える。出力の名前を絶対パスにする。書き込みの口が Wiki のルートとの重なりを確かめない。「ない」と答えた場所に、祖先で確かめた結論を覚える |
| 手を入れない実行 | 既定の書き出し先でも前の世代を読んで照らす（余計な読み取りに依る） |
| 劣化の基準（確定の後） | 確定のあとの片付けの失敗を、単位の失敗にする。知らせの出力の失敗を、単位の失敗にする。確定のあとの失敗を、警告せずに捨てる（手を入れなくても消せないファイルがある状態でも試す）。残した項目の警告に、付け替える前の名前だけを書く |
| 劣化の基準（失敗） | 書いたあとの `close` の失敗を握りつぶす。リンクを外す `unlink` の失敗を、`rmdir` で試し直す（0.10.0 と、6 版目の初めの規則の形） |
| 強制停止 | 退避した世代を、`del-N` に付け替えずに消す。領分の中の知らない項目を、拒む理由にする |
| 持ち主の確かめ | 記録と目印の Wiki のルートの識別子を照らさない |
| 入力の一覧 | 印を、走査の結果だけから作る（オントロジーを落とす） |
| 機械の情報 | 索引に Wiki のルートを書き足す。記録のトークンを中核に渡す |
| lint との一致 | 読めないページの未解決リンクを、印を付けずに落とす |
| 2 方式の一致（ブラウザ） | 片方の方式で被リンクを空にする |

### 9.6 書く側の試作で確かめたこと

書く側の規則（6、7.1）を、小さな試作（[write_model.py](../agent-runs/2026-11-11-wiki-browse-structure/write_model.py)）にした。探索（[write_sweep.py](../agent-runs/2026-11-11-wiki-browse-structure/write_sweep.py)）は、手を入れない実行、失敗、2 つ目の失敗、短い書き込み、強制停止の 5 つで、9.1 と 9.2 の基準を、試験の側が木を読んで確かめる。結果は [results.md](../agent-runs/2026-11-11-wiki-browse-structure/results.md) にある。

- 試作が写しているもの: 書き込みの口の Wiki のルートとの重なりの確かめ（6.1）、領分（6.2）、門（6.3）、書き出しの手順（6.4）、終了コードと確定のあとの失敗（7）、記録と持ち主の確かめ（7.1）。
- 試作が写していないもの: 入れ子の書き出しの拒否（6.1）、走査と中核、待ち受けと、記録の `instance` とその口で答えるサーバーの照合（7.1）、ロックを待つ時間、2 つのプロセスの同時の実行。識別子の関数は、`win_file_id()` の代わりに `os.stat` の `st_dev` と `st_ino` を使う。
- サーバーが動いているかは、試験の側がロックのファイルを自分で取ってみて確かめる（試作の関数を使わない）。
- 探索が見つけた試作の誤りは、6.4 の 3 つである。直したあとの結果は、results.md に書く。
- 4 回目のレビューのあとで、探索に基準を 4 つ足した。手を入れない実行の約束、既定の書き出し先の前の世代を読まないこと、確定のあとの失敗の警告、ディレクトリと砂場の根の属性である。
- 5 回目のレビューのあとで、警告の基準を「どの場所でも」に広げ、正常に戻る異常の探索、`<data_dir>` がない初めの実行、番号の巻き戻りの場面（3 回の実行に 1 つずつの失敗）を足した。対照に、一覧の番号で復旧する（`recover_by_published_seq`）と、目印を書いたあとの失敗を捨てる（`swallow_marker_failure`）を足した。
- 6 版目の全量の探索で、作業用のディレクトリにジャンクションがある状態では、止まる書き出し先のほかのすべてで、警告の基準が 7 件ずつ破れた。試作は、6.2 の初めの規則（`unlink`、外せなければ `rmdir`）のとおりに、`unlink` そのものの失敗と、その前の 6.1 の確かめ（`lstat`、`realpath`、識別子）の「分からない」を、`rmdir` の試し直しで飲み込み、0 で終わっていた。失敗のないときの約束は破れていない。規則を、1 つの操作に口を 1 つとする形に直し（3.2、6.2）、初めの形を対照（`fallback_rmdir`）にした。同じ探索で、既定の書き出し先の、前の世代に読み取り専用のハードリンクがある状態だけは、破れが見つかっていなかった。手を入れない実行も「消せなかったので残す」の警告を出すので、「警告がある」が満たされていたからである。警告の基準を、手を入れない実行にない新しい警告で量る形に締め（9.2）、その状態でも対照が見つかることを確かめた。締めた基準は、`--out` の同じ状態で 3 件ずつを挙げた。2 件は、警告が、付け替える前の名前（`old-N`）と失敗の種類しか書かず、どのファイルの失敗かを区別できなかったためである。警告に、残した項目の今の名前と、失敗した口と対象を書く形に直した（6.2）。1 件は、手を入れなくても失敗する呼び出しに失敗を入れたもので、新しい失敗ではない。この場合は基準を当てず、その代わりに、手を入れない実行の側で警告を確かめる（9.2）。どちらにも対照（`coarse_warning`、消せないファイルがある状態での `silent_post_commit`）を付け、見つかることを確かめた。
- 同じ全量の探索で、Wiki のルートと重なる `--out` の 2 つの状態で、世界の差分の基準が 2 件ずつ破れた（直す前の探索でも同じだった）。どちらも、`lstat` が誤って「ない」と答える失敗を入れたときで、失敗のないときの約束は破れていない。
  - Wiki のルートの下の `--out` では、6.1 の確かめが「ない」の答えから祖先にさかのぼり、その結論を「ない」と答えた名前に覚えていた。あとの口がその覚えに乗り、Wiki のルートの下に作業用のディレクトリを作った。守ること 1 の破れである。確かめを、対象そのものを見て、祖先にさかのぼらない形に直した（3.2、6.1）。初めの形を対照（`climb_on_absent`）にした。
  - 空の Wiki のルートそのものを `--out` に指した状態では、変わったのは、ルートの隣の作業用のディレクトリ（目印とロック）と、その親の更新時刻だけだった。Wiki のルートは変わっていない。探索の基準が、失敗を入れた実行にも「砂場の全体が変わらない」を当てていて、設計（9.1 は手を入れない実行にだけ求める。作業用のディレクトリは領分である）より厳しかった。基準を 9.1 に合わせた。Wiki のルートと重なる 3 つの状態で、`no_root_guard` が見つかることを確かめてある。
- 対照のうち、`del-N` に付け替えずに消すもの（`delete_in_place`）は、初めの探索では見つからなかった。途中まで消した `old-N` が戻る候補になるのは、そのあとで書き出し先がなくなったときだけで、探索にその場面がなかったからである。強制停止のあとで、利用者が書き出し先を消してから書き出す場面を足すと、見つかった。3 版目の「知らない項目があれば使わない」規則の対照（`refuse_unknown_entries`）も、置き換えの一時ファイルを拒む形にして、見つかることを確かめた。

### 9.7 過去の重大な指摘との対応

過去 7 回の重大な指摘 17 件を、2 回目と 3 回目のレビューの照らし合わせに従って、道具に当て直した。実装の最初の段（12 の 1）で、それぞれの指摘を直す前のコードに道具を走らせ、実際に見つかることを確かめる。

| 指摘 | 道具 |
| --- | --- |
| 1-1 絶対の出力の名前で、別の書き出しを上書き | 世界の差分（砂場に別の書き出しを置く） |
| 1-2 消すときに属性を変える | 世界の差分（属性を含む）と、書き出し先の初期の状態（読み取り専用のハードリンク）。作りでも、層に属性を変える操作がない |
| 1-3 描かないページの未解決リンクが消える | lint の `broken_links` との一致 |
| 1-4 絶対パスの検査の誤り | 推定をなくす（8）。機械の情報の基準。元の分類の正しさは、確かめる対象でなくなる |
| 1-5 誤った形のオントロジーで全体が止まる | 敵対的な入力（オントロジーに `node_types: []` を置く）と、決まった期待（関係表だけが使えない） |
| 1-6 空の書き出し先で前の世代を消す | 書き出し先の初期の状態（空と、作業用の `old-N`）に失敗と 2 つ目の失敗の探索を重ねる。世界の差分 |
| 2-1 `~` の `raw:` で書き出しが失敗 | 決まった期待（手を入れない実行が成功する） |
| 2-2 解釈できない URL で応答なし | 決まった期待（そのページを要求して、500 でない応答がある）と、解釈の探索 |
| 2-3 重なりを見つけても終わらない | 「重なれば終わる」という要求が、守ること 1 の言い換えでなくなる。残る要求（領分の外は変わらない）は、変化の探索と世界の差分で確かめる |
| 3-1 組み立ての途中の終了が、入力になった記録を消す | 記録を消すことは、言い換えのあとは欠陥でない。残る要求は、割り込みの探索（組み立ての呼び出しの直前に終了を走らせる）、強制停止の探索、7 の「動いていない」 |
| 3-2 YAML の誤った日付で全体が止まる | 敵対的な入力（オントロジーとページの両方）と、決まった期待 |
| 4-1 ロックを待つあいだに入力になった記録を消す | 3-1 と同じく、言い換えのあとは欠陥でない。変化の探索（ロックを取る呼び出しの直前）と世界の差分 |
| 4-2 入力の印の失敗が 500 | 失敗の探索と、劣化の基準（500 はどの行にもない） |
| 5-1 一覧の失敗で、0 ページの正常な Wiki になる | 走査の口（`os.scandir` の開く、取り出す）での失敗の探索と、劣化の基準。対照を層の中に置く |
| 6-1 属性を読めないと、守りから外す | 守る場所という考えがなくなる。残る形（種類を調べられないものを消す）は、`os.lstat` での失敗の探索と、世界の差分 |
| 6-2 リンクの `indexes` の更新に気づかない | Wiki の配置（リンクの `indexes`）と、変化の探索（索引の編集）。変化のあとの次の実行が、新しいナビゲーションを返すこと |
| 7-1 入力でないディレクトリの失敗で止まる | 触れない場所の基準（その場所への呼び出しが 1 つもない） |

## 10. 振る舞いが変わる点

| 変わる点 | 今 | 直したあと |
| --- | --- | --- |

今の試験のうち、これらを前提にしているものは、期待を書き換える。

## 11. 限界

- 2.2 に挙げた、守る範囲の外のもの（代替データストリーム、拡張属性、アクセス制御の一覧、マウント、競合、書き換えられた一覧）。
- **Wiki のページのディレクトリからジャンクションで届く、ルートの外の場所。** `wiki/shared` が外のフォルダーへのジャンクションで、書き出し先をそのフォルダーの中に指すと、6.1 は止めない（実体がルートの下にない）。書き出したファイルは、`wiki/shared/` の下にも見える。browse は、そこに前からあるものを変えない。出力の名前は `.md` で終わらないので、ページは増えない。
- **一覧にある名前に、利用者が同じ中身のファイルを置いた場合。** browse のものとして消す。同じ中身は、書き出し直せば得られる。
- **読み取り専用にされた前の世代のファイル。** 消せないので、作業用に残り、書き出しのたびに警告が出る。消すのは利用者である。
- **空の Wiki のルートそのものを `--out` に指し、書き出し先の `lstat` が誤って「ない」と答えたとき。** 始めの確かめを抜け、ルートの隣に、目印とロックだけを持つ作業用のディレクトリを作ってから、ルートを取り除く口で止まる。Wiki のルートは変わらない。次の手を入れない実行は、始めの確かめで止まり、その作業用のディレクトリを消さない。作業用のディレクトリは領分なので、守ること 1 には反しない（ADR-0017）。
- **POSIX の名前の付け替えは、空のディレクトリを置き換える。** `os.rename` は、付け替える先に空のディレクトリがあると、それを置き換える。付け替える前に先が「ない」と確かめるが、その答えが誤っていると、空のディレクトリを置き換えうる。Windows の `os.rename` は、先があれば失敗する。探索は Windows だけで流しており、POSIX のこの場合は確かめていない。
- **トークンの警告の範囲。** `<data_dir>/browse/` の下の記録のトークンだけを探す。記録を写したファイルや、ほかの `data_dir` のサーバーのトークンは、描かれても警告しない。
- **綴りの違う 2 つの Wiki の既定の書き出し先。** `wiki_key` が同じなので、既定の書き出し先を共有し、あとから書き出したほうが置き換える。持ち主の確かめ（7.1）で、置き換えるときに警告を出す。分けたいときは、`--out` を使う。`wiki_key` の作り方は、MCP の索引なども使うので、この計画では変えない。
- **2 回の走査で見えない変化。** 2 回の走査は、名前、大きさ、更新時刻を比べる。そのあいだに中身を変えて、大きさと更新時刻を元に戻す変化は見えない。競合として範囲の外である（2.2）。
- **同梱の確かさ。** `_vendor_digest()` は、列挙を拒まれると、空の集合のハッシュを返す（3.3）。browse は、その値を使わない。
- 探索は、口の呼び出しの N 回目に手を入れる（2 つ目の失敗は、1 つ目のあとの 30 回までの呼び出しに限る）。3 つ以上の失敗が重なる場合と、2 つのスレッドが同時に動く競合は、探さない。
- 書く側の試作は、開発用の PC（Windows 11、Python 3.14.6）だけで流した。ほかの OS と版は、12 の 1 の段で、試験の道具に移してから確かめる。
- 走査の計画が約束を変えたときは、4 を書き直す。

## 12. 順序

走査の計画（0.10.1。作者が 2026年11月12日に承認した）の実装が `info-hive-wiki` の main に入ってから始める。層の口（3.1）が、走査の計画の識別子の関数（`win_file_id()`）を使うからである。

1. 試験の道具（9）を作る。口に手を入れる仕組み、世界の差分、初期の状態と敵対的な入力の一覧である。0.10.0 に対して走らせ、違反を記録する。あわせて、過去の指摘を直す前のコードで、道具が指摘を見つけることを確かめる（9.7）。ただし、要求を言い換えで取り下げた指摘（1-4、2-3、3-1、4-1）は、元の反例ではなく、残る要求のほうを確かめる。試作の探索（9.6）を、この道具に移す。
2. 層の口と、失敗の読み替え（3）をそろえる。
3. 書く側（6、7.1）を作り直し、読む側（5）から重なりの仕組みを外す。
4. 仕事の単位（7）をそろえ、描く側（8）を分ける。
5. 入力の集合（4）を、走査の計画の関数と、1 つの入力の一覧に乗り換える。
6. 1 で記録した違反が消えたことを確かめ、元の設計の該当の節を書き換える。

各段で、その段までに期待を書き換えた試験、2 方式のブラウザの試験、起動の速さ（1,000 ページで 5 秒以内）が通ることを確かめる。

info-hive-wiki は、0.11.0 から Python 3.12 以上を対象にしている（to884/info-hive-wiki#46）。標準ライブラリの失敗の読み替えは版で違う（3.1）。今の browse の CI（開発リポジトリの `wiki-browse.yml`）は 3.12 だけで流しているので、1 の段で、Linux と Windows のそれぞれで 3.14 を足す。`--out` の書き出しのたびに前の世代を読んで照らす費用（6.3）と、2 回の走査（4.2）の費用は、1,000 ページの Wiki で測る。
