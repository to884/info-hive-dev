## この変更で閉じることと、閉じないこと

- **閉じること**: 最上位の除くディレクトリ（`indexes`、`graph`、`raw`、`assets`、`.evolution`、`.wiki-cache`）の下を、ページを集めるために列挙しない。その名前の項目には、種類を調べる呼び出しもしない。その名前のディレクトリが、外の書庫へのジャンクションやシンボリックリンクであっても、大きな Raw であっても、同じである。例外は 1 つで、`compute_stats()` が `indexes` の名前の項目に `os.lstat()` を 1 回呼ぶ（「決めること」の 7）。リンクの先もその下も調べない。
- **閉じること**: ページと索引のファイルを、同じたどり方で集める。たどれなかった場所と、調べられなかった項目を、結果と一緒に返す。
- **閉じないこと**: ページのディレクトリ（除く名前でないディレクトリ）に置いたジャンクションの先は、今までどおりたどる。Windows では、`wiki/shared` を外のフォルダーへのジャンクションにすると、その下の Markdown は今もページである（「作者が決めること」の 1）。
- **閉じないこと**: ファイルのシンボリックリンクは、今までどおりページとして読む。
- **閉じないこと**: 返した知らせを、lint、stats、グラフの抽出、MCP の索引は見ない。今と同じ集合を、今と同じに使う（「作者が決めること」の 4）。
- **閉じないこと**: たどっている間に wiki が変わること。なくなったものは、ないものとして返す。変化を受けるのは、呼び出し元である。
- **約束の立て方**: 走査の結果を、木の作りから決まる答えと等しくする（「決めること」の 9 の第一の約束）。今（0.10.0）の結果との違いは、「決めること」の 7 の表のものだけにする。この約束は、確かめた OS と Python の版（「検証環境の値」）についてのものである。今の実装は、Python の版によって結果が違うことがある（3.10 の `rglob` の重複除去、`Path.is_file()` の失敗の扱い）ので、確かめていない版では、表にない違いが出うる（「作者が決めること」の 6）。

## 背景

### 今のたどり方

wiki をたどる箇所は、次のとおりである（info-hive-wiki 0.10.0、コミット `f0a758f`）。

| 箇所 | たどり方 | 使う側 |
| --- | --- | --- |
| `wiki_pages.iter_page_files()` | `wiki_root.rglob("*.[mM][dD]")` で全体を列挙し、`is_page_path()` と `Path.is_file()` で選ぶ。`wiki_text.posix_rel()` の値を鍵に並べる | lint、search（MCP の索引の更新、`wiki_decide.py`、`setup_wiki.py` もこれを使う）、グラフの抽出と lint、browse の中核 |
| `wiki_stats.compute_stats()` | `wiki.rglob("*.[mM][dD]")` で全体を列挙し、**本文を読んでから** `is_page_path()` で除く | `/wiki:stats`、MCP の `stats` |
| `wiki_index.stat_signature()` | `root.rglob("*.[mM][dD]")` で全体を列挙し、すべてに `stat()` をかける | MCP の索引の更新（`WikiIndex.refresh()`）。索引を使うツールの呼び出しのたびに走る |
| `wiki_lint.index_files()` | 最上位の `index.md` を `Path.is_file()` で確かめ、`indexes` を起点に `rglob("*.md")` で列挙する | lint の索引の検査、browse のナビゲーション |
| `wiki_index.list_index()` | `indexes` を起点に `rglob("*.md")` で列挙し、すべてを読む | MCP の `list_index` |
| `wiki_browse_core.check_enumerable()` と `signature()` | `os.walk(root)` で全体を列挙する | browse。この変更では触らない（「決めること」の 9） |

### 実測

Windows 11（Python 3.10.11、3.12.13、3.13.7、3.14.6）と Linux（WSL の Ubuntu 24.04、Python 3.12.3）で確かめた。

ページの側:

| 置いたもの | Windows（4 つの版とも同じ） | Linux |
| --- | --- | --- |
| ディレクトリのシンボリックリンク（`dlink` → 外） | `rglob` も `os.walk` も降りない | 降りない |
| ジャンクション（`junc` → 外） | **降りる**。`junc/c.md` はページになる | ジャンクションはない |
| 除く名前のジャンクション（`raw` → 外） | `rglob` は**降りて**、`raw/c.md`、`raw/deep/d.md` を列挙する。そのあと `is_page_path()` が除く | `raw` をシンボリックリンクにすると、降りない |
| ファイルのシンボリックリンク | ページになる | ページになる |
| 先のないシンボリックリンク | ページにならない | 同じ |
| 循環するジャンクション（`sub/loop` → wiki） | 3.10 は `OSError` で止まる。3.14 は同じページを 128 回、127 階層まで返す | シンボリックリンクなので降りず、循環しない |

索引の側（今の `index_files()`）:

| 置いたもの | Windows | Linux |
| --- | --- | --- |
| `indexes/Upper.MD` | 返す | **返さない**（`rglob("*.md")` が大文字と小文字を区別する） |
| `indexes/sub/dir.md`（`.md` で終わる名前のディレクトリ） | **返す**。lint は読めずに飛ばし、MCP の `list_index` は読もうとして失敗する | 同じ |

標準ライブラリの関数の内側での、失敗の扱い:

| 関数 | 確かめたこと |
| --- | --- |
| `rglob` | 権限のないディレクトリを、黙って飛ばす（3.10 は差し替えで、Linux の 3.12 は実物で確かめた）。読み取りの障害（`EIO`）と、たどる間の消失は、3.10 で送出する。3.10 は、返したパスを `Path` の比較で重複除去する（`_RecursiveWildcardSelector` の `yielded`）。Windows では、大文字と小文字を区別するフォルダーにある `a.md` と `A.md` の片方を、黙って落とす（実物で確かめた。3.12 以降は両方を返す。3.11 は確かめていない） |
| `Path.is_file()` | 権限のエラーと `EIO` を、3.12 と 3.13 は送出し、3.14 は黙って偽にする（`os.path.isfile` を呼ぶ） |
| `os.path.realpath(…, strict=True)` | Windows で、結果から `\\?\` を外せるかを確かめる内側の呼び出しの `OSError` を握りつぶし、`\\?\` 付きのパスを成功として返す（3.14.6 のソース） |
| `os.stat()` | Windows の 3.10 は、アクセスを拒まれたディレクトリ（`C:/System Volume Information`）に、`st_ino` と `st_dev` が 0 の結果を**成功として**返す。3.14 は、0 でない識別子を返す。`C:/pagefile.sys` には、どちらの版も 0 を返す |
| `DirEntry.stat()` | Windows では、`st_ino` がいつも 0 である（Python の文書にもそう書かれている） |
| `os.scandir()` を閉じる | CPython は、閉じるときの `FindClose` と `closedir` の戻り値を見ない（3.10.11 と 3.14.0 の `ScandirIterator_closedir`）。閉じるときの失敗は、外に出ない。項目を取り出すときの失敗は、送出される（同じ版の `ScandirIterator_iternext` が `path_error()` を呼ぶ） |
| `os.stat()` の識別子 | Windows の 3.12 以降は、識別子の取得（`GetFileInformationByHandleEx` の `FileIdInfo`）に失敗しても、それを捨てて続け、`st_dev` を 64 ビットではなく 32 ビットの値（`dwVolumeSerialNumber`）にする。`st_ino` は 0 にならない（3.12.13 と 3.14.6 の `win32_xstat_slow_impl`、`Python/fileutils.c` の `_Py_attribute_data_to_stat`）。同じディレクトリが、別の識別子に見えることがある。3.10 は `FileIdInfo` を使わず、いつも 32 ビットの値を返す（実物で、3.10 は `0xb6dbc26f`、3.14 は `0xeeb6dbfbb6dbc26f`） |
| `os.stat()` のブロックデバイス | Windows の `os.stat()` は、属性の取得（`GetFileInformationByHandle`、3.12 以降は `GetFileInformationByHandleEx` の `FileBasicInfo` も）がエラー 1、50、87 で失敗すると、`st_mode` を `S_IFBLK` にして、成功として返す。ボリュームや物理ディスク（`\\.\C:` など）のための分岐だが、ふつうのファイルかどうかは確かめない（3.10.11 と 3.14.6 の `win32_xstat_impl` / `win32_xstat_slow_impl`。5 回目のレビュー） |
| `pathlib` の `_ignore_error`（3.10〜3.12）、3.14 の `glob` と `os.path.isfile` | 今の実装が「ない」と読む失敗である。3.10〜3.12 は、errno の `ENOENT`、`ENOTDIR`、`EBADF`、`ELOOP` と、Windows のエラー 21（`ERROR_NOT_READY`）、123（`ERROR_INVALID_NAME`）、1921（`ERROR_CANT_RESOLVE_FILENAME`）を無視する（3.10 の一覧の名前は `_IGNORED_ERROS`）。3.14 は、どの `OSError` も無視する。自分を指すシンボリックリンクでは、`DirEntry.is_dir()` と `os.stat()` が、Linux で `ELOOP`、Windows でエラー 1921 を送出し、今の実装は、それを無視してリンクを飛ばす（実物で確かめた） |

## 崩れた前提と、原則

2 回のレビュー、browse の構造の直しからの要望（R1〜R4）、browse の設計の 3 回目のレビューの重大 4 が崩したのは、次の 4 つの前提である。反例と、そのときの対応は、[root-causes.md](../agent-runs/2026-11-11-wiki-walk-excluded-dirs/root-causes.md) にある。

| | 崩れた前提 | 3 版目の原則 |
| --- | --- | --- |
| A | 標準ライブラリの関数を 1 つ呼べば、失敗は外へそのまま出てくる | W1: 走査が OS を呼ぶ口には、内側で扱われる失敗が結果を変えないことを、CPython のソースの箇所で示せる呼び出しだけを入れる。示せない呼び出しは、口に入れない |
| B | パスの文字列で、同じものかどうか、どちらが先かを決められる | W2: 同じディレクトリかどうかは、識別子だけで決める。取れなければ「分からない」にする。並びの鍵は、今の関数をそのまま使う。今と違ってよい並びは、今の関数ごとの鍵で同じになる組の中の順だけとし、場合を数え上げて書かない |
| C | 照らす相手は、自分で書いた写しでよい | W3: 今の実装との照合は、実物を呼ぶ。探索の答えと、走査が呼ぶはずの口の呼び出しの集合は、どちらも木の作りから計算し、等しいことを確かめる。走査の動きから、答えを作らない |
| D | 別の文書が、こちらの書いたとおりに動く | W4: この文書は、この文書の関数の約束だけを書く。呼び出し元の動きを、正しさの根拠にしない。使う側に残る OS の呼び出しも、使う側の変更の表に書く |
| E | 失敗は、障害のときにだけ起きる | W5 に足す: 失敗の分け方は、今の実装が何をどう扱うかをソースから表にし、木の状態として障害なしに必ず起きる失敗（解けないリンクなど）を、障害と分けて決める |

3 版目にも、A、B、C が、案の及ばなかった箇所に残っていた（3 回目のレビュー）。口の表に「確かめていない」行を残した（A）。索引の側の今の鍵を見落とし、違ってよい並びを数え上げで書いた（B）。失敗を入れたときの答えを、走査が記録した呼び出しから作っていた（C）。分類は [root-causes.md](../agent-runs/2026-11-11-wiki-walk-excluded-dirs/root-causes.md) の最後の節にある。4 版目にも、A が口の中心の `os.stat()` の識別子の取得に、C が索引の今の集合の計算に残っていた（4 回目のレビュー）。5 版目は、識別子を取る役割を `os.stat()` から外し、自分の関数（`win_file_id()`）で取る。5 版目には、レビューの前に自分で見つけた後退があった（前提 E）。6 版目は、失敗の分け方を、今の実装の扱いの表から決め直した。

2 版目から引き継ぐ原則は、次の 2 つである。

- W5: 失敗の読み替えは、1 つの関数だけが行う。「ない」「権限がなくて分からない」「そのほか」の 3 つに分ける。権限の失敗は、どの呼び出しで起きても、必ず知らせになる。分け方は、今の実装が何をどう扱うかと並べて決め、木の状態として必ず起きる失敗を、障害として送出しない（前提 E）。
- W6: たどり方は 1 つで、起点を変えて使う。結果は、ファイルの一覧と知らせの組で返す。

## 決めること

### 1. OS を呼ぶ口（W1）

走査が呼ぶのは、次のものだけである。どれも、呼ぶたびに `os` のモジュールから引いて呼ぶ。表の 3 列目は、その呼び出しの内側で扱われる失敗と、それが結果を変えない理由である（W1）。W1 が見るのは CPython の内側までである。`win_file_id()` が呼ぶ Win32 の API の内側と、たどる間に木が変わることは、W1 の対象の外である。

| 口 | 何のために呼ぶか | 内側での失敗の扱い |
| --- | --- | --- |
| `os.scandir()`（開く、項目を 1 つ取り出す、閉じる） | ディレクトリの一覧 | 開くときと、取り出すときの失敗は、`OSError` で外に出る（`ScandirIterator_iternext` が `path_error()` を呼ぶ）。閉じるときの失敗は、CPython が捨てる（`ScandirIterator_closedir` が戻り値を見ない）。走査は、閉じる前に項目を最後まで取り出すので、閉じるときの失敗は結果を変えない |
| 項目の `is_symlink()` | シンボリックリンクか | Windows は、一覧の情報（`win32_lstat`）から答え、OS を呼ばない。POSIX は `d_type` から答え、`DT_UNKNOWN` のときだけ `DirEntry_test_mode` で `lstat` する。そこでは `FileNotFoundError` を偽に読み替え、ほかの失敗は送出する（3.10.11 と 3.14.0 の `os_DirEntry_is_symlink_impl`、`DirEntry_test_mode`）。偽は、「ない」と同じ向きである（項目は、ファイルかどうかを調べる `os.stat()` で、ないものとして落ちる） |
| 項目の `is_dir()` | ディレクトリか（リンクの先で判定する） | `DirEntry_test_mode`。Windows はシンボリックリンクのときだけ、POSIX は `d_type` が `DT_UNKNOWN` かシンボリックリンクのときだけ `stat` する。`FileNotFoundError` を偽に読み替え、ほかの失敗は送出する（同じ箇所）。偽は、「ない」と同じ向きである |
| 項目の `stat(follow_symlinks=False)` | Windows で、ジャンクションかどうかを、属性とタグから見分ける | Windows では、一覧の情報（`win32_lstat`）を返し、OS を呼ばない（`DirEntry_get_lstat`）。読み替える失敗はない。POSIX では呼ばない |
| `os.stat()` | `.md` の項目がファイルかどうかと、その大きさと更新時刻。識別子には使わない | Windows では、ファイルを開けないとき（`ERROR_ACCESS_DENIED`、`ERROR_SHARING_VIOLATION` など）に、ディレクトリの一覧の情報（`attributes_from_dir`、`FindFirstFileW`）で、成功として答える。そのとき `st_ino` は 0 である（3.10.11 と 3.14.0 の `win32_xstat_impl`）。3.12 以降は、識別子の取得（`FileIdInfo`）の失敗も捨てる（背景の表）。この役割では識別子を使わない。開けないときの読み替えは、結果を「ファイルである」の向きにしか変えず、その向きは、ファイルとして返すと決めている（2 の表。「作者が決めること」の 5）。もう 1 つ、属性の取得がエラー 1、50、87 で失敗すると、`st_mode` を `S_IFBLK` にして成功として返す（背景の表。5 回目のレビュー）。一覧に載る項目がボリュームや物理ディスクであることはないので、Windows で `S_IFBLK` が返ったら「分からない」にする（2 の表）。これで、どの読み替えも、結果を変えないか、知らせになる。POSIX では読み替えない |
| `wiki_pages.win_file_id()`（Windows だけ） | ディレクトリの識別子（`VolumeSerialNumber` と `FileId`） | この計画で書く関数である。`ctypes` で `CreateFileW`（`FILE_READ_ATTRIBUTES`、`FILE_FLAG_BACKUP_SEMANTICS`）、`GetFileInformationByHandleEx(FileIdInfo)`、`CloseHandle` を呼び、どの失敗も読み替えずに `OSError` で送出する。ないパスは `FileNotFoundError`、拒まれたパスは `PermissionError` になる（`OSError` の第 4 引数に Windows のエラーの番号を渡すと、Python が分ける）。ファイルシステムが `FileIdInfo` を返さないとき（エラーの番号 1、50、87）は、`NoFileId`（`OSError` の子）を送出する。リンクの先をたどる。ジャンクションは Windows にしかないので、POSIX では呼ばない |

- `os.path.realpath()`、`os.path.samefile()`、`os.path.isfile()`、`os.walk()`、`Path` の入出力（`is_file()`、`is_dir()`、`rglob()`、`stat()`、`resolve()`）は、使わない。内側でいくつもの呼び出しをして、失敗を自分で扱うからである。ディレクトリの識別子を取るために `os.stat()` を使うこともしない（1 の表の `os.stat()` の行）。
- パスの文字列を作る操作（`os.path.join`）は、OS を呼ばないので使う。パスの文字列を比べて、同じ場所かどうかを決めることは、どこでもしない。
- **走査は、起点の下のパスだけを口に渡す。** 起点の親をさかのぼらない。
- browse の入出力の層が決めた口（browse の設計の 2）の一部である。

### 2. 失敗の読み替え（W5）

読み替えは、`wiki_pages.py` の 1 つの関数だけが行う。走査のほかの箇所は、`OSError` を受けない。

| 失敗 | 読み方 | 走査の動き | 今の実装（3.10〜3.12 / 3.14） |
| --- | --- | --- | --- |
| `FileNotFoundError`、`NotADirectoryError` | ない | その項目やディレクトリを、ないものとして続ける。知らせは出さない | 無視する / 無視する |
| 解けないリンク（errno の `ELOOP`、Windows のエラー 1921）、正しくない名前（Windows のエラー 123） | ない | 同じ。先のないリンクと同じく、ページにならない | 無視する / 無視する |
| `PermissionError`、`NoFileId`（識別子を返さないファイルシステム）、`FileId` がすべて 0 の `win_file_id()` | 分からない | 知らせに入れて、ほかを続ける | 権限は無視しない（3.10〜3.12 の `rglob` の一覧は黙って飛ばし、`Path.is_file()` は送出する） / 無視する |
| `EBADF`、準備のできていないドライブ（Windows のエラー 21） | 分からない | 同じ | 無視する / 無視する |
| Windows で、`.md` の項目と最上位の `index.md` への `os.stat()` が返した `S_IFBLK` の成功 | 分からない | 同じ | ブロックデバイスとして、ページにしない / 同じ |
| そのほかの `OSError`（読み取りの障害など） | 送出する | 走査の全体が失敗する。結果を返さない | 送出する / 無視する |

呼び出しごとの当てはめは、次のとおりである。

| 呼び出し | ない | 分からない |
| --- | --- | --- |
| 起点のディレクトリの一覧（開く、取り出す） | 空の結果（索引で、`indexes` がない、またはファイルである場合を含む） | 起点を `unlistable` に入れる |
| 途中のディレクトリの一覧 | そのディレクトリの下を飛ばす | そのディレクトリを `unlistable` に入れ、下を飛ばす |
| 項目の `is_symlink()`、`is_dir()`、`stat()` | その項目を飛ばす | その項目を `unknown` に入れる。降りず、ファイルにもしない |
| `.md` の項目の `os.stat()` | ファイルでない（先のないリンク） | その項目を `unknown` に入れる。Windows で、開けないファイルに識別子が 0 の成功が返ったときは、「分からない」にせず、ファイルとして返す（1 の表。「作者が決めること」の 5） |
| 識別子を取る `win_file_id()`（5） | 調べていた項目に降りない | 調べていた項目を `unknown` に入れ、降りない |

- 一覧の途中で失敗したときは、そこまでに取り出せた項目も使わず、そのディレクトリの全体を、たどれなかったものとして扱う。
- 解けないリンクと正しくない名前を「ない」にするのは、障害ではなく、木の状態として、障害なしに必ず起きるからである。自分を指すシンボリックリンクが 1 つあるだけで、`DirEntry.is_dir()` と `os.stat()` が送出する。今の実装も、ページにしない。5 版目は、これを「そのほか」として送出し、輪になったリンクが 1 つあるだけで lint、search、MCP の索引を止めていた。
- 準備のできていないドライブと `EBADF` を「分からない」にするのは、中身があるかどうかが分からないからである。今の実装は「ない」にしている（7 の違いの表）。
- 権限のない場所を飛ばして続けるのは、今の lint と search が、権限のないディレクトリがあっても止まらないからである。違いは、黙らずに知らせに入れることである。
- そのほかの `OSError` を送出するのは、障害でたどれなかったページを「なくなったページ」と区別するためである。MCP の索引は、集合にないページの行を消す（`WikiIndex.refresh()`）。飛ばすと、障害が索引の削除に変わる（「作者が決めること」の 2）。
- 3.12 と 3.13 では、権限のない `.md` の項目があると、今は `Path.is_file()` が送出し、lint が止まる。変更のあとは、どの版でも、その項目を `unknown` に入れて続ける。

### 3. たどる関数（W6）

`skills/info-hive/scripts/wiki_pages.py` に置く。標準ライブラリだけを使う。

```python
class MdFile(NamedTuple):
    rel: str        # wiki のルートからの相対パス（/ 区切り、ディスク上の綴り）
    size: int
    mtime_ns: int

class Walk(NamedTuple):
    files: list[MdFile]    # 名前が .md で終わる、ふつうのファイル（リンクの先がファイルのものを含む）
    unlistable: list[str]  # 一覧を作れなかったディレクトリ
    unknown: list[str]     # 種類か、同じ場所を回っていないかを、調べられなかった項目

def walk_markdown(start: Path, prefix: str = "", skip_top: bool = False) -> Walk: ...
```

- `os.scandir()` で、明示のスタックを使ってたどる（再帰しない）。
- **起点には、リンクであっても降りる。** 今の `index_files()` が `indexes` を起点に `rglob` するのと同じである。
- **`skip_top` が真のとき、起点の直下の除く名前の項目には、どの呼び出しもしない。** 名前が `SKIP_TOP_LEVEL_DIRS` に入っている項目を、種類を調べずに飛ばす。名前は、`is_page_path()` と同じく、ディスク上の綴りをそのまま比べる（`Raw/` は除かない。2 階層目より下の `raw` も除かない）。除く名前はどれも `.md` で終わらないので、ファイルであっても、飛ばして結果は変わらない。
- **途中のリンクの扱いは、今と同じにする。** ディレクトリのシンボリックリンクには降りない。ジャンクションには降りる。ディレクトリかどうかは、リンクの先で判定する。
- **同じ場所を回る道筋には降りない**（5）。
- **ファイルかどうかは、`os.stat()` で調べる。** 名前が `.md` で終わり（大文字と小文字を問わない）、ディレクトリでない項目に `os.stat()` をかけ、ふつうのファイル（`S_ISREG`）なら `files` に入れる。大きさと更新時刻は、そのときの値を一緒に返す。項目の `stat()` の値は使わない。Windows では、ディレクトリの一覧が持つ値が、ファイルの今の値より古いことがあるからである。ただし、Windows で開けないファイルには、`os.stat()` 自身が一覧の情報で答える（1 の表）。そのファイルの大きさと更新時刻は、古いことがある。
- `.md` で終わる名前のディレクトリは、`files` に入れない。中には降りる（今も `dir.md/in.md` はページである）。
- `prefix` は、返す相対パスの先頭に付ける。索引では `indexes/` を付ける。
- 1 回の呼び出しは、1 つの起点だけをたどる。起点のあいだで、通った場所の記録を共有しない。

### 5. 同じ場所を回る道筋（W2）

今は壊れている場合なので、直す。

- 同じディレクトリかどうかは、`win_file_id()` が返す `VolumeSerialNumber` と `FileId` の組（識別子）だけで決める。パスを解くこと（`realpath()`）も、パスの文字列を比べることも、しない。
- 規則は 1 つである。**ジャンクションを 1 つでも通った道筋では、入ろうとするディレクトリの識別子が、起点からそこまでに通ったディレクトリのどれかと同じなら、降りない。**
- 識別子を取るのは、ジャンクションに出会ってからである。まだジャンクションを通っていない道筋でジャンクションに出会ったら、**そのジャンクションのためだけに**、起点からそこまでのディレクトリ（走査が通ってきたパスそのもの）に `win_file_id()` をかける。取った識別子は、そのジャンクションの下の道筋だけで使い、同じディレクトリの兄弟の項目には引き継がない。兄弟に別のジャンクションがあれば、そのために取り直す。ジャンクションより下では、入ろうとするディレクトリごとに `win_file_id()` をかける。
- ジャンクションを通らない道筋の項目には、識別子を取る呼び出しを 1 度もしない。ジャンクションのない wiki では、識別子を 1 度も取らない。ジャンクションのない OS では、この節の全体が働かない。
- ジャンクションを通るまでは、識別子を比べなくてよい。リンクを通らずに降りるだけでは、同じディレクトリに戻れないからである。
- **識別子が分からないときは、降りない。** 入ろうとするディレクトリか、道筋のどれかのディレクトリの識別子を取れなかったとき（権限のエラー、識別子を返さないファイルシステム、`FileId` がすべて 0）は、調べていた項目を `unknown` に入れ、降りない。「ない」のときは、知らせずに、降りない。
- ジャンクションかどうかは、Windows で、項目の `stat(follow_symlinks=False)` の `st_file_attributes` に `FILE_ATTRIBUTE_REPARSE_POINT` があり、`st_reparse_tag` が `IO_REPARSE_TAG_MOUNT_POINT` であることで見分ける（`DirEntry.is_junction()` は 3.12 からなので使わない）。
- 輪でないジャンクション（下を指す `a/j` → `a/b`、別名の `alias` → `a`、外を指すもの）には、今までどおり降りる。同じファイルが 2 つのパスでページになるのも、今と同じである。

結果は、次のとおりである。

| 置いたもの | 今 | 変更のあと |
| --- | --- | --- |
| `sub/loop` → wiki | 例外（3.10）か、128 ページ（3.14） | `a.md` と `sub/b.md` の 2 ページ |
| `a/b/j` → `a`、`a/me` → `a` | 同じく壊れる | どちらにも降りない |
| `x/j1` → 外、外の `j2` → `x` | 同じく壊れる | `j1` には降り、`j2` には降りない |
| `up` → wiki の親 | 同じく壊れる | `up` には降りる。その中の wiki には降りない。親のほかの中身（`up/side/s.md`）は、ページになる |
| 先のファイルシステムが識別子を返さないジャンクション | 降りる | **降りない。** `unknown` に入る |

下の 2 行は、作者が 2026年11月11日に受け入れた代償である。文字列の比較への逃げ道を残さないことと、引き換えにした。

### 6. 並び（W2）

- `files`、`unlistable`、`unknown` は、今の `iter_page_files()` と同じ `wiki_text.posix_rel()` の戻り値を鍵に並べ、鍵が同じになる名前は、ディスク上の綴りの順にする。鍵の作り方を、この文書で言い直さない。
- `index_files()` は、今と同じく、`index.md` のあとに `indexes` の下を `Path` の順に並べる。`Path` の並べ替えは、今と同じく安定である。
- **今と並びが違ってよいのは、今の関数の並びの鍵で同じになる名前の組の中の順だけである。** 今は、その組の中の順が列挙の順で決まり、環境によって違う。変更のあとは、決まった順になる。今の鍵は、`iter_page_files()` では `posix_rel()` の値、`index_files()` では `Path` の比較である。
- この規則に当たる組には、たとえば次のものがある。これは例で、規則を言い換えたものではない。
  - `posix_rel()` で同じになる組: NFC にすると同じになる 2 つの名前（どの OS でも置ける。Windows の NTFS も名前を正規化しない）、`\` と `/` だけが違う名前（Linux と macOS）。
  - `Path` の比較で同じになる組: Windows で、大文字と小文字だけが違う 2 つの名前（大文字と小文字を区別するフォルダーに置ける）。
- 鍵が同じになるページは、今も、search と MCP の索引で同じ `rel_path` になり、あとから来たほうが残る。変更のあとは、どちらが残るかが、列挙の順ではなく、綴りの順で決まる。

### 8. MCP の索引の印

`stat_signature()` は、wiki の Markdown のパス、大きさ、更新時刻から印を作り、前の印と同じなら、ページを読み直さない。

- 変更のあとは、除くディレクトリの下の Markdown と、`.md` で終わる名前のディレクトリが、印に入らなくなる。
- それでよい理由は 3 つある。印が守るのは、ページの読み直し（`wiki_search.collect_pages()`）だけである。`list_index`、`lint`、`graph` のツールは、印を使わずに、呼ばれるたびにファイルを読む。印はメモリの中にしか持たない（`WikiIndex._signature`）ので、値が変わっても移行は要らない。
- 印を作る走査と、そのあとの `collect_pages()` の走査は、今と同じく、別の 2 回の走査である。
- 走査が送出すると、`refresh()` は、索引の行を消さずに失敗する。ただし、前の書き込みが途中で失敗していたとき（`needs_reconcile` が真）は、台帳と索引を合わせる処理（`reconcile()`）が、今と同じく走査の前に走り、索引を変える。権限がなくて飛ばしたディレクトリの下のページは、今と同じく、集合から外れ、索引の行が消える（「作者が決めること」の 4）。

### 9. 呼び出し元との約束（W4）

この計画の関数が約束するのは、次のことである。

- **第一の約束**: 失敗のないとき、`files` と並びは、wiki の木の作りから決まる答え（3〜6 の規則を、木に当てたもの）と等しい。知らせは空である。
- 第二の約束: 確かめた OS と Python の版では、`files` は、今の `iter_page_files()` と `index_files()` と、7 の表の違いだけが違う。確かめていない版では、今の実装の側が版によって違うので、表にない違いが出うる。
- 走査が結果を返したとき、`unlistable` と `unknown` がどちらも空なら、たどっている間に変わらなかったものは、欠けていない。空でなければ、その場所の下が欠けている。
- 走査が送出したとき、結果はない。
- たどっている間に wiki が変わると、結果は、変わる前とも変わったあとも違うことがある。なくなったものは、知らせなしに欠ける。これを受けるのは、呼び出し元である。

browse との関係は、次のとおりである。

- この変更では、browse のコード（`wiki_browse*.py`）に触らない。browse の構造の直しが、あとの版で、この計画の関数に乗る。browse の `list_inputs()` は、`iter_page_files()` と `index_files()` を呼んでいるので、この変更で、名前を変えずに新しい走査に替わる。
- browse の構造の直しからの要望（R1〜R4）は、すべて入れてある。R1 は 3 と 4、R2 は 4、R3 は 2 と 3、R4 は 1 である。
- 関数と型の名前（`walk_pages`、`walk_index_files`、`Walk(files, unlistable, unknown)`、`MdFile(rel, size, mtime_ns)`）は、browse の設計の 3 が写す。変えるときは、browse の側に伝える。
- 知らせと送出を browse がどう扱うか、たどっている間の変化を browse がどう受けるかは、browse の設計書が決める。この文書は、それを根拠にしない。

### 11. 限界

止める条件（「レビューの進め方」）により、次のものは直さずに、限界として残す。

## 試験（W3）

`tests/wiki/` に置く。リンクを作れない環境では、その木を飛ばす。

### 木と、木から計算する答え

- 試験は、木を表（どのディレクトリに、どのファイルとリンクがあるか）で持ち、表からディスクの上に作る。
- 表から、失敗のないときの答え（`.md` のファイルの相対パスと並び）を計算する関数を、走査のコードを使わずに書く。走査の結果が、この答えと**等しい**ことを確かめる。知らせは空である。
- 木は、「実測」の 2 つの表の行のすべてと、次のものを置く。NFD の名前、`.` で始まる名前とディレクトリ、大文字の拡張子、`.md` で終わる名前のディレクトリ、`Raw/` と `concepts/raw/`、`indexes` がファイル、`indexes` がない、空の wiki、輪でない 3 つの形（別名、下を指す、外を指す）、`indexes` がページのディレクトリを指す場合、同じ場所を回る 5 つの形（5 の表の上の 4 行と、`indexes` → wiki）、名前に `\` を含むファイル、鍵が同じになる名前の組（`posix_rel()` で同じになる組と、Windows で `Path` の比較で同じになる組）、ジャンクションと通常のディレクトリが兄弟の木。解けないリンク（自分を指すファイルとディレクトリのリンク、互いに指し合うリンク。ページの側と索引の側）の木。索引の下に、ふつうのファイルでない項目（先のないリンク、ディレクトリへのリンク、`.md` で終わる名前のディレクトリ、FIFO）を置いた木。大文字と小文字を区別するフォルダーは、Windows で `fsutil file setCaseSensitiveInfo` が使えるときに作る。FIFO は、Linux と macOS で作る。

### 今の実装との照合

- 今の実装は、写さない。`info-hive-wiki` の 0.10.0 の `wiki_pages.py` と `wiki_lint.py` を、そのコミットから取り出して読み込み、`iter_page_files()` と `index_files()` を呼ぶ。
- 上の木のうち、同じ場所を回る形を除いたものと、今ある試験用の wiki（`eval/` の下の wiki）で、新しい関数の結果が、今の関数の並びの鍵で同じになる組の中の順と、7 の違いを除いて、今と同じであることを確かめる。並びは、集合が同じで、各位置の今の鍵が同じであることで比べる。今の関数の集合も、今の関数の規則（`iter_page_files()` は `rglob("*.[mM][dD]")` と `is_page_path()` と `Path.is_file()`、`index_files()` は `index.md` と、`indexes` を起点に `rglob("*.md")` が返す名前のすべて）で、木の表から直接計算する。新しい集合から違いを戻して作らない。Windows、macOS、Linux の CI で流す。
- lint、search、グラフの抽出の今ある試験が通る。

### 探索（失敗の注入）

- 口（1 の表）を差し替えて、呼び出しを数える。一覧は、開くと、項目を 1 つ取り出すを、別々に数える。閉じるときは数えない（閉じるときの失敗は、CPython が捨てる。1 の表）。
- **走査が呼ぶはずの口の呼び出しの集合と、それぞれの役割を、木の表から計算する。** 役割は、ディレクトリの一覧、項目の種類、`.md` の項目がファイルかどうか、ディレクトリの識別子、ジャンクションのための道筋の識別子の 5 つである（識別子の 2 つは `win_file_id()` の呼び出し）。失敗を入れずに 1 回流し、走査の呼び出しの集合が、計算した集合と**等しい**ことを確かめる。余分な呼び出しも、足りない呼び出しも、違反である。失敗のない実行が送出したら、それも違反である。
- そのうえで、N 個の呼び出しのそれぞれに、2 の表の行から取った失敗（ない、解けないリンク、権限がない、`EBADF`、`EIO`。Windows では、正しくない名前と、準備のできていないドライブと、`os.stat()` が返す `S_IFBLK` の成功も。最後のものは、`os.stat()` の呼び出しにだけ入れる）を 1 つずつ入れて流し直す。失敗を入れたときの答え（ファイル、`unlistable`、`unknown`）は、失敗のないときの答えと、失敗を入れた呼び出しの役割から計算する。走査が実際にした呼び出しや、走査の内部の状態から、答えを作らない。走査の記録は、どの呼び出しに失敗を入れたかを知るためにだけ使う。
  - `EIO`: 走査は `EIO` を送出する。
  - 一覧の役割: そのディレクトリの下のファイルが、答えから消える。権限なら、`unlistable` にそのディレクトリが入る。
  - 項目の種類、ファイルかどうか、ディレクトリの識別子の役割: その項目と、その下のファイルが消える。権限なら、`unknown` にその項目が入る。
  - 道筋の識別子の役割: その識別子を使うジャンクションと、その下のファイルが消える。権限なら、`unknown` にそのジャンクションが入る。1 つの呼び出しが、いくつかのジャンクションの道筋に共通するときは、そのどれか 1 つだけが消えることを答えとする。
  - 「ない」のときは、同じものが消え、知らせは出ない。
  - 解けないリンクと正しくない名前は「ない」と、`EBADF` と準備のできていないドライブと `S_IFBLK` の成功は「権限がない」と、同じ答えになる。
- 走査の結果が、答えと**等しい**ことを確かめる。「一部であること」では確かめない。
- `walk_pages()` と `walk_index_files()` の両方に、上の木のそれぞれでかける。
- 差し替えは、走査が wiki の外のパスを口に渡したら、その場で失敗にする。
- 識別子を取れない場合を、別に確かめる。`win_file_id()` を差し替えて、決めた場所で `FileId` を 0 にする場合と、`NoFileId` を送出する場合を作る。ジャンクションの先、起点、道筋の途中のそれぞれで、調べていた項目が `unknown` に入り、降りないことを見る。ジャンクションでない兄弟のディレクトリには、`win_file_id()` を呼ばないことを見る。`.md` の項目への `os.stat()` が識別子 0 の成功を返したとき、ファイルとして返すことを見る。
- **対照**: わざと決まりを破った実装を置き、探索がどれも見つけることを確かめる。どの失敗も「ない」にする実装。権限のない場所を知らせずに飛ばす実装。知らせがあったら、知らせを 1 つにして全ページを捨てる実装。識別子を取れないときに、パスの文字列で比べる実装（Windows）。道筋の識別子を兄弟に引き継ぐ実装（3 版目の試作。Windows）。識別子を `os.stat()` から取る実装（4 版目の試作。Windows）。解けないリンクで送出する実装（5 版目の試作）。`S_IFBLK` の成功で、ページを知らせなしに落とす実装（6 版目の試作。Windows）。並びの鍵を NFC だけにする実装（Linux、macOS）。
- **口の一覧の確かめ**: `wiki_pages.py` の走査の関数の構文木をたどり、口の一覧にない入出力の呼び出しと、読み替えの関数のほかの `except OSError` がないことを確かめる。違反を 1 つ埋めた写しで、この試験が失敗することも確かめる。

### 除くディレクトリに触れないこと

- 口を差し替えて、呼ばれたパスを記録する。除く名前の項目（ふつうのディレクトリ、ジャンクション、シンボリックリンク、ファイルのそれぞれ）とその下に対して、`walk_pages()`、`compute_stats()`、`stat_signature()` が、口のどれも呼ばないことを確かめる。`compute_stats()` が、その下のファイルを読まないことも確かめる。`compute_stats()` が除く名前に呼んでよいのは、`indexes` の名前の項目への `os.lstat()` 1 回だけである。

### 使う側

- `compute_stats()` の結果が、同点のない試験用の wiki で、変更の前と後で同じである。同点のある wiki で、`os.scandir` の返す順序を逆にしても、`most_linked`、`pages_by_type`、`pages_by_dir` の並びが同じである。
- `stat_signature()` が、ページを足す、変える、消すと変わる。拡張子が `.MD` のページでも変わる（今ある試験）。`raw/` の下の Markdown を変えても変わらない。
- 索引を作ったあとで `os.scandir` が `EIO` を出すようにし、`WikiIndex.refresh()` が失敗して、索引の行が 1 つも消えないことを確かめる。
- MCP の `list_index` が、`indexes` の下に `.md` で終わる名前のディレクトリがあっても、ほかのファイルを返す。
- `indexes` がディレクトリのシンボリックリンクのとき、`walk_index_files()` の `files` の大きさと更新時刻が、先のファイルを変えると変わる。

試作と本文の違いは、次のとおりである。

- 試作の `iter_page_files()` と `index_files()` は、`Path` ではなく相対パスの文字列を返す。
- 試作は、今の実装を、決まったコミットから取り出さずに、作業フォルダーのサブモジュール（コミット `f0a758f`、変更なし）から読み込んでいる。
- 試作には、口の一覧を構文木で確かめる試験と、「使う側」の試験（`compute_stats()` の `os.lstat()` を含む）がない。
- 探索と識別子の確かめは、`win_file_id()` そのものを差し替えて、失敗、`NoFileId`、`FileId` が 0 の結果を返させる。`win_file_id()` の中の `CreateFileW`、`GetFileInformationByHandleEx`、`CloseHandle` には、失敗を入れていない。中のエラーの読み替えは、`file_id_probe.py` で、ないパスと拒まれるパスについて、実物で確かめただけである（5 回目のレビューの軽微）。

確かめていないことは、次のとおりである。

- macOS。
- Python 3.11。3.10 の `rglob` の重複除去が、3.11 にもあるか。
- 2 つ以上の失敗が同時に起きる場合。探索が入れる失敗は、1 回の実行に 1 つである。
- 識別子（`FileIdInfo`）を返さないファイルシステムの実物（FAT32、exFAT、古いネットワークのドライブなど）。差し替えで確かめただけである。
- 準備のできていないドライブ（エラー 21）の実物。差し替えで確かめただけである。
- Windows で、本当に開けない `.md` のファイル（アクセス拒否のファイル、ほかのプログラムが排他で開いているファイル）を置いた木。識別子を 0 にする差し替えで確かめただけである。
- 長いパスが無効な Windows（`LongPathsEnabled` が 0）。設定を変える必要があるので確かめていない。無効なときに、今の実装と同じく、長いパスのページが知らせなしに「ない」になるかもしれない。
- 大きい wiki（1,000 ページ以上）での速さ。ジャンクションのない wiki では、今の `iter_page_files()` と同じく、ページの候補ごとに `stat` を 1 回呼ぶ。
