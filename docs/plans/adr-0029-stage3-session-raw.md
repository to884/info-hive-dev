# ADR-0029 段階3の最初の実装

[ADR-0029](../adr/0029-wiki-and-raw-hold-no-links.md) の書き込みの部品を用意し、セッション取り込みを lint までつなぐ。

1. `wiki_fsguard.py` は設定された根と行き先を受け、根の下を上から検査する。既存の要素を `lstat` で調べ、リンク、リパースポイント、ハードリンク、検出できるマウントや識別子の輪、用途と型の不一致を拒む。根と祖先の別名は共通部品では許す。セッションの raw は従来どおり根と祖先のリンクを拒み、wiki との包含も拒む。ディレクトリは一段ずつ作って確かめる。一時ファイルは排他作成し、公開前に道と名前を再検査し、置き換えは名前で行う。排他公開は Windows の rename と POSIX の link・一時名の削除を使う。検査と変更のあいだの任意の同時置換を完全に防ぐ保証はない。
2. 保存先の検査と既存の原本・スラッグの照合を済ませ、`W/.wiki-cache/raw-roots.d/<乱数>.json` に根を一件、同じ共通部品で排他公開してから raw を保存する。設定時の綴り、解決した絶対パス、書き手、UTC の時刻を持つ。根の記録の失敗は保存失敗とし、既存の同一 raw に対しても記録が成功してから先に進む。記録後に中断した場合は記録を残す。競合時に raw は上書きしない。根の記録は検索キャッシュの掃除でも保管する。ローカルの絶対パスを持つため、Git の既定の除外は維持する。
3. `write` の成功時には、保存したバイト列を表す `raw_sha256` を返す。取り込み手順はこの値を source ページの同名のキーに写す。書いたあとに共通の raw 解決で参照を確かめてから、書き込み検査を通して読み取り専用にする。
4. lint は、候補を含む現在の raw の根を指定されていれば、そこから調べる。それ以外では、wiki の根と過去の根のうち候補を含むものを使い、別の過去の根を記録しても検査範囲が狭まらないようにする。記録の場所とファイルはリンクを通さずに読み、検査不能、壊れた記録、別の OS のパスは `links_unchecked` に出す。固定した過去の根の綴りを検査の起点に使うため、アクセス不能な過去の根が他の原本の検査を妨げない。CLI と MCP は共通の lint を呼ぶ。

記録は候補の経路を調べる起点に使う。保存時の wiki の別名を指定せず、その別名の親を基準にした相対参照を解く場合は、保存時と同じ候補を取り戻せないことがある。記録がない原本は、従来どおり調べられなかった経路を lint で知らせる。

保存、根の記録の失敗時の停止、記録後の中断からの再試行、並行保存、版の照合、現在とは別の根の途中のリンクの検出を試験する。ほかの書き手の移行、upgrade からの記録の追加、ADR-0023 の管理領域と Writer の接続は後続作業とする。
