# ADR-0029 段階3の MCP 起動ファイルの保護

[実装計画](wiki-links-2026-11-16.md) と [ADR-0029](../adr/0029-wiki-and-raw-hold-no-links.md) の I6 を、MCP の起動ファイルに適用する。利用者が設定した `INFO_HIVE_DATA_DIR` を根とし、根と祖先のリンクを許す。相対指定は中継で絶対化し、サーバーが作業ディレクトリを変えても同じ根を使う。

- 中継は `WriteGuard.hold_lock` で `server.lock` を取得し、稼働中のサーバーの確認、旧版の停止、残った記録の削除、新サーバーの待ち受け確認まで保持する。従来と同じタイムアウトを使う。Windows は旧版と同じ先頭 1 バイトを固定し、ハンドルを開いている間は削除を共有しない。POSIX は旧版と同じ `flock` を取る。ファイルは残し、ロックを明示的に解放してからハンドルを閉じる。
- `server.json` は、経路を検査し末端のリンクを追わずに開く。開いたハンドルの属性とファイルの実体を照合してから読む。ファイルの欠損や不正な JSON は従来どおり再起動できる。リンク、型の不一致、読み取り不能は理由を返し、記録を読んだりサーバーを起動したりしない。
- 公開は `WriteGuard.write_bytes` を通す。一時ファイルはランダムな名前で排他作成し、POSIX では作成時から `0o600` とする。古い PID で決まる一時名には触れない。置き換え前に両方の名前を検査し、失敗後は作成した一時ファイルだけを共通部品で片付ける。Windows のファイル権限は従来と同じくデータの場所から継承する。
- `server-info.lock` で記録の読み取り、公開と削除を短時間だけ直列化する。終了したサーバーは PID とトークンが自身と一致するときだけ `WriteGuard.remove_file` で消す。中継は再利用と停止の前に、プロセスの PID、起動時刻、コマンドライン、プロセスの環境から求めたデータの根を照合する。帰属や停止を確認できなければ記録を残して利用者に伝える。次の起動の前に、読んだ記録が別の有効なレコードに入れ替わっていないことを確かめてから、残った記録を消す。旧サーバーの停止や新サーバーの起動を待つ間は記録のロックを保持しない。
- 強制終了で残った記録の PID を別のプログラムが使う場合は、実行内容がサーバーと異なり、記録のポートが接続を拒むことを確かめてから、起動時の記録を片付ける。実行ファイルのパスへのアクセスを拒まれても、取得できるプロセス名から Python 以外だと確かめられれば同じ扱いにする。実行内容や待ち受けを確かめられない場合は記録を残し、停止済みと確認した場合の復旧手順を伝える。
- 中継は起動試行の識別子を `server-start.json` に書いて子に渡す。子は記録のロックの中で現在の識別子を照合してから公開する。中継は成功時も失敗時も自身の試行の識別子を消す。先の中継が強制終了した場合、次の起動試行が新しい識別子を置く。従来の接続情報に `start_id` を追加し、再利用と停止ではプロセスの環境と照合する。識別子がない旧記録の時刻が逆転していれば、記録を保持して理由を返す。
- サーバースクリプトの直接起動は、記録も起動の予約もないときにだけ公開できる。中継による失効と直接起動の公開の可否は、同じ記録用ロックで処理する。Python に渡した相対スクリプト名はサーバーの作業ディレクトリを基準にする。別の場所にインストールされた旧版の記録は、記録の待ち受けをそのプロセスが所有していることも確認する。
- `logs/`、`server.log` と `launch.log` も共通部品を通す。中継で検出した拒否は、場所と理由を MCP のエラーおよび標準エラーへ返す。子プロセスだけで起きた公開・終了時の失敗は `logs/server.log` に理由を残し、子プロセスの起動に失敗した場合は中継からそのログを案内する。終了時に記録の拒否が続いていれば、次の接続確認でも理由を知らせる。理由にトークンを含めない。終了時は索引を閉じてから記録を片付ける。
- 通常起動、並行起動、再利用、旧版からの再起動、アイドル終了を検証する。リンクを置いた各名前を拒否した際の理由と原本の保全を検証する。停止できない旧サーバーの記録と、時間切れ後に後続が公開した記録の保全、公開と終了の直列化、一時ファイルの権限、置き換え失敗時の片付けも確かめる。

同じデータの場所で旧版から切り替えるときは、旧版の中継と起動待ちでまだ記録を公開していない旧版の子が終了していることを前提とする。公開済みの旧サーバーは、新版の中継が帰属と停止を確認して切り替える。Windows で旧版によるロック名の削除と新版のロックファイルのオープンが重なると、共有違反などを利用者に知らせる。
