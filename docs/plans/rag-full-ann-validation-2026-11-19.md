# 全量 OCR 後の ANN の自動保守と再開の検証

2026年11月19日開始。
rag の固定コミット `4fabe3294d86a367e635bc18635af6e7132a8d93`（0.5.3 と、その後の未リリースの 5 コミット）を基準にする。
試験の準備中に確認した公開後の旧世代の後始末の欠陥は、回帰試験で再現してから修正する。
修正前後で、抽出・分割・埋め込みの入力を作るコードが同一であることを照合し、検証したコードのハッシュを残す。
OS の電源断・再起動、WSL の停止は行わない。

## 入力と準備

- 固定した 905 文書のうち、903 文書の製品形式の抽出結果を読み取る。保存済み 22,335 OCR ページのハッシュ、件数、抽出設定を記録する。
- 0.5.0 の PDF ヘッダー判定で拒まれたテキストだけの 2 文書は、現在の製品関数で別の作業領域に抽出する。原本のハッシュは固定目録と照合する。
- 製品の `chunks_for` を使う。同じモデル・版・入力ハッシュの確定ベクトルは再利用し、新規入力は Ruri-v3-130m の固定版で埋め込む。語彙は現在の製品の `tokenize` で全件を処理し直す。入力の切り詰めは行わない。
- データはリポジトリ外の専用領域に置く。元の OCR、旧 PoC、原本の PDF を更新しない。台帳と追記ベクトルの確定順序を守り、準備も再開できるようにする。

## 試験

1. 全文と実ベクトルを、索引がない製品形式の LanceDB テーブルへ投入する。この大量投入は検証用の準備であり、905 回の MCP 取り込みの完了とは扱わない。
2. 検証用 PDF を実 MCP の `register_pdf` から取り込む。製品の索引処理が全量テーブルの FTS、世代 Bitmap、IVF_SQ を作成する。
3. ANN 作成中に、この試験が起動した MCP プロセスを終了する。子ワーカーの終了、未公開のジョブ、確定済みベクトルを確認する。再接続後に同じジョブが再開し、行の重複なしで全索引の未索引行が 0 になることを確認する。
4. OCR を含む元文書の公開台帳を検証用に準備し、実 MCP で検索する。出典の文書、ページ、本文を照合する。
5. 検証用 PDF の追加と差し替えを実 MCP で実行する。追加時は索引更新中、差し替え時は公開後に旧世代が残る窓でも終了・再接続を行う。停止後の pending とテーブルの版を照合し、途中終了とコミット直後の終了を区別する。再開後に旧世代の除外、後始末の台帳、テーブルの整合を確認する。
6. 再接続や同一 PDF の再登録でテーブルの版や ANN の部品数が不要に増えないことを確認する。コミット直後の復帰は、実 LanceDB の既存回帰試験も使う。
7. 件数、索引統計、所要時間、容量、メモリ、実 MCP 検索の結果を報告する。原本の属性と、元の OCR の集約ハッシュも最後に照合する。

受け入れは、全索引で索引済み行数がテーブルの生存行数と一致し、未索引行が 0 であること、中断したジョブが同じ ID で完了すること、旧世代と重複行がないことを条件とする。
`index_cleanup_age_days` は 3650 とし、検証中に作る履歴を保持する。
MCP は準備済み Python 環境で製品の `rag_server.py` を起動し、stdio で接続する。配布の `uv run` 起動の再検証はこの経路に含めない。
検索の `nprobes` は 128（製品の既定値は 20）とする。ANN 単独と全件走査の結果も照合し、FTS だけで検索の試験が通らないようにする。
検証の成果は `docs/research/rag-full-ann-2026-11-19/` に置く。
