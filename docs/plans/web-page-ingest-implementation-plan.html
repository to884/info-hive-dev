/wiki:ingest は URL を受け付けますが、ページを取りに行く手順、翻訳、画像の扱いはまだありません。この計画は、要件定義書と ADR-0004、ADR-0005 で決めた設計を、info-hive-wiki への 3 つの PR に分けて実装する手順をまとめたものです。

01

目的と範囲

次の 3 つを、この順に実装します。

  • frontmatter の文字列の値を二重引用符で囲む書式を、パーサー、書き手、lint、テンプレート、評価用コーパスに徹底する（要件 §6.3）。
  • URL を渡すと、Web ページの本文を Markdown にして raw/ に保存し、日本語でなければ訳し、画像を保存して説明を添える（F-I10〜F-I15、ADR-0004）。
  • 知識ページに図表を入れる決まりと、それに合わせた lint・検索・初期化の修正（F-W01〜F-W07、ADR-0005）。

対象外は次のとおりです。/wiki:browse で mermaid や svg を表示すること（D-03 の注記どおり将来の作業）、JavaScript で描画されるページをスクリプトで取ること（O-15）、親リポジトリの文書の更新（9 節に挙げ、別に行います）。

全体の順序と依存

PR 1 を先にマージします。PR 2 は raw の frontmatter を引用符つきで書き、それを PR 1 のパーサーが読みます。PR 3 は lint のテストの fixture が引用符つきであることに依存します。PR 2 と PR 3 は、PR 1 のあとなら並べて進められます。

  1. PR 1

    frontmatter の引用符を徹底する

    前提: なし

    共通のパーサーと書き手を wiki_text.py に置き、lint・検索・統計がそれを使うようにします。引用符のない文字列を lint で指摘し、テンプレートと評価用コーパスを引用符つきに直します。詳細は 4 節。

  2. PR 2

    Web ページを取り込む

    前提: PR 1（raw の frontmatter を引用符つきで書く）

    新しいスクリプト wiki_fetch.py で HTML を取り、Markdown にして画像を保存します。翻訳と画像の説明はモデルが行い、その手順を ingest.md と ingest-workflow.md に書きます。詳細は 5 節。

  3. PR 3

    知識ページに図表を入れる

    前提: PR 1（lint のテストの fixture）

    図表の決まりを page-conventions.md に書き、lint のサイズ判定からフェンスの中身を除き、svg の参照先を確かめます。検索の索引からフェンスの中身を除く変更は、検索の移行の側に回します。init_wiki.py が wiki/assets/ を作るようにします。詳細は 6 節。

各 PR のマージ後に、親リポジトリ info-hive-dev のサブモジュールの参照を進めます（ユーザーに頼まれたとき）。

PR 1: frontmatter の引用符

ブランチは feature/frontmatter-quoted-strings です。今の手書きのパーサー（wiki_lint.py L121〜152、wiki_search.py L122〜152、wiki_stats.py L58〜71）は、引用符の中のカンマで配列を分け、行末のコメントを値に含めます。これを 1 つの共通のパーサーに置き換え、書式の決まりを文書と lint に入れます。

決める規則（page-conventions.md に書く）

  • 文字列の値は、配列の要素も含めて二重引用符で囲む。type、kind のような固定の英語の値も囲む。
  • YYYY-MM-DD の日付と数値は囲まない。日時（fetched_at）は文字列として囲む。
  • 値の中の " は \"、\ は \\ と書く。手書きのパーサーが戻す escape はこの 2 つだけにし、PyYAML（グラフのスクリプト）と同じ結果になるようにする。
  • 行末の # コメント は、引用符の外にあるときだけコメントとして捨てる。
  • graph: のような入れ子は、これまでどおり手書きのパーサーは読まない（PyYAML が読む）。
