# RAG の抽出キャッシュの保持と回収

前の全量試験で残った 2 件を修正する。
OS の電源断・再起動・WSL 停止は行わない。
既存の全量 OCR と ANN の証跡は変更せず、今回の試験は別の保存先を使う。

## 設計

- 退役の台帳に `rows_pending` を追加し、索引行の削除待ちと抽出キャッシュの回収待ちを分ける。既存の 2 列の台帳は行の削除待ちとして移行する。
- 行の削除前に再開位置を無効にする。削除と索引保守が済んだらキャッシュだけの回収待ちにする。この段階では行や再開位置を変更しない。
- 再登録する文書の抽出ロックを先に取り、その文書の索引行の後始末では共有・旧形式の抽出結果を残す。旧形式なら既存の移行処理で再利用する。
- 索引リセットでは行の削除待ちをキャッシュの回収待ちに変える。今取り込んでいる文書はロックで保護されており、以後の回収対象からも外す。
- ほかの wiki の公開文書・取り込み直し待ち、抽出ロックがあるキャッシュは消さない。保留した回収の記録を残し、後の取り込みや明示的な索引保守で再試行する。
- 中断中ジョブも、その wiki の policy.json の指紋と jobs の世代から参照中と判定する。別 wiki の設定やモデルに依存しない。
- 取り込み直しの一覧から外す文書は、ファイルの一覧を変更する前に同じ回収台帳へ記録する。共有違反と旧形式の削除失敗も回収待ちとして残す。

## 検証

1. 修正前に再登録による OCR 再実行とリセット後のキャッシュ残留を回帰試験で再現する。
2. 実 LanceDB で OCR キャッシュの再利用、共有 wiki の保護、ロック後の回収再試行、旧形式の回収、既存台帳の移行、リセット後の埋め込みカーソルの保持を確認する。
3. 実 OCR と実モデルを使う MCP 試験で OCR 結果のハッシュと更新日時の一致、再登録時の OCR 起動 0 回、不要キャッシュの回収を確認する。試験用のフックは製品に入れない。
4. Windows と Linux の回帰試験を行う。製品と試験を `ask-claude` の Opus で敵対的にレビューし、指摘を確認して修正する。
5. 結果を検証レポートとプロジェクト wiki に記録する。コミット・公開はこの作業に含めない。
