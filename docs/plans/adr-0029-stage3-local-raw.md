# ADR-0029 段階3のローカル原本と経験の保存

[ADR-0029](../adr/0029-wiki-and-raw-hold-no-links.md) の I2、I3、I6 を、通常の取り込みと経験の記録に適用する。セッション、字幕、Web の取り込みに続き、raw の書き手を `wiki_fsguard.py` に接続する。

## 通常の取り込み

- `wiki_raw_ingest.py save` に wiki、現在の raw の根、取り込むパスを渡す。`..` を含むパスは絶対化の前に拒む。現在の raw の根の内側の資料は、その位置で参照する。根の指定時の綴りと実体の両方で所属を比べ、根より下の道と項目を検査する。過去の根にある資料は、同じ検査を受けてから現在の根へ写せる。
- 根の外から写すファイルとディレクトリは、リンクの先の中身を通常のファイルとディレクトリに写す。wiki 記事と記事のあるディレクトリは既存の読み取り検査に通し、コピーする各項目を現在と過去の根に照らす。ディレクトリの循環は祖先の識別子で止め、同じディレクトリを指す別々の枝は写せる。走査で保存先を含む枝に出会った場合も取り込みを止める。
- 根の記録が書けてからコピーを始める。ファイルは一意の一時名から排他で、ディレクトリは同じ raw の根内の一時ディレクトリから名前を変更して公開する。ディレクトリを書き込む処理同士は同じ raw の根のロックを取る。コピー中に失敗したディレクトリは最終名に現れず、既存の保存先は上書きしない。中断後は保存先を確認し、保存済みの原本を入力にして再開できる。
- `save` は `raw_path`、`raw_ref` と lint と同じ方式の `raw_sha256` を返す。通常の兄弟配置の `raw_ref` は wiki の親からの相対パスとし、ほかの配置では絶対パスを返す。コピーするディレクトリには隠し項目と空ディレクトリも写す。ディレクトリのハッシュは設計どおり隠し項目と空ディレクトリを含まないため、コピー先全体が同じかどうかの判定には使わない。
- `encoding` は保存時のハッシュと照合した raw の文字コードを判定する。出力名を指定したときは UTF-8 の派生ファイルを同じ保存手順で置く。同じ内容の派生ファイルがあれば再利用する。原本と派生版を出典に使うときは、`raw` と `raw_sha256` の配列の順をそろえる。
- rag を利用する PDF は `pdf` で事前検査する。wiki、現在または記録済みの raw の根の内側では、根より下のリンクと、lint の対象にならない隠し項目を拒む。外部の PDF は指定された綴りで絶対化し、その値を `register_pdf` に渡す。登録後の source ページは引き続き rag の結果から版を記録する。過去の根の記録が読めず、所属を確かめられない場合は保存や登録を始めない。

## 経験の記録

`wiki_evolve.py capture` は `experiences/` の検査と根の記録のあとで、経験の JSON を排他公開する。再実行では既存の JSON の内容を照合する。以前の Windows 版で書かれた CRLF の記録は、そのバイト列のハッシュを返す。評価ループと `/wiki:learn` は、返された `raw_ref` と `raw_sha256` を source ページに引き継ぐ。以前の評価ループが作ったページを同じ内容で再処理する場合は、元の参照、日付、改行を保ったままハッシュを補える。
