# Web 取り込みで翻訳を省略したまま完了にしない

## 問題

英語の記事を取り込んだ際、取得器は `needs_translation: true` と判定したが、エージェントが `--language-override keep` を指定して翻訳を省略した。構造の検査は成功し、`--finish` が比較用の写しを消したため、その結果を取り込み完了と扱った。また、現行の検査は `translated_by` が空でなければ、英語の本文をそのまま残しても通る。

## 変更の範囲

正本は `info-hive-wiki/skills/info-hive/`。取り込みのコマンド、raw のエージェント、Codex の差分、Web の取り込みの参照文書と検査を同期する。テストと本計画、レビューの記録は親リポジトリに置く。他のセッションが進めている Codex 対応と Playwright 対応の差分は保つ。当初は実装までの依頼だったが、利用者からコミット、push、PR 作成、マージまでの指示を受けた。独立した worktree に切り出し、Opus のレビューと CI を確認してプラグイン、親リポジトリの順にマージする。GitHub リリースとタグの作成は依頼に含めない。

## 判定の変更

1. `fetch.json` の `needs_translation` は真偽値として読む。欠落や型の違いを「翻訳不要」にしない。
2. 翻訳が必要と判定された資料を `keep` で翻訳不要へ変更しても、通常の取り込みの完了条件は満たさない。エラーとして比較用の写しを残す。`translate` による翻訳の追加は引き続き使える。`keep` は、もともと翻訳不要の入力に対する互換性のため残す。
3. 翻訳を行う場合、本文のパーサーで対応付けた文章のブロックごとに未翻訳を検出する。コード、画像、インラインのコードは検出対象にしない。日本語の文字数の比率や名前を推定して削った残りから翻訳済みとは判断しない。段落の一部に残った外国語の文や節、中国語の文の丸残しや近似コピーをエラーにする。Unicode の単語も使って文章の残存を照らす。名前、表示文字列、値の列挙、原語の併記と区別できない句や、文末のない短い説明は、確認を要する警告にする。原文と文脈に基づく具体的な保持の理由が必要であり、一般的な理由の一括受理では翻訳を省略できない。見出し・リスト・引用・表のセルも同じ対応で調べる。日本語の補足を追加しても、本文の未翻訳は解消しない。
4. 言語の簡易判定は意味の正しさを保証しない。その限界と検出対象を明記し、訳文の読解確認は手順に残す。誤検出を無条件に受理する新たなフラグは作らない。
5. `check` の JSON に翻訳の検査結果と `completed` を出す。通常の診断は `completed: false`。`--finish` でも、エラーまたは未受理の警告があれば false のままで写しを残す。検査が通り、必要な警告の受理を経て、終了処理が成功した場合だけ true にする。

## 手順の変更

- W6 と W8、呼び出す側、Codex の手順で、日本語の raw を作れなければ未完了で止まり、英語の保存と日本語の要約で代替しないことを明記する。
- 原文の再現性、費用、時間、エージェント自身が判断した制約は、翻訳を省略して完了とする理由にしない。進められない場合は理由を伝え、`failed`（`error.kind: other`）として返す。
- `done` の根拠はフォルダーの消失や `ok` だけにしない。実際に実行した W8 の JSON の `completed` と翻訳の検査結果を読み、検査に使った言語条件をログに残す。
- 比較用の `fetch.json`、`fetched.md`、`cleaned.md` を手作業で作ったり、判定を変えるために書き換えたりしない。既存の raw を使う場合も、検査器が管理している比較元なしに「検査済み」を作らない。
- 警告を受理する理由は W9 より前に `prepare` の記録として残し、`--finish --accept-warnings --json` の `completed: true` を確認する。取り込みの完了記録を先に書かない。翻訳未実施のエラーは警告の受理では通らない。
- `translation.state: checked` はコード・画像・URL を除く文字があるブロックを 1 件以上照合した場合だけにする。コードや画像だけなら `no_prose` と `checked_blocks: 0` を返し、翻訳を行ったとは記録しない。`incomplete` は翻訳以外も含めた検査エラーの状態なので `errors` と合わせて読む。

## 検証

ネットに接続しない回帰テストで、(a) 英語のまま keep、(b) 翻訳者名だけ記入、(c) 一段落だけ翻訳、(d) 図の日本語の補足だけ追加、(e) 日本語の短い語だけ付け足す、を拒否し、`--finish --accept-warnings` でも比較元が残ることを確かめる。正しい訳、技術名・コード・画像の保持、日本語の原文、`translate` の指定、警告を含む既存の完了処理も確かめる。

製品名を含む短い見出し・表、論文名、同一段落の後半だけの未翻訳、中国語の一文字変更と後半の残存、各語を大文字で始めた文章、短いリリースノート、コードのみ、HTML の扱いも検証する。独立した worktree で、既存の Web 取り込み・raw のエージェント・Codex の操作手順・取得の回帰テストを実行する。設計と実装の完了時に、それぞれ `ask-claude` で Opus の敵対的レビューを行う。翻訳の意味や品質を機械で保証したとは報告しない。
