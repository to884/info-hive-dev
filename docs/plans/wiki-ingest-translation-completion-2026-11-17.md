# 翻訳を省略した raw を完了にしない

## 問題と範囲

取得器が `needs_translation: true` とした記事を、`--language-override keep` で英語のまま保存し、構造の検査の成功を取り込み完了と扱っていた。日本語の要約は raw の翻訳の代わりにはならない。

正本は `info-hive-wiki/skills/info-hive/`。コマンド、raw のエージェント、Claude Code と Codex の参照文書、検査器を同期する。試験と設計・検証・レビューの記録は親に置く。並行作業の Playwright 対応は含めない。利用者からコミット、push、PR 作成、マージまで指示を受けた。プラグイン PR #87 を先に、親 PR #171 を後にマージする。タグと GitHub リリースの作成は含めない。

## 完了の条件

- `needs_translation` の欠落や型の違いを翻訳不要と扱わない。翻訳必須の `keep` は常にエラーで、警告の受理では解除できない。
- raw の本文を日本語に訳し、実際のモデル名を `translated_by` に書く。進められなければ `failed`（`error.kind: other`）で理由を返す。費用、時間、原文の再現性は翻訳を省略する理由にしない。
- `ok` は検査の成功、`completed` は終了処理までの成功を表す。通常の診断は false、`--finish` が必要な検査と警告の確認を終え、比較元を消せた場合だけ true にする。
- `translation.state` は文字のあるブロックを照合した `checked`、文章がない `no_prose`、翻訳不要の `not_required`、誤りがある `incomplete`。`checked_blocks` は照合したブロック数で、翻訳した回数や言語を判別できた数ではない。
- `pending_reviews` が 1 以上なら未完了である。旧形式や、フォルダーの消失から完了を推定しない。

## 外国語の検出と確認を分ける

文字数の割合や固有名詞の推定から翻訳済みとは判断しない。かな・漢字以外の文字体系を Unicode の単語と字母で調べる。文章の全体が外国語なら 2 語以上または字母 20 字以上、日本語の中の外国語は 4 語以上または字母 20 字以上を確認の対象にする。文末、大小文字、原文との完全一致に依存しない。漢字があり、かなの文字数がかなと漢字の合計の 35% 未満のブロックも、短いものを含めて確認する。原文に近い漢字のまとまりも確認する。日本語の見出しなども該当し得るので、この条件で言語や訳の正しさを確定しない。コード、画像、インラインのコード、URL、図の補足は文章の検出に数えない。

候補を文章・名前・UI の文字列と機械で分類して受理しない。未解決の候補は `translation_review_required` のエラーにし、`--accept-warnings` では解除しない。文章の訳し忘れは訳して再検査する。

正しく保持する名前、識別子、文献名、表示文、エラーメッセージ、原語の併記、引用と、日本語として訳されている候補は、対象ごとの確認の記録で解決する。日本語の確認には `japanese_text` を使う。`<作業用フォルダー>/translation-review.json` に次を記録し、`--translation-review` を明示して検査する。

- 現在の `cleaned.md` と raw の実バイト列の SHA-256。パースとハッシュには同じ読み取りの写しを使う。
- 実際に確認したモデル名 `reviewed_by`。
- 構造上の位置と原文・訳文・対象の文字列に結び付いた対象の `id`、検査結果の全文をそのまま写した `text`、保持の種類 `kind`、対象ごとの具体的な `reason`。

不正な記録、別の本文のハッシュ、対象にない ID、重複、対象の一部だけの text、空の理由、決まった種類以外はエラーにする。一部だけ確認しても、残りの候補は未解決のままである。表示文、エラー、原語、引用を保持する場合は、同じブロックにかなまたは漢字を含む日本語の説明や訳が必要である。

有効な記録で解決した対象も `translation_reviewed` の警告にし、委譲の場合は親が原文と文脈と記録を読み、W9 より前に `prepare` のログに理由を書いてから受理する。raw のエージェントは警告を受理せず親へ返す。親が `done` を受理する条件は、実際の JSON の `warnings: []` と `reviewed_passages: 0` も含む。自分で W1〜W8 を行う場合は自分で確認して記録する経路であり、独立したレビューとは呼ばない。結果には確認した対象の全文、理由、モデル、件数、照合したハッシュが残る。キャッシュの確認記録が消えたあとも、実行した W8 の JSON とログから根拠を読める。

## 検査の限界

検査器が保証するのは、対象の検出と、確認記録の形式・対象・現在の本文への結び付きである。モデルが書いた分類や理由の具体性、確認者名の本人性、訳の正しさや完全性は保証しない。名前と理由は非空の自己申告の文字列として扱う。確認の記録を翻訳の代用にせず、候補のブロック全体を読み、残る文章は訳す。汎用の理由による一括受理は禁止する。

短い語や検出条件に当たらない言語の形の見逃しはあり得る。訳文の読み直しを残す。比較元やプログラム自体を任意に改ざんする実行者への防御は目的としない。`fetch.json`、`fetched.md`、`cleaned.md`、`removed.json` を手作業で作ったり変えたりして検査済みにしてはならない。

## 検証

元の事故（keep）、翻訳者名だけ、部分翻訳、補足だけ、日本語の付け足し、文字を少し変えた他の文字体系、文末の記号の違いについて、回帰にした代表例を確認記録なしでは拒否する。検出の閾値より短い語を日本語で区切った形などは検出できない場合があり、すべての部分翻訳を検出するという意味ではない。正しい訳、コード・画像・固有名詞、日本語原文、文献名や複数文の表示文に確認の経路があることを試す。

記録の欠落、不正、古いハッシュ、不明な ID、重複、部分的な解決、同じ表の値の ID、通常の警告の受理との違いをネットなしで試す。監査も未解決の対象や JSON の確認の証拠の欠落を完了とせず、委譲先の警告の受理を拒否する。監査は `prepare` のログの有無や記録の順序までは判定しない。関連回帰と encoding の検査、保存済み記事の一時 wiki による検証を行う。設計と実装は AGENTS.md に従い Opus の敵対的レビューを受ける。
