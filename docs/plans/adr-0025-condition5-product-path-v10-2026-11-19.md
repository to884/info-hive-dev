# ADR-0025 条件5の候補を製品経路で確かめる

二つの正解監査を通過した候補を、現在の画像OCRの経路へ接続する。主OCRの本文・行枠・順序は接続の前後で一致させる。選んだ候補は周囲のOCR枠の12特徴を加えた288特徴、閾値0.15で、出版物を外した学習では旧v9の固定教師を使った。全データから最終候補を学習するときは同じ教師の版、特徴の順序と定義、学習設定を保持する。全データで学習し直した数値を、出版物を外した開発評価の数値と混ぜない。

## 入力と判定の一致

| 特徴 | 接続する処理 |
|---|---|
| 主OCR、ぼかし、別解像度、RapidOCR | `rag_pdf.ocr_page` と現在の画像ワーカーの行記録 |
| NDLOCRの30・50・100文字用、余白付き100文字用の別読み | `collect_probe_v4.py` と同じ行割当、モデル、画素と余白 |
| 局所画像、文字位置、別読みの差 | `local_reads_v5.py`、`v5_features.py` と同じ切り出し・特徴 |
| MinerUの行画像の別読み | `collect_mineru_v6.py`・`mineru_features_v6.py` の画像・モデルの設定 |
| 周囲の枠の向き | 同一頁の主OCRの枠と向きから作る12特徴 |

製品側のフラグに至る通常の画像入力、特徴計算、固定モデル、最終比較を通して、研究側と照合する。PDFの符号や正解を特徴へ渡さない。NDLOCR、別読み、点線を含む行の形を変えず、処理の版・重み・特徴名順序と不足時の扱いを試験前に固定する。決めた版の入力を得られないときは、新モデルの印を付けた記録を作らない。

公開・合成の開発で、全評価ページについて確定本文と枠の対応、全特徴、数値、印を行別に照合する。最終モデルをファイルに出す場合は、研究の分類器の予測と製品が読む形式の数値と比較する。閾値の近くは実際の判定の一致も確認する。ToUnicodeだけが異なり固定画素が同じ対照を、製品の候補経路でも確認する。現行の `flags-v3` 経路で同じ印だったことは候補経路の確認にはならない。

## 未使用資料

公開と合成をそれぞれ未使用のまとまりで固定する。選定、モデル調整、実装比較に使った開発資料は入れない。評価の正解作成、試料の固定、判定の採点、失敗の扱い、入力のハッシュを事前に記録する。製品の経路で一度だけ実行し、各群で既定の正式基準を適用する。結果を受けて同じ未使用資料を調整と再受け入れに使わない。
