# 全量 OCR と ANN 自動保守の検証

2026 年 11 月 4 日開始。OS の電源断、OS/WSL の停止・再起動コマンドは実行しない。
PDF 原本の移動・複製・書き換えは行わない。

対象は、前回固定したローカル PDF 914 件、重複を除いた 905 文書のうち、`auto` が OCR に回す 22,335 ページすべてとする。
テキスト層が読めるページと既存の文書ベクトルは、入力ハッシュと設定を照合して再利用する。
`always` ですべてのテキストページも再認識する試験とは区別する。

1. 固定 NDLOCR-Lite のモデルを再利用する子プロセスを実装し、従来 CLI の文字列との一致、空白画像、子プロセスの終了を確認する。
2. 全 OCR 対象をページごとに SQLite へ確定し、実プロセスを停止して、保存済みページの試行回数と出力ハッシュを変えずに再開する。
3. CPU と隔離した GPU 実行環境を点検し、GPU を使う場合はノード実行のプロファイルを残す。実際に使った device と依存版を記録する。
4. 製品に FTS、世代 Bitmap、IVF_SQ の自動作成・差分更新・規模に応じた再構築を加える。ネイティブ処理の前に pending 状態を記録し、完了後の中断では同じ更新を再実行しない。
5. 実 LanceDB の回帰試験と、実 MCP の PDF 追加・変更・再接続で、索引の網羅、古い世代の除外、更新の重複抑止を確認する。
6. OCR の結果を全量の本文へ反映し、再分割と埋め込みを行う。再利用するベクトルは埋め込み入力ハッシュで照合する。
7. 検証用の全量データへ実 MCP から PDF を追加し、取り込みが ANN の自動作成を起動することを確認する。作成途中の MCP 強制終了と復帰、追加・置き換え後の自動保守も全量テーブルで検証する。
8. 全量の件数、索引統計、容量、メモリ、CPU 検索と、文字が得られなかったページやエラーを報告する。

ネイティブ抽出結果は `.rag-poc-data/full-20261104` に保持し、変更しない。
今回の派生データは `.rag-poc-data/full-ocr-20261104` と GPU 比較用の別保存先、成果は `docs/research/rag-full-pipeline-2026-11-04` に保存する。
全文の人手正解や全ページの CER を作ったとは扱わない。
