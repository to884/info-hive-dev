# ADR-0029 段階3のグラフ成果物の保護

`/wiki:graph` が呼ぶ `wiki_graph_extract.py` の成果物にも、ADR-0029 の I6 を適用する。グラフの読み取り専用の query と lint は従来の入口を使う。

- 既定の `<wiki>/graph` と wiki 内の `--out` には、wiki を根として `WriteGuard` を適用する。wiki の指定と、根のリンクを解いた名前の両方で所属を調べる。出力先が wiki の根と同じ場合はその直下のファイルを検査する。外側の名前で指定した場合は、途中の各項目が wiki 内を指すかを確かめ、指していれば wiki の根からの指定を求める。wiki の外にある出力先は、指定した場所を根とする。wiki の初期化やオントロジーの確かめに失敗した場合は、出力先を作らない。wiki または出力先に `..` を含む場合は、理由を標準エラーに書いて終了コード 1 で止まる。
- `.extract.lock` は共通部品で取得する。従来のロック名と待ち時間を保つ。同じ出力先の生成を排他し、成果物を検査し終えてから書き始める。
- JSONL、GraphML と SQLite を、出力先の中の一意な一時名にすべて書き終えてから、現在と同じ順（SQLite が先）で公開する。一時名は `<成果物名>.<PID>-<16バイト乱数の16進表記>.tmp` とし、`WriteGuard.open_new` で排他作成したハンドルから実体を控える。JSONL と GraphML はそのハンドルに書き、SQLite は作成済みの空ファイルを `mode=rw` で開く。SQLite 本体と `-journal`、`-wal`、`-shm` を接続前と公開時に検査する。公開先の SQLite に付随ファイルが残っていれば、場所を知らせて公開を止める。
- 選んだ形式の出力先を、一時ファイルの作成前と最初の置き換え前にすべて検査する。置き換えは既存の Windows 向け再試行のたびに、共通部品で一時名の実体と公開先を再検査する。書いている途中に失敗した場合や、最初の置き換えに失敗した場合は、従来どおり前の成果物が残る。途中まで公開した場合は、更新済みと未更新の名前を理由とともに標準エラーに書き、終了コード 1 で止まる。
- 前の実行が残した旧形式の一時ファイル `<成果物名>.<PID>.tmp`、今回の命名規則の一時ファイルと、一時名につく SQLite の付随ファイルだけを、排他を取ってから調べる。通常のファイルだけを削除する。一時名や付随ファイルにリンクがあれば、名前と理由を知らせ、そのファイルは残す。書き込みの途中で失敗した場合は今回作った実体を照合して片付ける。
- 回帰試験は既定と明示的な出力先、途中のリンク、ロックと成果物のハードリンク、古い一時名と SQLite 付随ファイルのリンク、通常の並行実行、前の成果物の保全を確認する。
