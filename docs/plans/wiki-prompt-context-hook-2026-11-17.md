# プロンプトのフックで wiki の候補を知らせる計画（2026-11-17）

決定は [ADR-0034](../adr/0034-wiki-prompt-hook-suggests-candidate-pages.md)、測定は [段階 0 の記録](../research/wiki-prompt-hook-stage0-2026-11-17.md)、仕組みの正本はプラグインの `skills/info-hive/references/prompt-context.md` にある。この文書は、作者が承認した計画と、段階 0 で変えたことを残す。

## 依頼と決めたこと

- 依頼: UserPromptSubmit で、`/wiki:query`、記事の直接の参照、埋め込みの検索のどれかで、指示に関係しそうな wiki を問い合わせる。
- 追加の依頼: wiki を調べるときは、その場で最適なモデルとエフォートを選ぶ。
- 作者が決めたこと:
  - 既定で有効にする。
  - 引く wiki は設定で選べる（既定はプロジェクトの wiki だけ）。
  - モデルとエフォートを選ぶ対象は、フックの候補を読む段だけ。`/wiki:query` は今のままにする。
- 仕様の制約: command のフックは `/` のコマンドもツールも起動できない。そのため、フックが自分で探し、`additionalContext` で候補を足す。

## 段階 0 で計画から変えたこと

| 計画 | 変えたこと | 理由 |
| --- | --- | --- |
| ゲートに本文の語の一致（S4）を入れる | 使わない。種類を S1〜S4（S4 は索引の要約）に振り直した | 採られるたびに精度を下げ、再現率を上げなかった（[測定](../research/wiki-prompt-hook-stage0-2026-11-17.md)） |
| 本文の BM25 をページ数の上限まで照らす | 本文を解析しない。本文は識別子を文字のまま照らすことにだけ使う | 本文の解析が重い（1,000 ページで約 11 秒）。題と見出しの走査は 1,000 ページで 0.15 秒 |
| 単位のありふれた度合いを本文で決める | 照らす欄（題、索引の要約）ごとに決める | 本文でありふれた語も、題と要約では手がかりになる |
| 題の 1 語の一致で採る | 1 語の一致は、長くまれな語が指示の語と同じ形で現れ、ほかの語が要約か見出しにあるときだけ採る | 「リスト」「パイプ」「メモリ」1 語で、無関係な指示が当たった |
| 識別子に大文字の語と 2 つの部分の版を含める | 数字を含む大文字の語と 3 つの部分の版だけにし、語の境目で照らす。版は題やスラッグにあるときだけ | `HTTP`、`OAuth 2.0` で発火した。`JSON` が `JSONL` に当たった |
| 飛ばす条件 | 会話の圧縮の要約（`This session is being continued …`）を足した | 実際の発言で、圧縮の要約が直接の参照で当たった |
| 段の表の R0 は 1 件の強い一致 | 候補が 1 件なら、一致の種類によらず R0 | 1 ページなら、サブエージェントを起こす費用のほうが大きい |
| 「読み方」は勧めの書き方 | 「自分で開かずに、Agent ツールを … で呼ぶ」と、理由とともに書く | 勧めの書き方では、メインが呼ばずに自分で読んだ |
| (b) サーバーへの届き方を段階 0 で測る | 段階 2 の始めに測る | 段階 1 は埋め込みを使わず、(b) の結果に依らない |
| ADR-0031 | ADR-0032 | 0031 は別の作業（wiki-overview）が使っている |
| トークン化は `wiki_search` から使う | `wiki_tokens.py` に移し、`wiki_search` からは名前を読み直す | `wiki_search` の import に 0.5 秒かかる |

## 受け入れの条件

- ゲート: 評価のデータで、無関係な指示と短文と利用者が打たないターンでの発火が 5%（短文は 0%）以下、精度 0.8 以上、ターンの再現率 0.4 以上（段階 2 は 0.6 以上）。直接の参照は 100%。
- 時間: 何もしない経路の p95 が 300 ms 以下（Git Bash）。150 ページの検索の経路の p95 が 1.0 秒以下。
- 失敗: どの失敗でも終了コード 0 で、利用者の指示を止めない。
- 読む段: 種類ごとに、開いていないページを引いた回が 0 で、事実の正しさが最良の組の 95% 以上の組のうち、いちばん安い組を表の値にする。
- レビュー: ask-codex（Sol）の敵対的レビューを、設計と実装のそれぞれで受ける。

## 確かめ方

1. `python -X utf8 -m unittest tests/wiki/test_prompt_hook.py` と関係する試験（`test_uninitialized_wiki.py`、`test_python_version.py`、`test_page_set.py`）。
2. `python tests/wiki/eval_prompt_context.py --split all --gate`。
3. `python tests/wiki/bench_prompt_hook.py launch` と `scale`。
4. `claude --plugin-dir <worktree の info-hive-wiki> --debug-file <path>` で、`Hook UserPromptSubmit ... provided additionalContext` が出ること、エラーの知らせがないこと。`stream-json` の記録で、R1 の指示に対して Agent ツールが書いたとおりの `subagent_type`、`model`、`effort` で呼ばれること。
5. デスクトップアプリで、指示のたびに窓が出ないこと（作者が目で確かめる）。
