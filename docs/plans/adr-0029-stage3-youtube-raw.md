# ADR-0029 段階3の YouTube 字幕取り込み

[セッションの実装](adr-0029-stage3-session-raw.md) に続き、[ADR-0027](../adr/0027-youtube-captions-via-pinned-yt-dlp.md) の字幕の保存を共通の書き込み検査に移す。

- `inspect` の既存 raw の一覧は、根の直下の Markdown を開く前に検査する。リンクを読まず、既存の `unreadable` に名前を、`raw_link_warnings` に経路と種類を返す。指定された根の別名は読むときに許す。保存ではセッションと同じく、根と祖先のリンクおよび wiki との包含を拒む。
- 承認に使う `source_sha256` はこれまでどおり json3 のハッシュとする。新規保存は競合と別版の条件を確かめて根を記録し、排他公開する。既存の同じ字幕を使う場合も、読み取り専用にする前に根を記録する。記録に失敗した場合は、原本の新規保存や属性変更を行わない。
- `created` と `same` は、実際の Markdown のバイト列の `raw_sha256` を返す。古い raw の改行や YAML の違いも保存したバイト列に含める。source ページに写せる `raw_ref` は、従来の相対表記がこの原本に解ければ使い、他の候補で曖昧か拒否になる場合は絶対パスを使う。確かめた原本に読み取り専用の属性を付ける。
- 既存の原本を使って取り込みを続けるときも、V4 で承認を得て V5 で根を記録する。V7 は `raw_ref` と `raw_sha256` を転記し、V8 は V5 の `raw_path` をそのまま対象に指定する。字幕の同一性と Markdown のハッシュは、同じ読み出しのバイト列から求める。
- `verify` の対象には、原本を含む根とファイルのパスを指定する。既存の `--slug` も使える。別の根に同名のファイルがあっても、対象は指定したファイルである。wiki 全体から字幕や根拠を解くときは、lint と同じ過去の根の記録も使う。
- 排他は原本のファイル名単位で行う。同じ動画を異なるスラッグに並行保存する場合、字幕の同一性と別版の判定は、それぞれ既存ファイルを一覧した時点の結果に従う。

試験では字幕の取得を既存の代替実装に差し替える。新規保存と再利用、根の記録の失敗、既存 raw のリンクを読まないこと、別の根を指定した lint で保存した版を照合することを確認する。Web、PDF、経験の取り込みは後続の変更とする。
