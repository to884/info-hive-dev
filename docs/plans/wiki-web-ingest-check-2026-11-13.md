# URL の取り込みに検査と雑音の規則を足す（中の案の設計、2 版、2026-11-13）

## 目的

`/wiki:ingest` に URL を渡したとき、モデルが raw を書き換える工程（雑音の削除、訳、画像の補足）の結果を、スクリプトが取得した直後の内容と照らし、規則に反していれば止める。あわせて、サイトに共通の雑音を取得の段階で消し、ブラウザで取った HTML も変換できるようにする。

検討の経緯と、小・中・大の 3 案の比較は [wiki-web-ingest-deterministic-2026-11-13.md](wiki-web-ingest-deterministic-2026-11-13.md) にある。作者は中の案を選んだ（2026-11-13）。比較のレポートは [docs/research/wiki-ingest-model-comparison-2026-11-13.md](../research/wiki-ingest-model-comparison-2026-11-13.md) にある。

この案は、モデルが raw の Markdown を直接書き換える今の形を変えない。モデルが規則を破ることは防げないが、破ったまま先に進むことを防ぐ。

## 方針

モデルの編集を 2 つの段に分け、段ごとに検査する。

1. **雑音の削除の段**: モデルは、取得した raw から文字列を消すことだけをする。書き足しも書き換えもしない。スクリプトは、取得した直後の写しと比べて、消すことだけをしたかを調べ、通れば削除のあとの内容を固定する。消したものは、すべて出力と記録に残す。
2. **訳と補足の段**: モデルは、固定した内容を訳し、画像の補足を書く。スクリプトは、固定した内容とブロックごとに照らす。削除はもう許さないので、ブロックの数、種類、順、コード、リンク先、画像の行、表の形が一致しなければならない。

削除と訳を同じ差分で見ると、消えたリンクが「雑音として消した」のか「訳で落とした」のかを区別できない。段を分けると、訳の段は厳密に検査できる。削除の段は、消すことだけをしたか、コードに触れていないかを検査できるが、消したものが本当に雑音かは検査できない。その判断は、出力に並ぶ消したものを見て、モデルが確かめる。

## 変更

### `wiki_fetch.py`

**作業用の写し**: `--wiki` を渡して raw を書くとき、raw を書く**前に**、書く内容と同じものを `<WIKI_ROOT>/.wiki-cache/ingest/<スラッグ>/fetched.md` に、取得の結果（`--json` の出力）を同じフォルダーの `fetch.json` に書く。同じスラッグの前の作業用のフォルダーがあれば、消してから作る。写しを書けなければ raw も書かない。

`unchanged` のときは何も書かない。出力の `work_dir` に、作業用のフォルダーがあるかを示す。raw が前の取り込みの途中のもので作業用のフォルダーがないときは、`--force` で取り直せば、写しと raw の両方を作り直せる。

作業用のフォルダーを消すときは（ここと、`wiki_rawcheck.py check --finish`）、`<WIKI_ROOT>/.wiki-cache/ingest/<スラッグ>` の各段が、シンボリックリンクでもジャンクションでもなく、解決したパスが `<WIKI_ROOT>` の中にあることを確かめる。そうでなければ消さずに止まる。

**言語の判定**: 出力に `needs_translation` を足す。規則は今の手順（`commands/ingest.md`）と同じにする。`source_lang` が空のとき、または `source_lang` の言語（`ja` で始まるか）と `ja_ratio`（0.5 以上か）が食い違うときは `ja_ratio` で決め、そうでなければ `source_lang` で決める。

**雑音の規則**: 規則で消したものは、出力の `removed_by_rule` に、規則の名前と元の文字列で示す。`--keep-noise` を付けると、この節で足す規則を使わない（今の `NOISE_WORDS` などは今どおり）。

規則は、当たる範囲を狭く決める。

- **MediaWiki の部品**: ページが MediaWiki で作られている（`<meta name="generator" content="MediaWiki …">` がある）ときだけ使う。class か id が `mw-jump-link`、`mw-logo`、`siteSub` に一致する要素と、行のセルの class に `metadata` がある表を落とす。
- **本文の前の部分**: 本文の前の部分を、本文のブロックのうち、リンクを除いた文字が 80 文字以上ある最初の段落より前のブロックとする。この部分にあるブロックだけに、次の規則を当てる。
  - 題名と同じ文字列だけからなる段落（重複した題名）。
  - リンクだけからなり、すべてのリンク先のパスに `/tag/` か `/tags/` の区切りがある段落（タグのリンク）。
  - 文字列が `Member-only story` か `Top highlight` と一致する段落。
  - `Read this story for free:` で始まり、リンク先に `source=friends_link` を含む段落。
- **Medium の画像の部品**: 文字列が `Press enter or click to view image in full size` と一致する段落は、本文のどこにあっても落とす。

**ブラウザで取った HTML**: `--html-file <パス>` と `--page-url <URL>` を足す。`--page-url` は、本文を取ったときのブラウザのアドレス欄の URL で、相対リンクと画像の基準にし、`final_url` に書く。`--html-file` を使うときは必須にする。ファイルは UTF-8 として読み、UTF-8 として読めなければ止まる（HTML の中の `<meta charset>` は使わない）。`source_sha256_of` は `dom` とし、`source_sha256` は読んだファイルのバイト列に対して取る。手順の今の書き方（「取った本文のテキストに対して取る」）は、これに合わせて直す。

**スラッグ**: 末尾がピリオドか空白のスラッグと、Windows の予約された名前を拒む。予約された名前は、`os.path.isreserved`（Python 3.13 以降の Windows）が使えればそれで調べ、使えなければ、`CON`、`PRN`、`AUX`、`NUL`、`COM` と `LPT` に数字（`0`〜`9` と上付きの `¹²³`）を付けた名前（拡張子つきと、大文字と小文字の違いを含む）を拒む。

### `wiki_rawcheck.py`（新しいスクリプト）

標準ライブラリと、同梱の markdown-it-py（`wiki_pages.new_parser()`。lint と閲覧と同じ設定）だけで書く。本文はこのパーサーで読み、トークンの木で照らす。行の接頭辞や正規表現で、入れ物や構造を推し量らない（実装の 1 回目のレビューで、行ごとの推し量りが入れ子のコード、エスケープした `]`、リストの続きの行の画像を見誤ったため）。サブコマンドは `freeze` と `check` の 2 つ。どちらも `--wiki`、`--raw-root`、`--slug` を取り、`--json` で結果を JSON にする。誤りがあれば終了コード 1、通れば 0 にする。

**画像の扱い（両方の段で共通）**: 画像は、パーサーの `image` のトークンである（コードブロックの中の画像の記法は数えない）。取得したかどうかは、`fetch.json` の `images` の `path` で決まる。取得した画像のファイルがなければ誤りにする。取得できなかった画像（`path` が空）は、ファイルを持たず、補足も要らない。

**`freeze`（雑音の削除の段の検査）**

`raw/<スラッグ>.md` を `fetched.md` と比べる。

誤り:

- frontmatter が違う。
- raw の本文が、`fetched.md` の本文から消すことだけで作れない。照らし方: 両方をブロックの木にする。各入れ物で、raw の子の並びが `fetched.md` の子の並びの部分列で、対応する子どうしも消すことだけで作れること（再帰的に照らす）。ブロックの種類と属性は同じでなければならない。コードブロックは中身も同じでなければならない（丸ごと残すか丸ごと消す）。段落などのインラインは、画像、リンク、インラインのコード、強調をそれぞれ 1 つのかたまり、ほかを 1 文字ずつとした並びで、raw の並びが部分列であること。部分列があるかは、先頭から貪欲に照らして判定する（対応の関係が何であっても、貪欲で正しい）。リストは項目に開き、リストの種類（記号と種類）を添えた項目を対応の単位にする（同じ記号のリストの間のブロックを消すと、CommonMark は前後のリストを 1 つにまとめるため）。表の行だけは、セルを位置で対応させ、セルの数を変えさせない（表の列は消せない）。
- raw の表の行に、見出しより多いセルがある。パーサーはそのセルを捨てるので、表示されず、木にも現れない。行ごとのセルは、パーサーの表の規則と同じ行の取り出しと分け方で数え直す（実装 8 回目）。
- 題名（最初の h1 の見出し）を消したか、変えた。
- 画像のファイルの過不足。残った画像の行から参照されるファイルはあること。どの残った行からも参照されないファイルは消してあること。取得できなかった画像は調べない。

通れば、raw の内容を `cleaned.md` に書き、消したもの（行と、行の中の文字列）を `removed.json` に書く。出力に、消したものと、規則で消したもの（`fetch.json` の `removed_by_rule`）を並べる。消したものの文字数が、本文の 2 割を超えたら警告する。

**`check`（訳と補足の段の検査）**

`raw/<スラッグ>.md` を `cleaned.md` と比べる。`cleaned.md` がなければ（`freeze` をしていなければ）誤りにする。

比べる前に、raw の木から補足を取り除く。補足は、画像を含むブロックのすぐあとに続く、同じ入れ物の中の引用で、最初の段落が `<表示名> 補足: `（表示名は 1 行の 60 文字以内）で始まるものである。1 つの引用の中に 2 つ目の補足の始まりがあれば誤りにする。

次に、両方の木を節点ごとに照らす。

誤り（どれかがあれば終了コード 1）:

- frontmatter が `translated_by` のほかで違う。
- 訳すページで `translated_by` が空。訳さないページで `translated_by` がある。訳すかどうかは `fetch.json` の `needs_translation` で決める。モデルが判定を覆すときは、`--language-override translate` か `--language-override keep` を付け、`--reason` に理由を書く。理由は出力に残る。
- 入れ物ごとの子のブロックの数が違う（表の行とセル、リストの項目、入れ子のリスト、引用を含む）。
- 節点の種類（見出しとその段の数、段落、リストとその記号、引用、表とセルの揃え、コードブロック）が違う。
- 改行（行末の 2 つの空白や `<br>` から作った改行）の数が違う。
- コードブロックの中身が違う（入れ物の中のコードブロックも比べる）。
- 画像の行が違う（alt、パス、title を含めて文字どおり）。
- ブロックごとの、リンク先の URL の多重集合が違う。
- ブロックごとの、インラインのコードの多重集合が違う。
- 表の行の数と列の数が違う。raw の表の行に、見出しより多いセルがある（`freeze` と同じ）。
- リストの項目の数が違う。
- 訳さないページで、ブロックの文字列が違う（補足を除いて、本文は 1 文字も変えない）。
- 取得した画像の行の次に補足がないか、2 つ以上ある。取得できなかった画像の行（`（未取得）` の付いた行）に補足がある。
- 補足の表示名が補足ごとに違う。訳すページで、表示名が `translated_by` と違う。

警告（終了コード 0 のまま、出力に並べる）:

- ブロックの訳文に、元のブロックにない英字か記号（`<`、`>`、`=`、`!`、`&`、`|`）を含む並びが現れた（`<>` の追加など）。
- 元のブロックの、文の先頭以外にある大文字で始まる語か、CamelCase の語か、すべて大文字の語が、訳文のブロックにない（`Greenwich`、`BoundedContext` の訳など）。見出しと表のセルでは、語ごとに大文字で始まるので、CamelCase の語とすべて大文字の語だけを調べる。よく使う機能語（`The`、`In` など）は数えない。
- です・ます調の文とである調の文が、どちらも全体の 1 割を超える。
- 訳文のブロックの文字数が、元のブロックの 0.2 倍に満たない（値は試験で決める）。

`check --finish` は、誤りも警告もなければ作業用のフォルダーを消す。警告は、モデルが直して再検査するか、残す理由を `<WIKI_ROOT>/log.md` の取り込みの行のサブ行に書いてから `--finish --accept-warnings` で消す（写しは再検査の基準なので、直す作業が残るあいだは消さない。実装 8 回目）。

### 限界

- **削除の正しさ**: 削除の段で消したものが本当に雑音かは、検査できない。本文の段落や、リンクだけの段落を消しても通る。消したものは出力と `removed.json` に並ぶので、モデルが確かめる。消した量が多ければ警告する。
- **訳の中身**: 原文にない内容の追加、固有の名前の訳、ブロックの中の文の訳し落としは、警告でしか見つからない。文字列の形から推し量るしかなく、誤りにすると正しい訳も止めるためである。
- **ブロックの順**: 同じ種類の段落を入れ替えても、リンクやコードを含まなければ、検査では分からない。
- **雑音の規則**: 規則が本文を消しても、`fetched.md` にはその本文がないので、後の検査は通る。規則は当たる範囲を狭くし、消したものを `removed_by_rule` に示す。気づいたら `--keep-noise --force` で取り直す。

### 取り込みの手順

`commands/ingest.md` の「Web ページの取り込み」と、`ingest-workflow.md` の「Web ページ」を、次の順に書き直す。

1. スラッグを決める。
2. `wiki_fetch.py` で取得する（ブラウザで取った HTML なら `--html-file` と `--page-url` も付ける）。
3. 出力の `removed_by_rule` を見る。本文を消していれば、`--keep-noise --force` で取り直す。
4. 残った雑音を、文字列を消すことだけで削る。コードブロックの中は変えない。飾りの画像は、行とファイルを消す。
5. `wiki_rawcheck.py freeze` を実行する。誤りがあれば直して、もう一度実行する。出力に並ぶ消したものを見て、本文を消していないかを確かめる。
6. `needs_translation` が真なら訳す。画像の補足を書く。
7. `wiki_rawcheck.py check` を実行する。誤りがあれば直して、もう一度実行する。警告は、直すか、理由を残す。
8. `check --finish` で作業用のフォルダーを消し、取り込みの手順 3 以降に進む。

### 試験

親のリポジトリの `tests/wiki/` に置く。

- `test_wiki_fetch.py` に足す: 雑音の規則（4 ページの形を模した HTML。規則に当たる要素と、当たらない対照。MediaWiki でないページの `metadata` の表、本文の中のタグのリンクと `Top highlight` の段落は残る）、`--keep-noise`、`--html-file` と `--page-url`（相対リンクと画像の基準、UTF-8 でないファイルの拒否）、作業用の写しと `fetch.json`（raw より先に書く、`work_dir`）、`needs_translation`（`lang="ja"` の英語の本文）、スラッグの拒否。
- `test_wiki_rawcheck.py` を足す: `freeze` の許す編集（行の削除、1 行の中の複数か所の削除、見出しの削除、共有の画像ファイルの片方の行だけの削除）と止める編集（書き足し、書き換え、並べ替え、題名の削除、コードブロックの中の削除、インラインのコードやリンクの一部の削除、frontmatter の変更、参照の残るファイルの削除、参照のないファイルの残り）。`check` の誤りの各項目と、警告の各項目、それぞれの対照（リストと引用の中の画像に、同じ入れ物で補足を付けた訳が通る、など）。作業用のフォルダーがジャンクションのときに消さないこと。
- 比較の 12 実行の raw を、手で試料にして確かめる（リポジトリには入れない）。Haiku の SQLite（コメントの訳、リンクの欠落）と Sonnet の SQLite（リンク 2 か所の欠落、`<>` の追加）が、`check` で誤りと警告になること。

## 入れないもの

- 中間表現、タグ、`apply`、錠（大の案）。
- 同時の取り込みの排他（今と同じく対象にしない）。
- `NOISE_WORDS` が本文の節を落とす今の不具合（id に `cookie` を含む節など）。別に直す。
