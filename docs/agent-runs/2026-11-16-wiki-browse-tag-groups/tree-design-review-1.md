参照 JS は、葉で Enter を押した場合も `preventDefault()` を呼ぶことを確認しました。設計本文の「リンクの既定の動き」と食い違うため、これは分類 B として扱います。設計自体については、葉をクリックした後の `tabindex` の同期と、ページ以外の葉の構造に記述の穴が残っています。
## 判定

**条件付きで採用可。確信度：中。** 分類 A の致命的・重大な反例は崩せなかった。ただし、参照 JS には本文の約束を破る Enter 処理があり、ページ以外の葉の構造とフォーカス管理には解釈の余地が残る。

## 致命的・重大な欠陥

### 1. 【分類 B／重大】参照 JS をそのまま移すと、葉を Enter で開けない

- **反例**：`a.fui-TreeItem[role=treeitem]` にフォーカスして Enter を押す。
- **結果**：参照の `enhanceTree` は葉にも `toggle(item)` を実行し、末尾の `ev.preventDefault()` に進む。`toggle` は葉では何もしないため、リンクの移動だけが取り消される。
- **根拠**：`.claude/skills/fluent2-html-replica/assets/fluent2.js:1351`、`:1384`、`:1396`。
- **照合結果：食い違い**。対象設計の `:90` は参照と「同じ操作」とする一方、`:99` は葉の Enter をリンクの既定動作に任せる。抽出した実際の関数を DOM の最小スタブで実行し、葉の Enter で `defaultPrevented=true` になることを確認した。

本文の葉の規則自体は正しいため、分類 A には数えない。

## 崩れる前提

- **「TreeItem を付ければ、葉にも必要な表示が付く」**
  
  フォーカス枠・最小高さ・字下げはいずれも子の `.fui-TreeItemLayout` に依存する。これを持たない葉では成立しない。`fluent2.css:11604`、`:11609`、`:11628`、`:11723`。

- **「葉のクリックはネイティブ動作だけでローヴィングと整合する」**
  
  索引のタグをクリックしてもページの再読み込みは起きない。クリック先にフォーカスが移っても、ネイティブ動作はその葉の `tabindex="-1"` を 0 に変えない。別途同期がなければ、実際のフォーカスと Tab の入口が別項目になる。対象設計 `:94`、`:103`。[APG もポインター操作時の同期を明示している](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/#kbd_roving_tabindex)。

- **「同じ class なら `div` を `a` に替えても同じ見た目になる」**
  
  Tree の CSS はリンクの既定の下線を解除していない。HTML 要素の既定表示までは class だけで消えない。

## 見落としと軽微な問題

### 2. 【分類 A／軽微】リンクにした葉に、既定の下線が残る

通常のブラウザー設定で、設計どおりの `a.fui-TreeItem` を表示すると、ページ名などにリンクの下線が付く。

`fluent2.css:11594` からの Tree 規則には `text-decoration` の指定がなく、既存の `style.css` にもこのアンカーに当たる解除規則がない。以前の `.fui-NavSubItem` は `fluent2.css:11028` で下線を解除していた。

対象設計 `:64` の要素変更によって生じる、明記されていない見た目の差である。ブラウザー実測ではなく CSS の静的照合による判断。

### 3. 【分類 C／軽微】ページ以外の葉の内部構造が確定していない

対象設計 `:64` はページの葉に Layout と main を明記するが、`:65`～`:69` のグループへの項目、未解決・曖昧、索引のグループ、「すべてのページ」には書いていない。

これらを文字直置きとして実装すると、次の結果になる。

- TreeItem 自身のフォーカス枠は消え、代わりの Layout の枠も出ない。
- Layout の字下げ・最小高さが効かない。
- 参照 JS の文字検索が main を見つけられない。

「すべての葉でページと同じ内部構造を使う」という省略表現かどうかを確定できないため、設計の重大欠陥とは判定しない。根拠は `fluent2.css:11604`～`:11613`、`:11723`～`:11727`、参照 JS `:1391`。

### 4. 【分類 C／軽微】ローヴィングの更新契機と試験に穴がある

対象設計 `:103` は枝のクリックだけに `tabindex="0"` への変更を指定している。索引の葉をクリックした後、Tab で外へ出て Shift+Tab で戻る手順では、クリック前の項目が入口として残りうる。

また、4 節には次の確認がない。

- 枝 → Tab →「一覧」→ Enter の一連の操作。
- 葉のクリック後の Tab の入口。
- `aria-level="11"` 以上。深さの試験は 6 段だけである。

## 検証した事実

| 主張 | 結果 |
|---|---|
| `a` の TreeItem、`span` の Layout に Tree の CSS が当たる | **一致**。該当規則はタグ名を限定せず、class・属性・親子関係で指定している |
| `tree-deep` で 11 段以上も字下げを止められる | **一致**。変数を項目自身で 4 に指定すれば、Layout の計算に使われる |
| actions 内のリンクへフォーカスした後も表示を保てる | **一致**。`fluent2.css:11748` は Layout 内の `:focus-visible` も表示条件に含む |
| `a[role=treeitem]` と `aria-current="page"` の併用は不正 | **不一致**。[WAI のナビゲーション Tree の例](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/examples/treeview-navigation/)でも使われている |
| 件数の文字色が押下時に必ず 4.5:1 を割る | **不一致**。light の `#616161`／`#e0e0e0` は約 **4.69:1** |
| ブラウザー・支援技術での実動作 | **確かめられず**。ブラウザー起動は読み取り専用環境で一時ディレクトリの作成を拒否された。実機読み上げも未確認 |

## 崩せなかった点

- CSP を保ったまま、class・ARIA・`tabindex` で開閉と移動を実装する方針。
- ローヴィングによって Tab の停止数を減らし、矢印キーで各項目へ移る方針。
- 索引の枝で、名前の操作を絞り込み、シェブロンを開閉に分けること。[APG の Tree 規約](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)は Enter の既定操作を開閉だけに限定していない。
- `aria-disabled` の葉を矢印キーでフォーカス可能にすること自体。
- 木の外にある検索結果と、スクリプトなしの表示を維持する方針。
