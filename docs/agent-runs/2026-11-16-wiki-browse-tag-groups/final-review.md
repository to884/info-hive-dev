## 崩れる前提

- **記事を直接持つグループは必ず葉である。** `app.js:408` は葉にだけ現在の印を付けるため、ページと子グループを併せ持つデータでは印が消える。ただし、同版の `_nav_tag_stage()` と `_check_tree()` がこの形を排除している。通常の生成結果に反例は見つからなかった。
- **保存不能時は、保存先を読み直しても値を得られない。** 設計 7 節の「読み直すと OS の設定に戻る」は、読み取り可能・書き込みだけ失敗する状態では成立しない。既存の保存値を読み直すためである。これは失敗を伴う条件なので、指定された分類 A には含めない。根拠：`theme.js:23–41`。

## 見落としと軽微な問題

1. **分類 C・軽微：設計書に改訂前の操作と試験条件が残っている。**  
   `docs/plans/wiki-browse-tree-2026-11-16.md:135–140` は、現在のページ項目の `aria-current="page"`、枝から「一覧」への Tab、記事の枝を押して開閉、9 段までの表示を試験するとしている。9 節ではページ項目と「一覧」を廃止し、枝の名前は Index への移動に変更した。実装と実際の試験は後者に一致し、深さの試験も `findability.test.mjs:399–408` では 8 段以上を検査する。**文書内の食い違いを確認した。**

2. **分類 C・軽微：テーマ試験は、暗い OS から明るい表示へ切り替える経路を検査していない。**  
   `findability.test.mjs:829–835` は暗い OS で初期状態を確認するだけで、トグルを操作しない。例えば保存式を誤って `want === "light" ? "auto" : want` にしても、現在のテーマ試験の操作列では検出できない。暗い OS でオフにすると `light` を保存すべきところ、`auto` に戻って暗いままになる反例である。**これは試験の網羅の指摘であり、現実装の式は正しい。**

3. **分類 C・軽微：トグルのキーボード操作と強制カラーの表示は、テーマ試験の検査対象に入っていない。**  
   `themeChecks()` はクリックで操作し、`colorChecks()` の強制カラー検査は現在グループの輪郭だけを読む。トグルのフォーカス輪、つまみ、ラベルを押せる範囲の描画不良は、これらの検査では検出できない。根拠：`findability.test.mjs:787–852`。実際に表示が壊れるとは確認していない。

## 検証した事実

- **一致：** ファイルを作らず `Snapshot` を組み立て、中核と参照実装の **30 ケースすべて**で、ID、名前、要約、件数、項目、子の構造が一致した。タグの追加ケース 11 件を含む。
- **一致：** `theme.js` と実装の `themeField()` を JavaScript VM で実行した。http／file、明暗それぞれの OS について、反対色の保存、再読込、`auto` への復帰、OS 変更への追従を確認した。保存先の読み書きが例外になる条件でも、当該ページへの適用と再読込時の `auto` を確認した。ブラウザの実ストレージを使った検証ではない。
- **一致：** `groupHref()` は記事では `href("index.html")` に断片を付ける。`root` を二重に付ける経路は見つからなかった。
- **一致：** 画面の生成文字列に残る「索引」は、検索の索引を指す文言だった。指定された Index 改名の漏れは見つからなかった。
- **確かめられず：** 実描画でのコントラスト、強制カラー、クリック範囲、フォーカス輪、ブラウザ固有の file ストレージ動作。Playwright は一時ディレクトリ作成時の `EPERM` で起動できなかった。
