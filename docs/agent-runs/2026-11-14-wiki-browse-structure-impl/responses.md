# browse の構造の直しの実装: レビューの指摘と対応

[設計（8 版目）](../../plans/wiki-browse-structure-2026-11-11.md)の実装（2026年11月14日）の記録である。

## 実装の前の確かめ（設計の 12 の 1）

- 黒箱の道具（`tests/wiki/browse_blackbox.py`）を、直す前の main（info-hive-wiki 5adb069）に当てた。失敗のない実行で 124 件の違反があった（[blackbox-before.md](blackbox-before.md)）。主なものは、`seq` と `build-report.json` の残り、ロックと目印の名前のリンクで止まる、`gen+extra`・`gen+edited`・`legacy` の `--out` を置き換える、`<data_dir>/browse` がリンクのときにその先を使う、`stop` が根のリンクで砂場を変える、である。どれも設計の 10 で振る舞いを変える点で、直したあとは 0 件になった（[blackbox-after.md](blackbox-after.md)。4 件は試験の側の基準の誤りで、直した）。
- 過去の 17 件の指摘（設計の 9.7）を、直す前のそれぞれのコミットで道具に当てることはしていない。直す前のコードは、層の口を持たないので、口に手を入れる探索を当てられない。黒箱の道具は失敗のない実行だけを量る。17 件は、対照（設計の 9.5）を層の中に置き、探索がそれを見つけることで確かめた（`browse_sweep.py` の CONTROLS と、`browse_read_sweep.py` の対照）。

## 実装で決めたこと（設計に書いていなかったこと）

| 決めたこと | 理由 |
| --- | --- |
| 初めての 2 つの書き出しや起動が同時に走り、`<data_dir>`、領分の根、状態のディレクトリを作る `mkdir` と、目印を作る排他の作成が `FileExistsError` で失敗したら、名前の種類を見て、ほかの browse が作ったものとして続ける | 0.10.0 の試験（同時の serve、同時の入れ子の書き出し）が通らなくなった。設計の 2.2 は競合を範囲の外とするが、0.10.0 が通していた振る舞いを後退させない。別の口で作り直すことはしない（3.2） |
| `stop` は、止めたサーバーが終わったあと、その instance と持ち主の記録が残っていれば消す | Windows で、記録を読んでいるほかのプロセスがいると、サーバー自身が記録を消せない（同時の 2 つの `stop` の試験）。設計の 7.1 の「終了と stop は記録を消す」に沿う |
| `--out` は、browse のデータの場所と重ならない場所にする（中にも、含むにもしない） | 0.10.0 と同じ。設計の 10 に変える点として挙げていない |
| POSIX では、状態のディレクトリを 0700、記録を 0600 で作る | 0.10.0 と同じ。トークンを持つ |
| 対照は、層の中の `MUTANTS` の集合で持つ | 対照を層の中にも置く（設計の 9.5）。空なら働かない |
| `wiki_initialized`（ADR-0019）は、層の外の入出力のまま使う | 設計を書いたあとに入った。`wiki_pages` の読み込み（3.3）と同じく、層の外に残す |
| マニフェストに `incomplete`（読めないページ、索引、オントロジー）を足した。ナビゲーションには `incomplete` を足した | 「不完全」を、データでも示す（守ること 9）。`app.js` は知らないキーを読まない |
| `App.touch()` を `mark_activity()` にした | 構文木の検査が、`Path.touch()` と見分けられない |

## 5 回目（[impl-review-5.md](impl-review-5.md)、Sol、却下。確信度は中）

前回までの直し（根そのものへの入れ子、確定のあとの `Stop`、`stop` のあとの片付け、標準出力と標準エラーの閉鎖）は、崩れなかった。4 回目の直しのコードに当てた探索の全量（[sweep-6](sweep-6/)。書き出しの 137 の状態で 243,034 回、サーバーの記録などで約 27,000 回、読む側で 2,552 回）でも、破れた決まりは 0 件で、対照はすべて見つかった。

| 分類 | 指摘 | 崩れた前提 | 対応 |
| --- | --- | --- | --- |
| A | 重大 1: Windows の 8.3 の短い名前で、まだない `<data_dir>` を `--out` に指すと、作る前の判定が重なりを見落とし、`<data_dir>/browse` と共通のロックを作ってから拒む | まだない場所の重なりは、今ある祖先の識別子と、まだない名前の比較で決まる | 作者の決定で、比べ方を詰めるのをやめ、「拒むときは、その実行で作った空のディレクトリを取り除いて戻す」形にした。名前の別名（8.3 の短い名前、大文字と小文字、Unicode の正規化）は、作る前には見分けきれないからである。領分の根に入ったあと、共通のロックのファイルを作る前にもう一度判定し、拒めば、その実行で作ったディレクトリを新しいほうから `rmdir` で取り除く（`_enter_root_then_check`、`_rollback`）。`rmdir` は空でなければ失敗するので、ほかのプロセスが中に置いたものは残し、警告を出す。起動も同じにした。実際の 8.3 の短い名前を使う試験（作られる環境だけで流す）と、取り除かない対照（`no_rollback`）を足した。取り除いたディレクトリの親の更新時刻は変わる（設計の 2.1 が守る対象から外している） |

| ― | 軽微: 設計の 9.1 の「何も変えない」と、6.4 の手順（拒む前に、領分の根、共通のロック、作業用のディレクトリを作る）が、文の上で食い違う | ― | 実装と試験は、領分の中の変化を許す（2.1）。設計の 9.1 の文は、「砂場の全体」ではなく「領分の外」と読むのが 2.1 と合う。設計の文の直しは、作者の判断に回す |
