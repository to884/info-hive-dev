# ADR-0025 の段階 2 の実装のレビュー（2 回目）

## 目的

1 回目のレビュー（`review-1.md`）の指摘を直した。直し方が原因を取り除いているか、新しい欠陥が入っていないかを壊してほしい。範囲と前提は `task-1.md` のとおりである。

## 1 回目の指摘と直し方

1. **移す途中で止まると、描画の識別が変わったあとにもう一度移す（重大）:** 印（`ocr/adopted.json`）を、ページを写す前に書くようにした。元ごとに、移し始めたときの描画の識別と状態（`copying`、`done`）を記録する。写すページの `adopted_render` は、今の描画の識別ではなく印の値を使う。途中で止まった元は、描画の識別が印と同じときだけ続きを写し、変わったあとは写さない。契約の試験に、途中で止める 2 件（同じ描画で続きを写す、描画が変わったら写さずに OCR する）を足した。
2. **設定が原因の失敗を `retry_job` で直せない（重大）:** `retry_job` は登録したときの設定のまま動く。wiki の手順に、失敗の理由が設定のときは、`configure` のあとで `register_pdf` で新しく登録すると書いた。rag の動きは変えていない（ADR の決めたとおり）。
3. **0.4.0 の結果の後始末が 0.4.0 の指紋を作り直せない（軽微）:** `Config.legacy_fingerprint`（0.4.0〜0.5.3 の式）を足し、`_legacy_generations` はこの式で候補を作る。記録した前の方針の指紋が、どちらの式の値でも、その設定の 0.4.0 の式の指紋を候補にする。既定の設定で 0.4.0〜0.5.3 の固定値（`1c61f7d9…`）と同じになることを試験で確かめる。後始末の試験の 0.4.0 の置き場所も、この式で作る。
4. **`always` のときの本文の説明（軽微）:** wiki の手順で、`wiki_pdf.py` と同じになるのは OCR しなかったページだけだと書いた。
5. **保存したページに抽出の識別がない（軽微）:** `judge-*.json` と `page-*.json` に `extraction_key` を入れ、読むときに今の鍵と照らす。

## 見てほしいこと
