# ADR-0025 の段階 2 の実装のレビュー（3 回目）

## 目的

2 回目のレビュー（`review-2.md`）の重大な指摘を直した。直し方が原因を取り除いているかを壊してほしい。範囲は、rag 0.5 の OCR の結果を移す処理（`info-hive-rag/scripts/rag_pdf.py` の `OcrStore.adopt_legacy` と `OcrStore.load`、`extract_pages` から呼ぶところ）と、その試験に絞る。前提は `task-1.md` のとおりである。

## 2 回目の指摘と直し方

- **指摘:** 移す元が 2 つ（`always` と `auto`）あると、1 つ目を移し終えて 2 つ目を印に書く前に止まったとき、描画の識別が変わったあとで、2 つ目の元から新しい描画の識別で移していた。
- **原因:** 「移すのは 1 回、1 つの描画の識別のときだけ」という決まりを、元ごとに記録していた。決まりは文書ごとである。
- **直し方:** 印（`ocr/adopted.json`）の `render` に、最初に移し始めたときの描画の識別を、文書ごとに 1 つだけ、ページを写す前に書く。どの元から写すページも、`adopted_render` はこの値にする。今の描画の識別が印の `render` と違えば、どの元からも写さない。元ごとの状態（`copying`、`done`）は、同じ描画の識別のあいだに途中で止まった元の続きを写すためだけに使う。
- **試験:** `tests/contract/test_rag_contract.py` に、元が 2 つのときに境目で止め、描画の識別を変えると、どの元からも写さずに OCR することを足した。

## 守るべき決まり（ADR の「今の OCR の結果を移す」と試験 3）

1. 移すのは、同じ PDF、同じ `ocr_dpi`、同じ OCR の版の結果だけ。
2. 移した結果は、描画の識別が移したときと同じあいだは使い回す。
3. 描画の識別が変わったあとは、移した結果を使わず、OCR をやり直す。
4. 移した結果を、もう一度移すことはない。

## 見てほしいこと

- 上の 4 つが、どの止まり方（印の書き込みの途中、元の途中、元と元の境目、`done` の前）と、どの順の設定の変更（dpi、pypdfium2 の版、OCR の版、`ocr_mode`）でも守られるか。
- dpi を変えてから戻したとき、OCR の版を変えたときに、印（文書ごとに 1 つ）が邪魔をして、移せるはずの結果を移せない、または移すべきでない結果を移す経路がないか。
- 1、2 回目に挙げられなかった欠陥。
