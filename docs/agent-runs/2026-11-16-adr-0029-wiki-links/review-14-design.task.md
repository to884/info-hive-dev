# 依頼：ADR-0029 の実装の設計（9 版目）の敵対的レビュー

対象は `docs/plans/wiki-links-2026-11-16.md` の 9 版目（main の `d109b61` に入った版）である。応答は日本語で書く。ファイルは変えない。

## 位置づけ

ADR-0029（`docs/adr/0029-wiki-and-raw-hold-no-links.md`、状態は提案）は、決定と不変条件（I1〜I7）だけを持つ。8 回目のレビュー（`review-8-adr.md`）で、ADR は採用可（確信度：中）になった。本設計書は、それを関数、欄、手順、試験に落とす。作者は 9 版目でいったんレビューを止めたが、9 版目の直しがレビューを受けていないので、改めて頼む。

## 前回のレビュー

前回のレビュー（`docs/agent-runs/2026-11-16-adr-0029-wiki-links/review-13-design.md`、却下）の重大 2 件を、9 版目で直した。

1. raw の根の記録（`raw-roots.d/`）を、書く段の管理領域の下に置いていたため、書く段の許すパスとぶつかった。
2. リンクの判定を中身を読むより前にする順番を、守る木の中の候補にしか当てておらず、今の raw の根の外にある rag でない raw には届いていなかった。

直し方が原因を閉じているか、直しで足した仕組みが新しい失敗を生んでいないかを、とくに確かめる。設計書が「レビューを受けていない」と挙げる、`resolve_raw()` の順番と身元と版の照らし方、raw の根の記録、書く段との接続（完全性の順番、記録の置き場所）を重く見る。

## このレビューで見ること

- 設計が、ADR の不変条件 I1〜I7 を満たすか。どれかを破る配置や操作の順がないか（冒頭の対応表から節をたどる）。
- 設計が、今のコードと、書く段の設計（`docs/plans/wiki-apply-2026-11-14.md`）に対して成り立つか。書いてある行番号と振る舞いが合うか。
- 記事、走査の `Walk.links`、記事を読む口、`resolve_raw()`、依存の完全性、raw の根の記録、書き込みの部品の契約が、互いに食い違っていないか。届かない読み手や書き手、黙って「ない」になる経路が残っていないか。
- 試験の一覧で、設計の要の振る舞いが確かめられるか。

ADR-0029 と本設計書の 1〜13 回目のレビューと修正案（`docs/agent-runs/2026-11-16-adr-0029-wiki-links/` の `review-*.md`、`proposal-1.md`、`summary.md`）と同じ指摘の繰り返しは除く。作者の決定（ADR の 1〜10）は崩す対象ではない。

重大の指摘には、発生の度合いを添える。A（仕様の矛盾か欠落で、実装すれば必ず踏む）、B（日常の使い方で起きうる）、C（まれな時機や名前）、D（作為的な配置が要る）。
