対象は、Claude Code プラグイン wiki（info-hive-wiki）の Web ページの取得器 `wiki_fetch.py` で、途中の取り込みを取得の前に再開するようにした実装の 5 版である。設計書は `docs/plans/wiki-fetch-resume-before-fetch-2026-11-14.md`（5 版）。これまでのレビュー（同じフォルダーの `design-review-1.md`、`impl-review-1.md`、`impl-review-2.md`、`impl-review-3.md`）と、設計書の「改訂の履歴」に、指摘と直し方がある。

差分は `docs/agent-runs/2026-11-14-wiki-fetch-resume/impl-4.diff` にある（worktree の中）。info-hive-wiki はサブモジュールで、変更はコミット済み（`git -C info-hive-wiki diff origin/main...HEAD`。origin/main はリリース済みの 0.14.1）。試験は親の `tests/wiki/test_wiki_web_check.py` の `ResumeBeforeFetchTest`。

5 版で変えたこと（4 版から）:
- 4 版の実装レビュー（`impl-review-3.md`）の重大 2 件は、0.14.0 の写しを続ける互換の経路のものだった。この経路を捨てた。`fetched_sha256` と `source_sha256_of` を取得の記録の必須のキーにし、0.14.1 までの版が書いた写し（どちらのキーもない）では、どちらの枝でも続けない。
- W2 の文を「URL だけで呼んだときに途中の取り込みがあれば、取得せずに返す」に直し、`"work_dir": false` に旧版の写しを含めた。CHANGELOG に互換でない変更として書いた。
- 試験の旧版の記録を、実際の旧版の形（両方のキーがない）にした。別の設定で取った旧版の記録を丸ごと戻す場合も足した。
- そのあと、main の #56（`/wiki:help`）と #55（0.14.1）をマージし、「0.14.0 が書いた写し」を「0.14.1 までの版が書いた写し」に直した（0.14.1 も同じ取得器のままリリースされた）。

保証（設計書の「前提」。4 版から変えていない）:
- 保証するのは整合である。写しのファイルの組（`fetched.md`、`fetch.json`、あれば `cleaned.md`）と raw が、1 つの取得と、その取得のあとの `freeze` が残しうる組のときだけ続ける。どこで止まっても、写しのファイルの一部を丸ごと別の取得のものに置き換えても、この組でなければ続けない。
- 取得の出自は保証しない。別の設定でも `fetched.md` が同じバイト列になる 2 つの取得は、どちらの `fetch.json` で続けても正しい組とする。別の取得の `cleaned.md` でも、今の `fetched.md` のあとの `freeze` が通す内容なら、正しい組とする。
- 作業用の写しは `wiki_fetch.py` と `wiki_rawcheck.py freeze` だけが書く。ファイルの中を手で書き換えたものは前提の外である（形の違う `fetch.json` で例外にならないことは守る）。

目的:
- `--html-file` で取ったページの取り込みを URL だけで再開でき、ネットにつながらなくても続けられること。
- 写しがないとき、続けられない写しのとき、`--force`、`--html-file`、別の URL のときは、取得して比べること。
- 続けるときに、最後に終えた段の出力と `source_sha256_of` を返し、手順書（`info-hive-wiki/commands/ingest.md` の W2・W3・W5、`info-hive-wiki/skills/info-hive/references/ingest-workflow.md`）がその確かめの段から続け、ループしないこと。
- `freeze` から切り出した `deletion_errors` と `deletion_report` で、`freeze` の出力が変わっていないこと。
- 互換を捨てたことが、CHANGELOG、手順書、文字の出力で、利用者に正しく伝わること。

判定の基準: 上の保証に反する反例（続けてはならない組で続ける、続けてよい組を続けない）を重大とする。保証の外のもの（出自、手で書き換えたファイルの中）と、設計書の「限界」に書いたものは、軽微か範囲の外とする。0.14.1 までの版の写しを続けないこと自体は、意図した変更として承知している（それが利用者に伝わらない、または新しい版の写しまで続けなくなる、という反例は重大とする）。

特に崩してほしい点:
- 5 版で互換を捨てたことで、新しい版が書いた正しい写しを続けなくなる反例。0.14.1 の main のマージで、frontmatter の読み方（`wiki_text.py`、`wiki_pages.py` の変更）が再開の照合に影響していないか。
- `resumable_fetch` の条件（設計書の 5〜10）で、保証に反する反例。
- 取得の前の再開と、取得して比べる枝の、出力と文字の出力の食い違い。
- 手順書の流れの矛盾、ループ、詰まり。
- 試験の抜けと、試験が実装の誤りを見逃す書き方。
- CHANGELOG の記述と実装の食い違い（0.14.1 の節との位置関係を含む）。
