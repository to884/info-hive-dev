## 判定

**却下。確信度：高。** 旧版の写しが存在しても、`--html-file` の読み込みで失敗すると、続けられないことが通知されない。依頼で指定された「旧版の写しがあるのに知らせない」反例に該当する。

## 致命的・重大な欠陥

1. **重大：`build` が `OSError`・`ValueError` を上げる経路では、旧版の写しへの通知が抜ける。**

   再現手順：

   - raw と、対応する旧形式の `fetched.md`・`fetch.json` を残す。`has_old_work_dir(...) == True` になる状態である。
   - 同じ URL・スラッグで、`--force` を付けず、次のいずれかを指定する。
     - 存在しないファイルを `--html-file` に渡す。
     - UTF-8 として読めないファイルを `--html-file` に渡す。
   - `--page-url` と `--json` も指定する。

   メモリ上のファイル操作による再現結果：

   | 入力 | 終了コード | 標準出力 | 標準エラー |
   |---|---:|---|---|
   | 存在しない HTML | 1 | 空 | 「ファイルを書けない」のみ |
   | UTF-8 でない HTML | 1 | 空 | 「UTF-8 で保存した HTML にする」のみ |

   **どちらにも `old_work_dir`、旧版では続けられない旨、途中の作業が消える旨が出ない。** 旧版の写しの内部を書き換えることを必要としない反例である。

   原因は、通常の旧版判定が HTML の読み込みより後にあり、例外時の旧版判定を `FetchError` のハンドラーだけで行うことにある。

   根拠：

   - `info-hive-wiki/skills/info-hive/scripts/wiki_fetch.py:1291`：ファイル読み込み。
   - 同 `1294–1297`：UTF-8 不正時の `ValueError`。
   - 同 `1309`：通常経路の旧版判定。
   - 同 `1597–1614`：`ValueError`・`OSError` では旧版判定も通知もしない。
   - `docs/plans/wiki-fetch-resume-before-fetch-2026-11-14.md:80`、`info-hive-wiki/CHANGELOG.md:15`：取得の結果によらず知らせるという記述とは、この経路で食い違う。

## 崩れる前提

- **取得の失敗は、旧版通知を備えた `FetchError` のハンドラーを通る。**  
  HTML ファイルが消えている場合は `OSError`、文字コードが違う場合は `ValueError` を通る。重大1で確認した。

- **JSON を読めなかった場合の例外は `JSONDecodeError` である。**  
  Python の整数変換制限でも `ValueError` が発生する。下記の軽微な問題で確認した。

## 見落としと軽微な問題

1. **軽微：旧版判定の例外が、取得失敗の処理そのものを壊す場合がある。**

   `fetch.json` を、数値が5000桁の次の JSON にする。

   ```python
   '{"x":' + '1' * 5000 + '}'
   ```

   整数変換制限が既定の4300桁である環境では、`old_version_work_dir` が `ValueError` を上げる。さらに、`--html-file` に HTML を渡して `--max-bytes 1` とすると、取得失敗を処理する `main:1602` からこの例外が漏れ、**標準出力・標準エラーとも空のまま未処理例外になる**ことを再現した。

   `work_dir_complete:149` と `old_version_work_dir:367` は、この `ValueError` を捕捉しない。手で変更した内容なので重大とはしないが、「形の違う `fetch.json` で例外にならない」という例外処理の保証には反する。

2. **軽微：通知試験の「every_outcome」は例外経路を網羅していない。**

   `tests/wiki/test_wiki_web_check.py:1707–1738` は、通常の終了コード0・3と、明示的に `FetchError` を投げる取得失敗を検査する。HTML の読み込み失敗と文字コード不正を検査しないため、重大1が残る。

   同 `1916–1937` の不正JSON試験も、キーと型の違いだけを扱い、JSONの読み込み自体が `ValueError` を上げる場合を検査していない。
