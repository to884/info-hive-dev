# 3 回目のレビューの目的

`docs/plans/wiki-walk-excluded-dirs-2026-11-11.md` の 3 版目を壊してほしい。`info-hive-wiki` のスクリプトが wiki のディレクトリをたどる経路を 1 つにまとめ、最上位の除くディレクトリ（`raw/`、`assets/` など）に降りないようにする設計の案である。実装はまだない。

2 版目は、このセッションでの自分のレビュー（`docs/agent-runs/2026-11-11-wiki-walk-excluded-dirs/design-review-2.md`）で却下された。2 回続けての却下を受けて、これまでの指摘を、崩した前提で分けた（`root-causes.md`）。3 版目は、その「構造を変える案」から書き直したものである。作者は 2026年11月11日に、「同じディレクトリかどうかは、識別子だけで決める。文字列の比較への逃げ道を残さない」と決め、その代償（設計の「決めること」の 5 の表の下の 2 行）を受け入れた。

## 設計が果たすべきこと

- wiki をたどる経路を `wiki_pages.py` の 1 つのたどり方にまとめ、ページと索引のファイルを同じたどり方で集める。
- 最上位の除く名前の項目には、種類を調べる呼び出しもしない。
- 失敗のないとき、ページの集合と並びを今と同じにする。違いは、設計の「決めること」の 7 の表に挙げたものだけにする。
- 失敗を「ない」「分からない」「そのほか」の 3 つに分け、1 か所で読み替える。権限の失敗と、識別子が 0 のときは、必ず知らせ（`unlistable` か `unknown`）になる。そのほかの `OSError` は送出する。
- 走査が OS を呼ぶ口を、内側で失敗を扱わない呼び出しだけにする。パスの文字列を比べて、同じ場所かどうかを決めることは、どこでもしない。
- 「閉じないこと」に挙げた動作（ページのディレクトリのジャンクションの先をたどる、ファイルのシンボリックリンクを読む、lint などが知らせを見ない、たどる間の変化を呼び出し元が受ける）は、設計が意図して残すものである。それ自体を欠陥として挙げるのではなく、その宣言と矛盾する記述や、宣言の範囲を超えて残る経路を挙げてほしい。

## 確かめてほしい点

1. 2 回目のレビューの重大 3 件と軽微 2 件が、3 版目の本文と試作で本当に解消しているか。対応の表の書き方ではなく、本文の決定と試作を見て判断する。
2. `root-causes.md` の 4 つの前提（A〜D）が、3 版目で本当になくなっているか。同じ前提に頼る箇所が、本文、試作、試験のどこかに残っていないか。とくに次の 2 つを見てほしい。
   - 口の表（「決めること」の 1）が、各呼び出しの内側での失敗の扱いとして書いたことに、誤りや抜けがないか。`DirEntry.is_symlink()`、`is_dir()`、`stat()`、`os.stat()`、`os.scandir()` の反復と閉じるときについて、CPython 3.10〜3.14 の実装と照らす。
   - 識別子だけで同じ場所を回る道筋を見つける規則（5）に、誤りがないか。循環を見逃す入力、輪でないジャンクションを誤って飛ばす入力、識別子が分からないのに知らせが出ない入力がないか。「ジャンクションを通るまでは、識別子を比べなくてよい」という主張が崩れる入力がないか。
3. 失敗のないとき、今の `iter_page_files()` と `index_files()`（info-hive-wiki のコミット `f0a758f`）に対して、7 の表のほかに、集合か並びが変わる入力がないか。Windows、macOS、Linux、Python 3.10 以上で考える。
4. 呼び出し元との約束（9）が、走査の本文と矛盾しないか。約束が成り立たない入力がないか。
5. 試験と探索（「試験」の節と `walk_v3.py`）。木から答えを計算する作りで、見つけられない誤りの形がないか。答えの計算（`model()`、`answer_with_failure()`）そのものが走査と同じ読み違いをしている箇所がないか。差し替え（`Injector`）が数えていない呼び出し、失敗を入れられない呼び出しがないか。対照が足りるか。
6. 「検証環境の値」と背景の実測の表に、保存された出力（`results.md` の「3 版目のための実測」より下）と食い違う記述がないか。試作と本文の違いのうち、設計が挙げていないものがないか。
