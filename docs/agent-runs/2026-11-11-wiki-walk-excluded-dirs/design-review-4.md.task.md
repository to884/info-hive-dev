# レビューの目的

`docs/plans/wiki-walk-excluded-dirs-2026-11-11.md`（4 版目）を壊してほしい。実装はまだない。

## この設計は何か

`info-hive-wiki` は、Claude Code のプラグイン `wiki` の本体である（このリポジトリのサブモジュール。今のコミットは `f0a758f`、0.10.0）。Markdown の wiki のページを、lint、search、グラフの抽出、stats、MCP の索引、閲覧（browse）が集める。今は、それぞれが `Path.rglob()` などで wiki の全体をたどり、ページでない最上位のディレクトリ（`raw/`、`assets/` など）の下も列挙してから除いている。

この設計は、wiki をたどる経路を `wiki_pages.py` の 1 つのたどり方（`walk_markdown()` と、その上の `walk_pages()`、`walk_index_files()`）にまとめ、除くディレクトリには降りないようにする。あわせて、OS の呼び出しの失敗を「ない」「分からない」「そのほか」に分けて、1 か所で読み替え、たどれなかった場所を知らせとして返す。Windows のジャンクションが同じ場所を回る道筋も、識別子（`st_dev` と `st_ino`）だけで見つけて降りない。

- A: 標準ライブラリの関数を 1 つ呼べば、失敗は外へそのまま出てくる
- B: パスの文字列で、同じものかどうか、どちらが先かを決められる

作者が決めたこと（2026年11月11日）: Raw の大きさの機能の前に、別の変更として直す。browse は自分で走査を持たず、この関数に乗る。同じディレクトリかどうかは識別子だけで決め、パスの文字列の比較への逃げ道を残さない。その代償（設計の「決めること」の 5 の表の下の 2 行）は受け入れた。

## 設計が果たすべきこと

- 第一の約束: 失敗のないとき、走査の結果（`files` と並び）は、wiki の木の作りから決まる答えと等しく、知らせは空である。
- 第二の約束: 確かめた OS と Python の版では、今（0.10.0）の `iter_page_files()` と `index_files()` との違いは、「決めること」の 7 の表のものだけである。
- 最上位の除く名前の項目には、どの口も呼ばない（例外は、`compute_stats()` の `indexes` への `os.lstat()` 1 回）。
- 失敗の読み替えは 1 か所で行う。権限の失敗と、識別子を取る役割での識別子 0 は、必ず知らせ（`unlistable` か `unknown`）になる。そのほかの `OSError` は送出する。
- 走査が OS を呼ぶ口には、内側で扱われる失敗が結果を変えないことを、CPython のソースで示せる呼び出しだけを入れる。

冒頭の「閉じないこと」に挙げた動作（ページのディレクトリのジャンクションの先をたどる、ファイルのシンボリックリンクを読む、lint などが知らせを見ない、たどる間の変化を呼び出し元が受ける）は、設計が意図して残すものである。それ自体を欠陥として挙げるのではなく、その宣言と矛盾する記述や、宣言の範囲を超えて残る経路を挙げてほしい。「作者が決めること」の推奨も、それ自体ではなく、推奨を採ったときに壊れることを挙げてほしい。

## 確かめてほしい点

1. 4 つの前提（A〜D）が、4 版目の本文、試作、試験のどこかに残っていないか。とくに次を見る。
   - 口の表（「決めること」の 1）の各行の、内側での失敗の扱いと「結果を変えない理由」に、CPython 3.10〜3.14 の実装と照らして、誤りや抜けがないか。Windows と POSIX の両方で。
   - 呼び出しの役割と答えの計算（試作 `walk_v4.py` の `expected_calls()`、`answers_with_failure()`、`model()`）が、走査と同じ読み違いをしていないか。走査の動きに頼って答えを作っている箇所が残っていないか。
2. 同じ場所を回る道筋の規則（5）。循環を見逃す入力、輪でないジャンクションを誤って飛ばす入力、識別子が分からないのに知らせが出ない入力、ジャンクションを通らない道筋に識別子の呼び出しをする入力がないか。
3. 第一の約束と第二の約束が成り立たない入力がないか。7 の表にない違いが、確かめた OS と版（Windows 11 の Python 3.10.11、3.12.13、3.13.7、3.14.6、Linux の 3.12.3）で出る入力がないか。
4. 失敗の読み替え（2）の表に、抜けている呼び出し、矛盾する扱い、知らせが出ずにページが欠ける経路のうち設計が認めていないものがないか。
5. 使う側の変更（7、8）と、今の実装（`wiki_stats.py`、`wiki_index.py`、`wiki_lint.py`、`wiki_search.py`）が食い違わないか。
6. 「検証環境の値」と背景の実測の表が、保存された出力（`results.md` の「4 版目のための実測」より下）と食い違わないか。試作と本文の違いのうち、設計が挙げていないものがないか。
