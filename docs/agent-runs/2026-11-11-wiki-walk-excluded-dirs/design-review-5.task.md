## この設計は何か

`info-hive-wiki` は、Claude Code のプラグイン `wiki` の本体である（このリポジトリのサブモジュール。今のコミットは `f0a758f`、0.10.0）。Markdown の wiki のページを、lint、search、グラフの抽出、stats、MCP の索引、閲覧（browse）が集める。今は、それぞれが `Path.rglob()` などで wiki の全体をたどり、ページでない最上位のディレクトリ（`raw/`、`assets/` など）の下も列挙してから除いている。

この設計は、wiki をたどる経路を `wiki_pages.py` の 1 つのたどり方（`walk_markdown()` と、その上の `walk_pages()`、`walk_index_files()`）にまとめ、除くディレクトリには降りないようにする。OS の呼び出しの失敗を「ない」「分からない」「そのほか」に分けて 1 か所で読み替え、たどれなかった場所を知らせとして返す。Windows のジャンクションが同じ場所を回る道筋は、Win32 の呼び出しから直接取る識別子（`win_file_id()`）だけで見つけて降りない。

## 設計が果たすべきこと

- 上の第一と第二の約束。
- 最上位の除く名前の項目には、どの口も呼ばない（例外は、`compute_stats()` の `indexes` への `os.lstat()` 1 回）。
- 失敗の読み替えは 1 か所で行う。権限の失敗と、識別子を取れないことは、必ず知らせ（`unlistable` か `unknown`）になる。木の状態として必ず起きる失敗（解けないリンクなど）では送出しない。そのほかの `OSError` は送出する。
- 走査が OS を呼ぶ口には、内側で扱われる失敗が結果を変えないことを、CPython のソースで示せる呼び出しだけを入れる（W1。対象は CPython の内側までで、Win32 の API の内側と、たどる間に木が変わることは対象の外）。

冒頭の「閉じないこと」に挙げた動作（ページのディレクトリのジャンクションの先をたどる、ファイルのシンボリックリンクを読む、lint などが知らせを見ない、たどる間の変化を呼び出し元が受ける）は、設計が意図して残すものである。それ自体を欠陥として挙げるのではなく、その宣言と矛盾する記述や、宣言の範囲を超えて残る経路を挙げてほしい。「作者が決めること」の推奨も、それ自体ではなく、推奨を採ったときに壊れることを挙げてほしい。
