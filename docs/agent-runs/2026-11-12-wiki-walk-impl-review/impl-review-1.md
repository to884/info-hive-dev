## 判定

**却下。確信度：高。** 新たに一覧へ出す大文字拡張子の索引を、MCP が指定された名前で取得できず、別ファイルを返す反例があります。また、標準的な APFS では試験の正解となる木を作れません。macOS 実機での実行は未確認です。

## 致命的・重大な欠陥

1. **重大：一覧で返した `Upper.MD` を取得すると、`Upper.md` を読む。**

   反例は、大文字と小文字を区別するファイルシステム上の次の入力です。

   ```text
   indexes/Upper.MD  → 本文「UPPER」
   indexes/Upper.md  → 本文「lower」
   ```

   `list_index(root)` は両方を一覧に返します。しかし `list_index(root, "Upper.MD")` は、拡張子が正確に `.md` でなければ `with_suffix(".md")` で置き換えるため、**「lower」を返します**。`Upper.MD` だけなら `FileNotFoundError` になります。仮想 POSIX パスで両方を実行して確認しました。

   根拠：`info-hive-wiki/skills/info-hive/scripts/wiki_index.py:956–963`、`:969–976`。取得側の分岐は既存ですが、この変更が Linux/macOS で新たに列挙するファイルと整合していません。

2. **重大：APFS では NFC/NFD の試験データが上書きされ、正しい走査でも試験が失敗する。**

   `TREES["NFC と NFD の名前"]` は、同じディレクトリに `é.md` と `e\u0301.md` を別ファイルとして作ります。APFS は正規化の違いを区別しないため、後の `write_text()` が先のファイルを上書きします。一方、`model_pages()` と `model_index()` は表の二項目を別ファイルとして数えます。したがってページ側は実際の一件と期待の二件が一致せず、`test_trees` と `test_explore` が失敗します。

   根拠：`tests/wiki/test_walk.py:107–108`、`:147–152`、`:243–256`、`:680–688`、`:735–748`。ワークフローは `macos-latest` を対象にしています。

   APFS の両形式がこの二名の共存を認めないことは、[Apple の仕様](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/FAQ/FAQ.html)で確認できます。**APFS 上の結果は仕様とコードからの判定で、実機未実行です。現在の `macos-latest` の一時領域が APFS である点は推測です。**

## 崩れる前提

- **一覧に返せる名前は、そのまま取得にも使える。** `.MD`、`.mD`、`.Md` を列挙すると崩れます。取得時に別の名前へ変換されます。
- **木の表をディスクへ書けば、表と同じ木ができる。** APFS の正規化を区別しない名前では崩れます。作成側は上書きを成功と扱い、正解側は二件を保持します。
- **構文木検査が通れば、許可した口以外の入出力はない。** 許可リストを判定に使っていないため成立しません。
- **探索の実行数が十分なら、重要な木も検証できている。** 特定の木を飛ばしても、別の木で実行数を満たせます。

## 見落としと軽微な問題

- **軽微：口の許可リストが機能していない。**  
  `PortTests.ALLOWED_ATTRS` は定義されているだけで、`violations()` は禁止名だけを調べます。メモリ上の写しに `os.listdir(start)` を追加したところ、判定は **`[]`** でした。設計で禁止する余分な列挙を検出できません。根拠：`tests/wiki/test_walk.py:855–877`。

- **軽微：試作で検出できた誤実装を検出する保証が減っている。**  
  試作の対照には、識別子が兄弟へ漏れる実装、`os.stat()` の識別子を使う実装、解けないリンクで送出する実装があります。製品試験の `CONTROLS` からはこの三つが落ちています。また、`FileId` がゼロになる試験はジャンクション自身だけで、試作にあった起点のゼロを試していません。根拠：試作 `walk_v7.py:1016–1021`、`:1108` と、`tests/wiki/test_walk.py:593–599`、`:784–804`。

- **軽微：リンク関連の探索が、実行数の条件を満たしたまま黙って欠ける。**  
  Windows でシンボリックリンクの作成だけが拒まれ、ジャンクションは作れる場合、四つの木が `test_explore` の `continue` で消えます。残る十一の木だけでも、木から計算した注入回数の下限は **1,870 回**で、`total > 500` を満たします。この探索では、飛ばした木が unittest の skip としても記録されません。根拠：`tests/wiki/test_walk.py:158–172`、`:735–749`。設計が求めた `WikiIndex.refresh()` の行保持試験もなく、`:954–966` は `stat_signature()` の送出だけを確認しています。

- **軽微：変更履歴の「障害で索引の行が消えなくなった」は範囲が広すぎる。**  
  属性の走査に成功した後、本文の `read_bytes()` が `EIO` になると、`collect_pages()` はそのページを飛ばし、`refresh()` は既存行を削除します。読み込み失敗を注入した実行で、`removed: 1` を確認しました。本文読み取りは設計の範囲外ですが、変更履歴にはこの限定がありません。根拠：差分 `impl-1.wiki.diff:30`、`wiki_search.py:268–271`、`wiki_index.py:853–864`。
