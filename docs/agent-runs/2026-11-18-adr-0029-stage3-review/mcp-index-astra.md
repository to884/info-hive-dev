# ADR-0029 段階3の MCP 索引保護のレビュー

2026-11-19。GPT-6.2 Astra が [設計](../../plans/adr-0029-stage3-mcp-index.md)、実装、修正後の差分をレビューした。

- 保持中の索引は再利用の前にリンクを検査し、索引ディレクトリ、SQLite 本体、Tantivy のディレクトリ、ロックファイルの実体も照合する。Tantivy の再試行では、writer を開く前に毎回検査する。
- 初期化の途中で失敗しても SQLite 接続とプロセス間のロックを閉じる。チャンクの検索が続いている間は reset がその世代を閉じない。
- チャンク索引はプロセス間のロックを取ってから tokenizer を読み、欠損や破損を見つけたら理由を返す。通常の書き込みが fingerprint の違いとして旧データを消すことを防ぎ、明示した reset で復旧できる。
- reset の前にチャンクを検査する。重複 ID や SQLite の整数の範囲外の `generation` で拒まれたあとも、すでにあるチャンクを検索できることを確かめる。

最終判定は承認。wiki の `query`、`get_page`、`stats` の MCP エラーに、理由、場所と `wiki_search.py --no-embed` の案内が出ることを確認した。記事を読む際のエラーとチャンク索引のエラーにはそれぞれの理由を残す。

## 検証

- Windows、Python 3.12 で、最終差分の MCP stdio、索引、検索キャッシュ、読み取り箇所の試験43件がすべて成功した。stdio で索引の経路、SQLite の付随ファイル、Tantivy のファイルに対する拒否と、その配置を戻したあとの復旧を確かめた。
- Windows、Python 3.14 で、MCP の中継、サーバー、索引、wiki とローカル原本のリンクの試験156件を実行し、151件が成功、5件をスキップした。この一括試験の開始後に加えた reset の入力検査は、上記の Python 3.12 の試験で確かめた。
