# ADR-0029 段階3の検索キャッシュ保護のレビュー

2026-11-19。GPT-6.2 Astra が [設計](../../plans/adr-0029-stage3-search-cache.md)、実装、修正後の差分を静的にレビューした。

- 外部の明示 `--cache` をボリュームの根から検査すると、通常の別ボリュームまで拒む。外部では既存の親を設定された根とする。wiki の根へ入る親の別名は検出し、その下の経路を検査する。
- MCP の同じ記事構成で `refresh()` を繰り返すと、最初のパースキャッシュ拒否が消えうる。記事が変わらずキャッシュを更新しないときは、直近の更新時の警告を返す試験を追加した。
- SQLite の本体と付随ファイルの経路を接続直前に検査する。接続後の初期化と同期でも書き込みが拒まれうるため、読み取り専用にした SQLite を使い、接続が閉じることとフォールバックを確かめた。
- セットアップが `status: lexical` を返すのは、ベクトル索引の経路や SQLite の書き込みで拒まれた場合である。パースキャッシュだけが拒まれ、ベクトル索引が準備できた場合は `ready` を返す。設計と検索の文書を実装に合わせた。

最終判定は承認。Windows の 8.3 名そのものの実機試験は行っていない。wiki の根の別名とその下のジャンクションは回帰試験で確かめた。

## 検証

- Windows、Python 3.12 で、フォールバックと読み取り箇所の検査14件、sqlite-vec を使う検索とセットアップなどの既存試験67件、スクリプトパスの検査16件が成功した。
- Windows、Python 3.14 で、検索、ページ集合、MCP 索引とサーバー、初期化と手順の回帰試験254件を実行した。246件が成功し、8件をスキップした。初回に検出した raw 取り込み手順のスクリプトパスの表記も修正した。
- CLI の実行でも、パースキャッシュと SQLite の付随ファイルへの書き込みを拒まれた場合に、警告付きで `--no-embed` と同じ検索結果が得られた。セットアップは `status: lexical` と終了コード1を返した。
