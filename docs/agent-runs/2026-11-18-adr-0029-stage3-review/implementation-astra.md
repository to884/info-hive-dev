# GPT-6.2 Astra の実装レビュー

対象は ADR-0029 段階3のセッション原本の保存、根の記録、source の版の照合、lint への接続。初回は3件を指摘し、修正後の再レビューでは3件の解消を確認した。最終判定は採用可。静的な再確認で新たな重大な問題は見つからなかった。

| 重要度 | 指摘 | 修正と回帰テスト |
| --- | --- | --- |
| 高 | 通常の取り込み手順の `inspect` が、リンクの raw を開いて原本のメタデータを返していた。 | raw の根と対象を共通のガードで確かめ、拒否理由を `raw.reason` に出す。リンクでメタデータを読もうとすると失敗する試験を追加した。 |
| 中 | 現在の根を指定しない lint で、対象 PDF を含まない過去の根があるだけで、rag の原本の範囲が未確認であることを知らせなくなった。 | 外の原本と扱う候補については、現在の根の有無で `scope_unverified` を判定する。無関係な根を記録した wiki でも警告が出ることを試験した。 |
| 中 | 先頭がピリオドのスラッグを受け付けるため、根と raw を保存したあとで、隠し項目として解決できず失敗していた。 | セッション用のスラッグ検査で先頭のピリオドを拒む。承認用の `show` と保存用の `write` が停止し、原本も根の記録も残らないことを試験した。 |

レビューでは、根の記録に失敗した場合の保存の停止、保存したバイト列に対応する `raw_sha256` の出力、並行保存での上書き防止も確認した。実行結果は [検証の記録](review-summary.md#検証) にある。
