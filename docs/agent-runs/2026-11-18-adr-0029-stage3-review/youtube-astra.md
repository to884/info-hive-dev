# ADR-0029 段階3の YouTube 字幕取り込み

2026-11-18。セッションに続き、YouTube 字幕の保存と再利用を、共通の書き込み検査と raw の根の記録に接続した。 [実装の設計](../../plans/adr-0029-stage3-youtube-raw.md)

## GPT-6.2 Astra の敵対的レビュー

- 設計レビューでは、既存原本の再利用を V4・V5 に通して版を記録すること、V8 で検査するファイルを明示すること、排他の単位を定めることが必要とされた。V5 の `raw_ref` と `raw_sha256` を source ページに転記し、V8 には `raw_path` を渡すようにした。`verify` は指定された根から対象ファイルを選び、wiki 内の他の参照には過去の根も使う。排他は同じファイル名に対して行う。
- 実装レビューでは、BOM 付きの原本を `same` で受け入れてから `verify` で失敗する問題が見つかった。字幕の原本のデコードを `utf-8-sig` にそろえた。回帰試験では BOM と CRLF を含むバイト列のハッシュが一致し、出力から source ページを作って `verify` が通ることを確認した。
- 修正後の再レビューの判定は承認。レビューは静的に行い、試験の実行は実装側で行った。

## 検証

- Windows・Python 3.12 で字幕と共通の書き込み検査の関連80件が成功した。根を記録できない場合に新規保存と既存原本の属性変更を止めること、既存原本のリンクを読まず報告すること、過去の根で保存した版を lint が照合すること、別の根に同名の字幕があっても `verify` が指定したファイルを選ぶことを確かめた。
- Windows・Python 3.14 ではセッション、字幕、raw の解決、lint、MCP を含む347件を実行し、342件成功、5件スキップだった。BOM 対応後にも旧原本の再利用、過去の根の lint、同名ファイルの `verify` を再実行し、3件とも成功した。
- 入口と Codex パッケージの追加試験は21件を実行し、20件成功、1件スキップだった。
