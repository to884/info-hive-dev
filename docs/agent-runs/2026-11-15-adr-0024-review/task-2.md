# レビューの目的（2 回目）

`docs/adr/0024-wiki-extracts-pdf-text-with-pdfium.md` は、info-hive の wiki の取り込みで、rag を使わないときの PDF の本文の取り出し方を、rag と同じ PDFium の文字の層にそろえる ADR の提案である。1 回目の敵対的レビュー（`docs/agent-runs/2026-11-15-adr-0024-review/review-1.md`）の指摘を受けて書き直した。

1 回目の指摘への対応は次のとおりである。直し方が、言い換えにとどまっていないかを見てほしい。

- 本文が同じになる範囲を、「何をそろえ、何をそろえないか」の表で決め直した（ページの区切りと番号、同じ版での文字の層の本文、判定はそろえる。OCR したページの最終の本文はそろえない）
- 判定は目安であるとして、見逃す状態を書き、判定を変えない「確かめるべきページ」の印と、エージェントの確かめ方を足した
- 抽出の識別を `EXTRACT_REVISION` と pypdfium2 の版の組にし、rag の側の決定を承認の条件にした
- 契約の試験に、wiki の出力そのもの（本文を出さないページ、分けて読んだ出力のつなぎ、つなぎ方）を足し、承認の条件の検証で `wiki_pdf.py` の実際の出力を比べることにした
- 軽微な指摘（表の優位、バイト列と文字列、MCP の案の退け方、分けて読む出し方、手順の番号）を直した

次の点を中心に崩してほしい。

- 1 回目の指摘が実際に直っているか。直し方から、新しい欠陥が生まれていないか
- 「確かめるべきページ」の印、分けて読む出し方、抽出の識別、契約の試験が、rag の今のコード（`info-hive-rag/scripts/rag_pdf.py`、`rag_index.py`、`rag_config.py`、`rag_server.py`）と wiki の取り込みの手順（`info-hive-wiki/skills/info-hive/references/ingest-workflow.md`、`info-hive-wiki/commands/ingest.md`）に対して成り立つか
- 承認の条件が、決定を確かめるのに足りるか。言い過ぎや、結果にない主張がないか

1 回目の指摘のうち直っていないものは、そのことを書く。
