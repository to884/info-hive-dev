# Opus レビューへの対応

初回レビューは Major 1 件・Minor 4 件で REJECTED。レビュー対象は測定コードで、原標本は完成済みだった。今回の対応後の再レビューは実施していない。

| 指摘 | 反証として確認したこと | 判断と対応 |
| --- | --- | --- |
| 試作は複数要因を同時に変える | 依頼は四つの出力の比較で、属性固定の仕組みだけの因果実験は要求していない。報告案も差の原因を未切り分けとしていた | 出力が複数要因を含むことを採用。今回の全要素・全描画値を含む書き出し方の結果として報告し、方式一般への評価を避けた。原因を分解する追加の試料は今回の比較に加えていない |
| 安定標本の最大値が一時的なピークを表さない | 既存スクリプトと同じ定義で、短いピークの取り逃しも報告していたが、より高い境界標本は保存済みだった | 採用。測定区間内で採取を開始・完了した境界標本も含めて再集計し、安定標本のみの値を併記した。描画中の安定標本はゼロで、真の一時ピークが未確認と明記した |
| 開始値の差が絶対値の中央値に混ざる | 報告の主表は最初から開始値を引いた増分で、NetworkProcess の約 32 MiB の差を記載していた | 絶対値を比較しない説明を追加し、WebKitWebProcess だけの観測最大と 10 周後の増分を併記した |
| 初回時間は全画像と screenshot の処理も含む | コードと報告案は画像取得完了までの上限寄りの指標として定義し、初めて表示された時刻を主張していなかった | 補助的な指摘として採用。decode の値を全画像処理の完了目安とし、取得画像を目視した。16 枚の画像の反復一致と現行 SVG・試作 SVG の画像一致を確認。取得時間から初回表示の優劣は確定しない |
| 生成過程の記録 | 原稿の SHA-256 と生成済み画像のハッシュ、フォントは測定前後に照合済み。resvg-js の版とバイナリ SHA は別ファイルに保存していた | 生成コードに版の検査、Chromium の版、コードの SHA、プラグインのコミットを追加した。別の出力先で再生成した全 400 画像が測定に使った画像と一致した。元の測定マニフェストは保持した |

原標本の採取、測定スクリプトと画像のハッシュ、元の2方式の測定スクリプトは変更していない。今回の主要な数値変更は、保存済み境界標本を含む再集計による。
