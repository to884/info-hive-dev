## 判定

**却下。確信度：高。** 走査上限と結果の再現性が両立する手順が未定義で、既存の Raw 本文読み込み経路も残っています。Windows のルート同一性判定と MCP の索引の扱いにも、具体的な誤集計・契約不整合があります。

以下、対象文書を「計画」と表記します。実装は未着手のため、設計上の欠陥と既存コードで確認できた挙動を区別しています。

## 致命的・重大な欠陥

1. **【重大】既存の統計処理が Raw の本文を読むため、追加する走査の制限だけでは目的を満たさない。**

   `compute_stats()` は wiki 全体を `rglob()` し、Markdown の本文を読んだ**あと**で `is_page_path()` によって `raw/` を除外します。`wiki/raw/` に大量・巨大な Markdown がある場合、新しい Raw 集計とは別に、上限なしで列挙・本文読み込みが走ります。Raw 集計を `--no-raw` で止めても、この既存経路は残ります。

   メモリ上のモックで、`wiki/raw/original.md` に対し `pages=0` でも `read_text()` が呼ばれることを確認しました。計画の「内容は読まない」「項目上限」「走査しない」の試験は、Raw 集計関数だけを対象にすると見逃します。

   根拠：[wiki_stats.py:123](C:/Works/info-hive-dev/info-hive-wiki/skills/info-hive/scripts/wiki_stats.py:123)、[計画:79](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:79)、同84–85行・234行。

2. **【重大】上限到達時の集計対象が走査順に依存し、CLI と MCP の同一結果を保証できない。**

   計画は「100,000 項目で打ち切る」と「走査順序に依存させない」を同時に要求していますが、打ち切る前の選択順序がありません。`os.scandir()` の列挙順は任意です。[Python 3.10 の仕様](https://docs.python.org/3.10/library/os.html#os.scandir)でも保証されません。

   上限を1に差し替え、`a.bin=1 byte`、`b.bin=20 bytes` を置く反例では、列挙順だけで合計が1または20になります。取得済みの一覧を最後に並べ替えても、合計・上位一覧・閾値判定の違いは消えません。複数ルートでも、先に走査するルートが上限を使い切ります。

   根拠：[計画:84](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:84)、同158–159行・233–236行。上限の試験と並び順の試験を別々に通しても、この組み合わせは検証できません。

3. **【重大】自動候補のルート自身と、その途中にあるリンクの扱いが未定義。**

   ルートの検査は「ディレクトリである」「wiki 自身・祖先ではない」「重複しない」だけです。一方、同一性判定と出力には `Path.resolve()` を要求しています。

   Linux で `<wikiの親>/raw` が外部書庫へのシンボリックリンク、Windows で同じ場所が外付けドライブや共有先へのジャンクションだった場合、記載されたルート検査は通ります。先に `resolve()` すると、走査開始時にはリンク先の通常ディレクトリになり、子項目のリンク除外では防げません。`raw` 自体が通常ディレクトリでも、そこまでの親にリンクがあるケースが残ります。

   これは「リンクをたどらない」と「意図しない書庫を走査しない」の適用範囲の欠落です。`resolve()` がリンクを解決する点は[Python の仕様](https://docs.python.org/3.10/library/pathlib.html#pathlib.Path.resolve)で確認できます。

   根拠：[計画:63](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:63)、同71–72行・80行・158行。231行の試験は、ルート自身・途中のリンクを含むとは書かれていません。

4. **【重大】Windows の `normcase()` は、実在する別ルートを重複として捨てる。**

   大文字小文字を区別する Windows のディレクトリに `C:/vault/Raw/` と `C:/vault/raw/` が別々に存在する状態で、両方を `--raw` に渡す反例です。解決後のパスを `normcase()` すると同じ文字列になるため、一方を除外して容量を過少集計します。

   `ntpath.normcase()` がこの2文字列を同一にすることは実行確認しました。実ファイルシステム上の再現は未実施ですが、この条件自体は ADR-0013 が既に取り上げ、同じ正規化を採らない理由として明記しています。

   根拠：[計画:72](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:72)、[ADR-0013:87](C:/Works/info-hive-dev/docs/adr/0013-rag-records-pdfs-by-absolute-path-and-hash.md:87)。

5. **【重大】相対 `raw:` の案内作成が、測定対象外へのファイルシステムアクセスを発生させる。**

   「lint と同じ規則」で解決するには、候補の存在確認が入ります。現在の lint は候補ごとに `Path.exists()` を呼びます。

   例えば source の `raw: "../remote/book.md"` に対し、`remote` が応答の遅い共有先へのリンクなら、Raw ルートとして選んでいなくても案内作成中に共有先へアクセスします。絶対パス参照を件数だけにしても、相対パス経由で同じ問題が戻ります。再帰走査ではありませんが、多数の参照の存在確認には Raw の100,000項目制限も適用されません。

   根拠：[計画:67](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:67)、[wiki_lint.py:203](C:/Works/info-hive-dev/info-hive-wiki/skills/info-hive/scripts/wiki_lint.py:203)、同233–235行。計画228行の「絶対パスの先を走査しない」試験では、この経路を検出できません。

6. **【重大】読み取り失敗による不完全な集計を、通常の合計として判定する。**

   読めない項目は `skipped.unreadable` に数えるだけで、下限としての扱いは `truncated` の場合にしか定義されていません。

   Linux で Raw 内にアクセス権のない20 GiBのディレクトリと、読める1 KiBのファイルを置く反例では、記載どおりなら `state="measured"`、`bytes=1024`、`truncated=false`、`level=null` になります。ハード閾値を超えている可能性があるのに、出力上の合計と閾値判定は通常の完全集計と同じです。ルート全体を読めない場合の状態も決まっていません。

   根拠：[計画:82](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:82)、同111行・146–156行。試験節には読み取り失敗時の合計・状態・警告の検証がありません。

7. **【重大】「索引は開かない」と、既存 MCP `stats` の契約が食い違う。**

   計画186行を `stats` 全体の契約として読むと、現在の実装を維持できません。既存処理は `state.wiki()` で索引を初期化し、`refresh()` 後の件数を `index` に返します。既存テストも、最初の `stats` 呼び出しで `index.sections > 0` を要求しています。

   未接続の wiki に初めて `stats` を呼ぶ状態が反例です。現状を維持すると「索引は開かない」に反し、その記述どおり索引を開かなくすると既存の状態報告・テストと両立しません。「Raw 集計部分だけが索引を開かない」という意味なら、文書の適用範囲が曖昧です。

   根拠：[計画:186](C:/Works/info-hive-dev/docs/plans/wiki-raw-size-in-stats-2026-11-11.md:186)、[wiki_mcp_server.py:395](C:/Works/info-hive-dev/info-hive-wiki/skills/info-hive/scripts/wiki_mcp_server.py:395)、同177–184行、[test_mcp_server.py:472](C:/Works/info-hive-dev/tests/wiki/test_mcp_server.py:472)、[commands/stats.md:5](C:/Works/info-hive-dev/info-hive-wiki/commands/stats.md:5)。

## 崩れる前提

- **「ページとして除外される Raw は読まれない」**  
  `compute_stats()` では本文読み込み後に除外されます。集計対象の除外と、走査・読み込みの除外は一致していません。

- **「出力をソートすれば結果は再現する」**  
  打ち切りによって取得した集合自体が違えば、再現しません。

- **「解決済みパスの大小文字をそろえれば同じディレクトリを判定できる」**  
  Windows の大文字小文字を区別するディレクトリで崩れます。

- **「測らない参照先にはアクセスしない」**  
  相対参照の存在確認とリンク解決で崩れます。

- **「設定で Raw を指定すれば、探索対象はその場所になる」**  
  計画は設定に加えて隣・内部の `raw/` もすべて測ります。設定変更後に残った旧 Raw や、別用途の同名ディレクトリも合算されます。

- **「Raw の大きさは検索に影響しない」**  
  固定名の `raw/` をページ集合から除く点は確認できます。ただし走査コストは残り、`wiki/W1_Raw/` のような別名の内部配置は `wiki_pages.py` の固定除外名に含まれません。

## 見落としと軽微な問題

- **【軽微】「100,000項目は少なくとも2,000ページ分」は計算が合わない。**  
  1ページに本文1ファイル・画像50ファイル・画像用ディレクトリ1個なら52項目です。1,924ページで、共通の `assets/` を含め100,049項目になります。さらに画像50枚・20 MiBは変更可能な既定値です。  
  根拠：計画87行、[wiki_fetch.py:1147](C:/Works/info-hive-dev/info-hive-wiki/skills/info-hive/scripts/wiki_fetch.py:1147)。

- **【軽微】複数ルートの順位の同点処理が一意でない。**  
  `A/assets/x.png` と `B/assets/x.png` が同じサイズなら、出力の相対 `path` も同じです。「バイト数、同じならパス」だけでは順序が決まりません。  
  根拠：計画140–145行・159行。

- **【軽微】無効なルートしかない場合と、`raw=[]` の意味が未定義。**  
  明示指定をすべて拒否した場合の `state`、空リストが自動探索を意味するか空集合を意味するかが決まっていません。  
  根拠：計画61–73行・156行・185行。

- **【軽微】Windows の再解析ポイント判定手順が未確定。**  
  `DirEntry.stat()` は既定でリンクをたどります。タグを読む時点の `follow_symlinks` が未指定で、試験には OneDrive のクラウド項目もありません。Python 3.10 に `st_reparse_tag` がある点は確認でき、API不在を欠陥とは判定しません。  
  根拠：計画80行・231行、[Python 3.10 の `DirEntry.stat()`](https://docs.python.org/3.10/library/os.html#os.DirEntry.stat)。

- **【軽微】「テキストは小さく、場所を取るのは画像」は示された測定から一般化できない。**  
  PDF抽出の0.59%は11文書・OCR追加分を除く測定です。Web訳文の書庫や利用者持ち込みのテキストについて、画像が支配的である根拠にはなりません。  
  根拠：計画38行、[PoCサマリ:27](C:/Works/info-hive-dev/docs/research/rag-poc-summary-2026-11-04.md:27)。
