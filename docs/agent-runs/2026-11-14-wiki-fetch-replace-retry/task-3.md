# 依頼: 2 回目のレビューの「重大」への直しの敵対的レビュー

2 回目のレビュー（`review-2.md`）の重大な指摘は、「退避の場所の名前がプロセス ID だけで決まるので、前の保存が残した退避の場所を、同じプロセス ID の次の保存が使い回し、残した古い画像を上書きするか消す」だった。軽微な指摘は、「古い画像を退避の場所に移した直後、記録の前に止められると、注記が付かない」だった。どちらも、直す前の版で落ちる試験にしてから直した。

## 直し方

- 退避の場所は、古い画像があるときに `tempfile.mkdtemp(prefix=f".{slug}.{pid}.", suffix=".old", dir=asset_dir.parent)` で作る。呼び出しごとに、まだない名前の空のディレクトリになる。前の呼び出しの退避の場所には触れない。古い画像がなければ作らない（`backup` は `None`）。
- 古い画像は、退避の場所に移す前に `moved` に記録する。戻しは `dest.exists()` を確かめてから移すので、移せなかった画像は飛ばす。
- 試験の手直し: 待つ時間の差し替えを、偽の `os.replace` で書く間だけにした。偽の `os.replace` が本物に任せる所は、本物の `PermissionError` なら本物の `sleep` で待つ。

## 壊してほしい不変条件

**本文の置き換えが成功するまで、どの古い画像も、元の場所か、その呼び出しが作った退避の場所のどちらかに、元のバイトで必ずある。どの呼び出しも、ほかの呼び出しが作った退避の場所に触れない。** 失敗したときに古い画像が退避の場所に残るなら、例外の注記がその場所を書く。

この不変条件を破る反例（呼び出しの並び、例外の起きる位置、割り込みの位置）を探してほしい。個別の経路を 1 つずつ塞ぐのではなく、不変条件が成り立つかを見たい。

## 限界として扱うもの（指摘は不要）

次のものは不変条件を破らないか、今回の変更で起きやすくなっていない既存の問題なので、直さない。

- 新しい画像を正式な場所に置いた直後、`placed` に記録する前に止められると、新しい画像が 1 つ残る（古い画像は退避の場所にあり、注記が付く）。
- `mkdtemp` の直後に止められると、空の退避の場所が残る。
- 戻しきれずに残った退避の場所は自動では消えず、溜まる。
- 戻しの例外が元の例外に替わる（元の例外は `__context__` に残る）。
- `finally` の `unlink` と `rmdir` が Windows で `PermissionError` になりうる。
- 本文の置き換えの直後、`replaced = True` の前に割り込まれると、本文だけが新しくなり、画像は古いものに戻る（直す前からある）。
- 戻しは最初の失敗で止まる。
