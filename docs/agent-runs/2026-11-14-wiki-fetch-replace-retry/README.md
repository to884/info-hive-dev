# wiki_fetch.py の名前の変更の試し直しの敵対的レビュー（2026-11-14）

`wiki_fetch.py` の `write_outputs` が、Windows でほかのプロセス（ウイルス対策の検査、検索の索引、エディター）が raw や画像を開いていると `PermissionError: [WinError 5]` で止まる不具合の修正を、GPT-6.1 Sol（effort high）にレビューしてもらった。2 回目と 3 回目は、1 回目と同じセッションを再開し、直しの差分だけを見てもらった。

| 回 | 依頼 | 対象の差分 | 結果 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | `task.md` | `submodule.diff`、`parent.diff`（最初の実装） | `review-1.md` | 条件付きで採用可（確信度 高） |
| 2 | `task-2.md` | `fix-1-submodule.diff`、`fix-1-parent.diff` | `review-2.md` | 却下（確信度 高） |
| 3 | `task-3.md` | `fix-2-submodule.diff`、`fix-2-parent.diff` | `review-3.md` | 採用可（確信度 中） |

3 回目は、個別の経路ではなく次の不変条件を壊してもらった。「本文の置き換えが成功するまで、どの古い画像も、元の場所か、その呼び出しが作った退避の場所のどちらかに、元のバイトで必ずある。どの呼び出しも、ほかの呼び出しが作った退避の場所に触れない」。Sol は、例外を入れる位置を変えた 44 通りで、この不変条件を崩せなかった。打ち切りの条件は、事前に次のように決めた。不変条件の反例が出れば直す。限界か、今回の変更で起きやすくなっていない既存の問題なら、ここに書いて終える。

## 指摘と対応

| 回 | 指摘 | 重大度 | 対応 |
| --- | --- | --- | --- |
| 1 | 本文の置き換えが失敗し、退避した古い画像を戻す名前の変更も失敗するか、戻す前の待ちで止められると、`finally` が退避の場所の中身を消し、古い画像のただ 1 つの写しが失われる | 重大 | 退避の場所の中身を消すのは、本文を置き換えたあとだけにした（`ffa9913`）。戻しきれなかったら、例外の注記（`add_note`）に退避の場所と戻し方を書き、`main` が標準エラーに出す |
| 1 | 試験が戻しの成功を前提にしている | 軽微 | 戻しがずっと失敗する場合と、戻す前の待ちで `KeyboardInterrupt` が起きる場合の試験を足した |
| 1 | CHANGELOG の「前の raw と画像を残す」が、戻しの成功を前提にしている | 軽微 | 戻しきれなかったときの扱いを CHANGELOG に足した |
| 2 | 退避の場所の名前がプロセス ID だけで決まる。前の保存が残した退避の場所を、同じプロセス ID の次の保存が使い回し、残した古い画像を上書きするか消す | 重大 | 退避の場所を呼び出しごとに `tempfile.mkdtemp` で新しく作る（`4e12188`） |
| 2 | 古い画像を退避の場所に移した直後、記録の前に止められると、注記が付かない | 軽微 | 移す前に記録する（`4e12188`）。戻しは `dest.exists()` を確かめてから移す |
| 2 | 試験が、失敗のあとの次の保存を確かめていない | 軽微 | 次の保存が成功する場合と失敗する場合の試験を足した |
| 3 | 本文の置き換えが失敗したあと、戻しの内側の `try` に入る直前に割り込まれると、古い画像は退避の場所に残るが、注記が付かない | 軽微 | 直さない。古い画像は失われず、不変条件は破れない。下の限界に書いた |

1 回目と 2 回目の重大な指摘は、どちらも直す前の版で落ちる試験にしてから直した。1 回目の指摘は、main の版（`8cb49d6`）の写しでも実ファイルで起きた（本文の置き換えが EIO、戻しが `PermissionError` のとき、古い画像が 2 つとも消える）。前からある欠陥で、最初の実装が戻しにも待ち時間を入れたので、止められる窓が広がった。

## 範囲

依頼は「`os.replace` の試し直しを足し、失敗したときに前の raw と画像を戻す今の処理は変えない」だった。戻しの手順（順序、最初の失敗で止まること）は変えていないが、レビューを受けて、次の 4 点を変えた。

- 後始末の規則: 退避の場所の中身は、本文を置き換えたあとだけ消す
- 退避の場所の名前: 呼び出しごとに `mkdtemp` で作る
- 記録の順序: 古い画像を退避の場所に移す前に記録する
- `main` の出力: `OSError` の注記も標準エラーに出す

info-hive-wiki の 3 つのコミットは層になっている。`f50e940` が試し直しだけで、`ffa9913` と `4e12188` が上の 4 点である。後ろの 2 つは外せる。

レビューのあとで main に 0.14.0（URL の取り込みの検査）が入り、`build` が作業用の写しの印（`fetch.json`）を `os.replace` で置くようになった。`wiki_fetch.py` の中の同じ形の名前の変更なので、マージのあとで `replace_with_retry` に替え、試験を 2 件足した。`wiki_rawcheck.write_atomic` の `os.replace` は、検査の CLI だけが使い、`wiki_fetch.py` からは呼ばないので直していない。

## 確かめたこと

- `tests/wiki/test_wiki_fetch.py` は 33 件が通る（Python 3.14 と `uv run --python 3.12`）。0.14.0 をマージしたあと、PyYAML を付けて `test_wiki_web_check.py`、`test_uninitialized_wiki.py`、`test_wiki_lint.py` も合わせた 185 件が通る。
- 修正の要所を 1 つずつ壊した写し 13 通り（`fetch.json` の名前の変更を `os.replace` に戻す、試し直しをなくす、4 つの名前の変更（退避、配置、本文、戻し）のどれかを `os.replace` に戻す、`OSError` を全部試し直す、Windows の判定を見ない、後始末で退避をいつも消す、注記をなくす、退避の場所を使い回す、移してから記録する、`main` で注記を出さない）では、それぞれ対応する試験が落ちる。
- Windows の実機で、別スレッドが `open(path, "rb")` で raw か古い画像を開いたまま `write_outputs` を呼んだ。0.3 秒で閉じれば書け、1.5 秒開いたままなら約 1.01 秒で `PermissionError`（raw は winerror 5、古い画像は winerror 32）を上げ、前の raw と画像が残り、一時のファイルも残らない。main の版では、どちらもすぐに失敗する。

## 限界（直さない）

- 新しい画像を正式な場所に置いた直後、記録する前に止められると、新しい画像が 1 つ残る（古い画像は退避の場所にあり、注記が付く）。
- 本文の置き換えが失敗したあと、戻しを始める前（`except` に入った直後）に割り込まれると、古い画像は退避の場所に残るが、注記が付かない（3 回目のレビュー）。
- `mkdtemp` の直後に止められると、空の退避の場所が残る。
- 戻しきれずに残った退避の場所は自動では消えず、溜まる。
- 戻しの例外が元の例外に替わる（元の例外は `__context__` に残る）。
- `finally` の `unlink` と `rmdir` も、Windows で同じ理由で `PermissionError` になりうる。
- 本文の置き換えの直後、成功の印を立てる前に割り込まれると、本文だけが新しくなり、画像は古いものに戻る（直す前からある）。
- 戻しは最初の失敗で止まる。
- `wiki_fetch.py` から使わないスクリプト（`wiki_browse_fs.py`、`wiki_evolve.py`、`wiki_index.py`、`wiki_mcp_common.py`、`wiki_search.py`）の `os.replace` は直していない。`wiki_graph_common.replace_atomically` は前から試し直す（失敗すると移動元を消すので、`write_outputs` の戻しには使えない）。
