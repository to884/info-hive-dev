# 開発専用画像での転記指示の比較

[統合設計の比較試験](../2026-11-19-adr-0025-condition5-design-local/design.md)を実施する。条件5の合否基準、正式評価用の画像・正解・採点器は変更しない。

## 入力と割付

- 横書きの合成原稿4種、各9行。対象記号は原稿ごとに `）`、`」`、`。`、`】`。0個、1個、連続2個を各3行とし、配列、位置、字の大きさ、連続字の間隔を変える。対照として濁点、枠外の同種記号と文字片、罫線、色見本を入れる。150 DPIで描画された字のインク範囲にv9の所属規則を当て、正解と一致することを固定前に確かめる。合成画像の幾何は整数倍率で管理する。
- 150 DPIの最近傍3倍、450 DPIの実寸表示をそれぞれ枠あり・枠なしで渡す。画像の外縁に共通の匿名行IDを付ける。解答のID、転記指示、画像のSHA-256と順序、合成原稿の正解のSHA-256、割付、集計コードを転記開始前に固定する。
- 両群とも全4原稿をSolとAstraが1回ずつ読む。担当は読取セッションを指す。各担当をリポジトリ外の空ディレクトリで起動し、設定、記憶、プラグイン、シェルを使わない一時セッションにする。同じ担当に両群の画像を渡さない。現行の所属・転記指示を両群で共用し、新群に「提出前に連続記号の位置と個数を見直す。」の1行だけを加える。正解、主OCR、文字層、他の回答、比較の目的は与えない。画像はCLIから直接添付し、操作履歴を検査する。
- v9と同じ正規化後の全文で二読が一致した場合に採用する。不一致か読めない票がある行だけ第三読に回し、元の画像と対象IDを渡す。事前割付は原稿1・3がSol、2・4がAstraで、群ごと・モデルごとに新規セッションを使う。最大3票のうち二つの既知票が一致すれば採用し、該当なしは未決定とする。読めないという回答は有効な票として扱う。操作、送信または出力形式の失敗は票として採用せず記録し、同じ入力で1回まで代替する。両試行が失敗した場合は比較を欠測とし、残りの票で正式な集計を確定しない。

## 集計と解釈

- 原稿別・群別に、対象記号の不足字数と不足行数、過剰な句読点・記号の字数と行数、全文一致、既知の誤り、未決定を数える。過剰記号にはUnicodeのPとSを含める。記号の過不足は正規化後の字種ごとの個数差で数える。文字や順序の違いは全文の一致と、余分な文字全般の補足集計で確かめる。
- 双方で確定した同じ行に絞った対比較を主とし、各群で確定した全行の集計と、第一・第二読それぞれの集計も出す。誤→正、正→誤、既知→未決定、未決定→既知はそれぞれ行数を出す。未決定は記号の過不足の分母に含めない。既知→未決定が1行でもあれば、未決定が減った行で相殺しない。
- 同じ確定行で対象記号の不足が減った原稿が2種以上あり、全体の不足も減り、過剰記号と余分な文字の行数・字数が増えず、全文一致が減らず、全36行で未決定が増えず、既知→未決定が0行なら、開発試料上で追試に値する差とする。旧群の不足が0なら改善の根拠は得られない。原稿内の悪化や個々の誤→正と正→誤は集計と併記する。未決定の削減や全面再読への判断には、未決定を生む失敗型の別試験が要る。小規模な合成画像で観測した差を、縦書き・境界例や正式評価へ外挿する根拠は得られない。
