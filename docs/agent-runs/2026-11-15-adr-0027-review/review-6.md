同梱の Markdown パーサーで、印の中の `**` と文字参照が解釈され、表のセルでは字幕の `|` 以降が表示から落ちることを再現しました。前回の再計算の矛盾は解消していますが、今回の印には出現の識別と読み取りに関する欠落が残っています。## 判定

## 致命的・重大な欠陥

### 1. 【重大・B】「時刻と字幕の語」は、字幕の一つの出現を識別しない

**反例：** json3 に次の二つのイベントがある。

```text
tStartMs=60010: 構成Aの設定値は15です
tStartMs=60990: 構成Bの設定値は15です
```

規定の変換後は、両方とも `[01:00]` になる。前者を `50`、後者を `60` に訂正しても、識別子は両方とも `(01:00, 15)` である。

- 別々の要約ページに置くと、「同じ出現への違う訂正」として拒否される。
- 同じページに置いても、「同じ組は1件」により、別々の出現を合算できない。
- 一つの字幕行に同じ数字が二回ある場合も区別できない。

秒への切り捨てとキーの重複は、メモリ上で再現した。引用に短い抜粋を添える規則はあるが、訂正の印と計数の識別子には、その抜粋が含まれない。

**根拠：** [ADR-0027](/C:/Works/info-hive-dev/.claude/worktrees/adr-0027-corrections/docs/adr/0027-youtube-captions-via-pinned-yt-dlp.md:67) の L67、L88、L102、L104、L109。**照合結果：仕様内の食い違い。** 前回重大2は異なる時刻については直ったが、同じ秒・同じ行に狭めると再発する。実動画での頻度は未検証。

### 2. 【重大・A】訂正した語の開始位置が記録されていない

規定の形式で次を書く。

```text
上限は50〔字幕 01:00「15」 根拠 model:前後の説明〕件である。
```

印の内部には訂正語がなく、直前の文章との境界もない。読み取り処理には、どこからを「訂正した語」とするかが定義されていない。

数字だけを特別扱いしても、日本語の用語、空白を含む名称、インラインコードや wikilink を使った語には、その規則を適用できない。例えば `解析にはC++〔…〕を使う` から訂正語を抽出する規則は、提示された形式に含まれていない。

これは表示だけの問題ではない。抽出した訂正語は、根拠への逐語一致、ページ間の訂正の一致、関連ページの参照、利用者に示す一覧に必要である。実装者が境界の規則を追加しなければ、規定の照合を実行できない。

**根拠：** [ADR-0027](/C:/Works/info-hive-dev/.claude/worktrees/adr-0027-corrections/docs/adr/0027-youtube-captions-via-pinned-yt-dlp.md:100) の L100、L103、L109〜111。**照合結果：必要な読み取り規則が欠落。** 未実装のパーサーが実際に誤解析したという主張ではない。

### 3. 【重大・A】関連ページの短い印から、回答の上限を決める訂正を特定できない

**反例：** 同じ要約ページに、次の二つの訂正がある。

```text
構成Aの上限は50〔字幕 01:00「15」 根拠 metadata:title〕件。
構成Bの上限は50〔字幕 02:00「60」 根拠 model:前後の説明〕件。
```

関連ページには、規定どおり次を置く。

```text
構成Bの上限は50〔[[講義の要約]] の訂正〕件。
```

短い印が保持するのは、要約ページと訂正後の `50` だけである。時刻も訂正前の語もなく、二つの印のどちらにも当たる。L109(4) の「要約ページの印に当たる」検査では、誤った対応を排除できない。

`uploaded`・1,000行・この2件だけなら、率は `0.4%`、ソースの confidence は `medium` になる。一方、構成Bの前提には `model` の訂正による「低」の上限が必要である。短い印を metadata 側へ対応させれば「中」、model 側なら「低」になり、対応を選ぶ規則がない。

**根拠：** [ADR-0027](/C:/Works/info-hive-dev/.claude/worktrees/adr-0027-corrections/docs/adr/0027-youtube-captions-via-pinned-yt-dlp.md:103) の L103、L109、L112。**照合結果：参照先を特定する情報が欠落。** ADR-0028 の上限表へ追記するだけでは、この欠落は埋まらない。

## 崩れる前提

| 暗黙の前提 | 崩れる条件 |
| --- | --- |
| 時刻と字幕の語で一つの出現を表せる | 同じ秒の複数イベント、同じ行で同じ語が反復する |
| 印の直前から訂正語を機械的に取り出せる | 空白で区切らない日本語、複数語の名称、Markdown を使った表記 |
| 要約ページと訂正後の語で訂正を参照できる | 同じ訂正語に、異なる出現・根拠種類が対応する |
| 日本語の括弧で囲めば逐語として表示される | 字幕の語に Markdown の構文や文字参照が含まれる |

## 見落としと軽微な問題

- **【軽微】印の内容と Markdown の衝突が未規定。** 同梱パーサーで `「**x** &copy;」` を印に入れると、強調と `©` に変わった。また、表のセルに `〔字幕 01:00「A|B」 根拠 model:文脈〕` を置くと、表示されたセルは `「A` で途切れ、根拠部分が落ちた。逐語一致を Markdown の原文と表示文字列のどちらで行うか、エスケープをどう扱うかがない。既存のページ規約は、表中の `|` が列を分けることを明記している。根拠：ADR-0027 L100〜101、[ページ規約](/C:/Works/info-hive-dev/info-hive-wiki/skills/info-hive/references/page-conventions.md:143)。
