# ADR-0027 の実装（wiki 0.22.0）の敵対的レビュー（3 回目）

2 回目のレビュー（`review-2.md`、却下）の指摘を、次のように直した。直しが原因を断っているか、直しで新しい穴ができていないか、これまでに見なかったところに穴がないかを崩してほしい。目的と対象は `task-1.md` と同じで、サブモジュールの差分は `wiki-diff-3.patch` にある。1 回目と 2 回目の結果（`review-1.md`、`review-2.md`）も読んでよい。

## 直したこと

1. **書式で切れたかけらで照らしていた（重大 1、2）。** 照合の単位を、inline（段落、見出し、表のセルなど）全体の表示される文字の並び（`wiki_captions.inline_texts`）に変えた。文字ごとに、本文、コード、改行、画像の種類と、書式、リンク、コード、改行で切れない続きの番号を持つ。
   - 印は、表示される文字の並びの中で探す。全体がコードスパンの中なら数えない（例として書いたもの）。全体が本文の 1 つの続きの中なら印として数える。どちらでもない（書式、リンク、コード、改行がまたがる）ものは、形の誤り（`bad_mark`）にする。
   - 語は、印と同じ続きの中で終わらなければならない（印の直前の語に書式を付けない）。語の前の文字の種類は、表示される文字の並びで見る（`**1**5` の 1、`[1](…)5` の 1、`` `1`5 `` の 1 は、5 の前の文字である）。
2. **`raw` に動画の raw を 2 つ以上持つ要約ページ（重大 3）。** 黙って 1 つを選ばず、`several_video_raws` の誤りにし、そのページをどの raw の要約ページにも数えない。要約ページのない raw は `no_summary` の誤りにする。
3. **読めないページを黙って除いた（重大 4）。** `load_pages` は、読めないページを `unreadable_page` の指摘にし、`check_wiki` は `only_raw` によらずこれを返す（その raw に関わるかを確かめられないため）。
4. **`parse_raw`（軽微）。** 読んだ部品（見出し、区間、題名、行）から、生成器と同じ形の本文を作り直し、元の本文と同じときだけ受け入れる。

ADR の「印」「記録の置き場所」「機械の照合」の行と、ingest-workflow の書き方も、これに合わせた。試験は `python -X utf8 -B -m unittest tests/wiki/test_wiki_youtube.py`（44 件）で、2 回目の反例も入れた。
