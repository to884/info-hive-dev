# 第1回の指摘への対応

Opus 5.5 high。条件付きで採用可、確信度中。ただし重大3件を直すまでは採用できないという判定だった。今回の実装の最終の採用判定としては扱わない。

## 重大3件

1. 身元の欄がない原本を missing にした。照合を一致・不一致・未確認に分け、明示された身元が違う候補だけを捨てるようにした。frontmatter のないテキスト、バイナリ、水平線で始まる原本、ディレクトリは版未検証として扱う。プロジェクトの wiki で missing_raw が2件から0件に戻った（project-wiki-after-review-1.json）。
2. 無関係な source の曖昧さも字幕の findings に入れた。原本の不確かさは raw_warnings に保ち、字幕の findings は動画の欄・定義があるページか、verify の対象の raw を指すページに限った。訂正の根拠の source は使う時点で照合する。動画のない不確かさを警告に残す試験、実際の verify が無関係な曖昧さで止まらない試験を追加した。
3. YouTube verify が raw の根を渡さず、最初の raw を直接読んだ。最初に共通の境界で検査し、check_wiki にも既知の根と wiki の綴りを渡すようにした。対象自体のハードリンクを parse_raw の前で拒む試験と、別の動画の raw の途中のジャンクションを読まずに指摘する実行の試験を追加した。

## 軽微と前提

- outside が消えた：URL以外の候補を raw_outside に出す。
- wiki_root を渡さない lint：collect_pages が raw をまだ読まずに根の文脈を保持し、lint が解決する。文脈のない手作りの配列では raw_* の summary を null にし、未検査と0を分ける。
- missing_raw の呼び出し元：セッションの保存直後の検査は resolved のときだけ属性を変える。共有の inode の属性を変えない障害注入の試験を追加した。書き手全体の移行ではない。
- 外の原本の FileIdInfo：絶対パス1つだけなので要求しない。識別子を取れない mock で resolved が変わらないことを確かめた。
- 水平線で始まる原本：身元が未確認という扱いにそろえた。
- raw の根を省くと途中を検査できないこと、過去の根と版の記録の移行がまだないことは、段階2の限界として公開の文書と CHANGELOG に明記した。47件の途中未検査と59件の版未検証は消さずに知らせる。
- raw の根が wiki の祖先のとき：規範の「根とその祖先」は操作ごとに1つの起点を決め、起点より下の別の根も検査すると明記する。この起点の規則は変更しない。
- 任意のディレクトリの原本はその木を調べるため費用がかかる。文字の参照ごとに必要な木を調べ、wiki とは無関係な木の全体の走査はしない。raw の path は絶対パスを保ち、scope / root / relative_path / source で wiki の相対パスと区別する。
