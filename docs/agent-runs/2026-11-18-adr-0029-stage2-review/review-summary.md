# ADR-0029 段階2の実装と敵対的レビュー

2026-11-18。wiki 0.34.0 の raw のリンク検証。最後のコードはプラグイン `558068b75ebd94951b026a97ceecc48e6a40b7b3`。公開前の CI と公開後の導入は別の記録にまとめる。

## 最終の判定

Opus 5.5 の第4回は **採用可、確信度高、動作上の新しい欠陥なし**。第3回の軽微1〜4と、ハッシュがそろった場合の複数の身元の扱いを、実測で閉鎖した。対象3ファイルの入力ハッシュがその後変わっていないことを `review-4-input-check.json` に保存した。

最終レビューの残る指摘は、内製の callback が使わなくなった例外の定義と受け口である。動きに影響しない指摘として記録し、レビュー済みのコードを保持した。第4回の文末の effort の自己申告は medium だが、呼び出しの実際の指定は status と task の記録にある **high** である。

## 閉じた欠陥と設計の要点

- 第1回の重大3件は、身元の欄がない raw の誤った missing、無関係な raw の曖昧さによる動画の取り込みの停止、YouTube verify の直接の読み取りと根の欠落だった。第2回は実測で閉鎖し、採用可、重大なしとなった。
- 身元を一致・不一致・未確認に分けた。保存済みのテキスト、バイナリ、ディレクトリに身元の欄がないときは版未検証として残し、欠落にしない。版を照らせるときは、使わない身元の複数値で拒まない。
- raw の拒否、検査不能、曖昧さ、版の不一致、範囲と版の未確認を、共通の解決で保持する。全候補のリンクを検査してからハッシュと身元を読む。
- 字幕の検査は、無関係な raw の問題を警告に残す。訂正に使う複数の raw の一部を読まなかった理由も、本文を絞ったあとまで保持する。既知の本文に訂正した語があれば、その根拠を使える。
- 保存後に新しい根の検査で止まらないよう、セッションと YouTube の write は根の `..` を取得・保存の前に拒む。書いた後の原本は resolved のときだけ属性変更へ進む。
- 単独の候補では実体の比較を要求せず、複数の一致候補をまとめるときだけ識別子を求める。根と祖先のリンクの例外は、操作ごとに決める規範を保つ。

## 統合と試験で分かったこと

並行して概要機能が0.32.0として公開されたため、プラグインの `d761c62` と親の `105fd0b` を統合した。lint の概要と raw の検査、SERVER_FILES の両方の依存を残した。今回は0.33.0に番号を変更した。

macOS の CI では、既存の書き手が拒む `/var` の別名を試験素材の根に使っていたことと、Unicode の正規化で同じになるファイルの存在判定に別の既存ファイルまで数えていたことが分かった。素材の根を実体にそろえ、対象の2つの名前を samefile で比べた。製品の拒否は緩めていない。主張と行き先の作例は、原本の版と根も示す素材に直した。修正後は Linux・macOS・Windows × Python 3.12/3.14 の6構成で成功した。

手元では、関連252件、概要と表示72件、MCP5件を確認し、最後の raw・YouTube・lint124件も成功した。途中にはセッション全体を含む324件も実行した。重なる実行の件数は足し合わせない。Opus が依存なしで流した第3回の一部には PyYAML の不足があったが、依頼元と CI は依存を入れて実行した。

## 残る段階

raw の書き手全体の raw_sha256 と根の記録の作成、記録の読み込みと upgrade、書き込みの部品と依存の完全性、取り込みの全経路の移行は、段階3以降である。今の根の外の、記録のない過去の rag の原本は外の原本と扱う。現在の根の指定だけで過去まで検査したことにはならない。既存ページの版未検証と、途中の未検査の警告は隠さず残す。検査後の同時の置き換えの完全な防止と bind mount の検出は保証しない。

公開前に、先行するプラグイン PR #91 が0.33.0を使用予定と確認したため、今回を0.34.0へ変更した。レビューしたコードは変えず、両ホストの版と CHANGELOG だけを更新した。第3回までの0.33.0という記述は、その時点の予定を保持している。
