## 致命的・重大な欠陥

### 1. 重大・B：標準出力が UTF-8 に固定されず、保存後に成功応答が失われる

**対象：** `info-hive-wiki/skills/info-hive/scripts/wiki_overview.py` の813行。関連箇所は14行、643行、655〜659行。

`main()` は `ensure_ascii=False` の JSON を `print()` するが、標準出力の符号化を設定していない。14行のコメントは `wiki_text` が「UTF-8 の標準入出力」を確かめると説明しているものの、現在の `wiki_text` にその処理はない。

**具体的な入力・操作順：**

1. 初期化済みの一時 wiki に `concepts/x😀.md` を置く。
2. `begin` と `prepare` を行い、通常の本文だけの下書きを置く。
3. `PYTHONUTF8=0`、`PYTHONIOENCODING=cp932` の子プロセスから、`-X utf8` を付けずに `write` を呼ぶ。

**実測結果：**

```text
終了コード: 1
標準出力: 0 バイト
標準エラー: wiki_overview.py:813 の UnicodeEncodeError
サイドカー: 保存済み
作業フォルダー: 削除済み
```

保存自体は成功しているが、応答の `page` に含まれる絵文字を cp932 に符号化できない。利用者には `written` が届かず、残っていない `work_id` で再試行することもできない。

絵文字を含まない日本語のエラーでも、JSON は cp932 で出力され、UTF-8 として復号できなかった。設計書189行の「常に標準出力の UTF-8 の JSON 1つ」という契約に反する。

試験の CLI ヘルパーは `PYTHONUTF8=1` と `-X utf8` を使うため、スクリプト自身による符号化の保証を検査できていなかった。

## 崩れる前提

- **`wiki_text` を先に import すれば、標準出力も UTF-8 になる。** 現在の実装では成立しない。
- **概要一覧を読めない場合は、共通の `read_os` がすべて未検査へ変換する。** `read_os` は一部の例外だけを分類し、`EIO` などは再送出する。

## 見落としと軽微な問題

### 1. 軽微・C：概要ディレクトリの一部の I/O エラーが既存の lint 全体を止める

**対象：** `wiki_overview.py` の696行、702行、707行。呼び出し元は `wiki_lint.py` の462行。

`_scan_sidecars()` は、`read_os()` が `denied` などを返す場合には未検査の `None` を返す。しかし、その走査ループを囲む `OSError` の処理がなく、`read_os()` が再送出する例外は外へ漏れる。

正常な概要を持つ一時 wiki で、`assets/overview/` に対する `os.scandir()` だけが `OSError(errno.EIO, ...)` を送出するよう差し替えた。`inspect_wiki()` と既存の `wiki_lint.lint()` が、ともに errno 5 の `OSError` を送出した。

概要の一覧を作れない場合に `overview_problems: None` を返すという設計書362行の契約にならず、概要以外の所見も返らない。新しい CLI の `status` は最外側で `io_error` に変換するが、既存の lint との共有関数の境界では処理されない。

これは例外注入による実測であり、実際のディスク故障を発生させたものではない。既存試験が扱う `PermissionError` とは、`read_os()` の分岐が異なる。
