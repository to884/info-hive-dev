# ADR-0031：ページの概要は `wiki/assets/overview/` のサイドカーに置き、`wiki_overview.py` だけが書く

| 項目 | 内容 |
| --- | --- |
| 状態 | 提案 |
| 決定日 | （承認の日を入れる） |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0005（図は mermaid と svg で書く）、ADR-0017（browse は自分が作ったものだけを置き換える）、ADR-0020（セッションの raw はスクリプトが書く）、ADR-0023（wiki の書く段）、ADR-0029（wiki と raw にリンクを置かない）、ADR-0030（browse は図を画像として見せる。提案）、[概要の設計](../plans/wiki-overview-2026-11-17.md) |

## 背景

作者は、`/wiki:browse` の記事のページの題名のすぐ後に、図を中心にした初心者向けの概要を表示することを求め、概要を作るプロンプトを決めた。

browse のサーバーは LLM を持たず、wiki のルートの下に何も書かない（ADR-0017）。概要は、Claude Code のセッションが前もって作り、どこかに置いておく必要がある。置き場所は、ページの本文、frontmatter、別のファイルのどれかになる。

ADR-0030 は、`wiki/assets/` の直下の svg だけを browse の入力にする。ADR-0023 の書く段（未実装）は、`.md` のページだけを受け、`assets/` への書き込みを受けない。`assets/` に svg を書く者は、どの設計にも決まっていなかった。

## 決定

| 項目 | 決定 |
| --- | --- |
| 作る時機 | コマンド `/wiki:overview <ページ>` で、求めたページだけ作る。取り込みには入れない |
| 置き場所 | サイドカーは `wiki/assets/overview/<ページの相対パスから .md を除いたもの>.overview.md`。図は `wiki/assets/overview-<P>-<C>.svg`（`<P>` はページの識別子のハッシュ、`<C>` は図の中身のハッシュ）。どちらも git で管理する |
| 結び付け | ページとサイドカーは、パスだけで結び付ける。サイドカーの中に、ページの名前を持たない |
| 新しさ | サイドカーに、概要を作るときに読んだページのハッシュ（BOM を除き、改行を LF にそろえた全文の SHA-256）を記録する。今のページのハッシュと違えば「古い」とする |
| 書き手 | `wiki_overview.py` だけが、サイドカーと概要の図を書く。モデルは、wiki の外の作業用のフォルダー（`<data_dir>/overview/work/`）に下書きを置き、スクリプトが検査してから wiki に置く |
| 中身 | 短い文、mermaid のフェンス、svg の画像。入力はそのページだけで、wikilink は書かない。見出しは h3 以下。写真は使わない |
| 扱い | 概要は、ページから作り直せる表示用の派生物である。ページの数、大きさの上限、検索、グラフ、統計に入れない。`log.md` に記録しない |
| lint | 元のページがない概要、壊れた概要、ない図、使われていない図を `overview_problems` で、古い概要を `overview_stale` で知らせる。直さない |

## 理由

- 本文の節にすると、概要がページの大きさ、検索、グラフに混ざる。概要は、ページの内容を初心者向けに言い直したもので、同じ事柄が 2 回索引に入る。frontmatter には図を置けない。
- `assets` は、走査、lint、検索、グラフ、統計、browse がすでに名前で除いている。新しい最上位のディレクトリを作ると、除外のリストを変えることになり、同じ名前のページのディレクトリを持つ wiki でページが消える。
- 図を `assets/` の直下に置くと、ADR-0030 の svg の入力にそのまま載る。概要のための別の配信の経路が要らない。
- スクリプトが書くと、ハッシュを browse と同じ関数で取れ、改行と文字コードをそろえられ、検査を通ったものだけが wiki に入る。新しさを、今の中身から推さずに済む。
- 図の名前に中身のハッシュを入れると、作り直しで前の図を上書きしない。図を置き、サイドカーを置き換え、古い図を消す順にすると、どこで止まっても、参照先のない図の参照ができない。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| ページの本文の h1 の直後に節として書く | browse に差し込みの仕組みが要らず単純だが、概要がページの大きさ、検索、グラフに混ざる。作者がサイドカーを選んだ |
| 新しい最上位のディレクトリ（`wiki/overviews/`） | 走査の除外のリストを変える。同じ名前のページのディレクトリを持つ wiki で、ページが黙って消える |
| `wiki/.wiki-cache/` | 全体が gitignore で「消してよい」場所である。作り直しに LLM のセッションが要るものに合わない |
| `<data_dir>`（wiki の外） | wiki と一緒に運べない。browse の「入力は wiki の内容」に反する |
| ページごとのディレクトリに、サイドカーと図をまとめる | ADR-0030 が `assets/` の下位のディレクトリの svg を読まない |
| モデルが Write でサイドカーを書く | ハッシュ、改行、検査を保証できない。ADR-0023 の向きと逆になる |
| 取り込みのたびに作る | 取り込みが長く、高くなる。作者がコマンドを選んだ |

## 影響

- `wiki/assets/` に、スクリプトが書くファイルが加わる。ADR-0005 の図（モデルが書く、ページの本文の図）とは、名前の形で分かれる。
- ADR-0023 と ADR-0029 の共有の書き込みの部品（`wiki_fsguard`）がまだないので、このスクリプトが道の確かめ（リンク、再解析点、ハードリンク）を自前で持つ。部品ができたら、そこを通す。
- ページを改名すると、概要は元のページのない概要になる。lint が知らせ、移す先の候補を示す。自動では移さない。
- browse での表示は、ADR-0030 の実装のあとに、別の設計で決める。それまでは、概要を作れても browse には出ない。

## 見直す条件

- ADR-0030 が、`assets/` の下位のディレクトリの svg を読むようになったとき（図の置き場所を見直す）。
- ADR-0023 の書く段が実装され、`assets/` への書き込みの口を持ったとき。
- 概要を、取り込みのたびに、または一括で作りたくなったとき。
