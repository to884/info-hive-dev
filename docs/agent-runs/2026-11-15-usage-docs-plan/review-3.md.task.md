# レビューの対象が果たすべき目的

info-hive の Claude Code プラグイン（wiki、今後 rag など）の使い方を、まったく知らない人に説明する利用者向け文書を作る。その計画（`docs/plans/usage-docs-2026-11-15.md`、3 版）と、置き場所と形式の決定（`docs/adr/0022-usage-docs-are-html-in-plugin-docs.md`）を壊してほしい。

読者は Claude Code を使ったことはあるが、Python、uv、GitHub の認証には詳しくない。基準の環境は Windows 11 と Claude のデスクトップアプリ（Code タブ）で、Cowork での違いはハウツー 1 本に分ける。文書の種類は Diátaxis で分け、チュートリアルを最優先にし、読む順番は一本道にする。チュートリアルでは手順ごとに、毎回同じに現れる「成功の目印」を示す。事実は、コマンドの定義、スクリプト、実際の実行から取り、確かめていないことは未確認と書く。

作者がすでに決めたこと（計画の「決まったこと」の表）は、決定そのものを覆すのではなく、その決定のもとで計画が成り立つかを見てほしい。ただし、決定どうしが矛盾する、または決定が既存の仕組み（`/wiki:help`、ADR-0021、AGENTS.md の決まり）を壊すなら、それは指摘してよい。

## これまでのレビューと、その対応

1 版と 2 版のレビューの結果は、`docs/agent-runs/2026-11-15-usage-docs-plan/review-1.md` と `review-2.md`、対応は同じディレクトリの `README.md` にある。3 版では、モデルを取ってくるきっかけが 3 つ（MCP サーバーの最初の接続、`/wiki:init`、MCP サーバーの最初の検索）に分かれていることに合わせて、2-3 の表、S1 の定義、計測の範囲を直した。lint の目印をツールの呼び出しの欄の結果にし、消すファイルへのリンクは全体を Grep して探すようにし、P0 を分類の対象から外した。

## 特に崩してほしい点

1. 2 回目の重大の対応（2-3 のきっかけの表、S1、計測の範囲、W1 の各回をスナップショットから始めること）が、原因を取り除いているか。きっかけの表が、実装（`.mcp.json`、`wiki_mcp_launch.py`、`wiki_mcp_server.py`、`setup_wiki.py`、`commands/*.md`）と合っているか。
2. 2-5 の目印の規則と、それで選んだ目印（lint の目印を含む）。規則に合っているのに毎回は現れない目印。
3. 3 版で足した記述が、新しく生んだ矛盾や手戻り。
4. これまでのレビューが見ていない観点で、計画が目的を果たせなくなる所。
