# レビューの対象が果たすべき目的

info-hive の Claude Code プラグイン（wiki、今後 rag など）の使い方を、まったく知らない人に説明する利用者向け文書を作る。その計画（`docs/plans/usage-docs-2026-11-15.md`、4 版）と、置き場所と形式の決定（`docs/adr/0022-usage-docs-are-html-in-plugin-docs.md`）を壊してほしい。

読者は Claude Code を使ったことはあるが、Python、uv、GitHub の認証には詳しくない。基準の環境は Windows 11 と Claude のデスクトップアプリ（Code タブ）で、Cowork での違いはハウツー 1 本に分ける。文書の種類は Diátaxis で分け、チュートリアルを最優先にし、読む順番は一本道にする。チュートリアルでは手順ごとに、毎回同じに現れる「成功の目印」を示す。事実は、コマンドの定義、スクリプト、実際の実行から取り、確かめていないことは未確認と書く。

作者がすでに決めたこと（計画の「決まったこと」の表）は、決定そのものを覆すのではなく、その決定のもとで計画が成り立つかを見てほしい。ただし、決定どうしが矛盾する、または決定が既存の仕組み（`/wiki:help`、ADR-0021、AGENTS.md の決まり）を壊すなら、それは指摘してよい。

## これまでのレビューと、その対応

1〜3 版のレビューの結果は、`docs/agent-runs/2026-11-15-usage-docs-plan/review-1.md`〜`review-3.md`、対応は同じディレクトリの `README.md` にある。4 版では、モデルの取得と MCP の接続を、読者の手順ではなくプラグインの中の出来事として書き直し（2-3）、計測は、きっかけそのものを起こす操作で行うようにした。ruri は、MCP のツール `query` をはっきり頼んで計る。lint の目印に `read_errors` を足し、`--ensure` が示すことを正した。そのあと作者が、セッションの取り込みのハウツーを足さないこと、W2 の写しを browse の 0.17.0 と Fluent 2 の画面のあとで取ること、ADR-0022 の承認を決めた。
