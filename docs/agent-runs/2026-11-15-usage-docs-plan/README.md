# 利用者向け文書の計画のレビュー（2026年11月15日）

[利用者向け文書の計画](../../plans/usage-docs-2026-11-15.md)の 1 版と [ADR-0022](../../adr/0022-usage-docs-are-html-in-plugin-docs.md) を、GPT-6.1 Sol（effort xhigh）の敵対的レビューにかけた記録である。対象には、v0.16.0（8c400d7）の `info-hive-wiki` も含めた。

| ファイル | 中身 |
| --- | --- |
| `review-1.task.md` | 依頼文 |
| `review-1.md`（`.log`、`.status.json`、`.task.md`） | レビューの結果。判定は「条件付きで採用可」（確信度は高）、致命的はなし、重大は 6 件 |

## 指摘の原因

重大の 1〜3 は、同じ前提から来ていた。成功の目印を、エージェントが判断して作るもの（ページの数、ページどうしのリンク、返答の本文）の上に置いていたことである。取り込みの手順は、主張をソースの要約に残すこと（`source_only`）を認め、`/wiki:init` の定義は JSON の転載を命じていない。目印を 1 つずつ差し替えるのではなく、目印に使ってよいものを、スクリプトかコマンドの定義が決めるものと、定義が出力をそのまま示すよう命じているものに限る規則を、計画の 2-5 に書いた。

重大の 4 と 5 は、どちらも「確かめたつもりで、別のものを確かめる」経路だった。4 は試行の初めの状態が決まっていなかったこと、5 は試験が試験のファイルの置き場所から対象を決めることである。初めの状態（S0、S1）と、試験を走らせる作業ツリーを、計画に書いた。

## 指摘への対応

| 指摘 | 対応 |
| --- | --- |
| 1. 取り込みで `index.md` が 1 行だけ増えるとは限らない | 2-5 の規則を立て、目印を、raw のファイル名から決まる `wiki/sources/味噌.md` と、`log.md` の決まった書式の行に替えた。`index.md` は「`[[味噌]]` の行が増える」とし、数は書かない |
| 2. W2 の共通のリンクと「2 本の出典」は、目印にならない | 目印から外した。つながりは、読者が話し合いの手順で頼む形にし、目印ではなく「こうなるはずです」という案内にとどめる。ならなかったときの対処も書く。質問の出典は「1 つ以上」とした |
| 3. `/wiki:init` の JSON が、返答の本文に出る保証がない | 目印を、会話の中のツールの呼び出しの欄の出力にした。デスクトップアプリでその欄を読めるかは、未確認に足し、段階 2 で確かめる |
| 4. 3 回の試行と大きさの計測に、初めの状態がない | VM のスナップショットで S0 と S1 を決め、各試行を S1 から始める。計測の範囲を「プラグインを入れる直前」から「`"status": "ready"`」までにし、3 つのキャッシュの大きさを前と後で記録する |
| 5. 「最新の main で試験を通す」では、変更したプラグインを試験しない | 変更したサブモジュールを checkout した同じ作業ツリーで試験を走らせ、`git -C info-hive-wiki rev-parse HEAD` を確かめると書いた。「手元にこのファイルがない」の誤りも直した |
| 6. 公開とリンクの版の対応を確かめずに終われる | 段階 3 で公開先を決めるときの 3 つの問い（版の対応、`wiki_help.py` の書き換えの規則と試験、公開の手順）を書いた。段階 4 の終わりの条件に、公開した URL の確認を足した。ADR-0022 の「版がそろう」を、リポジトリの中に限る書き方に改めた |
| 軽微: 大きさの合計と引用の根拠が合わない | 表の値は目安で、足すと約 1.8 GB、1.5 GB はコメントで計測ではない、と書いた |
| 軽微: 認証の確認と git の確認の順序 | 段階 2 の確かめる順を、git の有無 → 認証の順にした |
| 軽微: 残す文書にも消すファイルへのリンクがある | 張り替えの対象に残す文書を足し、`search.md:7` を例に挙げた。リンクの確かめ方にアンカーを足した |
| 軽微: `commands.md` だけでは `/wiki:help` がです・ます体にならない | `commands/*.md` の frontmatter も書き直すと、計画と ADR-0022 に書いた |
