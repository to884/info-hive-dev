# ADR-0025 条件5の達成に向けた設計

**正解の補充手順を小規模に比較し、未決定が減る根拠を得てから、正解と行の印を別々に見直す。** Sol と Astra の原案は、相互レビューでどちらも差し戻された。この文書は共通して崩れた前提を修正したもの。次に進めるのは開発専用画像での比較試験である。[Solのレビュー](reviews/C.md)・[Astraのレビュー](reviews/D.md)

## 維持する条件

主OCRの本文と箱、評価行、単位、正規化を固定する。検出済みの行では正規化後の編集距離1以上を誤りとし、未検出行は別記する。適合率50%以上、検出率80%以上、誤報率15%以下を点推定と、行で重み付けした比および単位平均の片側95%限界で検査する。各指標に有効な単位が10以上、印付き・誤り・正しい行が各20以上。開発用6組を別々に検査し、公開3組では行重みと単位平均の検出率がともに87%以上。未決定は評価に残し、現行の採点と100万配置の上限を適用する。丸めを含む採点器は今回変更しない。[ADRの承認条件](../../adr/0025-pdf-text-layer-with-pdfminer-vertical.md)・[固定条件](../../research/adr-0025-condition5-revalidation-v9-2026-11-18.md)

公開評価2組では、印に依存しない配置数の下限だけで3,237,696・124,961,760。固定v9の印で100万以下にするための最低解消数は8行・23行だが、最も有利な解消箇所を仮定した必要数である。解消箇所を有利さで選ばず、未決定への戻りを含めて実際の新しいラベルと印から再計算する。[検算](verified-evidence.json)

## 1. 補充の比較試験

正式評価に使わない複数の合成原稿を用意し、作成時の正解を固定する。同じ画像を現行・新指示群に別々の新規文脈で配る。最初に変えるのは「提出前に連続記号の位置と個数を見直す」の一文だけ。担当モデル、画像束、原稿が片側に偏らないよう割り付け、同じ担当に同じ画像を両条件で読ませない。主OCR、原稿、文字層、他の票を見せず、両群とも同じ二読と必要時の第三読で集計する。

記号0・1・2個を用意し、濁点、隣の文字片、罫線、色見本を対照にする。所属は固定150 DPIの指定軸で字全体のインクの半分以上と直交中心を確認し、450 DPIは字形の識別に使う。原稿別の脱落、過剰転記、全文の誤→正と正→誤、既知→未決定を記録する。試料と続行判断は回答前に固定する。縦列・境界・回転した字形は別の比較試験で扱い、連続記号の成績から改善を推定しない。[既存の診断と補充計画](../../plans/adr-0025-condition5-image-evidence-next-2026-11-19.md)

## 2. 正解の更新と監査

連続記号の改善だけで2,865行の全面再読へ進まない。二読だけで5,730件になる。全面再読の判断には、全配置上限を超えた二組で未決定を生む失敗型に新手順が効く根拠を求める。絞る場合は、旧正解に記号が残っていること、印、スコア、正誤に依存しない選定規則を公開8,822行に適用する。二重括弧が一つに転記されたような既知の脱落を選定できるか検証する。対象IDを再現できない場合は、元の補充2,865行を使う案を費用と合わせて再評価する。

生の領域正解、画像補充、有効正解を分け、行・箱・入力のSHAと採用した出典を記録する。補充対象を広げる版では引継ぎ条件、結合、二つの母集団・層・重みを固定する。件数検査だけを外して現行コードを流用しない。既知失敗例を新しい標本から除かず、たまたま引かなかった場合も、原因に対する診断を別記する。固定前に公開済みの種で標本を計算せず、保留や不合格を理由に同じ版で種を引き直さない。

**丸印の符号は画像の限界として残る。** 合成PDFの描画は共通のまま `ToUnicode` だけU+2022とU+30FBに変えると、150 DPI・450 DPIでRGBが完全一致し、正規化後の文字は異なった。公式判定は既定どおり、二読が既知で一致した場合は既存正解と照合し、一致・不一致を数える。二読が割れるか未決定なら参照不足。画素で符号を識別できない事実を理由に、既存の不一致を保留に変更しない。補充だけでは、生の領域正解にある既知の符号差は解消しない。これが再監査を止める場合、現行監査のまま保留するか、原稿などの独立した参照証拠を公式に認めるかは作者判断になる。[行別診断](../../research/adr-0025-condition5-reference-audit-rootcause-v9-2026-11-19.md)・[再現コード](glyph_collision.py)

## 3. 印を改善する候補

保存v9予測を新正解で採点し、同じ設定の `v6-mineru-hgb@0.15` を42出版物のLOPOで再学習する。これを基準に新しい証拠を一つずつ比較する。既試行537候補の履歴も保存する。

- **横長の箱を横切る縦列の順序**。固定画像と周辺で列を検出し、一文字と字形が対応づけられたら、固定箱に属する字だけを列の自然な順序に並べて主OCRと照合する。所属の軸と読み順は別々に判定する。反復字や隣列の混入で対応が一意でないときは欠測とし、列検出・字形対応・読み順の失敗を別々に数える。官報3ページの97/97行は文字層の字形位置を利用した原因診断。製品用特徴へ文字層や正解座標を入れず、正しい短行、罫線、ノンブルで誤報を検査する。
- **行頭・行末の記号欠落**。白書の別の失敗型として試す。既存の補助読みは文字単位の座標を持たないため、まず認識文字とインクの対応を別に検証する。対応不能と欠落なしは区別し、両仮説を最初の学習から一つに束ねない。[候補の比較と原因](../../research/adr-0025-condition5-edge-consensus-results-v10-2026-11-18.md)

## 4. 同じ判定を開発から製品まで使う

採点で測る最終的な印を先に定義する。製品の低確信度 `low` を残す案ではモデル印との論理和を開発時から採点し、置き換える案では設定と旧キャッシュの意味を先に決める。固定v9予測へ確信度0.3未満の規則だけを足した試算では、評価2回目9行、評価3回目18行が新たに印付きとなり、全27行が既知の正しい行だった。これは固定予測への加算であり、製品の実測値は未確認である。[現行関数と固定予測の検算](verified-evidence.json)

1. **開発関門**。42分割予測で6組と公開の追加条件を判定する。100万超過の組は全配置未測定とする。領域・画像正解の無作為監査を既定の母集団、層、二系統、三値判定で行い、既知の不一致の追跡結果も確認する。
2. **製品経路の一致**。通過後、既知の開発行で配布用の単一モデルを学習・固定する。LOPOは同じ分割モデルの参照結果と、配布モデルは同じ配布モデルの参照実装と製品経路で照合する。印の版、欠測、中断、設定、旧キャッシュ、既存の確認記録も検証し、行詳細とページ報告が同じ最終行判定に従うことを確かめる。
3. **未使用資料**。開発資料と出版物・原稿が重ならない資料を、既定の関門を通ってから用意する。必要数、割付、正解、モデル・閾値と停止規則を開封前に固定する。製品経路で公開と合成をそれぞれ一度測り、両方が正式条件を満たしたときに達成とする。

比較試験、正解更新、追加候補の実測、正式な再監査は未実施。二系統監査の規則、固定済みの採点結果、正解、製品設定は変更していない。リポジトリ指定のOpusレビューはClaude Codeの利用上限のため未了。
