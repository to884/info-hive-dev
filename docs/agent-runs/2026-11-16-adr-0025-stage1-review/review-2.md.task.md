# ADR-0025 の段階 1 の実装のレビュー（2 回目）

## 目的

1 回目のレビュー（`docs/agent-runs/2026-11-16-adr-0025-stage1-review/review-1.md`）の指摘を直した。直し方が指摘の原因を取り除いているか、直したことで新しい欠陥が入っていないかを壊してほしい。段階 1 の範囲と前提は `task-1.md` のとおりである。

## 1 回目の指摘と直し方

1. **部分取得でページの数の違いを見逃す（重大）:** `analyze_pages` で、最初のページを返す前に `pdfium_page_count` と `pdfminer_page_count`（ページツリーをたどるだけ）を比べ、違えば止まるようにした。全部を読み終えたときに比べる方式をやめた。`stop` は `itertools.islice` で切り、次のページを組み立てない。
2. **古い rag の手順に必要な情報がない（重大）:** `--json` に、文字の層の本文が空のページの数（`empty_text`）と一覧（`lists.empty_text`）を足した。手順では、`--json` の `sha256` と rag の `result.sha256` を照らし、違えばページの情報を使わない。rag の本文が空で `empty_text` に入っていないページを伝える。`ocr_mode` が分からないことも伝える。`always` のときの書き方を直した。
3. **`--max-chars` が上限になっていない（軽微）:** 最小を 500 文字にし、呼び出しの最初のページの見出しと本文の 1 文字が必ず入るようにした。見出しと本文の 1 文字が入らなければ、見出しの前で分ける。1 回の出力は上限を超えない。
4. **続きの位置に抽出の識別がない（前提）:** 続きの位置を `<SHA-256 の先頭 12 文字>:<ページ>:<位置>:<抽出の識別の 8 文字>` にした。ADR の `wiki_pdf.py` の節も直した。
5. **続きを標準エラーだけで知らせる（前提）:** 続きがあるときは終了コード 3 で終わるようにした。手順に、3 は誤りではなく、0 になるまで続きを読むと書いた。
6. **試験 7 の対照が元の `id()` を使っていない（軽微）:** 20 ページの合成の PDF にし、元の pdfminer（`id()` のまま）で取り出すと、少なくとも 1 ページで本文が変わることを確かめる試験を足した（手元の 8 回では、どれも 16〜19 ページで変わった）。列の順の番号の対照も残した。
7. **試作と同じ本文の比べ方（軽微）:** 正規化の前の本文（TextConverter が書いたまま、末尾の改ページの文字だけを除く）で、製品と試作を比べるようにした。
8. **CI が Linux と 3.12 だけ:** Windows と Linux、Python 3.12、3.13、3.14 の組で流すようにした。

## 見てほしいこと

- 上の直し方で、指摘の反例が本当に通らなくなったか。
- `render` の上限の保証に穴がないか（見出しの長さ、空の本文、`--from` で始めたとき、最後のページ）。
- 終了コード 3 にしたことで、手順や呼び出す側に困ることがないか。
- `analyze_pages` を呼ぶたびにページツリーを 2 回たどる費用（`wiki_pdf.py` は `--from` のたびに呼ぶ）。
- 試験 7 の「少なくとも 1 ページで変わる」が、落ちやすい試験になっていないか。
