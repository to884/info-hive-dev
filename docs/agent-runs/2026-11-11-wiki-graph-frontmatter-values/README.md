# wiki 0.9.5（グラフが読む frontmatter の値）の敵対的レビュー

2026-11-11、`info-hive-wiki` のグラフの抽出が frontmatter を wiki の lint と違う値に読む不具合（`sources: [true]` が、lint では `true.md` に解決し、グラフでは未解決になる）の修正を、設計と実装のそれぞれで GPT-6.1 Sol（effort high、`ask-codex` の `review`）に敵対的レビューしてもらった。設計は `docs/plans/wiki-graph-frontmatter-values-2026-11-11.md` にある。

## 設計

- `design-review-task.md`: 依頼の文面
- `design-review-1.md`: 判定は「条件付きで採用可」（確信度：高）。

| 指摘 | 対応 |
| --- | --- |
| 重大 1: オントロジーを PyYAML のまま読むと、数値の `kind`（規約どおり引用符なし）で `maps_from` が当たらなくなり、ノード ID と、それを指す参照が壊れる | `maps_from` の `type` と `kind` も、書かれた文字で読む（設計 2.6） |
| 重大 2: `"graph":`（引用符つきのキー）と読めない YAML が重なると、`unreadable_graph` が見落とす | 構文を読めないときは、行頭の `graph:`、`"graph":`、`'graph':` を文字で探す（設計 2.3） |
| 重大 3: PyYAML が `ValueError` を出す値（`created: 2026-13-01`）で、処理が止まる | PyYAML には構文だけを読ませ、値に組み立てるのは `graph` のノードだけにした。例外は種類を問わず捕まえる（設計 2.3） |
| ID が変わる範囲、lint の辞書と等しい範囲（NFC の前）、手元の wiki に例がないことを互換性の根拠にしていること | 設計 3 を書き直した。lint のパーサーが読めない書き方の欄を、診断 `unread_field` に挙げることにした（設計 2.4） |
| 軽微: 試験の比較の式、アンカーで共有する値、版の理由 | 試験と設計を直した。置き換えは新しい辞書と配列で行う |

## 実装

- `review-task.md`、`review-1.md`: 対象は info-hive-wiki の a38c537。判定は「却下」（確信度：高）。

| 指摘 | 対応（c71d468） |
| --- | --- |
| 重大 1: YAML に書けない文字（NUL など）で `SafeLoader` の生成が失敗し、ページの収集が止まる（0.9.3 からの後退） | ローダーの生成の例外も捕まえる |

| 重大 3: 自分を含むアンカーがあると、`BaseConstructor` が失敗し、参照の欄がすべて元の型のまま残る | 同上。参照の欄のノードだけを見て、中には入らない |

- `review-task-2.md`、`review-2.md`（1 回目のセッションの続き）: 対象は c71d468。判定は「条件付きで採用可」（確信度：高）。致命的・重大な欠陥はなし。1 回目の重大 1〜3 は再現せず、期待値が 0.9.3 のスクリプトの出力と一致することも確かめられた。

| 指摘（どれも軽微） | 対応（f2a32eb） |
| --- | --- |
| 値のない宣言（`sources:`）が、あとの読めないキー（`"sources": "s"`）を隠す | 書いた回数に値のない宣言も数え、値のある宣言が 1 つでもあれば比べる |

この 3 件を直したあとの再レビューは頼んでいない。

## 範囲外として残したこと

- `wiki_text` のパーサーが読まない YAML の書き方（字下げのない `- ` の配列など）を読めるようにすること。今回は、グラフが lint と同じに読まなくなり、診断 `unread_fields` で知らせる。
- `graph.relationships` が配列でない（`relationships: 7`）と抽出が、`predicate` が辞書だとグラフの lint が、`TypeError` で止まること（0.9.3 からある）。
- `object` のない関係の項目を、抽出もグラフの lint も黙って飛ばすこと。
- `tests/wiki/test_mcp_server.py` の後始末（`server_processes()`）が、終わったプロセスの `children()` で `psutil.NoSuchProcess` を出して、ときどきエラーになること。今回の変更と関係のない試験（中継の再接続、入れ直し）で、実行のたびに違う試験に出た。ツール `lint`・`stats`・`graph` の試験（`ScriptToolTests`）は通っている。

## レビューのあとに確かめたこと

- 実際の wiki で、0.9.3（c50854a）のスクリプトと今の実装の出力を比べた（どちらも wiki には何も書かない）。このリポジトリの `wiki/`（4 ページ、エッジ 12 本）と、作者のユーザースコープの wiki（39 ページ、エッジ 219 本）で、ノード、エッジ、別名、グラフの lint の結果が同じで、`unreadable_graph` と `unread_field` は 0 件だった。
- 文字列どうしでも、lint のパーサーと PyYAML で値が違う書き方がある。二重引用符の中の、`\"` と `\` のほかのエスケープ（`\t`、`\n`、`é`）と、引用符のない日時である。どちらもページの規約にない書き方で、グラフは lint と同じく書かれた文字として読むようになる。設計 3 の表と CHANGELOG に足し、試験に入れた（info-hive-wiki の 15d0668）。
- `docs/porting-plan.html` の、frontmatter の解析器が 2 系統あるという 2 か所に、0.9.5 からグラフも最上位の欄を手書きの解析器で読むことを足した。
- info-hive-wiki の CI（`wiki-tests.yml`）が走らせる試験のうち、手元で走らせていなかった `eval/retrieval` の単体の試験（40 件）と `eval/evolution` の 3 つも通った。検索の評価ゲート（`run_eval.py --gate`）は、グラフに触れないので走らせていない。
- PR を作ったあとで、0.9.4（info-hive-wiki#38、info-hive-dev#69）がマージされた。両方のブランチに main を取り込み、0.9.5 のままにした。グラフの lint は、0.9.4 で関係を調べる前に移したエッジの構築に `diagnostics` を渡す。0.9.4 のスクリプトでも、試験の期待値と、2 つの実際の wiki の出力が、今の実装と同じことを確かめた。数字だけのエッジの ID を引用符なしで書いた `contradicts`・`supersedes`（PyYAML は数に読む）が、書かれた文字で残ることの試験を足した。
