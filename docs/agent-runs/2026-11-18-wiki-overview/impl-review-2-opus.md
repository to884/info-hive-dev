## 崩れる前提

- **「リンクがあるときは識別子を照合すれば、元ページの不在を正しく確かめられる」**
  - `missing_page_state` は、wiki のどこかにリンクが1つでもあると、サイドカーの `page` 欄を読む。読めなければ `unknown` を返す。
  - そのため、壊れた孤立概要は、その概要と関係のないリンクが1つあるだけで `--orphan` では消せなくなる。軽微1で扱う。
- **「ハードリンクは overview_entry にすれば、表示と status がそろう」**
  - browse は、名前が規定どおりの項目を `rejected` として `broken` に描く。
  - status の一覧には、その概要が出てこない。軽微3で扱う。

## 見落としと軽微な問題

1. **【軽微】リンクのある wiki では、壊れた孤立概要を CLI で消せない（実測）。**
   - 手順：
     1. 概要を保存してから、元のページを消す。
     2. サイドカーを `b"broken"` に書き換える。
     3. 無関係なジャンクション `elsewhere/` を置く。
   - 結果：
     - status は `broken` になり、`orphan_id` が付かない。
     - `remove --orphan` は `not_orphan` で拒む。
     - ページの指定で消そうとすると `not_found` になる。
     - CLI から消す方法がなく、残るのは手での削除だけである。しかし SCHEMA はサイドカーを「手で編集しない」としている。
   - `elsewhere` を消すと、`removed` になった。
   - 文書も食い違っている。
     - `docs/plans/wiki-overview-2026-11-17.md:279` は「判定は PageState だけで行い、サイドカーの中身は読まない。壊れていても、元のページがなければ消せる（5 回目のレビューの重大 1）」のままである。
     - ADR-0033:40 と表示設計:295 は、新しい規則（不在を確かめられなければ消さない）になっている。
   - fail-closed なので安全側だが、段階1のレビューで直したことが、条件付きで元に戻っている。
2. **【軽微】リンクのある wiki で、存在しない概要に `remove --orphan` を実行すると `not_orphan` になる（実測）。**
   - 例：`remove(w, "0123456789abcdef")` は `not_orphan` になる。
   - リンクがなければ `{"status": "absent"}` を返す。
   - 原因：`read_sidecar` が返す absent を `_metadata(b"")` で読もうとして失敗し、`unknown` になる。
   - 利用者には「元ページがある」と誤って伝わる。
3. **【軽微】ハードリンクのサイドカーの扱いが、status と browse で分かれる（実測）。**
   - status：`overviews` は空で、所見は `unknown_entry` だけになる。page も reason も付かない。
   - browse：`broken` を描く。transient にはならない。
   - HEAD の status は、同じものを `broken/unreadable` としていた。設計4節の「既存の所見を変えない」と食い違う。
   - `manifest.incomplete.unreadable_overviews` も、この項目を数えない。
4. **【軽微・推測】診断の reason から衝突の理由が消える。** サイドカーが壊れていて、かつ P が衝突しているとき、reason には `detail` が入る。`collision` は記録されない（コードから）。

**採らなかった軽微指摘への判断：**

- `Assets/` 綴りとリンクの `assets` で全記事に警告を出すこと：保持で妥当である。降りずに概要の不在は確かめられない。
- SVG の SHA の衝突を mock で試すこと：fail-closed の確認として妥当である。
- sweep の網羅：全網羅とは主張していない。lstat と open の境界は専用試験で補っている。

## 検証した事実

- 作業ツリーは、提示差分と一致する範囲で固定されていた。`missing_page_state` は `wiki_overview.py:344` にある。
- **ジャンクションの裏の記事（実測）**
  - status は `page_unreadable`、browse の診断は `overview_page_unreadable` になった。
  - `remove --orphan` は `not_orphan` で拒んだ。主張と一致した。
- **ハードリンクのサイドカー（実測）**：browse は `broken` で、`transient` は `[]` だった。前回の再試行の繰り返しは解消している。
- **リンクのない wiki（実測）**：壊れた孤立概要を `--orphan` で消せた。主張と一致した。
- **too_large の重複**：`_draft` は `problem not in problems` で重複を除く。`test_oversized_draft_reports_size_once` もある。
- **存在しない概要への衝突診断**：概要がなければ状態は `none` なので、診断は出ない。サイドカーがあるときは1件になる（コードから）。
- **描かない記事の図**：`rendered_keys` で、描く記事の図だけを出力するようになった（コードから）。
- **不正な概要の案内**：無条件の再生成の案内は「診断で元ページと概要の状態を確認する」に替わった。古い概要には、作り直しの案内が残る。
- **ブラウザ試験の待ち方（読んだだけ）**：配色を変えたあと、図の `src` が変わって枠がなくなるまで待つ。手書き SVG の地が `rgb(255, 255, 255)` であることも確かめている。実行はしていないので、確かめられず。
- **文書**：ADR-0033:40 と表示設計:295 に、リンクの境界を追記していた。一致した。ただし保存設計:279 は古いまま（軽微1）。

## 崩せなかった点

- **NFC の照合**：照合する単位はディレクトリの境界と `.md` を除いた名前の一致である。`con` が `concepts/x` に一致するような接頭辞の誤一致はない。`concepts/p` という名前のディレクトリのリンクを、ページの `concepts/p` と取り違えることもない（コードから）。
- **署名の変化**：nlink が 1 に戻ると、入力の種類が `overview_entry` から `overview` に変わるので、署名が変わる。
- **一時障害との区別**：読み取り時に安全性の検査で拒んだものは `unsafe`、真の OS 障害だけが `os` になる。transient に入るのは `os` だけである。
- **BOM**：二重 BOM のページでも、BOM を一度だけ除く。ハッシュの経路は status と browse で共通になった。
