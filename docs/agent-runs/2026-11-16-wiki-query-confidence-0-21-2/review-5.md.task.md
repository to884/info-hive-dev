# 依頼: 4 回目のレビューの直しを壊す（5 回目）

4 回目のレビュー（`review-4.md`、却下）の 3 つの指摘は、どれも「ページごとのたどり（どのリンクから開いたか）を記録から復元できる」という前提が崩れたものだった。反例を塞ぐのをやめ、前提を変えた。差分は `docs/agent-runs/2026-11-16-wiki-query-confidence-0-21-2/plugin-5.diff`（プラグインの `origin/main..HEAD` の全体）である。

見つけ方は、答えのページごとに、そのページを初めて開いたときより前に呼んだ探す道具（MCP の `query`、CLI の `wiki_search.py` の検索で `--backlinks` を除く、`Grep`、`Glob`）だけで決める（`query-confidence.md` の縮退の理由の表のあとの 1〜4）。

1. 前に 1 つも呼んでいない → インデックス。縮退なし。
2. 前に呼んだ正常な hybrid の検索の結果にそのページが出ていた → その検索。縮退なし。
3. 前に `Grep`・`Glob` か縮退した検索を呼んでいた → 縮退。`Grep`・`Glob` があれば理由 0。
4. 前に呼んだのが正常な hybrid の検索だけ → 縮退なし。

たどり（リンク、frontmatter の `sources`、グラフ、`--backlinks`）は見つけ方に関わらない。前に呼んだ `Grep` が別の目的でも縮退に数えるので、判定は低い側に寄る。これは受け入れた（ADR の「見つけ方の決め方」）。

同じ記録から 2 通りの判定を導ける並び、決まらない並び、決め方が作者の案 2-B（`Grep` か `Glob` で答えのページを見つけたら縮退に数える。矛盾や答えがないことの確かめは数えない）から外れる並びを崩してほしい。`task-1.md` の成り立つべきこと 1〜5 は変わらない。低い側に寄ることで、測った問いのうち高が期待の問い（R01、R05、R08、R13）が、Sonnet の普段の道具の使い方（`Grep` を 48 回中 38 回使い、多くは矛盾の確かめだった）で中に落ちる見込みがどれほどあるかの見立てもほしい（推測なら推測と書く）。
