第6回の最初の報告（review-6.md）は却下で、第5回の重大1は保証全体が未閉鎖とされた。ユーザーの「第5回の5件を根本的に修正する」という依頼が残るため、根と読み取りの境界をさらに修正し、同じ第6回の継続として確認する。新しい独立した第7回は起動していない。

## 変更

- _article_rel は、まず渡された綴りと既知の根の綴りを要素ごとに比較する。一致しない場合に限り、祖先を上から realpath し、既知の根に届いたところで止める。そこから下の入力の要素は解決せず、article_path に渡す。CLI が wiki の根を解決した後でも、入力の根の別名に到達した時点で所属を復元し、途中の外向きのリンクを読む口で拒む。
- 文字列を小文字化した長さで元のパスを切らず、要素の個数で相対パスを作る。大文字小文字の変換で文字数が変わる例も回帰試験にした。
- source_wiki_root が、コーパスが元の wiki の一部かを判定する。一部なら元の根を引き継ぎ、外にある場合だけコーパスを独立した根として扱う。evaluate のコーパスを先に resolve する処理も外した。
- require_readable_articles は削除した。コーパスの事前検査は、その入力の tree を実際の根の文脈で検査する形にそろえた。run の test_keys、evaluate/run の copy_tree も同じ corpus_root を使う。元の wiki 全体に無関係なリンクがあっても、そのためだけに部分木の処理を止める形にはしていない。
- 記事を含みうるディレクトリの検査を、article_path の directory 引数と user_directory_path にまとめた。tree は起点と途中のディレクトリについて、降りる前にこれを使う。記事でない assets 等の範囲は、記事のリンクの規則では拒まない。
- user_file_path は記事の定義に入る名前を、読む口の入力検証の not_article で無検査読み取りに戻さない。POSIX では : を通常の名前として属性検査する。Windows で検査できない記事の名前は unknown として拒む。

## 追加した実行の回帰試験

- 実際の CLI に --wiki を根の別名で渡し、その配下から外へ向くジャンクションを通る候補を拒否し、通知が出ること。
- 文字列とバイト列の両入口でも、同じ別名と外向きリンクの組合せを拒否すること。
- wiki の部分木のコーパス内の assets/p.md が、元の wiki では記事として拒否されること。run と evaluate の両入口で本文を読まず、後続へ進まないこと。
- コーパス自身を誤って根として渡す対照を、同じ回帰の検査が失敗として検出すること。
- 元の wiki の assets/ 配下のコーパスでは、対象外のファイルを新たな記事にせず、ハードリンクの通常ファイルをコピーできること。
- リンクのディレクトリを、os.walk に渡す前に拒否すること。
- POSIX の : を含む記事が属性の検査を通り、ハードリンクなら拒否されること。これは Windows でも属性を差し替えた検査を実行した。実際に : を含むファイルを作る POSIX 専用の試験も追加したが、この Windows 環境では skip。
