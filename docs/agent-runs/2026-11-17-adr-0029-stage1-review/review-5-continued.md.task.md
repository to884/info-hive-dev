# 第5回レビューの継続：ローカルの読み取り環境を復旧

これは第6回や別のレビューではなく、現物を読めなかった前ターンの第5回レビューを完了するための継続である。コードとレビュー対象は変更していない。元の依頼は task-5.md にある。

前ターンは registered Core launch requires an installed app のため、現物、ADR、設計書、試験を読めず、添付差分だけの部分レビューになった。依頼元は、デスクトップ専用の CODEX_WINDOWS_REGISTERED_CORE が子の CLI に継承されたことを切り分けた。今回は子プロセスだけその変数を外し、インストール済みのデスクトップ同梱 CLI を使っている。read-only サンドボックスと approval never は維持する。この組み合わせでローカルの読み取りコマンドが動くことを確認した。

まずローカルの読み取りが動くか確かめ、元の task-5.md に列挙した対象と規範を実際に読む。第4回の6件の閉鎖判定、新しい欠陥、試験の妥当性を確認し、独立した第5回レビューの最終報告を全文で出す。前ターンの「未確認」のまま完了にはしない。コードと試験を書き換えず、再委譲や他モデルの追加レビューは起動しない。

前ターンの candidate の誤拒否は、依頼元も一時ディレクトリで実測した。通常の記事と wiki 外の候補は read_bytes に進むが、wiki/assets/candidate.md の通常ファイルは read_bytes 前に「候補が wiki の中の記事で、リンクか調べられないので読まない」で止まった。ハードリンクの記事は read_bytes 前に拒否された。これは独立した補助事実として扱い、自分でもコードと規範を照合する。

テストの範囲と出力形式は元の依頼どおり。第5回の最終報告では、前ターンの部分レビューと今回実際に確認した内容を区別し、現在のファイルと行番号を使う。
