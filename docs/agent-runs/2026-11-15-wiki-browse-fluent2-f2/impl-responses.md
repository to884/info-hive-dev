# browse の記事のページを Fluent 2 にする実装（段 F2）のレビューへの対応

## 1 回目（[impl-review-1.md](impl-review-1.md)、条件付きで採用可。分類 A は 0 件）

止める条件に届いたので、実装のレビューはここで終える。残った B と C は、どれも試験の確かめ方の問題なので、場所を数え上げずに、確かめ方の仕組みを直した。直した確かめは、壊した CSS（暗い配色だけで `#_body h3` を隠す、メタ欄の最後の行のホバーで地を変える）を一時的に足して流し、どちらも落ちることを確かめた。

| 分類 | 指摘 | 原因 | 対応 |
| --- | --- | --- | --- |
| B | 測れた部品を light と dark で合わせて数えるので、片方の配色だけで消えた部品を見逃す | 測れた部品の集合を、配色のループの外に 1 つだけ持っていた | 集合を配色ごとに作り、配色ごとに「測れなかった部品」を落とす |
| C | 読むだけの行の地が変わらないことを、メタ欄と関係表の先頭の行のホバーでしか比べていない。比が 4.5 を保てば、地を変えても通る | 4.2 の 1 つ目の規則（地を変えない）を、比の規則（2 つ目）と別の、場所を挙げた確かめにしていた | 地が変わりうる入れ物を順に測る `stateContrast` で、読むだけの入れ物（`#_main` の `tr` と `li`）のすべてについて、ポインターと押下の前後の地を比べる。先頭の行だけの確かめは外した |
| C | 長い値の材料が、種類、タグ、関係の証拠だけで、題名、要約、出典の題名、被リンクの題名、診断を覆っていない | — | 長い題名と要約を持ち、長い題名の出典を指し、関係のページへリンクし、長い未解決のリンクを持つページを足した。幅 320〜1000 の確かめが、メタ欄、被リンク、診断の長い文字を通る |

## ブラウザごとの結果（見た目を試作に合わせたあと）

| ブラウザ | 方式 | `findability.test.mjs` | 記録 |
| --- | --- | --- | --- |
| Chromium | 静的とサーバー | 失敗 0（`browse.test.mjs` も失敗 0） | `find-chromium.json`、`browse-chromium.txt` |
| WebKit | 静的 | 失敗 0 | `find-webkit.json` |
| Firefox | 静的 | F2 の確かめはすべて通る。F1 の検索の後読みの 3 件が落ちる | `find-firefox.json` |

Firefox で落ちる 3 件（フォーカスで `search.js` を読む、読めない検索の索引、遅れて届く検索の索引）は、`page.on("request")` と `page.route` で `file://` の要求を見る試験である。Firefox の Playwright は `file://` の要求を記録も差し替えもしないとみられ、F2 で変えていない検索の後読みの確かめなので、範囲の外とした。3 つのブラウザで両方の方式を流すと 40 分を超えたので、Firefox と WebKit は静的の方式だけにした。

## 実装の段で分かったこと

- 試作の `#_main a:active` の押下の色（`colorBrandForegroundLinkPressed`）は、暗い配色で地との比が 3.85:1 になり、試験が落とした。押している間もホバーの色のままにした。
- 関係表のセルを、レビューの時点では `word-break: normal` にしていた。レビューのあとで画面を撮って試作と見比べると、48em に収めるときに「ソース/の例」のように語の途中で折れていた。設計の 5 節（セルの中で語を折らない）と、作者が承認した試作に従い、`keep-all` に戻した。日本語は空白と句読点で折り返し、句読点のない長い値は入れ物の中で送る。決まった文字の見出しのセルは `nowrap` にした。
- レビューのあとで、試作にない見た目（本文の表の全周の線、見出しのセルの地、`pre` の枠、関係表の見出しの太字、h4 の余白）を外し、試作に合わせた。撮った画面は `shots/` にある。
- `#_main` の右端を越える要素を数える確かめは、畳んだ検索欄の消去ボタン（幅 0 で `overflow: hidden` の入れ物の中）を数えた。見えないので、祖先が切り取る要素を除いた。
