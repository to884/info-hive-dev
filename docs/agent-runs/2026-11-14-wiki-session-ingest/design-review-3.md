## 判定

**却下。確信度：高。** 未確認の写しが Git に入る経路と、異なるセッション ID を同一と判定する反例がある。再開時の完了判定と並行実行にも、取り込み済みという判定や raw の不変性を崩す条件が残る。

以下は未実装の設計に対する反例である。既存コードで実行確認した事項とは区別する。

## 致命的・重大な欠陥

**1. 【重大】未確認の写しを Git の管理外に置く保証が、警告だけで破られる。**

次の状態は、設計の初期化判定を満たす。

1. `SCHEMA.md` と raw のルートはある。
2. `.wiki-cache/.gitignore` はなく、上位にも除外規則がない。
3. 会話には、自動伏せ字に該当しない顧客情報がある。

この状態でも `extract` は `extracted.md` と `review.md` を書き、`work_dir_not_ignored` を警告するだけである。人の確認前に別セッションが `git add -A` を実行すれば、未確認の全文が登録対象になる。`.gitignore` が存在しても、中身が空の場合や、写しがすでに追跡対象の場合を扱う規定もない。

raw のルートから移しただけでは、「確認の前の写しは Git の管理から外れた場所に置く」という目的を満たさない。

根拠：[目的](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:38)、[書き込みと警告の規定](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:240)、[警告だけを確かめる試験](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:432)。既存の `wiki_initialized.py@7495ca5:67–91` は `.gitignore` を初期化条件に含めない。

**2. 【重大】`session_id` が同一性に入っておらず、別の ID の取り込みで以前の raw を再利用する。**

次の入力を用意する。

- `A.jsonl` と `B.jsonl` は同じバイト列。
- 内容には、UUID の A と B の両方の `sessionId` がある。
- どちらの ID 検索も、対応するファイルを一意に見つける。
- 題名、スラッグ、範囲、抽出条件は同じ。

まず `--session-id A` で抽出・確認し、要約ページを書く前に止める。次に同じスラッグへ `--session-id B` で抽出する。

ID の決め方では今回は B になる。しかし、同一性の比較項目に `session_id` がないため、ハッシュ、長さ、題名、抽出条件はすべて一致する。取り込み直しの表の2行目が適用され、**A を記録した raw を B の取り込みの確認済み原本として返す**。raw がまだなく作業用の写しだけの場合も、4行目で同じ問題が起きる。

混在 ID を認めた構造では、内容のハッシュだけから採用する ID は決まらない。

根拠：[ID の決定順と混在の許容](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:89)、[`session_id` を同一性から除く表](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:223)、[再利用の判定](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:288)。

**3. 【重大】未知の発話レコードを除くと、別の依頼への返答が前の返答につながる。**

形式変更を模した合成入力として、次の順序を与える。

```text
user / origin.kind=human       U1
assistant / text              A1
future_user / origin.kind=human U2
assistant / text              A2
```

U1 があるので、人の発言が0件という停止条件には当たらない。未知の種類はエラーにせず除く規定であり、`future_user` は「そのほか」の行に入り、ターンの境界にもならない。

結果として A1 と A2 が一つのアシスタントのターンになる。U2 の位置に通知の印はなく、A2 が U1 への返答として読める。`excluded` の件数だけでは、失われた境界を復元できない。

これは将来その名前が採用されるという予測ではなく、未知のレコードを受け付けて除く規則に対する反例である。根本原因 E の「除いた位置でも境界を残す」は、未知の種類には適用されていない。

根拠：[未知の種類はエラーにしない規定](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:111)、[未知の記録は境界にしない表](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:126)、[ターンの境界](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:152)、[根本原因 E](/C:/Works/info-hive-dev/docs/agent-runs/2026-11-14-wiki-session-ingest/root-causes.md:13)。

**4. 【重大】要約ページが存在した時点で、未完了の取り込みを `ingested` と判定する。**

既存の取り込み手順では、ソースページを作ったあとにも、関連ページの更新、主張と行き先の記録、インデックス、ログ、グラフの処理がある。

次の中断が成立する。

1. `check --finish` が完了する。
2. `sources/s.md` を作る。
3. 関連ページやインデックス、ログの更新前にセッションを中断する。
4. 同じ取り込みを再実行する。

表の1行目は raw と `sources/s.md` の存在だけで `ingested` を返す。未完了の後続処理を再開する状態は定義されていない。ソースページを書きかけの段階でも、存在条件は同じである。

第2回の「旧記事と新 raw が並ぶ」という逐次実行の反例は防いでいるが、**記事ファイルの存在を取り込み全体の完了とみなす前提**は残っている。

根拠：[既存手順3〜8へ進む規定](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:271)、[`ingested` の判定](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:287)。既存側は `commands/ingest.md@7495ca5:20–22`、`references/ingest-workflow.md@7495ca5:198–256`。

**5. 【重大・並行実行の決め残し】存在確認と原子的な置換だけでは、取り込み後の raw の上書きを防げない。**

同じ wiki・スラッグを2プロセスで扱い、一時ファイル名は処理ごとに異なるものとする。記載された手順では、次の割り込み順が成立する。

1. A の `check --finish` が検査を通り、要約ページがないことを確認する。R1 の一時ファイルを書き、置換の直前で停止する。
2. B が異なる条件で `extract --force` を実行する。まだ raw はないので表の5行目に入り、新しい写しを作る。
3. B が `check --finish` で R2 を置き、R2 に基づく `sources/s.md` を作る。
4. A が再開し、一時ファイルを raw に置換する。

最終状態は **raw が R1、記事が R2 の要約**になる。A の存在確認は記事作成前に済んでいる。個々の置換が原子的でも、この順序は防げない。

並行実行を排除する規定や、確認から置換までを保護する手順はない。第2回の重大7が、並行実行では再び成立する。

根拠：[同じ作業ツリーの別セッションを想定した説明](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:238)、[確認後の書き込み順序](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:257)、[`--force` の状態遷移](/C:/Works/info-hive-dev/docs/plans/wiki-session-ingest-2026-11-14.md:291)、[根本原因 O の対応](/C:/Works/info-hive-dev/docs/agent-runs/2026-11-14-wiki-session-ingest/root-causes.md:56)。
