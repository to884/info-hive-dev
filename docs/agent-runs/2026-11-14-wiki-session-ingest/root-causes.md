# 1 回目のレビューで崩れた前提（2026年11月14日）

[design-review-1.md](design-review-1.md)（Sol、却下、確信度は高）の指摘 8 件と「崩れる前提」を、設計書の 1 版目と照らした。どれも当たっていた。指摘を 1 つずつ塞ぐと、同じ前提から別の反例が出る。そこで、1 版目が暗に置いていた前提を書き出し、どの指摘がどの前提から出たかを対応づけてから、構造を変える。

## 前提と、それが崩れた指摘

| 記号 | 1 版目の前提 | 崩れた指摘 | 崩れ方 |
| --- | --- | --- | --- |
| A | 発言の本文を Markdown として連結しても、ターンの境界（見出し）は本文に壊されない | 重大 4 | 閉じていないコードフェンスが、あとのターンの見出しを飲み込む |
| B | 伏せ字の検査は、raw の全体を写しと比べれば足りる | 重大 5 | 全体の部分列で、見出しの並びも同じまま、本文をほかのターンへ移せる |
| C | frontmatter には機械が決める値だけが入る | 致命 1 | 題名、ブランチの名前、パスに、会話から来る文字列が入る。固定したので人が伏せられない |
| D | 話者は本文の形（タグ）とファイル全体の形式から推せる | 重大 2、重大 3 | 人の HTML を捨て、未知の差し込みを通す。`origin` のないファイルは古い対話ではなく `claude -p` だった |
| E | ターンの区切りは、残した人の発言だけで決まる | 重大 7 | 読めない行や除いた記録の位置で、別の依頼への返事が前の依頼につながる |
| F | 作業用の写しがないことは、確認が終わったことを表す | 重大 8 | 写しを失っただけの未確認の raw と、確認を終えた raw が同じに見える |
| G | raw の場所は wiki の隣の `raw/` である | 重大 6 | raw のルートを変えた wiki で、`raw/<スラッグ>.md` が lint で見つからない |
| H | 記録が同じなら raw も同じになる | 崩れる前提の表 | 時差の既定が PC で違う。引数と抽出器の版を変えても `unchanged` になる。記録の場所が出力に入る |

## 構造の変え方

| 記号 | 2 版目の構造 |
| --- | --- |
| A | 発言の本文は、ターンごとに 1 つのコードフェンスで囲む。フェンスの長さは、本文の中の最も長いバッククォートの並びより 1 つ長くする（3 以上）。本文がフェンスの外に出る経路がなくなるので、見出しを下げる処理も要らない。構造（ターンの見出しとフェンスの区切りの行）は、フェンスの外にだけある |
| B | 検査は、構造と中身を分けて照らす。raw を同じパーサーで読み、ターンの見出しとフェンスの区切りの行が写しと同じであること（消したターンを除く）を確かめる。中身は、ターンの番号で写しのターンと対応づけ、ターンごとに「消すことと `［伏せ字］` への置き換えだけか」を確かめる。本文をターンの外へ移す編集は、構造か中身のどちらかで必ず崩れる |
| C | frontmatter の値を 2 つに分ける。会話から来る文字列（`title`、`cwd`、`git_branch`）は、本文と同じ規則で伏せてよい。ハッシュ、ID、時刻、数、引数は固定する。題名とスラッグは、スクリプトが提案し、書く前に人が決める（`inspect` を足す）。ファイル名に残る文字列も、書く前に人が見る |
| D | 話者は、記録ごとの構造化された属性（`origin.kind`、`turnOrigin`）だけで決める。本文の形から話者を推さない。属性のない記録は「話者不明」として除いて数える。本文の加工は、ハーネスの既知の差し込みを、観測した位置（本文の先頭）に限って除くことだけにする。知らないタグは残し、本文がタグで始まる人の発言には警告を出して人の確認に回す。中断の印は、完全に一致する既知の文字列だけを扱う |
| E | ターンの境界は、残した人の発言のほかに、除いた記録と読めない行の位置でも切る。除いた位置のあとにアシスタントの本文が続くなら、何を除いたかを書いた印のターンを置く。読めない行は警告にもする |
| F | 確認の完了を、raw そのものに書く。`check --finish` が frontmatter に `reviewed_at` と手で伏せた数を書いてから、写しを消す。写しがなく `reviewed_at` もない raw は「確認の前に写しを失った」と判定し、`--force` で作り直すことを求める |
| G | ソースの要約ページに書く `raw` の値は、スクリプトが計算して出す。lint の `missing_raw()` と同じ解き方で、実際に見つかることを確かめる |
| H | raw の同一性に、記録の SHA-256 のほかに、抽出器の版と、出力を変える引数（`--tools`、`--exclude-last-prompt`、`--utc-offset`）を入れる。時差の既定は UTC にし、渡した値は frontmatter に残す。記録の場所は raw に書かない |

## 2 回目のレビューで崩れた前提

| 記号 | 2 版目の前提 | 崩れた指摘 | 崩れ方 |
| --- | --- | --- | --- |
| I | 入口で認識できなかった `.jsonl` は、ふつうのソースとして取り込んでよい | 致命 1 | 記録の形が変わると、思考を含む記録の全体が、伏せ字も確認もなしに raw になる。「何も通さない側に倒れる」と両立しない |
| J | 同梱のパーサーの出力（トークンと frontmatter の値）を比べれば、ファイルの字面を比べたことになる | 重大 2、軽微 5 | パーサーが捨てる文字列（参照の定義、frontmatter のコメント）と、パーサーが書き換える文字（NUL）の書き足しを見逃す |
| K | 「最後の人の発言」で、除く範囲が決まる | 重大 3 | 題名を確かめるやり取りを挟むと、除くのは取り込みの依頼ではなく、確かめへの返事になる |
| L | frontmatter から来た値なら、フェンスの外に置いてよい | 重大 4 | 改行を含む題名を `#` の見出しにすると、フェンスの外からターンの構造を壊せる |
| M | 伏せ字の規則は、記録と引数だけで決まる | 重大 5 | `Path.home()` が PC で違うので、同じ記録、同じ引数でも raw が変わる |
| N | 本文の先頭にある既知のタグは、ハーネスが作ったものである | 重大 6 | 人がその要素を資料として書くと、本文が消える。空になった発言は境界にもならない |
| O | 取り込み済みかは、要約ページがあるかで決まる。取り込んだあとの raw も `--force` で上書きしてよい | 重大 7 | 上書きした raw と、前の raw から書いた要約ページが並び、取り込み済みに見える |
| P | 記録のファイル名の ID と、記録の中の `sessionId` は同じである。`projects` そのものはリンクでない | 軽微 1、2 | 別のセッションから写した記録を含むファイルがある。`projects` をジャンクションにすれば、外を読める |

## 3 版目の構造

| 記号 | 3 版目の構造 |
| --- | --- |
| I | 入口を閉じる側に倒す。`.jsonl` は、キーワード（`session`、`session:<ID>`、`session:<パス>`）の有無によらず `inspect` にかけ、セッションの記録と認めなければ止まる。会話の記録らしい形かを見分けて、ふつうの取り込みに回す分かれ道は作らない（形で見分ける規則も拒否リストで、形を少し変えた記録に破られる。3 版目をレビューの前に見直して直した）。ふつうの取り込みに進むのは、ユーザーが明示して頼んだときだけである |
| J | raw の形を、決まった文法にする。`check` は、スクリプトが自前で書いた厳密な読み手で raw を読み、同じ書き手で書き直して、バイト列が raw と一致することを確かめる。パーサーが捨てる文字列も書き換える文字も、書き直しで一致しなくなる。中身の照らし合わせは、読み手が取り出した文字列で行う。同梱のパーサーでの読み方の一致は、補助の検査として残す |
| K | 除く範囲を、位置でなく記録の ID で決める。S1 で `inspect` が、取り込みの依頼の記録の `uuid` を出す。`extract --before <uuid>` は、その記録の行の前までを読む。範囲が固定されるので、あとで取り込み直しても、同じ範囲なら `unchanged` になる |
| L | フェンスの外に置く文字列は、スクリプトが決めた語、整形した時刻、形を検査した識別子（モデルの名前）だけにする。題名の見出しを本文に置かない。題名は frontmatter にだけ置き、1 行であることなどを検査する |
| M | 伏せ字の規則から、実行する PC の値（`Path.home()`）を除く。規則は、記録と引数だけで決まる。規則に当たらないホームのディレクトリは、人の確認で伏せる |
| N | 話者の属性で見分けられないものは、機械では見分けられないと認める。先頭の `<system-reminder>` は既定で除くが、除いたターンを `warnings` に出し、`--keep-reminders` で除かずに抜き出し直せる。人の発言の記録は、加工で空になっても境界にする |
| O | 取り込んだあとの raw は変えない。`sources/<スラッグ>.md` があれば、`--force` は拒む。別版のスラッグで取り込む。`check --finish` の raw の書き直しは、一時ファイルと名前の変更で行う |
| P | セッションの ID は、記録のファイル名とする。中の記録に別の ID があれば、`warnings` に出す。ID で探すときは、ID が記録のどこかの `sessionId` にあることを確かめる。設定のディレクトリの下の `projects` もリンクでないことを確かめる |

## 前提にしないこと（2 版目と 3 版目で明記する）

- 伏せ字の検査は、書き足しと言い換えと構造の変更がないことを保証する。消したことで意味が変わらないことは保証しない。
- 人の発言として属性が付いた記録に、ハーネスが知らない形で文を差し込むことは、機械では見分けられない。警告と人の確認でふさぐ。
- 人が本文の先頭に `<system-reminder>` の要素を書いたことと、ハーネスが差し込んだことは、機械では見分けられない（3 版目）。既定では除き、警告を出し、引数で除かずに抜き出し直せるようにする。
- 記録の形式は公開された仕様ではない。観測した属性の値が変われば、許可リストが何も通さなくなる側に倒れる（人の発言が 0 件なら終了コード 2）。漏れる側には倒れない。
