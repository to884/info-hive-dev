# raw だけを排他にしたときの wiki の整合性の確認（2026年11月14日）

作者の問い「raw だけを排他にすると、wiki の整合性がどうなるかを確認して」に答えるために調べた記録である。対象は、4 体の再設計の総括（[summary.md](../2026-11-14-wiki-session-ingest-redesign/summary.md)）が推した構造（raw は排他作成、索引とログの競合は既存どおり防がない）である。

## 取り込みが wiki に書く場所

`info-hive-wiki` の 7495ca5 の `commands/ingest.md` の手順 5〜8 で書くものと、書き手は次のとおりである。

| 書く場所 | 書き手 | 排他 |
| --- | --- | --- |
| raw | スクリプト（再設計では排他作成） | あり |
| `sources/<スラッグ>.md` | モデル（Claude Code の Write） | なし |
| 関連するエンティティとコンセプトのページ | モデル（`str_replace`、つまり Edit） | なし |
| `index.md`（分割していれば `indexes/`） | モデル（Edit） | なし |
| `log.md` | モデル（Edit で追記） | なし |
| `graph/graph.sqlite` | `wiki_graph_extract.py` | あり（`<出力先>/.extract.lock`） |
| MCP の索引 | MCP サーバー（ファイルの署名から作り直す） | ページから作り直せる派生物 |

wiki のスクリプトで排他を持つのは、グラフの抽出と閲覧（`wiki_browse.py`）だけである。共有のテキストファイル（索引、ログ、関連ページ）は、モデルが Claude Code のツールで書き、排他はない。

## 試したこと

一時ディレクトリの `index.md` と `log.md` で、もう 1 つのセッションに見立てたプロセスと、このセッション（Claude Code 2.1.321、デスクトップアプリ）の Edit と Write を並べた。

| 試験 | 結果 |
| --- | --- |
| 1. 読んだあと、ほかのプロセスが 1 行を足し、そのあとで Edit で 1 行を足す | 両方の行が残った。ハーネスは次のツールの結果に「ディスクで変わった」と知らせた |
| 2. ほかのプロセスが 1 行を足すのと同じ応答の中で、古い内容のまま Write で全体を書き直す | Write は `File has been modified since read` で拒んだ。何も消えなかった |
| 3. 2 と同じ並びで、Edit で 1 行を足す | Edit は当たり、ほかのプロセスの行も残った。結果に「ほかの変更がある」との注意が付いた |
| 4. ほかのプロセスが `log.md` を 10 ミリ秒ごとに「読む、足す、書く」で 1,500 回書き換える間に、Edit で 5 行を順に足す | **両方向に取りこぼした。** Edit の 5 行のうち 1 行（5 行目）は、Edit が成功と報告したのに消えた。ほかのプロセスの 1,500 行のうち 7 行が消えた。どちらも誤りは出なかった |

## 分かったこと

- **よくある競合は、Claude Code のツールが防ぐ。** 古い内容を覚えたまま全体を書き直すこと（Write）は拒まれる。`str_replace`（Edit）はディスクの今の内容に当たるので、ほかのセッションが先に足した行を消さない。試験 1〜3 で、取りこぼしはなかった。
- **ただし、同時の書き込みは、黙って失われる。** Edit も内部では「読む、直す、書く」であり、原子的ではない。2 つの書き手の「読む」と「書く」が数ミリ秒の中で重なると、後から書いた側が前の側の変更を消す。試験 4 では、Edit が成功と報告した行が消えた。人が操作する 2 つのセッションで重なる見込みは小さいが、0 ではない。起きたときは、どちらの側にも誤りが出ない。
- **起きたあとに見つける手段がない。** 4 体の相互レビューで C と D が確かめたとおり、lint の `index_type_mismatch` は索引にある項目の型を見るだけで、索引に足りない項目は見つけない。`log.md` はページの走査の対象外である。索引の行やログの行が消えても、lint は何も言わない。
- **Claude Code のツールを通らない書き手は、何の保護もない。** Codex の `apply_patch`、利用者のエディターの自動保存（Obsidian など）、スクリプトである。
- **意味の重複は防がない。** 2 つの取り込みが、同じ概念に別のスラッグでページを作ることがある。同じセッションを別のスラッグで 2 回取り込むことも防がない。これはファイルの壊れではなく、wiki の重複である。
- **派生物は戻る。** グラフはロックで 1 つずつ作り、ページから作り直せる。MCP の索引も、ファイルの署名から作り直す。共有のテキストファイルが正しければ、派生物はあとで整う。
- **これは、セッションの取り込みで新しく生じる問題ではない。** Web ページと PDF の取り込みも、同じ手順 5〜8 を同じツールで行い、同じ穴を持つ。セッションの取り込みでは、伏せ字の確認が wiki に書く前に終わるので、wiki に書く時間が長くなるわけではない。

## 結論

raw だけを排他にすると、raw の不変性は守られる。wiki の共有のテキストファイル（索引、ログ、関連ページ）は、ふだんの使い方では Claude Code のツールの検査で守られるが、書き込みが数ミリ秒の中で重なったときは、黙って行を失う。失った行は、lint でも見つからない。これは既存の取り込みにもある性質で、セッションの取り込みに固有のものではない。
