# 依頼: セッションの取り込みの実装の敵対的レビュー（6 回目）

5 回目のレビュー（`impl-review-5.md`、却下）の指摘を直した版である。目的、対象、範囲の外は 1 回目の依頼（`impl-review-1-task.md`）と同じ。崩れた前提と原因の構造は `impl-root-causes.md` の「5 回目のレビューのあと」にある。

## 直し方

- **禁じる文字列の集合を 1 つにした。** 題名とスラッグの検査（`check_no_secret()`）は、`scan` と同じ `scan_text()` で行う。人が伏せた文字列、自動で伏せた値の元の文字列（`password=` の値など）、自動の伏せ字の規則のどれかに当たれば拒む。`decide init`、`show --meta`、`write` の 3 か所がこれを使う。
- **終わりのない鍵の塊は、推さずに最後まで伏せる。** `RE_PEM` は、終わりの行がなければ文の最後まで（4 回目に狭めた規則を戻した。差し込みの判定は伏せ字の前の元の文で行うので、構造は壊れない。続く発言も伏せられるのは閉じる側として受け入れる）。探す文字列は、塊の行のうち、Base64 の文字だけで、16 文字以上か、4 文字以上で数字か `+ / =` を含む行。終わりを探し直す計算は、文の長さに比例する。
- raw のルートの祖先は、wiki の親の外にあっても、すべてリンクを拒む。
- S3 に、S2 で見つけた決定のファイルで続ける分岐を書いた。

直す前の実装で、足した試験が落ちることを確かめた。手元の実物の記録 982 ファイルで、`reply_unresolved` は 0 件、自己検査の失敗も 0 件だった。

## 特に見てほしいこと

- 禁じる文字列の集合を 2 つ以上持つ箇所、`scan_text()` を通らない検査が、まだ残っていないか。
- 終わりや範囲を「推す」処理が、まだ残っていないか。
- 1〜5 回目に崩せなかった点が、直しで崩れていないか。
