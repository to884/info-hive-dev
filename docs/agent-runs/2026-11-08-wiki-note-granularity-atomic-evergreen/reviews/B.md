## 自分の成果の見直し

同じ攻撃が自分にも当たる。結論は変えないが、採点と事実の 3 点を改める。

1. **大きさの数値がバイトだった（重大）。** 私は `tr -d | wc -m` の値を文字数として書いたが、Git Bash の `wc -m` はこの環境ではバイトを返していた。コードポイントで数え直すと、`コンテキストグラフ` は 2,891 ではなく 1,217 文字、`オントロジー` は 1,873 文字、source の part-3 は 2,990 文字、G1 は 1,121 文字である。したがって私の「`コンテキストグラフ` が作者の上限 4,000 文字に近づく」は誤りで、D の案④への「用語ページがすぐ満ちる」という攻撃は弱まる。また、私の入れ物の規則「用語ページがソフト上限の 8 割以上なら独立ページ」は作者の wiki ではほぼ発火せず、Yuan An 系が箇条書きになるという推定は結果として変わらない。課題文の「1,600〜4,300 文字」もバイトの誤記である。
