# グラフ改善設計の確認記録

対象は `docs/plans/wiki-graph-improvements-2026-11-17.md` の第2版である。
この作業では設計書・観測スクリプト・確認記録を追加し、プラグインと実 wiki のファイルは変更していない。

## 現行実装で確認したこと

- 隔離した試料では、proposed の直接辺を path が返し、期限切れの辺も edges が返った。
- 必須の status と confidence がない関係、本文にない引用、不正な期間を置いても、通常の lint では検出0件だった。
- 未知の述語と UTF-8 で読めない記事があっても extract は終了コード0となり、未知の辺は保存され、読めない記事は欠けた。
- DB 公開後の nodes.jsonl の置き換えに障害を注入すると、DBだけが新しくなった。
- 記事を削除して再生成しない場合、その記事のノードを問い合わせられた。
- 状態を編集すると生成エッジIDが変わった。別名そのものを node 引数へ渡しても解決されなかった。

試料の構成と結果は `probe_current.py` と `observations.json` にある。
現在の project wiki のメモリ内集計は84ノード・439辺・型付き関係0件で、`project_snapshot.json` に残した。
入力を読んだ集計であり、実 wiki の索引を書き換えていない。

## 自己点検で第2版へ加えた内容

| 点検した境界 | 明記したこと |
|---|---|
| 鮮度と照会の間の変更 | status の前置呼び出しだけを信用せず、同じDB接続の読み取りトランザクションへ結び付ける |
| 別の wiki の DB | 生成時の wiki_root と指定 wiki を照らし、移動・複製後は作り直す |
| 同じDBから異なる形式を書き出す場合 | build_id と bundle_id を分け、公開した bundle を上書きしない |
| 根拠の検証条件の追加 | ポリシー版1を変更せず、版2を明示して選ぶ |
| query の依存関係 | バイト列の照合と YAML の解析を分け、query は標準ライブラリだけで動かす |
| source ページ自身への関係の記述 | ハッシュを frontmatter を除く本文に結び付け、自己参照を避ける |
| 候補の主語と編集先 | 対象ページのノードIDと主語IDが一致した場合だけ patch を作る |
| 実行中のコードの変更 | 起動時に記録した実装と異なる場合は、同じ実装として処理を続けない |

自己点検は Opus による独立したレビューの代替ではない。
