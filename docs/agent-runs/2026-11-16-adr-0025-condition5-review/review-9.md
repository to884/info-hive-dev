## 判定

**却下。確信度：高。** 行が0件の有効なOCR結果で、印の付け直しと新しくOCRした場合の状態が食い違う。性質2を満たさない。

## 致命的・重大な欠陥

### 【重大】`lines: []` を読みの欠落として飛ばし、旧版の「不明」が残る

**反例：** 次の保存結果に `reflag_ocr.py ocr3` を実行する。

```json
{
  "text": "",
  "lines": [],
  "flag_revision": "flags-v2",
  "confidence_revision": "confidence-v1"
}
```

`reflag_ocr.py` は「読みがなく飛ばした」と数え、書き換えない。一方、行を検出しなかった応答を現行の `rag_pdf.ocr_page` に通すと、`lines: []` と `flag_revision: "flags-v3"` が返る。

両者を `confidence_record`、`page_flagged` に通した結果も異なる。

| 経路 | `page_flagged` |
|---|---|
| 付け直し後 | `None`：印が不明 |
| 新しくOCRした場合 | `False`：印なし |

ファイル入出力とOCRをメモリ上のスタブに置き換えて、実際の関数で再現した。`lines: []` は、行の記録そのものが欠けた `lines: null` とは異なり、製品が受理する正常な結果である。

**根拠：**

- `docs/research/adr-0025-condition5-2026-11-16/scripts/reflag_ocr.py:27–30`：`not lines` により空配列も除外する。
- `info-hive-rag/scripts/rag_pdf.py:60–75`：空配列は処理を継続し、現行の印の版を付ける。
- 同ファイル `:191–219`：空配列は有効な確信度記録になり、印の版によって `None` と `False` に分かれる。
- `docs/research/adr-0025-condition5-2026-11-16/scripts/score_v2.py:54–55`：現行版を要求して測定する場合、付け直せなかったファイルで停止する。

## 崩れる前提

- **空の行一覧は、読みを保存していない結果と同じである。** 検出した行が0件の正常なOCR結果で崩れる。製品側は空配列と記録の欠落を区別している。
- **各行の `flags` が一致すれば、結果全体の印も一致する。** 行が0件でも、ページの「不明／印なし」は `flag_revision` に依存する。

## 見落としと軽微な問題

- **【軽微】空配列の付け直しを試験していない。** `tests/contract/test_rag_review.py:93–96` の空本文の試料は、本文が空の行を1件持つ。今回の `lines: []` の反例とは異なる。
- **【軽微／仕様の限界】追加された `○` は捕えない。** `rapid_added("本文", "○本文")` は `False`、他の読みを本文と同じにした `static_flags` は `[]` だった。`SAME` が記号 `○` を数文字 `〇` に変換し、`_marked` が対象外にするためである。ただし、ADRの正規化後に数える手順には一致するため、重大な実装違反には数えない。根拠は `rag_ocr_flags.py:29,124–147`。

## 検証した事実

- **一致：** `test_rapid_added_counts_characters` のメソッドをASTから取り出し、7個のアサーションを実行して通過した。
- **一致：** 本文・RapidOCRの読み・別解像度の読み・確信度を変えた120通りの1行入力で、付け直しと新しい `rag_pdf.ocr_page` の行の印が一致した。
- **食い違い：** 空配列では、付け直し後が印不明、新しいOCR結果が印なしになった。
- **一致：** `probe_rapid_analyze.py:156–159` の現行版用の判定は、製品の `rapid_added` を直接呼ぶ。

## 崩せなかった点

- 負号追加の `"100" → "-100"`、`"100" → "−100"` は印になる。
- 純粋な脱落の `"ABAA" → "AAA"`、除外対象の入れ替えの `"O0" → "0O"` は印にならない。
- 必要な読みを持つ非空の行について、付け直しと新しいOCR結果の印の不一致は見つからなかった。
