# ADR-0025 の行の印の設計のレビュー（4 回目、実装の前）

## 目的

ADR-0025 の承認の条件 5 は、1 回目（確信度の閾値）で満たさなかった（`docs/research/adr-0025-condition5-results-2026-11-16.md`）。作者の決定で、次のように見直した。ADR の変更は `git diff HEAD~1 -- docs/adr/0025-pdf-text-layer-with-pdfminer-vertical.md` で見られる（「OCR の行の印とページの確認」の節と、承認の条件 5）。

- 確かめる単位を行にする。OCR の行に、確信度が低い、ぼかした読みと違う、別の解像度の読みと違い確信度が 0.9 未満、のどれかに当たれば印を付ける。
- 印の付いた行があるページは、今の手順（段階 3）どおり確認待ちにする。
- 条件 5 の基準を、行の単位の (a)〜(c) にする。(c) は正しく読めた行の誤報の割合（15% 以下）。検出器が見つけなかった行は (b) に入れない。
- 公開の PDF で、文字の層から正解を決められない OCR の行は、エージェントが目で書き起こして正解を作る。

印の組み合わせは、選ぶ資料だけで試して選んだ（結果の文書の「見直しの案 1 の試し」と、`docs/research/adr-0025-condition5-2026-11-16/scripts/probe_*.py`、`results/probe-*.json`）。確かめる資料はまだ測っていない。

次の性質を壊す欠陥だけを、重大として挙げてほしい。

1. **設計が実装できて、試した印と同じものになる:** ADR の印の決め方（ぼかし、別の解像度、行の対応、正規化、98 文字以上の行、縦書き、つながる行がないとき）が、試した probe のスクリプトの印と食い違わない。食い違うと、選ぶ資料の結果が製品に当てはまらない。
2. **段階 3 の仕組みと矛盾しない:** 確認待ち、台帳、作り直し、検索の印、`page_report`、`ocr_page_detail` が、確信度の代わりに印を使っても成り立つ（印が不明な結果の扱い、閾値を変えたときの扱いを含む）。
3. **条件 5 の基準と測り方が、偶然の合格や後からの選択を許さない:** 選ぶ資料で組み合わせを選んだこと、目で作る正解、(b) から外す行が、確かめる資料での合格を甘くしない。

公開の PDF の中身はこの依頼に含めない。
