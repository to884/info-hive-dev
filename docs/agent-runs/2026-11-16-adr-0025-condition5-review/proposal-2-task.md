# OCR の行の印と、その測り方の改善提案（GPT-6.1 Sol への依頼、2026-11-17）

## 頼みたいこと

rag プラグインは、PDF のページを NDLOCR-Lite で OCR し、誤っていそうな行に「印」を付け、印のある行を含むページを利用者の確認待ちにする。ADR-0025 の承認の条件 5 は、この印が誤りの行を十分に捕え、正しい行に付きすぎないことを、測る前に決めた測り方で確かめることである。3 回測り、3 回とも公開の PDF で不合格だった。

**条件 5 を、正当な方法で満たすための改善を提案してほしい。** 印の付け方の改善と、測り方（正解の作り方、行の対応、数え方）の改善の両方を対象にする。提案は、効きそうな順に並べ、それぞれに次を書く。

1. 何を変えるか（製品のコードか、測り方か）。
2. どの見逃しの種類に効くと見込むか。下の「試算」の表を使い、開発用の 3 つの資料それぞれで合否が変わりうるかを書く。
3. 誤報（(c) と (a)）が増える危険と、それを開発用の資料で確かめる方法。
4. 測り方を変える提案なら、それが「合格の線を下げる」ことではなく、正解の誤りを直すことである理由。結果を見てから正解の定義を変えることへの疑いに、どう答えるか。

さらに、次の問いに答えてほしい。

- 資料ごとに見逃しの種類が違う（下の表）。新しい資料で測るたびに、新しい種類が出る。見逃しを 1 種類ずつ塞ぐ印を足していくことは、ここで避けたい（場当たりの修正になる）。種類によらず効く、構造的な改善はあるか。
- 今の合否（下の「合否」）は、公開の PDF のように単位（ページ）ごとの偏りが大きい母集団で、満たせる見込みのあるものか。満たせないなら、それを示す根拠と、作者に示すべき選択肢。

## 資料

- **合成:** ADR などの Markdown から描いた PDF（解像度を下げた、ぼかした、雑音を足した、傾けた画像を含む）。
- **公開:** 選ぶ資料は白書の概要と官報の第 1828 号。2 回目の確かめる資料は防衛白書 51 ページと官報の第 1827 号。3 回目の確かめる資料は防災白書 50 ページと官報の第 1826 号 4 ページ。3 つとも、今は開発用の資料として使える（確かめる資料は 1 回ずつ使い切った）。次に確かめるときは、新しい資料が要る。
- **正解:** 合成は描いた文字。公開は、目で正しいと確かめたページの文字の層（pdfminer の行）。文字の層から決められない OCR の行（図の中の文字など）は、エージェントが OCR を見ずに書き起こし、食い違いは別のエージェントが目で決める。

## 合否（2 回目から同じ）

合成と公開のそれぞれで、次をすべて満たす。(a) 印の行のうち誤りの割合 ≥ 0.5、(b) 誤りの行のうち印の割合 ≥ 0.8、(c) 正しい行のうち印の割合 ≤ 0.15。点の値に加え、行で重みを付けたクラスターの片側 95% の限界と、単位ごとの比の平均の 1 標本 t の限界も満たす。情報のある単位が 10 以上、各数が 20 以上。単位は、合成では原稿、公開ではページ。

## 画像で確かめた、見逃しの例（中身は伏せ、形だけ書く）

- **正解の作り方のずれ（OCR は正しい）:**
  - 縦書きの表で、OCR は 1 列を 1 行として正しく読んだ。文字の層は、その列の名前を別の行に分けていて、行の対応で列の先頭の行だけが正解になった。「字を足した」に数えられた。
  - 横書きの見出しで、丸の図形の中の番号は OCR の箱の外にあり、OCR は箱の中を正しく読んだ。文字の層の行は番号を含んでいた。「字を落とした」に数えられた。
- **OCR の本当の誤り:**
  - 表のセルの数字で、罫線を「1」と読んだ（「0」を「10」）。
  - 本のアイコンを「□」と読んだ。
  - 官報の縦書きで、カタカナの「ロ」を漢字の「口」と読んだ。3 つの読み（本文、ぼかした読み、別の解像度の読み）がそろって同じに誤る。

## 守ること

- 作者の電子書籍は使わない。資料は合成と公開の PDF だけ。
- 測り方は測る前に文書に決め、確かめる資料は 1 回だけ数える。確かめる資料を数えたあとに、測り方を変えない。
- 見逃しの例を 1 つずつ塞ぐ修正をしない。前提を書き出し、構造で直す。
