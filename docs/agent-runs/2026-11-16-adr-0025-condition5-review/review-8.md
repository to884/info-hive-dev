## 判定

**却下。確信度：高。** 製品と開発時の判定関数は一致するが、両方に共通して、ADR が要求する記号の追加を見逃し、除外すると定めた差にも印を付ける欠陥がある。性質 1 を満たさない。

## 致命的・重大な欠陥

### 1. 【重大】追加された負号が記号として扱われず、確認待ちにならない

**再現：**

```python
rapid_added("100", "-100")  # False
rapid_added("100", "−100")  # False
```

横書きの行で、確信度を `0.99`、本文・ぼかした読み・別解像度の読みをすべて `"100"`、`rapid_text` を `"-100"` にすると、`static_flags` は `[]` を返す。これだけのページは確認待ちにならないことも実行して確認した。

原因は、`LOOKALIKE` が `"-"` を `"ー"` に変換したあと、`isalnum()` で記号かどうかを判定すること。`"ー".isalnum()` は真なので、追加された負号が対象から消える。これは同じ字形への置換ではなく、負号が一字増えた場合である。

**根拠：**

- `docs/adr/0025-pdf-text-layer-with-pdfminer-vertical.md:168`：別の読みが記号を追加した場合は印を付ける。
- `info-hive-rag/scripts/rag_ocr_flags.py:33`：`"-": "ー"`。
- 同ファイル `:117–135`：変換後の文字で差と文字種を判定。
- `docs/research/adr-0025-condition5-2026-11-16/scripts/probe_rapid_analyze.py:22–27,108–120`：開発時にも同じ欠陥がある。したがって、開発用 186 ページで製品との一致を確かめても、この ADR 違反は検出できない。

### 2. 【重大】差分の区切り方によって、純粋な脱落や除外対象の置換に印が付く

**再現：**

```python
rapid_added("ABAA", "AAA")  # True：B を落としただけ
rapid_added("O0", "0O")    # True：O→0、0→O という除外対象の置換だけ
```

`SequenceMatcher` は、前者を `delete("AB") → equal("AA") → insert("A")` と区切る。後者も `insert("0") → equal("O") → delete("0")` と区切る。

実装は `delete` を無視し、取り違えやすい英数字の除外を `replace` にだけ適用するため、残った `insert` が `"rapid"` の理由になる。確信度 `0.99`、ぼかした読みと別解像度の読みが本文と同じ状態でも、両例で `["rapid"]` が付き、ページが確認待ちになることを確認した。

**根拠：**

- `docs/adr/0025-pdf-text-layer-with-pdfminer-vertical.md:168`：文字を落としただけの違いと、指定した英数字間の一文字ずつの置換は数えない。
- `info-hive-rag/scripts/rag_ocr_flags.py:127–135`：差分の種類に依存した除外処理。
- `docs/research/adr-0025-condition5-2026-11-16/scripts/probe_rapid_analyze.py:112–119`：開発時の判定も同じ反例で崩れる。

## 崩れる前提

- **字形を統一しても文字種は保存される。** ハイフン・負号を長音符にすると、記号が文字として扱われる。
- **`SequenceMatcher` の操作列が、実際の脱落・置換を表す。** 反復文字列では、純粋な削除でも挿入を含む操作列になる。
- **製品と開発時の判定が一致すれば ADR に準拠している。** 今回は両方が同じ欠陥を持つため、一致確認だけでは上記を排除できない。

## 見落としと軽微な問題

- `tests/contract/test_rag_review.py:237–246` は、単純な追加、脱落、字形差、`Hello → He11o` を扱うが、負号の追加と反復文字列の反例は扱っていない。
- **3 回目の採点と照合の実行経路は、現存スクリプトだけでは確認できない。** `score_v2.py:47,149–162` は `ocr2` と旧モードに固定され、`compare_flags.py:31,47–52` は選ぶ資料だけを扱い、`rapid_text` を比較しない。`freeze_manifest.py:26–36` も `evaluation`／`ocr2` 専用である。まだ数えていないという説明と矛盾しないため、これは重大な欠陥には数えない。
