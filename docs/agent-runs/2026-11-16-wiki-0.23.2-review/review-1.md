## 判定

**条件付きで採用可。確信度：高。** 節の一括除外により、主張に含まれる印なしの訂正を目印から隠せる経路が増えています。`fetched_at` の追加と、印・定義の照合への影響は崩せませんでした。

## 致命的・重大な欠陥

`create` などの管理用識別子だけでなく、主張の数値まで消えています。これは漢字や言い換えという既知の限界ではなく、従来検出できた数字が今回の変更で検出されなくなる退行です。

## 崩れる前提

- **対象の節には管理用の語しかない。** 「主張と行き先」には、手順上、主張・条件・根拠・理由が入ります。数値や固有名詞も含まれます。
- **表の語は必ず検査対象の本文にも現れる。** 表だけに詳細を残す場合や、本文と表で数値が食い違う場合に崩れます。重複を照合する処理はありません。
- **見出し名だけで内容を分類できる。** 同名の節には任意の段落や h3 を置けます。除外は要約ページ以外にも適用されます。
- **`same` の `fetched_at` は既存 raw の初回取得時刻である。** これは成り立ちません。今回取り直した字幕の取得時刻です。ただし、変更後の手順の説明とは一致します。

## 見落としと軽微な問題

- **軽微：ADR と実装の対象範囲が食い違う。** `ingest-workflow.md` は新しい除外を明記していますが、ADR-0027 の「書かれていない訂正の目印」は更新されていません。
- **軽微：追加テストが主張の消失を検査していない。** `test_wiki_youtube.py` 1080〜1088 行は、除外節の `create` と `ギリシャ` が消えることだけを確認しています。主張の数値や用語まで消える反例はありません。
- **軽微：時刻の追加テストは `created` の形式確認に限られる。** 499〜501 行では時差の有無だけを確認し、`inspect`、`same`、秒精度、取得直後という順序は検査していません。実装の不具合は再現していません。

## 検証した事実

- **一致：** 現行コードの変更箇所は、提示された二つの差分と一致しました。
- **一致：** `fetched_at` は `json3` 取得後、raw の生成前に設定されます。時計と通信を差し替え、`inspect` と `write same` がそれぞれ今回の取得時刻を時差付き・秒精度で返すことを確認しました。
- **一致：** h1/h2 で除外が終わり、h3 と文末までは除外が続きます。Setext 形式の h2 でも確認しました。
- **検証範囲：** ファイルを書かない既存テスト21件は成功しました。反例はメモリ上で実行し、ファイル参照を差し替えています。ファイル作成を伴う全体テストと実ネットワークでの取得は実行していません。

## 崩せなかった点

- 除外節内でも、存在しない字幕語・根拠、未定義の印、末尾不一致、未使用の定義、定義間の矛盾、同じ位置の重複、confidence 不一致は検出されました。**(1)〜(5) を節の除外で迂回する反例は得られませんでした。**
- 引用・コード・リストの中に除外見出しを書いて、その外側の本文を隠す攻撃は成立しませんでした。
- `same` でも字幕を取り直すため、今回の取得時刻を返すこと自体に手順との矛盾はありませんでした。
