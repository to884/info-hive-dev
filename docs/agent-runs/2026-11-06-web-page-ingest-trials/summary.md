# Web ページの取り込みの試し（英語 3 本、日本語 3 本）

- 実施日: 2026-11-06
- 対象: info-hive-wiki のブランチ `feature/web-page-ingest`（計画の PR 2）の `wiki_fetch.py` と `commands/ingest.md` の手順
- 進め方: スクラッチパッドに `init_wiki.py` で一時的な wiki を 2 つ作り、サブエージェント 2 体（英語、日本語）に、ブランチの手順どおりに取り込ませた。導入済みのマーケットプレイス版のプラグインは使っていない。人と話し合わないまとめての取り込みとして行い、グラフ層は飛ばした。
- 訳と画像の補足を書いたモデル: Claude Sonnet 5.5（サブエージェントの実行環境のモデル。`translated_by` と補足の先頭にこの名前が入った）
- 詳しい記録: [en.md](en.md)（英語）、[ja.md](ja.md)（日本語）

- lint: 英語と日本語の wiki とも、6 ページで指摘なし。
- 再取得: 同じ URL とスラッグで取り直すと `"unchanged": true` になり、ファイルは書き換えられなかった（訳したあとの raw でも、frontmatter の原文の SHA-256 で判定できた）。
- 引用の照合: 要約ページとコンセプトのページに書いた訳文・本文からの引用は、`quote_in_text` ですべて一致した（英語 6 件、日本語 7 件）。
- 6 本とも、ページの中にエージェントへの指示に見える文はなかった。

## 見つかった不具合と対応

| 不具合 | 対応 |
| --- | --- |
| `<dd>` の中のコード例が段落の末尾に 1 行でつながる（Python のドキュメント） | 直した。`<dd>` をブロックとして変換する |
| MathML の数式が、表示の文字と TeX の注釈で 2 回並ぶ（Wikipedia） | 直した。TeX の注釈を `$…$` で 1 回だけ書き、代わりの画像は落とす |
| `[編集]` のリンク、カテゴリ、言語の一覧が残る（Wikipedia） | 直した。MediaWiki の部品の class を雑音とみなす |
| 題名のほかに `<h1>` があるページで、h1 と h2 が同じ `##` になる（SQLite） | 直した。題名のほかに `<h1>` があれば見出しを 1 段下げる |
| 題名に節の番号が残る（「1. Datatypes In SQLite」） | 直した。「数字.」で始まる番号を題名から外す |
| 目次が本文に残る（SQLite） | 直した。class か id に toc を含む要素を落とす |
| 手順で迷う点（raw に手を入れてよい時期、長いページの訳し方、見出しの訳、著者名の行、alt が空の画像、JSON の path の基準、記法を含む引用の照合） | `commands/ingest.md` と `ingest-workflow.md` に書き足した |

直したあとに同じ 6 ページを `wiki_fetch.py` で取り直し、Wikipedia のページで数式の重複と `[編集]` が消えたこと（雑音を削る前で 14,554 文字から 9,884 文字）、Python のページの例がコードブロックになったこと、SQLite のページで見出しが `##`・`###`・`####` に分かれ、目次が消えたことを確かめた。訳と補足を書く取り込みそのものは、直す前の版で行った。

## 残した課題

- 再取得で `unchanged` のとき、出力に `content_root` や `warnings` が出ない。初回の「本文を推定した」の警告は再取得では見えない。
- 著者のリンク、タグのリンク、著者の顔写真（CQRS）、曖昧さ回避の注記（Wikipedia）は、モデルが手で削る前提のまま残している。
- `<blockquote>` の中の `<pre>` は、引用の中のコードブロックとして出る。原文の構造どおりなので直していない。
- ログインが要るページと、JavaScript で描くページ（ブラウザで本文を取る手順）は試していない。
