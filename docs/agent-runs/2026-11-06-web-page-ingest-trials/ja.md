## 気づいた不具合・改善点
1. **コード例が段落に潰れる（python-secrets）**: `token_bytes` などの doctest の例（`>>> token_bytes(16) b'...'`）が、コードブロックにならず、直前の説明文の段落の末尾に 1 行でつながる。コードの改行が失われる。`<pre>` 以外の形（`div.highlight` の入れ子が `dd` 内にあるなど）の扱いを見直すとよい。ただし、レシピの節のコードブロックは正しく ``` で囲まれた。
2. **数式が二重になる（Wikipedia）**: MathML の表示と `{\displaystyle ...}` の注釈の両方が出て、「n {\displaystyle n}」のように、同じ式が 2 回並ぶ（8 か所）。`<annotation>` か `.mwe-math-fallback-image` のどちらか一方だけを出すか、`annotation` の LaTeX だけを `$...$` にするとよい。式が複数行に分かれて壊れた表示にもなっている（「1 − 1 m」など）。
3. **雑音の除去がモデルまかせで多い（Wikipedia）**: 他言語版リンクの一覧、「[編集]」リンク、曖昧さ回避の表（`.hatnote` 相当）、カテゴリ、「から取得」は、決まった形なのでスクリプトで落とせる。特に `[[編集](...action=edit...)]` は毎回出る。
4. **`unchanged` 時の出力が短い**: 再取得で `unchanged: true` のとき、`warnings` が `[]` になり、`content_root`、`ja_ratio`、`images` などが出ない。初回に出た「本文を推定した」警告が消えるので、`content_root: guess` のページで警告が見えなくなる。unchanged のときにも `content_root` を出すか、保存済みの値を示すとよい。
5. **JSON の `path` が相対パス**: `"path": "raw/消費税の基本的なしくみ.md"` が `--raw-root` からの相対ではなく、`raw-root` の名前（`raw`）を含む形で、`images[].path` は `assets/...`（md からの相対）と基準が違う。画像を Read で開くときに基準の違いで迷った。どちらも「`--raw-root` の直下からの相対」と手順に書くか、絶対パスの項目を足すとよい。
6. **手順の書き方で迷った点**: (a) 依頼では「表示名が Opus 5.5 のはず」だったが、手順は「システムの指示のモデル名」としており、食い違ったときの扱いが明確だった（システムを優先）。(b) 手順 4 の「雑音を削る」は、raw を書き換えないという手順 8 の決まりと順序が前後して読める。「手順 4〜7 の編集は保存直後だけ許す」と明記するとよい。(c) 日本語のページの引用は、Markdown のリンクや `*` を含む文だと照合に失敗する。「リンクや強調を含まない部分から引く」と手順に書くとよい（`normalize_quote` は記法を外さない）。(d) 画像の補足を書く位置は、alt がないとき（`![](...)`）の扱いを例に足すとよい。
7. 抽出の誤りは、`content_root: guess` の国税庁のページでは見つからなかった（サイドバーやフッターは混ざらなかった）。
