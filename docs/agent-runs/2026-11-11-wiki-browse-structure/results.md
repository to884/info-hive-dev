# browse の構造の直しの設計のための実測（2026年11月11日〜12日）

[設計](../../plans/wiki-browse-structure-2026-11-11.md)の 4.1、6、7、9 の根拠である。開発用の PC（Windows 11、Python 3.14.6）だけで測った。製品の仕様ではない。

0 は 5 版目のための実測、1 と 2 は 4 版目のための実測である。4 版目の試作と探索は、5 版目で直した（0.1）。1 の数は、直す前の試作のものである。

## 0. 5 版目のための実測（2026年11月12日）

### 0.1 試作と探索の直し

4 回目の設計のレビューの重大 6 を受けて、[write_model.py](write_model.py) と [write_sweep.py](write_sweep.py) を直した。

| 直したこと | 内容 |
| --- | --- |
| 書き込みの口の重なりの確かめ | 書き込みの口が、どれも、対象の親が Wiki のルートかその下でないこと、動かすディレクトリがルートかその祖先でないことを確かめる（設計の 6.1）。書き出しの始めにも、書き出し先とその親を確かめる |
| 既定の書き出し先 | 前の世代を読まない。種類と、空かどうかだけを見る |
| 持ち主の確かめ | 状態のディレクトリと、既定の書き出し先の作業用の目印に、Wiki のルートの識別子を書く。記録にも書き、使い回しと `stop` で照らす（設計の 7.1） |
| 知らせの出力 | 確定のあとに標準出力へ知らせを出す。失敗しても、警告にして終了コードを変えない（設計の 7） |
| 一覧の取り出し | ディレクトリの一覧を、開く、項目を 1 つ取り出す、の 2 つの口に分けた |
| ブロックデバイス | Windows で、種類がブロックデバイスなら「分からない」にする |
| 探索の基準 | 手を入れない実行の約束、既定の書き出し先の前の世代を読まないこと、確定のあとの失敗の警告、ディレクトリと砂場の根の属性、`close` の失敗で中身が失われる場合、別の Wiki のサーバーを使い回さず止めないこと、を足した |
| 初期の状態 | 書き出し先に、空の Wiki のルート、Wiki のルートの下、`data_dir` が Wiki のルートの下、を足した。状態のディレクトリに、別の Wiki が前に使っていた場合を足した |
| 2 つ目の失敗 | 1 つ目のあとの 30 回までの呼び出しに入れる |

口の呼び出しの数は、1 回の書き出しで 14〜183 回になった（4 版目の試作は 13〜109 回）。

## 1. 書く側の規則の試作と探索（4 版目）

- 試作: [write_model.py](write_model.py)。設計の 6（領分、門、静的の書き出しの手順）と 7.1（サーバーの記録）を写した。製品のコードではない。
- 探索: [write_sweep.py](write_sweep.py)。OS を呼ぶ口の呼び出しを数え、N 回目に手を入れる実行を、N を 1 から数え終わるまで繰り返す。
  - 手の入れ方: 権限の失敗、「ない」の失敗、短い書き込み、強制停止、書き込みを半分してからの強制停止。一部の状態では、1 つ目の失敗のあとの呼び出しにも 2 つ目の失敗を入れる。
  - 基準: 試験の側が砂場の木を自分で読み、設計の 9.1 と 9.2 を確かめる。基準に試作の関数は使わない。ただし、サーバーの「動いているか」は試作の `is_running()` で確かめる。
- 写していないもの: 作る場所が Wiki のルートの下にないかの確かめ、走査と中核、ロックを待つ時間、2 つのプロセスの同時の実行。

## 2. 読めないページ（4 版目）

[unreadable_probe.py](unreadable_probe.py) で、今の中核（wiki 0.10.0、`f0a758f`）と lint を、実物で呼んだ。この節は 4 版目のときの結果で、出力の全文（[unreadable_probe-output.md](unreadable_probe-output.md)）は、5 版目の直し（0.3）で書き換えた。

試験用の Wiki は次のとおりである。`a.md` が `[[b]]`、`[[missing]]`、`[[c#見出し]]` を持ち、`b.md` が `[[a]]` を持つ。

| | すべて読める | `a.md` だけ読めない | `a.md` の中身を空にする（対照） |
| --- | --- | --- | --- |
| browse の未解決リンク | `[("concepts/a.md", "missing")]` | `[("concepts/b.md", "a")]` | `[]` |
| lint の `broken_links` | `[("concepts/a.md", "missing")]` | `[("concepts/b.md", "a")]` | ― |
| browse の被リンク | a、b、c にある | なし | a だけにある |
| 中身が変わった出力のファイル | ― | 7 つすべて | 6 つ |

分かったこと:

- 読めないページがあると、browse も lint も、そのページを集合から外す。そのページへのリンクは、どちらでも未解決になる。両者は一致する。
- 3 版目の基準（「読めないページの表示だけが変わる」）は誤っていた。未解決リンク、被リンク、ほかのページの本文も変わる。
- 中身を空にして代わりに使う実装は、lint と食い違う。設計の 9.2 の基準（同じ失敗を入れた lint との一致）で見つかる。
