# 実装の 7 回目のレビューの指摘の、原因の構造による分類

対象: `wiki_rawcheck.py` の 7 回目の実装。レビュー: [impl-review-7.md](impl-review-7.md)（GPT-6.1 Sol、effort high、却下）。前の分類は [impl-root-causes-1.md](impl-root-causes-1.md)〜[impl-root-causes-6.md](impl-root-causes-6.md)。

6 回目までの指摘は崩せなかった。重大な指摘は 3 件で、2 件は 1 回目から続く「パーサーが決めることを、正規表現やパーサーの一部の処理で推し量る」構造の名残だった。

| 原因の構造 | 崩れた前提 | 指摘 | 直し方 |
| --- | --- | --- | --- |
| 表のセルの数を、行の先頭の入れ物を正規表現で外してから数えていた | 行の先頭の `>` と空白を外せば、セルの区切りだけが残る | 重大 1（リストの中の表では、見出しの行の `- ` をセルと数え、見えないセルの判定をすり抜ける） | 削除の段では、表の列の数（パーサーが読んだ見出しのセルの数）を変えさせない。取得器は表のすべての行を見出しと同じセルの数にそろえて書くので、列が変わらず文字を書き足せない限り、見えないセルは生まれない。訳と補足の段では、行ごとのエスケープしていない `|` の数を、取得と raw の同じ行どうしで比べる（入れ物の記号は `|` を含まないので、入れ物を推し量らない） |
| 画像のパスに、パーサーの処理の一部（`normalizeLink`）だけをかけていた | パスの正規化は、符号化だけである | 重大 2（スラッグの `&amp;` を、パーサーは文字参照として `&` に戻す） | 取得器が本文に書くとおりの画像の記法を、同じパーサーで読んで、パスを作る |
| 削除の段の結果を直接書き、その有無で段を決めていた | `cleaned.md` があれば、削除の段は終わっている | 重大 3（書きかけの `cleaned.md` を固定済みとして再開できる） | `removed.json` と `cleaned.md` を一時の名前で書き終えてから名前を変え、`cleaned.md` を最後に置く |
| 試験の穴と説明 | — | 軽微（入れ物の中の表、訳したあとの再開、`cleaned.md` の書き込みの失敗、再開の試験の説明） | どれも試験を足し、説明を直した |

この回で、表の列を消すことを、削除の段で許さないことにした。表の雑音は、行ごとか表ごと消す。
