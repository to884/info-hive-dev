# Sonnet 5.5 で新しい手順を実地に試した記録（2 回目、2026-11-14）

8 回目のレビューの指摘を直した版（`info-hive-wiki` の `feature/web-ingest-check`、9064af5、0.14.0）の手順（`commands/ingest.md`）を、Sonnet 5.5 のサブエージェント 4 体に読ませ、1 回目（[sonnet-trial.md](sonnet-trial.md)）と同じ 4 ページを取り込ませた。依頼文は 1 回目と同じで、wiki の場所だけを変えた。Skill ツールの `wiki:ingest`（導入済みの版）は使わせていない。ページごとに `init_wiki.py` で新しい wiki を作った。グラフ層と話し合いの手順は飛ばさせた。

1 回目から変わった点のうち、この試行に関わるもの:

- `check --finish` は、警告が残るあいだは作業用の写しを消さない（直さない警告は、理由を残して `--accept-warnings`）。
- `freeze` は、削除のあとに残った画像（`images`）を出し、W7 はそれを使う。
- 月と曜日の名前、図の出典の定型の語（`Created` など）を、「訳文にない名前」の警告から外した。
- 誤りと警告の行番号を、raw のファイルの行番号にした。

## 分かった改善点

4 体の報告から、次の点が挙がった。1〜4 は、この記録のあとのコミット（「2 回目の試行の改善点を直した」）で直した。1 は手順（W6、W8、参照の文書）と警告の文に直し方を書いた。2 は、日本語の文でふつうに使う略語（`PC`、`OS` など）を警告で数えないようにした。3 は、参照の文書に「長いページの訳し方」を足した。4 は、パネルの多い図では 2〜5 文を超えてよく、補足の中で段落を分けてよいことにした。5〜7 は取り込みの手順全体か判断の話なので、この変更では扱わない。

1. **一般の語を訳したときの警告の直し方**: `Domain Model`、`Boolean`、`Greenwich` のような語を訳すと、「訳文にない名前」の警告が出る。3 体とも「原語を残し、日本語を括弧で添える」で直した。W6 の「固有名詞の英語表記は変えない」と、日本語として定着した語の訳の境目が分かりにくい。直し方を W8 に書くとよい、という意見が 2 体から出た。
2. **`PC` の警告**: 「ノート PC」は自然な訳だが、原文にない英字として警告になる。担当は「ノートパソコン」に直した。
3. **長いページの訳の書き戻し**: Medium の担当は、`cleaned.md` をブロックに分けるスクリプトを作業用のフォルダーに書き、訳文を組み立てて raw に書き戻した（1 回目の試行の担当と同じく、自作した）。手順に例を載せてほしい、という意見があった。
4. **補足の長さ**: 「2〜5 文」は、パネルの多い図では窮屈だった（Medium）。
5. **ソースの要約ページと概念のページのスラッグの衝突**: CQRS とブルームフィルタの担当が、ソースの要約ページと同じ名前の概念のページを作れず、別の名前にした。Web の取り込みではなく、取り込みの手順全体の話である。
6. **主張と行き先の表の `create` と `update`**: 空の wiki に取り込むとき、使い分けに迷った（2 体）。これも取り込みの手順全体の話である。
7. **本文の先頭の「34 min read · Nov 2, 2026」**: 日付の行として残したが、読了時間を雑音とみるか迷った（Medium）。

## そのほか

- SQLite の担当は、比較演算子の列挙で `<>` が欠けている（`"!=", "", "IN"`）のを、取得器が落としたものと報告した。原文の HTML を確かめると、ページそのものが `"!=", "",` となっており、取得器の問題ではない。担当は補わずに残し、要約ページに注記した。
- SQLite の担当は、`check` の回数を 4 回と書いたが、出力は 3 回分だった。この記録では 3 回とした。
- CQRS の担当は、ページの 1 つを Write ツールで書こうとして、サブエージェントの環境の制約で拒まれ、Bash で書いた。書いた先は試行用の wiki の中だけである。プラグインの手順の問題ではない。
- 作業用のファイル（訳の書き戻しのスクリプトなど）は、SQLite と Medium の担当が作業用のフォルダーに置き、`--finish` で消えた（1 回目は、Medium の担当がスクラッチパッドに書いた）。
