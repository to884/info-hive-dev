# 実装の 3 回目のレビューの指摘の、原因の構造による分類

対象: `wiki_rawcheck.py` の 3 回目の実装。レビュー: [impl-review-3.md](impl-review-3.md)（GPT-6.1 Sol、effort high、却下）。前の分類は [impl-root-causes-1.md](impl-root-causes-1.md)、[impl-root-causes-2.md](impl-root-causes-2.md)。

2 回目までの指摘（貪欲の部分列、リストの中のコード、エスケープした `]`、強調の中の削除、入れ子の補足、原文の補足の形の引用、日本語のパス、`../..`）は崩せなかった。重大な指摘は 3 件に減った。

| 原因の構造 | 崩れた前提 | 指摘 | 直し方 |
| --- | --- | --- | --- |
| パスを、片方の表現を戻す向きで比べていた | パーサーの符号化を `unquote` で戻せば、記録のパスになる | 重大 1（スラッグに `%20` があると、別のパスになる） | 記録のパスにパーサーと同じ正規化（`normalizeLink`）をかけて比べ、ファイルの有無は元のパスで確かめる。どちらの表現も同じ関数を通す |
| 訳さないページの本文を、補足を消した行の文字列で比べていた | 補足の行と次の空の行を消せば、元の本文に戻る | 重大 2（引用の中の `>` の行、リストの項目のあいだ） | 入れ物の記号だけの空の行は比べない。段落の分け方とブロックの数は、木の比較で別に照らしている |
| パーサーの参照の定義の値を、そのまま比べていた | 参照の定義の値は、定義の中身だけを表す | 重大 3（行番号の `map` が入る）、軽微（同じラベルの 2 つ目の定義をパーサーが捨てる） | ラベル、URL、title だけを比べ、定義の行も数える |
| 木の形に、記法を入れていなかった | 消すことだけをすれば、記法は変わらない。だから比べなくてよい | 軽微（`##` を下線の見出しに、``` を ~~~ に変えても通る） | 節点の記法（見出しの `#` と下線、フェンスの記号）も比べる |
| 雑音の規則の文字数と、リンクの判定 | `_` は強調の記号である。リンクの文言にエスケープはない | 軽微（`x_` の数え方、`[a\]b]` のタグのリンク） | 変換は強調を `*` で書くので、`*` と `` ` `` だけを除く。リンクの正規表現でエスケープを読む |

試験には、どの反例も `ReviewCounterexample3Test` と `FetchCounterexample3Test` として入れた。
