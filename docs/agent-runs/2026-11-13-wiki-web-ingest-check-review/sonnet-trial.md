## 分かった改善点

4 体の報告から、次の改善点が挙がった。どれも、まだ直していない。

1. **リンクの誤りの出力**: 「リンク先の URL か title が違う」だけでは、どのリンクが足りないのか分からない。足りない URL と増えた URL を並べる。
2. **「訳文にない名前」の警告の空振り**: 月名（`November`、`April`）、図の出典の定型（`Created by`）、見出しの外の文の先頭近くの一般の語（`Boolean`、`Compares`）、一般に訳す語（`Domain Model`）。役に立った警告は人名（`Mike Tyson`）と地名・暦の名前だった。月と曜日の名前を除き、`Created by` のような定型を扱う。
3. **手順の番号**: `commands/ingest.md` の手順（1〜8）と「Web ページの取り込み」の手順（1〜9）の番号が、読み替えを要する。後者を区別して呼ぶ。
4. **訳さないページの補足の表示名**: 手順に決まっていない（訳したページだけ「`translated_by` と同じ」と書いてある）。システムの指示のモデル名と書く。
5. **`--finish`**: 最初から付けてよいこと（誤りがあれば消さない）を書く。
6. **雑音の削除で何も消さないとき**: `freeze` が要ることを書く。
7. **長いページの訳し方**: Medium の担当は、コードブロックを保ったまま訳文を差し込むスクリプトを自作した（スクラッチパッドに）。ブロックごとに訳し、コードブロックはそのまま残す方法を手順に書く。

## そのほか

- Medium の担当は、作業用のスクリプトをスクラッチパッドの `tr/` に書いた。依頼の「ほかのフォルダーには書き込まない」から外れるが、wiki と raw には影響しない。
- 4 体とも、作業用の写し（`.wiki-cache/ingest/<スラッグ>/`）を `check --finish` で消していた。
