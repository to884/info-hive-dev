# 実例の失敗型を再現した転記の追試

[前回の開発試験](../2026-11-19-adr-0025-condition5-transcription-pilot/report.md)と同じ旧・新の比較を、[実例の原因診断](../../research/adr-0025-condition5-reference-audit-rootcause-v9-2026-11-19.md)に対応する合成原稿で行う。条件5の合否基準、所属、正規化、採点器、正式な評価行と画像、100万配置の上限は固定する。

| 原稿 | 6行の構成 | 実例から移した特徴 |
|---|---|---|
| 1 | 横書き、対象の閉じ括弧0・1・2個が各2行 | 防衛白書の行44。150 DPIで細い閉じ括弧が二つの独立したインク成分となる。単字の幅5画素、短い間隔、行端寄り。 |
| 2 | 横書き、別の合成原稿と書体で閉じ記号0・1・2個が各2行 | 同型の難所に枠外の括弧、色見本と罫線を加える。色見本はU03の取違えの対照。 |
| 3 | 横書き、小さい句点の枠内幅を0・1・2・3/3に変え、字片や近い本文も置く | U08。字全体で所属を測る過剰転記の対照。 |
| 4 | 縦書き、複数成分の末尾3行と、隣接する2列を含む短い切り出し3行 | U10・U02・U04。字全体の上下幅の境界、または短い縦列の所属と順序が判断を分ける。 |

150 DPIで個別のグリフの全インクを測り、軸方向の半分以上と直交中心を検算する。U10型には全体で7/15（枠外）、8/15（枠内）を含める。原稿と配置は独立した人工データで、正式評価の画像や本文を転用しない。符号を画素で識別できない点線は対象外。画像は150 DPIの3倍最近傍・450 DPIを各々枠あり・なしで渡す。所属軸は原稿画像に明記し、枠線は箱の外側に描く。

実行は前回の受領・採用手順を再利用する。初回は旧・新とも同じ順の16枚・24行をSolとAstraに各一度だけ提示する。両群共通の指示にはv9のx・yの所属規則を記載する。新指示にだけ「提出前に連続記号の位置と個数を見直す。」を加える。初回票はそれぞれ新規の一時セッションで、画像と指示だけを渡す。正規化後の既知票が二つそろわなかった行だけ、旧・新とも原稿1・3はSol、2・4はAstraの新規セッションで第三読する。二つの既知票が一致しなければ未決定。CLIや形式の失敗は一度のみ同じ入力で代替する。

両方で確定した同一行の転記を主に比較し、対象記号の脱落、全文字の不足、過剰な記号・全文字、全文一致を行数と字数で出す。全文字の不足・過剰は文字種ごとの個数差で、順序違いは全文一致で扱う。未知は全24行を分母にし、判読不能票、第三読と、最終の既知→未決定・逆方向を記録する。原稿1・2の連続記号と境界・縦書きは別集計。前回同様、全体と原稿2種以上で記号不足が減り、過剰転記・未決定・全文一致が悪化せず、既知→未決定が0のときだけ追試を支持する観測差とする。正式な合否や非劣性を推定しない。

固定時に実行出力へSHAを記録する。正解・原票・画像はGit対象外の作業用フォルダーに保持し、集計には匿名行ごとの状態と不足・過剰数を残す。回答後に画像や所属、判断規則を調整しない。
