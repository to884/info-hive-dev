## 見落としと軽微な問題

1. **軽微：画像の代替テキストが変わっても、照合を通過する。**

   次の文書をメモリ上で `command_details()` に読ませた。

   ```markdown
   [s]: ./search.md

   ## `/wiki:query`

   ![a [x][s]](https://example.com/x.png)
   ```

   結果は、画像の行がそのまま返り、**警告は空、`verify_rewrite()` も `[]`** だった。しかし、同梱パーサーで描画すると、元の文書の代替テキストは `a x`、抽出後は `a [x][s]` になる。

   画像の子を検査から外し、元の記法を保持する `content` だけを比べているため、参照定義の消失による表示の変化を見逃す。

   根拠：`info-hive-wiki/skills/info-hive/scripts/wiki_help.py:440`、`:454`、`:456`。設計の `:108` も、この比較で足りるという前提を置いている。

   **影響の限定：** 現行文書には参照定義がなく、実物の試験も参照定義を禁止する（`tests/wiki/test_help_command.py:459`）。現行の出荷文書での破損ではない。

2. **軽微：本体が正常に扱う画像を、実物の試験が誤って不合格にする。**

   query 節に次を加える。

   ```markdown
   ![a [x](./search.md)](https://example.com/x.png)
   ```

   本体は画像の行を変更せず、警告なしで返す。ところが、試験の `parsed_destinations()` は次の2件を集める。

   ```text
   image: https://example.com/x.png
   link:  ./search.md
   ```

   代替テキスト内の `./search.md` にも GitHub URL への変換を要求するため、実物の試験は失敗する。メモリ上で文書を差し替え、実際の `main()` の出力を同試験に渡し、`:473` の比較失敗を確認した。

   本体では画像の子をたどらなくなった一方、試験側には従来の再帰処理が残っている。

   根拠：`tests/wiki/test_help_command.py:72`、`:469`、`:473`。同じ画像を正常とする個別試験は `:243` にある。
