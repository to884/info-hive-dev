## 判定

**却下。確信度：高。** 設計どおりの引数の渡し方で、Bash・PowerShell の両方に追加コマンドを実行させられる。また、保証する入力形式の一部が、Claude Code の対話モードの仕様と衝突する。

## 致命的・重大な欠陥

1. **致命：単一引用符で囲むだけでは、引数を保護できない。**

   根拠：`docs/plans/wiki-help-command-2026-11-14.md:42`。入力内の `'` の処理が定義されていない。

   反例となる引数：

   ```text
   query'; echo HELP_ARG_EXECUTED; #
   ```

   設計どおりに組み立てると、実行文字列の末尾は次になる。

   ```text
   --command='query'; echo HELP_ARG_EXECUTED; #'
   ```

   実際の `wiki_help.py` をこの形で呼び、Git Bash と Windows PowerShell の両方で、ヘルプの後に `HELP_ARG_EXECUTED` が出ることを確認した。両方とも終了コードは 0。入力は未知のコマンドとして拒否されず、`query` と追加のシェルコマンドに分かれる。単なる `query'` でも、Python に到達する前に構文エラーになる。

   `$ARGUMENTS` は入力を本文へ置換する機構であり、シェル用のエスケープを保証する機構ではない。[Claude Code 公式仕様](https://code.claude.com/docs/en/skills#pass-arguments-to-skills)

   設計の子プロセス試験は、引数配列で Python を直接呼ぶため、この欠陥を検出しない（同計画:149）。

2. **重大・推測：`/wiki:help /wiki:query` が、対話モードではヘルプへの引数にならない可能性が高い。**

   根拠：同計画:14、145、155。設計はこれを `query` と同義とし、確認には `claude -p` を使っている。

   Claude Code の公式仕様では、端末の対話入力で先頭にスラッシュコマンドを並べると、複数のスキルが展開され、残った文字列が各スキルの引数になる。一方、`claude -p` は最初のスキルだけを読み、残りを引数にする。[公式仕様の該当節](https://code.claude.com/docs/en/skills#stack-several-skills-in-one-message)

   この仕様を対象プラグインへ適用すると、対話入力 `/wiki:help /wiki:query` は、`help` と `query` の両方を展開し、`help` の引数は空になる。結果として一覧を出したり、問い合わせ用の指示まで読み込んだりする。より強い反例は `/wiki:help /wiki:init` で、ヘルプ要求に初期化用の指示が混入する。

   **公式仕様からの推論であり、対象環境の対話セッションでは未検証。** ただし、計画どおりの `-p` 試験では、この差を検出できない。

## 崩れる前提

- **入力全体を引用符で囲めば、常に一つの値になる。** 入力自身に `'` があると崩れる。上記の両シェルで再現済み。
- **`$ARGUMENTS` に、利用者が書いた後続文字列が届く。** 対話モードで後続の `/wiki:*` もコマンドとして展開される条件では崩れる。
- **同じ長さのバッククォートを探せば、CommonMark のコード区間になる。** 見出しや別のリスト項目など、ブロック境界をまたぐと成立しない。[CommonMark の優先順位](https://spec.commonmark.org/0.31.2/#precedence)
- **リンク先ファイルの存在を確かめれば、リンクの健全性を確認できる。** 存在しないフラグメントや、クライアントが開けない `file:` URI は検出できない。
- **タグと GitHub リリースがなければ、同じ版への変更追加は配布上の問題にならない。** マーケットプレイスから既に旧内容の 0.14.0 を導入した利用者には成立しない。計画自身もこの制約を認めている（同計画:122）。

## 見落としと軽微な問題

確認中に `wiki_help.py` に未コミットの実装が現れたため、以下は設計と、その読み取り時点の実装を区別して記す。

- **軽微：有効なリンク記法でも、壊れた宛先になるか、相対リンクのまま残る。**

  設計:87 は `[text](target)` を対象にするが、宛先を囲む山括弧やタイトルの扱いを定義していない。読み取り時点の実装で、次を確認した。

  ```markdown
  [検索](<./search.md>)
  [検索](./search.md "検索")
  ```

  前者は `<` と `>` をファイル名に含め、`.../docs/%3C./search.md%3E` に変換して不存在警告を出す。後者は書き換えられず、警告もない。どちらも有効な Markdown である。[CommonMark のリンク仕様](https://spec.commonmark.org/0.31.2/#links)

  根拠：`info-hive-wiki/skills/info-hive/scripts/wiki_help.py:302`、329。現行 `docs/commands.md` のリンクでは、この問題は発生しなかった。

- **軽微：リスト内のコードフェンスは「コード内を変更しない」という約束から漏れる。**

  反例：

  ````markdown
  - ```md
    [検索](./search.md)
    ```
  ````

  読み取り時点の実装では、コード内のリンクが `file:` URI に変わった。設計:78 の「行頭の 0〜3 個の空白」だけでは、リストや引用に属するフェンスを扱えない。

  根拠：同スクリプト:203、340、設計:78、87。

- **軽微：コード区間の判定がブロック境界をまたぐ。**

  次の入力では、`search.md` のリンクが書き換えられなかった。

  ```markdown
  `one
  ### Heading
  [検索](./search.md)
  `
  ```

  CommonMark では見出しがブロックを分けるため、先頭と末尾のバッククォートは一つのコード区間を作らない。読み取り時点の実装は空行までをまとめて処理し、リンクをコード内と誤認する。

  根拠：同スクリプト:254、325、設計:87。

- **軽微：見出しへの表示上の変更だけで、詳細が消える。**

  `## `/wiki:query` ##` は有効な ATX 見出しだが、設計:74 の正規表現にも、読み取り時点の実装にも一致しない。詳細なし・警告・終了コード 0 になる。現行文書の見出しでは再現しない。

  根拠：設計:74、81、同スクリプト:231。

- **軽微：`file:` の代替表示を使う条件に穴がある。**

  設計:93 は「どちらでも開けなければ」代替表示にするとしている。端末では開けるがデスクトップアプリでは開けない、という混在条件の扱いが決まっていない。実際に開けるかは未検証であり、利用不能そのものは断定しない。

- **軽微：試験計画が、上記の入力・記法の境界を含まない。**

  設計:145〜156 には、引用符を含む入力のシェル経由の試験、対話モードの後続コマンド展開、タイトル付きリンク、山括弧付き宛先、コンテナ内のフェンスがない。ファイルの存在だけでは、フラグメントの破損も検出できない。

## 検証した事実

- **一致：** 読み取り時点の全11コマンドに対応する文書の節があり、詳細は空ではなく、リンク先の不存在警告もなかった。
- **一致：** 既存の `eval/scripts/test_help.py` の `RealCommandsTests` 2件は通った。一覧の順序・各3行・引数説明について、現時点の破損は確認しなかった。全テストを実行したわけではない。
- **一致：** `tests/wiki/test_uninitialized_wiki.py:484` の `NO_WIKI` に `wiki_help.py` があり、同:492 の `WIKI_PATTERN` は wiki のパスを受け取る記述を検査する。設計はその分類を変えるものではない。
- **一致：** `plugin.json:3` は 0.14.0、`CHANGELOG.md:9` に同版の節がある。ローカル HEAD は計画に記された `bdae5f5` で、ローカルに `v0.14.0` タグはなかった。リモートのタグ・GitHub リリースの有無は未確認。
- **一致：** 同じバージョンのままでは既存キャッシュが置き換わらない、という計画:122 の説明は公式仕様と一致する。したがって、同じ 0.14.0 でも導入時点によって `/wiki:help query` の可否が分かれる。[Claude Code の更新仕様](https://code.claude.com/docs/en/plugins/loading#versions-and-updates)
