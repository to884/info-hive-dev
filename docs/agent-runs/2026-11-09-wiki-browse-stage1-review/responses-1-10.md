# browse の第 1 段階の設計: 1〜10 回目のレビューの指摘と対応

[browse の第 1 段階の設計](../../plans/wiki-browse-stage1-2026-11-09.md)は、Sol の敵対的レビューで 10 回却下され、そのたびに直した。2026年11月11日に設計の全体を書き直したので、それまでの指摘と対応の対照を、設計からここに移した。表の中の「（3）」のような節の番号は、書き直す前の設計（コミット `cb1920a`）の節を指す。

1 回目のレビュー（[design-review-1.md](design-review-1.md)、却下）の指摘への対応:

| 指摘 | 対応 |
| --- | --- |
| 重大 1: 関係表が、同じスラッグの別のページの関係を出す | 出ていく関係をエッジの `page` で振り分け、入ってくる関係は目的語が 1 つのページだけに対応するときに出す（3）。グラフの抽出の不具合は別の課題にした |
| 重大 2: オントロジーの変更に気づかない | 作り直しの印に `graph/ontology.yaml` を含め、世代に全入力の中身を含める（2、8） |
| 重大 3: `--out` で Wiki の中に書けてしまう | 書き出し先と Wiki を、解いた実体の場所で比べ、重なれば止まる（7） |
| 重大 4: 絶対パスの検査が Windows の例外の文字列を見逃し、漏れを見つけても公開してしまう | 例外の文字列を出力に入れない。公開の前に、複数の表現で調べ、見つかれば前の世代を残して失敗する（2、5） |
| 重大 5: Windows の予約名の取りこぼし | 予約名を、上付きの数字、`CONIN$`、`CONOUT$`、`COM0`、`LPT0` まで広げた（3） |
| 重大 6: 世代の入れ替え、排他、作り直しの途中の扱いが決まっていない | 入れ替えと復旧の手順、ロック、作り直しの途中の要求の扱い、世代の不一致の表示を決めた（6、7、8） |
| 重大 7: 3 方式の確認と、外部への通信の判定が足りない。起動の速さの測り方が狭い | 外部への要求と CSP の違反を失敗にし、起動の速さをコマンドから描画の終わりまでで測る（11）。方式の確認は、最初は子プロセスを含む 3 方式の一致としたが、2 回目と 3 回目のレビューを受けて、ADR-0016 の 2 方式に改めた |
| 崩れる前提: 2 度読むと内容がずれる | 入力を 1 度だけ読む写しから組み立てる（2） |
| 崩れる前提: サーバーと静的版で `raw` の描き方が違う | 描き方を 4 つに分け、試験は同じ描き方で比べる（4） |
| 崩れる前提: Wiki の外を指す `.md` | 最初は読まずに診断に挙げるとしたが、3 回目のレビュー（重大 4）を受けて、lint と同じに読むよう改めた（2） |
| 軽微: ナビゲーションの読み方が採用する関数と合わない | `collect_index_entries` を使わず、どの見出しでもグループにする（3） |
| 軽微: 関係表の「使えない」「0 件」の区別がない | `none`、`error`、`ok` に分けた（3） |
| 軽微: `--stop` がない | `stop` と、使い回しのための記録を足した（8、9） |
| 軽微: 暗黙の関係が被リンクと重なるという説明が誤り | `sourced_from` は表に出し、`mentions` と `summarizes_raw` だけを除く（3） |
| 軽微: コマンドの本数が古い | 10 本から 11 本に直した（9） |

2 回目のレビュー（[design-review-2.md](design-review-2.md)、却下）の指摘への対応:

| 指摘 | 対応 |
| --- | --- |
| 致命 1: 一時と退避のディレクトリの片付けが、名前の形の合う Wiki まで消しうる | 一時、退避、ロック、記録を、目印のある作業用のディレクトリの中に置き、その中の目印のあるものだけを消す。消す直前にも Wiki と重ならないことを確かめる（7） |
| 重大 2: 同じ内容の関係がページを区別せずに 1 本にまとめられ、ページで振り分けても消える | 最初は同じスラッグのページの関係表を出さないとしたが、3 回目のレビュー（重大 2）を受けて、グラフの抽出を先に直す形に改めた（3） |
| 重大 3: 古いロックの片付けの競合で、2 つの書き出しが同時に走る | OS のファイルのロックにし、古いロックを片付ける処理をなくした（7） |
| 重大 4: サーバーの起動と停止の競合で、1 つの Wiki に複数のサーバーができる | サーバーが生きているあいだロックを持ち、起動、使い回し、停止をロックで判定する（8） |
| 重大 5: `INFO_HIVE_DATA_DIR` を Wiki の中に向けると、状態のファイルが Wiki の中にできる | 状態の置き場所と既定の書き出し先が Wiki と重なれば止まる（7、8） |
| 重大 6: 子プロセスの比較は、3 方式を実際に動かす確認の代わりにならない | 作った 2 つの方式を実際のブラウザで確かめ、アプリでの確認はアプリを作るときに回す。3 回目のレビュー（重大 1）を受けて、作者がこれを ADR-0016 として決めた（11） |
| 崩れる前提: 1 度ずつ読んでも、全体の同じ瞬間の写しではない | 限界として書いた（2） |
| 軽微: NFC で同じになる別のファイル | どちらも描かず、診断に挙げる（2。名前は 4 回目のレビューの後に `id_collision` に改めた） |
| 軽微: ナビゲーションの階層、重複、索引を指す項目 | 見出しの木、複数の場所への掲載、`indexes/` を指す項目の扱いを決めた（3） |
| 軽微: `raw` の相対パスと URL の `link` の意味 | `link` は絶対パスだけにし、相対パスと URL は文字として出す（4） |
| 軽微: 新しい試験が CI で流れない、Windows がない | `wiki-browse.yml` で Windows と Ubuntu の両方で流す（11） |

3 回目のレビュー（[design-review-3.md](design-review-3.md)、却下）の指摘への対応:

| 指摘 | 対応 |
| --- | --- |
| 重大 1: 2 方式の確認では、ADR-0010 の合格の条件を満たさない | 作者が、第 1 段階の合格の条件を 2 方式に改め、アプリでの確認をアプリを作るときに回すと決めた（ADR-0016、11） |
| 重大 2: 同じスラッグのページの関係表を隠しても、別のページの入ってくる関係に取り違えた主語が残る | グラフの抽出を先に直し、browse はその契約（主語はページのノード、エッジにページ、`resolve_link()` での解決、同じ `node_id` の診断）を使う（3）。browse の実装は修正が main に入ってから始める |
| 重大 3: パスつきの `sources:` から `sourced_from` ができない | グラフの抽出の修正の契約に入れた（3 の契約の 4 と 6。4 回目のレビューで直した） |
| 重大 4: Wiki の外のページを browse だけで除くと、lint と食い違う | 除かずに lint と同じに読み、実体の絶対パスを出力に入れない（2） |
| 重大 5: `stop` の `os.kill` は、PID の使い回しで別のプロセスを止めうる | `os.kill` をやめ、操作のトークンとインスタンスの ID で確かめた HTTP の要求で止める（8） |
| 重大 6: 状態のディレクトリがジャンクションなら、Wiki の中に書ける | 書き込みのたびに、対象と親の実体の場所を確かめる関数を通す（7、8） |
| 重大 7: `old-*` が複数残ると、戻す世代が決まらない | 世代の目印に `published_seq` を持たせ、いちばん大きいものを戻し、ほかを消す（7） |
| 崩れる前提: 印を取る時点が決まっていない。組み立てが重なると古い結果が勝つ | 組み立ての前に取った印を結び付け、組み立てを 1 つずつにし、後に始めた結果だけを受け付ける（2、8） |
| 軽微: ナビゲーションの最初の見出しより前の項目、「最初の wikilink」の意味 | 最上位のグループに入れる。最初の wikilink で決め、解決しなければ状態つきの文字にする（3） |
| 軽微: 索引とオントロジーの境界の規則 | ページと同じに、lint とグラフの抽出のとおり読む（2） |
| 軽微: 生成の記録の置き場所の食い違い、3 方式の古い記述 | 作業用のディレクトリの中にそろえ（5）、1 回目の対照の行を直した |
| 軽微: 本文の外部リンクの扱いがない | `http:`、`https:`、`mailto:` は `noreferrer` のリンク、ほかは文字にする（3） |
| 軽微: JavaScript を切ったとき、停止の競合、複数の退避の復旧、外部リンクのクリック、日本語の組版の試験がない | 試験に足した（11） |

4 回目のレビュー（[design-review-4.md](design-review-4.md)、却下）の指摘への対応:

| 指摘 | 対応 |
| --- | --- |
| 重大 1: 目的語を `resolve_link()` で解くと、ノードの ID（`concept:y`）が未解決になる | 目的語は既存のスキーマのとおりノードの ID として引き、ページへの参照としては解かない（3 の契約の 3） |
| 重大 2: 曖昧ならエッジを作らない規則と、`unresolved_sources` が空なら必ず作る規則が両立しない | 合否の条件を、1 つのページに解決する `sources:` の値からは必ず作る、に改めた。`resolve_link()` はスラッグを返すので、ページの集合を求めて一意かを決める（3 の契約の 4 と 6） |
| 重大 3: `x.md` と `x.MD` が同じ識別子になる | NFC の衝突とあわせて `id_collision` にし、どちらも描かず、リンクを `ambiguous` にする（2） |
| 重大 4: Wiki の外の入力を読むのに、書き込みは Wiki のルートしか守らない | 読んだ入力の実体の場所を守る場所に入れ、消すときはリンクをたどらない（2、7） |
| 重大 5: 静的の書き出し先をサーバーの状態に重ねると、排他が崩れる | `--out` を `<data_dir>/browse/` と重ねず、目印の種類の違うディレクトリを互いに使わない（7、8） |
| 軽微: ADR-0016 の外部への通信 0 件と、外部リンクのクリックの扱いが合わない | ADR-0016 に、利用者のクリックでの外への移動は数えず、`Referer` が付かないことを確かめる、と書き足した |
| 軽微: `seq` が途中で壊れたとき | `os.replace` で置き換え、読めなければ目印から続きの値を求める（7） |
