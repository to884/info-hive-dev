# browse の第 1 段階の設計: 11 回目からのレビューの指摘と対応

[browse の第 1 段階の設計](../../plans/wiki-browse-stage1-2026-11-09.md)を 2026年11月11日に書き直したあとの、Sol の敵対的レビューの指摘と対応である。10 回目までは [responses-1-10.md](responses-1-10.md) にある。節の番号は、書き直した設計の節を指す。

11 回目のレビュー（[design-review-11.md](design-review-11.md)、却下）の指摘への対応:

| 指摘 | 対応 |
| --- | --- |
| 重大 1: `a\b.md` と `a/b.md` は識別子だけが衝突し、`[[b]]` が描かれていないページに解決する | 衝突の原因を列挙せず、識別子が同じかだけで決める。当たるページが 1 つでも、描かれていなければ `ambiguous` にする（3.1、3.3） |
| 重大 2: `duplicate_node_id` の診断は `page` を持たず、`pages` を持つ | `pages` のそれぞれのページに載せる。`ambiguous_relations` をやめ、この診断で兼ねる（3.6） |
| 重大 3: 待ちが上限を超えると、古い内容を印なしで返す。最初の組み立てでは返す中核がない | 答えに使う中核の印が、その要求で取った印と違えば「古い」と示す。中核がなければ 503 を返す（8.3） |
| 重大 4: Windows で `INFO_HIVE_DATA_DIR` を共有の場所にすると、記録のトークンを読まれる | wiki の MCP サーバーの記録と同じ扱いにし、警告を出して、限界に挙げた（8.4、限界）。作者に確かめる |
| 軽微: 作業用のディレクトリを作る前に、その中のロックを取る順序になっている | 共通のロックのあとで、ディレクトリと目印を作ってから、その中のロックを取る（7） |
| 軽微: 印が変わったまま失敗し続けると、5 秒の間が効かない | 同じ印での組み立ては 5 秒は試さない、という 1 つの規則にした（8.3） |
| 軽微: 未解決の wikilink が、外側の Markdown のリンクでクリックできる | 文字の中に wikilink のある Markdown のリンクは、リンクにしない（3.3） |
| 軽微（推測）: escape した形で書いたパスを、生成器が入れたものと誤る | 描画が利用者の内容として出した文字（escape を戻したあと）を記録し、それと照らす（5） |
| 試験の抜け | `a\b.md` の衝突、ホームと `data_dir` の目印、待ちの上限、権限と警告の試験を足した（11） |
