# 既存オントロジーを見直し・整理する提供案のレビュー

ユーザーの新しい指示: 「ユーザーの指示により既存のオントロジーを見直し整理する機能がほしい。記事を追加し続けると、過去に構築したオントロジーとは概念が乖離する可能性を憂慮している」。
直前の指示により、対象の単位は記事でなく顧客・製品などの実体である。

対象:
- docs/plans/wiki-ontology-maintenance-2026-11-19.md
- docs/plans/wiki-ontology-feature-experience-2026-11-19.md 第6版
- docs/plans/wiki-ontology-entity-granularity-2026-11-19.md

ユーザーの指示で既存定義を再検討し、統合・分割・再分類などと既存記録の移行を行う利用体験として矛盾がないかを敵対的にレビューする。
第5版までの「追加だけ、既存定義の再編は対象外」を変更した。定期自動実行ではなく明示した指示でproposeし、根拠・影響・試行を示して採用する案をapplyする。
概念の不適合と抽出不足・記録不足・現実の時期による変化の混同、新しい記事だけを読んで古い記録を誤って移す案、型と実体の統合の混同、部分移行で旧定義を消す事故などを特に確かめる。
既存entityページ・ID・エッジ参照との対応、通常ingestとの継続利用について、要件レベルで重要な欠落・矛盾を確かめる。

これは要件と大まかな利用体験の設計であり、実装コードや詳細なトランザクション設計を完成させる依頼ではない。未決定と明記した保存スキーマや排他の詳細を、未決定という理由だけで欠陥にしない。
読み取り専用。ファイル変更、別エージェントの起動、レビューの再帰委任は行わない。外部調査は不要。
具体的な欠陥と根拠、修正の方向を日本語で報告する。問題がなければ指摘を作らない。
