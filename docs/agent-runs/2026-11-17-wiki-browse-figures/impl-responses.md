# 図の描画の実装のレビューへの対応

## PR 1（svg）の 1 回目（[impl-review-1.md](impl-review-1.md)。却下、確信度 高）

| 指摘 | 判断 | 対応 |
| --- | --- | --- |
| 重大: BOM のない UTF-16 の svg が UTF-8 の判定を通り、公開の前の検査が中のパスとトークンを見つけない | 正しい。反例を手元で再現した | 判定を「UTF-8 として読める」から「XML として UTF-8 で読まれる」に替えた。UTF-8 として読め、XML 1.0 で許される文字だけからなり、宣言が別の符号化を名乗らないこと。UTF-16 と UTF-32 の ASCII の文字は NUL を伴うので落ちる（`is_utf8_svg`）。試験に BOM のない UTF-16 LE、BE、UTF-32 と、パスを含む UTF-16 の svg が出力に入らないことを足した |
| 軽微: `svg_size` が、コメントの中の `<svg` と `data-width` を拾う | 正しい | 正規表現をやめ、標準ライブラリの expat で根の要素の開始タグまでだけを読む。DTD があれば、その始まりで止めて分からないとする（`_svg_root_attrs`）。試験にレビューの 2 つの反例と、名前空間の接頭辞、根が svg でないもの、DTD、閉じていないタグを足した |
| 軽微: lint が文字参照を解く前に `#` で切るので、`&#38;` と `&quest;` で閲覧とずれる | 正しい。原因は、lint と閲覧が別々の規則で参照先を解いていたこと | lint が markdown-it と同じ関数（同梱の `unescapeAll`）でエスケープと文字参照を解いてから切るようにした（`image_ref_path`、`wiki_pages.unescape_destination`）。独自の文字参照の正規表現は消した。試験は、15 の参照先について、markdown-it の `src` から解いた結果と lint の結果を突き合わせる |
| 軽微: 暗い配色の試験が「入れ物と本文の地が違う」ことしか見ない | 正しい | 明るい配色のときの入れ物の地を先に読み、暗い配色でも同じであること、本文の地は変わることを確かめるようにした |
| 軽微: リンクの試験が、ファイルのリンクを作れないとディレクトリのリンクの確かめまで飛ばす | 正しい | 3 つの試験に分けた。ファイルのシンボリックリンク、ディレクトリのリンク（作れなければ Windows ではジャンクション。`link_dir`）、Windows のジャンクション |

崩せなかった点としてレビューが挙げたもの（読む口の上限、NFC と NFD の重なり、大文字と小文字、出力の名前の衝突、リンクの `assets` を一覧しないこと）は、変えていない。
