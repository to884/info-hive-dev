# browse の探しやすさと Fluent 2 の実装のレビューへの対応

## 1 回目（[impl-review-1.md](impl-review-1.md)、却下。分類 A が 2 件）

| 分類 | 指摘 | 原因 | 対応 |
| --- | --- | --- | --- |
| A（重大） | 索引のページで並べ替えたあとに Enter を押すと、見えている先頭ではなく、索引の順の先頭のページを開く | 行の順を、読み込んだときの配列と、並べ替えた DOM の 2 か所に持っていた。並べ替えは DOM だけに当たる | 行の順は DOM だけが持つ。Enter は DOM の今の並びで、見えている先頭の行を読む（`list.querySelector(".fx-row:not([hidden])")`）。試験に、題名の順に並べ替えて Enter を押す確かめを足した |
| A（軽微） | 知らない種類（`note` など）の札が、中立ではなく Fluent の既定の brand の色になる | 札の class は種類の値から `t-<種類>` を作るが、中立の色は `t-other` の名前にだけ当てていた | 種類の札は既定で中立の色にし、色を持つのは知っている 4 つの種類だけにした（`.fui-Badge.badge` を中立、4 つの `t-*` を上書き）。試験に、`note` の札が `t-other` と同じ地で、`t-concept` と違うことを足した |
| C | 記事のページの木に「不完全」の印が出ない（`nav.js` の `incomplete` を読まない） | `app.js` が `incomplete` を読んでいなかった（今回の前から） | 木の先頭に「読めない索引のファイルがあるので、この木は不完全」を出すようにした |
| C | 並べ替えと Enter を組み合わせる試験がない | — | 上の A の試験として足した |

## 2 回目（[impl-review-2.md](impl-review-2.md)、却下。分類 A が 1 件。致命と重大は 0 件）

| 分類 | 指摘 | 原因 | 対応 |
| --- | --- | --- | --- |
| A（軽微） | 断片を `#group=%` にすると例外になり、前のグループの絞り込みが残る。`index.html#group=%` で開くと初期化が止まる | ID の形を確かめる前に、`decodeURIComponent` で断片を解いていた | グループの ID は `_g` と英小文字か数字だけで、URL で符号化されない。断片は解かずに、そのまま形と木にあるかを確かめる。例外の起きる経路をなくした。試験に、絞ったあとに `#group=%` にする確かめと、`#group=%` で開く確かめを足した |
| C | 記事のページのコントラストの試験が、検索で木を隠したあとに測っていた | — | 木を出した状態（すべてのグループを開く）と、検索の結果を出した状態の両方で測る。木の状態の最小は明るい配色で 5.13、暗い配色で 7.08 |
| C | 索引のページの変換中のキーを試験していない | — | 記事と索引の両方で、同じ確かめ（`imeChecks`）を流す |
