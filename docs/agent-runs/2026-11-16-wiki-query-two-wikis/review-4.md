## 判定

**却下。確信度：高。** ファイルへのシンボリックリンクが比較から漏れ、仕様上は警告なしの `disjoint` でも、出典の誤認と他方のページの上書きが成立する。ハードリンクを対象外にする決定には依存しない反例である。

## 致命的・重大な欠陥

### 1. 重大：ディレクトリの分離では、ファイルへのシンボリックリンクを通じた共有を検出できない

両方の根を初期化し、次の配置にする。矢印はすべて**ファイルへのシンボリックリンク**である。

```text
U/
  SCHEMA.md
  own.md
  linked.md ───────────────────────→ P/secret.md
  index.md ────────────────────────→ P/secret.md
  .wiki-cache/search-index.json.tmp → P/secret.md

P/
  SCHEMA.md
  index.md
  secret.md    本文: # PROJECT_SECRET
```

前提は、ディレクトリの識別子と `wiki_key()` がそれぞれ異なり、全項目を一覧でき、配置が検査前後で変化しないことである。ハードリンクは作らず、リンク先ファイルの `st_nlink` は 1 とする。

設計の補助はディレクトリだけを比較するため、この配置は **`disjoint`** になる。`os.stat()` のリンク数にも異常がないので、仕様上の警告条件にも当たらない。

**読み取り側の反例**

- `walk_markdown()` は、ディレクトリのシンボリックリンクには降りないが、ファイルのシンボリックリンクは `os.stat()` で通常ファイルとして受け入れる。
- `collect_pages(U)` は `P/secret.md` の本文を `U/linked.md` の本文として収集する。検索結果に「ユーザースコープ」と付ければ、プロジェクトの本文を誤った出典で示す。
- `list_index(U)` も `U/index.md` を直接読み、プロジェクトの本文を U の索引として返す。

**書き込み側の反例**

MCP を利用できない状態で、計画が許可する CLI の `--no-embed --cache` を使う。

`write_parse_cache()` は既存の `search-index.json.tmp` を `write_text()` で開く。この時点でリンク先の **`P/secret.md` がキャッシュの JSON で上書きされる**。後続の `os.replace()` は、既に変更したリンク先の本文を復元しない。

**検証結果：食い違い。** ファイルシステムの入口をメモリ上のモックに置き換え、実際のページ収集・キャッシュ書き込み関数と、ソースから抽出した `list_index()` を実行した。

```text
walk_pages(U): ['linked.md', 'own.md']
collect_pages(U): linked.md の本文が '# PROJECT_SECRET'
list_index(U): wiki は U、index は '# PROJECT_SECRET'
ディレクトリ識別子: U 側と P 側の交差なし
通常ファイルの st_nlink: すべて 1
write_parse_cache 後: P/secret.md の内容がキャッシュ JSON
```

補助自体は未実装なので、`disjoint` と警告なしになる点は仕様からの判定である。実ファイルへの破壊試験は行っていない。

- [設計書:175](/C:/Works/info-hive-dev/docs/plans/wiki-query-two-wikis-2026-11-16.md:175)：警告はリンク数によるもの。ファイルのシンボリックリンクを止める規則がない。

## 崩れる前提

| 暗黙の前提 | 崩れる条件 |
| --- | --- |
| 同じファイルを読むには、ディレクトリの共有かハードリンクが必要である | 一方のファイルが、他方のファイルへのシンボリックリンクである |

## 見落としと軽微な問題

- **軽微：試験にファイルのシンボリックリンクがない。** [設計書:191](/C:/Works/info-hive-dev/docs/plans/wiki-query-two-wikis-2026-11-16.md:191) はディレクトリへのリンク、194 行はハードリンクを扱う。列挙された試験が通っても、今回の反例は残る。
- 第2節の「ディレクトリのシンボリックリンクには降りない」は実装と一致するが、ファイルへのリンクを受け入れる挙動が抜けている。第5節にも、この経路による出典の誤認・上書きの記載はない。
- 第8節の修正は、ハードリンクを除外する過程でファイル比較自体を失っている。通常ページ同士のファイルシンボリックリンクなら、従来のファイル識別子比較では検出対象になり得た共有が、6版目では比較対象から外れる。
