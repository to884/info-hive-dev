# フックとモデル選定の実装の敵対的レビュー

ユーザーは、23:30の利用上限解除後にモデル表の再測定・確定・Opusのレビューまで進めることを求めている。測定158回は現在進行中なので、まず実装と採点・選定の条件を読み取り専用でレビューする。最終表の根拠の確認は、測定と読み合わせが終わってから同じセッションで依頼する。

ファイルを変更せず、別のエージェントやモデルに依頼せず、外部通信や claude による測定も行わない。APIを呼ばない単体試験は動かしてよい。ユーザーの作業に並行しているため、測定の実行・停止・ファイルの削除をしない。

対象の目的:
- 指示から関係するwikiの候補だけを語彙で選び、2,000文字以内で出す。ユーザーwikiは有効にしたときだけ読む。
- 期限を超えた子を止めて指示を待たせない。所在を壊さず、表示した候補だけで段と既出記録を決める。
- モデル表は、固定した入力とエージェントで6組を比較し、未読・不正・曖昧な引用がなく、必読ページをすべて読み、正しさが最良の組の95%以上となる組から測定費用が最小のものを採る。字句の一致は採用の確定ではなく、意味と根拠の読み合わせを別に行う。

既知の採点の不具合: 単一のproject wikiを渡す問いでも、page_keysがuser側の同名ページを見て曖昧扱いする。修正と再採点を予定している。これは生の回答や読む成功の証拠を変えるものではない。採点だけを改めるときに実測の来歴を保つ方法も確認する。

旧Solレビューの重大6件は修正し、フック60件・測定14件の単体試験は通過した。旧版の未読引用には題名をリンクにした別の誤りも含まれていたため、読み取り成功とリンク解決を分けた。旧測定と新測定は混ぜない。

今は静的な欠陥と崩れる前提を具体例で報告する。未完の測定やモデル表がまだ暫定であることだけは、今回の既知の進行状態として扱う。
