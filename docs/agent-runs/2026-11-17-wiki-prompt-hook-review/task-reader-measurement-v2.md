# 読むモデルの再測定の道具の敵対的レビュー

読み取り専用でレビューする。ファイルの編集、別モデルへの依頼、ネットワークを使う測定はしない。

ユーザーは、候補を読むモデルとエフォートを再測定して確定することを求めた。前の測定には利用上限による欠測、読む成功の証拠の欠落、スラッグと表示用の題の混同があり、表を確定できなかった。

測定手順を第2版にした。次を壊す反例を探す。
- 固定した wiki、エージェント、問い、CLI の版とスクリプトの条件で再開する。
- 読み取りを呼んだだけでは既読にせず、成功した応答と対応づける。
- スコープと相対パスでページを区別し、未読・存在しない・曖昧な引用を分ける。
- 欠測した組を最安と誤認せず、回答の意味と根拠の読み合わせ前には表を確定しない。
- 利用上限で残りの呼び出しを止め、解除後の再試行は古い失敗を残す。

対象の実測は最初の1回が usage_limit_reached になり、残り157回は呼んでいない。API を使わない測定の試験14件とフックの試験60件は成功した。TIERS は変更しておらず、表は未確定である。

対象は tests/wiki/measure_reader_models.py、tests/wiki/test_reader_measurement.py、tests/wiki/fixtures/prompt_context/reader_questions.json、docs/research/wiki-prompt-hook-stage0-2026-11-17.md。必要なら単体試験を動かしてよい。実測の run サブコマンドは呼ばない。
