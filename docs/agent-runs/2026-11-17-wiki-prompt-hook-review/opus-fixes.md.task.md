# Sol の指摘を修正した実装の敵対的レビュー

読み取り専用のレビューを行う。ファイルを編集せず、別のエージェントやモデルへの依頼もしない。根拠のない懸念は推測と明示する。

対象は UserPromptSubmit のフックの段階 1。既定はプロジェクト wiki、ユーザー wiki は明示的に有効にしたときだけ読む。語彙だけで候補を選び、本文を出さず 2,000 文字以内にする。所在は JSON から復元可能である必要がある。実際に出す候補だけで読む段と既出記録を決める。プロンプトを止めず、解析の遅れを 2.5 秒で打ち切る。状態は並行実行でも上書きで失われない。

まず review-1.md の重大6件と軽微な指摘を確認し、修正後も再現する欠陥と新しい反例を探す。修正は wiki_prompt_context.py、wiki_prompt_hook.py、query-confidence.md、prompt-context.md、wiki-reader.md と、親リポジトリの test_prompt_hook.py、eval_prompt_context.py にある。git diff も参照できる。

今回の追加試験は58件を通過した。入力の除外、実在する長い所在、同名ページの片側の省略、状態の競合、遅い子の実際の停止を試験している。必要なら標準ライブラリの unittest と小さな再現を実行してよい。ネットワークを使う測定や別モデルの呼び出しはしない。

以下は引き継ぎ時から未完了で、今回の目的は実装の欠陥修正である。
- 読むモデルとエフォートの表は暫定。利用上限で失敗した測定と未読ページの引用を受け、再測定するまでリリースを認めない。
- uv 自体の起動失敗の標準エラーが画面でどう扱われるかと、デスクトップで窓が出ないかの実機確認は未完了。Python 内の失敗、タイムアウト、子の標準エラーは入口で捨てる。
- 既存の評価データは単一 wiki の調整済みのデータで、未知の wiki への一般化を示さない。
- 段階 2 の埋め込み検索とリリースは今回行わない。

重大な欠陥は具体的な入力、出力、コード位置を示す。単に未完了の測定を完成済みと評価しない。
