# プロジェクト用オントロジー設計の敵対的レビュー

ユーザーの依頼は「今の wiki の記事をもとに、このプロジェクトに合ったオントロジーを設計して」。
対象は info-hive-dev の wiki で、配布プラグイン全体の既定を変える依頼や、本番へ適用する依頼ではない。
設計書、完全な候補 YAML、根拠と試料、検査結果をレビューする。
変更や別のエージェントの起動は禁止。読み取りだけで実行する。

## 目的と前提

- 主題は開発知識。出典記事を保ち、製品・構成要素・版・変更・問題・判断・評価・概念を区別する。
- 既存の graph engine に 1 ページ 1 ノード、関係の主語は所有するページ、という制約がある。
- 現行のエンジンは状態/時間の経路フィルターや引用の意味・真偽の保証を提供しない。
- この設計は機械的な型制約と、人が確認する意味・状態・粒度の規則を区別する。
- ユーザーの許可なく本番の ontology やページは変えない。

## 特に崩してほしいこと

1. 現行の記事の意味に合う種類か。粒度が破綻する反例、重要な問いを表現できない点はあるか。
2. 新しい述語の主語/目的語、方向、既存の述語との整合に欠陥があるか。
3. 出典の記述から試料の関係を本当に支持できるか。とくに fixes、motivated_by、implements、selects。
4. ノードの状態・関係の status・評価の結果・対象版の扱いが矛盾していないか。
5. 検査済みの主張が検査の範囲を超えていないか。互換性を壊す YAML 変更があるか。
6. 候補を実 wiki に展開するときに設計通りに作れない点はあるか。

必要なら wiki の原記事と現行 scripts を自分で読んで確認する。
根拠の台帳の quote と supports の説明を無条件に正しいと扱わない。
試料は raw/すべてのリンク/インデックスを複製していないため、完全な wiki の構造 lint に合格しない点は既知の範囲外。
既存の汚れた作業ツリーの無関係な差分はレビューしない。

設計の採用を妨げる欠陥から挙げ、観測した欠陥と推測を区別する。
