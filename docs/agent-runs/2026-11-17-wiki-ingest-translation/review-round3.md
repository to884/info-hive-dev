## 致命的・重大な欠陥

### 1. 【致命】キリル文字・ハングル・ギリシャ文字の近似コピーが、警告なしで完了する

- **主張**: ラテン文字以外の文章で残存をエラーにするのは、原文の文と完全に一致する部分文字列が残った場合だけです。1 語を削るか 1 文字を変えると、エラーも警告も出ません。`--accept-warnings` がなくても `completed: true` になり、作業用の写しも消えます。前回の指摘 (1)「警告なしで完了する」が、形を少し変えただけで残っています。
- **反例**（`TranslationCompletionTest` の `prepare` と `run_check("--finish")` を使い、一時ディレクトリで実行した）:
  - ロシア語の 2 文で、各文の末尾の 1 語を削った。結果は `code 0, completed true, errors [], warnings [], wd_exists false`。
  - 先頭に `システムは文書を検索する。` を置き、ロシア語の 2 文を各 1 文字だけ変えた。結果は同じく、警告なしで完了した。
  - 韓国語の 2 文で、`생성합니다.` を `생성한다.` に、`확인합니다.` を `확인한다.` に変えた。警告なしで完了した。
  - ギリシャ語の 1 文で、末尾の 1 語を削った。警告なしで完了した。
- **根拠**:
  - `wiki_rawcheck.py` の `translation_block` は、ラテン文字以外の文章を、原文の単位と完全に一致する部分文字列（`normalized_prose(unit) in out_norm`）でしか照合しません。
  - 出力全体が外国語かを見る分岐（`plain_latin_prose(out)`）と、日本語の中の外国語の句を見る run の分岐は、`LATIN_WORD_RE` だけを数えます。
  - 近似コピーの検出（`SequenceMatcher`）は、漢字が 8 字以上ある単位に限られます。
  - 残る警告（`new_tokens`、`missing_names`、`short`）も、すべて ASCII の英字が前提です。
  - 英語で同じことをすると、全体を見る分岐がエラーにします（`en_one_word_typo_each_sentence` は `untranslated`）。書き方によって判定が非対称です。
- `web-raw.md:17` の「ラテン文字と漢字以外の文章も調べる」と、CHANGELOG の「キリル文字・ハングルなどの文章を丸ごと残した場合も…エラー」は、完全一致の場合しか満たしていません。

### 2. 【重大】正しく保持した完全な文がエラーになり、受理する道がない

- **主張**: 原文の単位が文末の記号で終わり、4 語以上かつ字母が 20 字以上なら、出力にその並びが残るだけで `untranslated` のエラーになります。句読点や括弧を変えても逃れられません。`--accept-warnings` でも通らないので、保持の理由を記録する道がありません。前回の指摘 (2) は、試験の形（文末のない表示名）でしか直っていません。
- **反例**（いずれも `--finish --accept-warnings` で `code 1`、`untranslated`）:
  - 文献の項目: `- Vaswani, A., et al. Attention Is All You Need. NeurIPS 2017.` をそのまま残した場合
  - 題名を 「」 で囲み、句点を外した場合: `- Vaswani, A. ほか「Attention Is All You Need」NeurIPS 2017 で発表。`
  - 文が 2 つあるエラーメッセージ: `アプリには「Unable to connect to the server. Check your network connection and try again.」と表示される。`
  - 句点を外して 2 つの 「」 に分けた場合
  - 引用に原語を併記した場合: `> Stay hungry, stay foolish forever.（ハングリーであれ、愚かであれ）`
  - ライセンス文: `THE SOFTWARE IS PROVIDED AS IS, WITHOUT WARRANTY OF ANY KIND.`
- **根拠**: `translation_block` の Unicode の語のループです。文末を見る `re.search(r"[.!?。！？;；]\s*$", unit)` は、出力ではなく原文の単位に掛けています。照合は句読点を取り除いた `normalized_prose` で行うので、出力の句読点をどう変えても結果は同じです。逃れるには、題名やメッセージの文字を書き換える（誤った訳を作る）しかありません。
- **影響**: 参考文献の節がある論文や技術記事は、正しく訳しても完了できません。

### 3. 【重大】欠陥 1 と 2 の境界は「文かどうか」ではなく、文字の並びが完全に一致するかで決まっている

- **主張**: エラーになるかどうかは、原文の文の字母がそのまま残るかどうかだけで決まります。そのため、次の 2 つが同時に起きます。
  - 正しく保持した文献の題名はエラーになる（欠陥 2）。
  - 訳していない文は 1 文字変えるだけで通る（欠陥 1）。
- 依頼元の説明にある「文末を伴う原文の文が残る場合をエラーに」は、文字の並びの同一性で実装されています。文と表示名などを区別するという設計の目的とは、別の基準です。

### 4. 【重大】round3 で、ラテン文字の部分翻訳がエラーから警告に格下げされた

- **主張**: patch の 67〜71 行で、run のループの `return True, "untranslated"` が `uncertain = True` に変わりました。その結果、各文の主語だけを訳して残りを英語のままにした段落が、警告と `--accept-warnings` で完了します。重点の「部分翻訳を拒む」と、`web-raw.md:17` の「段落の一部だけを訳した場合も調べ」に反します。
- **反例**:
  - `エージェントは searches document links before generating an answer. データベースは stores all pages and their explicit relationships.` → `completed true, warnings [translation_uncertain]`
  - 各文に `（リンク）` のような日本語を 1 つ挟んだ場合も、同じく警告だけで完了した。
- 防いでいるのは手順の規則（警告ごとに具体的な理由を書く）だけで、検査器は理由の中身を確かめません。

### 5. 【重大】文末の記号を使わない書き方の文章は、丸ごと残しても警告だけで通る

- **主張**: 文末の記号の集合 `[.!?。！？;；]` に含まれない記号で終わる文章は、完全一致でも警告だけになり、`--accept-warnings` で完了します。
- **反例**（いずれも `completed true`、警告 `translation_uncertain` のみ）:
  - ヒンディー語の 2 文（文末は `।`）
  - タイ語（文末の記号がない）
  - アラビア語の疑問文（文末は `؟`）
  - `…` で終わる英文
  - `)` で終わる英文
  - `:` で終わる英文（コマンドの紹介）
  - 句点のない英語のリスト項目（13〜14 語）
  - 句点のない韓国語のリスト項目
- **根拠**: 原文の単位の文末判定と、出力全体の判定 `[.!?;]\s*$` には長さの上限がありません。13 語の英文も、2 語の UI 名と同じ「文末のない短い説明」として警告になります。計画の「文末のない**短い**説明」とも合いません。

## 崩れる前提

- **前提**: 原文の文は、原文と同じ字母の並びで残る。
  - **崩れる条件**: エージェントが 1 語でも変える、削る、日本語を挟む（欠陥 1、4）。英語は全体を見る分岐で一部を拾えますが、日本語が 1 文字でも入ると拾えません。
- **前提**: 文は `.!?。！？;；` で終わる。
  - **崩れる条件**: `।`（ヒンディー語など）、`؟`（アラビア語）、`။`（ビルマ語）、`።`（アムハラ語）、タイ語の空白、`…`、`:`、リストや表のセル（欠陥 5）。
- **前提**: 文末を伴う外国語の文を正しい訳に残すことはない。
  - **崩れる条件**: 文献の題名、文が 2 つ以上あるエラーメッセージや UI の文言、引用の原語併記、ライセンス文、英語を扱う記事の例文（欠陥 2）。
- **前提**: 警告ごとに具体的な理由が書かれる。
  - **崩れる条件**: 検査器は `log.md` の `prepare` の記録を読みません。`--accept-warnings` が付いていれば、理由の有無に関係なく `completed: true` を返します。欠陥 4 と 5 の防止は、この手順の規則だけに頼っています。
- **前提**: `checked_blocks >= 1` なら、本文を検査した。
  - **崩れる条件**: 欠陥 1 の入力でも `state: checked` になります。この値は照合した数であり、未翻訳がないことは示しません（文書の定義とは合っています）。
