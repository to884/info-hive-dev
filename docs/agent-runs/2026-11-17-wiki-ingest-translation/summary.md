## 完了を決める条件

- 翻訳必須の `keep` はエラーにし、比較元を残す。`needs_translation` の欠落や型の違いも翻訳不要にはしない。
- 未解決の外国語の候補は `translation_review_required` のエラーで止める。文末、大小文字、原文との完全一致だけで文章や名前と分類して受理しない。
- 正しく保持する文字列と正しい日本語の候補は、対象の ID・text の全文・種類・具体的な理由と実際に確認したモデル名を、現在の原文・raw の SHA-256 に結び付ける。記録の配列は `decisions`、日本語の種類は `japanese_text`。不正・古い・部分的な記録で残りを一括受理できない。
- `--translation-review` を明示して記録を照合する。有効な記録も `translation_reviewed` の警告になり、親が原文と文脈を確認し、W9 より前に `prepare` のログへ理由を書いて受理する。raw のエージェントは警告を受理しない。
- 漢字の多い見出しや表のセルも頻繁に候補になるため、委譲時の `warnings` は通常の経路である。対象ごとに原文との対応を確認し、汎用の理由による一括受理をしない。
- JSON の `translation.pending_reviews: 0` と `completed: true` を後段への条件にする。委譲先の `done` は実際の `warnings: []` と `reviewed_passages: 0` も要求する。`ok`、翻訳者名、フォルダーの消失から完了を推定せず、監査も確認の証拠を要求する。

スキルの正本はプラグイン内の `skills/info-hive/`。親の `.agents/skills/`、`.claude/skills/` と skills-lock.json に、このスキルの別配置や登録はない。公開済みの Playwright とリンクの変更は main から統合した。`implementation.patch` は最新 main から今回のコードと試験だけの差分である。

## 保証する範囲

検査器は候補の検出と、記録の形式・対象・現在の本文への結び付きを調べる。確認者名は非空の自己申告の文字列で、本人性を保証しない。分類や理由の具体性、訳の正しさ・完全性は確認者が原文と文脈を読む。Codex などが自分で W1〜W8 を行う経路は自己確認で、独立したレビューではない。監査は `prepare` のログの有無・順序までは判定しない。

短い語や同一文の外国語の漢字に日本語の助詞を混ぜる形など、検出条件に当たらない見逃しはあり得る。確認の記録を翻訳の代用にせず、候補のブロック全体を読み、文章は訳す。比較元やプログラム自体の任意の改ざんに対する防御は目的としない。
