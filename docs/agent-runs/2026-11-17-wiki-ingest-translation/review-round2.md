## 判定

**条件付きで採用可**（確信度：中）。前回の反例は、見出しの名前、段落の後半の残存、中国語の 1 文字変更、短い項目のいずれも直っていました。一方で今回の方式の変更により、新しい欠陥が二つ入っています。

- **退行**：ハングル、キリル文字、ギリシャ文字など、ラテン文字でも漢字でもない言語の未翻訳が、翻訳者名を入れるだけで `completed: true` になります。前の版はこれを止めていました。
- **正しい訳を止める**：英語を残した正しい訳の一部が、受理できないエラーで止まります。

対象は、レビュー中に依頼元がコミットした `info-hive-wiki` の `b368afc` と、親リポジトリの未コミットの試験です。

## 致命的・重大な欠陥

### 1. 重大（実装と設計の退行）：ラテン文字でも漢字でもない言語は、原文のままで完了する

- **反例**（`--finish --accept-warnings`）：次の段落を原文のまま残し、`translated_by` だけを入れました。いずれも `code=0`、`completed=True`、`state=checked`、エラーも警告もありません。
  - 韓国語：`이 시스템은 문서 사이의 링크를 사용하여 …`
  - ロシア語：`Эта система использует ссылки между документами, …`
  - ギリシャ語：`Το σύστημα χρησιμοποιεί συνδέσμους …`
  - 韓国語の見出し：`## 시스템 설계 원칙과 구현 방법`
- ロシア語の 2 文のうち 1 文目だけを訳し、2 文目を残した場合（`ru-partial`）も完了します。
- **原因**：`translation_block` の判定は、ラテン文字の語（`LATIN_WORD_RE`）と漢字（`HAN_RE`）にしか反応しません（`wiki_rawcheck.py` の `plain_latin_prose`、外国語の一続きを調べるループ、中国語の検査）。最後の判定でも、`words` が空なら `identifier=True` になり、警告すら出ません。
- **この経路に実際に入ること**：`wiki_fetch.japanese_text_ratio` はかながなければ 0 を返すので、これらのページは `needs_translation: true` で検査に入ります。
- **退行であること**：前の版（`3ad7018`）は、文字数の比率でこれらをエラーにしていました。依頼元は「すべての言語の判別は保証しない」と断っています。それでも、元の事故と同じ型の「翻訳者名だけ」の未翻訳が、警告もなく `checked` として完了するのは、この修正の目的に反します。
- **試験の穴**：`TranslationCompletionTest` には、この種の言語の例がありません。

### 2. 重大（設計と実装）：英語を残した正しい訳の一部が、受理できない `untranslated` になる

- **反例**：いずれも `--accept-warnings` を付けても `code=1`、`untranslated` で止まります。
  - エラーメッセージを残す：`ログに Permission denied while opening the configuration file と出たら、所有者を確かめる。`（前の版では通っていた）
  - UI の表示名を残す：`Save all changes and continue をクリックして終える。`（前の版では通っていた）
  - 小文字のライブラリ名を残す：`- 使ったライブラリ: numpy、scipy、pandas、matplotlib。`
  - 文の形の論文名を残す：`論文 Language models are few-shot learners は GPT-3 を発表した。`
  - W6 の指示どおりに原語を添える：`最小権限の原則（principle of least privilege）に従う。`。W6 は「原語を括弧で添える」と指示しています（`references/web-raw.md` の W6）。3 語の `（retrieval augmented generation）` は通りますが、4 語以上かつ 20 文字以上だと止まります。
  - 表のセルの値を残す：`fast, safe`、`linux, darwin, windows`（コードスパンにしていないもの）
- **原因**：文章かどうかの判定（`plain_latin_prose`）の中心は、「文法語以外の小文字の語が 2 つ以上あるか」です。小文字の識別子、ライブラリ名、引用した文字列は、この判定で文章と区別できません。
  - 名前として警告に回すのは、すべての語が大文字で始まる句だけです（`possible_name`）。
  - 原文の丸残しの判定（`src_norm == out_norm and plain_latin_prose(src)`）と、外国語の一続きを調べるループは、すべてエラーを返します。
- **計画との食い違い**：計画の 3 は「製品名・論文名の可能性がある句は確認を要する警告」としています。実装では、小文字を含む名前や文の形の論文名はエラーになり、`--accept-warnings` でも通りません（計画の 4 で受理のフラグも作らない）。正しく訳したエージェントは、カタカナにするか、`failed` で止まるしかありません。

## 崩れる前提

- **「外国語はラテン文字か漢字で書かれている」**：韓国語、ロシア語、ギリシャ語、アラビア語、タイ語などで崩れます（欠陥 1）。前の版にあった、言語によらない比率の安全網を外したことで表に出ました。
- **「小文字を含む英語の一続きは文章である」**：小文字の識別子、ライブラリ名、エラーメッセージ、UI の表示名、文の形の題名、原語を添えた用語で崩れます（欠陥 2）。
- **「すべての語が大文字で始まる句は、名前として警告で扱ってよい」**：`## Why We Moved Away From Microservices` を訳さずに残しても、`translation_uncertain` の警告だけで終わります。警告の受理は呼び出す側の判断に任されているので、未翻訳の見出しが理由を書くだけで通ります。設計どおりの挙動ですが、検出が呼び出す側の判断に依存することは前提として残ります。
- **「規則を足せば誤検出は減る」**：判定は手で調整した規則の集まりです。
  - `GRAMMAR_WORDS` に `how`、`what`、`which`、`because`、`than` を追加している
  - `identifier` は「2 語ですべて大文字で始まる」
  - 中国語の検査は「漢字が 20 文字未満でかつ 1 文なら警告」「かなが 2 文字以下で類似度 0.85 以上」

  欠陥 2 の誤検出はエラーで、受理の経路がありません。直すには、規則か例外をさらに足すしかない構造で、場当たり的な修正の圧力は前の版から変わっていません。

## 見落としと軽微な問題

- **軽微（手順）：新しい操作名 `prepare` が、ログの操作名の一覧にない**：`web-raw.md` の 5 は `## [YYYY-MM-DD] prepare | …` を追記させます。しかし `skills/info-hive/assets/log.md.template` の操作の一覧は `ingest`、`query`、`lint`、`schema`、`shard` だけで、`prepare` がありません。取り込みを途中でやめると、対応する `ingest` のない `prepare` 行が残ります。
- **軽微（手順）：古い手順の記述が二か所に残っている**
  - `references/ingest-workflow.md:116`：「理由を `log.md` に書いてから `--finish --accept-warnings`」とだけ書き、`prepare` の記録にも `completed` の確認にも触れていません。
  - `references/ingest-workflow.md:442`：受け入れた警告の理由を「取り込みの行のサブ行」に書くとしていて、`web-raw.md` の新しい順序（W9 より前に `prepare`）と食い違います。
- **軽微（実装）：`checked_blocks` が実際に判定できたブロックの数ではない**：URL を除いた文字がある限り数えます（`# Graph` のような 1 語の見出しも 1 件）。`checked`（1 以上）は「文章を判定できた」ではなく「何か文字があった」という意味になります。
- **補足（欠陥ではない）**：`translation_html` は本番の経路では起きません。`wiki_pages.new_parser()` は `{"html": False}` で、`html_block` を作らないからです。試験も `mock.patch.dict(... {"html": True})` で強制しています。実際に `wiki_fetch.py --html-file` で文字の `<section>` を含むページを取り込み、訳して `check` しましたが、`translation_html` は出ず、`completed=True` でした。

- 一致：前回の反例のうち、次はエラーになりました（一時ディレクトリで再現）。

## 崩せなかった点

- `keep` による抜け道は塞がれたままでした。`untranslated` と `translation_required` も `--accept-warnings` では通りません。
- 英語については、現実的な部分翻訳（文や節を英語で残す、訳と原文を交互に置く、日本語を少し足す、句読点を変える）で、完了まで通る例を作れませんでした。
- 中国語は、文ごとの丸残しにも、かなを 1〜3 文字混ぜた近似コピーにもエラーが出ました。
- 次の正しい訳は通りました。
  - 普通の段落で製品名を英語のまま残した訳
  - 大文字で始まる見出しの名前を残した訳
  - かぎ括弧で囲んだ Title Case の論文名（`「Attention is all you need」`）
  - 3 語の原語を添えた訳
  - 日本語の原文
- 警告を受理する経路の手順（`web-raw.md` の 5 の `warnings`）は、`--finish --accept-warnings --json` の `completed: true` と翻訳の状態を確かめるように改められていました。

`✶ Insight ─────────────────────────────────────`
- 比率による判定から「残った外国語の文や節を見る」判定へ移ると、検出の根拠が「その文字体系の語を数える規則」に変わります。規則を書いた文字体系（ラテン文字と漢字）の外では、何も検出されなくなります。
- 小文字を含む英語の一続きは、文章と、識別子・引用・原語の併記とを、表層の形だけでは区別できません。区別できないものをエラーにすると受理の経路がなくなるので、誤検出がそのまま取り込みの失敗になります。
