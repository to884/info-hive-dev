# rag 0.5.3 の PDF のヘッダーのエラーメッセージの修正の敵対的レビュー（2026-11-13）

rag 0.5.2（[2026-11-13-rag-pdf-header-wording](../2026-11-13-rag-pdf-header-wording/README.md)）で、文書の書き方を「`%PDF-` の前にあるバイトが 1024 バイト以下なら受け付ける」にそろえた。`read_pdf` のエラーメッセージ「PDF の形式ではありません（先頭の 1024 バイトに %PDF- がない）。」は、試験が文字列を固定しているので、文書だけの 0.5.2 では残していた。rag 0.5.3 で、これを「PDF の形式ではありません（%PDF- がないか、最初の %PDF- の前に 1024 バイトを超えるバイトがある）。」に直し、試験と wiki を合わせた。GPT-6.1 Sol（effort high、`ask-codex` の `review`）に 1 回レビューしてもらった。

- 依頼: `review-sol.md.task.md`。対象は差分 `reviewed.diff`（前半が `info-hive-rag`、後半が親の試験と wiki）と、変更後の `rag_index.py`、rag の CHANGELOG と `plugin.json`、`tests/rag/test_jobs.py`、`wiki/concepts/pdfのヘッダーの条件.md`
- 結果: `review-sol.md`（採用可、確信度 高）
- レビュアーは、`has_pdf_header` を取り出して 16,150 件の入力（位置別、部分一致、複数の出現、乱数）で確かめ、新しいメッセージが拒むすべての場合を正しく言い表すことを確かめた。メッセージの文字列に依存する処理（再試行の判定、MCP の応答、wiki の取り込み手順）もないことを確かめた。依存が入っていないので、試験は流していない

## 指摘と対応

| 指摘 | 重大度 | 対応 |
| --- | --- | --- |
| wiki の `concepts/pdfのヘッダーの条件` の表の「`%PDF-` が先頭から 1024 バイトの範囲で始まる」は、開始位置 1024 を含まないようにも読める | 軽微（今回の差分の外） | 「`%PDF-` の前にあるバイトが 1024 バイト以下」に直した。同じ書き方だった `sources/pdfのヘッダーの判定の修正-rag-0.5.1` も直した |
| 新しいメッセージ全体を確かめる試験が、開始位置 1025 の場合だけ。ヘッダーがまったくない入力の試験は `%PDF-` の有無しか見ない | 軽微 | `test_file_that_is_not_a_pdf_is_rejected_when_read` の正規表現を、新しいメッセージの肝心な部分に合わせた |
| 前の版で失敗したジョブの `error` は、更新しても前のメッセージのまま返る（`retry_job` で消える） | 崩れる前提 | 今回の変更は保存済みの記録を書き換えないので、そのままにした |

## 確かめたこと

- `tests/rag/test_jobs.py` の 33 件が通った（Python 3.12、CI と同じ依存）。
- `git grep` で、rag と親（`docs/agent-runs/` と `docs/research/` の過去の記録を除く）に、前のメッセージと「先頭から 1024 バイトの範囲」の書き方が残っていないことを確かめた。
