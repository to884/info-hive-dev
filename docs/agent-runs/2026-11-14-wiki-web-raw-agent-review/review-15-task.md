# 依頼: 証拠を読み切れたかを確かめるようにした、確かめのスクリプトの敵対的レビュー

## 背景

`tests/wiki/check_web_raw_agent.py` は、wiki プラグインの URL の取り込みのセッションの記録（Claude Code の JSONL）から、分担を確かめる開発用のスクリプトである。確かめる分担は、raw の段（W1〜W8）を Sonnet のエージェント `wiki:web-raw` が行い、後段をメインのモデルが行うことである。

14 回目のレビュー（`review-14.md`、却下）の指摘は、先に `root-causes-14.md` のとおりに直した（JSONL を LF だけで分け、読めない行があれば不合格）。そのあと、同じ指摘について Sol に独立に考えてもらった修正案（`fix-proposal-14/proposal.md`）と、先の修正を総括した（`fix-proposal-14/synthesis.md`）。総括で採った穴を、この PR（to884/info-hive-dev#123）で直した。

決まりは「読めた回に違反がないことと、要る回をすべて読めたことを分ける。読めないものは、違反があったとは決めず、違反がないとは言えないとして不合格にする」である。

- 記録の行は、UTF-8 と JSON として読み、オブジェクトでない行も読めないものとして数える。エージェントのメタデータ（`agent-*.meta.json`、`agent-*.prefix.json`）が、ないか読めないときも数える。1 つでもあれば「セッションの記録のすべての行と、エージェントのメタデータを読めた」が不合格になる。
- `check --finish` の呼び出しの結果がないときと、行の頭から始まる check の JSON の候補を読めないときは、「check --finish の呼び出しの結果と、check の JSON をすべて読めた」が不合格になる。

実際の取り込みの記録 4 件は、すべて読めた（21/21、21/21、19/20、21/21。19/20 は、W8 を文字の出力で終えた 0.16.1 の版）。

## 確かめのスクリプトが主張する範囲（変えていない）

前提は次の 3 つである。手順に従って動いたセッションの記録であること（わざと隠したものと見せかけは見つけない）、空のフォルダーから始めた取り込みであること、1 回の確かめで取り込む URL は 1 つであること。

## 探してほしいこと

1. **読み切れたかの判定の穴。** 証拠が欠けているのに通る場面（欠けを見つける決まりの外にある欠け方）と、手順に従った取り込みを「判定できない」として落とす場面（Claude Code の正しい記録の形で、結果のない呼び出しや、行の頭から始まる読めない候補が出るもの）。
2. **check の JSON の候補の決まりの穴。** 行の頭の `{` と `"stage": "check"` の組み合わせで、本物の `--json` の出力を候補にしない場面と、本物でないものを読めない候補として数える場面。
3. **メタデータと記録の読み込みの穴。** 読めないものとして数えるべきものを数えない場面と、数えるべきでないもの（Claude Code が書く正しい記録の形）を数える場面。
4. **試験が見ていないために、上の欠陥が通ってしまうところ。**

範囲の外（前提の外の記録やプロジェクト、記録からは示せないこと）は、欠陥として挙げない。挙げるときは、範囲の外であることを書く。推測は推測と書く。挙動についての主張は、コードの行を根拠にする。
