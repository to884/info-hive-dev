# 依頼: 12 回目のレビューの指摘を直した版の、確かめのスクリプトの敵対的レビュー

## 背景

`tests/wiki/check_web_raw_agent.py` は、wiki プラグインの URL の取り込みのセッションの記録から、分担を確かめる開発用のスクリプトである。確かめる分担は、raw の段（W1〜W8）を Sonnet のエージェント `wiki:web-raw` が行い、後段をメインのモデルが行うことである。

12 回目のレビュー（`review-12.md`、却下）の重大な指摘は 2 件だった。どちらも、1 つの Bash の呼び出しの結果から check の回を読むところで起きた。これを `root-causes-12.md` のとおりに直した。

- **文字の出力の回:** 見出しの行から、`wiki_rawcheck.render` が書く形の行だけを読む。形は `render` そのものから作る（`check_text_forms`）。最後の行（写しを消した、残した）か、形に合わない行（freeze の出力、ほかのコマンドの出力、JSON）で回が終わる。
- **失敗した呼び出し:** check `--finish` の呼び出しは、結果が誤り（`is_error`）でも中の回を読む。回が通ったかは、回の出力で決める。
- **同じ時刻での担当の順:** 鍵は変えず、説明に書いた。

実際の取り込みの記録 3 件は、18/18、18/18、17/17 で通った。

## 確かめのスクリプトが主張する範囲（変えていない）

スクリプトの説明の「前提」「合否を決めるもの」「合否を決めないもの」に書いてある。前提は次の 3 つである。

- 手順に従って動いたセッションの記録であること。わざと隠したものと見せかけは見つけない。
- 空のフォルダーから始めた取り込みであること。
- 1 回の確かめで取り込む URL は 1 つであること。

## 探してほしいこと

1. **`render` の形で回を読むことの穴。**
   - `render` が書く行の形と、`check_text_forms` が作る形が食い違う場面（警告や誤りの文の中の改行、行の番号、取得と raw の行）。
   - 回の中にほかの行が入る場面と、回が早く終わりすぎて、写しを消したことや警告を見落とす場面。
2. **失敗した呼び出しを読むことの穴。**
   - 結果が誤りのときの、Claude Code の道具の結果の形（標準出力と標準エラーの並び、終了コードの行）で、回を取り違える場面。
   - 失敗した呼び出しを読むようになったことで、手順に従った取り込みを落とす場面と、範囲の中の違反を通す場面。
3. **試験が見ていないために、上の欠陥が通ってしまうところ。**

範囲の外（前提の外の記録やプロジェクト、記録からは示せないこと）は、欠陥として挙げない。挙げるときは、範囲の外であることを書く。推測は推測と書く。スクリプトの挙動についての主張は、コードの行を根拠にする。
