# 12 回目のレビューの指摘の原因と直し方

対象: 11 回目の指摘を直した確かめのスクリプト（`tests/wiki/check_web_raw_agent.py`）。判定は却下（確信度は高）。重大は 2 件で、どちらも、1 つの Bash の呼び出しの結果から check の回を読むところで起きた。プラグインの手順は対象にしていない（9 回目から崩されていない）。

## 根の原因

check の回を、回の出力の外にある手がかりで区切り、決めていた。

- 文字の出力の回の終わりを、「次の check の始まり」で決めていた。間に freeze やほかのコマンドの出力が入ると、その行も前の check の回に入った（指摘 1）。
- 回が成り立ったかを、呼び出し全体の誤り（`is_error`）で決めていた。`is_error` は、呼び出しの中の最後のコマンドの終了コードで決まる。その前に終えた check の出力とは関係がない（指摘 2）。

どちらも、回の出力そのものが持つ情報で決められる。`wiki_rawcheck.render` が書く行の形と、回の中の「写しを消した」の行である。

## 直し方

| 指摘 | 直し方 |
| --- | --- |
| 1. 後続の freeze の警告を、完了済みの check の警告として扱う | 文字の出力の回は、見出しの行から、`render` が書く形の行だけを読む。形は `render` そのものから作る（`check_text_forms`。文言が変わってもずれない）。最後の行（写しを消した、残した）か、形に合わない行（freeze の出力、ほかのコマンドの出力、JSON）で回が終わる。`render` は 1 回の `print` で書くので、回の中にほかの行は入らない |
| 2. 呼び出し全体が失敗すると、先に成立した完了と禁止行為まで捨てる | check `--finish` の呼び出しは、結果が誤りでも中の回を読む。回が通ったかは、回の出力で決める |
| 軽微: 同じ時刻での担当の順 | 鍵は変えない。担当をまたぐ前後は時刻でしか決まらない。時刻が同じか欠けたときは、エージェントの回をあとにする。このことを説明に書いた |
| 軽微: 試験 | 12 回目の反例 2 件の試験（`test_review12_counterexamples`）と、回の分け方の単体の試験（freeze の行、CRLF、誤りの回の取得と raw の行）を足した。時刻の試験の説明を、確かめている中身（結果の中の位置）に合わせ、別の呼び出しの順の試験を足した |

新しい試験は、前の版のスクリプトでは落ちることを確かめた。前の版では、1 件目の反例（freeze の警告）で落ちた。`check_runs` だけを新しくした版では、2 件目の反例（失敗した呼び出しの中の、警告の受け入れ）を見落として落ちた。

## 確かめ直した結果

- 実際の取り込みの記録 3 件は、18/18、18/18、17/17 で通った（前と同じ）。
- 親のリポジトリの試験 16 種は、すべて通った。
