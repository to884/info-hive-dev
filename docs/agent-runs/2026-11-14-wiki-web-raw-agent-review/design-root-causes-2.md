# 設計の 2 回目のレビューの指摘の、原因の構造による分類

対象: 設計の 2 版。レビュー: [design-review-2.md](design-review-2.md)（GPT-6.1 Sol、effort high、却下）。前の分類は [design-root-causes-1.md](design-root-causes-1.md)。

2 版は、1 版の指摘に対して、仕組みを足して答えた。2 回目の指摘を出どころで分けると、足したものが新しい欠陥を生み、残りの多くは、この変更が起こしたものでも、どの設計でも保証できないものでもなかった。3 版では、足したものを削り、主張を狭めた。

| 出どころ | 指摘 | 3 版での扱い |
| --- | --- | --- |
| 2 版で足したもの | 重大 1（メインが `check` をやり直すとき、エージェントが付けた `--language-override` を付けず、正しい raw を拒む） | `done` では、メインは `check` をやり直さない（raw があること、`url` が同じこと、作業用のフォルダーがないことだけを確かめる）。`warnings` で `check` を実行するときは、報告の `language_override`（専用の欄）を付ける |
| 2 版で足したもの | 重大 2 の半分（`--finish` を log のあとに移したので、`frozen` が「raw ができた直後」「ページを一部更新したあと」「log のあと」の 3 つを区別しない） | `--finish` を W8 のエージェントの段に戻した（0.14.0 と 2 回の試行と同じ）。エージェントは `--accept-warnings` を付けず、直さない警告が残るときだけ写しが残る |
| 2 版で足したもの | 重大 4（`changes` の合成の決まりがない） | 汎用の差分をやめ、問いの 3 つの種類ごとに、呼び出す側が変える依頼の欄を表で決めた |
| 0.14.0 からある問題 | 重大 2 の残り（`--html-file` で取得した取り込みを、URL だけで取り直すと、写しを見る前に終了コード 3 で止まる。条件と理由が会話の外に残らない） | この変更では扱わない。0.14.0 の `main` で再現し（`--html-file` のあと URL だけで取り直すと `existing_differs`）、限界に書いた。取り込みの状態をスクリプトが作業用のフォルダーに書く形は、別の変更として考える |
| どの設計でも保証できない主張 | 重大 3（前の途中の取り込みで別のモデルが訳した raw を、Sonnet が検査だけして通すと、Sonnet が作ったと記録する）、重大 6（文を考えたモデルの分担違反を、試験が通す）、軽微（モデルの ID は自己申告） | 作者の主張をやめた。log のサブ行は分担の記録とし、訳と補足の名前は raw から取る。raw の名前に Sonnet がなければユーザーに伝える。試験が確かめるのは、記録の応答のモデルと道具の使い方までで、文を考えたモデルは証明しないと書いた |
| 分けることそのもの | 重大 5（呼び出す側に Agent ツールがないと、プラグインがあっても、呼び出す側が自分で raw を作る） | 代わりの手順の条件を「使えるエージェントの種類に `wiki:web-raw` がない」の 1 つにし、呼び出す側に Agent ツールがない場合も含むことを、限界に書いた |

軽微な指摘:

| 指摘 | 3 版での扱い |
| --- | --- |
| 警告の `(kind, line)` は一意でない | `warnings` の照らし合わせを、`kind`、`line`、`message` の並び（出た順）にした |
| `model_unknown` に答える道がない | `needs_user` の種類から外し、`failed`（`model_unknown`）にした |
| エージェントが決めたスラッグを、呼び直しで保つ手順がない | 呼び出す側が、報告の `slug` を依頼の `slug` にする、と書いた |
| モデルの ID の照合を、独立の確かめと書いていた | 自己申告の目安と書き直した |
