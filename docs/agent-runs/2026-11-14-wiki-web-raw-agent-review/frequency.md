# 11〜15 回目のレビューの指摘の条件が、実際の記録で起きたか

確かめのスクリプトへの 11〜15 回目の敵対的レビューで挙がった重大な指摘について、その条件が、実際の取り込みの記録 4 件（`trial-cqrs.json`、`trial-bloom.json`、`trial-0161-cqrs.json`、`trial-0181-cqrs.json`）で起きたかを数えた（2026-11-15）。数え方は `frequency.py` にある（`python -X utf8 frequency.py <リポジトリのルート>`）。

## 数えた結果

W8 の呼び出しは、4 件で合わせて 4 回だった。

| 数えたこと | 結果 | 関係する回 |
| --- | --- | --- |
| W8 を、ほかのコマンド（Python のスクリプトなど）と 1 つの Bash の呼び出しにまとめた | 4 回中 4 回 | 11、12、15 の前提 |
| 1 つの結果に check の出力が 2 回以上ある | 0 回 | 11、12 |
| W8 の呼び出しの結果が誤り | 0 回 | 12 |
| 行の途中から始まる check の JSON | 0 回 | 15 の 1 |
| 記録の中の U+2028、U+2029、U+0085 | 0 文字（約 970 行） | 14 |
| 読めない行、agentId で結べないエージェントの記録 | 0 件 | 14、15 の 2 |

1 つの呼び出しにまとめることはふつうに起きたので、指摘の前提は現実にある。そのうえで問題になる細かい条件は、どれも起きていない。4 件では少なすぎて、頻度を数字にはできない。

## 指摘ごとの起きやすさ（推測）

| 回 | 起きる条件 | 起きやすさ |
| --- | --- | --- |
| 11、12 | 1 つの呼び出しで check を何度か動かすか、freeze を挟むか、あとのコマンドが失敗する | 中くらい（まとめることは 4 回中 4 回あった） |
| 13 | ページのコードに、check の出力とそっくりな行がある | とても低い（info-hive 自身を説明するページくらい） |
| 14 | ページに U+2028 などがあり、警告の詳細に出る。違反を見逃すには、エージェントが禁止の `--accept-warnings` も使う必要がある | とても低い |
| 15 の 1 | W8 の直前に、改行のない出力（`printf` など）がある | 低い |
| 15 の 2 | 起動したエージェントの記録のファイルがない | とても低い（Claude Code が落ちる、記録を集め損ねる、など） |

どの指摘も、起きたときの影響は開発用の確かめのスクリプトの合否の誤りで、利用者の wiki は壊れない（7 回目の手順の穴は除く。0.18.1 で直した）。

## 判断

11 回目から、指摘の条件はだんだん細かくなった。残っている穴が、まれな場面に移ってきたと読める。作者の判断で、15 回目の指摘を直した版（to884/info-hive-dev#123）を、16 回目のレビューをせずにマージした。
