# 11 回目のレビューの指摘の原因と直し方

対象: 10 回目の指摘を直した確かめのスクリプト（`tests/wiki/check_web_raw_agent.py`）。判定は却下（確信度は高）。重大は 3 件で、どれも、1 つの Bash の呼び出しで `check --finish` を何度か動かしたときに起きた。プラグインの手順は対象にしていない（9 回目から崩されていない）。

## 根の原因

1 つの道具の結果を「1 回の W8」として扱っていた。1 つの呼び出しで、検査、直す、再検査（取り直してもう一度）を続けることはある。その結果には check の出力が何回分も入る。10 回目の `finish_result` は、次のように読んでいた。

- 文字の出力は、全体から警告と「消した」を別々に探した。
- JSON は、写しを消した最後のものだけを返した。
- JSON があれば、あとの文字の出力を見なかった。

## 直し方

`check_runs` が、1 つの結果の中の check の出力を、出た順の 1 回ずつに分ける。分け方は次のとおりである。

- JSON の回は、その値で決める。
- 文字の出力の回は、`check: ` で始まる行から、次の回の始まりまでとする（`wiki_rawcheck.render` の形）。

回ごとに、写しを消したか（`removed`）と、警告が残ったまま消したか（`accepted`。`--accept-warnings` を付けたときだけ起きる）を決める。

| 指摘 | 直し方 |
| --- | --- |
| 1. 文字の出力で、前の回の警告を最後の回に混ぜる | 回ごとに警告を見る。警告で写しを残した回と、直して警告なしで消した回は、別の回になる |
| 2. 最後の正しい回が、前の回の禁止された警告の受け入れを消す | 違反は、エージェントのどの回でも見る。あとで取り直して正しく終えても消えない |
| 3. 最後の回が文字の出力でも、前の回の JSON を最後の結果にする | W8 の終わりは、写しを消した回のうち、時刻、担当、記録の順、結果の中の位置で最後の回とする。表示名は、その回が JSON のときだけ判定する（前の回の JSON は使わない） |
| 軽微: 時刻のない記録、同じ時刻 | 並べる鍵に、記録の順と結果の中の位置を足した |

試験に、それぞれの反例を足した。

## 確かめ直した結果

実際の取り込みの記録 3 件は、18/18、18/18、17/17 で通った（前と同じ）。
