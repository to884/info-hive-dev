# 依頼: 13 回目のレビューの指摘を直した版の、プラグインの出力と手順、確かめのスクリプトの敵対的レビュー

## 背景

`tests/wiki/check_web_raw_agent.py` は、wiki プラグインの URL の取り込みのセッションの記録から、分担を確かめる開発用のスクリプトである。確かめる分担は、raw の段（W1〜W8）を Sonnet のエージェント `wiki:web-raw` が行い、後段をメインのモデルが行うことである。

13 回目のレビュー（`review-13.md`、却下）の重大な指摘は 1 件だった。check の誤りの詳細が出したコードの本文の中の、check の出力の形の行を、別の回として数えた。11 回目から 13 回目の指摘は、check の文字の出力から回を組み立て直すこと（その出力にはページの本文がそのまま出る）から来ていた。`root-causes-13.md` のとおりに、3 か所を直した。

- **b（プラグイン、0.18.1）:** `wiki_rawcheck.render` は、項目の値の中の改行のあとの行を `CONTINUATION` で字下げする。
- **c（プラグインの手順、0.18.1）:** W8 は `check --finish --json` で動かす。
- **c（確かめ）:** W8 の終わり（写しを消した最後の回）は JSON の回でなければならない。JSON の回は、行の頭の `{` から始まるものだけにする。文字の出力の回は、違反（警告の受け入れ）を見つけるためだけに読む。
- **a（確かめ）:** raw のファイルに、確かめが読むスクリプトの出力の形の文字列があれば、判定できないとして不合格にする（`output_shapes`）。

実際の取り込みの記録は、CQRS とブルームフィルタ（`--json` で W8 を動かした版）が 19/19 で通った。0.16.1 の版の CQRS は、W8 を文字の出力で終えたので 17/18 になった。新しい手順の版（0.18.1）で、CQRS を取り込み直した（`trial-0181-cqrs.json`）。

## 確かめのスクリプトが主張する範囲

スクリプトの説明の「前提」「合否を決めるもの」「合否を決めないもの」に書いてある。前提は次の 3 つである（変えていない）。

- 手順に従って動いたセッションの記録であること。わざと隠したものと見せかけは見つけない。
- 空のフォルダーから始めた取り込みであること。
- 1 回の確かめで取り込む URL は 1 つであること。

「合否を決めるもの」に、「結果の形で読めること」（raw に出力の形の文字列がないこと）を足した。

## 探してほしいこと

1. **字下げの穴（b）。** `render` のどこかの出力で、ページから来る文字列が、字下げされずに行の頭に出る場面。`str.splitlines` と、確かめの側の `split("\n")` の食い違い。freeze の出力も含む。
2. **JSON だけで W8 を決めることの穴（c）。** 手順に従った取り込みを落とす場面（警告を受け入れる流れ、`--language-override`、結果が誤りの呼び出しなど）と、範囲の中の違反を通す場面。行の頭の `{` の決まりが、本物の `--json` の出力を落とす場面（Claude Code の道具の結果の形、CRLF）。
3. **判定できないことの穴（a）。** 本文の出力の形の文字列を見落として偽の回を数える場面と、ふつうのページを判定できないとして落としすぎる場面。raw にない本文（雑音として消したもの）が結果に出る場面は、範囲の内か外かを書く。
4. **手順の変更（c）が、エージェントと呼び出す側の流れを壊すところ。** W8 の直さない警告、呼び出す側の `warnings` の扱い、自分で W1〜W8 を行うとき。
5. **試験が見ていないために、上の欠陥が通ってしまうところ。**

範囲の外（前提の外の記録やプロジェクト、記録からは示せないこと）は、欠陥として挙げない。挙げるときは、範囲の外であることを書く。推測は推測と書く。挙動についての主張は、コードの行を根拠にする。
