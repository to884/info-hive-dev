# 8 回目のレビューの指摘の原因と直し方

対象: 7 回目の指摘を直した版。依頼で、確かめのスクリプトが主張する範囲（あったことの証拠だけを合否にする）を示した。判定は却下（確信度は高）。重大の 5 件は、どれも範囲の中の欠陥で、すべて確かめのスクリプトにあった。プラグインの手順は、軽微の 1 件だけだった（「崩せなかった点」に、W3 に戻る決まりと承認の照らし合わせが挙がった）。

## 確かめのスクリプト

| 指摘 | 原因 | 直し方 |
| --- | --- | --- |
| 1. 別の応答が同じ文を返すと、モデルが違っても重複として捨てる | 文の部品を、中身だけで重ねていた | 文の部品は、応答の id（なければ記録の uuid）とモデルと中身がすべて同じときだけ重ねる。直すと、要求の写しの記録（`api-request-blob`。モデルを持たない）が応答に数えられ、前の実際の記録 2 件が落ちた。会話の記録（`type` が `assistant` と `user`）だけを読むようにした |
| 2. `bash_to_review` が 300 文字で切れる | 表示の都合で切り詰めていた | 人が読む証拠なので、切り詰めない（`other_script_runs` も） |
| 3. `notindex.md` への書き込みで、索引を書いたことになる | 名前の末尾だけで見ていた | Edit と Write は wiki の `index.md` と `log.md` のパスそのものと比べる。Bash のリダイレクトは、cd のあとの相対パスでも書くので、ファイルの名前が同じかで見る |
| 4. 行の継続で分けた W8 が不合格になる | `check` と `--finish` の間に改行を許さなかった | 1 つのコマンドの中（`\` と PowerShell の `` ` `` による行の継続は越え、`;`、`&`、`|`、ふつうの改行は越えない）を許す |
| 5. 表示名が Sonnet かを合否にしていない | 値を出すだけだった | 訳したなら `translated_by` と補足の表示名に Sonnet があることを合否にする（訳さないページの空の値と、画像がないときはよい） |
| 軽微: エージェントの `--accept-warnings` を拒まない | W8 の終わり方の形だけを見ていた | エージェントのコマンドに `--accept-warnings` が見えれば不合格にし、W8 の証拠にもしない |

試験に、それぞれの反例を作り物の記録で足した。直したスクリプトで、実際の取り込みの記録 3 件（0.15.0 より前の版の 2 件と、0.16.1 の版の CQRS）を確かめ直し、どれも 17/17 で通った。

## プラグインの手順（軽微）

- 指摘: 「`wiki_fetch.py` を実行したら W3 に戻る」の決まりと、途中の写しから続けるとき（`work_stage` が `frozen` なら W5 の確かめのあとに W6）が、字義どおりにはどちらにも当たる。
- 直し方: 決まりを、ページを取り直して写しを作り直したとき（出力が `"unchanged": false`）に限った。途中の写しから続けるとき（`"work_dir": true`）は取り直しではないので、段ごとの続け方に従う。
