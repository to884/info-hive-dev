## 判定

**却下。確信度：高。** 限定された検証範囲の中でも、モデル違反や索引の更新漏れを合格にし、正常な W8 を不合格にする反例がある。`bash_to_review` もコマンド全文を保持していない。

## 致命的・重大な欠陥

### 1. 【重大】同じ本文の応答は、モデルが違っても重複として捨てる

`events()` の重複判定は、テキスト部品の内容を使い、応答の `message.id` と `model` を含めない。別の応答でも、同じ文なら後から来た方が消える。

反例として、正常な実記録のサブエージェントに、異なるメッセージ ID を持つ次の応答をメモリ上で追加した。

```text
応答A: model=claude-sonnet-5-5、text="Review check complete."
応答B: model=claude-opus-5-5、text="Review check complete."
```

**15/15、`ok: true`、`agent_models: ["claude-sonnet-5-5"]` になった。** 応答Bのモデルを空にしても同じ結果だった。「すべての応答のモデルを調べ、欠落も不合格にする」という主張に反する。

根拠：`tests/wiki/check_web_raw_agent.py` の108〜112行の重複排除、293〜304行の排除後のモデル検査。

### 2. 【重大】`bash_to_review` は300文字以降を捨てる

一覧へ入れるコマンドを `c[:300]` に切り詰めている。長いコマンドでは、書き込み処理そのものが一覧から落ちる。

これは意図的な隠蔽を仮定しなくても、対象の実記録で発生していた。

- `trial-bloom.json` のセッションには、755文字のメインのコマンドがある。
- 一覧に残るのは先頭300文字だけで、後半455文字が失われる。
- 失われる部分には `open(...).write(...)`、`log.md` への追記、後続の検査が含まれる。

**「全コマンドを人が読んで確認する」という、合否判定を狭めた後の確認経路が成立していない。** 自動で不合格にしないことではなく、手動確認用の証拠が欠落することが欠陥である。

根拠：`tests/wiki/check_web_raw_agent.py` の390〜396行。`other_script_runs` も325行で同様に切り詰める。既存試験も `c[:300]` を期待しているため、この欠落を検出しない（`tests/wiki/test_web_raw_agent.py` の473〜487行）。

### 3. 【重大】`wiki/index.md` を更新していなくても、別ファイルへの書き込みで合格する

索引とログの書き込み判定は、対象の絶対パスを照合せず、末尾が `index.md`・`log.md` かだけを見る。

正常な合成記録の `wiki/index.md` への編集を、次の成功した書き込みに置き換えた。

```text
Write <project>/wiki/notindex.md
```

本来の `wiki/index.md` を更新しなくても、**15/15、`ok: true`** になった。`notindex.md` も `index.md` で終わるためである。

空のフォルダーから始めても成立する。初期化で生成された索引が残り、その後に別ファイルを誤って更新するだけでよく、過去の取り込みや隠した操作は必要ない。

根拠：`tests/wiki/check_web_raw_agent.py` の349〜356行。初期化時の索引・ログの生成は `info-hive-wiki/skills/info-hive/scripts/init_wiki.py` の241〜243行。

### 4. 【重大】通常の行継続を使った W8 が不合格になる

次のように、長いコマンドを Bash の行継続で分けるだけで、W8 の証拠として認められなくなる。

```bash
python ".../wiki_rawcheck.py" check \
  --wiki "..." --raw-root "..." --slug cqrs --finish
```

`FINISH_CMD_RE` の `check\b[^\n]*--finish\b` が、`check` と `--finish` の間の改行を許さない。

正常な合成記録で、W8 のコマンドだけをこの形式に変更し、成功結果との対応を維持すると、**14/15、W8 の項目だけ不合格、`w8_finished_by: []`** になった。処理の順序も担当も変えておらず、隠蔽でもない。

根拠：`tests/wiki/check_web_raw_agent.py` の247行、328〜339行。既存の W8 試験は単一行のコマンドだけを使う（`tests/wiki/test_web_raw_agent.py` の373〜398行）。

### 5. 【重大】訳者名・補足の表示名を合否に使っていない

説明では、raw の `translated_by` と補足の表示名を合否の対象に含めている。しかし実装は値を抽出して返すだけで、Sonnet かどうかを検査していない。

正常な合成記録の raw について、次の値だけを変更した。

```yaml
translated_by: "Claude Opus 5.5"
```

結果は **15/15、`ok: true`、`translated_by: "Claude Opus 5.5"`** だった。

下位の `wiki_rawcheck.py` も、訳者名が空でないことと補足名との一致は見るが、Sonnet であることは検査しない。このため、W8 の成功を根拠に補うこともできない。

根拠：

- `tests/wiki/check_web_raw_agent.py` の34行、380〜399行。
- `info-hive-wiki/skills/info-hive/scripts/wiki_rawcheck.py` の1010〜1015行、1035〜1038行。
- 呼び出す側に非 Sonnet の表示名の確認を要求する手順は、`info-hive-wiki/skills/info-hive/references/web-raw.md` の47行。

## 崩れる前提

| 暗黙の前提 | 崩れる条件 |
|---|---|
| 同じテキスト部品は同じ応答の重複である | 別の応答が同じ短文を返す。異なるモデルやモデル欠落まで消える |
| コマンドの先頭300文字で手動確認できる | 長いパス、複数行の Python、ログの本文などで、実処理が後半に来る |
| `index.md` で終わる書き込み先は対象の索引である | `notindex.md`、別ディレクトリの `index.md` へ書く |
| 正常な W8 は `check` と `--finish` を同じ行に書く | 通常のシェルの行継続を使う |
| 表示名の適否は別の検査が保証する | `wiki_rawcheck.py` は任意の非空の訳者名を受け入れ、解析側も比較しない |

## 見落としと軽微な問題

- **【軽微】再開時に適用する規則の文面が衝突する。**  
  `references/web-raw.md` の109行は「どの段で `wiki_fetch.py` を実行したときも」W3を経てW4へ進むとする。一方、114行は `work_stage: frozen` ならW5の確認後にW6、翻訳済みならW8へ進むとする。`fetch_skipped: true` の再開でもスクリプト自体は実行するため、字義どおりには両方に該当する。  
  **推測：** 前者を優先して翻訳済み raw に再度 `freeze` をかければ、翻訳と訳者名の変更が削除規則に反して止まる。実モデルがこの分岐を選ぶかは未確認であり、重大な反例には数えない。`freeze` 側の根拠は `wiki_rawcheck.py` の678〜682行、716〜718行。

- **【軽微】警告をエージェント自身が受け入れる経路も試験されていない。**  
  エージェントの W8 を `--finish --accept-warnings` にし、警告を含む成功結果を対応させても15/15だった。`agents/web-raw.md` の28行は禁止しているが、解析側の328〜339行はこの引数を拒否しない。

- 表示名の不一致、同文の別応答、索引の誤った書き込み先は、既存試験に反例がない。モデル欠落の試験は全応答のモデルを空にするため、重複排除で一部だけ消えるケースを捉えない（`test_web_raw_agent.py` の447〜471行）。
