# 14 回目のレビューの指摘の原因と直し方

対象: 13 回目の指摘を直したプラグインの出力と手順（0.18.1）と、確かめのスクリプト（`tests/wiki/check_web_raw_agent.py`）。判定は却下（確信度は高）。重大は 1 件で、確かめのスクリプトの記録の読み込みにあった。プラグインの `render` の字下げは、11 種類の改行と行の区切りの文字で攻められても崩れなかった。

## 根の原因

記録の読み込みで、2 つの前提を置いていた。

- `str.splitlines()` の 1 つずつが、JSONL の 1 件の記録である。実際の区切りは LF だけである。JSON の文字列の中には、U+2028、U+2029、U+0085 がエスケープされずに入りうる（Claude Code の記録を書く `JSON.stringify` はエスケープしない）。ページの原文の行の区切りの文字は、check の警告の詳細を通って、道具の結果の記録に入る。
- 読めない行を黙って捨てても、判定に要る証拠は残る。実際には、捨てた行が警告の受け入れの回や、W8 の最後の回であることがある。

13 回目に「判定できないことを、通したことにしない」と決めたが、記録の読み込みには当てていなかった。

## 直し方

| 指摘 | 直し方 |
| --- | --- |
| 重大 1. `read_jsonl()` が JSON の文字列の中で記録を切り、違反の証拠を黙って捨てる | 記録は LF だけで分け、JSON の空白（空白、タブ、CR）だけを除いて読む。読めない行は、ファイルと行の番号で数え、1 つでもあれば「セッションの記録のすべての行を JSON として読めた」を不合格にする |
| 軽微: `output_shapes()` が、読む形より広く拒む（`"final_url": ` だけで拒む） | 出力の形を (正規表現, 行の頭で始まるか) の並び（`FETCH_FORMS`、`FREEZE_FORMS`）で書き、結果を読む形（`FETCH_OUT`、`FREEZE_OUT`）と、本文の中を探す形を、同じ並びから作る。違うのは行の頭の決まりだけになる |
| 軽微: 正常な流れの試験の W8 のコマンドに `--json` がない | `good()` の W8 を `check --wiki wiki --raw-root raw --slug cqrs --finish --json` にした |
| 試験の穴: 行の区切りの文字を、外側の JSONL に入れて読み直していない | `test_review14_counterexamples` で、U+2028、U+2029、U+0085 を含む警告の受け入れの回と、`--reason` を、`ensure_ascii=False` の JSONL に書いて読み直す。読めない行を足した記録が不合格になることも試す |

新しい試験は、前の版のスクリプトでは 4 つの場面すべてで落ちることを確かめた。

雑音として消し、raw に残らない文が結果に出る場面は、レビューでも偽の回を作れなかった。0.18.1 のスクリプトの出力は値の改行のあとを字下げするので、そこから偽の回はできない。`output_shapes` が raw だけを見ることは、説明に書いた。

## 確かめ直した結果

- 実際の取り込みの記録 4 件は、すべての行を読めた。CQRS、ブルームフィルタ、0.18.1 の版の CQRS は 20/20 で通った。0.16.1 の版の CQRS は 18/19 で、W8 の項目だけが通らない（W8 を文字の出力で終えた）。
- 親のリポジトリの試験 16 種は、すべて通った。プラグインは、13 回目のあとから変えていない。
