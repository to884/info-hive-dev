# 15 回目のレビューの指摘の原因と直し方

対象: 14 回目の指摘への Sol の修正案との総括（`fix-proposal-14/synthesis.md`）で直した確かめのスクリプト（to884/info-hive-dev#123）。判定は却下（確信度は高）。重大は 2 件である。どちらも、総括で決めた「読めた回に違反がないことと、要る回をすべて読めたことを分ける」が、読む相手の一覧そのものに届いていなかった。

## 根の原因

「読めないものを数える」決まりを、見つけたものにしか当てていなかった。

- **check の JSON:** 行の頭の `{` から始まるものだけを候補にしていた（13 回目に、文字の出力の誤りの詳細の中の、ページの 1 行の JSON を数えないために足した決まり）。行の途中から始まる印は、候補にも読めない候補にもならず、黙って消えた。1 つの呼び出しの結果では、前のコマンドの改行のない出力（`printf 'check result: '` など）のあとに、本物の JSON が行の途中から続く（指摘 1）。
- **エージェントの記録:** 見つかった `agent-*.jsonl` を読めたかだけを見ていた。起動したエージェントの記録のファイルが丸ごとない、空である、ということは、見つかったものの一覧からは分からない。応答のモデルもエージェントをまとめて見ていたので、正しい一方が空の他方を補った（指摘 2）。

## 直し方

| 指摘 | 直し方 |
| --- | --- |
| 1. 直前の出力に改行がないと、本物の check の JSON を候補から外す | 行の頭の決まりをやめ、印（`"stage": "check"`）をどれも説明する形にした。印の前のいちばん近い `{` から check の結果として読めれば回にする。render の文字の出力（check と freeze）の値の行の中の印は、ページの値なので数えない（`render_blocks` が値の行の範囲を返す。freeze の行の形も `render` から作る）。それ以外の印は、読めない候補として「判定できない」にする。13 回目に行の頭の決まりで防いだもの（誤りの詳細の中の 1 行の JSON）は、値の行の範囲で防ぐ。ページの本文そのものの印は、前から `output_shapes` が判定できないとする |
| 2. 起動記録と記録のファイルを結ばず、丸ごとの欠落を見逃す | メインの wiki:web-raw の Agent の呼び出しを、その結果の `toolUseResult.agentId` で、記録のファイル `agent-<agentId>.jsonl` と結ぶ。結果に agentId がない、ファイルがない、wiki:web-raw の記録でない、応答がない、のどれかなら、「wiki:web-raw のすべての呼び出しに、応答のある記録がある」を不合格にする。起動に失敗した呼び出し（結果が誤り）は除く。実際の記録 4 件で、`toolUseResult.agentId` がファイルの名前と一致することを確かめた |
| 軽微: 印より前で切れた出力（`{"stage": "ch`） | 直していない。印がないと、check の出力の跡が残らない。Claude Code がこの位置で切る事例は確かめていない。限界として説明に書いた |
| 試験の穴: 切る位置、丸ごとの欠落、直前の出力 | `test_review15_counterexamples` を足した。改行のない前置きのあとの JSON（違反と、正しい W8 の終わりの両方）、freeze の値の中の 1 行の JSON、説明できない印（ソースを検索した結果）、記録のファイルがないエージェント、空の記録、起動に失敗した呼び出し、agentId のない結果を試す。前の版では落ちることを確かめた |

試験の道具 `got` に、記録の `toolUseResult` を書けるようにし、Agent の起動の結果（`launched`）が agentId を返すようにした。

## 確かめ直した結果

- 実際の取り込みの記録 4 件は、Agent の呼び出しと記録のファイルを agentId で結べた。CQRS、ブルームフィルタ、0.18.1 の版の CQRS は 22/22 で通った。0.16.1 の版の CQRS は 20/21 で、W8 の項目だけが通らない（W8 を文字の出力で終えた。前と同じ）。
- 親のリポジトリの試験 16 種は、すべて通った。
