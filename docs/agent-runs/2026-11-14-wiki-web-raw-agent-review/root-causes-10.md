# 10 回目のレビューの指摘の原因と直し方

対象: 9 回目の指摘を直した確かめのスクリプト（`tests/wiki/check_web_raw_agent.py`）。判定は却下（確信度は高）。重大は 6 件で、どれもこのスクリプトにあった。作者の判断で、1、2、3、5 を直し、4 と 6 は前提の外として説明に書いた。

## 直したもの

| 指摘 | 原因 | 直し方 |
| --- | --- | --- |
| 1. 初期の `index.md` と `log.md` の説明文の記入例（`[[消費税]]`、`] ingest |`）だけで通る | ファイル全体から文字の並びを探していた | 索引は、プラグインの `wiki_pages.extract_wikilinks` で読む（コードの中のリンクは数えない。記入例はインラインのコードの中にある）。ログは、`## [日付] ingest |` の見出しの項目に分け、その項目の中に「raw:」のサブ行があることを見る |
| 2. 規約で認められたパス付きのリンク（`[[sources/cqrs]]`）を落とす | ファイルの名前だけでリンクの文字を組み立てていた | プラグインの `wiki_pages.resolve_link` で、リンクを `sources/<スラッグ>` のページに解く（パス付き、別名、アンカーも読む）。あわせて、メインが書いた要約ページの**すべて**にリンクがあることを求める |
| 3. 1 つの呼び出しで check を 2 度動かすと、終わる前の結果から表示名を取る | 完了の判定と表示名の取り出しが、別々に結果を探していた | `finish_result` が、1 つの結果の中の check の JSON をすべて取り出し、検査が通って写しを消した最後のものを選ぶ。完了の判定と表示名は、同じ出力から取る。サブエージェントの記録は、ファイルの名前ではなく最初の記録の時刻の順に並べ、表示名は時刻で最後に終えた W8 から取る |
| 5. 検索と check を 1 つの呼び出しにまとめると、検索の文字を `--accept-warnings` と読む | コマンドの文字列でオプションを探していた | 出力で決める。警告が残ったまま写しを消した check の出力は、`--accept-warnings` を付けたときだけ出る（`wiki_rawcheck.main`）。エージェントのその出力を違反とし、メインのその出力を、警告を受け入れる流れの W8 とする。コマンドからオプションを探すことはやめた |

試験に、それぞれの反例を足した。実際の初期のひな形（`assets/index.md.template`、`log.md.template`）を使う試験も足した。

## 前提の外としたもの

- **4. いくつもの URL と取り直し:** 1 回の確かめでは、1 つの URL を取り込む（`run` はそうする）と前提に書いた。取り直しでエージェントを何度か呼んだときの順序の取り違えは、時刻の順に並べて直した（3）。いくつもの URL を同時に取り込んだ記録では、表示名は最後に終えた W8 の分だけを見る。
- **6. スクリプトの名前とサブコマンドを名前に含むファイルの cat:** 前提の「見せかけは見つけない」に入れた。

## 確かめ直した結果

実際の取り込みの記録 3 件は、18/18、18/18、17/17 で通った（9 回目のあとと同じ。3 件目は W8 を `--json` なしで動かしたので、表示名を判定していない）。
