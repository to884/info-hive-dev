# 依頼: 11 回目のレビューの指摘を直した版の、確かめのスクリプトの敵対的レビュー

## 背景

`tests/wiki/check_web_raw_agent.py` は、wiki プラグインの URL の取り込みのセッションの記録から、分担を確かめる開発用のスクリプトである。確かめる分担は、raw の段（W1〜W8）を Sonnet のエージェント `wiki:web-raw` が行い、後段をメインのモデルが行うことである。

11 回目のレビュー（`review-11.md`、却下）の重大な指摘は 3 件だった。どれも、1 つの Bash の呼び出しで `check --finish` を何度か動かしたときに起きた。これを `root-causes-11.md` のとおりに直した。

- **回の分け方:** `check_runs` が、1 つの結果の中の check の出力を、出た順の 1 回ずつに分ける。JSON の回と、`check: ` で始まる文字の出力の回である。回ごとに、写しを消したか（`removed`）と、警告が残ったまま消したか（`accepted`）を決める。
- **警告の受け入れの違反:** エージェントのどの回でも見る。
- **W8 の終わりと表示名:** W8 の終わりは、写しを消した回のうち、時刻、担当、記録の順、結果の中の位置で最後の回とする。表示名は、その回が JSON のときだけ判定する。

実際の取り込みの記録 3 件は、18/18、18/18、17/17 で通った。

## 確かめのスクリプトが主張する範囲（変えていない）

スクリプトの説明の「前提」「合否を決めるもの」「合否を決めないもの」に書いてある。前提は次の 3 つである。

- 手順に従って動いたセッションの記録であること。わざと隠したものと見せかけは見つけない。
- 空のフォルダーから始めた取り込みであること。
- 1 回の確かめで取り込む URL は 1 つであること。

## 探してほしいこと

1. **`check_runs` の分け方の穴。**
   - `render` の出力のほかの行（誤りの行、画像の行、`--finish` のない check の出力）が、回の境目や判定を狂わせる場面。
   - JSON と文字の出力が入り混じったとき（JSON の中の文字の並び、標準エラーの混ざり）。
2. **最後の回の選び方の穴。**
   - 時刻、担当、記録の順の組み合わせで、手順に従った取り込みを落とす場面と、範囲の中の違反を通す場面。
   - 警告を受け入れる流れ（呼び出す側が `--accept-warnings` で終える）を正しく通すか。
3. **試験が見ていないために、上の欠陥が通ってしまうところ。**

範囲の外（前提の外の記録やプロジェクト、記録からは示せないこと）は、欠陥として挙げない。挙げるときは、範囲の外であることを書く。推測は推測と書く。スクリプトの挙動についての主張は、コードの行を根拠にする。
