# 14 回目の指摘への修正案（Sol）と、行った修正の総括

14 回目のレビュー（`review-14.md`）の指摘について、GPT-6.1 Sol に、直す前の版（`check_web_raw_agent.before.py`、`test_web_raw_agent.before.py`）だけを渡して、独立に修正案を考えてもらった（`task.md`、`proposal.md`）。今の版、`root-causes-14.md`、それより後の git の履歴は読まないように頼んだ。その案を、先に行った修正（`root-causes-14.md`、to884/info-hive-dev#115 で main に入った）と照らした。

## 根の原因の見方

| | Sol の案 | 先に行った修正 |
| --- | --- | --- |
| 今回の原因 | JSON の文字列の中身と、JSONL の記録の区切りを取り違えた | 同じ |
| 11〜14 回目のつながり | どの回も、区切りを、その形が保証する単位に合わせていなかった（11: 結果の全体と 1 回の検査、12: 検査と後の出力、13: ページの本文と検査の出力、14: 文字列の中身と記録の区切り） | 「判定できないことを、通したことにしない」を、記録の読み込みに当てていなかった |
| 根の前提 | 読めた回に違反がないことと、要る回をすべて読めたことを、混同している | 読めない行を捨てても証拠は残る、と思っていた |

Sol の言い方のほうが広く、先の修正で残った穴まで説明できる。

## 指摘ごとの照らし合わせ

| 指摘 | Sol の案 | 先に行った修正 | 照らした結果 |
| --- | --- | --- | --- |
| 重大: 記録を `splitlines` で分ける | LF だけで分ける。読めない行は、ファイルと行の番号を付けて判定できないとする。サブエージェントの記録は 1 回だけ読む | 同じ | 一致 |
| 同: 結果のない呼び出し | `finish` の呼び出しに結果がなければ、欠けたことを記録して不合格にする | 黙って飛ばしていた | 穴が残っていた |
| 同: 読めない check の JSON | 「候補がない」と「候補を読めない」を分ける | 黙って飛ばしていた | 穴が残っていた |
| 軽微: `output_shapes` が広い | 出力の形を 1 か所で定め、結果を読む側と本文を探す側で使い回す | 同じ（`FETCH_FORMS`、`FREEZE_FORMS`） | 一致 |
| 軽微: 試験のコマンド | 引数をそろえ、実際の `main()` の出力を試験の結果にする | コマンドの文字列だけを直した | 先の修正が弱い |
| 試験の穴 | 実際の出力を、記録の JSONL まで通して読み直す。結果を補う試験の道具を、止められるようにする | 作った JSON を JSONL に通した。補う動きはそのまま | 先の修正が弱い |

採らない案（出す側を `ensure_ascii=True` にする、LF で分けるだけにする）は、Sol と同じ判断だった。前者は Claude Code の記録の書き方をこちらで決められず、後者は、別の理由で証拠が欠けると、また見逃す。

## Sol だけが挙げた、同じ種類の穴と、その扱い

| 穴 | 扱い | 理由 |
| --- | --- | --- |
| 行の頭から始まる check の JSON の候補を読めないと、黙って捨てる（出力が途中で切れた、など） | 採った | 警告の受け入れの回が消え、あとの正しい回で合格になる |
| 結果のない `finish` の呼び出し | 採った | 途中で止めたセッションなどで起きる。違反とは決めず、違反がないとは言えないとして不合格にする |
| メタデータの JSON を読めないと `{}` になり、担当を取り違える | 採った | 手間が小さい。理由の表示を正しくする |
| 記録の中の UTF-8 として読めない行、オブジェクトでない行で、落ちる | 採った | 落ちずに、判定できないとする |
| 結果の文の部品を空白でつなぎ、行の頭が消える | 保留 | Claude Code が部品をどう分けるかを確かめていない |
| 重複したキー、食い違う同じ id の記録 | 採らない | 正しい記録で起きる道筋が見当たらない |

## 行った修正（to884/info-hive-dev の `fix/web-raw-evidence`）

- `read_jsonl` は、行ごとに UTF-8 と JSON として読み、オブジェクトでない行も読めないものとして数える。`read_json`（メタデータ）は、ない、読めない、オブジェクトでない、を数える。どれか 1 つでもあれば、「セッションの記録のすべての行と、エージェントのメタデータを読めた」が不合格になる。
- `check_json_spans` は、行の頭から始まる候補を読めなければ、その位置を返す。`finish_runs` は、結果のない呼び出しと、読めない候補を `gaps` に出し、「check --finish の呼び出しの結果と、check の JSON をすべて読めた」が不合格になる。違反があったとは決めない。
- 試験の道具 `paired` に、結果を補わない呼び出しを指定できるようにした。試験を 2 つ足した。
  - `test_unreadable_evidence_is_not_a_pass`: 結果のない呼び出し、途中で切れた check の JSON、メタデータの欠けと破損、読めない行。前の版では、1 つ目の場面で落ちることを確かめた。
  - `test_real_rawcheck_output_through_jsonl`: 実際の `wiki_rawcheck.main()` で freeze と `check --finish --json` を動かし、`--reason` に U+2028 を入れ、その出力を記録の JSONL に通して読む。正しい流れが通ることの試験で、前の版でも通る。
