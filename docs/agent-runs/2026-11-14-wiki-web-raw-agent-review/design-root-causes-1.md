# 設計の 1 回目のレビューの指摘の、原因の構造による分類

対象: [wiki-web-raw-agent-2026-11-14.md](../../plans/wiki-web-raw-agent-2026-11-14.md) の 1 版。レビュー: [design-review-1.md](design-review-1.md)（GPT-6.1 Sol、effort high、却下）。

| 原因の構造 | 崩れた前提 | 指摘 | 直し方（2 版） |
| --- | --- | --- | --- |
| エージェントのモデルを、確かめずに前提にしていた | `model: sonnet` と、`model` の引数を渡さないことで、Sonnet が選ばれる | 重大 1（許可リストで親のモデルに戻る、フォールバックの連鎖で別のモデルになる） | エージェントが自分のモデルの名前と ID を報告し、メインが ID を確かめる。Sonnet でなければユーザーに聞く。途中でモデルが替わる場合は、限界に書く |
| 取り込みの状態を、呼び出しごとに消えるエージェントに置いていた | 呼び直しても、前の条件が残る | 重大 2（`needs_browser` のあとの `existing_differs` で、HTML のパスを失う） | 取得の条件と答えを「依頼」にまとめ、メインが持つ。呼び直すたびに依頼の全体を渡す。問いの答えは、依頼に足す差分（`changes`）で表す |
| 条件を渡す道がなかった | メインが読んだ規約や会話の条件を、エージェントも知っている | 重大 5（「英語のまま保存して」、`SCHEMA.md` の規則） | 依頼に `conditions` と `language` を置く。エージェントは最初に `SCHEMA.md` を読む。エージェントには `omitClaudeMd: true` でユーザーの指示を渡さず、条件の道を依頼の 1 つにする |
| 完了を、エージェントの報告だけで判断していた | `status: "done"` なら、検査を通り終えている | 重大 4（`work_dir_removed: false` の `done`、依頼と違う `slug` や `url`） | メインが、raw のファイル、frontmatter の `url`、依頼との一致を確かめ、`check --json` を自分で実行して、残った警告が受け入れたものと同じかを照らす。合わなければ止まる |
| 検査の基準を消すのが、記録を残すより先だった | 受け入れた警告の理由は、報告で確実に届く | 重大 3（報告の前の中断で理由を失う。話し合いでやめると log を書かない） | `check --finish` を、log を書いたあとのメインの段に移す。エージェントは `--finish` を付けない。エージェントを使わないときも同じ順にする。写しは「取り込みの途中」の印として残る |
| 実地の確かめが、結果だけを見ていた | Sonnet の応答と Opus の応答があり、raw とページができれば、分担どおりである | 重大 6（Sonnet が後段まで作る、メインが raw を書く実装も通る） | セッションの記録から、道具の呼び出し（どのファイルに書いたか、どのスクリプトを実行したか）を、メインとエージェントに分けて調べる |
| 代わりの手順の条件が広すぎた | エージェントを呼べなければ、メインが同じ手順を行える | 崩れる前提（入れ子の上限、同時の数の上限） | メインが代わりに行うのは、エージェントがないとき（プラグインの外、Claude Code ではない）だけにする。呼び出しの失敗では、ユーザーに聞く。ユーザーに聞けないときは止まる |
| raw を作ったモデルの記録を、訳した印で代えていた | `translated_by` で、raw を作ったモデルが分かる | 崩れる前提（日本語のページでは空） | log のサブ行に、raw を作ったもの（エージェントとモデル名、またはメインのモデル）を必ず書く |

軽微な指摘:

| 指摘 | 直し方 |
| --- | --- |
| 自然な言葉の依頼では、報告の扱い方の手順に届かない | 呼び出す側の手順も、スキルの参照文書（`references/web-raw.md`）に置く。コマンドとスキルの両方がそれを指す |
| 参照文書の中で `${CLAUDE_PLUGIN_ROOT}` を使うと、スキルの決まり（`<skill-root>`）に反する | 参照文書は `<skill-root>` で書き、エージェントの本文で `<skill-root>` の置き場所を書く。静的な試験で、参照文書に `${CLAUDE_PLUGIN_ROOT}` がないことを確かめる |
| 書いてよい範囲に、取得のスクリプトの一時のファイルが入っていない | 「raw の編集と、`wiki_fetch.py` と `wiki_rawcheck.py` が書くもの（一時のファイルを含む）」と書く |
| `failed` と `needs_user` の形が決まっていない | `question`（`kind`、`message`、`options[].label`、`options[].changes`）と `error`（`kind`、`message`）の形を決め、知らない `kind` と「やめる」の扱いを書いた |
| 速さと費用の根拠を、raw の段に当てはめていた | 比較の時間は取り込み全体のものだと書き直し、実地の確かめで測ることにした |
| 同時に呼ぶ数に上限がない | 3 つまでにした。上限で呼べなかったときは、メインが代わりに行わない |
| 別のセッションが同じスラッグを使うとぶつかる | この変更の前からある問題として、限界に書いた |
