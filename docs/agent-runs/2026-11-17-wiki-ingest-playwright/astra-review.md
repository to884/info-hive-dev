# Playwright による Web の取得の敵対的レビュー

2026-11-17。Claude の利用上限に達したため、利用者の指示で GPT-6 Astra（high）に設計と実装をレビューしてもらった。レビュー担当はファイルを変更していない。

## 設計のレビュー

- P1 の条件付きの指摘: Chromium はリダイレクトの最初の要求だけを interception する。`route.fetch(max_redirects=0)` の 3xx をそのまま `fulfill` すると、公開 A → 公開 B → 内部 C の後半の検査が抜ける。3xx はブラウザへ渡さず、主ページの転送先を一段ずつ検査し、空の 200 で遷移を終え、新しい `goto` で取得する方式にした。副リソースの転送は追わない。
- P2: 2 秒経過と本文の静止だけでは、4 秒後に表示する本文を待てない。500 文字未満なら期限まで待つ方式にした。
- P2: Playwright の `goto` は HTTP エラーを例外にしない。ブラウザ側の 403 などのエラーページは、文字数が多くても原文にしないようにした。

## 実装のレビュー

- P2: 雑音の表示文言だけで 500 文字を超えると、自動取得せず、規則で消したあとに raw が空になる。Astra が 760 文字の反例を再現した。本文の長さは `apply_block_rules` のあとで判定し、`--keep-noise` は尊重するようにした。
- P2: HTTP の最終 URL からブラウザで取得すると、最初の公開リダイレクトで発行される Cookie が欠ける。Astra は実 Chromium で、Cookie を使う公開の JavaScript API の反例を独立に確認した。ブラウザも必ず元の URL から取得するようにした。
- 修正後の最新差分に、未解決の P1・P2 の指摘はなかった。Astra は追加の単体試験 21 件の成功も確認した。

## 実機での確認

関連の単体・契約試験は 287 件を実行し、285 件が成功、2 件は既存の条件によってスキップした。元の作業ツリーへ今回の変更だけを統合したあと、Codex の対応を含む 75 件も成功した。作業用の worktree とローカルのブランチは削除した。変更はローカル版 0.30.0 として置いており、push・マージ・公開はしていない。

## OS の既定ブラウザを使う追加変更

利用者の追加指定は、固定のブラウザ名を設定する意味ではなく、OS で既定にしているブラウザを使う意味だった。Windows では `AssocQueryStringW` から元の URL の `http` または `https` の既定アプリの実行ファイルを得る。返された Chrome または Edge の実パスを起動し、転送中も同じブラウザを使う。既定の設定やプロファイルは変更しない。検出不能や未対応の既定では、別のブラウザへ切り替えず止まる。Windows 以外では `--browser chrome|msedge|chromium` の明示が必要である。

Astra は追加の設計と実装を読み、未解決の P1・P2 の指摘がないことを確認した。サイズ取得の `S_FALSE`、バッファ長、実行ファイルの検証、元 URL のプロトコルによる選択、再開時に検出しないこと、Chromium の明示時だけ導入することを確認した。追加後の単体試験 31 件の成功と、実 API が HTTP・HTTPS とも Edge の実パスを返すことを、Astra も確かめた。

実装担当は `WIKI_TEST_BROWSER=system` の Edge と、ブラウザを明示した Chromium で、それぞれ実機試験 7 件の成功を確認した。Codex を含む回帰試験は 311 件を実行し、309 件が成功、2 件は既存の条件によってスキップした。ブラウザ本体の選択を OS の設定に従わせる変更であり、普段のログイン情報は引き継がない。未公開の 0.30.0 に含めた。

## 普段のログイン状態を使う追加変更

利用者の追加指定を受け、既定は公式 Playwright 拡張で普段のブラウザに接続する `existing` にした。要求した URL に一致する許可済みの既存タブだけを読み、ページの移動や Cookie の書き出しはしない。従来の独立した取得は `isolated` として残した。

最初の設計は、MCP の汎用ツール実行で新しいタブを開き、ネットワークを代理処理するものだった。Astra は、MCP の console ログが本文や認証値をファイルに保存すること、既存 Service Worker を経由する通信をページの route だけでは止められないこと、拡張が Cookie の追加を拒むため代理取得で認証更新を失うことを指摘した。この設計は採らず、固定した Playwright の拡張接続部分だけを使って、既に表示済みのタブを読む構造にした。

実装レビューでは次の 4 件を直した。

- 診断用の環境変数を子に継承すると、protocol 応答の DOM をログに書きうる。`DEBUG`、`DEBUG_FILE`、Playwright の診断用変数、`NODE_OPTIONS` を渡さないようにした。
- Node と Python の URL の正規化が違い、既定ポートや末尾 `/` で正しいタブを拒んでいた。WHATWG URL による照合を Node に一本化し、結果を元の要求の文字列と結び付けて親が検査するようにした。
- `document.images` の先頭から読むと、本文外のアバターや重複画像が画像数の上限を消費する。共通の Python の本文変換器で対象 URL を選び、その画像だけを読むようにした。DOM は stdin で渡し、一時ファイルにしない。
- 標準出力を書き終える前の `process.exit` は POSIX の pipe で大きい結果を切り詰める。書き込み完了を待つようにし、2 MiB の結果を別プロセスで受ける試験を足した。

再確認で、Astra の未解決の重大・中程度の指摘はなくなった。Astra も単体試験 41 件と Node の契約試験 10 ケースの成功を確認した。実装担当の関連試験は 337 件を実行し、335 件が成功、2 件を既存の条件でスキップした。独立した Chromium の実機試験 7 件も成功した。

`tests/wiki/check_browser_session_live.py` の実 Edge の試験では、HttpOnly Cookie が必要なローカルの本文と画像を取り込めた。Cookie の値や本物のサービスの認証情報は出力していない。画面確認の Computer Use は現在の URL を十分な確度で取得できず停止したため、その後の UI 操作はせず、既に起動していた読み取り試験の結果で成功を確認した。後続の内部修正は単体・IPC・出力の試験で確認し、追加の実ブラウザ接続は行っていない。

対象ページがまだ描画途中の場合は、ブラウザで表示を待ってから取り込む。読み込めない画像や別 origin の画像などは未取得とし、匿名で別の画像を取り直さない。接続の実装は `playwright-core` 1.66.0-alpha-2026-11-09 の内部の実装への依存なので、更新時には版の確認と契約の試験が必要である。変更は引き続きローカル版 0.30.0 で、公開はしていない。

## 公開用の差分の確認

利用者のコミット・push・PR 作成・マージの指示を受け、公開済みの wiki 0.29.0 と親の main から専用の worktree を作った。別のセッションの翻訳修正（wiki #87、親 #171）は除外し、今回の Playwright の変更だけを切り出した。両プラグイン定義は 0.30.0、CHANGELOG の日付は 2026-11-17 とした。

Astra は、runtime 3 ファイルと新しい試験 4 ファイルがレビュー済みの内容と SHA-256 で一致すること、`wiki_rawcheck.py` の変更が再開用の 3 欄だけであること、翻訳の完了判定が混入していないことを確認した。切り出しによる欠陥や範囲外の変更の指摘はなかった。Astra の単体・文書契約試験 81 件と Node の契約試験 10 ケースが成功した。

実装担当も公開用の worktree で関連の試験 321 件を実行し、319 件が成功、2 件は既存の条件でスキップした。Node の契約試験 10 ケースと差分の空白検査も成功した。上の 337 件の記録は、別作業の翻訳修正を含んでいた元の作業ツリーでの結果であり、公開用の差分の試験数とは区別する。
