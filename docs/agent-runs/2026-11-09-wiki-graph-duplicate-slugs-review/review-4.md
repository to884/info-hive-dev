## 判定

**却下。確信度：高。** 関係の中身全体を ID に含めたことで、エッジ ID を相互参照する `contradicts` が壊れる。通常の重複項目の保持と出典の分類は、検証した入力では崩せなかった。

## 致命的・重大な欠陥

1. **重大：`contradicts` の循環参照では、参照を書き直すたびに参照先の ID が変わる。**

   次の手順で再現する。スラッグもノード ID も重複させる必要はない。

   1. `concepts/a.md` と `concepts/b.md` に、それぞれ通常の型付き関係を 1 件書いて抽出し、エッジ ID を A₀、B₀ とする。
   2. a の関係に `contradicts: B₀`、b の関係に `contradicts: A₀` を加える。
   3. 再抽出すると、ID が A₁、B₁ に変わる。出力の `contradicts` は B₀、A₀ のままなので、両方とも存在しないエッジを指す。
   4. 参照を B₁、A₁ に直すと、次の抽出で ID が再び変わる。

   本番の構築関数で反復し、毎回 2 件とも参照切れになることを確認した。`64acc43` では `contradicts` を追加しても ID が変わらず、同じ操作で両方の参照が成立した。

   原因は、`contradicts` 自体が `item`、`variant` を通じて自身の ID の計算に入ること。循環した参照を成立させるには、相互依存するハッシュの固定点を求める形になる。`CHANGELOG.md:36` の「作り直したあとの ID に直す」という移行手順では、このケースを復旧できない。

   根拠：

   - `skills/info-hive/scripts/wiki_graph_extract.py:441–457`：参照フィールドを含む項目全体を `variant` にする。
   - 同ファイル 332–354 行：`variant` を ID のハッシュに含める。
   - `skills/info-hive/references/graph-workflow.md:55`：`contradicts` にエッジ ID を書くことを認めている。

## 崩れる前提

- **「参照先のエッジ ID を書き直しても、その変更は参照先の ID に影響しない」**  
  エッジ間の参照が循環すると成立しない。今回の ID は参照フィールドにも依存する。

- **「項目全体は、JSON の `sort_keys=True` で必ず直列化できる」**  
  キーの文字列化は最上位だけである。入れ子の辞書に数値キーと文字列キーが混ざると成立しない。

- **「項目 1 つから必ず 1 本」は無条件ではない。**  
  実装は、目的語が曖昧な項目や、`predicate`／`object` が空の項目を引き続き除外する。性質 (a) は、その除外を適用した後の項目についてのみ成立する。

## 見落としと軽微な問題

1. **軽微：入れ子の拡張メタデータで、以前は抽出できた入力が例外になる。**

   通常の関係に次を加えると再現する。

   ```yaml
   extension:
     1: one
     label: two
   ```

   実際の YAML パーサーを通した後、`build_edges()` が次の例外で停止した。

   ```text
   TypeError: '<' not supported between instances of 'str' and 'int'
   ```

   `64acc43` は、この未知の拡張キーを無視してエッジを作った。今回の実装は ID のために項目全体を読むため、拡張フィールドを使う運用にも影響する。

   根拠：`wiki_graph_extract.py:442–443`。`_normalize_for_json()` の 539–540 行は、入れ子の辞書のキーを文字列化しない。

2. **軽微：「必ず 1 本」という文書の記述に例外がない。**

   `graph-workflow.md:27` と `CHANGELOG.md:21` は無条件に記述している。しかし、共有ノード ID を目的語にした項目は `wiki_graph_extract.py:431–435` で除外される。こちらは既存の契約に従う動作であり、追加された説明との不一致である。

3. **軽微：試験は今回の ID の循環依存を検証していない。**

   `test_graph_duplicate_slugs.py:385–400` は、通常の項目の保持と並べ替えを検証している。エッジ ID を含む `contradicts`／`supersedes` と、入れ子の拡張メタデータは対象にない。
