## 判定

**却下。確信度：高。** 省略値と空文字が混在すると、対象項目が再び 1 エッジにまとまり、性質 (a) を満たさない。また、番号で区別する項目の並べ替えは、既存のエッジ参照を別の項目へ黙って向ける。

## 致命的・重大な欠陥

1. **重大：番号付けとハッシュで空値の扱いが違い、2 項目が 1 本にまとまる。**

   同じページに次の関係を置く。`concept:y` は一意に存在するものとする。

   ```yaml
   graph:
     relationships:
       - predicate: depends_on
         object: concept:y
         evidence: proof
       - predicate: depends_on
         object: concept:y
         evidence: proof
         source: ""
   ```

   両方とも、今回明記された「predicate と object があり、目的語が曖昧でない」というエッジ化条件を満たす。しかし、実行結果は **2 本ではなく 1 本**だった。`evidence` の省略と空文字の組合せでも再現する。

   `same` の計算では `None` と `""` を別グループにするため、両方の `ordinal` が 0 になる。一方、`edge_id()` は両方を `""` に変換する。その結果、同じ ID になり、`push()` が後の項目を捨てる。

   根拠：`skills/info-hive/scripts/wiki_graph_extract.py:464–466`（番号付け）、340–341 行（空値の変換）、428–432 行（重複除去）。

   出典の欠落は lint の対象だが、抽出がその項目を残すという今回の条件とは両立していない。

2. **重大：`contradicts` だけが違う項目を並べ替えると、外部参照が別の項目を指す。**

   同じページに、ID に入る欄がすべて同じで、次の欄だけが違う 2 項目を置く。

   - 項目 A：`contradicts: concept:p`
   - 項目 B：`contradicts: concept:q`

   p、q は存在するノードとする。抽出後、別ページの関係に `supersedes: <A のエッジ ID>` を書く。その後、A と B の順序だけを交換して再抽出する。

   実行結果では、既存の参照 ID は残るが、その ID のエッジは **`concept:p` を指していた項目から、`concept:q` を指す項目へ変わった**。参照元のファイルには変更がなく、参照先 ID も存在するため、単なる参照切れより見つけにくい。

   依頼文で明示された ID の入れ替わりには、この影響がある。性質 (a) の本数は満たすが、**項目単位の ID の安定性とは両立しない**。エッジ ID を永続参照に使う既存機能に対しては重大と判断する。

   根拠：`wiki_graph_extract.py:345–348`（参照欄の除外）、464–478 行（出現順の番号）。エッジ ID を参照できる規約は `references/graph-workflow.md:55–56`。

## 崩れる前提

- **「番号付けで同じとみなす値と、ID 計算で同じとみなす値が一致する」**  
  `source`／`evidence` の `None` と空文字で崩れる。

- **「ID に入れない欄だけが違う項目は、順番で区別しても参照の意味を保てる」**  
  その項目を別のエッジから参照すると崩れる。ID 集合が変わらなくても、ID と項目の対応が変わる。

- **「構築処理で直列化できれば、成果物にも書き出せる」**  
  `_stable_json()` の例外処理は、SQLite／JSONL の出力処理には適用されない。

## 見落としと軽微な問題

1. **軽微：追加試験の混合キーの `notes` は、実際の抽出ではまだ停止する。**

   `test_graph_duplicate_slugs.py:437–443` が追加した次の値で確認した。

   ```yaml
   notes:
     2: two
     label: three
   ```

   `build_edges()` は通る。しかし、本番の SQLite 作成処理と JSONL 書き込み処理は、どちらも次の例外になる。

   ```text
   TypeError: '<' not supported between instances of 'str' and 'int'
   ```

   根拠：`wiki_graph_extract.py:574` と 701–702 行が、混合キーを含む `extras` に再び `sort_keys=True` を適用する。

   これは既存の出力制約の残存である。未知の `extension` 欄だけなら出力から除かれるため今回の修正で通るが、追加試験は `notes` も含めながら `self.build()` までしか確認していない。

2. **軽微：ID 安定性の試験は、項目と ID の対応の変化を検出しない。**

   `test_edge_ids_do_not_depend_on_order_of_different_items`（402–413 行）は、ソートした ID の集合を比較する。上記のように ID が別の項目へ移っても、その集合は一致する。循環参照の試験（415–435 行）も、並べ替えは行わない。
