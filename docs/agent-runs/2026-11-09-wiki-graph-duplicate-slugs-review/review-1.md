## 崩れる前提

- **パスを指定すれば必ずエッジになる、とは限らない。** 指定先が node_id の重複で除外されていれば、エッジは作られない。同じ型の `a/Foo.md` と `b/Foo.md` に既定の ID を使うだけで、この条件になる。
- **lint と extract が同じページを選ぶのは、node_id が文字列である場合に限る。** lint は `str(explicit)` に変換するが、extract は変換しない。
- **内部でページを区別できても、出力のパスで区別できるとは限らない。** NFC/NFD の違いだけのファイルは、内部キーでは分離されるが、出力では同じパスになる。

## 見落としと軽微な問題

1. **軽微：パスなしリンクの曖昧性を、追加テストが独立して検証していない。**

   `other.md` に `[[Foo]]` と `[[a/Foo]]` が同居し、期待値は `{concept:first}` だけである。曖昧な `[[Foo]]` を誤って先頭ページへ解決しても、正しいパス付きリンクの結果に隠れる。

   実際に `link_target()` を「候補の先頭を返す」実装へメモリ上で変異させても、このケースと同名ページ間リンクのケースの三つ組は変わらなかった。

   根拠：`tests/wiki/test_graph_duplicate_slugs.py:122–133`、fixture の `[[Foo]] と [[a/Foo]]`。

2. **軽微：CHANGELOG とワークフローの説明に、node_id の一意性という条件が抜けている。**

   `a/Foo.md` と `b/Foo.md` をともに `type: concept`、明示 ID なしとし、前者に `[[b/Foo]]` を書く。両方が `concept:Foo` となり、後者は除外されるため、説明にある `mentions` は作られない。メモリ上でもエッジなしを確認した。

   これは除外されたページへ誤接続しない実装と整合するが、説明の無条件な表現とは食い違う。

   根拠：`CHANGELOG.md:15`、`skills/info-hive/references/graph-workflow.md:27`、`wiki_graph_extract.py:267–272, 401–403`。

3. **軽微：非文字列 node_id では、lint と extract の対応は依然としてずれる。既存問題であり、スキーマ外入力での反例。**

   `a/A.md` に `node_id: 1`、`b/B.md` に `node_id: "1"` を指定し、後者に型付き関係を書く。extract は整数 `1` と文字列 `"1"` の両ノードを残し、後者のエッジも作る。一方、lint は同じ ID と判定して後者を除外し、前者を孤立として報告する。

   「extract の build_nodes と同じページを選ぶ」というコメントは、この入力では成立しない。

   根拠：`wiki_graph_lint.py:107–114, 152–158, 279–281`、`wiki_graph_extract.py:267–273`。文書上の ID 形式は `graph-workflow.md:59`。

4. **軽微：NFC/NFD が衝突するページの出力は、実ファイルを一意に指せない。**

   `a/ガ.md` と、濁点を分解した `a/ガ.md` に別々の node_id を与えると、両ノードの `path` はともに NFC の `a/ガ.md` になる。後者の関係の `page` や孤立診断の `path` も同様で、出力のパスを開くと前者を参照し得る。

   内部キーによる主語の分離はできているが、出典パスの区別は残らない。正規化されたパスを出す既存仕様の制約である。

   根拠：`wiki_graph_extract.py:284, 391`、`wiki_graph_lint.py:298–300`。メモリ上で両ノードの同一パスを確認した。
