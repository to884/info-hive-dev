## 崩れる前提

- **ページキーの一意性は、ファイル名の命名規約に依存する。** Linux 上でファイル名に `\` を使うと、ディレクトリ区切りへの置換で別ファイルと衝突する。詳細は次節。`\` は `skills/info-hive/references/page-conventions.md:92` で禁止されているため、重大欠陥には数えない。
- **出力の `page` だけでは、NFC/NFD の別ファイルを識別できない。** 今回は ID が異なるため関係は残るが、宣言元をディスク上のファイルまで特定できる情報はエッジに出力されない。これは依頼文どおりの制約であり、browse 側で識別子衝突ページを除外する前提は引き続き必要である。

## 見落としと軽微な問題

1. **軽微：規約外のファイル名では、ページキーの衝突で主語を取り違える。**

   Linux 上で次の別ファイルを置く。

   - `concepts/a\b.md`：ファイル名にリテラルの `\` を含み、関係を書く。
   - `concepts/a/b.md`：関係を書かない。

   両方を `type: concept` とすると、スラッグは `a\b` と `b` で異なる。しかし、`collect_pages()` が作る `disk_rel_path` は両方とも `concepts/a/b.md` になる。後者が対応表を上書きし、前者の関係の主語が `concept:b` になる。診断は出ない。

   POSIX のパスと読み込み内容をメモリ上で与え、実際の `collect_pages()`、`build_nodes()`、`build_edges()` を実行して確認した。`64acc43` では主語は `concept:a\b`、現実装では `concept:b` だった。

   根拠：`skills/info-hive/scripts/wiki_graph_extract.py:177`、295 行、415–416 行。`wiki_pages.py:38–46` は、このファイル名を収集対象から除外しない。ただし、前述の命名規約には違反する入力である。
