抽出版の変更と索引の指紋が連動しない点、0.4.0 の複数文書をモデル変更後に移行する際に旧キャッシュを見つけられなくなる点が、差分上で見つかりました。ローカル実行環境が応答せず、実ファイル・ADR・試験との照合はできていません。最終結果ではこの制約と、差分から確認できる欠陥を区別します。
## 判定

**却下。確信度：中。** 提示差分では、抽出版の更新による無効化と、モデル変更を伴う複数 PDF の旧キャッシュ移行が成立しません。

ただし、ローカル実行環境が応答せず、指定ファイル・ADR・試験を直接読めていません。以下は**提示差分の静的レビュー**であり、依頼されたレビュー全体を完了した結果ではありません。

## 致命的・重大な欠陥

### 1. 【重大】抽出版を上げても、取り込み済み文書は再抽出されない

**主張：** `EXTRACT_REVISION` は抽出キャッシュの鍵に追加されていますが、索引の `fingerprint` には追加されていません。コメントが指示する「抽出方法を変えたら版を上げる」だけでは、索引の無効化が働きません。

**反例：**

1. `EXTRACT_REVISION = "extract-v1"` で PDF を取り込む。
2. 抽出方法を変更し、定数を `"extract-v2"` に上げる。
3. 同じ設定で、その PDF を再投入する。

`_stale_policy()` は指紋が同じなので変更を検知せず、`ingest_pdf()` は既存文書の分岐に入り、抽出器を呼ばずに処理します。検索にも旧抽出結果が残ります。さらに、返す `extracted_markdown` は新しい抽出キーのパスなので、そのキャッシュが未作成なら存在しないファイルを指します。

**根拠：**

- `scripts/rag_config.py`：`EXTRACT_REVISION`、`fingerprint`、`extraction_key`
- `scripts/rag_index.py`：`_stale_policy()`、`ingest_pdf()` の `existing` 分岐

**確認結果：** 提示差分の制御フローと一致。実行による再現は未確認。

### 2. 【重大】モデル変更後、2 件目以降の 0.4.0 キャッシュを移行できず、OCR を再実行する

**主張：** 旧モデルのキャッシュを探す情報が、最初の索引リセットで失われます。

**反例：**

1. 0.4.0、モデル M1 で PDF A・B を取り込む。抽出結果は wiki ごとの旧 generation に保存される。
2. 0.5.0 に更新し、OCR 設定を変えずにモデルを M2 に変更する。
3. A を再投入する。旧 `policy.json` があるため M1 の generation を推定でき、A は移行される。その後 `_reset_index()` が方針を M2 に書き換える。
4. B を再投入する。今度は `stale` が `None` なので、`_legacy_generations()` は M2 の generation しか返さない。

B のキャッシュは M1 の generation に残っていますが、探索されません。共有キャッシュも未作成なので、抽出・OCR をやり直します。これは「埋め込みモデルだけの変更では保存済み抽出結果を使う」という説明と食い違います。

**根拠：**

- `scripts/rag_index.py`：`_legacy_generations()` は旧指紋を `stale` からだけ取得
- 同：`_reset_index()` は `_write_policy()` で旧方針を置換
- 同：`previous-index.json` に保存した旧指紋を、移行候補の算出には使用していない

**確認結果：** 提示差分から成立する反例。実キャッシュによる再現は未確認。

## 崩れる前提

- **「抽出キーが変われば、取り込みでも抽出結果を更新する」**  
  索引の指紋が同じままなら、既存文書の分岐が抽出処理を飛ばします。

- **「旧キャッシュを移行する時点でも旧方針を参照できる」**  
  最初の PDF の取り込みで索引をリセットした後、残りの旧キャッシュについて成立しません。

- **「旧キャッシュの移動は途中で止まらない」**  
  `_adopt_legacy_extraction()` はファイル単位の移動です。ページ JSON を一つ移した直後に停止すると、再開時は移動先にページがあるため、残りの旧キャッシュを採用しません。

## 見落としと軽微な問題

### 【軽微】旧キャッシュ移行の中断で、未移動ページを再利用できなくなる

上記の途中停止では、旧ディレクトリに残ったページ JSON を `_adopt_legacy_extraction()` が移動しません。条件が `not any(cache.glob("page-*.json"))` だからです。

移動処理が再開されないことは差分から確認できます。未移動ページに対して実際に OCR が再実行されるかは、未読の `rag_pdf.py` に依存するため**未確認**です。

**根拠：** `scripts/rag_index.py`：`_adopt_legacy_extraction()` の採用条件と、逐次の `os.replace()`。
