埋め込まれた ADR と差分だけを照合し、停止後の再開、旧キャッシュの移行、抽出の版を変えた場合を中心に反例を探します。シェルでの読み取りやファイルの変更は行いません。抽出の版を指紋から外したことで、旧キャッシュの移行と埋め込みの途中再開に、版の違いを検出できない経路があります。また、索引を空にしたあとで別の版に置き換える場合の、0.4.0 のキャッシュ削除を確認しています。## 判定

**却下。確信度：高（提示された差分と ADR の静的照合）。** `EXTRACT_REVISION` を指紋から外す設計に対し、旧キャッシュの移行と埋め込みの再開が対応していません。抽出の版を上げたとき、旧結果を新しい版として保存する、または異なる抽出結果の索引を混在させる反例があります。

## 致命的・重大な欠陥

### 1. 【重大】0.4.0 の抽出結果を、新しい抽出の版の結果として移してしまう

**反例**

1. 0.4.0 で取り込んだ PDF の抽出結果が、wiki 内の `extracted/<generation>/` に残っている。
2. ページ判定やテキスト抽出を変更し、`EXTRACT_REVISION` を `extract-v2` に上げる。指紋は ADR の方針どおり変えない。
3. その PDF を取り込む。
4. `_legacy_generations()` は現在と同じ指紋の旧 generation を候補にする。
5. `_adopt_legacy_extraction()` が旧ページと `document.md` を、`extract-v2` のキャッシュへ移す。

旧結果に抽出の版を確かめる処理がありません。旧 `document.md` も移るため、既存文書の分岐では `markdown.exists()` が真になり、抽出し直す処理も通りません。

**結果：** 抽出方法を変更したにもかかわらず旧本文を返し、その旧結果を新しい抽出の版の共有キャッシュとして他の wiki にも提供します。

**根拠**

- `scripts/rag_config.py`：`extraction_key` には `EXTRACT_REVISION` が入るが、指紋には入らない。
- `scripts/rag_index.py`：`_legacy_generations()` の `fingerprints = [self.config.fingerprint]`。
- 同：`_adopt_legacy_extraction()` の無条件のファイル移動。
- 同：`ingest_pdf()` の移行後に行う `if not markdown.exists()`。
- ADR「0.4.0 の抽出の結果」の「指紋から抽出の設定が今と同じと分かる」という説明は、抽出の版について成立しません。

### 2. 【重大】抽出の版を上げると、旧抽出結果の埋め込み途中経過を新抽出結果に適用する

**反例**

1. ある PDF の取り込みで、最初の埋め込みバッチを保存したあとに停止する。`documents` への公開前で、`jobs.completed = N` と旧チャンクの行が残っている。
2. 抽出処理を変更して `EXTRACT_REVISION` を上げ、再開する。
3. 新しい抽出結果から作ったチャンクは、本文、分割位置、件数のいずれかが旧結果と異なる。
4. 指紋と generation は変わらないため、同じ `jobs.completed` を取得し、先頭の N チャンクの埋め込みを飛ばす。

例えば旧処理で N チャンクを保存済みなのに、新処理では全体が N 以下のチャンクになった場合、埋め込みループは一度も実行されません。旧抽出結果の索引行を残したまま、新処理の件数で文書を公開する経路になります。

**結果：** 新旧の本文・分割が混ざった索引、または新しい本文がまったく埋め込まれていない索引が完成扱いになります。

**根拠**

- `scripts/rag_index.py`：generation は `doc_id + self.config.fingerprint` から作る。
- 同：`completed` を同じ generation の `jobs` から取得する。
- 同：`for start in range(completed, len(chunks), self.config.batch_size)`。
- 同：保存する `chunk_id` も generation とチャンク番号で決まる。
- ADR：抽出の版を上げても指紋を変えず、中断したジョブは再開する方針。

この反例は、抽出処理の変更によってチャンクが変わる場合を前提にしています。これは ADR が想定するページ判定・テキスト抽出の変更そのものです。提示範囲には、途中経過と抽出の版を照合する処理がありません。

## 崩れる前提

- **「指紋が一致すれば、旧抽出結果を再利用できる」**  
  `EXTRACT_REVISION` が違うと崩れます。指紋は抽出結果の互換性を証明できません。

- **「同じ generation の completed は、現在のチャンク列の処理済み件数である」**  
  抽出の版を上げて未公開ジョブを再開すると崩れます。同じ PDF・同じ指紋でもチャンク列が変わります。

- **「索引を空にしたあとでも、旧キャッシュを削除する機会が残る」**  
  旧文書が現台帳から消え、取り込み直しの一覧だけに残った状態では、0.4.0 の wiki 内キャッシュを削除する経路が欠けます。

## 見落としと軽微な問題

### 【軽微】索引を空にしたあとで置き換えた文書の、0.4.0 のキャッシュが残る

旧文書 P を取り込み直す前に、同じ場所の新版 Q を取り込み、P が `previous-index.json` から外れる場合です。特に OCR 設定も変えた場合、P の旧キャッシュは移行されずに残ります。

`_prune_previous()` が呼ぶ `_remove_extraction(P)` は、共有先の `<data_dir>/extracted/P/` だけを削除します。wiki 内の旧 `extracted/<generation>/` を消す処理は、別の `removed` ループにしかありません。索引を空にした際に台帳から消えた P は、この通常の旧版削除経路では拾えません。

**根拠：** `scripts/rag_index.py` の `_prune_previous()`、`_remove_extraction()`、`for old_id, old_generation in removed`。ADR の「古い版を消すときは、0.4.0 の置き場所に残った結果も消す」と食い違います。

### 【軽微】`configure(ocr_dpi=0)` は範囲外として拒まれない

`if ocr_dpi:` により、明示された `0` が無指定扱いになります。現在値を維持して成功するため、「72〜300 の範囲外を拒む」という説明と一致しません。

**根拠：** `scripts/rag_server.py` の `configure()`。既定値にも `0` を使っているため、明示指定との区別がありません。

## 検証した事実

検証対象は、依頼に埋め込まれた差分と ADR のみです。指定どおりシェル、リポジトリの読み取り、実行試験は行っていません。

- **一致：** 共有キャッシュの鍵から、埋め込みモデルと分割設定が除かれている。
- **一致：** 最初の埋め込みバッチの生成後に `_reset_index()` を呼ぶ順序になっている。
- **一致：** 取り込み直しが残っている間は、`previous-index.json` に旧方針を保持する。
- **一致：** 旧ファイルの移動途中で止まった場合、次回は移動先にないファイルを移す。
- **食い違い：** 指紋一致だけでは、旧キャッシュと現在の抽出の版の一致を保証できない。
- **確かめられず：** 記載された試験の実行結果、`extract_pages()` の本文、差分外の処理。

## 崩せなかった点

- 最初の埋め込みが例外で失敗した場合、提示された順序では索引の初期化に到達しません。
- 同じ文書が取り込み直しの一覧と現台帳の両方にある場合、`_reset_index()` は場所とソースページの和を保存します。
- 文書ごとの削除ロックは待機しないため、指摘されていた相互削除の待ち合いは提示範囲から作れませんでした。
