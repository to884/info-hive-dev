# ADR-0025 の段階 3 の実装のレビュー（8 回目、範囲を絞る）

## 目的

7 回目（`review-7.md`、却下）の重大な指摘 2 つを直した。
- 空の理由の失敗を完了にしていた。失敗かどうかを `error is not None` で決め、メッセージのない例外も、例外の名前を理由にする。
- 公開している版と要約の読み取りが競合していた。要約と同じ時点に公開している generation の要約だけを使い、前のジョブの記録には戻らない。

今回は、範囲を次の 3 つの性質に絞る。この 3 つを壊す反例だけを、重大として挙げてほしい。

1. **確認を失わない:** `decide_ocr_pages` が受け付けた確認は、どの止まり方とどの順の操作でも、いつか索引に反映される。反映されないのは、利用者が作り直しを取り消したか、作り直しが失敗して再試行していないときだけである。方針が変わった索引のときは、取り込み直したときに反映される。
2. **取り消しと失敗を覆さない:** 利用者が取り消した作り直しと、失敗した作り直しは、明示的な `retry_job` なしには動かない。
3. **未公開の行を検索に出さない:** 検索は、その wiki で公開している generation の行だけを返す。作り直しの途中の行、前の版の行は出さない。

**対象外:** 同時に読んだときの表示のずれ（`page_report`、検索の印、`status` が、読むあいだに進んだ公開の版を反映しないこと）。次に読めば正しくなるものは挙げなくてよい。

範囲と前提は `task-1.md`〜`task-7.md` のとおりである。
