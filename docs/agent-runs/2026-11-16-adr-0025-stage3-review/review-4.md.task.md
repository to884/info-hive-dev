# ADR-0025 の段階 3 の実装のレビュー（4 回目）

## 目的

3 回目（`review-3.md`、却下）の重大な指摘 2 つは、どちらも「作り直しのジョブを登録したことの記録」を、ジョブとは別の DB（台帳）に置いていたことから来ていた。境目を 1 つずつ塞ぐのをやめ、構造を変えた。直し方が原因を取り除いているかを壊してほしい。範囲と前提は `task-1.md`〜`task-3.md` のとおりである。

## 直し方

- **受け持つ版:** 作り直しのジョブの行が、受け持つ台帳の版（`ingest_jobs.review_version`）を持つ。台帳の側の登録の記録（`review_registered`）はやめた。
- **登録:** `Jobs.register_rebuild(config, wiki, doc_id, version, only_if_uncovered=False)` が、確かめることと登録を、ジョブの DB の 1 つの `BEGIN IMMEDIATE` で行う。
  - 待ちか処理中のジョブがあれば、それに `review_version = MAX(既存, version)` を受け持たせる（処理中なら `rerun=1`）。
  - なければ、`version` を受け持つジョブを作る。
- **確認を受け付けたとき:** `decide_ocr_pages` は、台帳に書いたあと、その版で `register_rebuild` を呼ぶ。
- **状態からの登録し直し:** `reconcile_rebuilds` は、台帳の版が公開した版より新しい（wiki, 文書, 台帳の版）を走査で読み、`only_if_uncovered=True` で呼ぶ。その版以上を受け持ったジョブが状態によらず（取り消し、失敗、完了を含めて）あれば、登録しない。
  - 台帳に書いたあと、登録する前に止まった版は、受け持つジョブがないので登録される。
  - 取り消したジョブや失敗したジョブが受け持った版は、復活しない。
  - 取り消したあとで受け付けた新しい版は、受け持つジョブがないので登録される。
- **1 回の読み取り:** `page_report`、検索の印、`status` の、台帳の版と確認の結果は、`Ledger.state`（1 つの読み取りのトランザクション）で読む。
- **試験:** `tests/contract/test_rag_review.py` は 27 件。次を足した。
  - 取り消したあとの新しい版の登録
  - 失敗した作り直しが復活しないこと
  - 渡したパスと解決したパスが違うときも、渡したパスで作り直すこと

## 見てほしいこと

- 3 回目の 2 つの反例と、2 回目の「取り消し、失敗の復活」の反例が、通らなくなったか。
- `review_version` が実際の作り直しと食い違う経路がないか。
  - 待っているジョブに新しい版を受け持たせたが、そのジョブが取り消された場合。
  - `rerun` で待ちに戻った場合。
  - 完了したジョブが、受け持った版まで公開していなかった場合（`deferred` など）。
- 1〜3 回目に挙げられなかった欠陥。
