# ADR-0025 の段階 3 の実装のレビュー（3 回目）

## 目的

2 回目（`review-2.md`、却下）の重大な指摘 4 つと軽微な指摘を直した。直し方が原因を取り除いているか、新しい欠陥が入っていないかを壊してほしい。範囲と前提は `task-1.md` と `task-2.md` のとおりである。

## 2 回目の指摘と、原因の構造と、直し方

1. **取り消した、失敗した作り直しを、状態から登録し直していた。**
   - 原因: 登録し直しの条件を「台帳の版と公開した版の差」にしていた。差は、利用者が取り消したときや失敗が続くときにも残る。
   - 直し方: 台帳に、作り直しのジョブを登録した版（`review_registered`）を記録する。登録し直すのは、台帳の版がその記録より新しい（確認を書いたあと、登録する前に止まった）ときだけにした。`decide_ocr_pages` は登録したあとで、`reconcile_rebuilds` は登録し直したあとで記録する。取り消したジョブと失敗したジョブは、明示的な `retry_job` で動かす。
2. **公開している版の要約が空のとき、前のジョブの記録に戻っていた。**
   - 直し方: `load_summary` は、ファイルがないときだけ None を返す。空の要約（OCR したページがない）は、公開している版の正しい結果として使う。
3. **wiki の手順が、古くなったページの確認を落としていた。**
   - 直し方: 確認を始める条件を、`review:pending` と `review:stale`（新しい本文の確信度が高くても）にした。要約から外すページにも `review:stale` を入れた。
4. **作り直しが、ネットワークドライブの PDF を UNC のパスで取り込み直そうとしていた。**
   - 直し方: 索引の台帳の場所の行に、利用者が渡したままのパス（`locations.source`）を残し、作り直しはそれを使う。
- **軽微な指摘。**
  - 作り直しのジョブの再試行は、確かめることと待ちに戻すことを、1 つの `BEGIN IMMEDIATE` で行う。
  - 失敗した作り直しのジョブも、ジョブの行の `doc_id` で、確認の状態を返す。
  - 試験に、次の 4 つを足した。
    - 取り消した作り直しが復活しないこと。
    - 内側の繰り返しで追いついたあと、もう一度動かしても結果が欠けないこと（公開の直前に次の確認を受け付ける）。
    - 空の要約。
    - 利用者が渡したパスで作り直すこと。

## 見てほしいこと

- 上の直しで、4 つの反例が通らなくなったか。
- 登録した版の記録（`review_registered`）が、ほかの経路で食い違わないか。
  - 登録したのに記録する前に止まった場合。
  - 記録だけが残った場合。
  - 2 つの MCP の接続がある場合。
  - wiki を作り直した場合。
- 1、2 回目に挙げられなかった欠陥。
