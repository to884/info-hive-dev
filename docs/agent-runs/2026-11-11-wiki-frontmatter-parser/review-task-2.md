1 回目の指摘への対応:
- 重大 1（読まないキーの行 `source-url:` を挟んだあとの `  - "b"` を、前のキーの要素にしなくなる）: 読み方は変えない（YAML では `b` は `source-url` の要素で、決まり 1 に合う）。設計 2.2 の変わる点と、設計 3 の表、CHANGELOG の Changed に書いた。試験で値を固定した。配列の要素が減る入力を無作為の入力で分類し、表の 2 行（次の行が `- ` の行でない、字下げのない読まない行を挟む）のほかにないことを確かめた（設計 4）。
- 重大 2（行末の `]` がコメントの中にある複数行の配列）: 値が `[` で始まる行は、先に `_fm_multiline_flow()` で、YAML の読み方（フローのコメントの決まり）で 1 行目の括弧が閉じているかを見る。閉じていなくて、後ろの行で閉じれば、複数行の配列として読む。そうでなければ、今までどおり（行末が `]` なら 1 行の配列、でなければ文字列）。
- 重大 3（GraphML の ID の置き換えで、別のノードが同じ ID になる）: ID（ノードとエッジの ID、エッジの両端）は `_xml_id()` で書く。XML に書けない文字を U+FFFD と `{16 進のコード}` に、ID の中の U+FFFD を U+FFFD 2 つにする。XML に書ける文字だけで U+FFFD を含まない ID は変えない。値（題名など）は今までどおり `_xml_text()`（U+FFFD 1 つ）。
- 軽微（CR が GraphML の読み込みで LF になる）: 置き換えない。設計 2.11 と docstring に書いた。
- 軽微（試験の `as_parser()` が、引用符の空の文字列を値なしと混同する）: YAML のノードを見て、引用符のない空のスカラーだけを空の配列にした。
