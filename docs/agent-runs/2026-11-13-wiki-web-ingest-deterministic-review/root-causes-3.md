# 3 版のレビューの指摘の、原因の構造による分類

対象: [docs/plans/wiki-web-ingest-deterministic-2026-11-13.md](../../plans/wiki-web-ingest-deterministic-2026-11-13.md) の 3 版。レビュー: [review-3.md](review-3.md)（GPT-6.1 Sol、effort high、却下）。前の分類は [root-causes.md](root-causes.md)、[root-causes-2.md](root-causes-2.md)。

3 版で、2 版の指摘（語順による名前の欠落、数字の列挙、`cookie` の記事、通常の操作どうしの競合、`stage_id` の `:`）は崩せなかった。新しい指摘は次のとおり。

| 原因の構造 | 崩れた前提 | 指摘 | 4 版での変更 |
| --- | --- | --- | --- |
| 今の変換を正として段階を区切った | 今の変換の欠けは、文字のエスケープだけである | 致命 1（画像に付いたリンク、`<br>` を含む強調、連続した改行、項目の中の段落が落ちる） | 段階 1 の条件から「今の出力との一致」を外す。合格の条件は HTML の内容との一致だけにし、今の出力との差は、今の変換が内容を落としていた箇所として一覧にする |
| raw に書く口が 2 つあった | 錠を取る操作だけが raw に書く | 重大 2（`--stage` なしの旧来の使い方が錠を通らずに上書きする） | raw に書くのを `apply` だけにする。`--stage` なしで raw に直接書く使い方はやめ、`--stage` と同じ動きにする（設計案の本文に合わせて 5 版で直した） |
| 守る語の判断の単位が、語の綴りだった | 同じ綴りには、ページ全体で同じ判断を当てられる。守る句は 1 つの文字の並びに収まる | 重大 3（`Rust` の言語名とさび）、重大 4（`**Greg** Young`） | 判断の既定は綴りごとにし、出現ごとに外せるようにする（`fill` の `release_terms` で宣言する）。守る句は、インラインの境目をまたがない文字の並びの中だけで当てる。またいで当たらなかった出現は `review` が示す |
| 錠の生死を、ファイルの有無と中身で推し量っていた | 止まったプロセスの錠は、確かめてから消せる | 重大 5（確かめたあとに作られた別の錠を消す） | 錠を OS のファイルの錠（Windows は `msvcrt.locking`、POSIX は `fcntl.flock`）にする。プロセスが止まれば OS が外すので、錠を回収する操作そのものをなくす |
| 確定前の生成物の一覧と、公開の操作が決まっていなかった | `clean` が消す物の一覧で足りる | 重大 6（記録が残る）、軽微（排他的な作成で、書きかけの Markdown が残りうる） | Markdown のない raw の生成物（assets のフォルダー、記録、一時ファイル）をすべて確定前の生成物と定め、`clean` が錠を取って消す。Markdown は、書き終えた一時ファイルを `os.link` で正式な名前に結んで公開する（行き先があれば失敗し、書きかけは見えない） |
| 本文を替えたあとの判断の範囲が決まっていなかった | 判断の対象は、`review` を最初に呼んだときに決まる | 軽微（本文を替えたあとの候補） | 判断が必要な範囲は、`decisions.json` の `content_root` で決まる最終の本文で判定する。`review` は何度でも呼べ、足りない判断を示す |

## 4 版でも残る限界

- 3 版の限界（候補に挙がらない固有の名前、原文にない内容の追加）は変わらない。
- 強調やリンクをまたぐ句は、守る語として当たらない。`review` が示すので、モデルは訳しながら注意できるが、構造では守られない。
- OS のファイルの錠は、ネットワークのフォルダーでは効かないことがある。同じ機械で使う前提は 3 版と同じである。
