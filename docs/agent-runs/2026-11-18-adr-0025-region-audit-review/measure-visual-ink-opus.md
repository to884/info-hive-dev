## 問題がないと確かめた点

- **座標:** `save_views` は整数の箱を `(target - crop_left) * 3` で表示座標に移します。スクリプトは 3 で割り切れるかを確かめてから `// 3` で戻すので、厳密に元の値になります。`window` も同じ「切り出しの左上が原点、150 DPI」の座標で、両者はそろっています。
- **半開区間と中心:** インクの範囲は右と下を含まない形（終端に +1）で、中心は両端を含めて判定します。`region_truth.inside` と同じ意味です。
- **最近傍拡大の確認:** 切り出した範囲全体について、3 倍の最近傍拡大を戻した画像と一致するかを確かめています。PNG は可逆で、RGB から L に変えても値は変わりません。`region_truth_v9` の `convert("L")` と同じ値になります。
- **匿名の束の外を読まない:** 読むのは `index.json` と、正規表現で形を確かめた ID から作った 1 つの PNG だけです。`resolve()` でシンボリックリンクによる束の外への逃げを防いでいます。`reference_audit_v9` は `crop_rectangle` を消しており、出力にもページ座標は出ません。

### [Major] 背景の推定が読者の選ぶ窓に依存し、`region_truth` の固定条件とも違う

対象
`measure_visual_ink.py` 13〜15 行（コメント「region_truth の固定条件」）と 43〜44 行、計画の手順 2・4。

根拠
- `region_truth.ink_mask` は、背景を「字の箱を短い辺の長さだけ広げた範囲」の中央値で求め、インクは字の箱の中だけで数えます（`region_truth.py` 70〜76 行）。
- 試作は、読者が選んだ `--window` の中央値を背景にし、同じ窓の中をインクとします。
- 合成例で確かめました。20×20 の黒い四角の周りに 1 画素だけ白を残して窓を切ると、次のようになりました。
  - 窓が広いとき: `background 255`、範囲は `[10,10,33,30]`、2 成分
  - 窓が狭いとき: `background 0.0`、範囲は `[9,9,31,31]`（窓全体）、1 成分
- 窓が狭いときは白と黒が反転し、白い余白をインクとして数えています。

問題
- 濃い字や ■ を囲むように窓を狭く取ると、インクが窓の半分を超え、背景とインクが入れ替わります。このとき返る範囲は窓そのものです。
- 窓が字の内側に収まると、「インクなし」と出て、`window_edge_has_ink` も false になり、警告が出ません。
- 同じ字でも窓の取り方で結果が変わるので、計画の手順 4「読者自身の任意のファイル操作に依存させない」と合いません。
- 試作は字の箱の外にはみ出したインクまで数えますが、`region_truth.char_ink` は箱の中に限ります。コメントは「固定条件」と書いていますが、背景の推定も、インクを数える範囲も現行と違います。境界の判定は、まさにこの差で揺れます。

検証方法
`measure(g[9:31, 9:31], (9, 9, 31, 31), (0, 0, 40, 40), 0)` を、`(0, 0, 40, 40)` の窓と比べてください。`g` は白地に `[10:30, 10:30]` の黒い四角を置いた配列です。

修正の方向性
- 背景を推定する範囲を、プログラムが決めるように固定します（例: 対象の枠や切り出し全体の中央値、または `region_truth` と同じ広げ方）。窓は、インクを数える範囲だけに使います。
- 背景が窓の中の多数派でなくなったときは、警告ではなく失敗として止めます。
- コメントの「固定条件」は、実際に同じにしたものだけを書きます。

### [Major] 字の成分のまとめと隣の字片の分離を、プログラムで固定していない

対象
`measure_visual_ink.py` 41〜66 行（`components` と `envelope`）、計画の手順 2・4 と「次版の検証」の 1 項目め。

根拠
- 出力は 8 連結の成分の一覧と、窓の中の全インクを包む範囲（`envelope`）だけです。
- どの成分が同じ字かを指定する入力はなく、成分を選んで合わせた範囲の重なりも計算しません。
- `envelope` は、窓に入った隣の字片も無条件に合わせます。上の合成例でも、1 画素離れた字片が範囲 `[10,10,33,30]` に入りました。
- 試験のファイル（`test_measure_visual_ink.py`）はありません。

問題
- 計画の手順 2 は、「同じ文字の成分をまとめ、隣の字と区別できなければ未決定」とします。試作でこれをするには、読者が成分を手で選び、範囲の和、割当軸の重なりの分子と分母、直交中心を自分で計算し直すしかありません。手順 4 の「測定用プログラムを前もって固定」と合いません。
- そのまま使える値は `envelope` だけですが、これはまさに計画が禁じる「隣の文字片を同じ字にまとめる」計算です。
- 計画の検証項目（連続括弧が 2 字、句点の 1/3、複数成分の字の 7/15、隣の字片を合わせない）は、このプログラムでは判定できず、確かめられないまま通るおそれがあります。

検証方法
上の合成例の 2 成分から、黒い四角だけの重なりを出すには、出力の外で手計算が要ることを確かめてください。

修正の方向性
- 引数で成分の番号（または種となる点）を受け取り、選んだ成分を合わせた範囲で `axis_overlap`、`axis_length`、直交中心を返すようにします。
- 選んだ成分に接していて選ばれなかった成分があれば「未決定」とします。
- `envelope` は判定に使わない参考値と明記するか、出力から外します。
- 計画が挙げる合成の反例を、単体の試験として固定します。
