# 初めて使う開発行で中立化した表示を比較する

正式な独立監査と未使用の公開・合成評価は始めない。固定済みの開発用の公開資料から、既知で両方の正解に矛盾がない行を使う。既存の母集団で開発への取り込みと独立監査の印がある行、以前の監査の全抽出行、過去の開発用の選定表と保存済みの配布にある行を除く。候補と除外一覧のハッシュを記録する。対象候補は短い横枠、その他の横枠、短い縦枠、長い縦枠の4群に分ける。各群8行を、事前に定めた識別子のSHA-256順位で選ぶ。

従来の画像表示と中立化した新しい表示を別々に試す。両方とも同じ固定150・450 DPIの元画素、同じ枠、正解、所属と正規化を使う。新しい表示では、字体や以前に割れた字の例を指示に含めない。枠の寸法と固定画素だけで添付を選ぶ。行の両端の450 DPIの細部を保持し、併せて見る画像と必要な目盛りを保存する。送らない補助画像と各添付の画素寸法を記録する。

SolとOpusは各行・各版を別々の新規セッションで一度読む。モデルへ本文の正解と相手の票を渡さない。採点と例外の扱いも両票の発送前に固定する。既定の正規化と二票一致で、既存正解との一致、異なる一致、未決定、過剰転記、脱落を数える。出典が必要な合意は、この表示の比較では出典待ちとして報告する。出典経路の独立した検証は別の比較で扱う。読取と集計を、各CLIの原票と要求のハッシュに結び付ける。
