# 開発で未使用の短い枠でも列順を確かめる

v72で固定した旧・新の列順の指示を、既存の監査と開発の選定履歴を除いた開発資料で比べる。v70の候補の公刊資料から、既存の既知正解どうしが割れていない横軸の短枠を調べる。官報の幅35画素以下、官報の幅36〜120画素、その他の資料の短枠をそれぞれ6行、同じ条件を満たす行の固定文字列と行IDのSHA-256順で事前に選ぶ。行の正解・現在の二票の結果を選定に使わない。既存正解が既知で複数の正解が割れていないことだけを選定の条件にする。

各行の固定150・450 DPIは両版で同じ画像を同じ順に送る。既存の配布に周囲の配置がなければ、同じ固定150 DPIの配置画像を両版に追加する。列順の段落だけをv72と同じ形で置き換える。SolとOpusは各版を別々の新規セッションで `high` で一度読む。判定はv72と同じで、資料群ごとにも集計する。いずれかに誤りが出た場合は行別に保存し、旧・新で未決定が増えたかを調べる。正式の合否と既存正解は保持し、正式の未使用資料にこの開発試験を混ぜない。
