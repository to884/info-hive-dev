# v19の独立監査の作業記録

官報の末尾と防衛白書の符号の訂正を反映した正解で、同じ固定予測を使って開発6組・公開3組の追加条件を通過した。[開発の採点と二読](../v19-reference-candidate/development-result.md)

Opusの抽出前レビューで、集計の関数と正規化の依存が固定に足りないことを指摘された。実際の関数、読み込んだリポジトリ内のPython、前版の入力のハッシュ、pypdfium2・pypdf・numpy・scipy・Pillowの版を固定した。出典を読む前と集計の直前に照合する。既存の開発14行と、50画素近い高さを持つ横軸を含む25行の配布を個別に試し、目盛りの座標と最大24枚を確かめた。保存した構造化回答8件と、構文が拒否されたあとに返った最終回答1件を新しいパーサーで受領した。

母集団は領域5,988行、画像補充2,865行。固定は `77186237b1ba36db1da6ce8eaaa47831fe618a140e9fd3eb7232365aec13f8d1`。2026-11-20に二つの標本を一度だけ抽出した。和集合377行のSHA-256は `2c9f5f07724cc01757d16427319c4073d595b4a91d93206098a8e8764a48d21d`。212束を固定し、配布のSHA-256は `f6e8cb89b48e16a492637b12251e3848586800282eb5643db8321450b4fb17ed`。

原票は研究用corpusの `reference-audit-v19/delivery` に保存する。配布完了後に `run.py close`、`run.py source-requests`、pypdf 6.21.0を加えた同じPythonで `source.py` を順に実行する。旧版の原票や開発票を正式な参照に使わない。[手順](protocol.md)
