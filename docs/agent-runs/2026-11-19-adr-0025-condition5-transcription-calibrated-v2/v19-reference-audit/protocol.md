# 正解品質の独立監査 v19

既定の合否、正規化、固定150/450 DPI、所属、評価行、印と未決定の100万配置を保つ。v14の画像補充1行の境界訂正に、見た目だけでは符号を区別できなかった防衛白書1行の出典による訂正を加えた。旧教師・予測で開発6組と公開3組の追加条件を通過してから独立監査を行う。領域正解と画像補充正解について、不一致と参照不足が両方0の場合に通過する。画像補充の未決定層は別に報告する。

全正解、予測、母集団、方法のSHA-256を抽出前に固定する。領域は種 `2026112003`、画像補充は `2026112004`。従来どおり各層15行か全数を、同じ順序で一度だけ抽出する。過去の開発・監査に入った行も除外せず、その重なりを保存する。

SolとOpusは固定したPNGだけを各行一度読み、新規セッションを使う。局所表示は字形と元の枠への所属を確かめる用途に使う。元の枠に入るインクの長さが半分以上で、直交中心が範囲内の字を採る。横軸の短い複数列は目印付き、横書きと縦軸の行は全文で答える。『枠への入り方』の最短目盛りは固定150 DPIの1画素。『横座標』の最短目盛りは固定150 DPIの5画素で、丸印の中心は後者だけで記録する。

小さな白い穴がある句点と塗られた丸印を450 DPIで確認する。出典用の印の記録は既定の横軸の行に適用する。塗られた小さい点で符号が視覚から決まらなければ、行頭でも行中でも物理的位置を二票で独立に記録する。出典は既定の点と点線だけに使い、本文や既存票は読者へ渡さない。従来の出典で抽出できなかった場合や位置が証明できなかった場合の丸印は、元PDFの描画状態とフォント対応をPDFiumの別実装で確認する。該当の描画だけで固定画素を再現し、他の描画が同じ点を生まないことが必要。最初に保留した理由を記録する。

配送は絶対パスで行い、各役割の着手を原票とは別に一回だけ記録する。CLIの構造化された最終回答を、完了イベントおよび保存された原票と照合する。一つの会話の構造化出力で、入力検証がエラーになった内部応答は保存し、採用するのは一つの正常な最終回答だけとする。画像以外の道具は使わせない。既定の対象IDか本文形式が不明なら、その参照を採らない。
