# 条件5の開発試験　実資料での所属の確認

v9で画像補充した開発用の公開資料から、選定用・評価2回目・評価3回目の各組について、所属軸y、xかつ幅20画素以下、xかつ幅20画素超の3層を作る。各組・層から既存未決定1行と既存確定1行、合計18行を選ぶ。各層・状態の行の順は、事前に指定した文字列と資料ID・行番号のSHA-256順。選定に転記本文、OCR本文、印、正誤、スコアを使わない。調べた行は後の正式監査で開発既知行として扱う。

各行の保存済み150 DPI・450 DPIの枠あり／枠なし画像を、画素を変えず1枚に並べ、匿名IDと所属軸だけを付ける。両群で同じ画像を使う。現行の指示と、画像の照合順を具体化した指示を、SolとOpusの各新規セッションで比較する。既知の全文が異系統で一致した候補を数える。既存未決定は正解不明なので、新しい二票の一致を正解数とは呼ばない。既存確定行は既存の正規化後の全文との一致・不一致・未決定を数え、監査とは別に記録する。

新しい指示で未決定からの一致が2行以上増え、既存確定9行の一致が減らず、既存全文との不一致が増えなければ、別の開発用行で追試する。小標本の進行判断であり、公式の正解や採点は変更しない。事前固定後の試行と応答を保存し、同じ版で試行を差し替えない。
