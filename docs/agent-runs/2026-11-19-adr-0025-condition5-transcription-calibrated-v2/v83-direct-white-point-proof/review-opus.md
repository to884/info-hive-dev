### [Minor] 背景検査は文字をすべて隠してから調べるので、暗い字形に重なる白い字を拒否しない

対象

- `check_background_controls.py` 34–37 行目（対照は暗い図形をパスで描く 1 種類だけ）

根拠
次の内容の PDF を作り、`run.py` の `inside` と `dark_wide_background` を原文のまま実行しました。結果は PASS で、`drawn_objects` には image だけが記録されました。


これは、前回の Major で挙げた反例（◉ のように見える記号）と同じ種類です。違いは、暗い円をパスではなく文字の字形で描いた点だけです。

- v80 から受け継いだ「別の文字描画が点の位置に寄与」の検査は、v19 `trace.py` 179 行目の `area`（箱の周り 1 画素まで）しか見ていません。
- 実際の頁では、2 バイトを消した描画と文字をすべて隠した描画が、36×36 の文脈でまったく同じでした（差 0 画素）。この行は反例に当たりません。

この行の結論には影響しません。影響するのは、「暗い図形に重なる白い字を拒否した」という対照の主張です。この主張は、暗い図形がパスの場合にしか確かめられていません。v83 を根拠に別の行へ広げると、前回の Major がそのまま戻ります。

2. `dark_wide_background(blob, 1, (98,98,111,111), FLAGS)` に、`check_background_controls.py` と同じ `FLAGS` を渡して実行する。
3. 例外にならないことを確かめる。

修正の方向性

### [Minor] CID の意味の確認がフォントの種類を見ておらず、三点リーダーの除外は定数の検査になっている

対象
- `run.py` 24–46 行目（`font_ids`）、239 行目
- `check_background_controls.py` 58 行目と 61 行目
- `background-controls.json` の `"ellipsis_excluded": true`

根拠
- `font_ids` は、`/Subtype` が `CIDFontType0` であることも、`/CIDToGIDMap` がないことも確かめていません。`CIDFontType2` で `CIDToGIDMap /Identity` のフォントが ROS を Adobe-Japan1 と宣言していても、条件を通ります。その場合、CID 638 はグリフ番号であり、Adobe-Japan1 の「・」を意味しません。
- `0x2026 in allowed` と `inside((1,1,10,10),(2,2,9,9),4)` は、どちらも定数で、結果が実行前から決まっています。三点リーダーを当てる陰性対照は、実行されていません。

問題
この行のフォントは `CIDFontType0C` なので、結論は変わりません。ただし、`ellipsis_excluded: true` は、実行していない対照を実行したかのように記録しています。

修正の方向性
- `CIDFontType0` であることと、`CIDToGIDMap` がないことを条件に加える。
- 三点リーダーの除外は、`allowed` の形から言えることとして手順書に書く。対照として記録するなら、実際に CID 668 などを当てて `font_ids` が空になることを確かめる。
