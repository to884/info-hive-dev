# v95のレビューと対応

Opus `high` は、両解像度でのコンマ中心、数字の収まり、青い罫線片の分離、事前固定と独立セッションを確認した。新指示の二文が矛盾しているため、設計の判定は不承認だった。壊れやすい記述はv96の固定で直し、v95の旧・新の原票と結果を保存した。[レビュー](review-opus.md)・[v96の手順](../v96-explicit-numeric-boundary/protocol.md)

実際のv95の新の原票を確認し、両モデルが枠外4枠を含む全12枠で本物のコンマの番号を報告した。青い罫線片を選んだ票は0。従って、今回のコンマ除外は読み手が先に省いた結果ではなく、既存の所属式で処理したものだった。64票の起動設定も両モデルで `high` と確認した。[成分と起動の記録](verification.json)

新方式は、同じ数字間に二つの成分を報告すると未決定にする。旧方式は読み手が付けた余分な文字を過剰転記として数える。このため、文字列の最終結果と新方式の成分選択は別の記録として示す。v95で青い成分が選ばれた票はなく、この分類差は今回の値に影響しない。旧の原票は成分番号を含まないため、旧の文字列が正解でも実際の成分をどちらに対応付けたかは確定できない。

青い罫線片の除外は両版で明記した。画像だけでは区別しにくい黒い筆画の成績はv94の別の条件として残す。Y001とY009の枠の上には表の見出しが写る。数字は枠内に収まり、両版ともこの2枠で一致した。動かしたのはコンマの上下位置で、左右の重なりには差を付けていない。
