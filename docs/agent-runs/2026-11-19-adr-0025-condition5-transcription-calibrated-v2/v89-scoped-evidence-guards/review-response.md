# 追加検査の敵対レビューへの対応

Opus 5.5の `high` は、保存原票を使った開発試算の範囲で承認。重大な指摘0件、軽微な指摘6件。こちらの実行では固定入力255件、保存原票758票、および23対照を確認した。レビューは来歴と純粋関数を調べ、正式な入口への組み込みは対象外だった。[レビュー](review-opus.md)・[試算](replay-result.json)

最初の固定で、対象のFの二票に同じ単一中黒を加えた対照が保留にならなかった。従来の正規表現は行頭の中黒や連続の点には反応するが、行中や末尾の単一中黒は通す。今回の二件の入口だけでこれを保留する検査を追加し、開発版の再固定前後の方針を両方保存した。これ以外の文字を含む点の対照と、どの検査で保留になったかの記録を正式候補に追加する。固定結果の試算は同じだった。[最初の固定](evidence-policy-initial-failed.json)・[試験に使った固定](evidence-policy.json)

白い点の文字位置は探索条件を狭める開発用の確認値。固定150 DPIの拡大で左から五字と白い点の並びを確認し、レビュー担当も独立に確認した。次に版を固定するときは元のPDF描画証明の条件と区別して設定する。現版の方針と正式v64は上書きしない。[画素の根拠](visual-rank.json)

正式の次版では、150 DPIの近傍表示、配布時の枠と座標表示の構成、審査対象のハッシュを明示的に固定する。正式な処理は、小丸で保留すると上書き前の二票の本文をそのまま渡さないため、保留にする前の原票と枠の情報を持つ段で組み込む。正規化、座標の表現、誤った参照名の扱い、審査行と開発資料の重複の記録も確認する。現段階の開発承認の範囲はここまで。
