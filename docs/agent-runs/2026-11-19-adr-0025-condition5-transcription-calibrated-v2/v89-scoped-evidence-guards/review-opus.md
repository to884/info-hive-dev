## 関数ごとに必要な前提と、正式な処理に組み込むときに残る依存

**`reviewed`**
- 受領記録のキー（`state`、`model`、`effort`、`session_id`、`out`）を前提にしています。
- 絶対パスが一致すること、更新時刻の順序が正しいことも前提です。
- 対象のハッシュは見ていません。

**`freeze` と `policy`**
- `inputs` の 255 件は、この worktree の絶対パスです。
- ほかに次のものを含みます。
  - `C:\Windows\Fonts\meiryo.ttc`
  - `info-hive-rag/scripts/rag_pdf*.py`
  - v64 の方法の固定
- v89 のディレクトリは未追跡で、worktree は作業の終わりに消します。消すと `policy` は `FileNotFoundError` で止まり、`replay` を再現できなくなります。
- protocol の「審査済み 2 行を開発との重複として記録」を行うコードはありません。

**`adopt`**
次のものはすべて呼び出し側を信用しています。

- `case["partitions"]`、`case["earlier_reason"]`
- 二票が `decoded` と `NORMALIZE` を通っていること。順位の判定は、空白を除いた文字列を前提にしています。

正式な処理の `image_cases`（v27 `run.py` 177–203 行目、v64 が使う）が作る `case` とは、形が合いません。

- 丸で保留にした行では、`answer` を UNKNOWN に上書きしています。
- `partitions` と `earlier_reason` のキーがありません。
- JSON を通すと、座標は tuple ではなく list になります。

そのまま組み込むと、どれも保留に倒れます。誤った確定は起きませんが、規則は黙って何もしなくなります。

**白い点の経路**
- `unverified_round` を計算し直しません。前の処理が、丸で保留にした行を出典の段に送らないという順序を前提にしています。

**例外になる場合（保留にならない）**
- plain の画像の名前が `source_assets` にないと、`KeyError` になります。
- F の経路で、150 DPI のハッシュとファイルが合わないと、`png_checked` で `ValueError` になります。
