# 再レビューの確認

Opusの再レビューは承認。指摘を受け、起動前の一時ファイルがある試行を保存したまま再送できるようにした。障害のJSONLに配列やnullがあっても、確認できる利用枠情報だけを読む。Solは最初の一束の正常受領を待ってから並行に進む。準備時に、現在の配布コードと実地の両票を確認した事前試験のハッシュを照合する。

失敗して読取の有無が証明できない試行は、合否の基準どおり参照不足。残りの配布の再開は、利用枠に余裕があることを確認して行う。原票と外部台帳をまとめて意図的に書き換えられる状態は、ローカルだけの手順では保証できない。開発・監査の原票と台帳は作業中の受領処理だけが書き込み、履歴の手動操作は避ける。

レビューの文書は通常の作業記録として保持する。方法には現在のコードの版と、その版を実際に通した事前試験を固定する。[再レビュー](review-followup-opus.md)
