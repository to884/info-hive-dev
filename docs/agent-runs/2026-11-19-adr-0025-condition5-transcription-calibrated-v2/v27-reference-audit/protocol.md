# 新規の独立監査の作業手順

条件5の数値、正規化、枠と文字の所属、固定150/450 DPI、100万配置、領域と画像補充の独立監査の標本と合否を維持する。開発6組と公開3組の追加条件を満たした正解・予測、開発で採用した画像指示、照合、ライブラリの版を抽出前に固定する。母集団は前版と同じ評価行から作る。別の種で各層を一度だけ抽出し、過去の開発・監査との重なりを記録する。

監査の画像は固定画素から共通の手順で作る。開発比較と同じ一行単位で、SolとOpusの新規セッションに、対象識別子、画像、枠・軸の説明と回答形式だけを渡す。事前に決めた画像指示を対象グループに共通に使う。既存の本文、原票、正誤、主OCRや元PDFは渡さない。判読不能、不一致、採用できないモデル回答が返った試行はそのまま残す。

試行の予約、CLIの起動直前、完了時の原票のハッシュを、原票の置き場所とは別の追記台帳に保存する。予約後に起動記録がない試行は、起動前の技術障害として保存し、次の試行が可能。起動済みの試行は、利用上限の429、画像読取前の合成メッセージ、消費トークン0、モデルの回答なしをすべて確認したときだけ、解除後に再送する。CLIの記録のみで読取の有無を証明できない利用上限の疑いは再送しない。原票を受領できなかった系統の新規配布を止め、同時に着手済みの原票と別系統は保存する。配布を手動で続ける場合は、再送禁止の試行をそのまま保持した記録を台帳に置く。

Solの配布は一束の正常な受領を確かめてから並行に進める。利用枠が疑われる場合は、サービスの利用枠情報か開発用の試行で再開可否を確かめる。露出が不明な試行は既知標本の参照不足に残る。台帳と原票の両方への手動の書き換えは、来歴確認の対象外である。

二票を受領して、既定の正規化で全文、点の表記と位置を照合する。150 DPIで二つの閾値に同じ明るい穴が閉じ、字の輪郭と確認できる場合は、塗りつぶした丸印の保留に使わない。二票が同じ物理位置を示した点だけを元PDFの描画命令に結び付ける。元の命令だけで位置が証明できない場合は、PDFiumで実際の描画を切り分け、他の命令を除いた状態で固定画素と点の全数を再現する。白以外の地色は対象窓が一色の場合だけ同じ方法を使う。点の近くに別の筆画があるときは、二票の座標からそれぞれ3画素以内で二閾値に一致する唯一の候補だけを隔離描画へ送れる。登録済みのCIDまたは埋め込みフォント対応、その位置と元資料のハッシュがそろった箇所だけに符号を補う。

集計では領域正解・画像補充正解に対する一致、不一致、参照不足を報告する。既知標本の不一致と参照不足の両方が0で、既存の数値条件を満たしてから次に進む。画像補充の未決定層は別に集計する。先行版の独立監査、出典と開発票は変更せず、新版の正式な票にも使わない。
