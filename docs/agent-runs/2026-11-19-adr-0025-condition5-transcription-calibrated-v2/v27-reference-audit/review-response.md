# 初回の敵対的レビューを受けた修正

1. Solの利用枠エラーや既知のOpusの429と型が異なる応答で、新しい束の配布が続く問題を再現した。読取済みの正常な原票を受け取れなかった場合、開始済みの処理を保存し、その系統の次の投入を止める。Codexの失敗イベントからはメッセージを得られるが、それだけでは失敗前の消費トークンや画像読取の有無を証明できない。利用枠が疑われる試行を別に記録し、確証がなければ再送しない。Opusで実際に確認した拒否の条件は維持した。[Codex CLIのイベント定義](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs)
2. 生の配送ディレクトリの外に、試行の予約・起動・完了の台帳を追加した。予約と、外部コマンドを呼ぶ直前の記録、完了時に得たファイルのハッシュを個別に確定する。起動前の途中状態に対応し、起動後に原票を消すと、同じ束の読み直しが拒否される。台帳の書き込みは一時ファイルを同期し、存在しない確定パスにリンクする。
3. 既定の事前固定で記録したライブラリの版と入力を、抽出、画像作成、配布、集計、出典確認の各段階で照合する。
4. v31の対照147行目で一方が枠端に「告」を加えた。二票が割れた対照は開発記録に残す。訂正対象に使った行は独立の全文二票と固定画素が一致した場合に限る。対照の留保を監査の方法に固定し、対照の二票が同じ誤りで一致した場合はこの候補を固定できない。

6束の同時投入を使った対照で、型から外れた利用上限の疑いを受けると残り6束が未着手のままになった。起動前の試行を再送可能と扱い、起動後のファイル欠落を拒否した。固定の開発画像1行は新しい実装でSolとOpusが各一票返し、受領の再現を確かめた。[事前試験](transport-preflight.json)
