# 枠端と小点の表示を改めた独立監査

正式の入口は `official.py`。配布の再確認と抽出前の全寸法の検査は `preflight-final.json` を使う。`run.py` と `audit.py` は比較と回帰を再現するために保存した。

v27と同じ二つの監査、数値、固定150/450 DPI、枠、所属、正規化と全配置を使う。過去の標本と原票を保存し、次の候補と手順を事前に固定してから別の種で一度抽出する。領域正解・画像補充正解とも既知標本の不一致と参照不足を0とし、画像補充の未決定層は別集計とする。

SolとOpusの新規セッションの一行一束と着手台帳は同じ。枠の端では固定画像から枠の外の色と、二つの閾値で一致するインク成分が軸方向で枠に入る長さを示す。数値を付けるのは条件に合う成分の一部で、小さい塗り点などは番号がない場合も固定画像で確認する。読者は各成分が字全体に対応するか確認し、所属は従来どおり割当軸の半分以上と直交中心で判断する。

両端の新しい画像を付ける行では、旧画像「枠への入り方」の説明とその目盛りへの言及を取り除く。番号のない字や小点も確認する説明に換え、丸印の位置は「横座標」に統一する。段落の円を見分ける説明は固定方法の横軸指示に入っている。

幅が120画素より広く1200画素以下で、高さ35画素以下の横軸では、固定150 DPIの端から前後の段落にある丸印の位置を見る表示を加える。本文の前に独立する項目丸、数字や本文中の小点と句点、図表の見本を視覚で区別する。行頭・行末の枠端、該当する段落の画像、元の全区間と横座標を必ず添付する。24枚に収まらない場合は補助的な拡大を減らし、必須画像だけで超える場合は横座標の画像を画素を変えず2枚ずつ上下に置く。全ての束で必須画像、横座標の区間と説明の対応を送信前に調べる。

両票が同じ場所にある曖昧な丸を記録し、150 DPIの切り分けだけで位置を証明できない場合は、450 DPIの二つの閾値それぞれで候補が1個あり、同じ成分に対応することを確かめる。元PDFを切り分け、その成分の対応する150 DPIを再現し、他の描画と埋め込みフォントの対応を確認して、許可された符号だけ補う。本文と曖昧でない符号は、独立な画像二票で扱う。開発で扱った行と旧標本も母集団に含め、抽出との重複を別集計する。[v27の手順](../v27-reference-audit/protocol.md)
