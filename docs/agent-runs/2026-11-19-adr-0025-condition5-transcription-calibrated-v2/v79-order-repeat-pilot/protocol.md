# 列順の課題を複数回の独立票で再検証する

過去の監査・領域の修復・個別の再読まで除外して公刊の開発データを洗い出した。短枠の暗いインクが二つの幅に分かれ、その左右それぞれで上下に十分な濃い帯があることを要件にした。この範囲で官報の未使用対象を得られなかったため、開発合成で条件を再現する。以前の官報の7行は、既知の再現用に加え、新規素材の集計と分ける。[公刊資料の候補探し](screen.py)

合成は、縦の2列を横切る2字6行と、横書きの上下に別の行が続く表3行、縦書きが多い紙面に配置した横書きの2字3行で固定する。左右の本文は異なる一字とし、描画時の座標と配置から正解の順を作る。文字、表示、並びは旧・新の実行と新規セッションに共通。既存の固定画像と合否基準は保持し、合成画像を正式の未使用資料に入れない。合成では、配置、行の向き、枠内の部分の見え方を固定150と450 DPIで示し、正解・旧票・出典を読み手に渡さない。

旧・新ともSol・Opusを `high` に固定し、各行各版を別個の新規セッションで3回読む。行と反復の組を比較する。合成の縦列6行が旧指示で計4回以上逆転し、かつ少なくとも2行で逆転した場合に、改善を見る難度に達したとする。新指示では旧よりOpusの逆順が18票中4票以上減り、既知7行で逆順が増えず、対照6行で一致する誤読・脱落・過剰転記・未決定のどれも増えないことを、この開発の採用条件とする。難度に届かないか同じ誤りが増えたら、正式の手順へ入れない。条件5の数値の合否基準は適用段階が異なり、この開発の採用条件から独立する。
