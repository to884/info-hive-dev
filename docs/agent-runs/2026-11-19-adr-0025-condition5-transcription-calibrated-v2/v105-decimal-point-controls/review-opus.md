### [Major] 黒点だけがアンチエイリアスのない 2 値の円で、450 DPI の輪郭から描画の区分が分かる

**対象**
`generate.py:75-76`（`ImageDraw.ellipse`）、`generate.py:65`（`draw.text` で描くピリオド）、`generate.py:77`（対照の検査）

**根拠**
同じ条件で小さな再現をしました（Pillow、56px、fill=231、THRESHOLD=72）。
- 書体のピリオド：外接枠は Arial・Times・Calibri が 6×6、Consolas が 10×9 です。縁には中間の濃さの画素があり、その値は Arial で 2 種類、Times で 17、Calibri で 18、Consolas で 31 種類です。
- 黒点（`ellipse`, r=3.84）：外接枠は 8×8 で、画素は 52 個すべてが値 231 の 2 値です。中間の濃さが 1 つもありません。

`ImageDraw.ellipse` はアンチエイリアスをかけず、FreeType の文字はかけます。450 DPI の画像は縮小しない原寸（`k==3` のとき `digits_pixels` と `piece` をそのまま使う）なので、この違いがそのまま見えます。

**問題**
- 両方の指示が 450 DPI の「輪郭」を見るよう求めています（旧は v102 PROMPT の「まず450 DPIの拡大図で輪郭を見ます」、新は run.py:36 の「輪郭に見える根拠」）。
- そのためモデルは、Z015 のような実際の汚れを見分ける力ではなく、合成の痕跡（縁が階段状か、大きさが 8 か 6 か）で黒点と見分けられます。aligned-noise と both の過剰転記が少なく出て、点の所属を判定する力を高く見積もります。
- 新指示は輪郭と大きさを根拠に挙げることをより強く求めるので、旧と新の差にもこの痕跡が混ざります。
- generate.py:77 は `tobytes()` が完全に一致するかを見るだけです。円と字形が一致することはまずないので、この検査は何も保証していません。描画の痕跡で見分けられないことを確かめる検査がありません。

**検証方法**
1. `render(b, "aligned-noise")` と `render(b, "decimal-only")` の 450 DPI 画像から点の領域を切り出す。
2. 0 と 231 の間にある画素の数と、外接枠の寸法を比べる。上の再現と同じく、黒点は中間値が 0 になるはずです。

**修正の方向性**
- 黒点もピリオドと同じ過程で描く。例えば次のどちらかにします。
  - 9 倍以上の解像度で描いてから縮小する。
  - 書体の外形と同じ処理を通す。
- 大きさは書体の点と同じ寸法帯にそろえる（または、ずらす量を意図した変数として別に記録する）。
- 「描画の区分を縁の中間値と寸法から分類できない」ことを、生成のときの検査に加える。
