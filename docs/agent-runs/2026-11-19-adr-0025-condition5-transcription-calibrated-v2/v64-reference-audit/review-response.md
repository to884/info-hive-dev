# 事前固定の入口に対する再レビューの対応

Opusの二回目のレビューでは、正式経路で読み込むPythonコードの一部が事前固定から漏れたと指摘された。v47の事前検査の全入力を新しい入口から再ハッシュし、作業ツリー内のPythonの読み込みを記録する。診断と出典、座標画像など後段のモジュールも事前に読み込む。固定後は実際に読み込む作業ツリー内のコードのハッシュを照らす。

開発の検査では、レビューが挙げた7ファイルを固定一覧の写しから一つずつ外した。7例すべてを拒否した。枠の表示、大小の丸、出典の経路、既定の数値基準と母集団は維持した。

新たな小点の出典照合は、証拠の不足と想定外の異常を区別する。証拠の不足であった行は正式の結果からハッシュで確認できる記録に残す。固定した二票と実際の入口で官報117・120行目を確認し、大きい項目丸の対照、ハッシュの異なる対照を拒否した。

最終の画像依頼で両軸の指示を確認する。正式監査では同じ二つの母集団と判定を使い、開発時に訂正した行の重複件数と、重複を外した既知標本の値を別記する。再レビューの後に行う事前確認と母集団・抽出の固定までは、開発検査として扱う。
