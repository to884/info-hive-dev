# 条件5の開発診断　点線の画素・符号・採点可能性

長い横行4行で区画ごとの転記と行全体の転記を比較した。どちらも既存未決定2行は未決定、既存確定2行は一致1行・不一致1行だった。二つの未決定行では差が点線に集中した。防衛白書の1行は中黒9個とピリオド9個、災害資料の1行は通常転記で中黒56個とピリオド12個、区画転記で中黒56個とピリオド51個だった。実際の固定150 DPI画像では、一定間隔の独立した点がそれぞれ9個と56個見つかった。

## 画像と出典の照合

画像補充の横軸を固定資料から再調査した。横軸の未決定274行中193行に点線候補があり、内訳は公開評価2回目の137行、評価3回目の56行だった。Opusのレビュー後、位置の1画素差、先頭の小成分、1字が複数点を作る場合に対応した別版でも、未決定の検出行数は同じだった。改訂版では既存確定1,951行中10行にも画像候補があった。画像の点の検出だけで文章上の点線と断定できない。

防衛白書の目次2ページでは、PDFの描画命令のCID 668（`029C`）に埋め込みのToUnicodeがU+FFFDを指定していた。フォントが宣言するAdobe-Japan1の対応はU+2026。CID 1の埋め込みToUnicodeはU+0008で、これもPDFiumの抽出字数を物理的な点の個数に使えない理由となる。

防衛白書の2ページをメモリ上で複製し、フォント名と描画行列で対応した点線の描画オブジェクト137個だけを残して固定150 DPIで再描画した。全5,346成分は元の描画命令にある三点リーダー1,782字×3と一致した。元画像から見つけた成分の座標は、候補137行中135行で再描画とすべて一致した。災害資料では55行で中黒の符号と点を照合できた。うち2行では個別の原点の対応が1字ずれていたため、固定の画素、両抽出器、他の字の対応、同一符号の連続列全体を照合した。別の図中1行は符号を確かめられなかった。

## 画像だけで区別できない符号

同じ点線を描く二つのPDFを作り、ToUnicodeの対応だけを変えた。150 DPI・450 DPIのRGBは完全一致したが、現行の正規化後の文字は片方がピリオド3字、もう片方が中黒3字となった。画像の点数を確かめられても符号化を確かめられない場合がある。

2026-11-19、作者は、画像だけでは符号を区別できない行に限り、元PDFの描画命令とフォントのCID対応を、画像の二読とは独立した補助証拠として正式な正解と監査に使うことを認めた。数値の合否と固定画像は従来どおり。新しい参照手順を別版に固定し、過去の監査はその時点の記録として維持する。
