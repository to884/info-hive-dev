# v15の配送修正と確認

v14のSolの実行記録は、PNGを相対パスで指定していた。CLIは独立性のために空の一時フォルダーで起動し、そこを基準にパスを解決していた。標準エラーで添付PNGを開けなかったことを確認した。OpusはPNGを標準入力に含めて送るため、14束40行の原票が残った。v14の着手記録と原票147点を固定し、有効な両票は0行と記録した。[v14配送記録](../v14-reference-audit/delivery-record.md)

同じPNGを捨てず、受領の版だけを分けた。v14から固定した379行・190束の画像、ID、依頼の本文と正解を保持した。配布側で実行フォルダーを絶対パスに変換し、絶対パスで各PNGを渡す。新しい配布のSHA-256は `1c58d8d1773ae06c77aadf1e5ad28b6e1fd8303487f08fbdedb1c1b2c3216e75`。開発のPNGにだけ記した10字を、同じ配布・集計の流れでSolとOpusがいずれも完全転記してから、正式な配布を始めた。

Opusのレビューでは、エラーのパス表記が別形式の場合と、前版原票を誤った位置に探した場合の検査不足が指摘された。配布を変更せず、別の検査でv14の全原票のSHA-256と既知のセッションIDを再現し、v15の実行引数と添付エラーを調べている。[配送の独立した確認](verify_transport.py)
