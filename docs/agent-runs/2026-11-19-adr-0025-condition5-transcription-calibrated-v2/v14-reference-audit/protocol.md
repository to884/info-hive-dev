# 正解品質の独立監査 v14

新しい開発試験と固定画素で確認した行境界の訂正を反映した正解を対象にする。開発6組と公開3組の追加条件、旧v9教師で固定した予測、閾値、正規化、100万配置とすべての評価行を前版から維持する。既知の正解について不一致・参照不足がともに0のとき、それぞれの監査を通過とする。画像補充の未決定層は独立して記録する。

両母集団、公開の組、印と主OCRの正誤による層から、前版と同じ順序、各層15行か全数で一度だけ抽出する。種は領域 `2026112001`、画像補充 `2026112002`。以前に開発や監査で見た行も除かない。抽出前に正解、予測、方法、開発で見た行と層の分母をSHA-256で固定する。

画像票はSolとOpus各一回。固定150 DPIで枠への所属を確かめ、固定450 DPIで字形を読む。画像以外の参照、他の票、読んだことのある会話、印と正解を渡さない。横軸の短い枠は、文字のつながりが縦書きの複数列であれば横投影の目印で列ごとに書く。横書きは一つの全文として書ける。縦軸には全文に加えて行端・短い枠の細部を示し、区画別の転記を求めない。配置は固定画素と枠だけから全行に同じ規則で作る。

小さくて字種を区別できない丸印・点線は、見える位置と周囲の本文を二票で別々に確認する。両票の本文と点の形・所属・位置が従来の範囲内でそろったときに限り、コードポイントの判断に元PDFの描画命令とフォントのCIDを使う。画像で字種が区別できる記号として印を使わなかった場合も、9〜10画素の小さな黒い丸が行頭にあると測定できるときは、根拠の足りない字種の一致として保留する。黒い円の見た目だけで出典を当て直さない。ほかの本文・字形は二票を照合する。

出典を照合する頁は二票から `resolve.py source-requests` で決める。出典を読むのは `source.py` と pypdf 6.21.0で、元PDFの間接参照の幅を解決し、抽出された描画命令をすべて保つ。開発時の同一とみなす命令の折り畳みは使わない。位置を一意に証明できない命令が重なれば保留する。出典記録の対象、実装のSHA-256とAdobeの対応表を `resolve.py collect` で確かめる。

着手は各束と系統ごとに原票と別の記録を保存する。中断したときは、その記録がない組だけを起動する。開始済みの束に原票がない場合は参照不足として保存する。再抽出、開発票の流用、採点や正解の上書きは行わない。
