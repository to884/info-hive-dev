- 画像補充正解1行の訂正後、既存予測と同じ閾値0.15で開発6組と公開3組の追加条件を確認した。[訂正と採点](../v14-reference-candidate/development-result.md)
- Opusのレビューで、出典取得の出力形式と受領形式が一時的に不整合であることと、小さな丸の保留が黒丸の一字種に限られることを確認した。抽出前に前者をそろえ、後者は丸の画素と二票の位置から判定するようにした。元の7頁で出典取得と受領を通し、従来確定した4行の符号が同じであることを確認した。確認済みの開発20行で配布画像を作る試験を行った。
- 着手記録、OSのロック、中断からの再開は模擬試験とOpusのレビューで確認した。Windowsで親を止めた後に子が残っても、現行の読取は子の標準出力を親が受領してから原票を書き、原票の完了記録がない束は未受領として扱う。
- 2026-11-20に領域5,988行、画像補充2,865行の母集団と層別分母を保存した。母集団の固定は `de2be5e36c0b4997269f52dd6188bda9ddc35526a7c59ac85e0e522c47195b9d`。正式標本を一度だけ抽出した。和集合379行のSHA-256は `52bad13bb0efecd23319dd3038b2c79bf7cceb10ff6b77b53da1b412d52daeb0`。
