# 破綻しないディレクトリ構成案 の総括

## 推奨

4 案に共通する骨格（作業領域の根の直下に作者の番号付きディレクトリを並べ、`90_Wiki` と `91_Raw` を兄弟に置き、wiki の走査を `90_Wiki` に閉じ、役割→ディレクトリの対応を根の設定ファイルに持つ）をそのまま採り、細部はレビューで確かめられた側に寄せて統合する。土台はエージェント D の「外側の案内ファイル＋内側の作業領域設定＋`log_scope`」による探索方式とし、そこにエージェント A の現行コードとの食い違いの一覧、エージェント C の Foam 設定の正確な知見を足す。生成 SVG の置き場は ADR-0005 のまま `90_Wiki/assets/` に残し、作者の決定 2 の範囲は作者に確認する。

統合後の要点は次のとおりである。

| 論点 | 採る案 | 出どころ |
| --- | --- | --- |
| 作業領域の根 | グローバルは `~/info-hive/`、プロジェクトは `<プロジェクトルート>/<プロジェクト名>/`。Foam と VS Code で開くのも、`.foam/templates` を置くのもこの根 | B、C、D（A も見直しで同意） |
| 設定ファイル | 根の直下に JSON（標準ライブラリで読める）。役割キーは英語 | A（B は見直しで YAML を撤回） |
| 探索 | 外側のプロジェクトルートに案内だけのファイルを置き、祖先探索はサブモジュールの `.git` で止めない。`log` の既定はグローバルで、案内の `log_scope` でだけ切り替える。指定先が壊れていれば止め、黙ってグローバルに書かない | C、D |
| wiki との境界 | 日付ノートとノートは `90_Wiki` の外。lint と検索の走査は `90_Wiki` だけに渡す | 4 案一致、コードで確認 |
| 改名 | `90_Wiki` と `91_Raw` は原則改名しない。他の改名も「設定を直すだけ」ではなく、テンプレートの `filepath`、本文リンク、`raw:` を含む移行手順にする | A の規則を D、C の指摘で補正 |
| 日付・週次 | `20_Daily/YYYY/MM/YYYY-MM-DD.md`、`30_Weekly/GGGG/GGGG-Www.md`（ISO 週年）。古い年の日付ノートは Archive に動かさない | A、B、C。D の指摘で Archive を禁止 |

| プロジェクト wiki の命名 | 要件定義書 D-06 の `<project-id>--<topic-slug>.md` を維持 | A、B（C、D は見直しで追加） |

## 批評で動いたこと

- **エージェント A** は、Foam のルートと `.foam`、`.vscode`、対応表をプロジェクトルートに置く案を撤回し、内側の `<project-id>/` に移した。コードのサブモジュールが Foam の索引に入ること、グローバルとプロジェクトで同じテンプレートを使えないことを認めた。除外設定の名前も `foam.files.exclude` に改めた。
- **エージェント B** は、設定を YAML から JSON に改め、「Git の根まで探索し 1 段下も見る」方式を捨てて外側の案内ファイル方式に乗り換えた。古い年の日付ノートを Archive に動かす運用も取り下げた。
- **エージェント C** は、`init` 引数だけから wiki 全体の互換性を言い過ぎていたと認め、取り込み画像の `assets/sources/<slug>/` という追加階層を撤回して ADR-0004 の `assets/<slug>/` に戻した。D-06 の命名も追加した。生成 SVG を raw に置く案は「確定済みの意味としては扱わない」と後退させた。
- **エージェント D** は、画像原本のハッシュ命名案を引っ込め、D-06 の命名と `wiki_evolve_loop.py` の件を取り込み、`daily` キーの有無から保存範囲を推測しない方針に改めた。
- **最も鋭い反論**は、B の探索方式への指摘である。B 自身が「cwd はコードのサブモジュールの中であることが多い」と書きながら、探索を Git の根で止めていた。サブモジュールの Git の根は外側の親ではないので、プロジェクト用の入力が黙ってグローバルに落ちる。A、C、D の 3 者が独立に同じ欠陥を指摘し、B も認めた。これは決定的で、探索方式を C・D の 2 段構えに統一する根拠になった。
- **次に効いた反論**は、A の「ほかのディレクトリは対応表を直すだけで改名できる」「ファイル名だけでリンクは切れない」に対する C と D の指摘である。テンプレートの `filepath`、パス付きリンク、`$FOAM_PREVIOUS_DAILY_NOTE` の探索は対応表では直らない。A は規則 1 の保証を弱める形で受け入れた。
- 一方、B の「フォルダー名付きの `filepath` を単一ルートで使うと二重のフォルダーができる」は、C と D が Foam の公式文書で食い違いを確かめた。これを根拠にした独自のパス補正は不要になった。

## 推奨案が残る理由

- **wiki の走査範囲**：`wiki_lint.py` の `collect_pages` は渡した wiki ルートの下だけを再帰走査し、除外は `indexes`、`graph`、`raw`、`.evolution` などの固定名で判定する。4 者すべてが現在の作業ツリーで一致を確認した。`91_Raw` を wiki の中に入れると除外名に一致せず走査される点も一致。したがって兄弟配置が唯一安全である。
- **`index.md` は被リンクに数えられない**：D の指摘を B と C が確認した。日付ノートをインデックスに並べても孤立は消えないので、wiki の外に置く設計が必要になる。
- **初期化は番号付きの名前を受け付ける**：`init_wiki.py` は `project_root / wiki_dir`、`project_root / raw_dir` で場所を決める。4 者が確認。ただし `SCHEMA.md.template` の `wiki/`、`raw/` は置換されずにコピーされる（A、D が発見、B、C が確認）。
- **`wiki_evolve_loop.py` の raw 決め打ち**：`--raw` を省くと `args.wiki.parent / 'raw'` を作る。A だけが発見し、B、C、D がコードで確認した。兄弟配置では `~/info-hive/raw/` が勝手にできるため、各入口で解決済みの `--raw` を渡す要件を付ける。
- **`raw:` は文字列のパス**：`wiki_graph_extract.py` は `raw:<値>` をノード ID に使う。A の主張を B と D が確認。`91_Raw` の改名禁止の根拠になる。
- **Foam の除外設定名**：`foam.files.exclude` が現行で `foam.files.ignore` は非推奨。C の主張を A、B、D が Foam の `package.json` で確認した。
- **Foam の単一ルートでのパス解釈**：フォルダー名付きの `filepath` は単独で開いても使える。C と D が公式文書で確認し、B の説明が食い違いだった。
- **`$FOAM_PREVIOUS_DAILY_NOTE` はパスの型に依存**：パス変更前や移動後のノートは見つからない。D の主張を B と C が確認した。古い日付ノートを Archive に移さない根拠。
- **JSON の選択**：wiki は Python 3.10 以上で、lint・stats は標準ライブラリだけ。B が `retrieval-setup.md` と `CONTRIBUTING.md` で確認した。
- **ISO 週**：2026 年は 53 週あり、2027-01-03 までが 2026-W53。A と B が独立に計算し、C が再計算して一致した。Foam には `FOAM_DATE_WEEK` と `FOAM_DATE_WEEK_YEAR` があるので、テンプレートとスクリプトで同じ値を作れる。ただしこの 2 変数が ISO 週かは未確認。
- **生成 SVG の置き場**：ADR-0004（raw の不変性）と ADR-0005（`wiki/assets/`）は作者の決定 2 と同じ日に承認されており、どちらが後かは確かめられなかった（B が確認）。承認済みの 2 つの ADR と raw の定義を変える費用を、作者の一言の広い解釈だけで負うのは根拠が足りない。C も見直しで「確定済みとしては扱わない」とした。したがって ADR 維持を推奨し、作者に確認する。

## エージェントごとの要約

**エージェント A** は、作者のツリーをほぼそのまま採り、「表示名と識別子の分離」「`90`・`91` は改名しない」「4 つのルートを一致させる」「ファイル名に完全な日付」「境界を wiki の外に引く」の 5 規則を提案した。現行コードの読み込みが 4 案で最も深く、`wiki_evolve_loop.py` の raw 決め打ち、`SCHEMA.md` が置換されないこと、`91_Raw/experiences/`、JSON を選ぶ根拠は他の 3 者が確認して取り込んだ。当たっていた指摘は、Foam のルートをプロジェクトルートにしたためコードが索引に入ること、テンプレートの `filepath` の例が自分の対応表と食い違うこと、「対応表を直すだけで改名できる」「名前だけでリンクは切れない」が条件付きにすぎないこと、`daily` キーの有無で既定を兼用すると誤設定と意図を区別できないこと、Inbox からの「移動」が現行仕様にないことである。

**エージェント B** は、根を 1 つに固定して番号付きディレクトリを並べ、`.foam` を内側の作業領域に置き、役割→ディレクトリの対応を `info-hive.yaml` に持つ案を出した。ADR-0005 と作者のツリーに最も忠実で、`$FOAM_PREVIOUS_DAILY_NOTE` が数値の年月日パスを前提にすること、ASCII の並び順で `A0_Archive` が最後になること、ISO 週年の根拠は正確だった。当たっていた指摘は、探索を Git の根で止めるとサブモジュールから作業領域を見つけられず黙ってグローバルに書くこと（3 者一致）、Foam の単一ルートでのパス解釈が公式文書と食い違うこと、YAML が依存を増やすこと、`foam.files.ignore` が非推奨であること、古い日付ノートの Archive が探索設計と衝突することである。

**エージェント C** は、作者の番号付き構成に、作業領域を明示する設定、各ディレクトリの書き手、移動させないファイルの規則を加えた。外側に案内だけの `project.json`、内側に `workspace.json` を置き、祖先探索を `.git` で止めない構造は、A と D が最も丈夫と評価した。`foam.files.exclude` を正しく書いた唯一の案で、`.github/instructions` を外側のリポジトリに置く判断、未知の設定項目の保持、設定が壊れていたら書き込みを止める規則、タイムゾーンや同時編集の論点も正確だった。当たっていた指摘は、`--project` を付けない限り常にグローバルに書く設計が入力の軽さに反すること、生成 SVG を `91_Raw/assets/figures/` に版番号付きで置くと承認済みの 2 つの ADR と raw の定義を変えること、取り込み画像の `assets/sources/<slug>/` が ADR-0004 と異なること、`wiki_evolve_loop.py` の見落とし、D-06 の命名の欠落、`YYYYMMDD-HHMMSS-件名` の命名が人には重いことである。

**エージェント D** は、保存範囲、編集責任、正本、探索範囲の 4 つの境界を固定する整理で、外側 `P/.info-hive.json` に `log_scope` を持たせ「ローカルの wiki があるだけで log の既定を変えない」と明記した。`index.md` が被リンクに数えられないこと、`$FOAM_PREVIOUS_DAILY_NOTE` のため古い年を Archive に動かせないこと、「一意性の単位は作業領域 ID と日付」という定義、`graph/` をまるごと Git から外すと `ontology.yaml` を失う注意は、A と B が確認して価値を認めた。当たっていた指摘は、生成 SVG を raw に置き「raw 全体を一律に不変と扱わない」とした点、取り込み画像のハッシュ命名が ADR-0004 と食い違うこと、`80_Code` が「番号は W 直下だけ」という自身の規則に反すること、週次を月曜日の日付で名付けると Foam の Markdown テンプレートの変数では作れないこと、`wiki_evolve_loop.py` と D-06 の見落とし、非推奨設定の出典が daily-notes.md ではなく `package.json` であることである。

## 残るリスクと未確定事項

- **生成 SVG の置き場（作者の決定 2 の範囲）**。選択肢は、(a) 取り込んだ画像だけを指すと読み、SVG は ADR-0005 どおり `90_Wiki/assets/` に残す、(b) SVG も `91_Raw/assets/` に置く。(a) は ADR を変えずに済み、browse の配信設計もそのまま。(b) は ADR-0004 と 0005 の改訂、raw の意味の再定義、ページの深さに応じた相対パスの生成、版の管理が要る。どちらでも、ADR-0005 の `assets/<slug>-NN.svg` がページ相対で解決しない不備は直す必要がある。
- **プロジェクトの形**。4 者とも「`<プロジェクトルート>/<プロジェクト名>/` が作業領域で、コードは兄弟のサブモジュール」と読んだが、解釈である。サブモジュールを直下に並べる（B、C）、`repos/` にまとめる（A）、`80_Code/` にする（D）の 3 案があり、作者の指示にあるのは「サブモジュールとして配置する」だけ。番号を外側にも広げるかは作者が決める。
- **設定ファイルの名前と場所**。`.info-hive/workspace.json`（A、C）か `.info-hive.json`（D）か。形式は JSON で収束した。外側の案内ファイルに `log_scope` を持たせる点は収束したが、キー名は未定。
- **`50_Knowledge` の直下か `50_Knowledge/notes/` か**。作者のツリーは直下。C と D は ADR-0006 の `notes/` との連続性で 1 段足した。直下にするなら ADR-0006 の `notes/` を読み替える ADR が要る。
- **週次の名前**。ISO 週（`GGGG-Www`）か、週の月曜日の日付か。ISO 週は Foam の変数で作れるが、`FOAM_DATE_WEEK` が ISO 週かは未確認。月曜日の日付は JavaScript テンプレートが要り、Foam の MCP は JS テンプレートを拒む。
- **ADR の番号と場所**。`70_ADR` は 4 者とも仮。グローバルにも置くかは未決。ADR を wiki のソースとして取り込むかも未決。
- **`91_Raw` を Git に入れるか**。LFS か、除外か、外に置くか。PDF が増えるとリポジトリが重くなる。
- **Inbox から `91_Raw` へは移すか写すか**。現行の `ingest` は「raw に置く」としか定めていない。移動にすると Inbox への既存リンクを更新する必要がある。
- **`log` の実装で決める事項**。タイムゾーン、日をまたぐ作業の所属日、休日を挟んだ繰り越し元、Foam と `log` の同時編集。構成だけでは解決しないが、作業領域の設定に持たせる値として今決めておくとよい。
- **Foam の実機で未確認のこと**。`filepath` の中間ディレクトリを Foam が作るか、`foam_template` ブロックが生成ノートから消えるか、`FOAM_DATE_WEEK` が ISO 週か、マルチルートでの `filepath` の解決。4 者とも実機試験は行っていないので、構成案だけで「破綻しない」とは保証できない。採用前に、サブモジュールからの入力、Foam と `log` による同日ファイルの作成、改名後の参照、再取り込みを同じ試験用領域で確かめるのがよい。
- **既存の `~/wiki/`、`~/daily/` の移行**。新規作成だけ新構成にするか、既存も移すか。どの案も自動移動はしない。
- **wiki の文書と既定値の更新**。`SKILL.md`、`init.md`、`retrieval-setup.md` の `~/wiki/` を `~/info-hive/90_Wiki` に変えるなら、利用者に見える変更として SemVer の版を上げる。wiki に設定ファイルの読み込みを足すかは、ADR-0006 の「wiki のコードは変えない」とは別の変更として判断する。
