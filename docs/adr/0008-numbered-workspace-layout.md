# ADR-0008：info-hive の作業領域は番号付きのディレクトリで構成する

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月4日 |
| 改訂 | 2026年11月4日：wiki と raw のディレクトリ名を `90_Wiki` と `91_Raw` から `wiki` と `raw` に改めた。wiki プラグインの `/wiki:init --global` の既定（`~/info-hive/wiki/` と `~/info-hive/raw/`）に合わせたものである |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0004（raw に置く Web ページ）、ADR-0005（wiki の図）、ADR-0006（プラグイン `log`。保存先とノートの置き場所を本書で置き換える）、ADR-0007（rag の構成）、`docs/agent-runs/2026-11-03-info-hive-directory-layout/`（4 体のエージェントによる構成案と総括） |

## 背景

info-hive のプラグインは、`wiki` に加えて `log` と `rag` を作る。これまでは、プラグインごとに保存先を決めていた。wiki は `~/wiki/` か `<プロジェクト>/wiki/`、log は `~/daily/` か `<プロジェクト>/daily/`（ADR-0006）である。プラグインが増えると、利用者の手元にディレクトリが散らばる。また、プラグインどうしで置き場所の決め方が食い違う。

そこで、利用者の作業領域を 1 つの根の下にまとめ、その中の構成を決めた。構成案は 4 体のエージェントが独立に作り、相互にレビューした。総括で推奨された骨格を、決定者が重なりと漏れのないように整えた。

## 決定

### 作業領域

| 項目 | 決定 |
| --- | --- |
| グローバルの作業領域 | `~/info-hive/` |
| プロジェクトの作業領域 | `<プロジェクトルート>/<プロジェクト名>/`。開発するコードは、プロジェクトルートの直下にサブモジュールとして並べる |
| ディレクトリ名 | 先頭に 2 桁の英数字とアンダースコアを付ける。名前は既定値で、設定で変えられる。wiki が書く `wiki` と `raw` だけは番号を付けず、プロジェクトの wiki（`<プロジェクト>/wiki/` と `raw/`）と同じ名前にする |
| VS Code と Foam | 作業領域の根を VS Code で開く。`.foam/templates/` は作業領域の根に置く |
| 使わない名前 | `40` 番は使わない（`40_Projects` は置かない）。グローバルの作業領域にはプロジェクト固有の情報を置かず、プロジェクトの作業領域はそのプロジェクトの情報だけを扱うからである |

### グローバルの構成

```text
~/info-hive/
├── .info-hive/workspace.json
├── .foam/templates/daily-note.md
├── .github/instructions/
├── 00_Inbox/
├── 10_Assets/
├── 20_Daily/2026/11/2026-11-04.md
├── 30_Weekly/
│   ├── template.md
│   └── 2026/11/2026-11-02_11-08.md
├── 50_Notes/
├── 60_Output/
├── 92_RAG/
├── A0_Archive/
├── wiki/
│   └── assets/
└── raw/
    └── assets/
```

### プロジェクトの構成

```text
<プロジェクトルート>/                    Git リポジトリ
├── .info-hive.json                   案内のファイル
├── .github/instructions/
├── <プロジェクト名>/                   作業領域
│   ├── .info-hive/workspace.json
│   ├── .foam/templates/daily-note.md
│   ├── 00_Inbox/
│   ├── 10_Assets/
│   ├── 20_Daily/
│   ├── 30_Weekly/
│   ├── 50_Notes/
│   ├── 60_Output/
│   ├── 70_ADR/
│   ├── 92_RAG/
│   ├── A0_Archive/
│   ├── wiki/
│   └── raw/
└── <開発するコード>/                   サブモジュール
```

グローバルとの違いは、`70_ADR/` を置くこと、案内のファイル `.info-hive.json` をプロジェクトルートに置くこと、`.github/instructions/` を作業領域ではなくプロジェクトルートに置くことの 3 つである。`70_ADR` の番号は任意である。

### 各ディレクトリの役割

| ディレクトリ | 設定のキー | 置くもの | 書き手 |
| --- | --- | --- | --- |
| `00_Inbox` | `inbox` | 後で整理する Markdown のファイル | 人 |
| `10_Assets` | `assets` | Markdown 以外のファイル。`00_Inbox` と `50_Notes` から参照するものと、wiki に反映しない参考資料（Web から取り込んだ資料など） | 人 |
| `20_Daily` | `daily` | 日付ノートと、そこに貼る画像。画像は日付ノートと同じディレクトリに置く | log と人 |
| `30_Weekly` | `weekly` | 週次の見直しと、保留中のタスク。テンプレート `template.md` | log と人 |
| `50_Notes` | `notes` | カテゴリに分けて整理した Markdown。log の下書き、Markdown にした参考資料（wiki に反映しない Web ページ）、research のコマンド・エージェント・スキルで作った調査のレポートを含む | 人と log |
| `60_Output` | `output` | 成果物。形式を問わない | 人 |
| `70_ADR` | `adr` | 設計の決定。プロジェクトの作業領域だけに置く | 人 |
| `wiki` | `wiki` | wiki のページと、モデルが描いた svg（`assets/`） | wiki |
| `raw` | `raw` | wiki の原資料と、取り込んだ画像（`assets/`） | wiki |
| `92_RAG` | `rag` | rag プラグインのデータ | rag |
| `A0_Archive` | `archive` | 使わなくなったもの。ユーザーが `/log:archive` で明示的に移す | 人 |

### 置き場所の規則

| 項目 | 決定 |
| --- | --- |
| 一行のメモと `00_Inbox` | 一行で書けるものは日付ノートの `## メモ` に、1 つのファイルになるものは `00_Inbox` に置く。`/log:tidy` は日付ノートの `## メモ` を振り分ける。`00_Inbox` を整理するのは人である |
| `50_Notes` と wiki | `/wiki:ingest` は `raw` と `wiki` に書き、`50_Notes` には書かない。ユーザーの指示があれば、`50_Notes` のノートを `raw` に写してから `wiki` に反映する |
| Web ページ | wiki に反映するものは ADR-0004 どおり `raw` に置く。反映しないものは、Markdown にしたら `50_Notes` に、Markdown にしないなら `10_Assets` に置く |
| 画像 | モデルが描いた svg は `wiki/assets/`（ADR-0005）、wiki に取り込んだ画像は `raw/assets/`、日付ノートの画像は日付ノートと同じディレクトリ、`00_Inbox` と `50_Notes` から参照するものは `10_Assets` に置く |
| 成果物 | 形式にかかわらず `60_Output` に置き、`10_Assets` には入れない |
| `50_Notes` のカテゴリ | 利用者がディレクトリで決める。プラグインはカテゴリを固定せず、下を再帰的に読む。log の下書きは `50_Notes` の直下に置く |
| アーカイブ | ユーザーが `/log:archive` で明示的に移す。wiki のページはアーカイブに移さない。日付ノートと週次のファイルもアーカイブに移さない |
| 名前の変更 | `wiki` と `raw` は原則として名前を変えない。ほかのディレクトリの名前を変えるときは、設定を直すだけでなく、テンプレートの `filepath` とリンクを直す |
| プロジェクトの wiki | ページの名前は `<project-id>--<topic-slug>.md` にする（要件定義書 D-06） |

### 日付ノートと週次のファイル

| 項目 | 決定 |
| --- | --- |
| 日付ノート | `20_Daily/YYYY/MM/YYYY-MM-DD.md`。テンプレートは `.foam/templates/daily-note.md`（ADR-0006） |
| 日付ノートの画像 | 日付ノートと同じディレクトリに、`日付ノートのファイル名-連番.拡張子` で置く。連番は 01 から始まる 2 桁にする。例：`20_Daily/2026/11/2026-11-04-01.png` |
| 週次のファイル | `30_Weekly/YYYY/MM/YYYY-MM-DD_MM-DD.md`。週は月曜日に始まり、日曜日に終わる。年と月のディレクトリは月曜日の日付で決める。例：2026年12月28日から2027年1月3日の週は `30_Weekly/2026/12/2026-12-28_01-03.md` |
| 週次のテンプレート | `30_Weekly/template.md` に置く。Foam のテンプレートでは週の始まりと終わりを計算できないので、週次のファイルは `/log:review --week` が作る |
| 長く残るタスク | 週次のファイルの「保留中のタスク」の節に、「待っている」と「いつかやる」の小節を設ける。`@wait` のまま、または一定の日数以上繰り越したタスクは、`/log:close` が週次に移すかを聞く。`/log:review --week` は前の週の保留を新しい週に写し、項目ごとに再開、待機、中止を聞く。`/log:plan` は、期日の近いタスクと再開するタスクを日付ノートに戻す |
| 行末のタグ | ADR-0006 の `@wait`、`@drop`、`@from` に、`@someday`（いつかやる）と `@due(YYYY-MM-DD)`（期日）を足す |

### 設定と、作業領域の見つけ方

| 項目 | 決定 |
| --- | --- |
| 作業領域の設定 | 作業領域の根の `.info-hive/workspace.json`。形式は JSON。役割ごとのディレクトリ名を書き、キーは英語にする。書かなかった役割はプラグインの既定値を使う |
| 案内のファイル | プロジェクトルートの `.info-hive.json`。作業領域の場所と、log をプロジェクトとグローバルのどちらに書くかを示す |
| log の書き先 | 既定はグローバルの作業領域。案内のファイルで指定したときだけ、プロジェクトの作業領域に書く。プロジェクトに wiki があるというだけでは変えない |
| 見つけ方 | カレントディレクトリから親へさかのぼって案内のファイルと作業領域の設定を探す。コードのサブモジュールの `.git` で探索を止めない |
| 壊れた指定 | 案内のファイルが指す作業領域が見つからないときは、書き込みを止めて利用者に知らせる。グローバルの作業領域に書き込むことはしない |
| パスの制限 | 設定の値は作業領域の中の相対パスだけを受け付け、`..` と絶対パスは拒否する |
| 既存の `~/wiki/` | 移行しない。新しい構成で作るものはまだない |

作業領域の設定の例を示す。キーの細部は設計書で決める。

```json
{
  "version": 1,
  "name": "info-hive-dev",
  "dirs": {
    "inbox": "00_Inbox",
    "assets": "10_Assets",
    "daily": "20_Daily",
    "weekly": "30_Weekly",
    "notes": "50_Notes",
    "output": "60_Output",
    "adr": "70_ADR",
    "wiki": "wiki",
    "raw": "raw",
    "rag": "92_RAG",
    "archive": "A0_Archive"
  }
}
```

## 理由

- **作業領域を 1 つの根にまとめた理由。** プラグインごとに保存先を決めると、利用者の手元にディレクトリが散らばる。根を 1 つにすれば、VS Code と Foam で開く場所も 1 つになる。
- **`wiki` と `raw` を兄弟に並べた理由。** wiki の lint と検索は、渡した wiki のディレクトリの下だけを読む（`wiki_lint.py` の `collect_pages`）。日付ノートやノートを wiki の外に置けば、孤立の判定にかからない。`raw` を wiki の中に置くと、走査から除外する固定名に頼ることになり、プロジェクトの wiki（`wiki/` と `raw/` が兄弟）と構成が食い違う。
- **`wiki` と `raw` に番号を付けない理由。** wiki プラグインは、プロジェクトでもグローバルでも `wiki/` と `raw/` を既定にしている。グローバルの作業領域でも同じ名前にすれば、`/wiki:init --global` はベースディレクトリに `~/info-hive` を渡すだけでよく、利用者がどちらの構成でも同じ名前を見られる。`wiki_evolve_loop.py` が `--raw` を省いたときに使う wiki の隣の `raw/` も、この配置ではそのまま正しい場所を指す。
- **`wiki` と `raw` の名前を変えない理由。** frontmatter の `raw:` には、パスが文字列で残る。`wiki_graph_extract.py` はこの値をノードの ID に使う。
- **日付ノートと週次をアーカイブに移さない理由。** Foam の `$FOAM_PREVIOUS_DAILY_NOTE` は、決まったパスの形で前日のノートを探す。
- **設定を JSON にした理由。** wiki は Python 3.10 以上で動き、lint と stats は標準ライブラリだけを使う。TOML を読む標準ライブラリは 3.11 からで、YAML を読むには依存が増える。
- **見つけ方を案内のファイルの方式にした理由。** プロジェクトでは、コードのサブモジュールの中で作業することが多い。Git のリポジトリのルートで探索を止めると、サブモジュールのルートで止まり、プロジェクトの作業領域が見つからない。その結果、プロジェクトの記録が黙ってグローバルに書かれる。4 体のうち 3 体が独立にこの欠陥を指摘した。
- **週次のファイル名に年を入れた理由。** Foam の wikilink はファイル名で解決する。年のないファイル名は、同じ日付の並びが何年か後にまた来たときに、どの年の週を指すかが曖昧になる。
- **重なりと漏れを確かめた。** 置き場所の候補が 2 つ以上あるもの（成果物、ノートと wiki、画像、会議のメモ、Web ページ）と、置き場所がないもの（参考資料、派生データ、長く残るタスク、アーカイブの対象）を、決定者が 1 つずつ決めた。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| プラグインごとに保存先を決める（`~/wiki/`、`~/daily/`） | ディレクトリが散らばり、プラグインどうしで決め方が食い違う |
| `40_Projects` を置く | グローバルにはプロジェクト固有の情報を置かず、プロジェクトの作業領域はそのプロジェクトだけを扱うので、置くものがない |
| `00_Inbox/ADR` に ADR を置く | ADR は確定した記録で、収集箱に置くものではない |
| `raw` を `wiki` の中に置く（以前の既定 `~/wiki/raw/`） | 走査から除外する固定名に頼ることになり、プロジェクトの wiki と構成が食い違う |
| wiki と raw に番号を付ける（`90_Wiki`、`91_Raw`） | 最初はこの名前で決めたが、プロジェクトの wiki の `wiki/` と `raw/` と名前が違い、`/wiki:init --global` に `--wiki-dir` と `--raw-dir` の指定が要る。改訂で `wiki` と `raw` に改めた |
| Foam のルートをプロジェクトルートにする | コードのサブモジュールまで Foam の索引に入る |
| Git のリポジトリのルートまでさかのぼって作業領域を探す | サブモジュールの中から作業領域を見つけられない |
| 設定を YAML にする | wiki の lint と stats に依存が増える |
| 週次のファイル名を ISO 週（`2026-W45`）にする | 決定者が、週の始まりと終わりの日付が分かる名前を選んだ |
| 週次のファイル名に年を入れない（`MM-DD-MM-DD.md`） | wikilink が年をまたいで曖昧になる |
| 長く残るタスクを 1 つのファイルや専用のディレクトリにまとめる | 日付ノートのタスクと重なり、見直しの機会と結び付かない |
| アーカイブのコマンドを wiki に置く（`/wiki:archive`） | 移す対象のほとんどが wiki の外にある |

## 影響

- **ADR-0006 の置き換え。** ADR-0006 の保存先（`~/daily/`）とノートの置き場所（`<保存先>/notes/`）は、本書の `20_Daily` と `50_Notes` に置き換わる。テンプレートの置き場所（`.foam/templates/daily-note.md`）は、作業領域の根になる。ADR-0006 の状態を改めた。
- **log プラグイン。** 作業領域の設定を読む部分、`/log:archive`、週次のテンプレートを使う `/log:review --week`、保留中のタスクの扱い、`@someday` と `@due` を作る。
- **wiki プラグイン。** 次の変更が要る。利用者に見える変更なので、SemVer の版を上げる。
  - `--wiki` を省いたときに、作業領域の設定の `dirs.wiki` を使う。設定がなければ今までどおり `./wiki` を使う
  - `/wiki:init --global` の既定を、作業領域の `~/info-hive/wiki/` と `~/info-hive/raw/` にする。以前は `~/wiki/` と `~/wiki/raw/` を既定にしていた。wiki 0.2.0 で対応した
  - `wiki_evolve_loop.py` は、`--raw` を省くと wiki の隣の `raw/` を使う（419 行目）。この配置では `~/info-hive/raw/` がそのまま正しい場所なので、直す必要はない。設定で `raw` の名前を変えた作業領域では、各入口で解決した `--raw` を渡す
  - `init_wiki.py` は、`SCHEMA.md` の中の `wiki/` と `raw/` を実際のディレクトリ名に置き換えない
- **ADR-0005 の不具合。** `assets/<slug>-NN.svg` の参照は、ページが `wiki` の下の階層にあるとき、正しいパスを指さない。本書とは別に直す。
- **rag プラグイン。** ADR-0007 の永続ジョブの保存先と索引は `92_RAG` に置く。
- **共通の部分。** 作業領域の設定を読む部分は、wiki、log、rag のそれぞれに同じものを置く。食い違いを防ぐため、同じ入力で同じ結果になることを確かめるテストを `info-hive-dev` に置く。

## 未決の事項

- 案内のファイルと作業領域の設定の、キーの細部。
- 次の点は Foam を実際に動かして確かめる。`filepath` の途中のディレクトリを Foam が作るか、`foam_template` のブロックが作られた日付ノートから消えるか。

## 見直す条件

- Foam を実際に動かして、上の未決の点が想定と違ったとき。
- 番号付きのディレクトリ名が、利用者の既存の作業領域と合わないという要望が出たとき。
- `92_RAG` の中身が大きくなり、Git で管理するかどうかを決める必要が出たとき。
