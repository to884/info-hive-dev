# ADR-0018：info-hive の wiki の同梱のスクリプトは、Python 3.12 以上を対象にする

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月12日 |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0002（「Python 3.10 以上と uv の前提を変えない」）、ADR-0008（設定を JSON にした理由の 1 つに「`tomllib` は 3.11 から」を挙げた）、ADR-0012（MCP サーバー）、to884/info-hive-wiki#46（下限を 3.12 に上げた 0.11.0）、[wiki をたどる経路の計画](../plans/wiki-walk-excluded-dirs-2026-11-11.md) |

## 背景

`info-hive-wiki` の同梱のスクリプトは、Python 3.10 以上を対象にしてきた（ADR-0002、`CONTRIBUTING.md`）。rag は、はじめから `>=3.12,<3.13` である。info-hive-dev の CI は、wiki の試験のほとんどを 3.12 で流している。

wiki をたどる経路の計画（7 版目）の実測で、0.10 の実装の結果が、Python の版によって違うことが分かった。3.10 の `rglob` は、返したパスを `Path` の比較で重複除去し、Windows の大文字と小文字を区別するフォルダーで、片方のページを落とす。読み取りの障害の扱い、`Path.is_file()` の失敗の扱いも、版で違った。版ごとの違いを、決めることと試験で追い続ける費用が大きい。

同じ日に、info-hive-wiki の 0.11.0（to884/info-hive-wiki#46）が、下限を 3.12 に上げた（PEP 723 の宣言、文書、CI）。0.11.0 は、`python` で直接動くスクリプトの版を確かめない。この ADR は、下限の決定を記録し、版の確かめを足す。

## 決定

| 項目 | 決定 |
| --- | --- |
| 対象 | Python 3.12 以上。上限は付けない（3.14 まで試験が通っている） |
| uv で動くスクリプト | PEP 723 の `requires-python` を `">=3.12"` にする（0.11.0）。uv が 3.12 以上の Python を選び、なければ取得する |
| `python` で直接動くスクリプト | lint、stats、語彙の検索などは、利用者の `python` で動く。wiki のモジュールを読み込む入口は、どれも最初に読み込まれる `wiki_text.py` で版を確かめ、今までの対象だった 3.10 と 3.11 では理由を書いて止める。そこまで届くよう、`wiki_text.py` を読み込むまでに読むファイルには、3.10 にない構文と標準ライブラリを使わない。本物の 3.10 と 3.11 で入口を動かして確かめる。3.9 以前は対象にしない（3.6 以前では、`from __future__ import annotations` が構文の誤りになり、確かめより先に止まる） |
| CI | 対象のいちばん古い版（3.12）と、いちばん新しい版（3.14）で流す |
| 版 | 下限の引き上げは 0.11.0（#46）で出た。最低の版を上げるのは、利用者に見える互換性の変更なので、0.x の minor を上げた。版の確かめは、まだリリースしていない wiki をたどる経路の修正（0.10.2 として準備していたもの）と一緒に、0.11.2 で出す（0.11.1 は、PDF の取り込みの手順の修正に使われた） |

コマンドの呼び方を `python` から `uv run --script` にそろえるかは、この決定に含めない。

## 理由

- 3.10 と 3.11 のための分岐と記述が、走査の計画の決めること、試験、変更履歴に入り込んでいた。3.12 以上にすると、`DirEntry.is_junction()` が使え、ジャンクションの見分けで項目の `stat()` を呼ばなくてよくなる。
- rag はすでに 3.12 である。wiki と rag の MCP サーバーは、同じ利用者の手元で動く。
- 3.12 は、2028 年 10 月まで保守される。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| 3.10 以上のままにする | 版ごとの違いを追い続けることになる（背景） |
| 3.12 以上で、上限を付ける（rag と同じ `<3.13`） | wiki は、3.14 まで試験が通っている。上限は、依存の都合があるときに付ける |
| 版の確かめをせず、宣言と文書だけを変える（0.11.0 の形） | `python` で直接動くスクリプトは、古い版で途中から壊れ、理由が分からない。0.11.2 からは、走査が 3.12 で入った `DirEntry.is_junction()` を使う |

## 影響

- ADR-0002 の「Python 3.10 以上と uv の前提を変えない」と、ADR-0008 の「`tomllib` は 3.11 から」は、この ADR で前提が変わった。どちらの決定も変えないので、元の ADR は書き換えない。
- 利用者の手元の `python` が 3.10 か 3.11 だと、lint などのコマンドが理由を書いて止まる（0.11.2 から）。uv で動くものは、uv が 3.12 以上の Python を取得する。
- 0.11.0 への更新のあとの最初の接続で、MCP のサーバーの環境を作り直し、動いているサーバーを 1 度起動し直す。
- Raw の大きさの設計の版は、0.12.0 にずらす。
