# ADR-0032: Codex の会話履歴を読み取り API で取り込む

| 項目 | 内容 |
| --- | --- |
| 状態 | 採用 |
| 決定日 | 2026年11月17日 |
| 決定者 | エージェント（Codex の会話履歴を自動で取り込む依頼の範囲で決定） |
| 関連 | ADR-0020、ADR-0031 の会話履歴の制限を更新 |

## 背景

Codex CLI 0.166.0 には、従来の rollout JSONL と、ページに分けてデータベースに保存する履歴がある。JSONL の探索だけでは新しい履歴を取り込めない。また、取り込みの作業そのものが実行中の履歴に追記されるため、確認中に対象が広がらないよう、取り込む範囲を固定する必要がある。

## 決定

- Codex の `app-server` の読み取り API でチャットと履歴を読む。モデルのターン、履歴の書き出し、複製、復元、削除は実行しない。取得した未加工の会話を一時ファイルに保存しない。
- 入口は `$wiki:info-hive ingest session` と `session:<ID>` にする。`wiki_session.py locate --host codex --current` は `CODEX_THREAD_ID`（なければ `CODEX_SESSION_ID`）で実行中の ID を特定する。ID が取れなければ、別の会話を勝手に選ばず、一覧から利用者に選んでもらう。
- 読み取り元は `codex:<ID>` として `wiki_session.py` の `--transcript` に渡す。実行中の会話では、取り込みを依頼したターンの ID を `--before` に固定し、そのターン全体を除く。追加入力が来ても、取り込み依頼と作業が記録に混ざらないようにする。
- ページをすべて読み、ユーザーの発言と公開されたアシスタントの本文だけを許可リストで抜き出す。思考、ツールの結果、システムや開発者の指示、他エージェントの通知、圧縮の要約は本文にしない。
- `source_sha256` は、選んだ範囲だけを決定的に直列化したデータに対して取り、`source_sha256_of: "codex-thread-range-v1"` と記す。更新時刻や接続先など、範囲の外の値はハッシュに混ぜない。範囲内が変われば既存の決定を拒む。
- Codex の読み取りと抽出だけを別モジュールにし、伏せ字、手動の決定、表示、承認済みのハッシュの検査、raw の排他作成、読み取り専用化、scan / verify は既存の `wiki_session.py` で行う。
- Codex の raw は `source_kind: "codex-session"`、版は `codex_versions` に書き、発言者を Codex と表示する。Claude Code の既存の決定ファイル、frontmatter、raw のバイト列は変えない。

## 理由と検討した選択肢

SQLite を直接読む方法は、内部スキーマと同時更新の扱いに依存する。JSONL だけを読む方法は、新しい保存方式の会話を取りこぼす。Codex 自身の読み取り API を使うと、両方式の履歴を同じ入口で扱える。

全文を一度ファイルに書き出してから既存の抽出器へ渡す方法は、確認の前の会話をディスクに置かない ADR-0020 と食い違う。メモリ内で抽出し、承認後にだけ raw を作る。

## 影響と検証

Codex CLI が必要になる。確認した API は 0.166.0 のもので、対応する API がない版では理由を伝えて止まる。履歴の形式を推測して別の会話へ切り替えない。

合成した履歴で、ページング、並び順、重複、非会話の除外、範囲の固定、伏せ字、手動の決定、承認後の書き込み、scan / verify を試験する。Claude Code の既存 fixture は、変更前の base SHA-256 と raw の SHA-256 に一致することを確かめる。実際の会話を試験の fixture や調査資料に保存しない。

利用者の指示に従い `ask-claude` は使わず、Codex のエージェントによる読み取り専用のレビューを行う。
