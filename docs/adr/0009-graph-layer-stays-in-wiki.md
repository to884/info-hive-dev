# ADR-0009：グラフ層は wiki プラグインに残し、別のプラグインにしない

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月4日 |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0003（プラグインごとにリポジトリを分ける）、ADR-0006（日々の記録を別のプラグインにした判断）、ADR-0007（rag の構成）、`docs/agent-runs/2026-11-04-graph-plugin-split/`（2 体のエージェントによる検討と総括） |

## 背景

wiki プラグイン（`info-hive-wiki`）は、移植元 llm-wiki-plugin v0.3.0 で加わった型付きのグラフ層を持つ。中身は次のとおりである。

- オントロジー `<WIKI_ROOT>/graph/ontology.yaml`（ノードの種類と述語）
- ページの frontmatter の `graph:` メタデータ（`node_id`、`aliases`、`relationships`）
- 抽出・検査・問い合わせのスクリプト `wiki_graph_extract.py`、`wiki_graph_lint.py`、`wiki_graph_query.py`
- コマンド `/wiki:graph`
- 取り込み・問い合わせ・lint・アップグレードの各手順に組み込んだグラフの段

正本は Markdown で、`graph/` の生成物（`nodes.jsonl`、`edges.jsonl`、`graph.sqlite`、`graph.graphml`）はいつでも作り直せる。2026年11月4日に、日本語のノード（`person:山田太郎` など）で抽出、検査、4 種類の問い合わせが動くことを手作業で確かめた。

info-hive は、日々の記録を `log`、RAG を `rag` として、wiki と別のプラグインにしてきた（ADR-0006、ADR-0007）。同じようにグラフとオントロジーも別のプラグインに分けるべきかを、2 体のエージェント（GPT-6.1 Sol と GPT-6 Astra）に独立に検討させ、相互にレビューさせた。2 体とも、レビューのあとも「今は分けない」という同じ結論だった。

## 決定

| 項目 | 決定 |
| --- | --- |
| 配置 | グラフ層とオントロジーは、wiki プラグインの中に残す。新しいプラグイン（`graph@info-hive`）とリポジトリは作らない |
| 位置付け | グラフ層は、wiki の既存のページを調べるための任意の索引とする。wiki、log、rag を横断する基盤にはしない |
| 当面の作業 | 分割の代わりに、wiki の中でグラフ層の境界を整理する（「影響」の節） |
| 見直し | 「見直す条件」の節のどれかが具体化したら、分割を検討し直す |

## 理由

- **wiki の手順との結び付きが強い。** グラフは、ページの形式、wikilink、frontmatter の `sources` と `raw` を入力にする。取り込み、問い合わせ、lint、アップグレードの各手順に組み込まれている。配布を分けても、呼ぶ時点、生成物の鮮度、失敗したときの扱いを wiki と合わせ続ける必要があり、結び付きは消えない。
- **分けたときのつなぎ方が決まらない。** グラフは、日本語の別名と正規化（`wiki_text.py`）と判定レイヤー（`wiki_decide.py`）を wiki と共有している。分けた場合の案は、公開した CLI を絶対パスで呼ぶ、共有コードを各プラグインに同梱する、MCP の窓口を置く、の 3 つが出た。どれも、発見のしかた、版のずれ、接続の障害の扱いのいずれかが詰め切れていなかった。
- **軽くなる効果を測っていない。** グラフ専用の常駐する処理はない。分けても、検索のためのモデルの導入は wiki に残る。PyYAML を wiki の必須から外せる余地はあるが、効果は測っていない。
- **log と rag を分けた理由が当てはまらない。** log は、厳選したページという wiki の前提と合わない記録を扱う（ADR-0006）。rag は、永続ジョブと再開という独立した実行の責任を持つ（ADR-0007）。グラフ層は wiki のデータの索引であり、どちらの性質も持たない。
- **分けると先に費用が増える。** 抽出から問い合わせまでを通すグラフ層の専用のテストがない。分ければ、互換性の確認、移行、2 つのプラグインの同時のリリースが増え、移植元の修正の振り分け先も増える。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| 今すぐ `graph@info-hive`（リポジトリ `to884/info-hive-graph`）に分ける。依存は graph から wiki への向きにする | wiki とのつなぎ方と共有コードの持ち方が決まらず、移行とテストの負担が先に来る。分ける場合の構成案としては残す |
| オントロジーだけを別のプラグインにする | extract と lint がオントロジーの規約を解釈するので、小さな設定と実装の間に互換性の管理が増える。分野別の語彙を複数配る需要も確認できない |
| wiki、log、rag に共通のグラフ基盤に広げて、独立させる | 今のノード ID、出典の参照、引用の照合は wiki のページを前提にしている。日付ノートや PDF のチャンクを扱うには、識別子の名前空間と出典の位置の設計が先に要る |
| 移植元と同じ形を保つためだけに、手を入れずに同梱し続ける | 後述の「任意の層」と実装のずれが残る。分けない場合も整理は要る |

## 影響

wiki プラグインの中で、次の整理を行う。利用者に見える動作を変えるものは、SemVer の版を上げてから入れる。

- **「任意の層」の契約をそろえる。** 今は、`init_wiki.py` が `graph/ontology.yaml` などを必ず置き、セットアップが PyYAML を必ず入れる。オントロジーがないときの動作も入口ごとに違う。extract は空のオントロジーで続け、lint は終了コード 1 で止まり、query は `graph.sqlite` の有無だけを見る。新しい wiki でグラフを使うかを選べるようにするか、どの入口も同じ扱いにするかを決め、既存の wiki のオントロジーは保つ。
- **作り直しが要る条件を直す。** `graph-workflow.md` と `ingest-workflow.md` は、型付きの関係も新しいページもない取り込みでは extract を省くと書いている。しかし extract は、本文の wikilink、`sources`、`raw` からもエッジを作るので、それらを変えただけでもグラフは変わる。
- **作り直しの中断に備える。** extract は既存の `graph.sqlite` を先に削除してから作り直すので、途中で止まると問い合わせができなくなる。障害は再現していない。
- **手順の正本をまとめる。** グラフの有効化、更新、検査、問い合わせ、作り直しの規約を `graph-workflow.md` に集め、ほかの手順は呼ぶ時点と結果の扱いだけを書く。
- **境界を保つ。** 日本語の別名と正規化は `wiki_text.py`、判定は `wiki_decide.py` に置いたままにする。`wiki_lint.py`、`wiki_search.py`、`wiki_stats.py` が `graph/` を走査から外す決まりも残す。
- **回帰テストを足す。** このリポジトリの `tests/graph/` に、日本語のノード、NFC と NFD、独自のオントロジー、暗黙のエッジ、4 種類の問い合わせ、オントロジーのない状態、作り直しの中断を通すテストを置く。分割を考え直すときの基準にもなる。

## 未決の事項

- **グラフを使わない利用者の扱い。** 新しい wiki で、グラフのテンプレートと PyYAML を選択式にするか。選択式にすると今の既定の動作が変わる。アップグレードが有効・無効の状態を勝手に変えないことは決めておく。
- **将来の位置付け。** グラフを wiki の任意の索引にとどめるか、log や rag や複数の wiki を横断する基盤にするか。後者を選ぶなら、分割の優先度が上がる。

## 見直す条件

次のどれかが具体化したら、分割を検討し直す。

- log、rag、複数の wiki から、関係の問い合わせやオントロジーの管理を直接使う要件ができた。
- グラフ専用のストレージ、推論の処理、大きな依存パッケージが必要になった。
- グラフだけを更新することが多くなり、wiki 全体のリリースを待つことが実際の支障になった。
- 上の整理のあとも、グラフを使わない利用者の導入時間やコンテキストの負担が、問題として測られた。

分ける場合は、検討で両案に共通した次の構成から始める。プラグイン名は `graph`、導入名は `graph@info-hive`、リポジトリは `to884/info-hive-graph` とし、`plugin.json` の `dependencies` に `wiki@info-hive` を宣言する。コマンドは `/graph:*` にし、利用者のページと `<WIKI_ROOT>/graph/ontology.yaml` は残して生成物だけを作り直す。`/wiki:graph` には互換期間を設け、graph を先に配ってから wiki 側の実装を外す。
