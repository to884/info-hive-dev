# ADR-0017：`/wiki:browse` は、自分が作ったものだけを置き換え、消す。入力の実体は、置き場所によらず Wiki の内容として読む

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月11日 |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0010（中核と表示の分離）、ADR-0016（閲覧専用の確認）、[browse の第 1 段階の設計](../plans/wiki-browse-stage1-2026-11-09.md)（守ること 1 を本 ADR で言い換える）、[browse の構造の直し](../plans/wiki-browse-structure-2026-11-11.md)、`docs/agent-runs/2026-11-09-wiki-browse-stage1-review/impl-root-causes.md`、`docs/agent-runs/2026-11-11-wiki-browse-structure/design-review-2.md` |

## 背景

browse の第 1 段階の設計は、守ること 1 を「browse は、Wiki のルートの中と、読んだ入力の実体に対して、作る、書き換える、名前を変える、消す、のどれもしない」と定めた。実装（wiki 0.10.0）は、これを守るために、Wiki のルートと、Wiki の外にある入力の実体を「守る場所」として調べ上げ、書き込みのたびに、対象が守る場所と重ならないかを確かめている。

この作りは、守る相手をすべて調べ上げることを前提にする。実装のレビュー 7 回と、構造の直しの設計のレビュー 2 回で、調べ漏れが繰り返し見つかった。

- 守る場所を調べた時点と、書き込む時点のあいだに、入力が変わる（実装のレビューの 3 回目、4 回目）。
- 一覧や属性を調べられない入力が、守る場所から外れる（5 回目、6 回目）。
- 実体の置き場所を祖先からたどる判定は、ハードリンクでは成り立たない（設計のレビューの 2 回目）。

もう 1 つ、Wiki のページが browse 自身の状態のファイル（`server.json`。サーバーを止めるためのトークンを持つ）を指している場合の扱いが、決まっていなかった。0.10.0 は、状態のディレクトリと入力の重なりを見つけるとサーバーを終わらせる。構造の直しの 2 版目は、browse の持ち場にある実体を読まないとした。レビューは、読まないページの未解決リンクが lint と食い違うこと、ハードリンクでは持ち場にあると判定できないことを示した。

## 決定

| 項目 | 決定 |
| --- | --- |
| 書き込みの守り | browse は、自分が作ったファイルとディレクトリのほかを、書き換えない、名前を変えない、消さない。Wiki のルートの下には、何も作らない。Wiki の入力の実体を調べ上げて守ることは、しない |
| 自分が作ったものの決め方 | 書き出しのたびに、作ったファイルの一覧を残す。置き換えたり消したりするのは、一覧と照らして browse のものと確かめられたものだけである。書き出し先に一覧にないものがあれば、書き出しを止める。細部は、構造の直しの設計の 5 に定める |
| 入力の読み取り | 入力の実体の中身は、実体がどこにあっても、lint と同じに、Wiki の内容として読む。browse の状態のファイルや、書き出したファイルを指すページも、同じである |
| 守る範囲（2026年11月11日、構造の直しの設計の 3 回目のレビューのあと） | 守るのは、項目の名前、種類、通常の中身、属性（読み取り専用か、と更新時刻）である。代替データストリーム、拡張属性、アクセス制御の一覧、マウント、調べてから操作するまでの競合、利用者が書き換えた一覧は、守る対象にしない。browse が中に項目を作る、名前を付け替える、消すディレクトリ（`--out` の書き出し先の親と、`<data_dir>`）の更新時刻は、避けられずに変わるので、守る対象から外す（2026年11月12日、4 回目のレビューのあとに明記） |
| browse の領分（同） | `<data_dir>/browse/` の全体（共通のロック、既定の書き出し先、サーバーの状態のディレクトリ、作業用のディレクトリ）と、`--out` の書き出し先の隣に作る作業用のディレクトリを、browse の領分とする。領分の中に利用者が手で置いたものは、守らない。領分の中で消すときも、リンクとジャンクションはたどらず、属性は変えない |

守ること 1 は、次の文に言い換える。

> **閲覧専用。** browse は、領分の外では、自分が作ったファイルとディレクトリのほかを、書き換えない、名前を変えない、消さない。例外は、書き出しのために空のディレクトリを取り除くことだけである。Wiki のルートの下には、何も作らない。未解決リンクをクリックしてもファイルを作らない。

例外は、書き出し先に指されたディレクトリが空のときと、途中で止まった書き出しが空のディレクトリを残したときである。空のディレクトリを取り除いても、内容は失われない。

レビューを止める条件（2026年11月12日、4 回目のレビューのあと）: 確かめた OS と版で、失敗のないときの約束を破る反例が出なければ、残りの指摘は構造の直しの設計の限界に書いて、作者の承認に回す。

## 理由

守る範囲と領分は、構造の直しの設計の 3 回目のレビューのあとで足した。範囲を決めないと、どの仕組みにも入らない保存の機能（代替データストリームなど）が、レビューのたびに 1 つずつ反例になる。範囲は、試験が実行の前と後で量れるものに合わせた。領分を決めないと、browse の状態のファイルや作業用のファイルを、名前で自分のものと言えるかが、規則ごとに食い違う。

- 守る相手を調べ上げる作りでは、調べ漏れが、そのまま守りの穴になる。自分が作ったものだけを確かめる作りでは、確かめられないものには触れないので、確かめ漏れは「消せずに止まる」「残して警告する」の側に倒れる。
- 一覧と照らす対象は、browse が書いた場所の中だけである。Wiki の配置（リンク、ジャンクション、ハードリンク、一覧を作れないディレクトリ）に依らない。
- 入力を置き場所で読み分けないので、読まないページができない。未解決リンクの一覧は、どの配置でも lint と一致する（守ること 2）。
- `server.json` を指すページを描いても、サーバーでは、そのページを見られるのは、表示のトークンを持つ手元のブラウザだけである。そのリンクを置いたのは、利用者である。

## 検討した選択肢

| 選択肢 | 内容 | 採らなかった理由 |
| --- | --- | --- |
| A. 今の作りのまま、調べ方を厳密にする | 守る場所を、壊す操作のたびに調べ直す。持ち場の単位で確かめる | 仕組みが今より増える。ハードリンクのように、置き場所が 1 つに決まらない実体の扱いが、課題として残る |
| B. 自分が作ったものだけを置き換え、消す（採用） | 本 ADR の決定 | ― |
| C. 状態のファイルを指すページを、読まずに診断に挙げる | 持ち場にある実体を入力として読まない | 読まないページの未解決リンクが、lint と食い違う。ハードリンクは、持ち場にあると見分けにくい |

## 影響

- Wiki のページが browse の作ったファイルを指しているとき、browse は、そのファイルを置き換え、消すようになる。ハードリンクなら、Wiki の側の名前と中身は残る。シンボリックリンクなら、先のないリンクになる。
- `server.json` を指すページがあると、操作のトークンがページに描かれる。静的の書き出しでは、書き出したファイルにトークンが残り、ファイルを持ち出すと渡る。トークンは起動ごとに変わり、サーバーが終われば使えない。公開の前の検査が、警告を出す。
- `--out` の書き出し先に、利用者のファイルや、利用者が書き換えたファイルがあると、書き出しが止まる。0.10.0 で作った `--out` の書き出し先は、一覧に名前がないので、利用者が消してから書き出し直す。既定の書き出し先は領分なので、そのまま置き換える。
- 領分（状態のディレクトリなど）に利用者が置いたファイルは、browse の名前と同じなら置き換えられ、消える。
- `--out` の書き出し先や、その中のファイルに付けた代替データストリームは、次の書き出しで失われる。
- browse の第 1 段階の設計の、守ること 1 と 6（書き込みの守り）は、構造の直しの実装のあとで書き換える。
- ADR-0016 の「閲覧専用の確認」（閲覧の操作の前後で Wiki のファイルのハッシュが変わらず、増えも減りもしない）は、変えない。
