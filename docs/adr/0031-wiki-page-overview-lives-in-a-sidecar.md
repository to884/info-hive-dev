# ADR-0031：ページの概要は、図を埋め込んだ 1 つのサイドカーに置き、`wiki_overview.py` だけが書く

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月17日 |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0005（図は mermaid と svg で書く）、ADR-0017（browse は自分が作ったものだけを置き換える）、ADR-0020（セッションの raw はスクリプトが書く）、ADR-0023（wiki の書く段）、ADR-0029（wiki と raw にリンクを置かない）、ADR-0030（browse は図を画像として見せる。提案）、[概要の設計](../plans/wiki-overview-2026-11-17.md) |

## 背景

作者は、`/wiki:browse` の記事のページの題名のすぐ後に、図を中心にした初心者向けの概要を表示することを求め、概要を作るプロンプトを決めた。

browse のサーバーは LLM を持たず、wiki のルートの下に何も書かない（ADR-0017）。概要は、Claude Code のセッションが前もって作り、どこかに置いておく必要がある。

設計の 1 版目から 4 版目は、概要を「サイドカー 1 つと、`assets/` の直下の svg 数個」にした。4 回の敵対的レビューで、重大な指摘の多くが次の 2 つの前提から出た。

- 概要が複数のファイルからなるので、置く順、止まったときの状態、電源断のあとの状態が毎回の論点になった。
- svg を ADR-0005 の図と同じ `assets/` の直下に置くので、「どのファイルなら消してよいか」に、記録でしか答えられなかった。記録の仕組みを 3 度作り直し、4 回目で、記録を置く `.wiki-cache` が git で運べないことが分かった。

## 決定

| 項目 | 決定 |
| --- | --- |
| 作る時機 | コマンド `/wiki:overview <ページ>` で、求めたページだけ作る。取り込みには入れない |
| 置き場所 | 概要は、`wiki/assets/overview/<P>.overview.md` の 1 つのファイル（サイドカー）。`<P>` はページの識別子（`.md` を除いた NFC の相対パス）のハッシュ。git で管理する |
| 図 | svg はサイドカーの本文の後ろに、情報文字列が `svg-figure <名前>` のフェンスで埋め込む。本文は `![説明](#fig-<名前>)` で参照する。`assets/` に別の svg のファイルを作らない |
| 結び付け | ページとサイドカーは、ファイル名の `<P>` で結び付ける。サイドカーの `page` の欄は人が読むためのもので、`<P>` と食い違えば壊れた概要とする |
| 新しさ | サイドカーに、概要を作るときに読んだページのハッシュ（BOM を除き、改行を LF にそろえた全文の SHA-256）を記録する。今のページのハッシュと違えば「古い」とする |
| 書き手 | `wiki_overview.py` だけが、サイドカーを書く。wiki への書き込みは、サイドカー 1 つの `os.replace` か削除だけである。モデルは、走査が除く `wiki/.wiki-cache/overview/work/` に本文と svg の下書きを置き、スクリプトが検査してから組み立てて置く。スクリプトはモデルの本文を書き換えない |
| 保存前の元のページ | 置き換え前に現在のページを読み、`page_changed` を確定する。ページがなくなっていれば `page_gone`（終了コード 3）、そのほかの読み取り失敗か非 UTF-8 なら `page_unreadable`（終了コード 1）で止める。サイドカーを置き換えず、下書きを残す。保存後はページを読み直さず、確定済みの値で応答する |
| 停止時の保証 | OS が稼働し続ける間のプロセス停止では、置き換え前の状態（初回は未作成）か、検査済みの新しいサイドカーが残る。電源断や OS の停止後の、概要の存続と内容の完全性は保証しない |
| 引数 | 利用者の引数（ページ名）は、シェルのコマンドの行に入れない。スクリプトが経路を確かめてから返す要求のファイルのパスに、モデルが Write ツールで書く |
| 中身 | 短い文、mermaid のフェンス、埋め込んだ svg。入力はそのページだけで、wikilink は書かない。見出しは h3 以下。写真は使わない |
| 扱い | 概要は、ページから作り直せる表示用の派生物である。ページの数、大きさの上限、検索、グラフ、統計に入れない。`log.md` に記録しない |
| lint | 元のページがない概要、壊れた概要、元のページを読めない、走査が不完全で元のページが分からない、を `overview_problems` で、古い概要を `overview_stale` で知らせる。直さない |

## 理由

- `os.replace` の原子性により、OS が稼働し続ける間のプロセス停止では、置き換え前の状態か、本文と図がそろった新しい概要が残る。複数のファイルにまたがる順序と片付けの仕組みが要らない。
- 原子的な置き換えと、電源断後の永続化は別の保証である。ファイルの `fsync` と `os.replace` だけでは、ディレクトリエントリの永続化までは保証できない。概要は再生成できる派生物なので、この設計ではディレクトリを同期せず、電源断後の永続化を保証の範囲に含めない。
- 元のページを読めるかの確認と `page_changed` の確定を置き換え前に終えることで、ページの読み取り失敗のために、保存を終えたあとで応答を作れなくなることを避ける。
- スクリプトが wiki に作るのは自分の名前空間（`assets/overview/<P>.overview.md`）のファイルだけになり、消すのもそれだけになる。ADR-0005 の図や利用者のファイルの持ち主を決める必要がない。
- 本文の節にすると、概要がページの大きさ、検索、グラフに混ざる。frontmatter には図を置けない。
- `assets` は、走査、lint、検索、グラフ、統計、browse がすでに名前で除いている。新しい最上位のディレクトリを作ると、除外のリストを変えることになり、同じ名前のページのディレクトリを持つ wiki でページが消える。
- 名前をページの識別子のハッシュで決めると、ページのパスの形（大文字と小文字、長さ、`.overview.md` で終わるディレクトリ）に依らず、サイドカーどうしが衝突しない。
- 引数を引用符の中でシェルに渡す形は、PowerShell が U+201D を引用符の終わりと読むので、禁じる文字を数える方式では守れなかった。
- 下書きの置き場所は、利用者が `INFO_HIVE_DATA_DIR` を wiki の中に向けても、ページにならない場所でなければならない。`.wiki-cache` は走査が名前で除き、Web とセッションの取り込みが作業用に使っている。ここに置くものは、どれも作り直せる。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| ページの本文の h1 の直後に節として書く | browse に差し込みの仕組みが要らず単純だが、概要がページの大きさ、検索、グラフに混ざる。作者がサイドカーを選んだ |
| 新しい最上位のディレクトリ（`wiki/overviews/`） | 走査の除外のリストを変える。同じ名前のページのディレクトリを持つ wiki で、ページが黙って消える |
| `wiki/.wiki-cache/` に概要を置く | 全体が gitignore で「消してよい」場所である。作り直しに LLM のセッションが要るものに合わない |
| `<data_dir>`（wiki の外） | wiki と一緒に運べない。browse の「入力は wiki の内容」に反する |
| svg を `assets/` の直下に別のファイルで置く（1〜4 版目） | 置く順、片付け、電源断のあとの状態、ADR-0005 の図との持ち主の区別に、記録の仕組みが要った。記録は git で運べず、別の PC では片付けられなくなった |
| svg を `assets/overview/` の下に別のファイルで置く | 持ち主の問題は消えるが、複数のファイルの順序の問題は残る。ADR-0030 が `assets/` の下位のディレクトリの svg を読まない |
| サイドカーをページのパスに写した場所に置く（1 版目） | `foo.md` と `foo.overview.md/bar.md` のように、ファイルとディレクトリが衝突する |
| モデルが Write でサイドカーを書く | ハッシュ、改行、検査を保証できない。ADR-0023 の向きと逆になる |
| 取り込みのたびに作る | 取り込みが長く、高くなる。作者がコマンドを選んだ |

## 影響

- 電源断や OS の停止後には、概要の欠落、以前の内容への巻き戻り、破損がありうる。`written` の通知後も同じである。復旧後に `status` と lint で残った概要を確かめ、欠落したものは新たに作り、古いものや壊れたものは `--refresh` で作り直す。
- `page_changed` は、保存前の読み取り時点と `prepare` 時点の比較だけを表す。その読み取り後に元のページが変わっても、保存後の応答を変えない。現在の概要の状態は `status` と lint で判定する。
- エディターや GitHub でサイドカーを開いても、図は見えず、svg のソースになる（作者が受け入れた）。
- browse（段 2）に、サイドカーに埋め込まれた svg を取り出し、自分の書き出し先に写して `<img>` で見せる経路が要る。ADR-0030 が wiki の svg を写すのと同じ作りにする。
- ADR-0023 と ADR-0029 の共有の書き込みの部品（`wiki_fsguard`）がまだないので、このスクリプトが経路の確かめ（リンク、再解析点、ハードリンク、綴り）を自前で持つ。部品ができたら、そこを通す。
- 除外したディレクトリを指す別名のリンクを wiki の中に置くと、今の走査はそれをたどり、サイドカーや下書きをページとして数える。これは走査の今の性質で、ADR-0029 の実装で直す。
- ページを改名すると、概要は元のページのない概要になる。lint が知らせ、移す先の候補を示す。自動では移さない。
- browse での表示は、ADR-0030 の実装のあとに、別の設計で決める。それまでは、概要を作れても browse には出ない。

## 見直す条件

- ADR-0023 の書く段が実装され、サイドカーの書き込みを受け持てるようになったとき。
- エディターや GitHub で図が見えないことが、使いにくいと分かったとき。
- 概要を、取り込みのたびに、または一括で作りたくなったとき。
