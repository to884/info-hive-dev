# ADR-0020：Claude Code のセッションの raw は、会話だけを抜き出し、人の決定を当てて、スクリプトが 1 回で、重ねて書かない形で作る

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月14日 |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0004（Web ページの raw）、ADR-0015（記事作成の方法論は段階を分けて入れる）、ADR-0018（Python 3.12）、ADR-0019（wiki の根は `SCHEMA.md` で決まる）、[セッションの取り込みの設計](../plans/wiki-session-ingest-2026-11-14.md)、[wiki の書く段の方針](../plans/wiki-apply-2026-11-14.md) |

## 背景

作者は、Claude Code のセッションの会話を、記事の形で wiki に取り込みたいと考えた。セッションの記録（JSONL）は、会話のほかに、ツールの結果、モデルの思考、ハーネスの差し込み、アプリの通知などを大量に含む。記録の形式は公開された仕様ではなく、12 日間で 5 つの版が現れた。記録には、利用者が意図せず残したメールアドレスや顧客の名前も入る。

設計は 7 回の敵対的レビュー（GPT-6.1 Sol）と、4 体のエージェントの独立した再設計と相互レビューを経た。1〜3 版目は、人が自由に直した写しを元と照らして許された編集かを推す作りと、ファイルの有無から状態を推す作りを持ち、レビューのたびに新しい反例で崩れた。4 体の再設計の総括は、「安全に関わる事実を、書き手が作った結果として持たず、あとから推していた」ことを共通の原因とし、推すのをやめる構造を推した。4 版目で足した wiki の書く段（ロックとパッチ）は 4 回目のレビューで崩れたので、作者の判断で別の設計に分けた。

## 決定

| 項目 | 決定 |
| --- | --- |
| 入口 | 新しいコマンドは足さない。`/wiki:ingest` の引数（`session`、`session:<ID>`、`session:<パス>`、`.jsonl`）で受け付ける（ADR-0015）。`.jsonl` は、セッションの記録と認めなければ止まり、ユーザーの明示の依頼なしに、ふつうの取り込みへ回さない |
| 抜き出し | 許可リストで、残すものだけを決める。話者は記録ごとの属性（`origin.kind`）で決め、本文の形から推さない。返答の宛先は `parentUuid` のつながりでたどり、着いた先が会話でない記録なら印のターンを置く。`uuid` のない知らない記録は読み飛ばす。モデルの思考は入れない |
| raw の中身 | 記録から抜き出した逐語の会話である。記事はソースの要約ページで書く。ターンの本文は、本文の中の最長のバッククォートの並びより長いフェンスで囲み、フェンスの外にはスクリプトが決めた語、時刻、番号、検査した識別子だけを置く |
| 伏せ字 | 自動の規則（メール、ホームのディレクトリ、秘密の値）は、記録と引数だけで決まり、実行する PC の値を使わない。人の決定は、伏せる位置と消すターンの番号として持ち、伏せる文字列そのものはディスクに書かない |
| raw の作り方 | raw を書くのはスクリプトだけである。人とモデルが自由に直す写しは作らない。記録の範囲、引数、抽出器の版、人の決定から、raw を 1 回で作る。確認の前の会話の文は、ディスクに置かない |
| raw の書き方 | 承認した raw の全体の SHA-256 に一致したときだけ、一時ファイルから重ねて書かない形（POSIX は `os.link`、Windows は `os.rename`）で置く。上書きの手段（`--force`）は持たない。書いた raw は読み取り専用にする |
| 同じ取り込み | 作った raw のバイト列と、置いてある raw のバイト列が一致することである。キーを並べて同一性を決めない。実行の時刻は raw に書かない |
| 状態 | スクリプトは、取り込みが済んだかを判定しない。Web ページの W2 と同じく、モデルが wiki を見てユーザーに聞く |
| wiki の書き込み | 要約ページと関連ページは、既存の取り込みと同じくモデルが書く。書く前に、伏せた文字列が入っていないかをスクリプトで探し、中身をユーザーに見せる。wiki の書き込みの排他は、[書く段の設計](../plans/wiki-apply-2026-11-14.md)で扱う |

## 理由

- 自由に直した写しから「どんな編集だったか」を復元する検査は、部分列、トークン、字面の書き直しと方法を変えるたびに崩れた。編集される写しを作らなければ、書き足し、言い換え、構造の変更を起こす手段がなく、検査も要らない。
- 状態をファイルの有無で、同一性をキーの列挙で表すと、キーや状態の抜けがレビューのたびに見つかった。raw のバイト列そのものを同一性にすれば、出力を変える入力はすべて自動的に含まれる。
- 話者を本文の形から推すと、人の文を捨て、知らない差し込みを通した。記録ごとの属性と親のつながりなら、実物の 3,491 件の返答の宛先がすべてたどれた。3 版目までの規則では、キューに入った入力への返答 545 件が前のターンに混ざっていた。
- 記録をそのまま raw に写すと、思考と秘密が原本に入る。抜き出しを原本にし、記録の SHA-256 で出所を残すのは、Web ページの原文の HTML を残さない ADR-0004 と同じ割り切りである。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| 記事だけを raw に置く | モデルが書いた文が一次の出典になり、主張を元の会話で確かめられない |
| 確認の前の写しを作業用のフォルダーに置き、人が編集したあとで照らす（1〜3 版目） | 照らし方を変えるたびに新しい反例で崩れた。写しが Git に入る経路も残った |
| 確認の前の写しを `.wiki-cache` に置き、`.gitignore` を必須にする | 追跡済み、規則が効かない、上位の規則など、確かめる条件が増える。写しを作らないほうが簡単で強い |
| 知らない版や種類の記録で、入力の全体を拒む | 検証環境の 63 ファイルのうち 57 を拒み、日常的に使えない |
| 専用のコマンド `/wiki:session` | 手順は `/wiki:ingest` の引数で表せる（ADR-0015） |
| 取り込んだあとの raw を直す手段（`--force`、`withdraw`） | ADR-0004 の不変性と食い違う |

## 影響

- `info-hive-wiki` に `wiki_session.py`（`locate`、`list`、`inspect`、`show`、`decide`、`write`、`verify`、`scan`）を足す。`commands/ingest.md` に S1〜S10 を足す。
- 守れないことは、設計書の「保証しないこと」に並べた。主なものは、人が実際に読んで決めたこと、言い換えた個人の情報、`uuid` のない新しい形の入力、いま動いているセッションの記録に残る文、wiki の書き込みの競合、別名を経由して wiki の書き込みが raw に届くこと（Windows では読み取り専用で防ぎ、POSIX では今回の raw なら `verify` で見つける）、raw のルートの置き場所である。
- wiki の書き込みの排他と、raw の置き場所の全体の守りは、[書く段の設計](../plans/wiki-apply-2026-11-14.md)で決める。決まったら、セッションの取り込みもそちらへ移す。

## 見直す条件

- Claude Code の記録の形式が変わり、許可リストが会話を通さなくなったとき、または `uuid` のない形で入力が届くようになったとき。
- プラグインのコマンドの本文で `${CLAUDE_SESSION_ID}` が置き換わらないと分かったとき（入口の `session` を、ユーザーに聞く形に変える）。
- wiki の書く段の設計が決まったとき。
