# ADR-0016：`/wiki:browse` の第 1 段階は、サーバーと静的 HTML の 2 方式で合格とし、アプリでの確認はアプリを作るときに行う

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 決定日 | 2026年11月9日 |
| 決定者 | info-hive の開発者（このリポジトリの作者） |
| 関連 | ADR-0010（合格の条件の一部を本 ADR で置き換える）、ADR-0001（3 条件）、ADR-0002（サーバーの対策）、[browse の第 1 段階の設計](../plans/wiki-browse-stage1-2026-11-09.md)、`docs/agent-runs/2026-11-09-wiki-browse-stage1-review/design-review-3.md`（指摘 1） |

## 背景

ADR-0010 の「合格の条件」は、試験用の Wiki で 3 方式（サーバー、アプリ、静的 HTML）のリンクの移動、被リンク、診断の結果が一致することと、閲覧専用であることを、3 方式に共通の試験で実際に動かして確かめる、としている。

一方、ADR-0010 の「未決だった事項の決定」の 6 は、アプリの技術を今は決めないとしている。作る順序の 4 は、最初のアダプタをサーバーにするとしている。第 1 段階の時点では、製品としてのアプリが存在しない。

browse の第 1 段階の設計の 3 回目のレビューは、この 2 つが食い違うと指摘した。技術を決めないことは、3 方式の受け入れ試験を免除する決定ではない。第 1 段階を 2 方式だけで確かめるなら、合格の条件そのものを改める判断が要る。

## 決定

ADR-0010 の「合格の条件」のうち、「交換できることの確認」と「閲覧専用の確認」の 2 行を、次のように改める。「HTML のバイト一致」の行と、ADR-0010 のそのほかの決定は変えない。

| 項目 | 決定 |
| --- | --- |
| 交換できることの確認（第 1 段階） | 試験用の Wiki で、サーバーと静的 HTML の 2 方式のリンクの移動、被リンク、診断の結果が一致することを、実際のブラウザで動かして確かめる |
| 閲覧専用の確認（第 1 段階） | 閲覧の操作の前後で Wiki のファイルのハッシュが変わらず、ファイルが増えも減りもしないこと、外部への通信が 0 件であること（サーバーでは 127.0.0.1 以外への通信が 0 件）を、2 方式に共通の試験で確かめる |
| アプリでの確認 | アプリを作ると決めたときに、アプリのアダプタを足す作業の合格の条件として、3 方式で上の 2 つを確かめる。アプリのない間に、試験用のアダプタを作って代わりにすることはしない |

中核の出力（画面の契約とデータの契約）は、ADR-0010 のとおり 3 方式に共通のものとして作る。アプリだけのために中核の契約を変えることは、アプリを作るときの作業にする。

## 理由

- 製品として存在しない方式を確かめる試験は、試験用のアダプタの動作を確かめるだけで、アプリの独自スキーム、CSP、WebView の権限での動作の証明にならない。ADR-0010 自身が、同じ HTML でも基準の URL、CSP、WebView の権限で動作が変わるとしている。
- 2 方式の試験でも、中核と表示の方式を分けたことは確かめられる。サーバーは要求ごとに中核の出力を配り、静的 HTML は同じ出力を書き出す。基準の URL（`http://127.0.0.1` と `file://`）と CSP の置き方が違う 2 つで結果が一致すれば、方式に依存する作りが中核に紛れ込んでいないことの証拠になる。
- アプリの技術は今は決めないので、アプリの合格の条件を今決めても、そのときの技術で書き直すことになる。

## 検討した選択肢

| 選択肢 | 内容 | 採らなかった理由 |
| --- | --- | --- |
| A. ADR-0010 のまま 3 方式で確かめる | 第 1 段階で試験用のアプリ（PoC と同じ Tauri の殻など）を作り、3 方式で試験する | 製品にしない殻の保守と CI が増える。殻の結果は、後で選ぶ技術での動作の証明にならない |
| B. 2 方式で確かめ、アプリは後にする（採用） | 本 ADR の決定 | ― |
| C. 第 1 段階では方式の一致を確かめない | サーバーだけを確かめる | ADR-0010 の中核と表示の分離を、第 1 段階で一度も確かめないことになる |

## 影響

- ADR-0010 の状態の欄を「承認（合格の条件の交換できることの確認と閲覧専用の確認は 0016 で一部を置き換え済み）」にする。ADR-0010 の本文は書き換えない。
- browse の第 1 段階の設計の試験の節は、本 ADR を根拠に 2 方式の試験を定める。
- アプリを作る作業を始めるときは、本 ADR の「アプリでの確認」を合格の条件に入れる。
