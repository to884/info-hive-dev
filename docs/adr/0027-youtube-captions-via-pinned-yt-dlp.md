# ADR-0027：YouTube の動画は、固定した yt-dlp で字幕を取るスクリプトが raw を 1 回で作り、取り込みの手順に動画の分岐を足す

| 状態 | 提案 |

| 決定者 | info-hive の開発者（このリポジトリの作者） |

## 背景

作者は、YouTube の動画の字幕を取り込み、要約を wiki に残したいと考えた。今の `/wiki:ingest` に動画の URL を渡すと、ページが `text/html` なので Web ページの経路（`wiki_fetch.py`）に進む。2026-11-15 に試すと、raw に残ったのはページの下のリンク（概要、プレスルーム、著作権…）だけで、字幕は入らなかった。

調査レポートで、字幕の取り方を 8 つ（A1〜A8）、プラグインへの組み込み方を 4 つ（B1〜B4）挙げた。公式の YouTube Data API の `captions.download` は、動画を編集する権限を求めるので、他人の動画には使えない。この ADR は、yt-dlp で字幕を取る A2 と、取り込みに動画の分岐とスクリプトを足す B2 の組み合わせを決める。

この ADR の観測は、開発用の PC（Windows 11、自宅の回線）で、2 本の公開動画を使い、yt-dlp 2026.08.19 で試したものである。利用者の環境での動きは保証しない。

| 動画 | 動画の言語 | 投稿者の字幕 | 自動字幕の元のトラック | チャプター |
| --- | --- | --- | --- | --- |
| 英語の音楽の動画（3 分 33 秒） | `en` | `de-DE`、`en`、`es-419`、`ja`、`pt-BR` | `en` と `en-orig`（同じ字幕） | なし |
| 日本語の模擬講義（45 分 49 秒） | `ja` | なし | `ja` と `ja-orig`（同じ字幕） | 5 |

- PEP 723 で `yt-dlp==2026.8.19` を固定したスクリプトを `uv run --script` で動かすと、Python 3.12.13 と 3.14.6 の両方で、メタデータの取得と、json3 の形の字幕の取得ができた。PO Token は求められなかった。
- json3 のバイト列の SHA-256 は、別々に取った 2 回で一致した。英語の動画の `en` と `en-orig` は、scoop の yt-dlp で取った回（23:04）と uv の yt-dlp で取った回（23:33）で一致した。日本語の動画の `ja-orig` は、23:31 と 23:34 の 2 回で一致した。日をまたいだときは試していない。
- yt-dlp の `automatic_captions` は、英語の動画で 160 の名前を持ち、json3 を持つのは 157 だった。各トラックの字幕の URL には `kind=asr` と `lang` が付き、YouTube が訳したトラックにだけ `tlang` が付く。`tlang` のないトラックは、英語の動画では `en` と `en-orig`、日本語の動画では `ja` と `ja-orig` の 2 つずつで、どちらも同じ `lang` だった。トラックの名前（キー）の `-orig` の有無では見分けられない。
- 固定した yt-dlp 2026.08.19 の `yt_dlp/extractor/youtube/_video.py` を読んで確かめた。元の言語の自動字幕は、`-orig` の付いた名前と付かない名前の両方で登録する（L4305〜L4313）。`translationLanguages` にない言語では、`isTranslatable` が偽なら `-orig` なしの名前だけで登録する（L4317〜L4327）。訳したトラックには `tlang` を付けて登録する（L4310〜L4313）。再生できない動画に予告編がある（`trailerVideoId`）と、予告編の動画の結果を返す（L3941〜L3947）。
- 実行のたびに「No supported JavaScript runtime could be found. Only deno is enabled by default」と警告が出た。yt-dlp は、JS の実行環境なしで YouTube から取ることを非推奨としている。今回は字幕を取れたが、取れ続ける保証はない。
- 字幕の URL には、`ip`、`signature`、`expire` などの引数が付く。
- 日本語の自動字幕には句読点がなく、聞き違いがあった。冒頭の自己紹介で、話し手の専門と名前が別の語に置き換わっていた。json3 の 1,384 の出来事（event）のうち 691 は、前の行に改行だけを足すもの（`aAppend`）だった。

## 決定

### 入口と経路

| 項目 | 決定 |
| --- | --- |
| 取り方 | yt-dlp を Python のライブラリとして使い、字幕だけを取る（`skip_download`、`noplaylist`）。動画と音声は落とさない |
| 依存 | 新しいスクリプト `wiki_youtube.py` を `uv run --script` で動かし、PEP 723 で yt-dlp の版を 1 つに固定する。`requires-python` は、ADR-0026 のとおり、ほかの uv で動くスクリプトと同じ範囲（今は `">=3.12,<3.15"`）にする。ADR-0026 の CI の確かめ（範囲のすべての minor の版で `uv sync --script`）の対象にも入る |
| 版の上げ方 | YouTube の変更で取れなくなったら、yt-dlp の固定を上げたパッチ版を出す。利用者の PATH の yt-dlp は使わない |
| JS の実行環境 | 求めない。yt-dlp の警告は、そのまま利用者に伝える。取得に失敗し、その警告が出ていたときは、deno を入れると直るかもしれないと添える |
| 入口 | 新しいコマンドは足さない。`/wiki:ingest` と、自然言語の取り込みの依頼で、URL が動画と分かれば、Web ページの経路より先に動画の分岐に進む |
| 動画と認める URL | `youtube.com`、`www.youtube.com`、`m.youtube.com` の `/watch?v=<ID>`、`/shorts/<ID>`、`/live/<ID>`、`/embed/<ID>` と、`youtu.be/<ID>`。`<ID>` は 11 文字の `[A-Za-z0-9_-]` である。`list=` が付いていれば、その動画だけを取り、そう伝える |
| 動画でない YouTube の URL | 再生リスト（`/playlist`）、チャンネル（`/@名前`、`/channel/`、`/c/`、`/user/`）、検索、そのほかの `youtube.com` と `youtu.be` の URL は、取らずに止まる。1 回の取り込みで扱うのは 1 本である |
| 経路の守り | 判定は、標準ライブラリだけの共通のモジュールに置き、`wiki_fetch.py` と `wiki_youtube.py` の両方が使う。`wiki_fetch.py` は、渡された URL と、リダイレクトのあとの最後の URL のどちらかが `youtube.com` か `youtu.be` なら、本文を読まずに止まり、動画なら動画の分岐を案内する。手順の書き漏れ、短縮 URL、`wiki:web-raw` の取り違えで、ページの下のリンクだけの raw ができないようにする |
| 取った動画の照合 | yt-dlp が返した動画の ID が、URL から取り出した ID と同じでなければ止まる（yt-dlp は、予告編など別の動画へ移す結果を返すことがある） |
| 止まる動画 | 配信中、配信の予定、配信の直後（`live_status` が `not_live` か `was_live` でない）。公開か限定公開でない（`availability` が `public` か `unlisted` でない。非公開、ログインが要る、年齢の制限、メンバー限定など） |
| 止まり方 | yt-dlp が失敗したら（ボットの確認、429、PO Token、取得できない動画）、メッセージをそのまま伝えて止まる。自動でやり直さない。字幕がない動画も止まり、字幕を `.md` か `.txt` にして `raw/` に置く今の方法を案内する |

### トラック

| 項目 | 決定 |
| --- | --- |
| トラックの種類 | トラックの名前（キー）からは推さない。yt-dlp が返す各トラックの json3 の URL の引数で決める。`subtitles` のトラックは `uploaded`（投稿者が上げた字幕）。`automatic_captions` のうち、`kind=asr` で `tlang` がないものは `asr`（元の言語の自動字幕）。`tlang` があるものは YouTube の自動翻訳で、使わない。どれにも当たらないトラックは使わない |
| 同じトラック | `asr` のトラックは、`lang` が同じなら同じトラックとみなし、1 つにまとめる（名前は `<lang>-orig` があればそれ、なければ `<lang>`）。`lang` の違う `asr` のトラックが 2 つ以上あれば、自動では選ばない |
| 話された言語 | L は、`asr` のトラックが 1 つならその `lang`、なければ yt-dlp の `language` とする。どちらも分からなければ、自動では選ばない |
| 言語の照らし方 | 言語のコードは、大文字と小文字を区別せず、最初の `-` より前（主の言語）で比べる。`ja` と `ja-JP`、`en` と `en-US` は同じ言語である |
| 選び方 | (1) 主の言語が L と同じ `uploaded` のトラックのうち、コードが L とちょうど同じものが 1 つならそれ、なければ主の言語が同じものが 1 つだけならそれ。(2) なければ `asr` のトラック。どれにも決まらなければ（候補が 2 つ以上、L が分からない、字幕がない）、取らずにトラックの一覧を示して止まる。利用者は `--track` で `uploaded` か `asr` のトラックを指定できる。指定したトラックを取れなければ、別のトラックに替えずに止まる |

### raw

| 項目 | 決定 |
| --- | --- |
| raw を書く者 | raw を書くのはスクリプトだけである。モデルは raw を直さない（句読点を補う、聞き違いを直す、訳す、はしない） |
| raw の作り方 | 2 つの段に分ける。`inspect` はディスクに何も書かない。メタデータとトラックの一覧を取り、トラックが決まれば、その json3 をメモリに取って `source_sha256` を出す。メタデータ、トラックの一覧と種類、選んだトラック、`source_sha256`、置いてある raw との関係、警告を JSON で返す。トラックが決まらなければ、`source_sha256` と置いてある raw との関係は `null` にし、決まらなかった理由を返す。`write` は選んだトラックの json3 を取り、raw を 1 回で作り、ADR-0020 と同じく重ねて書かない形で置いて、読み取り専用にする。上書きの手段は持たない |
| YouTube から来た文字の置き場所 | 字幕の本文、動画の題名、チャンネルの名前、チャプターの題名は、どれも信頼できない入力である（S-01）。raw では、frontmatter の引用符で囲んだ値（`page-conventions.md` の書き方でエスケープする）か、フェンスの中にだけ置く。フェンスの外には、スクリプトが決めた語、時刻、番号だけを置く（ADR-0020 と同じ）。Markdown の強調、リンク、画像、文字参照、HTML として読まれないようにするためである |
| フェンス | 本文の中の最長のバッククォートの並びより 1 つ長い（3 つ以上の）バッククォートで囲み、情報文字列は `text` にする |
| json3 から行へ | 出来事のうち `segs` を持つものの `utf8` をつなぐ。改行は空白にし、前後の空白を除いて、空になった出来事（`aAppend` の改行だけのものを含む）は捨てる。残った出来事を、`tStartMs` の昇順で、同じ値なら json3 の中の順に並べ、1 つにつき 1 行の `L<番号> [時刻] 本文` で書く。番号は、並べた順に 1 から振る通し番号で、同じ json3 からはいつも同じ番号になる。行の番号は、同じ秒に始まる出来事が 2 つ以上あっても、字幕の 1 行を 1 つに指す。時刻は `tStartMs` を秒に切り捨て、動画の長さが 1 時間未満なら `mm:ss`、1 時間以上ならすべての行で `h:mm:ss` にする。本文の文字は、NFC にそろえるほかは変えない |
| 区切り | チャプターがあれば、チャプターごとに区間を作る。区間は開始の時刻からつぎのチャプターの開始の前までで、行は `tStartMs` で属する区間を決める（区間をまたぐ字幕は、始まった区間に置く）。区間ごとに、フェンスの外に `## 区間 N [時刻]`、フェンスの中の最初の行に `題名: <チャプターの題名>` を置く（題名の行には行の番号を振らず、字幕の行に数えない）。題名のないチャプター（yt-dlp の `<Untitled Chapter N>`）は、題名の行を書かない。チャプターがなければ、10 分ごとに同じ形の区間を作る（題名の行はない）。字幕の行のない区間は、フェンスを置かず、「この区間に字幕はない」と書く。長い動画を分割して読むときの区切りにする |
| 見出し | raw の先頭の見出しは `# YouTube の字幕 <video_id>` にする。題名は frontmatter にだけ書く |
| raw に入れないもの | 投稿者の説明文、コメント、字幕の URL（`ip` と署名を含む）、取得の時刻、元の json3 のファイル。投稿者の説明文は、字幕と出所が違うので入れない |
| frontmatter | キーは英語にする。`url`（`https://www.youtube.com/watch?v=<ID>` の形にそろえる）、`video_id`、`title`、`channel`、`uploaded`（投稿日）、`duration`（秒）、`video_lang`（L）、`caption_track`（まとめたあとの名前）、`caption_kind`（`uploaded` か `asr`）、`caption_lang`、`source_sha256`（json3 のバイト列の SHA-256）、`source_sha256_of: "json3"`、`fetched_by`（スクリプトと yt-dlp の版） |

### 同じ取り込みと状態

| 項目 | 決定 |
| --- | --- |
| 同じ資料 | `video_id` と `source_sha256`（json3 のバイト列）の 2 つが同じなら、同じ資料である（F-I08、F-I15 と同じく原本のハッシュで決める）。トラックの名前（`caption_track`）は、同じ字幕でも `-orig` が付いたり付かなかったりするので、同一性に使わず、記録するだけにする。題名、チャプター、スクリプトと yt-dlp の版が変わっても、字幕が同じなら同じ資料とみなし、別版を作らない |
| 置いてある raw との関係 | `inspect` は、スラッグによらず、`<RAW_ROOT>` の直下の `.md` のうち frontmatter の `video_id` が同じものをすべて挙げ、それぞれ `same`（`source_sha256` も同じ）か `different` かを返す。frontmatter を読めないファイルは、名前を警告に挙げる。指定したスラッグのファイルが、別の動画の raw、YouTube の raw でないもの（`video_id` のない記事やメモ）、frontmatter を読めないもの、のどれかなら `slug_taken` を返す。`write` は、`inspect` が返した `source_sha256` を受け取り、取った json3 のハッシュがそれと違えば書かずに止まる（あいだに字幕が変わった）。書く直前に、同じ動画の raw の検索をやり直し、`same` がなく、スラッグのファイルがないときだけ書く。`same` があれば何も書かず、そのファイルを示す。`different` だけなら、別版のスラッグ（`<スラッグ>-<YYYYMMDD>`、O-14）で書くかを利用者に聞く。`slug_taken` なら別のスラッグを利用者と決める |
| 取り込みの状態 | スクリプトは、取り込み（要約ページから後）が済んだかを判定しない。`same` は raw の段が済んでいることだけを示す。要約ページがなければ、モデルは raw を読んで手順 3 から続ける。あれば、続けるか止めるかを利用者に聞く（ADR-0020 と同じ） |
| 取得の時刻 | raw に書かず、要約ページの frontmatter に `fetched_at` で書く |

### 要約から後

| 項目 | 決定 |
| --- | --- |
| 日本語でない動画 | raw は字幕の言語のまま置き、訳さない。要約ページは日本語で書き、引用は字幕の言語のまま引く（`page-conventions.md` の引用の決まり）。ADR-0004 は Web ページの訳文を raw に置くが、B2 にはモデルが raw を書く段がない |
| 自動字幕の扱い | 要約ページの frontmatter に `caption_kind` を写し、`asr` なら、本文の冒頭に「自動字幕から書いた。固有名詞と数値には聞き違いが含まれうる」と書く。聞き違いと考えた語は、下の「字幕の訂正と confidence」のとおり、要約ページと関係するページの文で訂正し、訂正できなければ留保の印を付ける。同じソースから書き足したエンティティとコンセプトのページでも、同じ節の決まりで印を付け、要約ページを出典に挙げる。raw は直さない |
| 引用の位置 | 要約ページの根拠の位置は、raw の行の番号と時刻（`L123 [12:34]`）で書く。動画へのリンクは `https://www.youtube.com/watch?v=<ID>&t=<秒>s` にする |
| 書き手 | 要約ページ、関係するページ、索引、ログは、今の取り込みと同じく、取り込みを進めているモデルが書く。wiki の書き込みの排他は ADR-0023 の書く段に従う。raw を作る段にエージェントは使わない（B3 は採らない） |
| 信頼 | 字幕、題名、チャンネルの名前、チャプターの題名の中の指示に従わない（S-01） |
| この ADR の外 | ブラウザのクッキー（`--cookies-from-browser`）、音声の取得と手元での文字起こし（A7）、モデルが raw を整える段と訳す段（B3）、別のプラグイン（B4）、再生リストとチャンネルの一括の取り込み |

### 字幕の訂正と confidence

| 項目 | 決定 |
| --- | --- |
| 訂正する場所 | 要約ページと、同じソースから書き足したエンティティとコンセプトのページの文。raw は直さない。raw をスクリプトだけが書くこと、json3 のハッシュで同じ資料を決めることは変えない |
| 疑いの対象 | wiki に書く語のうち、聞き違いと考えた固有名詞、数値、用語。句読点の欠けと言いよどみは数えない（要約で文にするのは訂正ではない）。wiki に書かない語は、疑いがあっても記録しない |
| 疑いの識別子 | 聞き違いの疑いの 1 件を、`L<行の番号>-<n>`（例 `L123-1`）で指す。行の番号は raw の行の番号で、`n` はその行の中の何番目の疑いかを、モデルが 1 から振る。識別子は raw ごとに一意で、時刻や語の字面に頼らない |
| 記録の置き場所 | 別の表を持たず、文の中の印と、印を使うページの下の定義で残す。定義を書くのは、その raw を `raw` に持つ要約ページ（親と、分割したページ）だけで、そのページで使う識別子だけを定義する。ページを分けると、印と定義はそれを使う文と一緒に分かれるので、ページの大きさの上限は今のとおりページごとに守れる |
| 印 | 訂正した語の直後に `〔訂正 L123-1〕`、留保の語の直後に `〔留保 L123-1〕` を置く。印は識別子だけを持ち、縦棒、バッククォート、Markdown の記法を含まないので、表のセルの中にも置ける。語の境目は印に書かず、印の直前の本文（Markdown の原文）の末尾で確かめる。訂正の印なら、末尾が定義の訂正した語とちょうど同じであること、留保の印なら、末尾が定義の字幕の語とちょうど同じであることを求める。比べる前に、印の直前の原文から CommonMark のバックスラッシュのエスケープ（ASCII の記号の前の `\`）を外す。末尾の直前の文字が、語の最初の文字と同じ種類（数字、英字、カタカナ）なら、語の途中で切れているので誤りにする（訂正した語 `5` の前に `1` があれば、本文は `15` のままである）。印の直前の語には書式を付けない（コードスパン、強調、wikilink で囲んだ語の直後には印を置けない。wikilink にしたい語は、印のある箇所と別に書く） |
| 定義 | ページの末尾近くに `## 字幕の訂正と留保` の節を置き、識別子ごとに 1 項目の箇条書きで書く。訂正は ``- L123-1: 字幕 `15` を `50` に訂正（根拠 種類:場所）``、留保は ``- L123-1: 字幕 `15` は留保`` の形にする。字幕の語と訂正した語はコードスパンで囲み、中の最長のバッククォートの並びより 1 つ長いバッククォートを使う（Markdown の記法と文字参照として読まれないため）。語の先頭か末尾がバッククォートか空白なら、囲みの内側の前後に空白を 1 つずつ足し、読むときは CommonMark のとおり前後の空白を 1 つずつ外す。字幕の語は、その行の中の部分文字列で、同じ行に 2 回以上出るなら ``字幕 `15`（2 つ目）`` と何番目かを書く。表にしないのは、字幕の縦棒が表のセルを分けるからである |
| 根拠の種類と場所 | `metadata:title`、`metadata:channel`、`metadata:chapter:N`（raw の frontmatter の題名、チャンネルの名前、N 番目のチャプターの題名）、`caption:L130`（同じ raw の字幕のほかの行）、`wiki_source:<スラッグ>`（wiki のほかのソースの raw）、`model:<理由>`（モデルの知識だけ）のどれかである。`model` 以外は、訂正した語がその場所に逐語であるときだけ使える。投稿者の説明文は raw にないので、それに頼る訂正は `model` にする |
| 印を付ける箇所 | 同じ識別子に頼る語は、要約ページごとに、最初に使う箇所に印を付け、それ以降は訂正した語だけでよい。印を省いた再出現も、同じ識別子に頼るものとして扱う（そのページの定義か、指した要約ページの定義にある訂正した語か留保の語は、印の有無によらず、その識別子に頼る語である）。同じ識別子を 2 つ以上の要約ページで定義するときは、定義が同じでなければ誤りにする。引用は raw の逐語のままにし、印を引用の中に入れない |
| 関係するページ | エンティティとコンセプトのページは、識別子を新しく作らず、定義も書かない。要約ページの訂正した語か留保の語を使うときは、最初に使う箇所の直後に `〔訂正 [[要約ページ]] L123-1〕` か `〔留保 [[要約ページ]] L123-1〕` を置く。指した要約ページにその識別子の定義がないか、印の直前の本文の末尾が、訂正なら訂正した語、留保なら字幕の語と合わなければ誤りにする |
| 留保に使う場面 | 聞き違いと考えても正しい語を決められない語と、利用者が退けた訂正 |
| 数え方 | 1 件は、要約ページで定義した 1 つの識別子である（同じ識別子は何ページで定義しても 1 件）。重みは、`metadata`、`caption`、`wiki_source` の訂正が 1、`model` の訂正と留保が 3 である。重みの合計を raw の字幕の行数（行の番号の最大値）で割って 100 を掛けた値を、疑いの率とする |
| confidence | 親の要約ページ（スラッグが raw のファイル名と同じページ）の frontmatter に、`confidence` を `"high"`、`"medium"`、`"low"` のどれかで書く（グラフのエッジと同じ語彙）。動画のソースでは必須にする。ほかの経路のソースには、この ADR では書かない。書かれていないことは「判定していない」を表し、高いとも低いとも読まない |
| confidence の規則 | confidence は、raw とその要約ページの定義だけから、いつでも同じ計算で決まる。出発点は raw の `caption_kind` で、`uploaded` なら `high`、`asr` なら `medium` である。`asr` は疑いが 0 件でも `high` にしない（疑いの少なさは、モデルが気づいた誤りの少なさで、誤りの少なさではない）。出発点から下げる方向だけに動かす。`model` の訂正か留保の定義が 1 件以上あれば、`high` を `medium` にする。疑いの率が 3 以上なら `low` にする。重みとしきい値は、較正していない仮の値である |
| 数え直し | 要約ページの定義が変われば、そのたびに計算し直し、親の要約ページの値を書き換える。利用者が訂正を退けて留保にすれば、重みは 1 か 3 から 3 になり、confidence は下がるか変わらない。訂正に頼る文を消したときと、利用者が字幕の語のほうが正しいと判断して定義と印を外したときは、上がりうる |
| confidence の意味 | この raw から wiki に書いた語が、字幕の聞き違いの訂正と留保にどれだけ頼っているかの目安で、出発点は字幕の種類である。内容の正しさでも、人の確認（要件定義書の 8 章の検証状態）でもない |
| 機械の照合 | 印の読み取りと confidence の計算は、標準ライブラリだけの共通のモジュールに置く。`wiki_youtube.py verify` は、raw と、用意したページを受け取り、次を確かめる。(1) 定義の字幕の語が、識別子の行の raw の本文に、書いた何番目かの位置で逐語であること。(2) 訂正の定義なら、種類と場所が決まった形で、`model` 以外なら訂正した語がその場所に逐語であること（留保の定義には、訂正した語も根拠もない）。(3) 同じ識別子の定義が要約ページの間で食い違わないこと。同じ行の同じ位置（字幕の語と何番目か）を、2 つの識別子が指さないこと。(4) すべての印が、同じページか指した要約ページの定義に当たり、印の種類（訂正か留保）が定義と同じで、印の直前の本文の末尾が、訂正なら訂正した語、留保なら字幕の語と同じであること。定義だけあって印のない識別子も誤りにする。(5) 計算した confidence が、親の要約ページの値と同じであること。要約ページか関係するページの印を変える計画では、ADR-0023 の書く段で承認を求める前に、用意したページに当て、合わなければ承認を求めない。lint も同じモジュールで (1)〜(5) を照らし、取り込みの外でページを直したときの食い違いを指摘する |
| 書かれていない訂正の目印 | `verify` は、用意したページの本文（引用、コード、印を除く）から、数字の並びと、2 文字以上の英字かカタカナの並びのうち、raw（字幕と frontmatter）にも定義の訂正した語にもないものを「raw にない語」として挙げる。印を付けずに直した語を見つける目印で、保証ではない。漢字だけの名前と、言い換えた語は挙がらない |
| 利用者への伝え方 | 計画の承認を求めるときに、定義の一覧（識別子、時刻、字幕の語、訂正した語、種類と場所）、confidence とその理由、「raw にない語」の一覧を示す。取り込みの終わりの報告にも、種類ごとの件数と confidence を書く |
| 回答の確からしさとの関係 | `/wiki:query` の回答の確からしさ（ADR-0028、提案）は、ソースの要約ページか raw で確かめた主張を「高」の出発点にする。動画の raw か、それを `raw` に持つ要約ページ、またはそれらを出典にするページに頼る前提は、その raw の confidence を上限にする（`medium` なら「中」、`low` なら「低」）。confidence は親の要約ページの値で、親の要約ページがなければ（raw を作って中断したときなど）raw の `caption_kind` の出発点を使う。`model` の訂正か留保の識別子に頼る語を使う前提は、印の有無によらず「低」を上限にする。印を省いた再出現は、そのページの定義（関係するページなら、印で指した要約ページの定義）の訂正した語か留保の語と照らして、識別子を引く。ADR-0028 の上限の表に、これを書き足す必要がある |
| 型付きのエッジ | `asr` のソースからは、型付きの意味のエッジを書かない（本文の wikilink からの `mentions` だけにする）。`uploaded` のソースからは書いてよい。ただし `evidence` は raw の逐語にし、訂正した語に頼る関係は書かない。エッジの `confidence` は、ソースの `confidence` より高くしない |

## 理由

- yt-dlp は、YouTube の変更（署名、PO Token、JS による抽出）に追いつく作業を続けている。標準ライブラリで同じことをするのは、yt-dlp を作り直すことになる。そこで、`CONTRIBUTING.md` の「新しい補助の処理には標準ライブラリを優先する」から外れ、セットアップ、ハイブリッド検索、グラフのコンパイルと同じく、uv で版を固定した PEP 723 の依存にする。依存はこのスクリプトだけに閉じ、ほかの経路には入れない。
- 版を固定すると、YouTube の変更で取れなくなったときに、プラグインのパッチ版を待つことになる。それでも固定するのは、試験した版で動くことを優先するからである。下限だけを書いても、uv は一度解決した環境を使い続けるので、新しい版に自動では上がらない。
- 利用者の PATH の yt-dlp を使うと、利用者に別の導入を求め、版も環境ごとに違う。uv のスクリプトなら、wiki の初期化で入れる uv だけで動く。
- 公式の API は他人の動画に使えず、youtube-transcript-api は自動字幕と投稿者の字幕の区別が yt-dlp より粗い。Gemini は字幕そのものを返さず、raw の原本にならない（調査レポートの A3、A6、A8）。
- トラックの種類を名前から推すと、`-orig` のない元の字幕を自動翻訳と取り違えた（1 回目のレビュー）。YouTube が字幕を返すときの引数（`tlang` の有無）は、訳したかどうかそのものを表すので、名前の付け方に左右されない。自動翻訳を使わず、トラックを推して替えないのは、どの字幕から書いたかを確かめられるようにするためである。
- 字幕をフェンスの外に書くと、字幕の `**` や画像の記法が Markdown として読まれ、原文にない構造になる（1 回目のレビューで再現）。ADR-0020 と同じく、外から来た文字はフェンスか引用符の中にだけ置けば、字幕の中身によらず逐語になる。題名を見出しにしないのも同じ理由である。
- 同じ資料を原本のハッシュで決めるのは、ADR-0004 と F-I15 と同じである。raw のバイト列で決めると、スクリプトや yt-dlp の版を上げただけで、字幕が同じでも別版になった（1 回目のレビュー）。トラックの名前を加えると、同じ字幕に `-orig` が付いたり付かなかったりするだけで別版になった（2 回目のレビュー）。原本のバイト列とそれを持つ動画だけなら、名前の付け方にも道具の版にも左右されない。
- 題名とチャプターの書き換えは別版にしない。題名とチャプターは固有名詞を確かめる手がかりでもあるので、書き換えで確かめの材料が変わることはある。それでも、主張の根拠になる字幕が同じなら同じ資料とし、raw には最初に取ったときの題名とチャプターを残す。
- 同じ動画の raw を、スラッグによらず探すのは、利用者が別のスラッグを付けて取り込み直したときにも、同じ資料を 2 つ置かないためである。
- yt-dlp が返す動画の ID を照らすのは、yt-dlp が別の動画へ移す結果を返すことがあり、公開の状態と字幕の有無だけでは、依頼と違う動画を見分けられないからである。
- 投稿者の説明文は、固有名詞を確かめる手がかりになる。それでも raw に入れないのは、字幕と出所が違うからである。説明文に頼る訂正は、raw で照らせないので、外に根拠のない `model` の訂正として重く数える。
- 自動字幕の聞き違いは、句読点の欠けより重い。固有名詞と数値が入れ替わると、もっともらしい誤りが wiki に積み重なる（SKILL.md の「気づかれない汚染」）。留保だけでは、正しい語が分かっていても wiki に書けず、作者は訂正を求めた（2026-11-16）。
- 訂正を raw でなく要約ページと関係するページで行うのは、raw を原本の写しに保つためである。raw を直すと、どこが字幕でどこがモデルの推測かを raw から見分けられなくなり、書き換えを照らす検査（ADR-0004 の `wiki_rawcheck.py` と同じ種類）が要る。同じ json3 から毎回同じ raw ができることも崩れる。
- 訂正を見えない形にすると、外れた訂正が、確かめた事実と見分けられない語として広がる。そこで、訂正を、使う文の中の印と、字幕の逐語と根拠を書いた定義に残し、利用者に一覧で示す。定義の字幕の語が raw にあることと、`model` 以外の根拠の場所に訂正した語があることはスクリプトで照らせるので、存在しない語を「訂正した」と書く誤りと、根拠の種類の付け替えは止められる。訂正した語が正しいかは機械で確かめられないので、外に根拠のない `model` を重く数える。
- 訂正を別の表でなく文の中の印に残すのは、記録を、それが支える文と同じ単位にするためである。4 回目と 5 回目のレビューで、表を要約ページごとに持つと、ページを分けるだけで疑いの率が下がった。表を raw ごとに 1 つにすると、疑いの多い長い動画で表がページの上限を超え、置ける場所がなくなった。語ごとに時刻を束ねると、同じ字幕の語を出現ごとに別の語へ訂正できなかった。印と定義は、それを使う文と一緒にあるので、ページを分けても数が変わらず、ページの大きさは今の分け方で守れる。
- 疑いを、時刻と字幕の語でなく、スクリプトが振った行の番号の識別子で指すのは、6 回目のレビューで、同じ秒に始まる 2 つの行の同じ語を区別できなかったからである。行の番号は同じ json3 からいつも同じで、字幕の 1 行を 1 つに指す。印に訂正した語と字幕の語を入れないのは、印の境目と、印の中の記法と縦棒の読まれ方が決まらなかったからである（6 回目）。語は定義の箇条書きのコードスパンに置き、印の直前の本文の末尾と照らす。関係するページの印にも識別子を持たせるのは、要約ページの名前と訂正した語だけでは、同じ語の 2 つの訂正のどちらに頼るかを決められなかったからである（6 回目）。
- 出発点を raw の `caption_kind` から決めるのは、raw を直接読む経路や、要約ページを書く前に中断した raw でも、confidence を引けるようにするためである（4 回目のレビュー）。
- 留保と退けた訂正を、重い疑いとして数えるのは、疑いを訂正の成否と切り離すためである。4 回目のレビューで、訂正の件数だけを数えると、利用者が訂正を退けて留保に戻すほど confidence が上がった。退けても、字幕の聞き違いの疑いは残っている。confidence をいつでも印から計算し直す値にしたのは、計算し直す場面を限ると、退けた訂正の重みが変わる場面と食い違ったからである（5 回目のレビュー）。
- confidence を出発点から下げる方向だけで決めるのは、疑いの数がモデルの気づいた誤りの数で、残った誤りの数ではないからである。印を付け忘れた疑いは数えられないので、付け忘れても出発点（`asr` なら `medium`）より上がらない形にした。付け忘れそのものは機械で見つけきれないので、「raw にない語」の目印を利用者に示す。件数でなく行数に対する率にするのは、長い動画ほど件数が多くなるのを、聞き取りの悪さと取り違えないためである。
- confidence を frontmatter に保存するのは、raw とその要約ページの定義だけから決まり、ほかのページが変わっても変わらないからである。要約ページの定義が変われば、同じ計算で書き換え、lint が食い違いを指摘する。ADR-0028 が回答の確からしさをシンセシスに保存しないのは、wiki のどこが変わっても判定が変わりうるからで、この confidence には当たらない。

## 検討した選択肢

| 選択肢 | 採らなかった理由 |
| --- | --- |
| 文書だけで済ませる（B1） | 手で写す方法（A1）は、字幕の種類と時刻が残らない。動画の URL がページの下のリンクだけの raw になる穴も残る |
| raw の段をエージェントに任せ、句読点と聞き違いを直す、訳す（B3） | モデルの書き換えを照らす検査が要る（ADR-0004 の `wiki_rawcheck.py` と同じ種類）。raw が原本の写しでなくなり、同じ json3 から同じ raw ができなくなる。聞き違いの訂正は、raw でなく要約ページで行う |
| 自動字幕を訂正せず、留保だけを付ける（3 版目まで） | 正しい語が題名やほかの資料で分かっていても wiki に書けない。作者が訂正を求めた |
| 訂正を記録せず、本文だけを直す | 外れた訂正が、確かめた事実と見分けられない。利用者が何を直したかを知れない |
| 訂正の件数で confidence を決める | 長い動画ほど件数が増え、聞き取りの悪さと見分けられない |
| 訂正が少なければ confidence を上げる | 訂正の少なさは、モデルが気づかなかった誤りの多さでもありうる |
| 訂正の表を要約ページごとに持つ（4 版目） | 要約ページを分けるだけで疑いの率が下がる。raw を直接読む経路で confidence を引けない |
| 訂正した語だけを数え、退けた訂正と訂正できない語を数えない（4 版目） | 訂正を退けて留保に戻すほど confidence が上がる |
| 疑いの表を raw ごとに 1 つにし、親の要約ページに置く（5 版目） | 疑いの多い長い動画で、表がページの上限を超えて置けない。語ごとに時刻を束ねるので、同じ字幕の語を出現ごとに別の語へ訂正できない |
| 文の中の印に時刻、字幕の語、根拠を書き、時刻と字幕の語の組で出現を指す（6 版目） | 同じ秒の 2 つの行の同じ語を区別できない。印の中の訂正した語の境目が決まらず、印の中の記法と縦棒が Markdown として読まれる。関係するページの印から、どの訂正に頼るかを決められない |
| 疑いの表を wiki の外の機械向けのファイル（JSON など）に置く | 大きさの上限はなくなるが、ADR-0023 の書く段が扱うのは wiki のページ、索引、ログで、新しい種類のファイルの書き方と守り方が要る。記録が、それが支える文から離れる |
| confidence を 0〜1 の数値にする | 較正のデータがなく、較正したように見える。グラフのエッジと語彙もそろわない |
| 別のプラグインにする（B4） | 字幕を取るだけなら軽く、永続ジョブも要らない。音声の文字起こし（A7）を入れるときに考える |
| youtube-transcript-api（A3） | 依存は軽いが、トラックの種類の区別とチャプターがない。公式の API でない点は yt-dlp と同じである |
| 利用者の PATH の yt-dlp を使う | 導入と版が利用者ごとに違う |
| yt-dlp の下限だけを書く | uv は解決した環境を使い続けるので、新しい版に自動では上がらない。試験していない版で動く |
| トラックの名前の `-orig` で、元の自動字幕と自動翻訳を見分ける（1 版目） | yt-dlp は元の字幕を `-orig` なしの名前でも登録し、`-orig` がない動画もある |
| 自動翻訳のトラックを、日本語の字幕がないときの代わりに使う | 機械の訳で、出所と誤りが追えない |
| 字幕をそのまま Markdown の行にする（1 版目） | 字幕の中の記法が Markdown として読まれる |
| raw のバイト列で同じ取り込みを決める（1 版目、ADR-0020 の方式） | スクリプトと yt-dlp の版を上げると、字幕が同じでも別版になる。セッションと違い、raw の中身は人の決定を含まず、原本のハッシュで足りる |
| `video_id`、トラックの名前、json3 の SHA-256 の 3 つで決める（2 版目） | 同じ字幕でも、yt-dlp が `-orig` の付いた名前を登録するかどうかで名前が変わる |
| 指定したスラッグの raw だけと比べる（2 版目まで） | 別のスラッグで取り込み直すと、同じ資料の raw が 2 つできる |
| 投稿者の説明文を raw に入れる | 字幕と出所が違う |
| 元の json3 も `raw/assets/` に残す | 1 本で約 1 MB になる（45 分の講義で 968,449 バイト）。ハッシュで出所は確かめられる |

## 影響

- `info-hive-wiki` に `wiki_youtube.py`（`inspect`、`write`）と、動画の URL を判定する共通のモジュールを足す。`wiki_fetch.py` は、YouTube の URL を、リダイレクトのあとも含めて拒む。今の `wiki_fetch.py` は応答の本文を読んでから最後の URL を返すので、リダイレクトの先を本文を読む前に確かめる形に取得の処理を変える。`commands/ingest.md` に動画の分岐（Web ページの分岐より先）を、`references/ingest-workflow.md` に手順と要約ページの書き方を、`SKILL.md` に起動の例を足す。ユーザーに見える機能なので、プラグインの minor の版を上げる。
- 試験は、保存した yt-dlp のメタデータと json3 を素材にし、ネットワークにつながずに動かす。URL の判定、リダイレクトのあとの拒み、トラックの種類（`tlang` の有無、`-orig` のない元の字幕）、選び方、止まる動画、ID の照合、json3 から行への変換、フェンスの長さ、記法を含む字幕、区間の分け方、行の番号の振り方、同じ資料の判定、字幕の URL が raw に入らないことを確かめる。`verify` と lint の照合（定義の字幕の語の位置、根拠の場所、識別子の重なり、印と定義の対応、印の直前の末尾の照らし方とエスケープ）と、confidence の計算も、作った要約ページを素材に確かめる。YouTube から実際に取る確かめは、リリースの前に手で行う。
- トラックの種類の判定は、yt-dlp が返す字幕の URL の引数（`kind`、`lang`、`tlang`）に頼る。これは yt-dlp と YouTube の公開の仕様ではない。引数が変われば、判定はどのトラックも `asr` と認めずに止まる（推して替えない）。
- 要件定義書の F-I02 の対象に YouTube の動画を足し、動画の要件を新しい番号で足す。F-I03 には、動画の raw は字幕を Markdown に変えたもので、出所は json3 の SHA-256 で記録し、取得の時刻は要約ページに書くと書き足す。F-I08 には、動画は `video_id` と json3 の SHA-256 で、スラッグによらず照合すると書き足す。
- 自動字幕の聞き違いは、要約ページと関係するページで訂正し、raw は直さない。訂正した語が正しいかは機械で確かめられず、`model` の訂正は外れうる。重みと confidence と本文の併記で目立たせ、利用者が退けられるようにして、これを受け入れる。
- 末尾の照合で語の途中の切れ目を見分けるのは、数字、英字、カタカナだけである。漢字の語は、`東京都` を `京都` に訂正したと定義して本文を直さなくても通る（8 回目のあとの直しで、レビューを受けていない）。
- 印を付けずに本文だけで直した語は、「raw にない語」の目印でしか見つからない。漢字だけの名前と言い換えは目印に挙がらない。付け忘れても confidence は出発点より上がらないが、利用者に示されない訂正が残りうる。これを受け入れる。
- 訂正に頼る文を消すか、利用者が字幕の語のほうが正しいと判断して印を外すと、confidence は上がりうる。印を外したのが利用者の判断かは、計画の承認でしか確かめられない。
- 印の分だけ、要約ページの本文が長くなり、読みにくくなる。印を付けるのは、出現ごと、要約ページごとに最初の箇所だけにして、増え方を抑える。
- `wiki_youtube.py` に `verify` を、標準ライブラリだけの共通のモジュールに印の読み取りと confidence の計算を、lint にその照合を足す。`page-conventions.md` に `confidence` の欄と印の形を、`wiki/SCHEMA.md` のテンプレートと日本語の別名の表に `confidence`（別名の候補は `確かさ`）を足す。
- ADR-0028（`/wiki:query` の回答の確からしさ、提案、別のセッションで作業中）の上限の表に、動画の raw とそれに頼るページの `confidence`、`model` の訂正の印と留保の印の付いた語を足す必要がある。2 つの ADR のどちらが先に承認されても、後から入る側が合わせる。
- confidence の重みとしきい値（`model` と留保の重み 3、疑いの率 3）は、較正していない。実際の取り込みで定義がたまったら、見直す。
- 題名とチャプターの書き換えは別版にしないので、raw の題名とチャプターは、最初に取ったときのものが残る。
- 2 つの取り込みが同時に同じ動画を別のスラッグで書くと、同じ資料の raw が 2 つできうる（3 回目のレビュー、時機による軽微な指摘）。重ねて書かない置き方は、別の名前への書き込みを排他しない。ADR-0023 のロックが実装されたら、raw の書き込みもその中で行う。それまでは、この重複を受け入れ、要約ページを書く段でモデルが wiki を見て気づく。
- 敵対的レビュー（GPT-6.1 Sol）は、字幕の取り方と raw について 3 回行い、判定は却下、却下、採用可だった。作者が字幕の訂正と confidence を求めたあと（2026-11-16）、4〜8 回目を行った。4〜7 回目は却下（重大は 4、3、3、1）で、重大の多くは、直しで足した記録の形（表の単位、出現の指し方、印の読み方）から出た。8 回目は採用可で、残ったのは軽微な 2 件だった。3 回目のあとに足した 3 つ（`slug_taken` の範囲、`inspect` のハッシュを `write` で照らすこと、同時の取り込みの重複を受け入れたこと）は、4 回目で崩れなかった。8 回目の軽微な 2 件への直し（照らす前にバックスラッシュのエスケープを外すこと、末尾の直前の文字の種類で語の途中の切れ目を誤りにすること）は、レビューを受けていない。実装のときの試験とレビューで確かめる。
- yt-dlp の固定を上げるたびに、パッチ版を出す。YouTube の変更が続くと、この頻度が上がる。
- YouTube の利用規約に、字幕の自動の取得がどう当たるかは、この ADR では判断しない。利用者向けの文書に、公式でない取り方であることと、取れなくなりうることを書く。

## 見直す条件

- 取得の失敗が続き、yt-dlp の固定を上げても直らないとき、または上げる頻度がパッチ版の手間を超えるとき。
- yt-dlp が、字幕の取得にも JS の実行環境を求めるようになったとき（deno を依存にするかを決める）。
- 字幕の URL の引数で、トラックの種類を見分けられなくなったとき。
- 同じ動画の json3 のバイト列が、字幕が変わっていないのに取るたびに変わると分かったとき（同じ資料の決め方を、字幕の行から作ったハッシュに変えるかを決める）。
- 自動字幕の聞き違いの疑いが多く、`low` のソースが目立つとき（A7 で精度の高い文字起こしを使う案を見直す）。
- 利用者が退ける訂正が多いとき（`model` の訂正を許すか、重みを見直す）。
- 字幕のない動画の取り込みを、利用者が頻繁に求めるとき（A7 と B4 を見直す）。
- ログインや年齢の制限のある動画を取り込みたいとき（クッキーの扱いを決める）。
